# 创作画布交互大改造实施计划

## 本次执行范围（用户已确认：先做成文档，不着急动手）

本次**只做一件事**：把下述计划落成正式文档 `docs/superpowers/plans/2026-09-30-画布交互大改造-执行方案.md`（遵循仓库"较大功能的规格与计划放 docs/superpowers/plans/，日期前缀命名"的约定）。

**不改任何代码、不跑任何构建**。四期实施（A 基础修复 → B 架构收敛 → C 交互升级 → D 并发多变体）等用户明确说开始后再启动，每期完成即停下等验收。

## Context（为什么做）

用户对标 LibTV/TapNow 等主流 AI 节点画布，认为当前画布"交互 bug 多、不顺手、设计落后"。经全量摸底 + 用户确认，痛点共 12 项（IME 中文输入失效、滚轮不缩放、节点位置错乱、框选语义打架、创建/连线繁琐、报错体验差、并发状态异常等），根因已全部定位到代码。用户拍板三个方向性决策：

1. **导航范式对标主流节点画布**（滚轮缩放、左键拖空白=框选、空格/中键=平移）——放弃早期"左键拖拽=平移"旧约定；
2. **做并发多变体**（完整对标 LibTV，schema v2 放开唯一索引）；
3. **分期**：本期 = bug 修复 + 交互升级 + 架构收敛 + 并发变体；脚本分镜节点、播放列表→混剪后续单独立项。

定位到的关键根因（实施时对照）：
- IME：受控输入每键经 `updateNodeData→commit→reconcileFlowNodes` 全图解析对账并给所有节点换新 data 对象，卡顿反噬组合输入；现有 `useImeGuardedValue`（nodes.tsx:30-64）治标不治本。
- 位置错乱：`createFromMenu`（CanvasEditor.tsx:190-196）把 wrapper 相对坐标传给要屏幕坐标的 `screenToFlowPosition`，必然偏移；`addAtCenter` 强制 `fitAll()` 视口猛跳 + `nodes.length%2` 网格排布会叠节点。
- 框选怪异：`selectionKeyCode="Shift"` 且 `multiSelectionKeyCode` 含 Shift，语义打架；`zoomOnScroll={false}` 滚轮不缩放。
- 架构债：节点形状在 5 处手写（types/graph/nodes/NODE_LABELS+probeDataFor/addNode+toFlowNode+toGraphNode）；editor-store.ts 817 行巨石。

## 硬约束（红线）

- 迁移只追加（v1 不动，v2 起步），走 `lib/schema-upgrade/` 共享 gate（readiness 已统一接入，零改动即覆盖）。
- 画布模块绝不从 `lib/final-edit/` 导入；共享能力只从 `lib/media-core/` 取。
- `parseCanvasGraph` 严格校验、runs 幂等重放先于一切校验、nodeEpoch 防迟到发布——三条红线语义不变。
- 新颜色一律设计令牌（浅色 `:root` + 深色 `html[data-theme='dark']` 成对）；React Flow 深色覆盖写在 `@layer` 之外；`sc-canvas-*` 在 `@layer components` 内。
- `CanvasEditorController` 公开接口与既有 `data-testid` 尽量保持（Playwright editor/execution/recovery/performance suite 依赖）；确需改的列入测试更新清单。
- UI 文案中文；Apple 极简风格；本地路径走 `dataRoot()`。

## Phase A 基础修复（先治病，可并行，A1 收益最大）

### A1 输入本地化根治 IME
- 新增 `components/creative-canvas/use-node-text-field.ts`：聚焦期间完全本地 state 驱动（忽略 value prop 变化，不经 React Flow data 往返）；防抖 500ms 或失焦提交 `updateNodeData`；未聚焦时同步外部值（撤销/重载生效）。不再需要 composition 分支，天然覆盖 IME。
- `nodes.tsx`：删 `useImeGuardedValue`，四处输入全部换新 hook——TitleInput、PromptNode textarea、GenerationNode prompt、ReferenceRow note（note 现为 defaultValue+onBlur，顺势统一）。
- `editor-store.ts` `updateNodeData` 加快速路径，判定规则：

| patch | 跳过 reconcile？ |
| --- | --- |
| keys ⊆ {title, text, prompt, modelKey, generationMode, parameters} | 跳过（这些字段不参与槽位对账） |
| 含 references / referenceLabelCounter | 走全对账（低频点击，不敏感） |
| 结构变化（nodes/edges/position）→ 走 `commit` 全路径 | 连线增删是槽位对账唯一真实触发源 |
| uploadIntoNode 写 assetId/mediaKind | 走全对账（mediaKind 影响端口类型） |

- 安全网：服务端 `saveCanvasGraph` 保存时无条件 `reconcileCanvasGraph` 不变，最终一致性服务端兜底。

### A2 导航范式重配
`CanvasEditor.tsx` ReactFlow 配参（435-456 行）：
```tsx
selectionOnDrag={!spacePressed}          // 左键拖空白=框选
panOnDrag={spacePressed ? [0, 1] : [1]}  // 空格按住:左键平移;平时:中键平移
zoomOnScroll                             // 滚轮缩放
panOnScroll={false}
zoomOnPinch                              // 触控板捏合缩放
zoomOnDoubleClick={false}
selectionKeyCode={null}                  // Shift 降级为纯多选切换键
multiSelectionKeyCode={['Meta', 'Control', 'Shift']}
```
- 新增空格平移 hook：keydown Space（非 editable target）置 spacePressed；keyup/blur/visibilitychange 复位（blur 兜底防粘滞）；spacePressed 时 wrapper 加 cursor-grab。
- 键盘补全：Cmd/Ctrl+A 全选、Esc 追加清空选择。
- **注意并写进文档**：此配置下触控板双指滚动=缩放（与 ComfyUI 一致），平移靠空格/中键；`panOnScroll` 留作后续偏好项。
- Playwright regression 视口测试（wheel+中键拖）与新范式一致，预期零改动通过。

### A3 位置修复
- `dropMenu` state 改 `{fromNodeId, clientX, clientY, localX, localY}`，`createFromMenu` 用屏幕坐标调 `screenToFlowPosition`（修偏移 bug）。
- `addAtCenter`：落点改视口中心；删 `nodes.length%2` 网格；删强制 `fitAll()`（工具栏 fit-view 按钮保留=测试锚点）。

### A4 报错与反馈体系

### A5 任务并发 UX（多变体前的过渡态）

## Phase D 并发多变体（schema 级，最高风险，最后做）

### D1 schema v2 迁移
追加进 `lib/creative-canvas/schema.ts`（v1 一字不动）：
```sql
DROP INDEX IF EXISTS idx_cct_node_active;                       -- 放开"同节点至多一个活跃任务"
ALTER TABLE creative_canvas_tasks ADD COLUMN variantIndex INTEGER NOT NULL DEFAULT 0;
CREATE INDEX IF NOT EXISTS idx_cct_node_results ON creative_canvas_tasks(canvasId, nodeId, phase, createdAt);
CREATE INDEX IF NOT EXISTS idx_cct_node_phase ON creative_canvas_tasks(canvasId, nodeId, phase);
```
不改表不重建，走共享 gate 自动纳入；`schema_too_new` 前向保护天然覆盖旧版本打开 v2 库场景。

**node_states 语义调整**：`activeTaskId` 降级为"最近创建的任务"（展示用）；`currentAssetId` = 最近发布成功者（最后完成者胜，LibTV 同款）；**nodeEpoch 成为唯一发布门禁**。

**`repository.ts publishCanvasNodeResult` 新门禁**：删 `activeTaskId===taskId` 检查；保留 nodeEpoch 匹配 + 新增防御性断言（任务属于该节点、同 epoch、已 succeeded）；`activeTaskId` 改条件更新（仅等于本次 taskId 时清 NULL）。epoch 相等 ⇒ 节点未被删除重建 ⇒ 迟到发布的唯一真实危害（跨代污染）仍被拦截。

**tasks.ts `createCanvasRun`**：busy 检查仅 branch 模式保留；single 支持 variantCount ∈ {1,2,4} + 单节点活跃任务上限 8（新错误码 `node_variant_limit`）；single 变体同 nodeId 插 N 行（variantIndex 0..N-1），无 task_inputs 互联。

### D2 planner
`CanvasPlanRequest` 加 `variantCount`（仅 single 生效，branch 强制 1 并入指纹 canonical）；`node_busy` 检查移到调用方按 mode 决定；新 problem code `variant_count_invalid`。

### D3 runner/recovery/scheduler
- scheduler **零改动**（名额按任务行粒度，N 变体各自领名额/lease/fence，全局 10 名额自然约束）。
- recovery 逐任务行语义不变；`releaseNodeActiveTask` 已是条件更新天然兼容。
- 多变体同时 polling 且 lease 过期的重启接管竞态：依赖既有每任务独立 fence，无需新代码但**必须显式测试覆盖**。

### D4 UI 候选列表
- `runtime-store.ts`：NodeRuntime 扩展 `activeTasks[]` + `candidates[]`。
- `nodes.tsx`：生成按钮 → 数量分段控件（1/2/4）+ 状态文案（生成/追加变体/重新生成）；NodeStatus 升级多任务徽章行。
- 新增 `ResultCandidates.tsx`：候选缩略图横行、点击切换预览（本地态）、逐个下载、状态徽章；主结果 = currentAssetId，本期**不做手动设主**（后续扩展）。
- `runNode` 请求体带 variantCount。

### D5 API 候选投影（服务端维护）
- `repository.ts` 新增 `listCanvasNodeCandidates`（succeeded 任务按 nodeId 取最近 12 条，走 v2 新索引）。
- `app/api/canvas/[id]/route.ts` 返回体加 `nodeCandidates`（GET/PATCH 都带）；runs 路由校验 variantCount。

## 验证方案

每阶段先跑同名 node 测试（`node scripts/creative-canvas-<模块>.test.ts`），UI 改动跑 `node scripts/creative-canvas.playwright.test.mjs --suite editor|execution|recovery|performance|all`（需先 `npm run build`）：

- **A1**：editor suite（含 IME 用例）+ performance 逐键输入用例；**真机验收**：50+ 节点画布中文拼音逐键流畅、撤销后同步。
- **A2/A3**：editor + regression（视口用例）；新增左键框选/空格平移/Cmd+A/落点偏移回归用例；**真机**：触控板捏合、双指滚动=缩放确认。
- **A4/A5**：editor（toast 锚点兼容）+ execution（run-node 禁用态新断言）。
- **B1/B2/B3**：graph（端口规则等价性）/planner/review-regressions 全跑；editor 全量（撤销/粘贴/历史深度）；recovery。
- **C1–C5**：editor 新增派生/右键/边 hover/默认模型用例；export 不破坏；**真机**：右键手感、动画帧率、浅深双主题走查。
- **D1**：schema 测试扩 v1→v2 升级、全新库、schema_too_new、迁移中断回滚。
- **D2/D3**：planner（指纹区分/busy 按 mode）、scheduler（4 变体并发领取/独立 fence）、recovery + external-recovery（多变体重启接管互不踩踏）、usage（N 变体各自记账）。
- **D4/D5**：api（variantCount 校验/候选投影）；execution 扩 4 变体全链路；performance（50 节点×4 候选轮询开销，长观察挂 `caffeinate`）。

**Playwright 测试更新清单**（行为变更项，需同步改断言）：
1. `status-message` testid 宿主从 banner 改 toast 容器（锚点不变）；
2. execution suite 连击 run-node 场景：A5 改断言禁用 → D4 改断言追加成功（693-802 行逐条过）。

## 风险与回滚

| 风险 | 缓解 | 回滚 |
| --- | --- | --- |
| D1 旧版本打开 v2 库 | `schema_too_new` 前向保护，画布禁用不阻塞旧工作台 | v2 是加法迁移，v2 代码完整兼容 v1 语义数据 |
| D1 迁移失败 | 共享 gate 备份→锁→审计；失败进 compatibility_only | schema-upgrade 恢复候选重验流程 |
| D 并发发布竞态 | SQLite 写事务串行化；"最后完成者胜"是明确定义的产品语义；epoch 拦截跨代污染 | 语义不符预期则后续加 variantIndex 定序补丁 |
| A1 快速路径 references 漂移 | 服务端对账兜底 + 结构变化走全路径 + 判定表排除 | 单 if 分支，revert 即回全量 |
| B2 拆分保存管线回归 | 纯平移不改逻辑；双页冲突用例为验收门 | B2 单独 commit 整体还原 |
| A2 破坏肌肉记忆 | regression 视口用例已与新范式一致 | 一组 props 回退 |

回滚总体策略：四个 Phase 各自成 commit 序列（A 子项独立）；D1 迁移单独 commit 含测试扩展；索引删除是唯一不可逆项，若需恢复单任务约束须先清理多余活跃任务（迁移注释写明）。
