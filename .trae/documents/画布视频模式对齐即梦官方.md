# 画布视频模式对齐即梦官方（全能参考／智能多帧／智能编辑／超长视频）

## 背景

画布视频生成节点的模式划分（文生/图生/视频生/参考生成）与即梦官方产品口径不一致。即梦官方（产品截图 + 方舟 Seedance 2.5 教程 docs.volcengine.com/docs/82379/2607688）的模式是：文生视频／首尾帧／全能参考／智能多帧／智能编辑／超长视频。用户拍板：

- 模式文案对齐官方；**智能多帧独立成模式**（对应方舟「关键帧参考生视频」：多张 reference_image、≥2 张图、omni=reference、比例/时长自由）。
- Seedance 2.5（`external-jimeng-seedance-2-5`，doubao-seedance-2-5-260628）共六个模式：文生视频／全能参考／首尾帧／智能多帧／智能编辑／超长视频（数组顺序即下拉顺序，文生视频在前，其余按官方产品顺序）。
- Seedance 2.5 新增三个真模式：**智能多帧（frames-to-video）**、**智能编辑（video-edit）**、**超长视频（video-extend）**。
- 2.5 的「视频生视频」与「参考生成」两个参考入口**合并为一个「全能参考」**（图/视频/音频混搭，跨类型至少 1 份）。
- Seedance 2.0 保持现有四模式与文案不动；公司渠道不动。

官方合同（2.5）：智能多帧 → 多张 reference_image 关键帧，omni=reference，ratio/duration 自由；edit → `omni_reference_task_type=edit`、ratio 锁 adaptive、duration 锁 -1、参考视频必须 4–30 秒、提示词需含编辑类关键词；extend → `omni=extend`、ratio 锁 adaptive、提示词需含延长类关键词（时长官方仅为「建议 4–30 秒」，不作硬下限）；全能参考 → `omni=reference`、ratio/duration 自由。

另带修一个现存 bug：参数渲染不按 `parameter.modes` 过滤（nodes.tsx L758-821 全量渲染），切换模式后残留的越界参数（如文生切图生后残留的 aspectRatio）会让 planner 报 `parameter_not_supported`。

## 实现步骤

### 1. 类型层（新枚举只增不删）

- `lib/creative-canvas/types.ts`：`CanvasGenerationMode` 与 `CANVAS_GENERATION_MODES` 追加 `'frames-to-video' | 'video-edit' | 'video-extend'`（注释：frames-to-video=方舟关键帧参考生视频；edit/extend=方舟 omni 子任务）。`video-to-video` 保留在枚举中（旧图反序列化兼容），只从 2.5 能力表摘掉——旧 2.5+video-to-video 节点提交时报 `mode_not_supported`，用户手动切到全能参考，不做自动迁移。
- `lib/video-providers/types.ts`：`SubmitReferenceVideoRequest` 增加可选 `omniReferenceTaskType?: 'reference' | 'edit' | 'extend'`；注释：`durationSec: -1` 仅 2.5 编辑子任务透传。

### 2. jimeng 适配器（`lib/video-providers/jimeng.ts` submitReference）

- omni 字段请求化：`if (isSeedance25(request.model)) body.omni_reference_task_type = request.omniReferenceTaskType ?? 'reference'`（2.0 由 isSeedance25 门掉，绝不发送——现有测试断言保留）。
- 时长：`request.durationSec === -1 && isSeedance25(request.model)` 时透传 -1，否则走 `normalizeJimengDuration(..., maxJimengDurationSec(model))`（-1 不能被钳成 4）。
- ratio 不改：调用方对 edit/extend 显式传 `aspectRatio: 'adaptive'`。

### 3. 能力表设施（`lib/creative-canvas/capabilities.ts`）

- `CanvasModelCapability` 新增可选字段：
  - `mediaInputMinimums?: ReadonlyArray<{ modes: ReadonlyArray<CanvasGenerationMode>; min: number }>`——跨类型「非 text 输入合计 ≥ N」（单规则 min 表达不了混搭）。
  - `modeLabels?: Partial<Record<CanvasGenerationMode, string>>`、`modeHints?: Partial<Record<CanvasGenerationMode, string>>`——按模型覆盖界面模式名/提示（2.5 的 reference-to-video→全能参考、image-to-video→首尾帧；2.0 用全局文案）。
- `validateCapabilityInputs`：per-rule 校验后追加 mediaInputMinimums 检查，复用 `input_count_below_minimum` problem code，不新增 code。

### 4. 2.5 能力表（`lib/creative-canvas/adapters/external-capabilities.ts`，2.0 整段不动）

- `modes: ['text-to-video', 'reference-to-video', 'image-to-video', 'frames-to-video', 'video-edit', 'video-extend']`（即下拉顺序：文生视频/全能参考/首尾帧/智能多帧/智能编辑/超长视频，文生在前、其余按官方产品顺序）。
- inputs：首尾帧规则保持原样（image-to-video，1–2 图）；全能参考（reference-to-video）：image 0–9、video 0–3（maxDurationSec 30）、audio 0–3；智能多帧（frames-to-video）：**image min 2–9**（关键帧至少 2 张，不给 video/audio 规则——接入即报 input_kind_not_supported）；edit/extend：video min 1–3（maxDurationSec 30）、image 0–9、audio 0–3。
- `mediaInputMinimums: [{ modes: ['reference-to-video'], min: 1 }]`（智能多帧由 image min:2 覆盖，无需列入）。
- parameters：`durationSec` 的 modes 排除 video-edit（edit 锁 -1，界面隐藏），包含 frames-to-video；`aspectRatio` 收窄为 `['text-to-video', 'reference-to-video', 'frames-to-video']`（edit/extend/首尾帧都锁 adaptive）。
- `modeLabels`/`modeHints` 按 §3 字段配置；`evidenceNote` 更新：edit/extend 与 duration=-1 为本地请求映射验证，真实样例未跑。

### 5. 外部适配器（`lib/creative-canvas/adapters/external.ts`）

- `REFERENCE_MODES` 追加 `'frames-to-video'`, `'video-edit'`, `'video-extend'`——参考交付（COS 强制）与组合校验自动覆盖新模式。
- submit 参考分支按模式映射：`video-edit → omni:'edit' + ratio:'adaptive' + durationSec:-1`；`video-extend → omni:'extend' + ratio:'adaptive'`；frames-to-video 与其余参考模式 `omni:'reference'`、ratio/duration 取节点参数。
- prepare 前置校验（把方舟异步失败前置为同步报错，code `prompt_keyword_missing`）：
  - edit：提示词需命中编辑类关键词（中英文：编辑/修改/替换/改成/删除/去掉/移除/增加/添加/edit/remove/replace/add…）；
  - extend：需命中延长类关键词（延长/延续/续写/向前/向后/extend/continue…）。
  - edit 的参考视频单段下限收紧为 4 秒（官方硬要求）；**extend 保持 2 秒下限**（官方仅「建议」），上限均 30 秒。`referenceCombinationProblems` 增加 mode 参数。

### 6. planner（`lib/creative-canvas/planner.ts` buildPlanTask）

- 校验前计算 `effectiveParameters`：已知参数但 `parameter.modes` 不含当前模式 → **静默丢弃**；未知 key 保留（继续报 parameter_not_supported，不吞真实违例）。校验与计划任务都用 effectiveParameters。
- 效果：切模式后残留越界参数不再炸计划（顺带修掉现存 bug）。

### 7. 节点 UI（`components/creative-canvas/nodes.tsx`）

- `MODE_LABELS` 追加 `'frames-to-video': '智能多帧'`、`'video-edit': '智能编辑'`、`'video-extend': '超长视频'`；渲染改为 `capability?.modeLabels?.[mode] ?? MODE_LABELS[mode] ?? mode`。`REFERENCE_MODE_HINTS` 同理支持 `modeHints` 覆盖（智能多帧提示：≥2 张关键帧图，模型在帧间生成连续过渡）。
- 模式下拉 onChange：同一 `updateNodeData` 里 prune 掉 `parameter.modes` 不含新模式的参数键（FAST_PATH_DATA_KEYS 已含 generationMode+parameters，可走快速路径）。
- 参数渲染加过滤：`capability.parameters.filter(p => !p.modes || p.modes.includes(currentMode))`——edit 模式下时长/比例控件自动消失。

### 8. 文档

- `docs/reference/创作画布.md`：「视频模式各有独立合同」「参考素材约束落在 prepare」两条改写为按代际（2.0/2.5）与五模式描述，补 omni 子任务映射与 duration=-1 透传约定。

### 9. 测试

- `scripts/jimeng-video-adapter.test.ts`：新增 2.5+edit（omni=edit、duration=-1 不被钳、ratio=adaptive）、2.5+extend（omni=extend、duration 透传）、2.0 带 omniReferenceTaskType 也不发送。
- `scripts/creative-canvas-providers.test.ts`（10.x 续编号）：全能参考仅 1 段视频（旧 image min:1 会拒，验证合并）；全能参考零媒体 → capability_unavailable；智能多帧 2 图 → 恰好 1 POST（omni=reference、两个 reference_image、ratio/duration 取节点参数）；智能多帧仅 1 图 → capability_unavailable；智能多帧接入视频 → capability_unavailable；智能编辑正常链路（omni=edit、ratio=adaptive、duration=-1，残留参数不影响）；缺编辑关键词 → prompt_keyword_missing；编辑参考视频 3s → prepare 失败；超长视频（omni=extend、duration 透传）。现有 10.5–10.8 作回归。
- `scripts/creative-canvas-planner.test.ts`：当前模式不接受的已知参数被静默丢弃、未知 key 仍报错。
- `scripts/creative-canvas-graph.test.ts`：新枚举值可反序列化，非法值仍 invalid_node。
