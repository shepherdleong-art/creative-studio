性质：执行文档，一张卡一个 commit，不自动 push。

配套诊断：`scripts/probe-luna-script-gen.ts`（PS515 复跑 `generateScriptV3`，真实调用公司网关）

## 0. 为什么要做

用户反馈：**「脚本生成和图片绑定太深，卖点、脚本类型、图片有一丁点对不上就直接拒绝生成。有些产品图片数量不多、种类不多，很难受。」**

代码勘察确认这不是模型能力问题，是校验层的设计问题：**三类"审美偏好"被写成了"生成前置条件"，而且全是一票否决，一份写得很好的口播正文会因为一个封面标题词不合规而被整份丢掉。**

### 0.1 三道闸门（实测定位）

**闸门 1：模板可行性一票否决** — `lib/script-generation-v3.ts:488` `assertMaterialFeasible()`

模型只要返回一次 `templateFeasible: false`，第 1 次尝试就抛 `ScriptMaterialMismatchError`，不重试、不降级。`scripts/script-generation-v3.test.ts:401` 还专门断言了「模板和素材不匹配时应立即停止，不能盲目重试」。

提示词把门槛定在 5/5 全覆盖（`lib/script-generation-v3.ts:587`）：

> 先判断**全部** template.narrativeStructure 是否都有附图承接；**若任一核心阶段缺少画面**，返回 templateFeasible=false 和空 segments，禁止硬写

7 个模板每个 5 个叙事阶段。「开箱体验」要拆包→取出→安装→首次使用，「对比测评」要使用前 vs 使用后 —— 一套场景图**结构性地不可能**有这些画面。对少图产品来说，一半模板是天生不可行的，跟模型发挥无关。

**闸门 2：封面标题 29 个条件全是与运算** — `lib/script-generation-v3.ts:291-321`

一个 8-22 字的标题要同时满足 29 条才算过。最难的是两条交叉引用：

- 品类词必须**原样**出现在某段 `visualKeywords` 里，且那段的 `visualRefs` 要和标题 `visualRefs` 命中同一张图；
- 场景词同理。

而且词表写死成家具专用：`secondaryValuePhrase` 必须从「必备 / 氛围担当 / 优雅之选 / 舒适之选 / 安心之选 / 质感之选 / 空间亮点 / 日常搭档 / 松弛搭档」9 个里原样选一个，**不允许留空**。非家居品类（3C、美妆、食品）拼不出合法标题。

标题不合规 = 整份脚本作废。3 次机会耗完就是 PS515 那条「两次修正后仍未返回有效脚本结构」（`script_contract_invalid`）。

**闸门 3：策略分析和脚本生成互相不认账**

分析阶段 requirements 明写（`lib/script-generation-v3.ts:887`）：「不分析分镜图片；图片承接能力在脚本生成阶段单独判断」。于是分析可以推荐「开箱体验」，生成再以「图片承接不了开箱」把它毙掉 —— **用户按系统的推荐走，反被系统拒绝。**

**附带：错误信息在半路被吞掉两次**

- `generateAndPersistScriptV3` 直接把 `ScriptGenerationV3Error` 抛出去，没转成带 `error` code 的 body；manager 的 catch 分支（`lib/script-generation-manager.ts:226`）统一写成 `code: 'script_generation_error'` —— **错误码丢了**。
- `sanitizeError`（`lib/script-generation-manager.ts:121`）只保留 `{ code, message }` —— **`details` 里的 `unsupportedNarrativeBeats` / `validationIssues` 全丢了**。
- 前端只剩 `alert('生成失败: ' + message)`（`components/ScriptPanel.tsx:296`），死胡同。

### 0.2 根因一句话

校验层混淆了两类规则：

| 类别 | 例子 | 该不该阻断 |
|---|---|---|
| **不许编造**（防幻觉） | 每段必须有 `visualRefs`、只能引用真实存在的 `sellingPointId`、不得虚构参数 | ✅ 必须硬拦，这是这套设计的价值所在 |
| **必须齐全 / 必须合格式**（质量偏好） | 5 阶段全覆盖、标题 29 条、封闭词表、`sellingPointUsage` 登记格式 | ❌ 被错误地写成了生成前置条件 |

**本轮要守住第一类，放开第二类。不能一刀切全放 —— 一旦放开「不许编造」，这个产品的核心价值（脚本内容有画面依据）就没了。**

## 1. 目标与范围

### 1.1 目标

一句话：**永远有稿出，且明确告诉用户缺什么。**

- 素材不足时降级出稿，而不是拒绝；
- 缺失的叙事阶段、兜底的封面标题、未采用的卖点，全部以**警告**形式随脚本返回并在界面显示；
- 只有真正无法产出内容（一段合法 narration 都写不出）才算失败，且失败时给出可点的下一步。

### 1.2 本轮包含

| 卡 | 内容 |
|---|---|
| 卡 1 | 校验分级基座：`blocking` / `advisory` + 最优候选保留 |
| 卡 2 | 模板可行性从一票否决改成降级出稿 |
| 卡 3 | 封面标题三级兜底 |
| 卡 4 | `sellingPointUsage` 改服务端推导 |
| 卡 5 | 错误码与 details 打通到前端 |
| 卡 6 | UI：警告条 + 可操作失败面板 |
| 卡 7 | 封面词表去家具化（低优先，可延后） |

### 1.3 本轮不包含

- **时长校验（`script_duration_unresolved`）保持现状不动。** 时长是真实功能约束（`script-duration-policy` 给封面预留了 20 帧、批量渲染按预算切轨），不是审美偏好。卡 1-4 落地后模型腾出的空间会显著提高一次过率，先观察再决定要不要放宽。
- 策略分析阶段（`analyzeScriptStrategyV3`）的校验逻辑；只在卡 2 让它的推荐结果能被生成阶段的 `suggestedTemplateId` 覆盖。
- `lib/batch-production/` 的脚本导入路径（`scripts.ts:198` 走 `splitCoverTitle(title)`，与本轮无关）。
- 智能混剪 `lib/final-edit/` 的渲染逻辑。
- 数据库迁移 —— **本轮不需要任何迁移**，`script_drafts.outputJson` 是自由 JSON。

## 卡 1：校验分级基座

### 1.1 现状

`normalizeCandidate`（`lib/script-generation-v3.ts:511`）里所有校验都 `throw ScriptOutputValidationError`，重试循环（`:944`）三次耗尽后统一抛 `script_contract_invalid`。**没有"部分合格"这个中间态。**

### 1.2 改动

在 `lib/script-generation-v3.ts`：

1. 给 `ScriptOutputValidationError` 加 `severity: 'blocking' | 'advisory'`（构造函数第二参，默认 `'blocking'` 保持旧行为）。

2. 定义分级口径（**这张表是本轮的合同，后面所有卡都按它走**）：

| 校验 | 位置 | 级别 |
|---|---|---|
| JSON 不可解析 / 空响应 | `:963` | blocking |
| `segments` 无一段非空 narration | `:520` | blocking |
| 段落引用了不存在的 `sellingPointId` | `:404` | blocking |
| 段落 `visualRefs` 为空或引用非法 | `:419` | blocking |
| 段落缺 `visualIntent` / `visualKeywords` | `:416` | blocking |
| `materialAssessment.templateFeasible` 非布尔 | `:505` | blocking |
| 封面标题 29 条中的「引用非法 visualRef / sellingPointId」 | `:377`、`:380` | blocking |
| 封面标题其余 27 条（长度、词表、拼接、交叉承接、泛称） | `:327`-`:374` | **advisory** |
| `sellingPointUsage` 登记不合法 / 覆盖不全 | `:468`、`:481` | **advisory**（卡 4 会整个删掉） |
| `unsupportedNarrativeBeats` 不在模板阶段列表内 | `:495` | **advisory**（卡 2 会改写） |

3. 把 `normalizeCandidate` 的返回改成：

```ts
interface ScriptCandidate {
  script: ScriptOutputV3;
  qualification: 'qualified' | 'too_short' | 'too_long';
  advisories: string[];   // 未阻断但已降级的原因，逐条可读
}
```

`normalizeCandidate` 只在 blocking 时 throw；advisory 收集进 `advisories`，并**就地应用兜底值**（标题走卡 3，usage 走卡 4）。

4. 改重试循环的**终止行为**（`:944-1018`），这是本卡的核心：

```
for attempt in 1..3:
    调用模型
    try  normalizeCandidate
    catch blocking → 记 lastValidationIssues，rewritePrompt，continue

    // 走到这里 blocking 全过
    if advisories 为空 && qualification === 'qualified':
        立即返回（一次过，行为与今天完全一致）

    // 保留"目前最好的一份"：先比时长合格，再比 advisories 少
    bestCandidate = better(bestCandidate, candidate)
    rewritePrompt(带 advisories 定点修正)，continue

循环结束：
    if bestCandidate 存在 && bestCandidate.qualification === 'qualified':
        返回 { script: bestCandidate.script（已含 warnings）, attempts: 3 }   ← 新增的成功出口
    if bestCandidate 存在:
        抛 script_duration_unresolved（时长本轮不放宽，保持现状）
    抛 script_contract_invalid（一次 blocking 都没过 —— 真失败）
```

5. `ScriptOutputV3` 加可选字段（`lib/script-providers/types.ts:121` 附近）：

```ts
export type ScriptWarningCodeV3 =
  | 'unsupported_narrative_beats'
  | 'cover_title_fallback'
  | 'selling_point_derived';

export interface ScriptWarningV3 {
  code: ScriptWarningCodeV3;
  message: string;                 // 面向用户的中文，直接上界面
  unsupportedNarrativeBeats?: string[];
  suggestedTemplateId?: string;
  suggestedTemplateName?: string;
}

// ScriptOutputV3 新增：
warnings?: ScriptWarningV3[];
```

**必须是可选字段** —— 历史草稿没有这个字段，`ScriptResultView` / 混剪 / 批量都要能照常读。

### 1.3 坑

- `advisories`（面向模型的修正提示，中文可操作）和 `warnings`（面向用户的结论）是**两个东西**，不要混用同一个数组。前者进 `rewritePrompt`，后者进 `script.warnings`。
- `better()` 的比较必须**稳定且确定**：先比 `qualification === 'qualified'`，再比 `advisories.length` 少，相同则保留**先出现的**（不要用后者覆盖，否则同状态重跑结果会漂）。
- 保留 `attempts` 字段语义不变（`script-generation-v3-service.ts:279` 写进 `inputSnapshot`）。

### 1.4 验证

- `node scripts/script-generation-v3.test.ts`
- 现有「一次过」用例（`:282` 附近）必须原样通过，`attempts` 不变。

## 卡 2：模板可行性改降级

### 2.1 现状

`assertMaterialFeasible`（`:488`）：`templateFeasible === false` → 直接抛，整份作废。

### 2.2 改动

1. **改提示词**（`lib/script-generation-v3.ts:586` `SCRIPT_TEMPLATE_REQUIREMENTS` 第一条），把「禁止硬写」换成「降级出稿」：

```
若部分叙事阶段缺少画面承接：仍必须产出完整脚本，把缺失阶段合并或跳过、其余阶段照常推进，
并在 unsupportedNarrativeBeats 中原样列出被跳过的阶段；
同时在 suggestedTemplateId 给出 allowedTemplates 中更契合当前图片的模板 id。
只有全部叙事阶段都无任何画面承接时，才返回 templateFeasible=false 和空 segments。
```

同步改系统提示词（`:955`）中的「不能承接时明确返回素材不匹配」→「部分阶段不能承接时降级出稿并列出缺失阶段」。

2. **`SCRIPT_OUTPUT_CONTRACT.materialAssessment`（`:593`）加字段**：

```ts
suggestedTemplateId: 'string；可为空；当前图片更契合的模板 id，只能取自 allowedTemplates'
```

生成提示词（`generationPrompt`，`:643`）需要把 `allowedTemplates`（id + name + suitable）一起传下去 —— 现在只传了当前选中的一个模板，模型没法推荐别的。

3. **`assertMaterialFeasible` 改名 `readMaterialAssessment`，返回值代替抛异常**：

```ts
function readMaterialAssessment(raw, input): {
  unsupportedNarrativeBeats: string[];
  reason: string;
  suggestedTemplate?: { id: string; name: string };
}
```

- `templateFeasible` 非布尔 → 仍抛 blocking；
- `unsupportedNarrativeBeats` 里有不在 `template.narrativeStructure` 的项 → **过滤掉**并记一条 advisory（不再抛）；
- `suggestedTemplateId` 不在 `SCRIPT_TEMPLATES` 里 → 丢弃，不报错；
- 有缺失阶段 → 产出一条 `warnings` 条目：

```
code: 'unsupported_narrative_beats'
message: `当前分镜图片没有覆盖《${templateName}》的 ${n} 个叙事阶段，已按可承接的部分改写。${suggested ? `更契合这批图片的模板是《${suggested.name}》。` : ''}`
```

4. **真失败的判定挪到 segments**：`templateFeasible === false && groundedSegments.length === 0` → 抛 `ScriptMaterialMismatchError`（带 beats + reason + suggestedTemplate）。这条**不再是一次性**：第 1 次遇到时按 blocking 走重写（提示词里加一句「必须降级出稿，不得返回空 segments」），**第 2 次仍然空**才向上抛 `script_material_mismatch`。

5. `ScriptMaterialMismatchErrorDetails`（`:87`）加 `suggestedTemplateId?` / `suggestedTemplateName?`。

### 2.3 坑

- `unsupportedNarrativeBeats` 是**原样字符串匹配**模板阶段文案。模型很容易改写一两个字，过滤后可能变空数组 —— 这时不要报 advisory，按「阶段全覆盖」处理即可，不要因为字符串没对上就制造假警告。
- `suggestedTemplateId` **不能自动改模板重跑**。自动换模板会让用户完全失去控制（他明确选了模板）。只做建议 + 卡 6 的一键按钮。
- 别忘了 `rewritePrompt`（`:668`）也要带上新的 `allowedTemplates` 和改过的 requirements，否则重写轮又回到旧口径。

### 2.4 验证

- **必须改** `scripts/script-generation-v3.test.ts:401` 的断言 `calls === 1`。新语义是：第 1 次 `templateFeasible=false` + 空 segments → 重写；第 2 次仍空 → 抛 `script_material_mismatch`，`calls === 2`。
- 新增用例：`templateFeasible=false` + **非空** segments + 合法 beats → **成功返回**，且 `script.warnings` 含 `unsupported_narrative_beats`。
- 新增用例：`suggestedTemplateId` 非法 → 被丢弃，不影响出稿。
- `:432` 那条（beats 混入非法阶段）语义变了：非法阶段被过滤而不是抛错，用例要重写。

## 卡 3：封面标题三级兜底

### 3.1 现状

`normalizeTitleParts`（`:255`）29 条与运算，`valid` 为假就抛，整份作废。`coverTitleParts.source` 类型已有 `'model' | 'system_split'`，但 V3 生成路径**从来不会走到 `system_split`** —— 这条兜底通道在 V3 里是死的（`components/ScriptResultView.tsx:161` 的提示 UI 也就永远不显示）。

### 3.2 改动

1. `coverTitleParts.source` 联合类型加 `'system_composed'`，需同步改三处：
   - `lib/script-providers/types.ts:124`
   - `lib/final-edit/mixcut-script.ts:18` 和 `:42`
   - `components/ScriptResultView.tsx:161`（判断改成 `source !== 'model'`）

2. `normalizeTitleParts` 改成 `resolveTitleParts`，三级兜底：

**第 1 级 —— 严格结构**（现有 29 条全过）→ `source: 'model'`，无 advisory。

**第 2 级 —— 沿用模型措辞，只查安全底线**。29 条里只保留这几条：
   - `primary` / `secondary` 都非空，且有效字数 2-16；
   - 无句读标点（`hasNoSentencePunctuation`）；
   - 不在 `GENERIC_COVER_TITLE_KEYS` 万能标题黑名单里；
   - 两句不相同、不互相包含（`titlesAreComplementary`）。

   过了就用模型原文 → `source: 'system_composed'` + advisory「封面标题未满足结构规则，已沿用模型措辞」。

   > 这一级是本卡的重点。模型写的标题通常**没问题**，只是没通过"品类词要原样出现在某段 visualKeywords 里"这种交叉引用规则。为了一条形式规则丢掉一个好标题（更别说丢掉整份脚本）不划算。

**第 3 级 —— 服务端合成**。第 2 级也不过时：
   - `primary` = 排名第 1 卖点 title 中截取的 2-6 字证据词 + 品类词（品类词依次取 `rawParts.productCategoryTerm` → `input.productCategory` → 从 `visualKeywords` 里挑一个非泛称词）；
   - `secondary` = `splitCoverTitle(script.title).secondary`，为空则用固定安全短语；
   - → `source: 'system_composed'` + advisory。

   合成结果仍要过第 2 级的安全底线；再不过就退到 `splitCoverTitle(script.title)`，**绝不抛异常**。

3. 只要 `source !== 'model'`，产出 `warnings` 条目：

```
code: 'cover_title_fallback'
message: '封面标题未通过结构校验，已使用兜底标题，建议进入智能混剪前手动确认。'
```

### 3.3 坑

- **降级标题会被批量生产烧进封面。** `lib/batch-production/script-catalog.ts:28` 直接读 `coverTitleParts`，`batch-renderer.ts` 会把它合成到封面图上。所以卡 6 的界面提示必须**显眼**，不能只是一行小灰字。
- `titleKey()` 做了 NFKC + 去标点 + 小写，第 2 级的黑名单比对要继续用它，别改成裸字符串比较。
- 第 3 级的证据词截取不要产生病句（"软弹沙发沙发"）—— 复用现成的 `titlePartsDoNotOverlap` 做一次自检，重叠就只用品类词。
- 保留原来那 27 条的 `issues` 文案 —— 它们现在作为 advisory 进 `rewritePrompt`，仍然是让模型下一轮写对标题的唯一依据，**不要因为不再抛异常就把这段删了**。

### 3.4 验证

- `scripts/script-generation-v3.test.ts:465` / `:505` / `:534` / `:572` 四条标题用例语义全变：不再断言「必须重写到过」或「最终失败」，改为断言「重试后仍不合规 → 成功返回 + `source: 'system_composed'` + 有 `cover_title_fallback` 警告」。
- 新增：非家居品类（`secondaryValuePhrase` 无合法值可选）也能出稿。
- `node scripts/final-edit-mixcut-script.test.ts`、`node scripts/batch-script-catalog.test.ts` 确认新 `source` 值不炸下游。

## 卡 4：`sellingPointUsage` 改服务端推导

### 4.1 现状

`normalizeSellingPointUsage`（`:440`）要求模型自己登记一张覆盖全部卖点的表，登记不合法或漏项就抛。但这张表的**每一个字段服务端都能自己算出来** —— `status` 完全由「该卖点是否出现在某段 `sellingPointIds` 中」决定，`title` 从 `sellingPointById` 查。只有 `reason` 是模型独有的信息。

让模型重复登记一份服务端已知的数据，然后因为登记格式不对而作废整份脚本，是纯粹的自伤。

### 4.2 改动

改成服务端推导，模型的 `sellingPointUsage` 只作为 `reason` 的来源：

```ts
sellingPointUsage = sellingPoints.map((point) => ({
  sellingPointId: point.sellingPointId,
  title: point.title,
  status: groundedSegments.some((s) => s.sellingPointIds.includes(point.sellingPointId))
    ? 'used' : 'omitted_no_visual_support',
  reason: 模型给的对应 reason（存在且非空时）
    ?? (used ? '正文已引用该卖点' : '当前分镜图片缺少支撑该卖点的画面证据'),
}));
```

- 不再校验 `status` / `visualRefs` 一致性 —— 服务端算出来的天然一致；
- 模型漏登记 / 多登记 / 登记错 → 静默忽略，只在**有卖点被降级为 `omitted_no_visual_support`** 时产出 advisory，让下一轮有机会补上；
- 若最终仍有卖点未采用，产出 `warnings`：

```
code: 'selling_point_derived'
```

## 4. 纪律与红线

1. **不许放开「不许编造」那一类校验。** 段落必须有 `visualRefs`、只能引用真实存在的 `sellingPointId` / `visualRef`、不得虚构参数 —— 这几条是 blocking，一条都不能降级。降级的是"必须齐全/必须合格式"，不是"必须有依据"。
2. **不许自动换模板。** 用户明确选了模板，系统只能建议，不能替他改。
3. **不许静默降级。** 每一次降级都必须在 `script.warnings` 里留痕并显示到界面。用户可以接受"素材不够但先出稿"，不能接受"不知道自己拿到的是降级稿"。
4. **不改数据库。** 本轮零迁移；`warnings` 是 `outputJson` 里的可选字段，老草稿读出来就是没有，正常。
5. **历史草稿必须能照常打开。** 改完后随手开一份改造前生成的 V3 草稿确认不白屏。
6. **时长校验本轮不动。** 想放宽时长另开一轮，不要混在这批里。
7. 不自动 push。
