## 修复与验证

固定渲染运行期原先读取开发目录的 setup 脚本来判断 Chrome 版本，并直接读取原始 TS 文件记录构建器哈希；源码被裁剪后的交付目录无法满足这些依赖。classic 模板还假定包装资源位于数据根，在数据与程序目录分离时会找错位置。

本轮改为读取随包 `film-runtime.json`，setup 也读取同一契约；构建时归档固定清单中的构建器源码及 SHA256，运行时只核验来源、不执行归档源码；模板查找改用共享包装资源解析器。存在随包归档时优先校验归档，不能借旁边的开发源码掩盖资源损坏。没有放宽本地数据、密钥或开发目录的打包禁入清单。

| 验证 | 结果 |
| --- | --- |
| 版本契约、声明/锁文件/安装版本、Chrome 错配与缺件 | 通过；无 setup 脚本时正常检查 |
| 随包构建器清单 | classic 与叠层构建器 SHA256 与源码一致；篡改、清单缺失拒绝；开发源码不能掩盖归档损坏 |
| standalone 资源边界 | 通过，保留运行资源并排除用户字体、渲染缓存、数据及密钥 |

隔离测试将核心依赖的 34 个模块编译并打包，移除测试应用中的 `lib/` 和入口源码，运行资源复制自 `.next/standalone/packaging`，第三方原生依赖取自生产 node_modules；数据根为独立临时目录，未设置包装目录覆盖变量。实际运行使用 Node 22.22.2、HyperFrames 0.8.134、Chrome 152.0.7977.30、FFmpeg 6.0、FFprobe 4.4-tessus。所有素材为 P0 已有合成样本，没有调用生成供应商或写入用户项目数据库。

并排抽帧已实际查看，封面、正文字幕与标签在抽样位置相同。这不代表真实产品保真或完整人工听审。

## 证据与复跑

证据目录：`outputs/2026-10-17-reassembled-p1/`（本机数据，不进 Git）。

- `build.log`：完整生产构建结果。
- `portable-render.log`：最终成功的隔离测试，包含各阶段及进程成功结果。
- `summary.json`：结果摘要及原始临时工程位置。
- `portable-result.json`、`portable-checks.json`、`portable-comparison.json`：运行时、完整渲染清单、技术检查及对比证据。
- `portable-comparison.jpg`：12 帧并排对照。

构建后执行 `node scripts/film-render-portable.test.mjs` 可验证资源边界；实际渲染追加两个环境变量：`FILM_PORTABLE_SPEC` 指向已有有效 spec，`FILM_PORTABLE_REFERENCE` 指向同一 spec 的参考 MP4，参考片旁须保留其构图文件。默认清理无渲染测试目录；实际渲染保留临时工程并打印路径。

最初测试夹具使用未打包 JS，误把 Next 会内联的 fontkit 当成生产缺失依赖；改为打包纯 JS 依赖、外置原生媒体依赖。第二次完整出片后，对比夹具因输出在工程外而被正确拒绝；修正目录和参考构图传递后重新完整渲染、对比通过。失败不能计作验收通过；第二次日志保留在 `portable-render-attempt2.log`。
