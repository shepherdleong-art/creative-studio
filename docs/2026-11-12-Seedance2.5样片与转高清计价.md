# Seedance 2.5 样片与转高清计价

2026-11-12，用户确认公司 Seedance 2.5 直连使用火山方舟 API，样片与转高清采用官方刊例价。适用精确模型 `doubao-seedance-2-5-260628` 的画布 `draft` / `final-from-draft` 任务。

## 单价与示例

| 阶段 | 分辨率 | 原始输入不含视频 | 原始输入包含视频 |
| --- | --- | --- | --- |
| 样片 | 480p | 70 元/百万 token | 42 元/百万 token |
| 样片转高清 | 1080p | 77 元/百万 token | 46 元/百万 token |

文字、图片及音频参考均不算视频参考。转高清依据原样片的输入确定价格档位，样片视频本身不算新增的视频参考。两个任务独立收费，样片费不抵扣高清费。

以 5 秒、16:9、无视频参考为例：480p 样片约 3.36 元，1080p 高清约 18.71 元，两阶段合计约 22.07 元。以 API 返回的 `usage.completion_tokens` 计算实际费用；上述示例是按像素与时长估算的金额。

| 样片时长 | 无视频参考的 480p 预计费用 |
| --- | --- |
| 5 秒 | 约 3.36 元 |
| 10 秒 | 约 6.73 元 |
| 15 秒 | 约 10.09 元 |
| 30 秒 | 约 20.18 元 |

官方依据：[模型价格](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)、[Seedance 2.5 输出尺寸与样片说明](https://docs.volcengine.com/docs/ark/seedance-2-5?lang=zh)。上表按官方 854×480、24 fps 计算，保留到分；实际 token 用量可能不同。

## 视频参考的最低 token 与提交前报价

2026-11-12 核对了官方价格页链接的 [Seedance 2.5 最低用量表](https://bytedance.larkoffice.com/wiki/FXaYwxzJ5i5Zdik32ipcWzt7nxd?table=tblheIYDXXwYM43b&view=vew2CR2JYM) 和 [Seedance 2.5 价格计算器](https://bytedance.larkoffice.com/share/base/form/shrcnhVCMxKxcwW1QML5r9u8nvh) 的公开字段公式。该表 339 条参考记录在 4–30 秒输出时长下的最低输入秒数均符合下述规则：

```text
最低参考视频时长 = ceil(输出视频时长 × 2 / 3)
普通估算 token = (实际参考视频总时长 + 输出时长) × 输出宽 × 输出高 × 24 / 1024
最低 token = (最低参考视频时长 + 输出时长) × 输出宽 × 输出高 × 24 / 1024
提交前报价 token = max(普通估算 token, 最低 token)
```

多个视频先合计实际时长，最低时长只应用一次。输入图片、音频不计视频时长；未知/零/无效的视频时长不按零放行。两阶段分别采用 480p / 1080p 的输出像素与 42 / 46 元每百万 token；转高清只继承原样片的参考视频总时长，样片视频本身不额外计入。

| 输出时长 | 最低计费参考视频时长 |
| --- | --- |
| 4 秒 | 3 秒 |
| 5 秒 | 4 秒 |
| 6 秒 | 4 秒 |
| 7 秒 | 5 秒 |
| 10 秒 | 7 秒 |
| 15 秒 | 10 秒 |
| 30 秒 | 20 秒 |

例如 5 秒输出、16:9、参考视频合计 3 秒：480p 样片按约 86,467.5 token 估算，约 3.631635 元；转 1080p 按约 437,400 token 估算，约 20.1204 元。团队预算按分向上取整，分别预留 **3.64 元、20.13 元**；成功后仍按供应商返回的实际 token 结算。前述 token 是公式估算值，官方表的整数显示与 API 返回可能略有不同。

最低用量规则版本 `seedance-2-5-video-minimum-2026-11-12`、普通估算 token、最低 token、计价 token 和最低参考时长会随提交前报价保存。4–30 秒阈值从官方表抽取到 `scripts/fixtures/seedance-2-5-minimum-token-thresholds.json`，供离线回归使用。

## 记账行为

- `lib/seedance-2-5-pricing.ts` 集中保存官方阶段单价、像素表和估算公式；`usage-pricing.ts` 按阶段生成 token 计价计划，版本为 `seedance-2-5-ark-2026-11-12`。
- 画布提交前以冻结参数报价；转高清从同画布、同模型和渠道的已完成样片读取输入、时长及比例。报价不会把样片重复计为视频参考，也不会加上或减去样片费用。
- 成功产物落库后优先按供应商返回的 `completion_tokens` 记账。无视频参考且缺少实际 token 时，按产物实际宽高、时长和 24 fps 估算，并在明细标记 `estimated: true`。
- 带视频参考的样片/转高清在提交前按上述官方最低规则预留，成功后按实际 token 记账；缺少实际用量仍待核对，不把预留额写成实际消耗。自动时长及无法确定尺寸或参考视频时长的任务仍不伪造零元费用。
- 样片/转高清在受理时不把预留当作实际消耗，失败不写成功费用。查询、补下载及重复记账按原 task/attempt 事件键去重。历史账本与冻结快照不重写；普通 `direct` 任务沿用原账单均价，本次只补两个阶段。
- 团队 execution 的金额单位为分，预留/结算沿用已有向上取整规则；账本保留整数微元，界面的舍入位数可能不同。

回归：`node scripts/seedance-2-5-pricing.test.ts`、`node scripts/creative-canvas-seedance-stage-usage.test.ts`。其余关联回归为 `usage-pricing`、`usage-ledger`、`creative-canvas-usage` 和主流程检查；全部使用本地模拟，不发送付费请求。

## 提交前审查修正

结算与账本从执行尝试的冻结报价读取 token 单价，再乘供应商实际 token 用量；历史已提交但未计价的阶段任务继续保留未计价，不在完成后补套新价格。与 H3 共用只读报价快照读取器。回归覆盖样片、转高清分别使用不同冻结单价，以及旧未计价尝试；不重写既有账本，也不重新生成。

自动时长尚不能预留金额时，报价仍保存已知单价与版本；产物返回实际 token 后再按冻结单价晚到结算。仅历史通用未计价快照缺少单价，继续保持未计价。
