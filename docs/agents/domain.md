# Domain Docs

工程类 skill 探索代码库时，怎么读本仓库的领域文档。

## 动手前先读

- **`CONTEXT.md`**（仓库根）：领域词汇表。本仓库用它代替 `GLOSSARY.md`；没有 `GLOSSARY-MAP.md`，是单上下文仓库。
- **`docs/adr/`**：读和你要动的区域相关的 ADR。ADR 用中文写，正文是一段白话的决策叙述，后接「考虑过的做法」和「影响」。
- **`docs/reference/`**：常驻的模块级实现参考，一个模块一篇。改对应模块前读对应那一篇（清单见 `AGENTS.md` 的表格）。

文件不存在就**安静跳过**：不要提示缺了什么，也不要一上来就建议创建。`/domain-modeling` 会在真的定下术语或决策时才创建。

## 目录结构

```
/
├── CONTEXT.md          ← 词汇表（本仓库不用 GLOSSARY.md）
├── docs/
│   ├── adr/            ← 架构决策
│   ├── reference/      ← 常驻模块参考
│   └── superpowers/    ← 规格与计划
└── lib/                ← 业务模块，一个模块一个目录
```

## 用词汇表里的词

产出里点名领域概念时（任务单标题、重构提案、假设、测试名），用 `CONTEXT.md` 里的说法，不要漂到它标注 `_避免：` 的同义词。

需要的概念词汇表里没有，是个信号：要么你在发明项目不用的词（重新想），要么真有缺口（记下来交给 `/domain-modeling`）。
