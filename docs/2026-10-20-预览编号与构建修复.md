# 预览、编号与构建修复

视频预览按数据库登记的真实 storage 相对路径生成 URL，兼容 skill 导入到 outputs 子目录的视频；不再假定所有文件都在 videos 根目录。视频接口保留流式 Range 和浏览器兼容预览。包装 iframe 显式使用浅色 color-scheme，避免深色模式把透明窗口合成为白底。

包装显示与导出编号统一为 f1–f4，旧 A–D 输入继续兼容。脚本 j 序号与视频运镜 k 序号统一小写，已有大写数据在读取和导出时兼容归一化，重复检查不区分大小写。

本机启动构建停在 “Creating an optimized production build” 时，确认 Next 构建进程内存已达 43 GB 以上。历史告警显示单个动态文件操作匹配约 9.4 万个本地文件；增加忽略注释未能控制扫描，改用 Webpack 的对照构建也出现堆内存耗尽。这两种临时实验均未保留。

采用仅源码和依赖的隔离目录后，完整 Next 构建通过，编译阶段约 8 秒，TypeScript 检查约 17 秒。日常 build 命令已接入同一流程，并保留原 standalone 资源同步与负载禁入校验。隔离输入、缺失产物保留旧构建、同步失败回滚、依赖硬链接清理不伤原文件均有独立测试。

预览验证包含真实 skill 视频在浏览器中播放及拖动、包装透明窗口在浅色/深色下的像素断言，以及现有包装预览来源检查。编号、视频路径、Range、混剪脚本、脚本导入、运镜模板和工作区回归通过；构建戳、standalone 边界测试通过。

最终使用桌面启动器的数据根环境执行 `npm run build`，完整构建与资源同步通过。清理构建临时目录后，以临时空数据库实际启动生成的 standalone：首页和项目 API 返回 200，真实 skill 视频的兼容预览 Range 返回 206，SQLite 在指定运行数据根创建成功。Windows 免安装包及安装器边界测试通过。构建仍有两条 Next 自身的动态追踪告警，但不再扫描本机素材库。
