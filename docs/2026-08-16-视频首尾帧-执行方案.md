## 1. 目标和范围

一条运镜任务现有分镜图继续作为首帧，用户可以额外本地上传一张尾帧图。供应商在确认支持时，按对应协议生成首尾帧之间的运动。

### 1.1 本轮包含

| 路径 | 供应商类型 | 当前模型/别名 | 本轮状态 |
|---|---|---|---|
| 直连 Seedance 2.0 | `jimeng` | `doubao-seedance-2-0-260128` | 可先实现 |
| 公司可灵 | `openai-video` | `kling-*` 的已配置别名 | 等卡 0 确认映射 |
| 公司 Seedance | `openai-video` | `doubao-seedance-2-0-260128`、Fast 别名 | 等卡 0 确认映射 |

### 1.2 本轮不包含

- 原生 `kling` 适配器的 `image_tail` 探针和接入；
- Seedance 1.x、未核验的 Seedance 2.x 变体；
- 批量生产 `lib/batch-production/`；
- 智能混剪和 `lib/final-edit/`；
- 从上一条视频自动接力尾帧；
- 从分镜候选或同组图片选择尾帧；
- 发布、push、安装包构建。

尾帧来源本轮只支持“当前项目内本地上传一张”。

## 2. 已确认事实、证据和未知项

### 2.1 本地代码与配置已确认

2026-08-16 的本地配置中，公司 Seedance 2.0、Seedance 2.0 Fast，以及多组可灵模型都经本机 LiteLLM 转发到公司中转站。

数据库中已启用的公司 Seedance 2.0 和公司可灵供应商均为 `openai-video` 类型，应用只连接本机 `127.0.0.1:4000`。

当前 `lib/video-providers/openai-video.ts` 向 `POST /v1/videos` 发送以下公共基础字段：

```json
{
  "model": "<alias>",
  "prompt": "<prompt>",
  "seconds": "5",
  "images": ["<first-frame-url>"]
}
```

可灵 3.x 非 Omni 还会条件性加入 `multi_shot`、`shot_type`。已识别的公司可灵模型还会加入 `response_format` 和按首帧比例吸附的 `size`。

它目前只表达一张首帧。代码和现有公司文档注释都没有证明第二个 `images` 元素就是尾帧。

当前 `lib/video-providers/jimeng.ts` 调用 Ark 的 `/contents/generations/tasks`，首帧是 `content` 中不带 `role` 的 `image_url`。

### 2.2 腾讯云公开资料能证明什么

[腾讯云 CreateAigcVideoTask](https://cloud.tencent.com/document/api/266/126239) 使用 `FileInfos.N` 表达输入文件。

首尾帧模式下，`Usage` 可为 `FirstFrame` 或 `LastFrame`。首帧和尾帧各最多一张；首帧可以单独存在，尾帧不能单独存在。

[AigcVideoTaskInputFileInfo 数据结构](https://cloud.tencent.com/document/api/266/31773) 也列出了 `FirstFrame`、`Reference` 和 `LastFrame`。

公开页给出了可灵及多个版本，但同时要求以具体模型文档确认版本能力。公开列表没有给出 Seedance。

这些资料只能证明腾讯云下游协议存在首尾帧语义，不能证明公司 `POST /v1/videos` 如何映射该语义。

### 2.3 直连 Seedance 的公开依据

[火山方舟创建视频生成任务](https://docs.volcengine.com/docs/82379/1520757?lang=zh) 使用 `content` 数组提交文本和图片，并把 Seedance 2.0 系列列入首尾帧能力范围。

[火山引擎开发者文章的模型示例](https://developer.volcengine.com/articles/7615547765435432996) 给出了 `first_frame`、`last_frame` 角色示例。

实现时仍要把能力锁到本次核验的精确 Seedance 2.0 模型 ID，不能用 `/seedance/i` 给全部 Seedance 模型开放。

### 2.4 明天必须确认的未知项

| 编号 | 未知项 | 未确认时的行为 |

## 3. 已定设计决策

### D1. 尾帧归属单条视频任务

每条运镜对应一条 `video_jobs`。新增可空列 `tailImageId TEXT`，不挂在分镜、分镜组或供应商上。

### D2. 尾帧资产必须属于项目

尾帧图保存为：

```text
role = input
usage = video_tail_frame
projectId = 当前项目
```

项目删除时依靠现有项目资产清理流程回收数据库行和磁盘文件。

单独删除图片时，引用计数必须同时检查 `video_jobs.sourceImageId` 和 `video_jobs.tailImageId`，防止留下悬空引用。

### D3. 能力由适配器声明，但必须带协议身份

不要只加一个无上下文的全局布尔值。建议合同：

```ts
type TailFrameProtocol =
  | 'ark-content-roles'
  | 'company-gateway-kling'
  | 'company-gateway-seedance';

interface TailFrameCapability {
  supported: boolean;
  protocol?: TailFrameProtocol;
  reason?: 'unsupported_model' | 'contract_unverified';
}
```

`VideoProviderAdapter` 增加可选的 `tailFrameCapability(model)`。未实现、未知模型或合同未核验都返回不支持。

前端能力来自后端供应商安全响应，不能在浏览器按供应商名称或模型字符串自行猜测。

### D4. 能力使用精确 allowlist

直连 Seedance 初始只开放 `doubao-seedance-2-0-260128`。Fast 和其他变体必须有独立证据后再加入。

公司可灵和公司 Seedance 的 allowlist 由卡 0 结论填写。禁止使用覆盖全部 `kling` 或全部 `seedance` 的宽泛正则。

### D5. 不支持时失败关闭

有 `tailImageId` 但能力不支持时：

- 创建 API 返回 400；
- 前端保留尾帧预览和“移除”入口，显示不兼容提示；
- 创建按钮禁用；
- 队列在首次 submit 前再次拒绝。

任何路径都不允许静默丢弃尾帧。

### D6. 创建校验和提交校验缺一不可

供应商的 `type`、`defaultModel` 可以在任务创建后被修改，失败任务重试时也会更新 `job.model`。

因此创建 API 的校验只负责早反馈。队列必须以“当前供应商类型 + 当前任务模型”在首次 submit 前重新核验能力和尾帧资产。

### D7. 已提交任务只轮询，绝不重新扣费

如果 `providerTaskId` 已存在，继续原有轮询分支，不重新 submit，也不因为本地尾帧文件后来缺失而阻断远端结果补抓。

新增尾帧逻辑不能改坏 `Resuming polling for existing task_id` 合同。

### D8. UI 异步更新只认稳定行 key

上传开始时捕获 `shotId + row.key`，响应回来后只更新同一个稳定行。

不能使用数组 `idx` 处理异步响应。用户在上传期间删除行、切换分镜或新增行时，旧响应不能附到另一条运镜。

### D9. 公司尾帧必须走 LiteLLM 和 COS

公司尾帧请求的 API base URL 必须是本机回环 LiteLLM。首帧和尾帧都必须经现有 COS 上传并使用预签名 URL。

公司尾帧不允许回退 `CREATIVE_STUDIO_PUBLIC_BASE_URL` 或自动探测的本机/公网 URL。COS 未配置或任一图片上传失败时，在请求 `/v1/videos` 前失败关闭。

公司身份由卡 0 核验的精确模型映射和 `company-gateway-*` 协议共同决定。该协议在提交前按 `executionScope='company'` 调用现有 provider execution gate 的 media 能力检查。

这样可以同时校验回环 LiteLLM、sidecar 运行状态和 COS 可用性，不需要在本轮给整个 `video_providers` 表新增 scope 字段。

非公司 `openai-video` 的既有传输行为不在本轮改变。若同一模型别名同时被公司和外部网关使用，现有身份不足，立即停止并单独设计持久 scope 迁移。

日志不得打印密钥、Authorization、完整预签名 URL 或图片 base64。真实调用前必须单独获得用户授权。

### D10. “提交结果不确定”禁止自动重试

`providerTaskId` 已落库时可以可靠防止重复 submit，但不能覆盖“上游已接单、本地在收到 task ID 前超时或断网”。

卡 0 要确认网关是否支持幂等键。若支持，使用由本地 job 派生的稳定 request key；若不支持，网络中断、超时或无法判定的 5xx 必须标记为 `submission_unknown`。

`submission_unknown` 不进入自动重试。人工核对供应商后台后，用户明确确认“可能重复扣费”才允许手动重试。

## 4. 适配器请求合同

### 4.1 直连 Seedance 2.0

无尾帧时保持现有请求完全不变，首帧不新增 `role`。

有尾帧时才切换为首尾帧模式：

```json
{
  "content": [
    { "type": "text", "text": "<prompt>" },
    {
      "type": "image_url",
      "image_url": { "url": "<first-frame>" },
      "role": "first_frame"
    },
    {
      "type": "image_url",
      "image_url": { "url": "<tail-frame>" },
      "role": "last_frame"
    }
  ]
}
```

测试必须证明无尾帧请求仍只有一张图且不带 `role`，带尾帧请求的角色和顺序精确匹配。

### 4.2 公司可灵和公司 Seedance

`openai-video` 的无尾帧请求继续保持 `images: [first]`，结构不变。

2026-08-17 卡 0 结论（**已经免费字段探测 + 真实任务双重验证**；依据：用户提供的腾讯云 CreateAigcVideoTask 文档、网关 400 透传行为、E2 真实任务成片人工抽帧比对）：

| 模型别名 | 网关字段 | 首帧表达 | 尾帧表达 | 下游映射 | 幂等键 | 证据位置 |
|---|---|---|---|---|---|---|
| `kling-3.0`（公司可灵） | `images` + `LastFrameUrl` + `OutputConfig` | `images[0]` | **`LastFrameUrl`（腾讯原生 PascalCase，网关透传）**；比例必须同时给 `OutputConfig.AspectRatio`（首尾帧模式 size 被忽略，默认落 16:9） | 腾讯云 FileInfos Usage=FirstFrame + LastFrameUrl + OutputConfig.AspectRatio | 下游有 SessionId 去重，网关侧字段未核验，本轮不发送 | 免费探测：`scripts/company-gateway-field-probe.mjs`；E2：`scripts/company-kling-tailframe-e2e.ts`，成片 828x1108、末帧精确收束（2026-08-17） |
| `doubao-seedance-2-0-260128`、`doubao-seedance-2-0-fast-260128`（公司 Seedance） | `images` | `images[0]` | **`images[1]`**（比例跟随图片，不需要 size/AspectRatio） | 中转站实际下游未核验（非腾讯 VOD 链路） | 同上 | E3：用户真实任务 2026-08-16，成片 834x1112、末帧精确收束 |

已证伪的写法（不要再试）：

- 可灵尾帧用 `images: [first, tail]`——下游当参考图（Reference）模式，出片 16:9 且末帧不收束；
- `aspect_ratio` / `last_frame_url` / `lastFrameUrl` 等 snake/camel 变体——网关 400 `UnknownParameter`（参数校验在任务创建前，错字段免费失败）。

实现要点（`lib/company-gateway-tail-frame.ts` + `lib/video-providers/openai-video.ts`）：

- allowlist 精确匹配上表三个别名；其他模型（含 `kling-2.5`、`kling-3.0-Omni`）一律 `contract_unverified`；
- 尾帧请求强制回环 LiteLLM baseUrl + provider execution gate media 门禁 + 首帧尾帧双 COS 预签名 URL，任一不满足在 POST 前失败关闭，禁止公网 URL 回退；
- 可灵与 Seedance 分别编码，无尾帧请求保持原单图结构与既有传输回退行为；
- 单元测试覆盖非回环 baseUrl、COS 未配置、COS 上传失败三种拒绝路径，以及两家的精确字段形状。

如果公司中转对可灵和 Seedance 使用不同形状，分别编码，不要强行抽象成同一个双图数组。

## 5. 数据、API、队列和 UI 合同

### 5.1 数据库迁移

在 `CORE_DB_MIGRATIONS` 末尾追加：

```sql
ALTER TABLE video_jobs ADD COLUMN tailImageId TEXT
```

不得修改任何已发布迁移，不改旧建表语句，不加入批量生产迁移流。

`scripts/db-migrations.test.ts` 必须：

- 给旧库夹具创建 `video_jobs`；
- 验证迁移后存在 `tailImageId`；
- 不再把工作流 trigger 断言为数组最后一项；
- 继续证明已发布 trigger 仍然存在；
- 不假设 `tailImageId` 是所有历史数据库的最后一列。

### 5.2 上传和资产校验

`POST /api/upload` 允许 `usage=video_tail_frame`。该 usage 必须满足 `files.length === 1`，必须传 `projectId`，且项目必须真实存在。

多文件、缺少项目、未知项目和非法图片都在写数据库或文件前返回 400。测试还要证明失败后没有新增资产行或残留文件。

创建任务时，尾帧资产必须同时满足：

- 资产存在；
- `projectId` 与任务项目一致；
- `role='input'`；
- `usage='video_tail_frame'`；
- 当前供应商类型和任务模型支持尾帧。

批量创建运镜时，任意一条失败就整批返回 400，不允许部分插入。

### 5.3 队列提交

`SubmitVideoRequest` 增加可选的 `tailImagePath` 和 `tailMimeType`，两者必须成对出现。

队列只在 `providerTaskId` 为空的 submit 分支中：

1. 重新核验适配器能力；
2. 读取并验证尾帧资产；
3. 传给适配器；
4. 任一步失败都让任务明确失败，不静默降级。

已有 `providerTaskId` 时直接进入轮询，不需要重新上传尾帧，也不能发起第二次生成。

首次 submit 的异常必须区分“明确拒绝”和“结果不确定”。结果不确定时写入 `providerStatus='submission_unknown'`，停止自动重试。

### 5.4 前端状态

每条 `motionRows` 增加：

```ts
tailImageId: string | null;
tailImageUrl: string | null;
tailUploadState: 'idle' | 'uploading' | 'failed';
```

UI 行为：

- 支持时显示“上传尾帧”；
- 已有尾帧始终显示缩略图和“移除”；
- 切到不支持的供应商后不隐藏已有尾帧；
- 显示“当前模型不支持，请移除尾帧或换供应商”；
- 不兼容或上传中时禁止创建；
- 切换分镜后，`perShotMotionCache` 保留尾帧状态；
- 结果卡按 `tailImageId` 显示“含尾帧”。

移除未提交尾帧时可调用现有图片删除 API。上传响应到达时若原行已不存在，应立即尝试删除这张未引用资产，避免产生孤儿文件。

## 6. 执行任务卡

### 卡 0：公司内网协议核验

**目标**：只确认合同，不生成视频。

到公司后执行：

1. 启动本机 LiteLLM sidecar，确认只监听 `127.0.0.1:4000`；
2. 从现有供应商配置确认三组实际模型别名；
3. 查公司中转站文档或负责人提供的请求示例；
4. 确认公司 `/v1/videos` 如何表达首帧和尾帧；
5. 确认可灵和 Seedance 各自的腾讯云下游产品、Action、模型版本；
6. 确认网关是否支持幂等键，以及字段或 Header 的精确写法；

## 9. 立即停止并报告的条件

出现以下任一情况就停止：

1. 公司 `/v1/videos` 的尾帧字段仍无权威依据；
2. 公司 Seedance 的腾讯云下游产品与公开资料不一致；
3. 请求接受尾帧字段，但成片没有向指定尾帧收束；
4. 某模型只接受字段却静默忽略；
5. 必须修改批量生产、final-edit 或迁移历史条目；
6. 队列出现重复 submit 或远端任务数增加；
7. 提交响应不确定，但系统准备自动重试；
8. 公司尾帧准备绕过回环 LiteLLM 或回退非 COS 图片 URL；
9. 同一模型别名同时用于公司和外部网关，无法可靠判断 scope；
10. 需要把本机服务暴露到公网；
11. COS、网关或日志可能泄露密钥和完整签名 URL；
12. 尾帧资产可能被单独删除后留下悬空引用；
13. 异步上传可能把图片写到错误的运镜行。

这份方案的核心门禁是：公开腾讯云文档只能证明下游支持首尾帧，不能替代公司中转协议。先确认映射，再打开公司模型能力。
