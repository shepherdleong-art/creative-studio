## 0. 目标与范围

给「视频生成」工位加首尾帧：一条运镜任务除了首帧（现有的分镜图），还能再指定一张尾帧图，模型自动补中间运动。

**已拍板的范围（不要扩大）：**

| 项 | 定死的范围 |
|---|---|
| 尾帧来源 | **只支持本地上传一张** |
| 不做 | 「同组其他分镜图」「当前分镜候选图」「上一条视频尾帧接力」 |
| 不做 | 批量生产（`lib/batch-production/`）侧的任何改动 |
| 不做 | 混剪 / final-edit 侧的任何改动 |

即梦 poll 响应里那个 `content.last_frame_url`（`lib/video-providers/jimeng.ts:30`）是「尾帧接力」的现成入口，**本次不碰**，留着。

## 1. 已定死的设计决策

执行者**不得更改**下列决策。觉得有问题 → 停下来报告，不要边做边改。

**D1 · 归属粒度 = 单条视频任务。**
一个分镜可以配多条运镜（`motionRows`），每条运镜 = 一条 `video_jobs` = 一段视频。尾帧是「这段视频的结尾」，所以挂在 `video_jobs` 上，不是挂在分镜上。列名 `tailImageId`，可空。

**D2 · 尾帧图的身份 = `role='input'` + `usage='video_tail_frame'`，且必须绑 `projectId`。**
绑 projectId 是为了被项目删除连带回收（`app/api/projects/[id]/route.ts` 的 `DELETE` 按 projectId 查出所有 image_assets，事务删行后 unlink `path`/`originalPath`/`processedPath`）。不绑就是永久垃圾文件。

**D3 · 能力声明写在适配器上，不写在业务代码里。**
`VideoProviderAdapter` 增加可选方法 `supportsTailFrame?(model): boolean`。**没实现 = 不支持。** 三家各自表态，业务层只问这一个问题。

**D4 · 不支持时必须报错，不许静默丢弃。**
用户传了尾帧、供应商不支持 → 创建 API 返回 400。静默丢掉会让用户以为尾帧生效了，拿到一段没有尾帧的视频还找不到原因。前端同时按能力隐藏入口，两道都要有。

**D5 · 三家的初始开关**

| 适配器 | 开关 | 依据 |
|---|---|---|
| `jimeng` | **开** | Ark `content` 数组用 `role: first_frame` / `last_frame` 表达首尾帧，协议有依据 |
| `kling` | **由卡 0 实测决定** | 官方文档只对 1.0/1.5/1.6 明确写了 `image_tail`；2.5/3.0 只在第三方转发平台文档里见过 |
| `openai-video` | **关（硬编码 false）** | `images` 数组第二个元素是否被当尾帧，《小林生影_AIGC模型调用文档》里查不到依据 |

**D6 · 防重复扣费纪律原样保留。**
`lib/video-queue.ts` 里 `const existingTaskId = ...` 那段（锚点 `Resuming polling for existing task_id`）：已有 `providerTaskId` 的任务直接进轮询、不重新 submit。**这段一个字都不要动。** 重新 submit 会在供应商侧产生第二条付费任务。

**为什么必须先做**：团队主力是可灵 2.5 / 3.0，而这两个版本支不支持 `image_tail` 是整件事唯一的外部未知数。先花 1 条 5 秒任务的钱问清楚，比写完一整条链路再发现主力供应商用不了划算得多。

**产出**：本文档「卡 0 结论」表格填上答案。卡 3b 依赖它。

```js
// 一次性探针:验证可灵当前模型是否接受 image_tail(首尾帧字段)。
// 会在供应商侧产生 1 条真实付费任务(5 秒)。只跑一次;跑完把结论写回
// docs/2026-08-16-视频首尾帧-执行方案.md 的「卡 0 结论」表格。
//
// 用法:
//   node scripts/probe-kling-tail-frame.mjs <providerId> <首帧图路径> <尾帧图路径>
// 例:
//   node scripts/probe-kling-tail-frame.mjs kling-2-5 storage/originals/inputs/a.png storage/originals/inputs/b.png

import fs from 'node:fs';
import path from 'node:path';
import Database from 'better-sqlite3';
import { dataRoot } from '../lib/data-root.ts';
import { resolveVideoProviderRuntimeConfig } from '../lib/video-auth.ts';
import { getKlingToken } from '../lib/video-providers/kling.ts';

const [providerId, firstPath, tailPath] = process.argv.slice(2);
if (!providerId || !firstPath || !tailPath) {
  console.error('用法: node scripts/probe-kling-tail-frame.mjs <providerId> <首帧图路径> <尾帧图路径>');
  process.exit(2);
}
for (const p of [firstPath, tailPath]) {
  if (!fs.existsSync(p)) { console.error(`图片不存在: ${p}`); process.exit(2); }
}

const db = new Database(path.join(dataRoot(), 'data', 'workbench.db'), { readonly: true });
const provider = db.prepare('SELECT * FROM video_providers WHERE id = ?').get(providerId);
if (!provider) { console.error(`找不到视频供应商 ${providerId}`); process.exit(2); }
if (provider.type !== 'kling') { console.error(`${providerId} 不是 kling 类型(实际 ${provider.type})`); process.exit(2); }

const runtime = resolveVideoProviderRuntimeConfig(provider);
if (!runtime.configured) { console.error(`供应商未配置完整: ${runtime.missing.join(', ')}`); process.exit(2); }

const b64 = (p) => fs.readFileSync(p).toString('base64');
const token = getKlingToken(runtime.accessKey, runtime.secretKey);
const url = `${runtime.baseUrl.replace(/\/$/, '')}/v1/videos/image2video`;

// 字段组装与 lib/video-providers/kling.ts 的 submit 完全一致,只多一个 image_tail。
const body = {
  model_name: runtime.model,
  image: b64(firstPath),
  image_tail: b64(tailPath),
  prompt: 'gentle camera movement, stable product detail',
  duration: '5',
  mode: 'pro',
  sound: 'on',
};
if (/v3|3\.0/i.test(runtime.model)) { body.multi_shot = 'true'; body.shot_type = 'intelligence'; }

console.log(`[probe] model=${runtime.model}`);
console.log(`[probe] url=${url}`);
console.log(`[probe] 字段=${Object.keys(body).join(',')}`);

const res = await fetch(url, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${token}` },
  body: JSON.stringify(body),
});
const text = await res.text();
console.log(`[probe] HTTP ${res.status}`);
console.log(`[probe] 响应: ${text.slice(0, 1200)}`);
```

**跑法**：对**每一个**要开尾帧的可灵供应商各跑一次（现有种子里是 `kling-3` 和 `kling-2-5`，见 `lib/seed.ts` 的 video_providers 段）。

```bash
node scripts/probe-kling-tail-frame.mjs kling-2-5 <首帧图> <尾帧图>
node scripts/probe-kling-tail-frame.mjs kling-3   <首帧图> <尾帧图>
```

图片可以从 `storage/originals/inputs/` 随便挑两张真实的分镜图（≥300px、JPG/PNG，可灵对尾帧的约束是 JPG/PNG、≤10MB、边长 ≥300px）。

**判读规则（严格按这个，不要自己引申）**

| 观察到 | 结论 |
|---|---|
| HTTP 200 且 `code === 0` 且拿到 `data.task_id` | 该模型**接受** `image_tail` → 记 ✅ |
| HTTP 4xx，或 `code !== 0` 且报文提到 `image_tail` / 参数非法 | 该模型**不支持** → 记 ❌ |
| 其他任何情况 | **停下来报告**，把 HTTP 状态和响应原文贴出来，不要猜 |

> ⚠️ 「接受字段」不等于「尾帧真的生效」。拿到 task_id 之后等这条任务出片，**人眼看一下最后一帧是不是给的那张尾帧图**，把这个结果也填进结论表。字段被接受但被忽略也是常见情况。

#### 3a. `lib/video-providers/jimeng.ts` —— 开

把 `const body: Record<string, unknown> = {` 里的 `content: [...]` 拆出来（锚点：`const seedance2 = isSeedance2(request.model);`）：

```ts

    // 标 role: 'first_frame' —— 不标会被当成「多模态参考图模式」,与首尾帧模式互斥。
    // 没有尾帧时保持原样不带 role(这是已经在跑的老行为,不要动)。
    const content: Array<Record<string, unknown>> = [
      {
        type: 'text',
        text: normalizeJimengPrompt(request.prompt),
      },
      {
        type: 'image_url',
        image_url: { url: imageDataUrl },
        ...(request.tailImagePath ? { role: 'first_frame' } : {}),
      },
    ];
    if (request.tailImagePath) {
      content.push({
        type: 'image_url',
        image_url: { url: fileToBase64DataUrl(request.tailImagePath, request.tailMimeType || 'image/png') },
        role: 'last_frame',
      });
    }

    const body: Record<string, unknown> = {
      model: request.model,
      content,
      resolution: '1080p',
      ratio: 'adaptive',
      duration: normalizeJimengDuration(request.durationSec, seedance2 ? 15 : 12),
      watermark: false,
      generate_audio: true,
    };
    if (!seedance2) body.camera_fixed = false;
```

```ts
import { getDb } from './db.ts';
import { videoProviderSupportsTailFrame } from './video-providers/index.ts';

/** 尾帧图在 image_assets 里的 usage 标记。上传白名单见 app/api/upload/route.ts。 */
export const VIDEO_TAIL_FRAME_USAGE = 'video_tail_frame';

export type TailFrameCheck =
  | { ok: true; tailImageId: string | null }
  | { ok: false; error: string };

/**
 * 校验一条视频任务上的尾帧图。返回 ok:false 时调用方必须回 400,
 * 不许静默丢弃 —— 静默丢弃会让用户以为尾帧生效了(见执行方案 D4)。
 *
 * 通过条件:该图存在、属于同一项目、是本工位上传的尾帧图、且该供应商/模型支持首尾帧。
 */
export function checkTailFrame(params: {
  tailImageId: unknown;
  projectId: string;
  providerType: string;
  model: string;
}): TailFrameCheck {
  const raw = typeof params.tailImageId === 'string' ? params.tailImageId.trim() : '';
  if (!raw) return { ok: true, tailImageId: null };

  if (!videoProviderSupportsTailFrame(params.providerType, params.model)) {
    return { ok: false, error: `所选视频供应商的模型 ${params.model} 不支持首尾帧,请去掉尾帧图或换一个供应商` };
  }

  const asset = getDb().prepare(`
    SELECT id, projectId, role, usage FROM image_assets WHERE id = ?
  `).get(raw) as { id: string; projectId: string | null; role: string; usage: string | null } | undefined;

  if (!asset) return { ok: false, error: '尾帧图不存在' };
  if (asset.projectId !== params.projectId) return { ok: false, error: '尾帧图不属于当前项目' };
  if (asset.role !== 'input' || asset.usage !== VIDEO_TAIL_FRAME_USAGE) {
    return { ok: false, error: '该图片不是本工位上传的尾帧图' };
  }

  return { ok: true, tailImageId: raw };
}
```
