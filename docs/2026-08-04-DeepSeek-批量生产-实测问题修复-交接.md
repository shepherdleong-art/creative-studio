## 1. 问题 3 ★ 最严重:BGM 曲库为空,把整条生产链卡死

### 1.1 实际现象

用户点「开始批量生产」后,**没有任何后续** —— TTS 没跑、成片没生成。

### 1.2 完整根因链(已定位)

```
storage/bgm/ 是空目录(0 个文件)
    ↓
readBatchBgmPool() 查 final_edit_bgm_tracks 表 → 空
    ↓
phase-e.ts:155 抛错
  「曲库为空：请先把背景音乐放入 storage/bgm/ 目录并重新扫描后再开始批量生产」
    ↓
startBatchProduction 中止
    ↓
scheduleAllocationRenderTasks 从未执行
    ↓
narration 任务(phase-e.ts:99-113)从未创建 → TTS 当然不会跑
    ↓
render 任务也从未创建 → 没有成片
```

**所以「没真的跑 TTS」和「后续生成没继续」是同一个原因**,不是配音本身有问题。

### 1.3 为什么会这样:闸门位置放错了

上一轮交接文档 §M2-D **明确写过**:

> **闸门位置**:BGM 缺失是**输入问题**,拦在**第 2 步开始按钮**,不要等到导出口才拒绝:
> - 曲库为空 → 禁用开始,提示曲库位置与刷新入口

实际实现把检查放在了**后端 `phase-e.ts` 抛异常**,而前端:
- 「开始批量生产」按钮**不检查曲库**,照常可点
- 界面上**没有任何地方显示曲库状态**
- 用户点完才失败,而且错误提示不明显

### 1.4 更根本的问题:BGM 的 UI 整个没做

PRD §6.3.3 的 BGM 需求组,目前只实现了 `bgmParams`(音量/淡入/淡出三个滑杆)。以下 **P0 全部缺失**:

| 需求 | 状态 |
|---|---|
| FR-S2-40 曲库为 `storage/bgm/`,与单条共用,放文件即可 | ❌ 界面无任何体现 |
| FR-S2-41 默认自动模式,系统自动分配 | ⚠️ 后端有,界面无说明 |
| FR-S2-42 可选手动指定 1–N 首 | ❌ 未实现 |
| FR-S2-44 显示分配预期(「曲库 12 首,8 条成片自动分配」) | ❌ 未实现 |
| FR-S2-47 曲库为空**阻断流程**+提示位置+**刷新入口** | ❌ 前端无,只有后端抛错 |
| FR-S2-50 曲库列表可试听、手动模式可勾选 | ❌ 未实现 |

### 1.5 要做什么

**A. 新增批量 BGM 曲库 API**

复用单条模式的现成能力,**不要新建曲库、不要新建表**:
- 曲库扫描:`lib/final-edit/bgm.ts` 的 `scanFinalEditBgm(db, storageRoot)`
- 曲库读取:`lib/batch-production/bgm.ts` 的 `readBatchBgmPool(db)`(已存在)
- 单条的曲库 API 可参照:`app/api/final-edit-bgm/`

新增(或复用)一个批量可调用的接口,提供:
- 列出曲库曲目(id / 文件名 / 时长)
- 触发重新扫描 `storage/bgm/`
- 试听(可复用 `app/api/final-edit-bgm/[id]/file`)

**注意**:批量 API 必须走既有的 readiness 门禁(铁律 §0.2 第 3 条)。

**B. 第 2 步增加 BGM 区**

位置:`components/batch-production/BatchStepScripts.tsx`,与现有的音量/淡入/淡出参数放在一起。

必须包含:

1. **曲库状态行**,例如:
   - 有曲子:`曲库 12 首 · 8 条成片将自动分配` + `[重新扫描]` `[管理曲目]`
   - 空曲库:`曲库为空 —— 请把音频文件放进 storage/bgm/ 后点击重新扫描` + `[重新扫描]`
2. **重新扫描按钮** —— 用户放完文件不用重启应用
3. **可展开的曲目列表**:每首显示文件名 + 时长 + 试听按钮
4. **可选手动指定**:展开后可勾选,勾选则只在选中范围内分配;不勾选 = 全库自动(默认)

> 默认路径必须是**零操作**:用户往文件夹放满曲子,什么都不用点就能开跑。手动指定是进阶选项,默认收起。

**C. 开始按钮加前置闸门**

`BatchStepScripts.tsx` 的 `startDisabledReason` 增加一条(优先级排在现有条件之后即可):

```
曲库为空 → '背景音乐曲库为空，请先放入音频并重新扫描'
```

同时保留 `phase-e.ts:155` 的后端检查(纵深防御),但用户**不应该再有机会点到它**。

### 1.6 验收

- `storage/bgm/` 为空时:第 2 步显示空曲库提示,开始按钮禁用并说明原因
- 往 `storage/bgm/` 放 3 个音频 → 点「重新扫描」→ 曲库状态变成「曲库 3 首」,开始按钮可用
- 点开始后:**narration 任务被创建并执行**(查 `batch_tasks` 表应有 `workType='narration'` 的行)
- 成片渲染完成后能听到背景音乐

## 2. 问题 1:第 1 步素材池太矮,无法预览

### 2.1 实际现象

素材区只能看到**一行的一半**,缩略图上下被裁切,左右还有半个卡片露出来。完全没法看清素材内容。

### 2.2 根因

`components/batch-production/BatchStepMaterials.tsx:253`:

```tsx
<div className="min-h-0 flex-1 overflow-x-hidden overflow-y-scroll overscroll-contain rounded-2xl bg-surface-subtle p-3 [scrollbar-gutter:stable]">
  <div className="grid gap-3 lg:grid-cols-2">
```

- 高度靠 `flex-1` 从父容器分配,但同一列还要塞下「素材区」卡片头(标题+说明+工具栏)和「画质与调色(进阶)」整张卡片,留给素材列表的空间被挤到很小
- `lg:grid-cols-2` 两列布局让每个卡片更宽更矮,缩略图被压

### 2.3 要做什么

**目标:素材池是这一步的主体,应该占据绝大部分可用高度,内部上下滚动浏览。**

1. **给素材列表一个有意义的最小高度**,不要只依赖 `flex-1`。例如 `min-h-[520px]`,同时保留 `flex-1` 让它在大屏上继续长高。
2. **「画质与调色(进阶)」移到素材池下方**并保持默认收起,不要和素材池抢垂直空间。
3. **列数改为响应式**:窄屏 1 列、中屏 2 列、宽屏 3 列(`sm:grid-cols-2 xl:grid-cols-3`),让单卡不至于过宽过矮。
4. 确认卡片内缩略图用固定宽高比(`aspect-video`)且 `object-cover`,不被拉伸或裁切成条。

### 2.4 验收

- 1440px 宽的窗口下,素材区一屏能完整看到**至少 2 行**完整卡片(缩略图不被裁)
- 滚轮在素材区内滚动时,只有素材列表滚动,页面不跟着动
- 缩略图比例正常,不变形

## 3. 问题 2:分析时画面闪烁,预览消失

### 3.1 实际现象

点「分析」后,画面时不时闪烁,而且之前能看到的缩略图预览没了。

### 3.2 根因(两个,要分开处理)

**闪烁**:`BatchPreparationPanel.tsx:375, 382` 有两个 3 秒轮询:

```ts
window.setInterval(() => void loadProxyTasks(selectedBatchId), 3_000);
window.setInterval(() => void loadWorkspace(selectedBatchId), 3_000);
```

每轮都 `setState` 触发整棵子树重渲染。若素材卡的 `key` 或 `<img src>` 在重渲染时发生变化,浏览器会重新发起图片请求 → 视觉上就是闪一下。

**预览消失**:锁定(frozen)后素材区走的是另一个分支,渲染成**纯文字列表**:

```
素材 29936330 · 分析版本 ce65450b    从后续分配排除
```

缩略图完全没有了。

### 3.3 要做什么

**A. 消除闪烁**

- 确保素材卡的 `key` 稳定用 `asset.id`,不要用数组下标或含变化字段的复合 key
- 确保 `<img src>` 是稳定 URL,不要在 URL 上拼时间戳或随机数
- 用 `React.memo` 包住素材卡组件,让轮询导致的父组件重渲染不波及未变化的卡片
- 轮询只在**确实有进行中任务**时开启;没有 running/queued 任务时停止,避免无谓重渲染

**B. 锁定后也要能看到缩略图**

冻结素材列表改为与未锁定时一致的**卡片网格**(缩略图 + 名称 + 分析版本 + 排除按钮),而不是纯文字行。

用户锁定后仍然需要确认"这批用的是哪些素材",纯 ID 列表(`素材 29936330`)无法辨认。

### 3.4 验收

- 点分析后,已加载的缩略图**不再重新闪烁**
- 分析进行中,进度正常更新,但图片不重新请求
- 批次锁定后,素材区仍是带缩略图的卡片网格,能一眼认出用了哪些素材
- 所有任务结束后,轮询自动停止(可用 DevTools Network 面板确认不再有周期请求)
