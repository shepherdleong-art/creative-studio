# 创作画布 参考

> 从 `AGENTS.md` 下沉的实现细节。**动 `lib/creative-canvas/`、`app/api/canvas/`、`components/creative-canvas/`、`app/canvas/` 任何东西前读这里。**
> 产品口径以 `docs/superpowers/specs/2026-09-09-infinite-canvas-prd.md` 为准；分阶段实施与验收记录见 `docs/2026-09-09-无限画布-执行记录.md`。

## 一句话边界

创作画布是**独立模块**：自己的表、自己的迁移流、自己的调度器、自己的 API 与页面，**不写旧 `jobs` / `video_jobs` / `projects` / `shot_sets`**，也**不从 `final-edit/` 导入**（与批量生产、详情页脚本同一条红线）。旧工作台的队列与页面不受它影响。

## 模块地图

| 文件 | 职责 | 改动前必须知道 |
| --- | --- | --- |
| `types.ts` | 纯类型：图定义、参考槽位、任务阶段、提交状态 | 阶段名可以改，但**不能合并掉影响重提与名额的区别** |
| `graph.ts` | 纯图操作：解析、连接校验、循环、参考槽位对账、复制映射 | 解析期就拒绝端口不兼容与重复连线；运行投影字段一律拒收 |
| `capabilities.ts` | 模型能力表（模式／输入／参数／证据层级） | 证据层级只能由真实样例提升；fixture 通过不算 |
| `schema.ts` / `readiness.ts` / `runtime-readiness.ts` | 独立迁移流 + 共享升级 gate | 迁移只能追加；新 scope 要走共享备份／锁／审计 |
| `config.ts` | 功能开关与执行器模式 | 开关关闭时不建表、不起 worker、不碰数据根 |
| `repository.ts` | 画布 CRUD、修订号保存、节点运行投影、发布守卫、候选投影 | 保存冲突返回 409 且**不覆盖客户端草稿**；发布门禁只有 nodeEpoch（v2 起不再看 activeTaskId） |
| `tasks.ts` | run／task／input 持久化、幂等创建、名额领取、多变体 | 名额是**持久化的 `slotHeld`**，领取在单个写事务里完成；single 模式可同节点并发多变体（上限 8） |
| `planner.ts` | 单点／分支计划、输入冻结、计划指纹 | 计划必须可重放：同一实现既做预览也做提交前重验 |
| `runs.ts` | 幂等启动 | **重放查询先于一切校验**：图改了、任务开始了，也要返回原结果 |
| `scheduler.ts` | 持久化调度器（全局默认 10 名额） | 停止顺序：停领取 → 中止在途 AbortSignal → 排空 |
| `runner.ts` | 一次任务的 prepare→submit→poll→download→publish | 有远端 ID 就**绝不重新提交**；提交前必须先落 `submitting + maybe_sent` |
| `recovery.ts` | 重启恢复、待核查核查、补下载、继续、停止、租约接管 | 恢复不许用「重新生成」绕过错误 |
| `assets.ts` | 素材导入、产物登记、Range 读取 | 产物**不做内容去重**（一任务一输出有唯一索引） |
| `export.ts` | manifest 固定 + ZIP | 先固定 manifest 再打包；缺失文件要指名报错 |
| `logs.ts` | 独立运行日志与任务历史快照，复用旧项目 LogDrawer / LogViewer | schema v4；按画布和任务双重限定；落库和文件前脱敏，不记录正常轮询与租约心跳 |
| `usage.ts` | 画布账本包装 | eventKey 按任务稳定：重试／补下载不重复计费；未计价模型不编造金额 |
| `adapters/` | fixture 与公司执行器、素材交付、能力表 | 交付与单次 POST 必须分开；fixture 只在被标记的临时数据根启用 |

## 几条最容易踩的约定

- **回归测试同名前缀**：改动对应模块就跑 `node scripts/creative-canvas-<模块>.test.ts`；浏览器验收是 `scripts/creative-canvas.playwright.test.mjs --suite editor|execution|recovery|export|performance|all`。
- **长观察必须 `caffeinate`**：macOS App Nap 会冻结后台测试进程（心跳出现规律 15 秒空洞），不 `caffeinate` 跑出来的「性能问题」是假的。
- **不要 source `canvas-profile.sh`，也不要调 `npm run dev`／`start.command` 做测试**：它们会把数据根固定回真实画布目录并拉起 4100 代理。测试 harness 自己建临时根与空闲端口，直接启动 `.next/standalone/server.js`。
- **测试与构建前显式设 `CREATIVE_STUDIO_DATA_ROOT`**：`dataRoot()` 在模块首次加载时固定，静态 import 之后再改环境变量不算隔离。
- **`adapters/index.ts` 的能力注册放在 `globalThis`**：Next 会把 instrumentation 与路由分别打包，模块级 Map 在两边是两份实例（启动期注册的模型会在 API 里看不到）。
- **公司自由创作不叠加旧参考前缀**：画布路径一律 `referenceGuidanceMode: 'none'`，提示词按节点原文提交。
- **七牛渠道与公司尾帧必须走 COS**：缺配置或上传失败在 POST 前 fail closed；视频／音频参考没有本机 URL 回退通道。
- **视频模式各有独立合同**：文生（content 只有文本项）、首尾帧（首帧必填、尾帧可选）、全能参考／智能多帧（多模态参考 `reference_image`／`reference_video`／`reference_audio`）。方舟的首帧、严格首尾帧、多模态参考三种模式互斥，能力表按 `modes` 声明规则，适配器不静默丢素材：图生视频接两张图时，planner 按参考列表顺序推断首帧／尾帧（↑↓ 排序即调换），适配器侧 `last_frame_role_required` 兜底保留。**Seedance 2.5 另有 omni 子任务**：智能编辑（`omni_reference_task_type=edit`，锁 ratio=adaptive＋duration=-1，参考视频硬性 4–30 秒）与超长视频（`extend`，锁 ratio=adaptive）；2.5 全模态参考一律显式提交 omni 字段（reference/edit/extend），编辑／延长还要求提示词含对应意图关键词（prepare 前置校验，`prompt_keyword_missing`）。2.0 不认识 omni 字段，永不发送。
- **参考槽位随连线对账**：断开连线（或删除来源节点）时，对应槽位在 `reconcileCanvasGraph` 中直接移除，不留「失效引用」；编号游标只增不减，重连分配新编号，提示词里的旧 @参考N 按未知提及报错。槽位用途（role）不在界面手标：默认按来源类型分配，图生视频帧角色由 planner 按顺序覆盖。
- **节点尺寸持久化在 `size.width/height`**：四角调整宽高，右缘改宽、底缘改高；增加高度优先分给提示词；提示词和生成节点以实际内容高度为下限，不能把底部操作缩进滚动区。React Flow 把拖后尺寸写 `node.width/height`（`setAttributes`），映射必须先读它们，再回退加载期的 `style.width/height`；不要把自动测量的 `measured.height` 保存成用户高度。旧图没有 height 时继续由内容撑开，默认宽度仍来自 `node-kinds.ts` 的 `defaultWidth`。
- **素材节点高度由媒体内容决定**：四角／底边按比例带动宽度缩放，只写宽度属性，图片和视频保留自身比例。加载时忽略素材旧 `size.height`，再次保存时移除它；否则固定高度会在替换素材或改宽后留下大块空白。提示词／生成节点仍保存自由高度。
- **节点内滚动不控制视口**：内容容器与提示词使用 `nowheel` 隔离滚动、`overscroll-behavior: contain` 阻断边界滚动传递；双指滚动只浏览节点内容，画布空白处保留原来的缩放手势。
- **小地图点击定位、右键隐藏**：点击按 MiniMap 返回的画布坐标居中，并显式保留当前 zoom（`setCenter` 缺省会改缩放）；隐藏后右下角可重新显示，显隐仅限当前编辑器会话。当前 React Flow MiniMap 实现不转发 `onContextMenu`，右键事件由外层容器拦截，避免冒泡到画布菜单。
- **「素材（当前结果）」与结果自动物化**：任务发布新产物时，客户端轮询发现未见过的候选 assetId 就在源节点右侧自动飞出素材节点（assetId 钉死的快照，上游重跑不跟随）；首次投影只建档不飞，否则打开画布被旧结果刷屏。生成 → 素材的**溯源连线**只记录出处：不产生参考槽位、不参与端口匹配，`reachableGenerationNodes` 视其为死端（不许借它走到素材自己的下游，否则分支会卷入旧快照的消费者）。菜单里的「素材（当前结果）」保留为手动补钉入口（打开画布前的旧结果）。**生成节点内不放任何产物 UI**（多变体产物同样各自飞出）；大图、播放、替换、下载都在素材节点上。
- **参考素材约束落在 prepare**：2.0 参考视频／音频单段 2–15 秒、每类总时长 ≤15 秒；2.5 单段放宽到 30 秒、不设分类总时长（编辑子任务的参考视频另有 4 秒下限）。音频必须与图或视频同时出现（方舟规则）；图片可回退 data URL，视频与音频只能走交付层（COS）拿到公网地址。
- **能力表只开放有依据的组合**：注册了但没有公司路由的模型（例如当前 `config.yaml` 里没有的 `qiniuyun/gpt-image-2-medium`）不许在界面开放——提交必然失败的模型比「未开放」更糟。
- **图片模型按路由存在性选择**：当前可用的是 `image2-medium`（有路由、有真实案例）；改这一条前先跑 `node scripts/canvas-p7-readiness.mjs`。
- **导航范式对标主流节点画布**：滚轮／触控板双指滚动＝**缩放**；左键拖空白＝框选（`selectionOnDrag`）；平移靠**中键拖拽**（`panOnDrag: [1]`）；`panOnScroll` 关闭。改配置前先跑 editor + regression 两个 Playwright 套件。**空格不做快捷键**（历史教训：焦点残留在按钮/输入框时，空格会误触发生成或把字打进文本框）；点击后按钮一律 `blur()`，空格/回车不会重复触发「生成」白烧额度。
- **节点输入一律走 `useNodeTextField`**：聚焦期间本地草稿驱动（忽略外部 value），IME 组合期只存草稿、`compositionend`／非组合逐键提交，失焦兜底。受控输入经 React Flow props 往返会把中文组合提前固化——不要再手写受控输入。
- **节点标题只由右键「重命名」进入编辑**：默认显示普通文字，单击／双击不进入输入；重命名草稿在回车／失焦后一次提交，Esc 取消，输入法确认候选不提交重命名。
- **`updateNodeData` 快速路径只认白名单键**：`title`／`text`／`prompt`／`modelKey`／`generationMode`／`parameters` 的 patch 跳过全图 reconcile；`references` 等结构变化必须走全路径（服务端对账兜底）。新增可快速路径的键要同步 `FAST_PATH_DATA_KEYS`。
- **并发多变体（schema v2）语义**：single 模式提交 `variantCount`（1/2/4，非法值归一 1），同节点并存活跃任务上限 8（`MAX_NODE_VARIANTS`，超限 `node_variant_limit`）；branch 模式仍要求节点空闲（`node_busy`）。发布门禁只有 nodeEpoch，**最后完成者成为主结果**（`currentAssetId`），候选投影按节点取最近 12 条成功任务（`idx_cct_node_results`），供自动物化去重与 API 查询使用，界面不再单独展示候选列表。
- **Playwright 两条铁律**：高负载下节点随 1.5s 轮询持续重渲染，`page.click` 会一直等不到稳定——用 `dispatchEvent(new MouseEvent('click', { bubbles: true }))`；`waitForFunction` 是 raf 轮询，**里面禁止发 fetch**（会形成每秒几十个请求的风暴，把浏览器连接池打满、页面轮询饿死）——等服务端状态用 Node 侧循环 `fetch` + `setTimeout`。

## 环境与运行

- 画布数据根固定为仓库目录；网页版 `127.0.0.1:3100`，独立 LiteLLM 代理 `127.0.0.1:4100`；桌面壳用回环随机端口。启动入口见 `docs/reference/打包与桌面运行.md`。
- 开关：`CREATIVE_STUDIO_CANVAS_ENABLE=1` 开放画布；`CREATIVE_STUDIO_CANVAS_EXECUTOR=disabled|fixture|company`。`fixture` 还要求 `CREATIVE_STUDIO_CANVAS_TEST_ROOT=1` 且显式设置数据根，界面会显示「测试模式」。
- 真实样本：`node scripts/canvas-p7-readiness.mjs`（只读前置检查）→ `node scripts/canvas-p7-sample.mjs R01…`（受控样本驱动，产物与回执落到 `outputs/canvas-validation/p7/`）。R07 视频生视频（参考视频＋参考图＋参考音频）、R08 参考生成、R09 首尾帧这三个样本会向方舟发真实请求。
- 已知环境阻塞：不在公司内网时公司网关 HTTPS 握手被重置，公司渠道样本需待内网补验；外部供应商已配置时可独立验证对应链路。外部成功不能替代公司模型合同验证，内网不可达也不能作为本地调度／保存／恢复测试的阻塞理由。

## Seedance 直连与公司边界

- `adapters/seedance-capabilities.ts` 声明两代直连模式与参数；精确型号输出规则在 `lib/video-providers/seedance-contract.ts`。2.5 的 30/10/10、纯音频、分类 30 秒与媒体预检已本地映射；真实组合效果仍单列验收。
- 生成阶段放在节点参数与任务快照中，缺省为 `direct`。2.5 `draft` 锁 480p；`final-from-draft` 只使用固定 `draftAssetId`，服务器从已成功任务查出远端身份，绝不接收客户端自填远端 ID/时间。
- `video-metadata.ts` 与 schema v3 保存来源、供应商时间/用量、格式和附属尾帧；只有远端明确确认的 Draft 能进入转正式流程。过期按远端创建时间 +7 天，规划及首次 POST 前重验，已提交正式任务仍可恢复。
- Final 有独立请求白名单。分支遍历在 Final 节点停止，选片、复制、刷新不会触发生成；普通溯源边仍是规划死端。模型/渠道切换不把固定 Final 自动改成普通任务。
- 原视频扩展名、尺寸、时长、编码/像素格式落盘；播放使用共享 `video-browser-preview.ts`，下载和导出保留原件。MOV/PCM 同样生成 MP4/AAC 预览。尾帧作为附属资产，不占主输出；可从结果添加为素材节点。
- 2.0 标准 4K 使用独立持久化名额（并发 1）与至少 4 秒启动间隔（15 RPM）；准备耗时后在提交意图时续设间隔，租约恢复不再次占用提交额度。
- 公司时长、尺寸档位和尾帧分别引用共享模块。公司 2.5 仍只有已验证 1080p，Fast 显示网关默认待核；2.0 标准为未注册候选。公司扩展模式、档位、30 秒、样片/Final 受真实探测门禁约束，不能称为全渠道对齐完成。
- 直连没有公司计价依据；自动时长待产物探测后计量，不回退为 1 秒。任务记录提供生成次数，供应商实际 usage 与账本估算分开保存。

本地验收及未执行项见 `docs/2026-10-03-画布即梦全渠道对齐-本地验收.md`。付费探测脚本 `scripts/canvas-seedance-contract-probe.ts` 默认仅 dry-run；执行还需用户对具体批次授权。已经写入回执的请求禁止自动重跑。

## 运行日志

编辑器右上角「运行日志」查看当前画布最近 300 条记录；「任务 → 查看日志」按任务筛选（跨画布任务使用其所属画布）。支持实时刷新、级别筛选、复制全部／错误和关闭自动滚动。独立接口为 `GET /api/canvas/[id]/logs?jobId=&limit=`，经过功能开关与 readiness gate，最多返回 1000 条。

任务创建、准备、提交、远端身份、下载、成功、失败、恢复及停止意图写入 `creative_canvas_logs`，错误在补下载成功后仍保留；有新错误的轮询会记录，正常轮询与租约心跳不刷屏。日志另写 `dataRoot()/storage/logs/canvas-YYYY-MM-DD.log`（UTC 日期），复用共享脱敏方法清除密钥、鉴权内容与 URL 查询参数。未生成阶段日志的旧任务显示明确标记的历史状态快照，不能还原旧执行全过程。
