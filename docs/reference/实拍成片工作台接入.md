# 实拍成片工作台接入

适用：已完成固定渲染的实拍成片，登记到现有五步工作台后换候选、调整截取位置与顺序，再向原交付目录导出新版本。P2 增加指定镜头的第二/四步返工，生成仍由原图片/视频队列执行。使用源码桌面或免安装桌面；安装版另验。

## 当前工作台入口

四套 overlay 模板成片进入第五步时，通过同源 `use-mixcut` 接口一次性转入原单条精准混剪草稿；顶部沿用分镜组切换。字幕、包装文案与版式、音乐及已有镜头时间线保留，原配音拼接为供原播放器使用的音轨。后续编辑和导出走原精剪接口与 worker，不再显示独立实拍编辑区或制作进度区。

转换在事务中检查版本，保留不可变导入记录、原交付文件和完整转换前审计快照。`timeline.importedFilmEditor` 标识接管后的草稿；恢复历史时保留此标识。冻结的历史 classic 模板尚不能无损转换，继续使用兼容入口。下文固定渲染编辑协议只适用于尚未接管的历史草稿。

同项目、同交付目录共用 `成片审片-<项目ID前8位>.html`，按分组显示视频；只在播放时加载媒体，并暂停其他播放器。原单片 HTML 归档到各自 `.creative-studio/<绑定ID>/legacy-review.html`。原精剪导出成功后复制新版视频、封面并更新这个汇总页；目录离线或刷新失败保留成功导出，并在任务输出记录 `reviewWarning`。

## 新视频候选与定长变速

具备 `film-external-candidates/1` 的版本可在第五步“添加新视频候选”：上传到本项目/分镜组，预览并填写审核区间，再登记到指定镜头；随后仍需明确选择候选并替换。上传及登记不改时间线，外部素材使用真实 `final_edit_external_assets` 身份，不创建供应商任务。已登记素材由删除入口保护，供历史恢复使用。

Agent 可按 P2 镜头协议提交 `register_external`，字段为 `externalAssetId`、`approvedRangeSec`、`requestId`、`expectedRevision`；复制/探测后复核版本和素材状态，冲突不能抬版本自动重试。网络结果不确定时重放同一请求，返回原回执。候选内部媒体身份仍用 `external-asset-<id>`，不得把它当作供应商远端任务 ID。

具备 `film-fixed-duration-speed/1` 的版本可在第五步“调整镜头速度”，范围 0.25–4 倍，保持片段时长和其他镜头位置，按新速度调整源片结束位置；审核范围或 classic 转场余量不足则拒绝。保存走草稿版本检查，冲突保留输入。变速后需要复核圆点、引线和画面的对应关系。改变片段时长及总片长不由此能力提供；验收范围见[新素材与变速](../2026-10-19-实拍重组新素材与变速-Windows验收.md)。

## 连接与登记

启动桌面版后，在仓库根（免安装版使用包内 Node）运行：

```text
node scripts/reassembled-workbench.mjs doctor <数据根绝对路径>
node scripts/reassembled-workbench.mjs connect <数据根绝对路径>
node scripts/reassembled-workbench.mjs import <数据根绝对路径> <导入清单.json>
node scripts/reassembled-workbench.mjs review <数据根绝对路径> <成片登记ID>
```

CLI 读取指定数据根的 `storage/run/electron-service.json`，只访问本机回环服务，核对实例 ID、数据根摘要与 API 版本。导入令牌仅从本机文件读取，不打印或放进审片页。CLI 不直接写 SQLite。Windows 的 `connect` 需要当前桌面具备 `film-review-launch/1`，注册该用户/数据根专属的审片协议；其他平台或未配置协议时，桌面重启、端口变化后仍需重跑 `review` 更新 HTTP 连接。

协议处理器固定当前应用、Node、数据根和 Electron 用户目录；URI 仅含成片 ID、数据身份、交付版本及审片 token。按数据根串行发现/启动与导航，只有状态缺失或明确拒绝连接才进入冷启动，超时不作为重复启动依据。桌面 `loadURL` 完成后写带请求身份的原子回执，助手核对回执后报告成功。隐藏 PowerShell 包装器与 Node 助手保持到桌面退出，现有启动脚本显式等待 Electron，再清理 sidecar；不能对隐藏 PowerShell 使用 detached 启动，也不能提前 unref 结束其宿主。

connect 后对已有成片执行 review 更新 HTML。已配置的协议入口可跨桌面重启和随机端口变化；程序或数据目录移动后重新 connect/review。`disconnect <数据根>` 可离线解除同归属协议，正常交付不自动解除。浏览器可能要求确认打开本机应用。诊断在数据根 `storage/logs/reassembled-launch.log` 与 `reassembled-launch-error.json`；状态/日志不记录原始 URI 或 token。Windows 实测范围见 [审片启动验收](../2026-10-19-实拍重组审片启动-Windows验收.md)。

导入清单 v1 的类型定义为 `lib/final-edit/reassembled/types.ts` 的 `FilmImportManifest`：

| 字段 | 要求 |
| --- | --- |
| schemaVersion / importKey | 固定 1；同一条完成工程保持同一 importKey |
| projectId / root / title | 现有工作台项目 ID、工程绝对路径、可读标题 |
| specFile / renderManifestFile | 工程内已成功渲染的 spec.json 与 render-manifest.json 相对路径 |
| files | 相对文件名到 SHA256 的映射；包含所有渲染输入、原图、生成图、候选、渲染单/清单及已交付 MP4/JPG |
| sceneImage / sceneProvenance | 场景图相对路径与真实生成出处 |
| shots | 与渲染单逐镜对应；指定入选候选，以及本镜头自己的候选列表 |
| candidates | id、视频 file、实拍 sourceImage、分镜 generatedImage、真实 providerId/model/prompt、可为空的 providerTaskId、图片 provenance、已审核源片区间 approvedRangeSec |
| delivery | 原交付目录 directory 与原渲染基础名 baseName；原 MP4/JPG 必须存在且与渲染清单一致 |

所有文件留在工程根内，拒绝路径越界与哈希变化。候选关联工作台已有视频供应商；无远端 ID 时留空，不能伪造生成任务身份。服务端复核已有视频后，把素材复制到数据根的受管目录，在事务中登记场景、分镜、完成的视频、脚本及成片组。重复清单返回同一组；同 importKey 的不同内容拒绝，不能覆盖人工编辑。

清单的文件路径统一使用 `/`。Windows 固定渲染历史 spec 和 `render.inputs` 可能使用反斜杠：服务端先按原始内容核验哈希，再规范化受管副本中的路径；导入方不能改写原始渲染记录来迁就清单格式。

初版工程仍以原名交付，登记后生成 `<基础名>-工作台审片-<身份前8位>.html`。HTML 的视频/封面用同目录文件，可本地播放；协议入口发现当前实例，HTTP 备用链接绑定生成时的实例，两者均核对数据目录、成片和交付版本。服务端审片视频使用内部不可变渲染副本；JPEG 走 `/api/reassembled-films/<绑定ID>/cover?version=<版本>`，首次交付读取导入副本，后续读取该已发布版本的成功任务输出，不回退到其他封面。点击编辑后桌面主进程消费只含项目/成片身份的导航请求，不接受任意 URL。

## 开工归属与制作同步

具备 `film-production-sync/1` 的桌面版本支持先建归属再制作。CLI 新增 `begin <数据根> <begin.json>`、`production <数据根> <制作批次ID>`、`sync <数据根> <制作片号ID> <sync.json>`；类型以 `production-types.ts` 为准。`begin` 传稳定 requestId、工程绝对 root、新建项目生产身份或已有 projectId，以及各条 key/importKey/title/clips。返回稳定项目、分镜组、镜头映射和预留成片组身份。同 requestId 不同参数拒绝；同内容重连返回同一批次。

`sync` 提交 `{requestId, expectedRevision, snapshot}` 全量追加快照：files 是工程相对路径与 SHA256；tasks 记录实际本地任务 ID、kind、clipId、状态、供应商/模型/最终提示词、inputFiles，以及实际存在的 remoteTaskId、成功 outputFile；shots 保存原图、当前分镜图和具备准确出处的候选；script 保存已成功脚本任务 ID 和 narration。不能上传密钥、请求头或任意扩展字段。相对路径使用 `/`，新生成使用新文件名，已登记文件和终态任务不可改写或删除。

制作任务由 skill 的执行器负责；queued/running/failed/cancelled 仅保存为只读台账，不进入工作台执行队列。成功媒体经哈希、图像元数据、实际视频流/时长校验后才登记 succeeded 核心行。五步页面按当前阶段展示该批各条的状态和完成素材。原重新生成入口拒绝对受管图片建任务，须在最终接管后走 P2 逐镜头接口；人工审核标记不允许 Agent 覆盖。

同步和最终导入都核对已同步实际数据库行，文件处理前后再次核对版本和基线。人工修改、删除、选择变化返回 409，保留现有内容，不能仅改 expectedRevision 强行续写。冲突应读回当前状态并保留待处理素材，不直接改库解除。两条成片的基线相互独立。

完成后导入清单增加 `production: {itemId, expectedRevision}`，projectId/importKey/root、场景、镜头候选、脚本及已同步指纹必须相符。导入复用已有对象和预留成片 ID；成功后锁定该条制作同步，后续修改走 P2 候选或内容提案。完全相同的旧请求重放只返回原结果，不重新应用；不会覆盖接管后的人工修改。历史已完成工程仍可使用不带 production 的原导入方式。

生产同步测试入口为 `reassembled-film-production.test.ts`（`FILM_PRODUCTION_BASE_MANIFEST` 指向已验证合成工程）及 `reassembled-film-production.desktop.test.mjs`（`FILM_PRODUCTION_FIXTURE` 指向服务验收输出；`FILM_DESKTOP_APP_ROOT` 可指定新免安装 QA 包）。服务测试不能代替桌面和免安装的实际运行证据。

## 编辑与导出

第五步复用既有时间线、裁切工具、修订记录及成片 worker。P1 支持同一镜头的已登记候选替换、截取位置、镜头顺序和可投影的历史恢复。后续 `edit-film-content/1` 增加下述内容编辑；源片构图和配音文件保持原契约。定长操作保留总片长；显式时长修改使用下述独立命令。未接入的编辑明确拒绝，避免保存后被固定渲染忽略。classic 标注随所属镜头平移，仍需检查人物避让与标签内容。

**换镜头后可直接导出。** 用户在本轮明确取消强制预览及确认闸门：完整带包装预览是可选操作，历史画面会显示版本提示，不增加确认按钮。预览生成使用相同固定渲染核心，不把旧画面当作新编辑的实时效果。

导出冻结素材/模板哈希与组、草稿修订，继续使用 `renderFilm` 的完整技术核验。当前交付目录中创建 `-v2`、`-v3` 等视频和 JPG；两份新文件成功后才将上一对移入 `旧版/`。不覆盖陌生同名文件或已改变的原文件。外部目录离线、身份标记失效、渲染失败均保留旧成片。新文件成功但旧版被占用时，显示归档警告并提供重试。

同一修订重复导出复用同一任务，未完成的交付只预留一个版本。失败可重试，取消释放未发布版本；已完成版本不能通过旧任务重试覆盖或复活。重新打开未完成任务会恢复本地队列。旧修订的导出结果保留其准确版本，不冒充当前编辑。

## P2 局部返工与人工保护

第五步选择镜头 →「返工这个镜头」进入第二步；编辑实际提示词、底图及参考图，生成后明确采用分镜图；进入第四步生成该镜头视频，审核实际视频与有效区间后登记为第五步候选；回到第五步明确替换。链接保留 `filmGroup`、`filmShotSet` 和 `filmClip`。原片段时长保持不变，classic 转场余量继续校验；新内容的人物避让和标注位置仍须审片。

每镜头的返工版本与生成请求存于 `final_edit_film_shots` / `final_edit_film_reworks`（final-edit 迁移 v14）。生成不抢占 `shots.latestJobId`，队列完成只产生候选；明确采用才写当前图。因此迟到结果、Agent 续跑不覆盖人工选择。所有生成请求冻结输入、参考图、提示词、供应商、模型；旧导入清单没有记录的参考图不能猜测，返工时显式选择。

`GET /api/final-edit-groups/<groupId>/rework/<clipId>` 返回来源、当前版本、候选和历史；`POST` 必须携带 `requestId`（8–100 位字母数字、下划线或短横线）、整数 `expectedRevision` 和以下操作：

| type | 参数与行为 |
| --- | --- |
| generate_image | providerId、model、prompt、inputImageId、referenceImageIds、size、quality；创建单个新图片候选任务 |
| select_image | imageId；人工明确采用该镜头候选或恢复导入图，Agent 禁止 |
| generate_video | providerId、model、prompt、imageId、durationSec；imageId 必须仍是当前选择，创建单个新视频候选任务 |
| register_video | videoJobId、approvedRangeSec；成功视频必须属于当前项目/组/镜头，复制新托管文件、核验哈希和范围后追加候选，不修改时间线 |

同一请求标识和完整相同命令重试返回原结果，不新建生成任务；标识复用于不同内容返回 409。重启后「继续原任务」重放已保存命令，使用原任务 ID 和参数。失败任务不会因此重新付费生成。发生版本冲突时保留表单输入，用户核对并点击「刷新当前版本」后才能按新版本再次提交；自动轮询不会悄悄更新表单写入基线。

API 根据本机实例 token 判断 Agent，根据同源浏览器请求判断工作台操作；不接受 body 自称 human。Agent 只能生成和登记候选，不能采用图片或直接 PATCH 已接管时间线。该规则是本机协作协议，不是对能操纵浏览器或任意写本地数据库的攻击者的权限隔离。旧无版本切图、整组换景/批量视频入口和删除已接管分镜组均拒绝操作；普通项目原行为保留。局部队列只领取/恢复指定任务，不启动其他镜头的待处理任务。

Agent 使用既有 CLI，无需打印 token 或直接写库：

```text
node scripts/reassembled-workbench.mjs shot <数据根> <成片组ID> <镜头ID>
node scripts/reassembled-workbench.mjs rework <数据根> <成片组ID> <镜头ID> <命令.json>
```

先确认 doctor 包含 `shot-rework-candidates/1`，读取版本，再保存带稳定 requestId 的命令文件。网络结果不确定时重用原文件重试。409 时重新读取并判断，不自动把旧命令的版本号改成最新。生成收费仍由用户授权和预算约束；P2 验收中的本机假供应商不代表付费供应商已实测。

## 验证

### 批次定位与连接发现

`ReassembledProductionStatus` 在项目总览展示逐条制作进度；携带有效 `filmGroup` 进入已接管成片后改为“返回成片总览”导航，避免整批卡片把第五步编辑器或第二/四步返工面板挤到屏幕下方。归属继续使用 projectId、groupId、shotSetId 和 clipId，不依赖卡片顺序或文件名。

CLI 发现阶段缺少、损坏服务状态或实例失联时，明确提示启动使用同一数据目录的桌面并重跑 doctor，不创建项目、不自动注册或启动供应商。错实例、错数据身份及非本机地址仍拒绝。`reassembled-workbench-doctor.test.mjs` 只使用临时目录和本机 HTTP；`FILM_DOCTOR_CLI` 可指定包内 CLI，验证实际装配脚本。

### 内容编辑与 Agent 提案

第五步“编辑包装、字幕与音乐”使用本地草稿，保存 `set_film_content` 带打开时的 variant revision。`timelineJson.filmContent` 与镜头共用修订、恢复和交付版本；原始 binding.specJson 不改，`projectFilmTimeline` 校验内容后投影到同一固定渲染。允许的字段见 `reassembled/content.ts`，不接受来源路径、CSS、运行时或源片字段。字幕编辑不生成配音；读取工作台时字幕轨道显示当前修订内容。

四模板支持标题、封面/正文卖点、位置/缩放/旋转、时序和显式模板切换；classic 支持已有封面/标签/标注/片尾文字、标注坐标和时间。标注时间在原始镜头坐标中保存，渲染时跟随镜头重排平移。音乐支持源入点、音量和淡入淡出。字体、颜色、封面换图和音轨生成尚未接入，不能用该能力标识推断已开放。

`GET /api/final-edit-groups/<groupId>/film-content` 返回当前 variantId、revision、镜头、content、originalContent、历史和提案。`POST` 接受 `{requestId, expectedRevision, summary, content}`，创建 `final_edit_proposals.kind=film-content` 候选，不修改当前修订；相同请求幂等，内容或归属不同拒绝复用 ID。提案创建与采用都检查基线。用户可打开提案后精修，以 `set_film_content` 携带 proposalId 保存；旧提案即使携带最新期望版本仍拒绝，采用与修订写入同一事务。Agent 不能直接 PATCH 当前内容。

CLI：`current <数据根> <成片组ID>` 读取；`propose <数据根> <成片组ID> <提案.json>` 提交。先确认 `film-content-proposals/1`。提案界面会显示过期状态，不自动重置版本；自动轮询不更新脏表单的写入基线。历史恢复产生新修订，导出从当前快照生成 MP4/JPG。

classic 的跟踪标注使用 `callout-edit.ts`：圆点位移同步平移全部关键帧；显示区间裁剪按原轨迹插值端点，保持原移动速度。卡片位置独立调整，也可明确改为固定圆点。最终仍按所属镜头、画幅和最短显示时长校验，不因表单编辑放宽渲染契约。

新增验证：`reassembled-film-content.test.ts`（五模板投影/拒绝），`reassembled-film-content.integration.test.ts`（持久化/恢复/渲染），`reassembled-film-proposals.test.ts`（候选/幂等/过期/采用），`reassembled-film-callout-edit.test.ts`（跟踪轨迹位移和插值），`reassembled-film-content.desktop.test.mjs`（真实表单与导出，`FILM_CONTENT_PROPOSALS=1` 增加真实 CLI 提案采用）。具体隔离路径和已测边界见 [完整接管阶段记录](../2026-10-19-实拍重组完整接管-实施与验收.md)。这些能力仍在迭代，不能以源码验收代替更新后的免安装验收。

### 显式片段时长

局部视频返工创建任务时明确关闭公司 Kling 3.0 智能分镜：通过 `normalizeVideoMultiShotForStorage(provider.type, model, false)` 保存 `multiShot=0`；非目标模型保留 NULL。单镜头返工不继承普通视频入口的默认多镜头语义。专项为 `reassembled-rework-single-shot.test.ts`，真实 Windows 来源/免安装最终证据见 [真实返工验收](../2026-10-19-实拍重组真实素材接管与返工恢复-Windows验收.md)。

`film-ripple-duration/1` 对应第五步“调整镜头时长”和 variant 命令 `set_film_clip_duration {clipId,durationFrames,expectedRevision}`。以 24fps 整数帧调整所选镜头源终点，后续镜头整体平移差值，素材、源区间、速度及人工内容快照保留。每镜至少 12 帧，成片含封面至少 360 帧；当前总长从 variant.timeline 计算，原始 spec 与配音信息不回写。

投影用新 canvas.frames 校验源片、审核范围与 classic 转场余量，再检查字幕、配音、音乐淡变和包装边界。字幕、配音和四模板定时卖点保留绝对时间，classic 标注按所属镜头平移，片尾按最后镜头和总长生成。失败整次拒绝并给出依赖冲突，不自动删改人工内容；界面显示总长变化及需要重审的画面对应关系，完整预览仍可选。原始非整数帧源入点在未改入点时保持精确值。

时长、速度和截取表单均冻结打开时的修订。冲突保留输入，取消重开后才取得新基线；时间线历史可恢复先前时长。通用混剪不接收该实拍专用命令。专项测试和实际桌面证据见 [片段时长 Windows 验收](../2026-10-19-实拍重组片段时长-Windows验收.md)，以该记录明确的通过范围为准。
