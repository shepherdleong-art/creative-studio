# 固定渲染命令

`scripts/film-render.ts` 将已准备好的实拍重组工程渲染为 MP4、JPG、技术检查报告和输入清单。核心为 `lib/film-render/render.ts` 的 `renderFilm({ spec, runDir, signal, onStage })`，不访问工作台数据库，不调用生成供应商。

支持 classic/1 及 `overlay-poster`、`overlay-journal`、`overlay-minimal`、`overlay-variety`（A/B/C/D，版本 1）。统一为 1080×1440、24fps、20 帧完整静帧封面、至少 15 秒。classic 包含字幕、贴纸、卖点标注和片尾；叠层模板使用正文硬切、共享字幕和模板卖点标签。第一阶段验收见 [Windows 执行记录](../2026-10-15-固定渲染命令-Windows执行记录.md)、[macOS 验收记录](../2026-10-15-固定渲染命令-macOS验收记录.md) 与 [Windows 桌面导出验收](../2026-10-16-固定渲染命令-Windows桌面验收记录.md)。第二阶段见 [Windows 四模板接入验收](../2026-10-16-固定渲染命令-四模板接入验收.md) 与 [macOS 第二阶段验收](../2026-10-17-固定渲染命令-macOS第二阶段验收.md)，两平台分别实际验证。

## 使用

在仓库准备 Node 22+、依赖和离线包装运行时。入口会根据自身位置定位仓库，允许从其他目录使用绝对路径调用；已有环境变量不覆盖。

```powershell
npm run setup:packaging
node scripts/film-render.ts doctor
node scripts/film-render.ts templates

$filmProject = 'I:\m7-studio\outputs\你的工程'
node scripts/film-render.ts spec $filmProject 01 --out .\render-spec.json
node scripts/film-render.ts render .\render-spec.json --run-id first --progress-json
node scripts/film-render.ts verify "$filmProject\variants\01\renders\first\01.mp4" --spec .\render-spec.json
node scripts/film-render.ts gate $filmProject 01
```

成片基础名取 `--base-name`，其次取 `review/delivery.json` 中明确的 `variants` 或 `files` 片号映射，没有交付记录则用片号。实际输出名看最后一行 JSON，不能假定总是 `01.mp4`。交付记录可以保留旧文件名；比较历史成片时，应按交付 SHA256 核实实际文件，不能凭重命名后的名字猜归属。

`spec` 只读 `packaging.json`、`variants/<片号>/timeline.json` 与输入素材；classic 另读 `DESIGN.md`、`tools/style.css`。视频、封面、配音、音乐的时间线路径均相对片号目录；生成的渲染单统一为工程内路径。`--out` 和所有输出目录拒绝覆盖。

现场脚本有额外参数时须显式保留：RC2C 02 使用 `--music-in 8`；其余已验收样本为 0。封面默认第 16 帧（对应 RC2C 的 0.65 秒取帧），可用 `--cover-frame 0` 等改为 0–19 范围内其他帧。BS619-A v3 需显式指定对应基础名，历史 v2 交付映射不代表 v3。

```powershell
node scripts/film-render.ts spec $filmProject 02 --music-in 8 --out .\02-spec.json
node scripts/film-render.ts compare .\new.mp4 .\original.mp4 --spec .\02-spec.json --ssim 0.98 --sheet .\comparison.jpg --reference-html .\original-hf\index.html
```

`gate` 是独立开场审核闸门，交付前运行。技术渲染成功不等于视觉或用户审核通过；旧审核缺哈希会明确返回 `legacyReviewWithoutHash`，不能补造批准。

## 渲染单与输出

渲染单 `schemaVersion: 1` 显式记录 canvas、shots、subtitles、audio、output，以及 classic 或 cover/packaging 模板分支。所有输入必须存在且在 `project.root` 内，拒绝符号链接越界；单条内不重复使用同一源片。镜头从第 20 帧连续到结尾。classic 非末镜多准备 4 帧过渡余量；叠层模板硬切，无过渡余量。若有 `approvedSourceRangeSec`，实际准备区间必须全部位于已审核范围。

### 四套叠层模板输入

在 `packaging.json.variants[片号]` 写入 `packaging` 段即可切换；缺此段沿用 classic：

```json
{
  "variants": {
    "01": {
      "packaging": {
        "template": "overlay-poster",
        "title": "小卧室梳妆角",
        "subtitle": "胡桃色与法式细节",
        "coverPoints": ["几何线框抽面", "六抽屉分区收纳"],
        "bodyCues": [{ "id": "detail", "text": "法式线框细节", "startFrame": 90, "endFrame": 165 }],
        "layouts": {}
      }
    }
  }
}
```

主副标题非空、最多 100 字；封面卖点最多 3 条。正文区间是含封面的成片帧坐标，结束帧不含在区间内。`spec` 用共享 `postProcessTimedCues`、`sanitizePointCues` 整理间隔/最短停留/片尾/数量限制，并在 stderr 逐条报告调整前后内容；缺 ID 时按输入顺序生成 `cue-1` 等。核对报告后再渲染，不自动提炼或对齐口播。

生成的 `packaging` 采用共享配置字段：enabled、template、varsOverrides、pointCuesMode、pointCues、layouts。校验拒绝清洗后改变的文案/卖点/布局、字体槽、重复 ID、重叠/越界时序及无对应卖点的布局。当前不支持 classic 标注、贴纸或片尾。

底片采用无损 `qp 0` 准备片段、20 帧静止封面、硬切与思源黑体字幕，再用 CRF 12 编码。`overlay-subtitles.ts` 直接读取 `templates/classic/1/assets/fonts/SourceHanSansCN-VF.ttf`，校验冻结哈希并用 fontkit 按 400 字重生成 SVG 字形轮廓，交给 sharp 栅格化；保持共享默认位置、字号及描边，无需系统安装字体。缺字拒绝渲染，不静默回退系统字体；构图和渲染清单记录字体哈希。共享 `renderVideoPackaging` 完成 CRF 18 包装，显式启用 `staticCover`，第 20 帧隐藏封面层。工作台默认退场动画不变。最终 JPG 从完整成片取帧。

生产布局须避开人物完整可见轮廓及显示区间内动作范围，不能只检查脸部；四模板按稳定卖点 ID 设置 `layouts[template].cues[id]`。移位、缩小或调整时段仍无法避让时，省略该处卖点并记录原因。固定命令不含自动人物检测，实际成片须检查进场、停留、退场完整区间及字幕/产品冲突。

配音为 48kHz 单声道 PCM16 WAV，按实际采样点裁切并拼接，不重叠、不越过片尾。`audio.music.inSec` 指配乐源入点。已核实默认混音为 −14dB 配乐、0.25 秒淡入、1 秒淡出、口播侧链闪避、两遍 −16 LUFS / −1.6 dBTP / LRA 11 归一化。

每次写入 `variants/<片号>/renders/<runId>/` 新目录，保留 spec、准备片段、HyperFrames 工程与日志、音频中间件、内部审核图、MP4、JPG、`checks.json` 和 `render-manifest.json`。已有工程及旧交付不覆盖。失败保留中间文件和 `failure.json`，不写成功清单。

清单记录输入、渲染单、构建器和模板资源 SHA256，以及 Node、FFmpeg、FFprobe、HyperFrames、Chrome、锁文件哈希、阶段耗时、黑边修正证据和产物哈希。边缘修正仅在输出出现黑条且源片对应边缘正常时启用，最终封装时裁掉右侧 8 像素后恢复 1080 宽；源片自身黑边不误修。

## 运行时与检查

工作台和命令共用 `packaging/` 中锁定的 HyperFrames 0.8.134、Chrome 152.0.7977.30，运行阶段禁止自动下载、遥测和 npx 回退。classic 使用仓库自带思源黑体 VF 与 GSAP 3.14.2，资源哈希冻结。Windows 复用 `win-hide-spawn.cjs`，探针输出经私有临时文件，超时/中止等待子进程退出；HyperFrames 中止会结束本任务进程树。仅 `ffprobe deadline` 可自动重试一次。

`doctor` 检查声明、锁文件、安装版本、Chrome、字体和 GSAP 哈希，返回实际工具路径及版本；无效 FFmpeg 环境变量发生回退时明确警告。升级步骤见 [视频包装](视频包装.md#升级-hyperframes)。

离线版本契约在 `packaging/film-runtime.json`，setup 与运行期共同读取；运行期不读取 `scripts/setup-packaging-runtime.mjs`。standalone 同步会把固定清单中的构建器源码存入 `packaging/film-builders/`，附 SHA256 清单，仅作构建来源核验，不执行这些源码。随包归档存在时优先核对归档，缺件或不符不得回退到旁边的开发源码。classic 模板通过共享包装资源解析器查找，支持数据根与程序目录分开。

Windows 默认 FFprobe 使用锁定的 `@ffprobe-installer/ffprobe@2.1.2`（x64 平台包 5.1.0），随 standalone 分发；旧 4.0.2 在真实 H.264 素材上可发生探针收尾超时，不能用文件输出或重试声称消除。仍支持显式工具路径覆盖，实际采用值以 `doctor` 与清单为准。排查、回归和 Mac 交接见 [P0 收尾记录](../2026-10-16-FFprobe稳定性与P0收尾.md)。

Windows 工作台深层路径另有两个兼容边界：classic 的 HyperFrames 事务目录可能超长，`hyperframes.ts` 在原工程路径超过 160 字符时，将生成的工程暂存到 `dataRoot()/storage/run/hf-*` 中渲染，完成后复制结果与日志回原渲染目录。只清理本次创建且成功的临时目录，失败保留诊断；`hf/windows-workspace.json` 记录路径与保留状态。复制逐文件执行并拒绝链接，避免 Node 22 深路径 `cpSync` 的本机崩溃。叠层封面中间文件缩短为 `base/p-cover.png`；检查图以 Buffer 交给 sharp，再由 Node 写入，避免 libvips 的路径限制。这些调整不修改 classic/1 构建器、模板、画面检查或阈值，也不承诺任意长度的 Windows 路径。

`verify` 核对解码帧数、分辨率、24fps、片长、完整解码、音频覆盖、响度、全片黑帧、前 20 帧 RGB 平均差、JPG 相似度和生成黑条。阈值沿用 Windows 现场：−17 < LUFS < −15、真峰值 ≤ −1.4dBTP、封面 RGB 平均差 < 0.8、无连续 0.1 秒以上黑帧。文字完整性、产品保真、口播与画面对齐仍需实际审片。

`compare` 对帧数/时长/分辨率/帧率、音频响度（差 ≤0.5 LU）与音轨时长（差 ≤1 帧）、构图文件逐字节一致性及抽样 SSIM 作检查并生成并排图。classic 比较 HTML；叠层模板比较 `base/composition.json`，并抽查正文卖点中点。默认 SSIM ≥0.98，同一渲染单复渲使用 ≥0.99。原片有缺陷时不能降低全局阈值冒充一致；记录具体差异与用户决定，原始失败报告保留。

最后一行是结果 JSON；`--progress-json` 额外逐行输出阶段进度。退出码：0 成功、2 输入错误、3 工具/资源缺失或不符、4 渲染/技术检查失败。

- `node scripts/film-render-spec.test.ts`：五组金样往返、只读转换、输入校验与批准源片区间。
- `node scripts/film-render-process.test.ts`、`film-render-media.test.ts`：进程错误/中止、真实 FFmpeg、音频、帧数、静帧与黑边检查。
- `node scripts/film-render-cli.test.ts`、`packaging-runtime-pin.test.ts`：CLI 错误码、缺资源/哈希/版本、工具回退和版本锁。
- `FILM_E2E=1 node scripts/film-render.e2e.test.ts`：合成素材与跟踪标注完整出片两次，比较 SSIM ≥0.99。PowerShell 先设 `$env:FILM_E2E='1'`。
- `node scripts/film-render-overlay.test.ts`：四模板转换、只读输入、调整报告和无效配置；`FILM_E2E=1 node scripts/film-render-overlay.e2e.test.ts`：四模板各两次完整出片与比较，严格检查 20 帧静止和 380 帧总长。
- `node scripts/film-render-subtitles.test.ts`：思源黑体字形实际栅格化、字幕位置、系统字体独立性、缺字/缺资源/哈希错误拒绝。
- `node scripts/film-render-probe.test.ts`：Windows 随包探针 64 次检查；`FILM_PROBE_SOURCE` 可选择本机失败素材作真实回归，详见收尾记录。
- 构建后 `node scripts/film-render-portable.test.mjs`：隔离打包后的核心、随包运行资源和独立数据根，删除开发源码后核验运行时及构建器来源；设置 `FILM_PORTABLE_SPEC`、`FILM_PORTABLE_REFERENCE` 可追加实际渲染及源码参考片对比。它验证渲染核心资源边界，不代表完整免安装版 UI 或第五步闭环验收。
