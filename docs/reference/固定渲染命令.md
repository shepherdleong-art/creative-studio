# 固定渲染命令

`scripts/film-render.ts` 将已准备好的实拍重组工程渲染为 MP4、JPG、技术检查报告和输入清单。核心为 `lib/film-render/render.ts` 的 `renderFilm({ spec, runDir, signal, onStage })`，不访问工作台数据库，不调用生成供应商。

当前支持 classic/1：1080×1440、24fps、20 帧完整静帧封面、至少 15 秒；包含字幕、逐镜贴纸、固定或跟踪卖点标注和片尾。四套工作台叠层模板接入此命令属于第二阶段。Windows 验收与剩余验收项见 [2026-10-15 执行记录](../2026-10-15-固定渲染命令-Windows执行记录.md)。

## 使用

在仓库准备 Node 22+、依赖和离线包装运行时。入口会根据自身位置定位仓库，允许从其他目录使用绝对路径调用；已有环境变量不覆盖。

```powershell
npm run setup:packaging
node scripts/film-render.ts doctor
node scripts/film-render.ts templates

$filmProject = 'I:\m7-studio\outputs\你的工程'
node scripts/film-render.ts spec $filmProject 01 --out .\render-spec.json
node scripts/film-render.ts render .\render-spec.json --run-id first --progress-json
node scripts/film-render.ts verify "$filmProject\variants\01\renders\first\01.mp4" --spec .\render-spec.json
node scripts/film-render.ts gate $filmProject 01
```

成片基础名取 `--base-name`，其次取 `review/delivery.json` 中明确的 `variants` 或 `files` 片号映射，没有交付记录则用片号。实际输出名看最后一行 JSON，不能假定总是 `01.mp4`。交付记录可以保留旧文件名；比较历史成片时，应按交付 SHA256 核实实际文件，不能凭重命名后的名字猜归属。

`spec` 只读 `packaging.json`、`DESIGN.md`、`tools/style.css`、`variants/<片号>/timeline.json` 与输入素材。视频、封面、配音、音乐的时间线路径均相对片号目录；生成的渲染单统一为工程内路径。`--out` 和所有输出目录拒绝覆盖。

现场脚本有额外参数时须显式保留：RC2C 02 使用 `--music-in 8`；其余已验收样本为 0。封面默认第 16 帧（对应 RC2C 的 0.65 秒取帧），可用 `--cover-frame 0` 等改为 0–19 范围内其他帧。BS619-A v3 需显式指定对应基础名，历史 v2 交付映射不代表 v3。

```powershell
node scripts/film-render.ts spec $filmProject 02 --music-in 8 --out .\02-spec.json
node scripts/film-render.ts compare .\new.mp4 .\original.mp4 --spec .\02-spec.json --ssim 0.98 --sheet .\comparison.jpg --reference-html .\original-hf\index.html
```

`gate` 是独立开场审核闸门，交付前运行。技术渲染成功不等于视觉或用户审核通过；旧审核缺哈希会明确返回 `legacyReviewWithoutHash`，不能补造批准。

## 渲染单与输出

渲染单 `schemaVersion: 1` 显式记录 canvas、shots、subtitles、audio、classic、output。参数不能省略后依赖隐式默认。所有输入必须存在且在 `project.root` 内，拒绝符号链接越界；单条内不重复使用同一源片。镜头从第 20 帧连续到结尾，除最后一镜外多准备 4 帧过渡余量；若有 `approvedSourceRangeSec`，余量也必须位于已审核区间。

配音为 48kHz 单声道 PCM16 WAV，按实际采样点裁切并拼接，不重叠、不越过片尾。`audio.music.inSec` 指配乐源入点。已核实默认混音为 −14dB 配乐、0.25 秒淡入、1 秒淡出、口播侧链闪避、两遍 −16 LUFS / −1.6 dBTP / LRA 11 归一化。

每次写入 `variants/<片号>/renders/<runId>/` 新目录，保留 spec、准备片段、HyperFrames 工程与日志、音频中间件、内部审核图、MP4、JPG、`checks.json` 和 `render-manifest.json`。已有工程及旧交付不覆盖。失败保留中间文件和 `failure.json`，不写成功清单。

清单记录输入、渲染单、构建器和模板资源 SHA256，以及 Node、FFmpeg、FFprobe、HyperFrames、Chrome、锁文件哈希、阶段耗时、黑边修正证据和产物哈希。边缘修正仅在输出出现黑条且源片对应边缘正常时启用，最终封装时裁掉右侧 8 像素后恢复 1080 宽；源片自身黑边不误修。

## 运行时与检查

工作台和命令共用 `packaging/` 中锁定的 HyperFrames 0.8.134、Chrome 152.0.7977.30，运行阶段禁止自动下载、遥测和 npx 回退。classic 使用仓库自带思源黑体 VF 与 GSAP 3.14.2，资源哈希冻结。Windows 复用 `win-hide-spawn.cjs`，探针输出经私有临时文件，超时/中止等待子进程退出；HyperFrames 中止会结束本任务进程树。仅 `ffprobe deadline` 可自动重试一次。

`doctor` 检查声明、锁文件、安装版本、Chrome、字体和 GSAP 哈希，返回实际工具路径及版本；无效 FFmpeg 环境变量发生回退时明确警告。升级步骤见 [视频包装](视频包装.md#升级-hyperframes)。

`verify` 核对解码帧数、分辨率、24fps、片长、完整解码、音频覆盖、响度、全片黑帧、前 20 帧 RGB 平均差、JPG 相似度和生成黑条。阈值沿用 Windows 现场：−17 < LUFS < −15、真峰值 ≤ −1.4dBTP、封面 RGB 平均差 < 0.8、无连续 0.1 秒以上黑帧。文字完整性、产品保真、口播与画面对齐仍需实际审片。

`compare` 对帧数/时长/分辨率/帧率、音频响度（差 ≤0.5 LU）与音轨时长（差 ≤1 帧）、HTML 逐字节一致性及抽样 SSIM 作检查并生成并排图。默认 SSIM ≥0.98，同一渲染单复渲使用 ≥0.99。原片有缺陷时不能降低全局阈值冒充一致；记录具体差异与用户决定，原始失败报告保留。

最后一行是结果 JSON；`--progress-json` 额外逐行输出阶段进度。退出码：0 成功、2 输入错误、3 工具/资源缺失或不符、4 渲染/技术检查失败。

## 验证与边界

- `node scripts/film-render-spec.test.ts`：五组金样往返、只读转换、输入校验与批准源片区间。
- `node scripts/film-render-process.test.ts`、`film-render-media.test.ts`：进程错误/中止、真实 FFmpeg、音频、帧数、静帧与黑边检查。
- `node scripts/film-render-cli.test.ts`、`packaging-runtime-pin.test.ts`：CLI 错误码、缺资源/哈希/版本、工具回退和版本锁。
- `FILM_E2E=1 node scripts/film-render.e2e.test.ts`：合成素材与跟踪标注完整出片两次，比较 SSIM ≥0.99。PowerShell 先设 `$env:FILM_E2E='1'`。

当前入口面向源码工程，未接入工作台的任务调度、交付目录、编号、发布与审片状态。P1 安装版调用还须处理运行时检查中的 setup 脚本定位、构建器源码哈希的打包方式及停机注册；资源复制成功不代表 P1 已完成。macOS 和桌面单条/批量导出需各自补验，不以 Windows 命令行通过替代。
