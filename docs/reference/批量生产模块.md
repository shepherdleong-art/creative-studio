`batch_asset_analysis`（素材身份是内容指纹、不依赖路径），v3 批次版本 `batch_production_versions` + 素材池 `batch_asset_pool_items`，v4 项目脚本 `batch_scripts` + 脚本快照 `batch_script_snapshots`，v5 成片计划 `batch_output_plans` + 成片版本 `batch_output_versions`（份数决定 N 条计划），v6 生产任务 `batch_tasks` + 任务尝试 `batch_task_attempts`（重试只增加尝试），v7 正式产物 `batch_artifacts` + 计划当前成片指向，v8 将正式产物改为按计划与路径追加保存并保护其批次谱系不被物理删除，v9 推导，linked 重新定位必须指定来源 id 且内容完全一致。`prepare.ts` + `GET /api/batch-production/prepare` 在 readiness gate 后自动同步输入；`components/mixcut/MixcutWorkspace.tsx` 提供“单条精准混剪/批量生产”模式入口。Phase B 在 `batch-flow.ts` ## Phase E — 联合分配与正式导出（v16）

- Phase E（联合分配与正式导出）在 v16 增加联合分配运行和批次内素材排除；`allocator.ts` 是一次读取全部冻结输入的纯确定性分配器，`allocation-store.ts` 保留运行谱系并保证单条重分配不改其他计划。单条重分配（换一批画面）把目标计划**历史所有版本**用过的非锁定素材、区间与封面都纳入避让（打分惩罚 + overlap 惩罚），派生 seed 纳入当前版本指针：连续点击持续换新、不会在两批画面间来回切换，同状态重试仍幂等，锁定句段不受避让影响，素材池耗尽才回退复用并给出 `previous-version-reused` 提醒。`batch-renderer.ts` 只读指纹一致的原片和冻结 LUT，复用 `ColorPipeline`，通过原有 batch scheduler 真实渲染；`batch-export.ts` 成对追加发布视频/封面并拒绝覆盖。`phase-e.ts` 负责可恢复启动、任务接线和逐条正式发布，`batch-workspace.ts` 聚合卡片状态，输出媒体 route 只接受稳定 ID。没有真实口播时仅生成显式静音候选，正式发布门禁必须要求已核验的 storage 相对口播快照。**媒体代际（B2）**：成功渲染尝试是媒体身份——`batch-workspace.ts` 候选暴露 `renderAttemptId`、版本列表暴露 `candidateRenderAttemptId` / `artifactId`；candidate 媒体 URL 绑定确切成功 attempt、artifact URL 绑定确切 artifactId，同一个 URL 的所有普通/Range 请求固定同一物理文件，封面任务成功后卡片封面**不刷新页面**即随成功切换（queued/running/failed 不提前切换）。**下载与播放（B3，2026-09-03 改）**：导出页播放器、下载视频、下载封面全部绑定 `currentFormalArtifact`（播放器 key 含 artifactId，正式成片从 A 切到 B 时真实换源）；完整渲染候选不抢在正式成片前播放或下载。
- 片段级手动编辑（检查成片的「调整片段」）在 `output-arrangement.ts`：trim（等长换窗/变长修剪）、replace（换素材，窗口从 0 起）、删除、插入、分割，就地改当前候选版本 `arrangementJson`（单事务整读-改-整写），每次画面生效编辑 `editRevision +1` 并删除 `$.review`（画面变了必须重新过审核门禁）；`editRevision` 进 `phase-e.ts` 的渲染 requestKey，否则就地编辑后的重渲染会被 `createBatchTask` 幂等去重吞掉。变长修剪/删除/插入都 ripple 平移后续片段，口播字幕不动，画面短了 tpad 补齐、长了裁掉；分割是纯结构操作（总长不变，不递增 editRevision、不清 review、不重渲染）。**渲染时机（2026-09-03 编辑器优先，取代 2026-08-25 版本）**：编辑器里的预览是客户端实时合成的，不看渲染产物，片段编辑一律只保存 arrangement，`deferRender`/`commit_render` 已删除；除改封面（`set_cover`）会按新封面契约建一条 `output_version_cover` 任务外，检查阶段任何编辑都不排渲染任务，整片 mp4 只在导出编排时渲染（见「编辑器优先与正式导出」节）。**素材使用次数（F3）**：池视图按片段出现次数实时派生 `useCountByPlanId`（`clips[]` 有几次计几次，split 切成两段计 2 次），前端素材列表徽标显示「本片已用 ×N / 其他成片已用 ×M」，两数独立并存；封面身份仍走独立的 `coverUsedByPlanIds`，不计入片段次数。**审核重置提示（B4）**：每次画面生效编辑原子返回 `reviewCleared`（编辑前确有审核态才为 true），编辑器据此常驻提示「已重置审核状态、需重新审核」；纯结构 split、无变化提交、无既有审核均返回 false。API：`GET/POST .../outputs/[planId]/arrangement|clips`，口播音频走 `outputs/[planId]/media?kind=narration`。前端编辑器 `components/batch-production/BatchOutputEditor.tsx` + 实时预览 `BatchTimelinePreview.tsx`（客户端即时合成，复用 `components/final-edit/preview-playback.ts` 纯函数；这是 UI 层共享，`lib/batch-production/` 服务端仍不依赖 `final-edit/`）。编辑器为比例时间轴 `BatchTimeline.tsx`（画面轨 + 字幕/口播对照轨 + 播放头与预览同步）：拖边缘变长修剪、拖中段等长平移、分割工具点击切开、右键菜单删除/精细修剪。

## 编辑器优先与正式导出（2026-09-03 改）

- 新工作流：生产阶段只准备口播、画面安排与封面 →「检查成片」点卡片直接进编辑器用实时预览检查修改（无双模式切换、无历史版本选择器）→ 点「通过」只代表编辑方案审核通过 →「导出成片」时才真正渲染 mp4 → 导出页现有播放器播放这份正式成片；再次编辑后重新导出成功，同一张卡、同一个播放器原位切到新成片。正式成片仍从冻结的原始素材与安排快照渲染，浏览器代理预览绝不作为正式输入；静音占位仍只能预览，正式导出必须确认口播就绪且渲染结果 audioMode=narration。
- 封面任务 `output_version_cover`（workType=render）：Phase E 为每个当前输出版本建立，全生命周期接入 `tasks.ts`（合法 targetKind 组合校验，非法组合仍拒绝）、`batch-render-executor.ts`（按 targetKind 分派封面/完整渲染并写各自结果）、`runner.ts`（运行中心跳 + 完成前版本 CAS + **三向契约 CAS**：现代任务要求 task requestKey、执行结果 `coverContractHash`、当前数据库契约三者一致；任一解析失败或不一致都按 superseded 终止并丢弃迟到结果）、`scheduler.ts`（不被口播闸门阻塞，仍受版本有效性与并发约束；同一封面契约成功复用，失败走显式重试）。`batch-renderer.ts` 抽出独立封面渲染接口与 `BatchCoverRenderResult`（只含封面谱系、契约、路径与指纹），两类结果分别解析、校验、清理，封面任务绝不冒充可播放视频候选；封面契约哈希由渲染所依据的冻结 snapshot 派生（resolveCoverContract 接受冻结 arrangementJson 覆盖），渲染期间同版本又编辑时不会把旧画面标成新契约。换画面/重分配/切换输出版本会同时取消旧版本两类任务。工作区无法解析当前契约时保守视为没有可用现代封面；只有不带现代契约 key 的老批次才回退到最近成功完整渲染的封面继续检查预览。
- 两种渲染契约（`cover-contract.ts` 是唯一计算源，建任务、新鲜度、工作区选封面、导出前最终并发校验四处共用）：封面契约（输出版本+封面渲染器版本 `batch-cover-v1`、素材身份与指纹、取帧时间、裁切缩放位移、主副标题文字样式、色彩链/LUT、画幅输出规格）出 `coverContractHash`，是封面任务 requestKey；完整渲染契约（outputVersionId + editRevision + coverContractHash + 口播/字幕/BGM/画面安排/输出预设有效身份 + 渲染器契约版本）出完整渲染契约哈希，是 `output_version` requestKey、`formalOutdated` 判断与发布前 CAS 的唯一来源（`formal-artifact-freshness.ts`）。task 无契约哈希的老任务回落「修订号+封面时间点」比对，**证据不足（任一事实缺失或损坏）一律保守判为已过期**，不靠猜。
- 工作区口径（`batch-workspace.ts`）：卡片分开返回 `coverTask` / `fullRenderTask` / `currentFormalArtifact`，状态拆成 `reviewable` / `approvable` / `exportEligible` / `formalOutdated` / **`exportStatus`**（not_exported/rendering/failed/exported，服务端统一判断，导出页只消费它不得再自拼任务状态），旧 publishable 含义已废止。**封面任务按当前 coverContractHash 选择**（A→B→A 时展示旧 A 任务的事实，不展示较新的 B 任务或其失败状态）；完整渲染任务同样只认当前 `fullRenderContractHash`，较新的旧契约失败任务不能遮住当前状态。正式产物必须按稳定路径组成 video/cover 一对，且两份 checksum 同时命中同一次成功完整渲染才算新鲜；丢失、损坏或错配任一半都 `formalOutdated=true` / `not_exported`。封面失败单独显示并可重试，不并入整批模糊的「需处理」；无完整渲染任务但已可检查的卡片不显示为 processing。返工期间 `currentFormalArtifact` 仍返回且 `formalOutdated=true`（前端显示「当前修改尚未导出」），导出页继续播旧正式成片。片段编辑路由（clips）**只在前后的 coverContractHash 真的变化时才排封面任务**：BGM、字幕、口播音量等 visualChanged 编辑不再平白重做封面。
- 导出编排（`export-orchestrator.ts` 的 `orchestrateBatchExport`，`POST .../exports` 唯一入口；前端只消费其状态，不自拼任务状态）：先预检（计划归属、当前输出版本、productionReady、口播、当前版本审核、正式导出预检，不合格直接 skipped 给原因），再算完整渲染契约建或复用精确匹配当前 requestKey 的 `output_version` 任务，并取消旧契约待执行任务；**编排模块内部**对新建或复用的 queued/running 任务都唤醒并等待调度器启动（懒加载 bootstrap，幂等），唤醒失败显式报错、保留已排队任务供重试，路由与其它直接调用方不需要也不应该再关心领取时机。单条返回 skipped / render_queued / rendering / render_failed / already_published / published；failed 终止轮询、显式重试才回队列。succeeded 先校验结果结构、audioMode、契约、文件与指纹，再复制到正式导出目录；最后在同一事务重查 currentVersionId、editRevision、coverContractHash、**reviewStatus** 与完整渲染契约（渲染或复制期间被编辑/撤销审核都拒绝旧结果，撤销审核不递增 editRevision，只比对修订号拦不住，必须在事务内复核审核态），video/cover artifact 成对注册并原子切换 currentArtifactId；同一事务内还判断「同渲染结果（版本+视频/封面成对指纹）是否已被并发请求注册为当前」——是则不再注册第二对（并发重复 POST 的最终幂等兜底），本请求多复制的文件随后清理；当前视频匹配但封面损坏时不误报幂等，而是发布一对新产物并切换指针。CAS 失败只清理本次新建未注册文件、不碰旧正式产物；已发布同契约重复 POST（含顺序与并发）返回 already_published，不重复复制。
- 关闭/刷新页面：渲染任务继续跑，重新进入能看状态，但需再点一次「导出」完成发布——导出意图只在前端内存，本轮零迁移不做持久化导出会话，文案不得假装自动发布。老批次已有成功完整渲染任务可作新鲜候选继续发布；老 artifact 与导出文件不删除，只是产品界面只认当前指针。

## Phase A — 项目素材卡与本地技术分析

- Phase A 的项目素材卡在快照前通过 `asset-preparation.ts` 使用既有 batch scheduler 排队本地 FFprobe 基础分析；结果明确标记为 `technical`，不冒充内容理解。`project-asset-media.ts` 只按 `projectId + assetId` 解析并重验权威来源、完整 SHA-256 与真实容器，生成受控 960×540 JPEG 缩略图并提供原片 Range 预览；`startBatchProduction` 不再重复创建素材分析任务。

## 语义优先分配与封面标题（v17–v23）

- 语义优先分配与封面标题在 v17–v23 落地：v17 内容分析请求 `batch_asset_analysis_requests`（冻结素材指纹与视觉供应商身份），v18 补执行作用域，v19 脚本/快照目标成片时长，v20 脚本/快照配音配置，v21 任务表 workType 加 `narration`，v22 素材来源核验快速路径，v23 任务表 workType 加 `semantic_score` + 新表 `batch_semantic_matrices`。`semantic-match.ts` 做「句段 × 素材池场景」LLM 语义矩阵打分：按内容指纹落库（不绑版本），确认整体输入后幂等排队，`POST .../semantic-score` 可手动触发或换供应商；失败/未打分时分配器走关键词+质量兜底不阻塞开跑。`executors.ts` 的 `createSemanticScoreExecutor` 无内容分析时 completed+skipped，LLM 失败回 failed code `semantic_fallback`；打分与分配共用 `allocator.ts` 导出的 `splitAllocationScriptBody` 断句。`cover-title.ts` 复用全局 `final_edit_title_presets` 预设：批次设置以 `coverTitleMode('none'|'preset'|'custom')`/`coverTitlePresetId`/`coverTitleStyles`/`coverTitleFraming` 为整批基准，按需以 `coverTitleStylesByScript`（`sourceScriptId → 完整主/副样式`）记录脚本覆盖；覆盖随版本 `defaultsJson` 冻结，渲染按成片计划所属快照的 `sourceScriptId` 取覆盖，缺省回落基准。UI 稳定写完整样式形状，样式按当前画幅解析，canonical 比对自动纳入输入身份；封面标题卡右侧预览下拉既用于逐份核对标题文字，也用于选择当前调整脚本，未单独调整的脚本沿用基准，可「恢复基准样式」或「应用到全部脚本」——后者会清空**全部**单独调整，所以当其他脚本存在覆盖时按批量提交同款做内联二次确认（提示要清除几份），并在样式编辑区常驻「本批已有 N 份单独调整」份数。空映射时提交端不写 `coverTitleStylesByScript` 键，以保持旧批次再确认幂等；取消勾选脚本后残留的覆盖条目不清理，以保持取消后再勾选的幂等（渲染只按当前快照 `sourceScriptId` 查找）。`batch-renderer.ts` 渲染封面时按冻结样式 sharp SVG 合成主/副标题，换封面抽帧同样保留标题。分配器单区间装不下句段（句段估算时长超过所有场景）时走句段内多镜头拼接兜底 `stitchSegment`（reason `semantic_stitch_fallback`、chunk clipId 带 `:part:<k>`、警告 `stitched-segment:<id>`，素材池全空才保留 `no-legal-media`），字幕 cue 按句段整切一次不按 chunk 重复；`subtitle-cues.ts` 把口播对齐句段经 `splitNarrationForDisplay` 清洗标点并按 ≤16 字切分（段内按字数权重比例分配，与估算路径同款）；`PUT .../start` 对草稿版本先经 `prepareBatchSemanticScoreBeforeStart` 幂等排队语义打分，有未完成打分时返回 `semantic_scoring` 不冻结，前端在任务终态后自动续跑，打分失败/不可用不阻塞开跑。批量成片开头与单条剪辑同契约加 20 帧封面片头（`FINAL_EDIT_INTRO_DURATION_US`）：带标题的封面先于视频生成以作片头静帧输入，音轨整体 `adelay`、字幕叠加窗口整体后移，产物时长校验按「片头 + 正文」——`script-duration-policy` 本来就为片头扣了这 20 帧，不加片头会让每条批量成片系统性短一个封面。因为封面被烤进成片，`BATCH_RENDER_ADAPTER_VERSION` 升为 `batch-render-v2`；渲染任务 requestKey 不再只含 `cover.timeUs` 而是纳入统一 `coverContractHash`（`cover-contract.ts`），换封面只重做封面任务，整片渲染等到导出时再排。**斜体渲染（B1）**：字幕与封面标题的斜体从 `font-style` 改为 `skewX(-12)` 剪切合成（`lib/media-core/cover-title-svg.ts` 的 `textStyleToSvgElements`），librsvg 不会为没有 italic 字面的字体合成斜体而浏览器会，统一走剪切后预览与成片同款；`BATCH_RENDER_ADAPTER_VERSION` 因此再升为 `batch-render-v3`——旧 v2 任务点「重新生成」保留原 requestKey，新 attempt 运行当前代码产出修复后的斜体。斜体补偿规则：先按字号估 `fontSize × tan(12°)` 的 overhang 从可用宽度扣除再缩字号，锚点坐标不动（左/中/右对齐语义不破坏），同一段文字开启斜体后可能比直立略小，属接受取舍；收缩下限 0.5 倍钳的是**总收缩比**（overhang 要按缩后字号重估一轮，两轮各钳一次会把斜体压到 0.25 倍，同一段文字开不开斜体差一倍字号）。**已知残留（有意保留）**：剪切绕基线做，字身上半部相对锚点右移 ≈ `ascender × tan(12°)` ≈ 0.17 × 字号，这段溢出落在锚点一侧（right 对齐最明显，实测 80px / PingFang SC 越过右锚点 1~7px），而缩字号是宽度方向的杠杆、结构上够不着——根治只能移锚点（破坏 left/right 对齐语义）或改绕中线剪切（引入随字体变化的 ascender 猜测常量且只减半不根治）；默认样式是 center 对齐且对齐框左右各留 10% 画幅（1080 宽留 108px），残留碰不到画面边缘，故保留。另注：单条混剪的文字 overlay 走浏览器 Canvas（`components/final-edit/text-canvas-renderer.ts`）仍用 `font-style` 合成斜体，与批量的剪切合成外观不同，统一需另立任务。

## 共享字体选择器（SystemFontPicker，2026-09-02）

- 批次字幕/封面与单条精准混剪字幕/封面统一使用 `components/ui/SystemFontPicker.tsx`，不再各自渲染原生 `<select>`。组件接收 `{ value, ariaLabel, disabled, onChange, compact?, portalRoot? }`，内部统一读取共享字体目录与收藏偏好。替换入口：`BatchTextStyleEditor.tsx`（单条字幕样式 + 批量封面主/副标题精调）、`BatchStepScripts.tsx`（批次默认字幕/封面标题）、`FinalEditInspector.tsx` 的 `StyleEditor`（单条精准混剪）、`mixcut/CoverEditorDrawer.tsx`（封面共享字体）。所有调用点在 family 变化时都清除旧 `fontPostscriptName`。
- 字体数据复用既有链路：`/api/system-fonts`（服务端扫盘）+ `components/system-fonts.ts` 的 `queryLocalFonts()` 会话合并（stale-while-revalidate 缓存）。`SystemFontPicker` 首帧用 `getCachedFontOptions()`，挂载后 `requestFontOptions()` 后台重校验，不重置搜索/页签/收藏/选择；`BatchTextStyleEditor.tsx` / `BatchStepScripts.tsx` 已删除各自 fetch/state/刷新实现。不改变 `/api/system-fonts` 返回格式与 `lib/media-core/system-fonts.ts` 的扫描/缓存规则。**不变式**：`SystemFontPicker` 的 `fonts` state 只装「检测到的目录」，**绝不能把当前 `value` 掺进去**——掺了 `currentMissing` 恒为 `false`，「当前字体」保护行永远不渲染，卸载掉的字体会被静默当成普通可选项（首版就是这么写的，已修）。目录就绪前（无会话缓存的首帧）一律按「已检测到」处理，避免误报缺失。
- 收藏偏好 `components/font-preferences.ts`：localStorage key `creative-studio-font-favorites-v1`，值为去重后的 family 数组（最近收藏在前）。`useSyncExternalStore` 暴露快照，同页写入主动通知、跨标签页经 `storage` 事件同步，避免多个面板各持一份漂移 state；localStorage 不可读/损坏/不可写时收藏当场仍生效（内存快照），只是不跨刷新保留。收藏是本机个人操作偏好，不属于项目内容，不进入批次冻结快照、成片版本或导出包。
- 纯逻辑在 `lib/media-core/font-identity.ts`（Node 直接测）：`fontIdentity = NFKC 归一 + 去空格 + en-US 小写`，搜索、去重、收藏命中、缺失判断全部用它，提交仍保留原 family 字符串；`mergeFontSources` 固定顺序（当前值 → 服务端 → queryLocalFonts → 收藏，同 identity 保留第一个原值）；`sortFontFamilies` 收藏按偏好顺序在前，其余按 `Intl.Collator('zh-CN', { numeric: true, sensitivity: 'base' })`，collator 相等再按原字符串码点破平，保证各平台结果唯一。
- 浮层定位：普通页面 `createPortal(..., document.body)` 固定定位到触发器附近，监听 resize 与捕获阶段 scroll 重算，避免被右栏 `overflow-y:auto` 或卡片裁掉；两个封面抽屉在 dialog 内提供脱离滚动字段的 overlay host（`mixcut/CoverEditorDrawer.tsx` 紧跟「共享字体」section；`BatchCoverEditorDrawer.tsx` 的 host 由 `BatchTextStyleEditor` 自托管——它在字体触发器所在 `<label>` **之后**（不能放进 label 内：label 会把浮层非交互区域——分组标题 / 「N+ 个字体」页脚 / 内边距——的点击转发给被标注控件即触发器，等于点一下标题就关面板；放在 label 外 DOM 顺序不变，label 本身不可聚焦）紧跟一个 host 并传给它自己的 `SystemFontPicker`，主/副标题各一份，Tab 从浮层出去落到本编辑器下一个控件「字号」，而不是跳过整个样式编辑器），浮层控件按 DOM 顺序进入抽屉焦点陷阱，Tab 从字体面板出去落到触发器所在 section 的下一个控件而不是抽屉末尾；浮层仍用 fixed 坐标和高于抽屉的层级。字体面板在 document 捕获阶段先消费 Esc 并 `preventDefault + stopPropagation`，抽屉 keydown 兜底检查 `event.defaultPrevented`，实现「第一次 Esc 只关字体面板，第二次才关抽屉」。
- 可访问性与性能：触发器 `aria-haspopup="dialog"`/`aria-expanded`/`aria-controls`，浮层 `role="dialog"`；缺失字体的选择按钮 `aria-disabled="true"`（可聚焦、激活不改字体），星标按钮可操作；「全部」页在同时存在多个组时渲染分组标题（当前字体 / 收藏 / 全部字体），标题不占 `data-font-row` 行号，键盘导航按纯行索引走，避免 listbox option 内嵌按钮的非法 ARIA；列表按固定批次 80 项渐进追加、滚到底自动加载下一批；End 加载完整结果并聚焦真正的末项，第 80/81 项边界的 ArrowDown 先追加下一批再把焦点移到第 81 项（统一经 `pendingFocus` 在渲染后落焦点，不依赖扩容前的旧行数）；浅色/深色用设计令牌，无硬编码浅色值。

## 红线（这几条同时留在 AGENTS.md）
