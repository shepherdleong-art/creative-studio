# 批量生产模块（`lib/batch-production/`）参考

自动词时间由 `formula/subtitle-cues.ts` 按标点、停顿、长度和时长组成可读短句，`output-audio.ts` 在生成及联动编辑时使用真实首尾词边界投影字幕。原始词时间仍留在声音依据中；人工 SRT、人工素材台词与手改字幕不自动重分组。连续分割不把短句拆回单字，恢复自动字幕可重新生成短句；旧正式视频不改写。

公式字幕的显示换行由 `media-core/subtitle-svg.ts` 共用于 `BatchTimelinePreview` 和 `batch-renderer`。只改版式，不改 cue 文本/时间/来源；末行沿用基线，多行向上排，过长块按可用高度缩字号。公式整片契约升为 `formula-render/2`，使旧单行渲染失效；普通批次、封面标题及 classic/1 仍用原单行实现。

外部整篇配音由 `formula/external-narration.ts` 管理，公式独立迁移 v26 追加不可变 `batch_formula_external_narrations`（与普通批量迁移版本无关）。按 collection、脚本会话和 scriptKey 保存修订，音频/SRT 一次核验保存并推进资料修订；同输入重试恢复回执，移除写新记录，旧文件和冻结生成不删除。`FormulaExternalNarrationPanel` 在第二步提供按脚本上传、试听和确认，接口只返回受控试听地址所需身份，不暴露本地路径。

统一配音生成冻结外部记录，`narration-store`/worker 使用实际音频和已确认 SRT，不调用 TTS/对齐服务；SRT cues 保持整句时间，标为 `manual`。单/双声道规范为 48kHz PCM16 后直接数样本核验时长，字幕文字须与完整朗读文案一致。生成、媒体读取、制作及正式渲染重验指纹，审片和 `export-manifest` 保存外部来源与人工确认依据。首版不将整篇外部配音自动分给混合模式的多个空隙。

公式人工改编由 `formula/deviations.ts` 对比本输出绑定的不可变选片、初始排片与当前片段。`review-context.ts` 和 `formula/export-manifest.ts` 共用它，保存原/现顺序、删除槽位、插入/换片的真实素材和指纹及源区间变化；连续分割不误报，部分删除仍可见。审核快照纳入这些证据，成片行显示人工改编，撤销后按实际内容重算；旧正式包不改写。该对照不等于新来源已经核验，未核验的人工来源仍不能正式制作。

人工素材核验由 `formula/manual-clip-edit.ts` 经原 clips API 的 `formulaMedia` 分支执行：先在事务外校验受控原片的实际指纹、媒体及显式区间，再在事务内重验文件和输出修订，同次写入 v25 不可变 `batch_formula_manual_media` 记录及片段编辑。`formulaSourceId` 随分割、撤销保存，并进入渲染身份；不修改原 `formula` 依据。来源不能跨输出复用；播放、制作和正式清单使用同一记录，保护动作可以连续分割，但截断或打散后不能通过制作检查。

静音画面替换/插入已接入界面，已有必需原声不能用它删除。公式拖放由 `BatchReviewTimelineDock` 打开 `FormulaManualMediaMonitor`，在中央完整原片上复用 `TrimEditor` 选区间；替换等长，插入可改时长，可填写保护动作。点击明确的静音应用按钮才写入，取消不保存；普通批次拖放保留原路径。审片显示人工选定区间和静音选择，不继续把已替换片段称为原来的系统安排区间。历史无核验记录的草稿仍不能正式制作。

保留原声的后台沿用同表的 v2/v3 JSON 核验记录，保存人工台词、源时间、试听确认及被替换话语的区间映射；v1 静音记录不改写。`manual-audio-basis.ts` 只推导当前有效声音依据，不改原 `formula`。原声及字幕随画面重建，未覆盖的原话语仍受完整性检查；再次换片继承原始覆盖关系，分割/裁切只按仍有效的部分计算。人工时间标为 `manual`，新原声替换其旧字幕，其他手改字幕保留。预览/渲染/正式清单共用身份，清单只列实际声音来源。

新原声替代 TTS 使用显式 `replaceNarrationClipIds`，界面从 `narrationSpeechByClipId` 展示实际台词，默认不勾选；选项变化清除试听确认。后台要求当前配音完整落在新画面时间内且不切断话语，与画面/原声/字幕同事务保存。v3 在 `replaces[].narration` 记录原配音文本及共享覆盖身份：各有效片段映射回首次确认的新原声区间，全部必要区间仍存在才抵扣旧配音；新旧语音时长无需相同，不能把原声秒数直接当作 TTS 秒数。分割、再次换片继承覆盖坐标，删掉必要部分恢复旧配音的必需性；未选配音不移动，仍有重叠则拒绝。审片和正式清单共用该记录，原生成依据不改写。

`FormulaManualMediaMonitor` 提供静音/保留原声、实际台词及源秒数、播放位置取点和试听确认。原声预览不静音，旧台词取 `sourceSpeechByClipId`（当前有效声音依据，不是手改字幕）；改台词、时间、取用范围、时长或模式后清除确认。只有用户勾选才提交 `speechConfirmed`；区间内完整台词、次序与重叠在界面检查，后台独立复核。审片池上传使用 query `projectId`，成功项刷新、失败项逐文件显示；编辑候选补入本项目在线且健康的受控视频副本，不修改冻结池，也不扫描其他模块四上下文。

人工素材面板冻结打开时的视图、请求身份和首次提交内容；回复丢失后锁定选择、重试原请求。后台幂等回执返回 `replayed`，工作台仅在当前修订恰为该编辑后的修订时恢复对应撤销记录；后续有其他编辑则提示返回核对，不能将其一并撤销。元数据未加载、源时长不足、动作区间越界及必需原声被静音换掉均阻止应用，保存错误保留在面板内。

统一审片的视频边缘修剪由 `media-core/video-trim-range.ts` 共享前端预览与 `trim_variable` 保存换算。已有非整帧接缝的未编辑端点必须保持原值，不能在拖动另一端时重新取整，否则会误报覆盖相邻片段。见 [右端修剪修复记录](../2026-09-29-片段右端修剪锁死修复.md)。

双击视频轨道片段打开中央完整素材预览，修剪直接复用单条 `TrimEditor` 胶片选框；拖动选框等长换窗并同步预览入点，选框聚焦时方向键逐帧移动（Shift 十帧）、Home/End 到首尾、Enter 完成、Esc 取消。保存走既有 `trim`，保留原始微秒长度、倍速、时间轴位置与邻片；携带版本和修订校验，可撤销。独立 I/O 面板已移除；`set_source_range` 后端保留兼容，不作为此入口。

时间轴「精调」与右侧「封面」共用统一封面抽屉，来源/截帧、构图与包装文字在同一草稿中编辑。`set_cover` 可携带包装与打开时的版本/修订，单事务保存并参与整包撤销；冲突不得部分保存，预览不得改写成片。模板/字体仍影响整片，正片卖点时序保持。入口与验证详见 [视频包装](视频包装.md)。

脚本准备区支持全选、取消全选和整批删除。全选保留既有份数，新选脚本默认 1 份；删除采用一次请求、单事务校验全部项目归属。v26 追加 `catalogDeleted`，删除仅退出批量脚本目录，同步不得复活，保留第 3 步原脚本和历史快照。成功后清理选择并使已确认草稿输入失效，冻结批次不显示编辑操作。

审核 HTTP 接口接收逐条 `planId/outputVersionId/editRevision/issueSetHash`，身份来自已经显示的 arrangement `reviewContext`，点击确认不得临时换成最新身份。`review-context.ts` 汇集当前安排、激活分配报告、同源提示、公式替换/区间及声音问题；`review-confirmation.ts` 同事务重验并保存实际接受的问题快照，逐条返回成功或冲突等原因。工作区、导出编排和发布最终事务均检查快照仍匹配；旧普通审核记录兼容读取，公式不接受缺少快照的确认。纯包装/封面锁定推进审核修订但不改变问题集合；实际效果变化仍清审核。界面显示逐条结果，单条失败不自动推进，公式返工保留当前安排供调整。

曲库扫描共用 `lib/media-core/bgm-catalog.ts`，单条旧路径只做兼容再导出。文件移走、替换或不可读后，旧曲目退出 ready 列表但保留身份；恢复相同内容后复用原 ID。扫描只清退扫描前且未被并发更新的旧记录，不删除冻结版本里的音乐引用；生成/渲染仍须核对实际文件与指纹，不能用同名新文件替代旧内容。

公式制作使用独立 `formula/schema.ts` 迁移流及共享升级 gate。v9 扩展共享任务的 `formula_stage` 类型，重建时同时保留 attempts 和 asset_analysis_requests；未识别字段、索引、触发器或引用会阻止公式升级，不可丢弃后继续。`generation.ts` 在同一事务冻结输入、建立输出身份并入队；`stage-executor.ts` 的结果通过原 runner 的租约/控制态事务提交。领取、心跳及提交都检查公式能力和当前输入版本，能力关闭时公式任务可恢复地退回队列，普通任务继续。选片结果只是核验后的文件身份，`executionReady=false`；不能把选片任务成功当作声音、可用区间或可审成片就绪。

公式 v19 在可编辑输出之后增加持久化制作检查。`execution-store.ts` 随输出创建/编辑排队，启动续接可补队；实际媒体、声音、字幕及包装运行文件经检查后，保存不可变结果并同事务排入当前封面任务。工作区与审核同时核对制作结果、当前内容契约和封面成功记录；只写 `productionReady=true` 不能通过。纯包装/封面锁定保留内容检查，实际修改须重新检查；迟到结果不能覆盖新编辑。检查失败显示原因和「重试检查」，沿用原任务恢复。此就绪位表示可审片，正式整片发布仍须通过独立的完整渲染及发布核验。

公式正式导出沿用 `export-orchestrator.ts → batch-renderer.ts → phase-e.ts`。渲染结果携带实际使用的制作检查记录和完整渲染身份；只有经检查的原声、配音或混合声音可产生可发布结果，编辑后未经重新检查的渲染仍不可发布。导出前核对当前检查、封面及人工审核，发布前再次核验实际文件、声音与包装；复制完成后的注册事务重查当前内容、检查记录、审核和文件，拒绝期间发生的修改。公式不依赖旧语义分配报告，普通批次仍要求真实 narration；静音占位不能发布。视频、封面成对追加保存，重复导出幂等，返工和关闭公式能力不影响已有正式文件的访问。导出包实现与历史下载见下文；真实素材全流程验收仍按计划推进，阶段证据见[执行记录](../2026-10-22-实拍公式混剪-开发执行记录.md)。

公式渲染结果的 `formulaIdentity` 由 `formula/export-identity.ts` 读取不可变的生成输出原号/份次，并记录本次实际包装；共享 `media-core/export-identity.ts` 严格校验并生成「脚本141-第02份-f3/无包装」后缀。发布前和最终登记时核对该身份，文件防重名序号另加，普通 J/K/f 规则不变。旧公式候选须先通过既有完整渲染/制作/审核验证，再从不可变身份及已核对的包装补齐命名；已发布文件继续用原路径，不批量更名。

公式 v20 追加不可变导出包和产物引用。`formula/export-package.ts` 固定用户所见的正式视频/封面身份，核验当前审核、完整渲染契约和实际文件，异步校验后在登记事务重查；`export-manifest.ts` 仅提取明确的剪辑字段，不序列化服务配置或素材路径。第四步 `FormulaExportPackages` 创建、列出历史包，经独立 `formula/packages` 接口下载；历史下载按包中 artifact 引用读取，不跟随返工或新发布，也不依赖公式执行开关。

`media-core/verified-zip.ts` 提供带内容核验的 ZIP 流，下载前检查文件，流中再次比较完整校验值，缺失、变化和中断均不能产生成功的残缺 ZIP。包内按编号子目录保留正式中文文件名；JSON/CSV 共用同一冻结清单。产物外键保护历史包的文件记录，清理逻辑不得删除这些引用仍指向的实体文件；原项目 ZIP 和普通批量导出保持原入口。

第二步「生成」先保存当前份数、声音、时长及包装设置，再提交 `formula/generation`；请求身份由已保存设置及输入修订确定，回复丢失后重试仍返回同一请求。后台使用原持久调度器逐条续接；生成接口只返回请求、版本及输出数量，不返回冻结服务配置。制作后前两步输入默认只读，编辑成片走第三步；修改上游资料需显式打开下一轮输入。

公式 v21 追加不可变输入修订记录，`input-revision.ts` 和 `formula/input-revisions` 接口按用户所见的批次版本、集合修订打开修改。同一事务推进集合修订，旧页面写入失效；旧批次版本仍冻结且继续作为当前结果，直到新生成请求成功才切换。`input-editing.ts` 统一导入、制作设置、选片规则与区间的可编辑判断；前两步的「修改输入」及 imports 响应共用该状态，草稿从数据库恢复。工作区进度的 `inputRevisionOpen` 让标题和当前批次列表显示「准备下一轮」，不再误显示输入锁定。新生成在同一事务重新启动暂停/停止批次，但幂等重试旧请求不改变控制态；旧 worker 仍由现有版本/租约校验拒绝提交。历史导出包不随新输入切换。

公式 v22 追加 `batch_formula_manual_speech`，`manual-speech.ts` 保存按集合/素材指纹的不可变人工台词修订，并在同一事务推进资料修订。`FormulaManualSpeechPanel` 及 `formula/manual-speech` 提供第一步原片试听、台词片段/时间、明确无话语及恢复自动识别；支持用当前轮自动识别结果填写后再改。保存前后核验真实文件；无音轨不能登记话语，时间不能越界或重叠；同次保存回复丢失可回读原记录。上游修改后须显式重新生成。

生成输入的可选 `manualSpeech` 冻结人工记录，声音任务输入包含确切记录身份，复用键不会将旧人工记录当成新自动识别。`source-speech.ts` 消费人工记录前仍核验当前文件及媒体时长，不调用 ASR；`transcriptionIdentity=null` 和 `manualVerification` 明确人工来源，`no_speech` 与 `no_audio_stream` 区分。台词时间原样进入声音编排、字幕和音画联动保护；人工填写句段不伪造逐字识别。审片显示人工依据，正式清单 `manualSourceSpeech` 仅从冻结请求提取实际用片的对应记录。记录已试听不等于整条成片已审核，原制作检查与发布门禁保留。

`formula/progress.ts` 为工作区聚合当前请求、最新选片链和当前编辑检查的进度，只有实际检查和封面就绪才计入可审片。缺编号、声音/时长冲突和任务失败显示具体原因；需要配音却未冻结音色时提示回第二步点「修改输入」选择音色后重新生成，不无限等待。第二步顶部展示进度，第三步使用可展开的简版，当前批次标题和列表同步显示制作中、部分就绪、可审片或控制状态。暂停/继续/停止和失败重试沿用既有任务接口；此进度不代表正式 MP4 已渲染。真实服务及整批素材验收仍按开发计划推进。

公式人工选片由 `formula/selection-rules.ts` 保存不可变修订（追加迁移 v10）。保存同时校验集合修订、选片修订和已确认脚本身份，并推进集合修订；生成请求冻结完整规则及素材指纹。单镜头指定按「脚本修订 + 行身份 + 镜头序号」定位，优先于同号主片，不能按编号覆盖所有重复镜头；改用其他编号时分别保留原编号和实际编号。指定素材失效时进入需处理，不自动换片；脚本修订后旧的单镜头指定须重新核对，旧生成请求及已落盘选片不变。人工选片不代表区间已核验，也不能直接进入批准候选轮换。

人工选片和可用区间面板按同一集合修订刷新。保存先同步父面板资料，再显示成功；某面板尚未读到当前集合修订时暂时锁定编辑，读完再恢复，避免刚保存区间就选主片时误用旧版本。已有未保存修改继续保留并提示显式重新读取，不为消除冲突而覆盖草稿或放宽服务端版本校验。

公式可用区间在 `formula/asset-ranges.ts` 保存逐素材、逐集合的不可变修订（追加迁移 v11），与内容指纹绑定；`candidate-media.ts` 供人工确认和后台选片共用带取消信号的真实文件核验。批准只表示人工确认了画面区间，`audioStatus=pending` 始终保留；区间要容纳至少 12 个完整的 24fps 输出帧，保护动作含帧边界不能越出可用范围。轮换规则冻结勾选候选的区间修订身份，输入快照保存完整区间；候选排列由冻结种子、脚本顺序、份次和槽位确定。区间改动/撤回后新输入须重新批准轮换，旧决策不变；首次决策落盘前可在批准池内回退，不能借用池外素材。`rangeStatus=confirmed` 也不等于真实声音、最终裁切或可执行成片就绪。

公式缺片替换由 `formula/replacements.ts` 对冻结的素材表、命名与人工说明提出直接目标；只在原编号没有可用文件、且未被人工主片/批准池固定时调用。沿用已冻结表格识别或素材整理记录里的脚本模型，模型身份变化要求恢复配置或新建请求。引用必须能回到来源单元格/文件/说明修订；引用具体文件时限制实际候选，已知未解释冲突、无定义、仅同类、虚构引用、台词不等价和具体尺寸无依据不能通过。替换仍执行目标的主片/轮换及真实文件核验。从 `formula-selection/3` 起，原号、实际号、理由、双方依据、明确资料差异和 `reviewStatus=pending` 与原选片结果一起落盘；当前新结果为 `/4`，旧结果保持可读，重试和补回原片不改旧结果。自动替换只是文字资料支持的选片，`basisScope=text_only`、`executionReady=false`，不能替代真实画面/声音核验或第三步审片。统一审片现可读取逐条摘要、替换筛选和完整选片历史；实际时间轴片段标记、既有建议导入及完整生成入口仍待补齐。

集合级人工统一替换保存在 `selection-rules.ts` 的不可变规则中，第一步可填写原编号、直接替代编号、原因和差异。单镜头指定优先，原片可用时优先原片；缺片才用人工映射，人工主片/批准池失败不绕开限制。原编号必须有当前素材定义，目标必须来自本集合；失效目标不退回自动替换，循环和多跳拒绝。`formula-selection/4` 的 `manualReplacement` 保存规则身份、资料差异和 `basisScope=manual_choice`，页面显示“人工统一替换 · 待审”，不冒充 AI 等价判断。追加公式迁移 v13 标记规则格式：已有行默认格式 1，新写入为格式 2，旧生成快照可缺字段；迁移历史检查使旧公式 worker 拒绝新结构，基础批量仍独立验证。省略 `replacements` 字段保留原规则，显式空数组才清除。

公式逐条重选由 `formula/reselection.ts` 追加不可变输入（公式迁移 v12），按 planId 作用于同一脚本的某一份输出；请求同时核验选片阶段、当前成片版本和编辑修订。单镜头指定只从原请求冻结的候选中选择；重试复用已保存种子，明确重选才新建修订。原规则、旧结果、历史成片与正式文件保留，当前成片指针清空后不能继续沿用旧审核；原 runner 在领取、心跳和提交时排除已被替代的选片阶段。工作台只把存在实际成片版本的公式安排交给播放器，空编辑视图不能冒充已生成时间轴或显示假时长。`FormulaSelectionHistoryPanel` 接入原属性区，展示依据/差异、原片预览和历史；它尚不能代表整条公式成片可制作或正式导出，阶段证据见[执行记录](../2026-10-22-实拍公式混剪-开发执行记录.md)。

公式帧级时长计算位于 `formula/duration.ts`，公共入口 `planFormulaDuration` 只接受每槽位已经选定的连续区间、确切媒体身份和已就绪声音长度；声音待处理时只返回 `waiting_audio`。它以 24fps 帧边界保存源/正文映射（源帧号也用 24fps 时间网格，不是摄像机原生帧号），总片长仅加一次 20 帧封面。参考目标保全内容并标偏差，严格上限向下取帧，固定片长不补循环/定格；保护动作、锁定段和完整原声不可缩短。配音窗口必须覆盖连续非原声槽位，先满足窗口真实长度，再按偏好分配画面余量，触上限后重分，余帧按原槽位顺序补齐。`timeline.ts` 已把实际声音接到该计算；排片阶段结果仍为 `executionReady=false`，后续制作检查、封面、人工审核和正式渲染分别完成，不能凭时长计算成功跳过。

公式原声识别入口 `formula/source-speech.ts` 先核验项目、受控来源及真实指纹，再临时提取 16kHz 单声道 PCM。提取保留音轨相对视频起点的延迟，识别时间始终使用原片坐标；只处理第一音轨，当前单次上限十分钟，超限明确要求处理。无音轨与“有音轨但未识别出台词”分开返回；转写不传 Excel 文案提示，结果包含来源、模型/服务身份摘要、原片长度和逐词时间，仍为待审且 `executionReady=false`。取消贯穿文件核验、提取和网络请求，临时声音在成功/失败/取消后清理。

公式迁移 v14 追加逐输出原声检查输入/结果及 `batch_formula_execution_stages` 视图，不重建旧选片表。选片成功在同一事务为该份实际使用的每个来源排任务，全部配音模式跳过；原 runner 继续执行，结果在选片历史面板自动更新。请求冻结识别服务是否配置及模型/端点摘要，不保存密钥；旧请求缺服务配置时不能暗中改用当前服务。文件/识别失败可按原任务重试；未配置或超长来源保持需处理，不冒充整条声音计划就绪。重选使旧来源检查失去提交资格，历史和同脚本其他份保留。

`speech-store.ts` 从已保存的成功原声结果复用识别依据，条件为同项目、素材、内容指纹、处理输入、服务身份及算法版本；失败不复用。原调度器对相同来源/识别输入只领取一个进行中的任务，其他份待它完成后读取结果，不另建 worker 或在网络期间持有数据库事务。复用仍核验当前原片，再向该份独立声音记录写入结果和来源阶段 ID；文件丢失不能凭缓存通过。剩余文案配音由下述 v16 阶段承接；逐输出完整声音编排、人工转写兜底和真实服务验证仍待完成。

公式迁移 v15 追加逐输出文案映射阶段及结果，`audio-mapping.ts` 根据冻结原文和实际原声生成 source/tts/on_screen/reference 分块。当前 `formula-audio-mapping/5` 保留精确覆盖和人工用途，并支持有完整句子引用及单独模型核对的同义、句内含义对应。`sourceCoverage.kind=semantic` 保存实际引用及 `verification`（提示版本、模型公开身份、理由）；引用须来自原声，数字/单位和否定表述差异先由程序阻断，模型不能放宽。第二次调用使用同一冻结模型，重新核对完整台词/脚本上下文与剩余配音，响应必须完整且逐项确认覆盖、无重复旁白；未确认则需处理，调用失败重试，取消不提交。旧 `/1`–`/4` 结果保持可读和不变，不补写历史判断。

原声完整保留，不按语义引用裁切音频或猜词组时间，实际字幕不改成脚本文字。精确路径仍对每个连续配音窗口合并后查重，语义路径还核对同义重复。混合模式使用冻结脚本模型，程序检查原文拼接、槽位顺序与连续非原声窗口；纯原声的文案只作参考。统一配音及无原声场景有模型时也分配花字/备注，无模型且没有明确用途标记时兼容整文配音，有明确标记则需处理。结果保留每份自己的原声依据和待配音文案，尚无真实音频及时间线，始终 `executionReady=false`。审片显示模型判断与完整台词对照；正式清单的 `scriptAudioMapping` 沿成片绑定的时间线读取生成依据并白名单保存语义核对字段，实际后续编辑仍由音画及字幕字段表达。数量换算、否定改写等有差异的表述可由人工用途入口处置，不能凭映射成功替代制作检查与审核。

自动 on_screen/reference 须由同一冻结模型另一次调用逐块确认用途，保存 `roleVerification`；原文包含标签完整保留，花字另存原文子串 `displayText`，不能删掉数字/单位/否定后自动放行。只展示的文字不进入 TTS 或声音字幕；包装关闭时需处理。`formula-timeline/2` 将花字映射到实际画面，单片最多 24 条、每条最多 60 字符，同镜头按顺序分时、每条至少 12 帧；太短不丢字。`output-presentation.ts` 转为稳定包装 cue，并只加一次片头；有明确花字时不追加自动提炼卖点。正式清单条件性白名单保存花字正文/核对依据，兼容旧块字段；实际修改仍读发布包装配置。

公式 v23 追加不可变 `batch_formula_manual_audio_inputs`，`manual-audio-mapping.ts` 和逐输出 `manual-audio` 接口提供混合、统一配音模式的人工恢复入口。第三步 `FormulaManualAudioPanel` 逐段选择原声、连续无原声窗口配音、指定镜头花字或仅参考，保存前确认试听；原文必须完整，参考文字不朗读也不自动成为花字。已有花字正文及目标镜头经读取、人工保存和重启保留；扩展版本化 JSON，不修改已发布迁移。人工不同表述保留实际原声、实际字幕与差异提醒，`basis=manual`、`manualVerification` 和 `sourceCoverage.kind=manual` 区别于模型及精确覆盖，不绕过后续制作检查或审核。

人工保存复用 `reselectFormulaOutput` 的版本校验、旧任务取消与当前输出失效，但在同一事务复制原选片结果，后续 worker 不重新抽片；从原公式和这些原片重新编排，不带入旧时间轴人工调整。人工记录绑定原映射及原声内容签名，缓存复用来源标识不改变台词身份，真正的媒体或台词变化则拒绝消费。相同请求可幂等回读，失败事务不留下半份重做；新阶段沿既有调度器恢复并拒绝迟到提交。历史版本、正式包及兄弟输出保持不变，正式清单只带对应输出的人工确认身份及白名单内容。页面保留未保存修改和不确定回复下的原请求，已有更新须显式重新读取。

公式 v24 追加不可变 `batch_formula_replacement_hints`，`replacement-hints.ts` 解析现有 JSON/TXT 主建议，`replacement-hints-store.ts` 负责项目/批次归属、整份保存/清除、资料修订及相同请求回读。第一步 `FormulaReplacementHintsPanel` 经 `formula/replacement-hints` 接口预览、保存和读取；原说明及 TXT 行号保留，备选及同号文件不变成规则。重复 JSON 字段、归一后重复编号、自替换、多跳/环和超过 256 KiB/1000 项的文件拒绝。预览不写数据库，保存及资料修订同事务，已保存快照重启可读。

`generation.ts` 冻结可选 `replacementHints`，旧请求缺省为空。`formula-replacement/2` 只将旧建议的编号对作为模型候选提示，不把旧说明或路径发给模型充当证据；仍按当次材料资料核验语义、完整台词、明确数量和实际文件。同级候选优先采用通过核验的旧建议，原编号和用户显式规则仍遵守既有优先级。选片结果中的 `importedSuggestion` 保存源记录/文件指纹、编号对和行号，第三步显示文件来源，正式清单逐字段提取；清除或新一轮资料不回写旧结果及历史包。该入口不声明本批 19 个建议都可采用，也不完成真实画面/声音听审。

最后一份原声结果与后续映射入队在同一事务完成。`selection-store.ts` 的 `repairFormulaContinuations` 在原 runner 每轮开始时补齐旧版本已完成选片/原声但尚无映射的当前请求，能力关闭、暂停及被替代的输入不补；某请求续接失败记录一次日志，保留输入并继续其他任务，修复后自动再试。重选及旧任务提交继续使用同一执行视图与租约保护，不能按脚本身份广播修改其他输出。

公式迁移 v16 追加逐输出配音阶段及结果，映射完成后同事务入队；已冻结完整配音配置但缺阶段的当前请求也由原 runner 续接。`generation.ts` 冻结所选供应商/模型/地址摘要、音色/语速及对齐身份，不保存密钥；旧请求缺完整冻结时显示未配置，不能临时套用当前服务。`narration.ts` 仅合成映射留下的文案，调用共享 TTS 适配器，按 48kHz 单声道 PCM16 的实际样本数计算时长；拒绝损坏、全零静音、错误内容或越界字幕，等分回退不能通过配音就绪。当前只证明有非零样本，不能替代真实人声和内容听审。

配音缓存按项目、确切文本、声音参数和处理版本隔离，每次复用仍完整核验文件。相同声音块的任务在共享调度器中排他领取，其他块可并行。对齐失败保留已生成声音，原任务重试仅重新对齐；密钥轮换可继续，模型或服务变化要求恢复配置或新建制作请求。提交前再核验文件，迟到任务受选片修订/租约约束；每份保存自己的文案、镜头窗口、音频指纹、实际长度和逐词时间，`executionReady=false`，还未接入最终排片。

选片历史同时返回 `narration` 状态；原属性面板提供逐段配音试听和实际秒数。`formula/outputs/[planId]/narration` 按项目、批次、输出、选片修订及配音块校验归属，只读已保存且通过指纹核验的文件，复用现有 Range 响应。切换原片/配音或离开面板停止旧试听；逐段试听与下述整条排片预览共存，不代替整片制作检查及人工审核。

公式迁移 v17 追加逐输出排片阶段及结果，挂在已保存的文案映射与实际配音结果下。无补配音时由映射结果直接续接，有配音时由配音完成事务续接；原 runner 补建旧版本缺失的排片阶段。执行及提交再次核验视频和配音，重选后迟到任务不能落盘。`timeline.ts` 保存原声/配音源区间、正文位置及逐词时间；20 帧封面不写进正文坐标。原声默认前后各留 120ms 并向外对齐帧，完整台词与动作保护不被缩短。

`timeline-ranges.ts` 联合选择合法区间组合，先容纳连续配音窗口，再满足总片长；固定目标不能只试每镜头第一个区间。没有人工区间时仅从合法原片边界提出待审裁切，不声称识别了精彩动作。组合计算超过保护预算时明确需处理，不截断候选冒充成功。`timing-settings.ts` 保存参考/严格上限/固定、正文/总长、可选统一秒数及 0–2000ms 原声边距；旧设置读取默认参考总长、Excel 秒数及 120ms，旧客户端省略字段保留原值，未改动保存保持幂等。

选片历史新增 `timeline`，原属性面板显示实际正文/封面/总长、目标、每镜头源/正文范围和冲突；第二步可保存时长设置。它是不可变排片依据；下述 v18 将成功结果接入可编辑草稿，尚不能据此进入正式审核/渲染。

公式迁移 v18 追加排片与 `batch_output_versions` 的一对一关联及来源不可变约束。`formula/output-store.ts` 在排片成功提交事务中建立 `formula-output/1` 草稿；旧成功排片由原 runner 续接补建，重复续接只复用原版本，不覆盖用户编辑或重新配音。仅当前输入、最新选片且未停止的批次可以建立版本；重选仍保留历史。新草稿为 `productionReady=false`，由 v19 的实际制作检查接续封面任务；未经检查不直接排封面或批准发布。

公式包装初次分配由 `formula/output-presentation.ts` 在真实排片之后完成。生成请求冻结项目产品名、卖点及完整封面预设；输出按请求种子、planId 和包装/封面各自的选择保存配置、选中身份及首镜头封面取帧。每份成片有自己的 `arrangement.packaging/cover/formulaPresentation`，重试不重抽，预设库或项目后来改动不回写旧配置；历史请求缺项目文案时也不暗读现值。启用包装时模板负责文字，封面预设构图继续生效，原生标题样式保留供关闭包装后使用。

初次花字由该输出的实际词级时间对齐，20 帧片头只加一次，标识随输出保存。显式重新提取使用当前输出字幕和冻结卖点，不能查询同脚本的旧整段配音。公式审片与封面抽屉以成片保存的 `outputPreset` 为准，不使用页面默认画幅；公式画幅在第二步设置。包装/封面锁定及整批重分配沿用输出修订；全部画幅和真实素材验收仍按原计划推进，已有草稿须通过制作检查、审核与发布核验。

`formula/preview.ts` 优先读取当前可编辑版本，仅对尚未建立版本的旧排片保留只读投影；`formula/output-preview.ts` 从当前声音计划生成预览坐标，媒体 URL 仍固定原排片身份。`preview/media` 核验项目/批次/输出/选片/排片/片段及真实文件，复用 Range/no-store。分割或移动只改变当前坐标，不凭新片段 ID 编造音源。公式能力关闭时保留读取，通用编辑接口也拒绝写入，页面显示只读原因。

`media-core/preview-audio-timeline.ts` 按源/正文坐标驱动真实媒体，只保留当前和下一段；加载/seek 未就绪时暂停画面，失败需用户重试。原播放器新增可选多声音输入，旧单条 narration/BGM 路径保留；切换、卸载与外部单段试听停止旧播放。时间轴点播放时同步停止外部试听，迟到的原生播放事件不得抢停新试听，异步画面加载也读取当前播放状态。当前公式画面读取原片，背景音乐读取本输出已保存来源；代理/解码兼容仍待完整验收，逐输出包装、封面及正式发布遵守本页的检查与版本约束。

共享 runner 在调用执行器前检查合并后的中止信号。首次进度写入也可能发现租约已经过期，此时不再启动执行器，任务按租约丢失恢复；不能假定执行器后来注册的 abort 监听还能收到已经发生的中止事件。

## Phase E — 联合分配与正式导出（v16）

批量语义矩阵按最多 4 句 × 32 场景串行评分，按原始句段/场景身份合并完整结果后才落库；单块失败不发布部分矩阵，任务停止后不再请求后续块。素材拆解与评分提示词不变。生产进度的停表与成功判定分离，无活跃任务不代表已有成片；回归证据见 [大素材池语义匹配修复](../2026-10-12-批量大素材池语义匹配修复.md)。

生产进度顺序为锁定设置 → 匹配画面语义 → 生成口播 → 自动配画面，分配使用口播真实时长。`progress-summary.ts` 的 `batchAllocationProgress` 在语义/口播任务未结束时保持等待；计划卡在确认输入时即存在，不能用卡片数量证明分配完成，须看分配结果或全部实际版本，受阻报告显示失败。

统一审片在 `source-conflicts.ts` 按权威原图归组实时生成同源提醒，显示在成片行与预览区；workspace 和 arrangement 视图返回 `sourceConflictAssetIds` 及带权威 key 的 `sourceConflictGroups`，供具体片段分组色块、「同源图」标记及「区间重复」汇总使用，局部编辑的空结果优先于旧卡片提醒。`review/video-usage.ts` 按当前全批次素材身份分配 A/B…，按原图 key 分配 S1/S2…；不能从扁平 ID 列表猜同源组。8 色设计令牌用 `@theme static` 保留，避免 Tailwind 裁掉运行时色号。手动编辑、审核、导出仍只提示、不拦截；自动排片遵守下面的同源互斥规则。不把旧分配警告当作当前同源事实。见 [同源提醒修复记录](../2026-09-29-统一审片同源提醒.md)。

- 同源互斥（`batch-allocation-v4`）：模块 4 视频经 `video_jobs.shotId → shots.sourceImageId` 追溯原始分镜图，同一项目内跨分镜组生成的版本也归为同源；不能使用 `video_jobs.sourceImageId`（它指向生成候选图）。找不到原始分镜时回落 shot，外部/无 shot 素材保持独立。自动排片每张原图只选一个视频版本，主分配与拼接均不回退同源兄弟、不循环已用源窗口补时长；无完整安排则报告素材不足、保留旧成片。跨成片和历史版本可复用，纯分割同一视频兼容；人工锁定版本及窗口预留，已明确锁定的同源片段不被静默改写。规则仅用于新分配和「换一批画面」，手动编辑仍只提醒。

完整视频导出默认优先使用 NVIDIA GPU 硬件编码，不可用时回退 CPU；合成滤镜保持不变。参数、探测缓存、取消与回退契约见 [导出硬件编码](./导出硬件编码.md)。

- Phase E（联合分配与正式导出）在 v16 增加联合分配运行和批次内素材排除；`allocator.ts` 是一次读取全部冻结输入的纯确定性分配器，`allocation-store.ts` 保留运行谱系并保证单条重分配不改其他计划。单条重分配（换一批画面）把目标计划**历史所有版本**用过的非锁定素材、区间与封面都纳入避让（打分惩罚 + overlap 惩罚），派生 seed 纳入当前版本指针：连续点击持续换新、不会在两批画面间来回切换，同状态重试仍幂等，锁定句段不受避让影响，素材池耗尽才回退复用并给出 `previous-version-reused` 提醒。`batch-renderer.ts` 只读指纹一致的原片和冻结 LUT，复用 `ColorPipeline`，通过原有 batch scheduler 真实渲染；`batch-export.ts` 成对追加发布视频/封面并拒绝覆盖。`phase-e.ts` 负责可恢复启动、任务接线和逐条正式发布，`batch-workspace.ts` 聚合卡片状态，输出媒体 route 只接受稳定 ID。普通批次没有真实口播时仅生成显式静音候选，正式发布必须提供已核验的 storage 相对口播快照；公式批次按本页独立声音及制作检查规则验证。**媒体代际（B2）**：成功渲染尝试是媒体身份——`batch-workspace.ts` 候选暴露 `renderAttemptId`、版本列表暴露 `candidateRenderAttemptId` / `artifactId`；candidate 媒体 URL 绑定确切成功 attempt、artifact URL 绑定确切 artifactId，同一个 URL 的所有普通/Range 请求固定同一物理文件，封面任务成功后卡片封面**不刷新页面**即随成功切换（queued/running/failed 不提前切换）。**下载与播放（B3，2026-09-03 改）**：导出页播放器、下载视频、下载封面全部绑定 `currentFormalArtifact`（播放器 key 含 artifactId，正式成片从 A 切到 B 时真实换源）；完整渲染候选不抢在正式成片前播放或下载。
- 片段级手动编辑（检查成片的「调整片段」）在 `output-arrangement.ts`：trim（等长换窗/变长修剪）、replace（换素材，窗口从 0 起）、删除、插入、分割，就地改当前候选版本 `arrangementJson`（单事务整读-改-整写），每次画面生效编辑 `editRevision +1` 并删除 `$.review`（画面变了必须重新过审核门禁）；`editRevision` 进 `phase-e.ts` 的渲染 requestKey，否则就地编辑后的重渲染会被 `createBatchTask` 幂等去重吞掉。变长修剪/删除保持后续片段位置，空位在预览和导出中保留黑场。空格切换播放/暂停（跟随成片或素材预览），C 切换分割工具，V 切换选择工具；输入文字、输入法组合、修饰键和封面弹窗内不拦截快捷键。修剪只对被拖动的端点做帧对齐，未拖动端点保持原值（自动分配的接点不一定落在整帧上，重新取整会压到相邻片段）；`trim_variable` 与统一审片的拖动预览共用 `media-core/video-trim-range.ts`，保证预览即落库，前端限制源时长、最短时长和邻片边界。时间轴默认开启 8px 磁吸，支持片段两端、正文起止和播放头，Alt 临时关闭，吸附显示辅助线；插入优先填空位，不足时仅顺延后续片段。视频支持 0.25–4 倍速与逐片段画面缩放/位移，减速不得覆盖相邻片段；口播/BGM 支持分割后删除，按原位置保留静音。裁切范围存 arrangement.audio，画面参数存 clips[]，并纳入完整渲染契约；分割是纯结构操作（总长不变，不递增 editRevision、不清 review、不重渲染）。**渲染时机（2026-09-03 编辑器优先，取代 2026-08-25 版本）**：编辑器里的预览是客户端实时合成的，不看渲染产物，片段编辑一律只保存 arrangement，`deferRender`/`commit_render` 已删除；除改封面（`set_cover`）会按新封面契约建一条 `output_version_cover` 任务外，检查阶段任何编辑都不排渲染任务，整片 mp4 只在导出编排时渲染（见「编辑器优先与正式导出」节）。**素材使用次数（F3）**：池视图按片段出现次数实时派生 `useCountByPlanId`（`clips[]` 有几次计几次，split 切成两段计 2 次），前端素材列表徽标显示「本片已用 ×N / 其他成片已用 ×M」，两数独立并存；封面身份仍走独立的 `coverUsedByPlanIds`，不计入片段次数。**审核重置提示（B4）**：每次画面生效编辑原子返回 `reviewCleared`（编辑前确有审核态才为 true），编辑器据此常驻提示「已重置审核状态、需重新审核」；纯结构 split、无变化提交、无既有审核均返回 false。API：`GET/POST .../outputs/[planId]/arrangement|clips`，口播音频走 `outputs/[planId]/media?kind=narration`。前端编辑器 `components/batch-production/BatchOutputEditor.tsx` + 实时预览 `BatchTimelinePreview.tsx`（客户端即时合成，复用 `components/final-edit/preview-playback.ts` 纯函数；这是 UI 层共享，`lib/batch-production/` 服务端仍不依赖 `final-edit/`）。编辑器为比例时间轴 `BatchTimeline.tsx`（画面轨 + 字幕/口播对照轨 + 播放头与预览同步）：拖边缘变长修剪、拖中段移动到空位或跨片段排序（move_clip，仅改时间线位置，源截取不变）、分割工具点击切开、右键菜单删除；不再提供独立精细修剪面板及双击入口。

## 编辑器优先与正式导出（2026-09-03 改）

- 新工作流：生产阶段只准备口播、画面安排与封面 →「检查成片」点卡片直接进编辑器用实时预览检查修改（无双模式切换、无历史版本选择器）→ 点「通过」只代表编辑方案审核通过 →「导出成片」时才真正渲染 mp4 → 导出页现有播放器播放这份正式成片；再次编辑后重新导出成功，同一张卡、同一个播放器原位切到新成片。正式成片仍从冻结的原始素材与安排快照渲染，浏览器代理预览绝不作为正式输入；静音占位仍只能预览；普通批次正式导出须确认口播就绪且 audioMode=narration，公式批次则核验原声/配音/混合声音及对应制作检查记录。
- 封面任务 `output_version_cover`（workType=render）：Phase E 为每个当前输出版本建立，全生命周期接入 `tasks.ts`（合法 targetKind 组合校验，非法组合仍拒绝）、`batch-render-executor.ts`（按 targetKind 分派封面/完整渲染并写各自结果）、`runner.ts`（运行中心跳 + 完成前版本 CAS + **三向契约 CAS**：现代任务要求 task requestKey、执行结果 `coverContractHash`、当前数据库契约三者一致；任一解析失败或不一致都按 superseded 终止并丢弃迟到结果）、`scheduler.ts`（不被口播闸门阻塞，仍受版本有效性与并发约束；同一封面契约成功复用，失败走显式重试）。`batch-renderer.ts` 抽出独立封面渲染接口与 `BatchCoverRenderResult`（只含封面谱系、契约、路径与指纹），两类结果分别解析、校验、清理，封面任务绝不冒充可播放视频候选；封面契约哈希由渲染所依据的冻结 snapshot 派生（resolveCoverContract 接受冻结 arrangementJson 覆盖），渲染期间同版本又编辑时不会把旧画面标成新契约。换画面/重分配/切换输出版本会同时取消旧版本两类任务。工作区无法解析当前契约时保守视为没有可用现代封面；只有不带现代契约 key 的老批次才回退到最近成功完整渲染的封面继续检查预览。
- 两种渲染契约（`cover-contract.ts` 是唯一计算源，建任务、新鲜度、工作区选封面、导出前最终并发校验四处共用）：封面契约（输出版本+封面渲染器版本 `batch-cover-v1`、素材身份与指纹、取帧时间、裁切缩放位移、主副标题文字样式、色彩链/LUT、画幅输出规格）出 `coverContractHash`，是封面任务 requestKey；完整渲染契约（outputVersionId + editRevision + coverContractHash + 口播/字幕/BGM/画面安排/输出预设有效身份 + 渲染器契约版本）出完整渲染契约哈希，是 `output_version` requestKey、`formalOutdated` 判断与发布前 CAS 的唯一来源（`formal-artifact-freshness.ts`）。task 无契约哈希的老任务回落「修订号+封面时间点」比对，**证据不足（任一事实缺失或损坏）一律保守判为已过期**，不靠猜。
- 工作区口径（`batch-workspace.ts`）：卡片分开返回 `coverTask` / `fullRenderTask` / `currentFormalArtifact`，状态拆成 `reviewable` / `approvable` / `exportEligible` / `formalOutdated` / **`exportStatus`**（not_exported/rendering/failed/exported，服务端统一判断，导出页只消费它不得再自拼任务状态），旧 publishable 含义已废止。**封面任务按当前 coverContractHash 选择**（A→B→A 时展示旧 A 任务的事实，不展示较新的 B 任务或其失败状态）；完整渲染任务同样只认当前 `fullRenderContractHash`，较新的旧契约失败任务不能遮住当前状态。正式产物必须按稳定路径组成 video/cover 一对，且两份 checksum 同时命中同一次成功完整渲染才算新鲜；丢失、损坏或错配任一半都 `formalOutdated=true` / `not_exported`。封面失败单独显示并可重试，不并入整批模糊的「需处理」；无完整渲染任务但已可检查的卡片不显示为 processing。返工期间 `currentFormalArtifact` 仍返回且 `formalOutdated=true`（前端显示「当前修改尚未导出」），导出页继续播旧正式成片。片段编辑路由（clips）**只在前后的 coverContractHash 真的变化时才排封面任务**：BGM、字幕、口播音量等 visualChanged 编辑不再平白重做封面。
- 导出编排（`export-orchestrator.ts` 的 `orchestrateBatchExport`，`POST .../exports` 唯一入口；前端只消费其状态，不自拼任务状态）：先预检（计划归属、当前输出版本、productionReady、口播、当前版本审核、正式导出预检，不合格直接 skipped 给原因），再算完整渲染契约建或复用精确匹配当前 requestKey 的 `output_version` 任务，并取消旧契约待执行任务；**编排模块内部**对新建或复用的 queued/running 任务都唤醒并等待调度器启动（懒加载 bootstrap，幂等），唤醒失败显式报错、保留已排队任务供重试，路由与其它直接调用方不需要也不应该再关心领取时机。单条返回 skipped / render_queued / rendering / render_failed / already_published / published；failed 终止轮询、显式重试才回队列。succeeded 先校验结果结构、audioMode、契约、文件与指纹，再复制到正式导出目录；最后在同一事务重查 currentVersionId、editRevision、coverContractHash、**reviewStatus** 与完整渲染契约（渲染或复制期间被编辑/撤销审核都拒绝旧结果，撤销审核不递增 editRevision，只比对修订号拦不住，必须在事务内复核审核态），video/cover artifact 成对注册并原子切换 currentArtifactId；同一事务内还判断「同渲染结果（版本+视频/封面成对指纹）是否已被并发请求注册为当前」——是则不再注册第二对（并发重复 POST 的最终幂等兜底），本请求多复制的文件随后清理；当前视频匹配但封面损坏时不误报幂等，而是发布一对新产物并切换指针。CAS 失败只清理本次新建未注册文件、不碰旧正式产物；已发布同契约重复 POST（含顺序与并发）返回 already_published，不重复复制。
- 关闭/刷新页面：渲染任务继续跑，重新进入能看状态，但需再点一次「导出」完成发布——导出意图只在前端内存，本轮零迁移不做持久化导出会话，文案不得假装自动发布。老批次已有成功完整渲染任务可作新鲜候选继续发布；老 artifact 与导出文件不删除，只是产品界面只认当前指针。

## Phase A — 项目素材卡与本地技术分析

- 外部素材的「提取文件名描述」按钮走 `POST /api/batch-production/assets/filename-description` 与 `filename-analysis.ts`，不要求先建批次或配置视觉供应商。仅本地核验原片并将原文件名转换成描述/标签，按整条视频一个场景写入新的分析版本；`analysisLevel=content` 表示可匹配，`analyzer=filename` 明确区别于画面观察，画质未知、动作时间未定位。已有视觉结果保留，重复提取复用，活跃分析任务不抢写；历史冻结引用不变。后续文字语义匹配仍使用原流程并可能产生调用费用。
- 文件名提取支持 `Accept: application/x-ndjson` 逐条返回真实核验/落库进度，默认 JSON 保持兼容；成功回执立即更新素材及已选分析版本，断线保留已完成项。项目日志记录开始、逐条结果与结束；AI 画面分析和语义匹配按阶段记录日志。语义 `semantic_fallback` 保留失败尝试和有界重试，项目日志用 WARN，生产进度区分重试与关键词兜底；错误分类只输出固定安全文案，不记录模型原文。

- Phase A 的项目素材卡在快照前通过 `asset-preparation.ts` 使用既有 batch scheduler 排队本地 FFprobe 基础分析；结果明确标记为 `technical`，不冒充内容理解。`project-asset-media.ts` 只按 `projectId + assetId` 解析并重验权威来源、完整 SHA-256 与真实容器，生成受控 960×540 JPEG 缩略图并提供原片 Range 预览；`startBatchProduction` 不再重复创建素材分析任务。

帧，不加片头会让每条批量成片系统性短一个封面。因为封面被烤进成片，`BATCH_RENDER_ADAPTER_VERSION` 升为 `batch-render-v2`；渲染任务 requestKey 不再只含 `cover.timeUs` 而是纳入统一 `coverContractHash`（`cover-contract.ts`），换封面只重做封面任务，整片渲染等到导出时再排。**斜体渲染（B1）**：字幕与封面标题的斜体从 `font-style` 改为 `skewX(-12)` 剪切合成（`lib/media-core/cover-title-svg.ts` 的 `textStyleToSvgElements`），librsvg 不会为没有 italic 字面的字体合成斜体而浏览器会，统一走剪切后预览与成片同款；`BATCH_RENDER_ADAPTER_VERSION` 因此再升为 `batch-render-v3`——旧 v2 任务点「重新生成」保留原 requestKey，新 attempt 运行当前代码产出修复后的斜体。斜体补偿规则：先按字号估 `fontSize × tan(12°)` 的 overhang 从可用宽度扣除再缩字号，锚点坐标不动（左/中/右对齐语义不破坏），同一段文字开启斜体后可能比直立略小，属接受取舍；收缩下限 0.5 倍钳的是**总收缩比**（overhang 要按缩后字号重估一轮，两轮各钳一次会把斜体压到 0.25 倍，同一段文字开不开斜体差一倍字号）。**已知残留（有意保留）**：剪切绕基线做，字身上半部相对锚点右移 ≈ `ascender × tan(12°)` ≈ 0.17 × 字号，这段溢出落在锚点一侧（right 对齐最明显，实测 80px / PingFang SC 越过右锚点 1~7px），而缩字号是宽度方向的杠杆、结构上够不着——根治只能移锚点（破坏 left/right 对齐语义）或改绕中线剪切（引入随字体变化的 ascender 猜测常量且只减半不根治）；默认样式是 center 对齐且对齐框左右各留 10% 画幅（1080 宽留 108px），残留碰不到画面边缘，故保留。另注：单条混剪的文字 overlay 走浏览器 Canvas（`components/final-edit/text-canvas-renderer.ts`）仍用 `font-style` 合成斜体，与批量的剪切合成外观不同，统一需另立任务。

公式编辑的版本化声音计划在 `formula/output-audio.ts`，接入现有 `output-arrangement.ts` 事务及整包撤销。`formula.audioSources/videoSources` 保存服务端来源依据，`audioPlan` 保存各声音的源/正文坐标、画面关联、增益和待处理问题；原声随画面，TTS 独立编辑。公式编辑要求当前输出版本与修订，撤销快照也绑定原输出版本；普通模式仍沿用原规则。原时间轴在视频后按需增加原声行，再显示配音、BGM；点击原声选中关联画面，不提供独立拖离操作。字幕和声音问题跟随当前修改，预览读取同一版本。人工来源的静音、保留原声及显式替代配音路径见本文开头；仍需通过媒体核验、制作检查及当前版本审核才能正式渲染。

公式声音渲染由 `formula/render-audio.ts` 为原 `batch-renderer.ts` 解析逐段来源：核对排片/输出关联、当前编辑版本及能力，重算音画联动和完整话语检查，再核验选中原片、实际配音及指纹。渲染使用当前 `audioPlan` 的源区间、正文位置和增益，按实际音画长度输出；结束前重验文件与修订，变更或取消后清理本次候选。结果的 `productionReady` 来自本次实际使用的制作检查记录；缺少或不匹配时保持 false，渲染完成本身不代表经过人工审核或已正式发布。

公式整片契约在 `cover-contract.ts` 追加 `formula-render/1` 输入，包含逐段声音及来源、音乐文件/压低/继承参数、正文时长与 24fps/20 帧片头、所有镜头指纹/色彩和实际字幕样式；普通契约保持兼容。公式未进入旧素材池时，封面与正文统一使用中性色彩，不查询分析表中的颜色。`batch-renderer.ts` 在首次媒体探测前捕获这些输入及封面标题配置，公式结果返回 `fullRenderContractHash`；`runner.ts` 对照任务、当前契约与实际结果，拒绝缺少身份、旧格式或 A→B→A 的错配结果并清理候选。此检查证明候选来自哪个版本，不代替最终就绪、人工审核及发布检查。

多源音频延迟后必须先用样本数建立时间戳，再 `apad/atrim`。真实测试发现 FFmpeg 在混音尚未提供首帧时可能先输出 `NOPTS` 的延迟静音；直接裁切会吞掉片头或分割后片段的等待时间。公式路径的每段延迟与最终 20 帧片头均按 48kHz 样本数处理，混音使用 `normalize=0` 保持分割前后的设定音量；`formula-renderer.test.ts` 以不同频率声标检查源 5–7 秒、编辑后的区间、片头、取消和过期结果，不以文件生成成功代替声音验证。

公式短渐变由 `media-core/audio-edges.ts` 定义，默认在所选区间内做 5ms 起止淡化，不延长或重叠话语；连续同源、同音量的结构分割不另加淡化。播放器把这些连续片段合成同一播放区间，避免换解码器时出现停顿，但不改已保存的编辑片段。淡出按播放头时钟安排；正常帧只同步当前时刻，不能先用上一帧时刻重排未来增益。起播使用 `preview-audio-start.ts` 的 AudioWorklet 从真实采样到达开始计数，避免渐变在媒体解码等待期间提前结束；加载失败明确报错。处理节点随播放器释放，普通批次不经过这条新音频链。

公式混音最后使用 `media-core/audio-protection.ts` 的同一软峰值曲线：0.75 以下不改变采样，较大峰值平滑收至 0.9 附近，给有损编码留余量；浏览器原声、配音和音乐共用一个输出节点。`audio-stereo.ts` 保持单声道复制到左右声道后的原电平，不改已有立体声差异；它必须在公式滤镜链首部执行，否则前面的重采样可能先隐式减小单声道音量。验收逐声道检查真实输出，不能用双声道混为单声道后的增益掩盖差异。该处理不是响度归一化，也不代表所有多声道来源、循环接缝或真实听感已经验收。

公式背景音乐在 `formula/output-music.ts` 保存每条实际曲目及文件指纹：初次建立输出时从生成请求已保存的候选池确定性选择，明确 none 不加音乐；手动新选曲保存当前 ready 曲库条目，同曲调参保留原文件。换曲和关闭保留本输出的来源历史，撤销只接受该历史中的曲目与指纹，不接受客户端路径；重复续接不会改写已有草稿。旧草稿已缺失音乐的情况不自动补曲，以免覆盖人工选择。

`formula/preview-music.ts` 按项目、批次、当前输出版本及选片/排片关联解析已保存音乐，核验受控路径、指纹和文件身份；前端连续预览及当前曲目试听使用同一受控 URL，支持 Range/no-store，曲库归档不改播另一文件。文件缺失或变化明确报错；编辑视图仍可打开修正。渲染前后均核验音乐指纹，公式人声+BGM 混音不做隐式音量均分。真实内容听审与完整发布契约仍需继续完成。

公式音乐裁切由 `media-core/music-timeline.ts` 统一校验并映射：源/正文长度相等，区间有序且不重叠，未编辑时铺满正文、显式空列表为无音乐；只播放正文内部分。虚拟源坐标按冻结文件时长循环，不根据实时曲库限制裁切。保存、整包恢复、预览与渲染共用规则；播放器 seek 未解码时静音并暂停推进画面/话语，FFmpeg 分段按 48kHz 样本延迟、重建时间戳及 `normalize=0` 混合，分割不改变音量。普通批次保持原音乐路径。

公式 `music.ducking` 保存版本化参数，新输出默认开启、再降 8dB、说话前 100ms 渐弱、结束后 250ms 恢复；旧草稿缺省关闭，非法参数拒绝保存。`media-core/music-ducking.ts` 从当前原声/配音正文区间产生同一线性幅度包络，连续片段和不超过恢复加渐弱时间的短间隙合并。播放器逐帧更新音乐音量，FFmpeg 按采样应用同一表达式；公式复杂滤镜写入本次私有任务目录再交给 FFmpeg，避免 Windows 命令长度限制，完成/取消后清理。音乐调参、关闭和整包撤销都保留参数；右侧单曲试听不施加成片人声包络，需播放成片试听效果。保存期间音乐控件禁用，待保存和刷新完成再解锁，避免迟到刷新覆盖下一次选择。

## 共享字体选择器（SystemFontPicker，2026-09-02）

- 批次字幕/封面与单条精准混剪字幕/封面统一使用 `components/ui/SystemFontPicker.tsx`，不再各自渲染原生 `<select>`。组件接收 `{ value, ariaLabel, disabled, onChange, compact?, portalRoot? }`，内部统一读取共享字体目录与收藏偏好。替换入口：`BatchTextStyleEditor.tsx`（单条字幕样式 + 批量封面主/副标题精调）、`BatchStepScripts.tsx`（批次默认字幕/封面标题）、`FinalEditInspector.tsx` 的 `StyleEditor`（单条精准混剪）、`mixcut/CoverEditorDrawer.tsx`（封面共享字体）。所有调用点在 family 变化时都清除旧 `fontPostscriptName`。
- 字体数据复用既有链路：`/api/system-fonts`（服务端扫盘）+ `components/system-fonts.ts` 的 `queryLocalFonts()` 会话合并（stale-while-revalidate 缓存）。`SystemFontPicker` 首帧用 `getCachedFontOptions()`，挂载后 `requestFontOptions()` 后台重校验，不重置搜索/页签/收藏/选择；`BatchTextStyleEditor.tsx` / `BatchStepScripts.tsx` 已删除各自 fetch/state/刷新实现。不改变 `/api/system-fonts` 返回格式与 `lib/media-core/system-fonts.ts` 的扫描/缓存规则。**不变式**：`SystemFontPicker` 的 `fonts` state 只装「检测到的目录」，**绝不能把当前 `value` 掺进去**——掺了 `currentMissing` 恒为 `false`，「当前字体」保护行永远不渲染，卸载掉的字体会被静默当成普通可选项（首版就是这么写的，已修）。目录就绪前（无会话缓存的首帧）一律按「已检测到」处理，避免误报缺失。
- 收藏偏好由 `/api/font-favorites` + core `font_favorites` 表持久化到同一 `dataRoot()` 的本机数据库，跨项目、任务、端口与浏览器环境共享。旧 localStorage key `creative-studio-font-favorites-v1` 仅作迁移与显示缓存；按字体 identity 合并迁移，取消收藏保留墓碑，避免旧窗口重新导入。写入为单字体幂等操作，事务防止不同窗口互相覆盖；同页即时同步、打开选择器/窗口聚焦/可见页每 15 秒重取。保存失败回滚并提示。收藏不进入批次冻结快照、成片版本或导出包；回归 `scripts/font-favorites.test.ts`。
- 纯逻辑在 `lib/media-core/font-identity.ts`（Node 直接测）：`fontIdentity = NFKC 归一 + 去空格 + en-US 小写`，搜索、去重、收藏命中、缺失判断全部用它，提交仍保留原 family 字符串；`mergeFontSources` 固定顺序（当前值 → 服务端 → queryLocalFonts → 收藏，同 identity 保留第一个原值）；`sortFontFamilies` 收藏按偏好顺序在前，其余按 `Intl.Collator('zh-CN', { numeric: true, sensitivity: 'base' })`，collator 相等再按原字符串码点破平，保证各平台结果唯一。
- 浮层定位：普通页面 `createPortal(..., document.body)` 固定定位到触发器附近，监听 resize 与捕获阶段 scroll 重算，避免被右栏 `overflow-y:auto` 或卡片裁掉；两个封面抽屉在 dialog 内提供脱离滚动字段的 overlay host（`mixcut/CoverEditorDrawer.tsx` 紧跟「共享字体」section；`BatchCoverEditorDrawer.tsx` 的 host 由 `BatchTextStyleEditor` 自托管——它在字体触发器所在 `<label>` **之后**（不能放进 label 内：label 会把浮层非交互区域——分组标题 / 「N+ 个字体」页脚 / 内边距——的点击转发给被标注控件即触发器，等于点一下标题就关面板；放在 label 外 DOM 顺序不变，label 本身不可聚焦）紧跟一个 host 并传给它自己的 `SystemFontPicker`，主/副标题各一份，Tab 从浮层出去落到本编辑器下一个控件「字号」，而不是跳过整个样式编辑器），浮层控件按 DOM 顺序进入抽屉焦点陷阱，Tab 从字体面板出去落到触发器所在 section 的下一个控件而不是抽屉末尾；浮层仍用 fixed 坐标和高于抽屉的层级。字体面板在 document 捕获阶段先消费 Esc 并 `preventDefault + stopPropagation`，抽屉 keydown 兜底检查 `event.defaultPrevented`，实现「第一次 Esc 只关字体面板，第二次才关抽屉」。
- 可访问性与性能：触发器 `aria-haspopup="dialog"`/`aria-expanded`/`aria-controls`，浮层 `role="dialog"`；缺失字体的选择按钮 `aria-disabled="true"`（可聚焦、激活不改字体），星标按钮可操作；「全部」页在同时存在多个组时渲染分组标题（当前字体 / 收藏 / 全部字体），标题不占 `data-font-row` 行号，键盘导航按纯行索引走，避免 listbox option 内嵌按钮的非法 ARIA；列表按固定批次 80 项渐进追加、滚到底自动加载下一批；End 加载完整结果并聚焦真正的末项，第 80/81 项边界的 ArrowDown 先追加下一批再把焦点移到第 81 项（统一经 `pendingFocus` 在渲染后落焦点，不依赖扩容前的旧行数）；浅色/深色用设计令牌，无硬编码浅色值。

## 素材级代理与代理键简化（v25，2026-09-06）

- 代理归属**素材**、不绑批次（共识 2/13），缓存键 = `{ assetId, contentFingerprint, profileVersion }` 的 sha256——**摘掉色彩快照与色彩链版本**。色彩/LUT 是预览层实时效果，不再是代理身份的一部分：换 LUT 不重转码、不失效旧代理；原片指纹或代理规格变化才产生新 key。`PROXY_PROFILE_VERSION` 不推进（键简化本身已使全部旧键失配，旧缓存行成为清理候选）。
- 新代理请求**一律不带色彩快照**（共识 13）：`batch_proxy_requests.colorJson` 列保留（NOT NULL，避免重建 cache 表），请求侧固定写入 LUT 关闭快照（`COLOR_SNAPSHOT_OFF`）。executor 滤镜链已退役全部色彩维度（A4）：只有 `scale=-2:min(720,ih),format=yuv420p`，不再读取请求的 colorJson/色彩链版本；`preview.ts` 解析顺序为 代理→原片→不可用，`original_pending_lut` 暂览分支已删除；确认整体输入时不再自动为 LUT 素材请求代理（手动入口保留）。LUT 导入/验证/存储（`lut-catalog.ts`、luts 路由）与正式渲染的色彩烘焙（`color-pipeline.ts`）原样保留。
- v25 迁移放宽批次绑定：`batch_proxy_requests` 重建，`batchId`/`batchVersionId` 可空（外键保留）、唯一约束拆成两个**部分唯一索引**（`WHERE batchVersionId IS NOT NULL` 上批次版本身份、`WHERE batchVersionId IS NULL` 上 `(projectId, assetId, proxyKey)` 素材级幂等）、表级 `CHECK((batchId IS NULL) = (batchVersionId IS NULL))` 防半空；`batch_tasks.batchId` 同步改为可空（素材级任务不挂批次）。重建同 v14 套路：先让全部新子表引用新 tasks——注意除了 `batch_task_attempts`，v17 的 `batch_asset_analysis_requests.taskId` 也是 ON DELETE CASCADE，漏掉重建会在 DROP 旧 batch_tasks 时级联清空真实存量（real-database-copy 测试抓过这个问题）。
- 素材级请求的幂等**由部分唯一索引保证**：`requestProxy` 先 INSERT，冲突（`SQLITE_CONSTRAINT_UNIQUE`）时捕获并返回现存请求，不做应用层先查后插。素材级请求不要求批次存在或已确认，只校验 `projectId + assetId` 归属（素材属于该项目、指纹与 `batch_assets` 一致）；`createBatchTask` 的 proxy_generate 校验分两支：批次绑定请求维持 project→batch→version→request 完整谱系，素材级请求只校验归属。`batch_tasks` 无批次的代理任务由调度器按「无批次视为运行中、无批次控制态」领取/心跳/完成（LEFT JOIN + `COALESCE(controlState,'running')`）。
- API：`POST /api/batch-production/assets/[assetId]/proxies?projectId=…`（素材级，响应 `{ requested: [{ assetId, taskId, requestId, cacheItemId, proxyKey }] }`）；批次级 `batches/[id]/proxies` 保留，请求同样不再携带色彩快照。

## 自定义脚本导入

自定义脚本可在未创建批次、未选素材时从「脚本与口播」导入。`BatchScriptImportDialog` 支持直接输入、批量粘贴及 TXT/Markdown 多文件预览；`manual-script-files.ts` 按一文件一脚本读取（文件名作标题，正文保留空行），支持 UTF-8、带 BOM 的 UTF-16 和 GB18030，最多 50 文件、每文件 64 KB。保存复用手动项目脚本 API 的整批校验/事务；仍需勾选脚本、创建批次并确认素材等输入后才能生产，冻结快照不被导入或修改覆盖。
