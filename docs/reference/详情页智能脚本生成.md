# 详情页智能脚本生成

本文记录 `lib/script-studio/` 的常驻架构与修改边界。它面向从项目详情页图片建立可追溯卖点库，再生成、编辑和版本化管理口播脚本的完整链路。修改该目录、`app/api/**/script-studio/`、`components/script-studio/` 或项目页脚本步骤前，应先读本文和对应实现。

## 1. 模块边界与不可破坏的约定

### 1.1 独立领域模块

- 模块有自己的 `{ version, sql }` 迁移流、readiness、任务表、调度器、执行器、API 与 UI，不是旧 `jobs` / `video_jobs` 队列的附属状态。
- 领域数据按 `projectId` 隔离。来源集只能引用当前项目的 `image_assets`；任务、卖点库修订和脚本读取都带项目归属条件。
- 需要共享生产编码能力时，只从 `media-core/` 方向取用：当前是 `production-codes.ts` 与 `production-code-reader.ts`。**不得从 `final-edit/` 导入，也不得让成片模块反向承载本模块领域逻辑。**
- 现有共享底层还包括 `script-providers/`、`schema-upgrade/`、数据库、`dataRoot()`、时长/字幕工具和 sharp；这些依赖不等于可以依赖 `final-edit/`。
- 目录导入会复制图片并写入当前项目的 `image_assets`，这是明确的数据入口；不要把它改成按文件名或时间戳猜测项目归属。
- 运行输入以任务创建时的 `inputSnapshotJson` 为准。供应商 ID/模型、卖点库修订、知识目录上下文和爆文模板全文等需要冻结的内容，不得在执行时悄悄改读“当前值”。

### 1.2 调度器默认关闭

真机调度器必须显式授权：

```bash
CREATIVE_STUDIO_SCRIPT_STUDIO_ENABLE_SCHEDULER=1
```

- 未设置为精确值 `1` 时，`ensureScriptStudioSchedulerStarted()` 抛出禁用错误；启动钩子只恢复任务记录，不启动真实供应商 worker。
- `instrumentation.ts` 在 Node 启动时调用 `startScriptStudioSchedulerAfterReadiness()`。readiness 失败或环境变量未开都返回 `null`，不阻塞旧功能。
- 创建任务和补跑路由也会尝试启动调度器，但捕获启动失败后仍保存 `queued` 任务。因此“能创建 queued 任务”不代表“已获准调用真实供应商”；响应中的 `schedulerEnabled` 才反映环境变量状态。
- 生产 bootstrap 的调度循环为 2 秒、调度器并发 1；通用 scheduler 参数上限为 3。脚本方案生成另有 `generationConcurrency`（默认 2），二者不是同一层并发。
- 修改实际供应商或执行语义时，要同步递增 `bootstrap.ts` 的 executor version，确保 Next 热更新保留的旧闭包先停止再替换。

## 2. Schema 与共享升级 gate

### 2.1 独立迁移流

`lib/script-studio/schema.ts` 的 `SCRIPT_STUDIO_MIGRATIONS` 当前目标为 v11，迁移记录表是 `script_studio_schema_migrations`。

**只能向后追加新版本，不得修改已经发布的 SQL。** 每条迁移在 `IMMEDIATE` 事务中执行，随后做 `foreign_key_check`，通过后才插入版本记录。历史存在未知版本、缺版本或高于当前代码版本时进入 `compatibility_only`；不得强行修补或降级。

主要表按职责分组：

| 职责 | 表 |
| --- | --- |
| 详情页来源 | `script_studio_source_sets` |
| 卖点库与修订 | `script_studio_libraries`、`script_studio_library_revisions`、`script_studio_selling_points` |
| 任务与恢复 | `script_studio_tasks`、`script_studio_task_stages`、`script_studio_task_request_usage` |
| 项目脚本 | `project_scripts`、`project_script_revisions` |
| 策略/模板目录 | `script_studio_catalogs`、`script_studio_catalog_revisions`、`script_studio_strategy_entries`、`script_studio_framework_templates`、`script_studio_copy_hook_templates`、`script_studio_visual_hook_templates`、`script_studio_template_assets` |
| 提炼表达 | `script_studio_distilled_points` |
| 爆文模板库 | `script_studio_viral_tpl_libraries`、`script_studio_viral_tpl_revisions`、`script_studio_viral_tpl_entries`、`script_studio_viral_tpl_style_cache` |

`script_studio_selling_point_themes` 是已发布迁移保留的历史表，当前 runner 不再写入。不能因为运行时已不用就删除旧迁移条目或篡改版本历史。

### 2.2 gate 的真实执行边界

- `readiness.ts` 通过 `runSchemaUpgradeGate({ scope: 'script-studio', ... })` 接入共享锁、审计、备份和恢复设施。
- gate 在持锁环境中处理中断审计与临时备份清理；`ensureScriptStudioSchemaReady()` 对待执行迁移先创建经过校验的 SQLite 备份，再逐版本迁移，最后由 gate 写入结果审计并释放锁。
- 锁超时、锁不可用、审计不可写、备份失败/校验失败、磁盘不足、迁移失败或历史异常均只让本模块进入兼容模式，API 返回 503；不得因此阻断不读这些表的旧功能。
- 运行路径统一来自 `dataRoot()` 与 `schemaUpgradeRuntimePaths()`：
  - 备份：`data/backups/schema-upgrades/`；
  - 跨进程锁：`data/schema-upgrade.lock.db`；
  - 审计：`storage/logs/schema-upgrades.jsonl`。
- `runtime-readiness.ts` 只缓存成功 readiness；失败会重查。`http.ts` 的 `assertScriptStudioApiReady()` 是 API 统一前置闸门，不能绕过它直接操作模块表。

## 3. 核心数据模型与版本语义

### 3.1 来源集、卖点库与脚本修订

- `sourceSet` 固定一组有序 `imageAssetIds` 和内容指纹。指纹按项目内唯一；相同内容复用来源集，不重复建行。
- `library` 用 `currentRevisionId` 指向当前卖点库版本。每次视觉提取、人工编辑或重新组织都会创建新 `libraryRevision`，卖点事实、证据引用、风险、可用性和详解随修订保存。
- 权威证据定位是 `evidenceRefsJson` 中的 `{ pageIndex, tileRef }` 配对；旧 `sourcePageIndex` / `tileRefsJson` 仅作兼容投影。跨页合并时不能拆散页码与切片的配对。
- `detailStatus` 在入库时由本地重算：`missing` 无详解，`verified` 的高风险内容有事实/证据支撑，`unverified` 含未支撑内容。爆文模板改写只接受证据有效、用户保留、结构重验通过且 `detailStatus='verified'` 的卖点。
- `project_scripts` 是脚本主体，`project_script_revisions` 是不可变版本链。AI 初稿、AI 再生成、人工编辑分别记录 origin；当前指针切换不改历史内容。脚本修订还冻结来源卖点库、模板与知识目录追溯信息。
- 默认生成链路直接使用已核验事实。`distiller` 只有显式注入时才执行；其提炼结果有独立规则版本、审核状态和不可变编辑链，不能把草稿自动当成已确认事实。

### 3.2 任务、阶段和生产模式

任务状态：

```text
queued | running | succeeded | partial | failed | cancelled
```

阶段状态：

```text
pending | running | succeeded | failed | skipped
```

任务有两种来源模式：

- `first_extraction`：从来源集读取详情页并建立新卖点库；
- `reuse`：使用创建任务时冻结的 `libraryRevisionId`，不重新识图。

生产模式独立于来源模式：

- `standard`：常规方向规划与脚本生成；
- `pain_solving_15s`：仅允许 15 秒，先做内容机会规划，再按机会生成；
- `template_rewrite`：按选中的爆文模板逐条改写；选择数必须等于生成数，同一模板可重复选择以生成变体。

共享输入契约位于 `generation-contract.ts`：目标时长只允许 15/20/30/45/60 秒，数量为 1–6 的整数。`extractOnly=true` 是模板改写的前置建库任务，保存卖点库后即成功，不进入规划与脚本生成。

`requestKey` 在 `(projectId, requestKey)` 上唯一。自动派生键覆盖项目、来源/库修订、时长、数量、供应商及精确模型、知识指纹、生产模式和模板计划等执行身份。数据库层使用原子 get-or-create，并比较规范化完整快照；同 key 不同请求体返回 409，不能吞掉非唯一冲突的数据库错误。

## 4. 生成、校验与持久化流程

主实现是 `runner.ts`，真实供应商组装在 `runtime.ts`，视觉/复核适配器在 `adapters/`。

### 4.1 首次提取

典型阶段顺序：

```text
input_check → read_pages → extract → evidence_gate → organize → save_library
→（可选 distill）→ plan → generate → validate
```

1. `read_pages` 按来源集读取项目图片并切片，长图使用有界尺寸与条带处理；不凭文件名决定项目归属。
2. `extract` 使用直接视觉提取，要求模型只读取清晰可见信息，并返回页身份、卖点、详解、事实与证据。服务端重新映射图片引用，执行去重和跨商品冲突检查。
3. `evidence_gate` 先做结构、证据位置、促销和高风险分类，再对高风险卖点做有界并发复核。无可用卖点时 fail closed；手动复核模式仍执行结构与来源检查，不冒充模型二次核验。
4. 需要跨批组织时，`organize` 把核验事实整理成完整卖点与详解；同次直接视觉提取已完成组织时可标记 skipped。组织失败不静默退回碎片库。
5. `save_library` 在事务中追加新修订并移动当前指针。恢复时优先读取该阶段已经保存的修订，避免重读图片和引用漂移。

### 4.2 复用、规划与生成

- 复用路径以 `load_library` 取代识图/证据/建库阶段，但仍重验证据结构和可用性，不能产出零引用脚本。
- `plan` 负责创意方向、受众画像、知识推荐、痛点机会或模板计划及方向卖点包。知识上下文已在创建任务时冻结；目录当前指针变化不影响旧任务。
- `generate` 对方案逐条生成、校验、修复并保存。常规生成最多三轮正文尝试；结尾检查与语义审核失败走定向修复/复审，不再无界整篇重写。单条失败不阻断其他方案，最终按保存数得到 `succeeded` / `partial` / `failed`。
- 标题校验与近期历史去重在保存事务中重读，AI 再生成通过 `targetScriptId` 追加修订，而不是覆盖旧版本。
- `validate` 保存时长、正文、事实引用、标题与重复度等校验快照。模板改写不套用常规 CTA 审核，校验中明确写 `not_required`。
- 请求预算持久化在 `script_studio_task_request_usage`：默认每方案 8 次文本 `completeJson`，任务总额为 `requestedCount × 8`；标题修复最多 2 次且共享方案余额。提炼与规划分析各有独立计数。中断恢复不重置余额。

### 4.3 爆文模板改写的特殊约束

- 客户端只提交条目 ID，服务端读取模板并冻结完整全文、顺序、结构、内容哈希与风格计划；不信任客户端全文。
- 每个模板有独立筛选白名单、风格分析和中间状态。`generate` 阶段 payload 持久化这些状态，风格缓存键为“内容哈希 + 实际模型 + 提示词版本”，只写完整成功结果。
- 同一模板的变体串行生成，以便后续变体看到前序文本做差异化；不同模板可受生成并发控制。
- 单条“再生成一版”从当前脚本内容快照重建原模板与原卖点库绑定，不读取后来切换的模板库当前版。

## 5. 调度、取消、恢复与补跑

### 5.1 领取和租约

- scheduler 只领取 `queued`，在事务中改为 `running`，默认租约 5 分钟并增加 `attemptCount`。
- `recoverInterruptedTasks()` 把租约为空或已过期的 `running` 退回 `queued`，清空租约和当前阶段。启动钩子在 readiness 后调用恢复。
- runner 每个阶段落库；已保存的卖点库修订、已保存方案的 `generationPlanIndex`、模板中间态和请求用量都是恢复依据。
- 生成恢复按 `generationTaskId + libraryRevisionId + generationPlanIndex` 找回已保存方案，不重复生成；保存与标题检查共用事务，减少恢复和并发重复。

### 5.2 中断与手动停止

- 手动停止 queued：路由直接写 `cancelled`。
- 手动停止 running：通过全局 scheduler 单例登记取消并 abort；runner 最终写 `cancelled`，已保存脚本仍保留。
- 进程停机也会 abort，但与手动取消不同：未带手动取消标记的任务回到 `queued`，等待下次恢复。
- `lib/shutdown.ts` 先停止 scheduler 领取并中止/等待在飞任务，再关闭 SQLite，保证任务收尾仍能写库。

### 5.3 失败/部分成功补跑

`POST .../tasks/[taskId]/retry` 只允许 `partial` / `failed` 父任务，创建带 `parentTaskId` 的确定性补跑任务：

- 已保存的卖点库优先转为复用；
- 常规模式按剩余数量补跑；
- 痛点模式只保留未完成机会，机会不足本身不算失败；
- 模板改写过滤已完成模板并重算计划指纹。

补跑幂等，重复请求返回同一子任务，不复制已完成方案。

## 6. API 与 UI 入口

所有模块 API 都先过 readiness。项目域基础路径为 `/api/projects/[id]/script-studio`，全局设置域为 `/api/script-studio`。

### 6.1 项目域 API

| 路由 | 方法与职责 |
| --- | --- |
| `/source-sets` | GET 来源集；POST 校验当前项目图片并创建/复用来源集 |
| `/import-directory` | POST 从用户明确给出的本机绝对目录导入详情页图片 |
| `/tasks` | GET 近期任务；POST 幂等创建生成/建库任务 |
| `/tasks/[taskId]` | GET 任务与阶段快照 |
| `/tasks/[taskId]/cancel` | POST 停止 queued/running 任务 |
| `/tasks/[taskId]/retry` | POST 对 failed/partial 任务补跑 |
| `/library` | GET 当前及历史卖点库；POST 基于当前版生成人工编辑新修订 |
| `/library/organize` | POST 重新组织当前卖点与详解并保存新修订 |
| `/library/evidence` | GET 指定卖点证据图，供人工核对 |
| `/distilled-points` | GET 提炼表达；POST 执行 `approve` / `edit` |
| `/scripts` | GET 项目脚本列表 |
| `/scripts/[scriptId]` | GET 单条/指定修订；POST 保存完整人工编辑新修订 |
| `/scripts/[scriptId]/revisions` | GET 修订历史 |
| `/scripts/[scriptId]/current` | PUT 切换当前修订指针 |
| `/scripts/[scriptId]/regenerate` | POST 创建单条 AI 再生成任务 |
| `/viral-template-recommend` | POST 基于当前项目和卖点推荐爆文模板 |

### 6.3 UI

- 项目工作台 `app/projects/[id]/page.tsx` 的脚本步骤挂载 `components/script-studio/ScriptStudioPanel.tsx`。面板覆盖上传/目录导入、建库、任务阶段轮询、模板选择、生成/停止/补跑、脚本编辑、历史修订和证据查看。
- `TemplateRewritePicker.tsx` 负责爆文模板推荐与手动选择；`ScriptTemplateSwitchDialog.tsx` 负责按既有脚本换模板再生成；`SellingPointEvidence.tsx` 展示来源图。
- 设置页 `app/settings/page.tsx` 的“脚本知识与模板”挂载 `ScriptKnowledgeSettings.tsx`，其中嵌入 `ViralTemplateSettings.tsx`。目录与模板库都是不可变版本新增/激活，不提供物理删除；已排队任务继续使用创建时快照。
- 前端轮询只是展示与恢复视图，不是任务执行器。页面刷新后通过近期任务找回 queued/running；真实推进由后端 scheduler 完成。

### 7.2 日志与敏感信息

- 本模块的用户可视过程主要来自 `script_studio_task_stages` 的持久化快照，不要另造只存在内存中的“假进度”。
- 真实 LLM 调用经 `completeJson` 携带 usageContext，`refId` 为任务 ID，视觉、复核、生成、组织使用各自 `refType`；不要改成无法归属的匿名调用。
- `limits.ts` 的资源日志只输出指标名称、实际值和阈值。新增日志不得加入 API Key、请求头、完整鉴权 URL、图片 Base64 或完整提示词。
- 任务快照只保存供应商 ID 和模型，不保存密钥。密钥解析留在共享供应商层。
- 目录导入只接受同源 JSON 和明确的绝对路径，校验 Origin/Sec-Fetch-Site；只读目录直接子文件，不递归，拒绝符号链接/文件变化，并限制数量、单文件、总字节和像素。原文件不修改，验证后的副本进入 `dataRoot()/storage/originals/inputs/`。
- 目录导入默认上限为 200 张、单张 32 MiB、总计 512 MiB；XLSX 默认上限 32 MiB。XLSX 还要通过 ExcelJS 实际解析 OOXML，不能只信扩展名。
- 模板参考图保存内容哈希副本，读取经过 `assertNoStorageSymlink`；不要提供任意本机路径读取 API。

## 8. 测试与验证入口

### 8.1 当前测试文件事实

当前工作树**没有收录** `scripts/*script-studio*.test.*`，也没有其他测试文件导入 `lib/script-studio/`。因此不存在可诚实列出的“详情页智能脚本专用测试命令”。`scripts/script-generation-v3.test.ts`、`script-workflow.test.ts` 等属于旧脚本链路，不应冒充本模块测试；`final-edit-canvas.playwright.test.mjs` 也与本模块无关。

修改本模块时应为对应领域补充真实测试，而不是仅运行旧脚本测试后宣称覆盖。尤其应覆盖：迁移历史与 gate、同 key 不同快照冲突、阶段恢复、预算延续、手动取消与停机回队、模板中间态恢复和项目隔离。
