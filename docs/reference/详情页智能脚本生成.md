# 详情页智能脚本生成

> 关联方案：`docs/superpowers/plans/2026-08-29-详情页智能脚本生成-技术执行方案.md`  
> 当前状态：阶段 0-5 已实现；阶段 6 已获真实公司供应商授权并完成 1 个商品/1 个品类的性能实测，尚未达到计划要求的 ≥6 商品、≥3 品类。  
> 2026-08-31：卖点层级与方向编排已实施（规格：`docs/superpowers/specs/2026-08-31-详情页卖点层级与方向编排设计.md`）——完整卖点库保留，生成前由本地编排器为每个方向准备卖点包，模型只根据各自卖点包写作。

## 模块边界

- 核心代码位于 `lib/script-studio/`，使用独立的 `{version, sql}` 迁移流（`schema.ts`），不走会吞错误的旧 core runner。
- 模块只依赖 `lib/media-core/` 与通用 `lib/`；**不允许 import `lib/final-edit/`**。需要共享的脚本可读性逻辑已上移到 `lib/media-core/script-visibility.ts` 和 `project-script-reader.ts`。
- `script_drafts` 保留只读兼容，新流程写 `project_scripts` / `project_script_revisions`；历史数据不做批量改写。
- 调度器默认关闭，只有 `CREATIVE_STUDIO_SCRIPT_STUDIO_ENABLE_SCHEDULER=1` 才会启动真实供应商执行。阶段 0-5 测试直接注入假供应商，不走该调度器。

## 关键约定

1. 空 `shotSetId` 表示项目级脚本，同一项目内可见；非空历史脚本保持原有窄隔离。
2. 实际使用时才把脚本快照绑定到目标 `shotSetId`。
3. 卖点库修订和项目脚本版本都不可变；人工编辑/再生成追加版本，切换历史只改当前指针。
4. 数字、材质、认证、功效、绝对化声明必须通过二次证据核验；文案只能写“已通过二次证据检查”，不得写“逐字核真”。
5. 所有资源限制值来自 `lib/script-studio/limits.ts`，不要在业务逻辑里写死。
6. 源像素/解码缓冲超过保护值**不阻断导入**：超限只写 `logLimitHit` 日志并在来源集报告里提示「自动压缩/分条处理」；超大图在 `tiling.ts` 走逐条带「源坐标裁剪 → 缩放」的流式管线，峰值内存只与单条带相关。
7. 切片编号契约：提取 prompt 约定切片按从上到下顺序 `tile_1` 起编号，`tileRefs` 必须用此编号；服务端 `parseTileRefIndex`（`runner.ts`）按 1-based 解析，失败不猜、兜底第 0 片。改编号规则要 prompt 与解析一起改。
8. 高风险卖点二次核验按最多 4 条 claim、最多 6 张去重切片组成一个有界请求，最多 4 个请求并发；每条 claim 仍有独立 ID/封闭问题，判定仍逐条在服务端做字符串匹配，不能用批内其他 claim 的答案互相证明。取消时剩余条目按「未核验」排除。
9. 提取按批并行：页内切片按 `extractTileBatchSize`（默认 6；公司 Luna 实测 14 张连续命中 120 秒超时）分批、`extractConcurrency`（默认 4）有界并发调用，服务端按批序合并；批提示携带整页 1-based 编号区间（`tileRange`）。每批记录尝试次数与毫秒耗时，便于区分内容固有开销和上游随机长尾。
10. 任务取消语义：`POST .../tasks/[taskId]/cancel` 打取消标记并中断运行中信号；Next instrumentation 与 API route 可能被打入不同模块实例，因此运行中控制器通过全局 `Symbol.for(...)` 注册，API 不能依赖自己的模块级 `Map`。runner 落库 `cancelled`（不再领取），区别于停机中断的 `queued`（租约恢复）。
11. 首轮脚本生成默认 2 路并发；响应返回后按方案顺序保存并重新对已保存兄弟方案做差异校验，既缩短等待又保持版本/去重契约。
12. 第三步会列出已配置、已启用且支持视觉的脚本供应商，用户为每个任务显式选择一个模型；视觉提取、证据复核和脚本生成全程共用该选择，并把 `providerId + model` 固定进任务快照。**执行端以快照为准**：`runtime.ts` 用快照 `providerModel` 覆盖执行模型并经 `completeJson` 的 `model` 参数固定实际调用，排队期间供应商配置从 A 改为 B 不会让任务显示 A 却调用 B。新项目默认选择公司 Luna，并明确标注"需要公司内网"；离开内网时可手动切换到已配置的外部 Gemini 等模型。所选模型不可用时提交前失败关闭，不得静默回退；历史任务没有选择快照时继续沿用公司视觉供应商默认值。
13. 公司 Luna 的响应存在显著随机长尾：同一 6 图批次曾第一次 120 秒超时、第二次 23.8 秒成功；2026-08-31 17:14 冷启动后的零并发 6 图探针又连续两次卡满 120 秒。客户端优化可以减少请求数和关键路径，但不能消除公司上游排队；完整证据见 `docs/2026-08-31-详情页智能脚本真机实测.md`。
14. Script Studio 调度器保存在 `globalThis` 以跨 Next bundle 转发取消，但开发热更新不会替换旧 executor 闭包；凡是改变任务实际供应商或执行语义，都必须递增 `bootstrap.ts` 的 `SCRIPT_STUDIO_SCHEDULER_EXECUTOR_VERSION`。所有创建任务的 API 必须先 `await ensureScriptStudioSchedulerStarted()` 再入队，版本不一致时先停旧调度器再启动新实例，避免任务快照显示外部模型而旧闭包仍请求 Luna。
15. 卖点层级数据契约（schema v2/v3，只追加不改已发布版本）：`script_studio_selling_points` 增加 `themeKey`/`themeTitle`/`hierarchyRole`/`importance`（v2）与 `evidenceRefsJson`（v3）。`themeKey` 一律由本地按 `pageIndex + 规范化 themeTitle` 生成（NFKC + 空白折叠 + 小写；模型 themeKey 只作辅助信息，绝不直接作为修订级稳定键；同页同标题跨批次归并，跨页不碰撞）；v3 迁移用 SQL 近似（TRIM）重写老数据。大标题只是策划主题：分组、排序与 prompt 语境可用，写进脚本的事实仍必须来自通过证据门禁的原子卖点。手动编辑创建新修订时这些字段原样保留；去重合并时主题取首个非空、角色取最强、重要度取最高。视觉提取 `promptContractVersion` 为 3，老模型/老响应缺字段时本地默认值兜底，不强制重读详情页。字段规范化统一在 `selling-point-normalize.ts`（`normalizeImportance`：null/undefined/NaN/空串回退 50，`Number(null)=0` 不会被钳成 1）。
16. 证据定位契约（v3）：权威结构是 `evidenceRefsJson`——每条引用自带 `pageIndex + tileRef` 配对，跨页去重合并后仍能把每条 evidenceQuote 定位回正确页面与切片；旧 `sourcePageIndex`/`tileRefsJson` 两列由配对结构派生，仅供兼容。解析（vision-extract）、去重（dedupe）、持久化（libraries）、结构门禁（evidence-gate）、二次核验取图（runner `evidenceTilesForPoint`）与卖点库 UI 展示全部使用配对结构；v3 迁移从旧两列回填。结构门禁同时校验定位合法性：非空 tileRef 必须能按 `tile_N`/数字解析，提供页数/切片数范围时页码与切片索引均不得越界（`pageIndex=999`、`tileRef=not_a_tile` 直接证据失败）。单条卖点核验取图硬封顶 `reprobeMaxImagesPerBatch`（默认 6）：精确切片优先、相邻片按序补位，6 条引用带相邻片膨胀成 18 图的溢出不允许发生。
17. 方向卖点包（`direction-briefs.ts`）：`plan` 阶段一次为本轮全部方向做纯本地、确定性编排。证据边界 fail closed——`evidenceGate=failed`、`usable=0` 或用户禁用的卖点一律不进入卖点包（usable 被重新打开也不例外）；全部方向候选为空时任务以 `evidence_insufficient`（可用证据不足）失败，不得产出零引用脚本。每方向按组成规则编排（如 scene_seeding 必须含场景/外观主张 + 功能/结构证据支撑，组成不足时降级补位并在理由中记录），排序优先级为「方向类型匹配 > 本轮重复惩罚 > 主主题连贯 > 主题角色 > 提取重要度 > 证据状态」；可选槽位先补给本轮尚未使用的方向内类型（类型分数是硬优先，只罚排序无法让未使用的次级类型上位），保证多方向卖点包在供给充足时实质分化。容量每方向 6–10 候选 / 3–5 必选（15 秒为 8/3）；`feature_showcase` 的必选优先跨 3 个不同主题。每个方向的主题、必选/可选 ID、候选数量、降级标记与理由写入 `plan` 阶段快照，首稿与相似度重试复用同一份包。
18. 生成与校验边界（fail closed，不可绕过）：`generator.ts` 的 `brief` 为必填，缺少 brief 直接抛错且不发起模型调用，没有回退完整卖点库的旧兼容入口；提示词只包含包内候选（required 标 `priority`），归一化丢弃模型返回的包外 ID，时长补齐与确定性回退也只从包内取事实。`validation.ts` 的引用白名单同样排除 evidenceGate=failed 卖点，且整条脚本至少引用一条卖点——零引用脚本（`sellingPoint_refs_required`）不得通过校验。提取/核验适配器的资源默认值（批大小、并发、超时、重试）一律取自 `limits.ts`，业务模块不再各自硬编码。
