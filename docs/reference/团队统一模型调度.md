# 团队版统一模型调度

> 需求依据：`docs/superpowers/specs/2026-11-10-团队版统一模型调度-功能方案.md`
> 任务图：`docs/superpowers/plans/2026-11-10-团队版统一模型调度/README.md`
> 验收记录：`docs/2026-11-11-团队版统一模型调度-全量验收.md`

## 范围内与范围外

团队服务端的新建生成任务只向员工暴露两个统一模型：

- **Image 2**：普通项目场景图（单条/批量/应用场景/重新生成）、创作画布图片节点、团队实拍局部图片返工。
- **可灵 3.0**：普通项目单条/逐行/批量视频、创作画布视频节点、团队实拍局部视频返工。

个人本地版、旧任务恢复、直连可灵、其他图片/视频模型仍走原路径。统一模型不是把所有同名模型合并；只识别下方四条精确公司通道。

## 身份与能力

### 精确通道目录

| 统一模型 | 通道 | 真实供应商行 | 精确模型 |
| --- | --- | --- | --- |
| Image 2 (`image2`) | 七牛 | `company-gateway-qiniuyun-gpt-image-2-medium` | `qiniuyun/gpt-image-2-medium` |
| Image 2 (`image2`) | 腾讯 | `company-gateway-image2-medium` | `image2-medium` |
| 可灵 3.0 | 七牛 | 种子中的七牛可灵 3.0 行 | `qiniuyun/kling-3.0` |
| 可灵 3.0 | 腾讯 | 种子中的腾讯可灵 3.0 行 | `kling-3.0` |

统一任务写入 `unifiedModel` 与规则版本 `unified-media-2026-11-10-v1`；真实通道只写入 execution operation/attempt 和 `execution_media_channels`，不覆盖旧任务的真实身份。

### 完整组合而不是参数并集

能力判断必须按一个通道的完整 `(清晰度/档位, 比例)` 格子执行，不能把两家列表分别合并。

- Image 2 当前可执行组合来自 `unifiedImageCatalogCombinations()`：腾讯支持 1K/2K/4K × 七种比例；七牛支持 2K/4K × 五种比例，`4K 3:4` 使用已验证的 4K 9:16 donor 裁切。
- 典型非法组合 `1K + 9:16` 没有通道可执行，必须在创建和提交前拒绝。
- 可灵 3.0 统一项目/画布一期只开放已能实现一致合同的图生视频（首帧＋可选尾帧），3–15 秒；比例/档位、首尾帧、智能分镜共同筛选通道。`4K + 尾帧`因缺少可信上游样例在提交前拒绝。

## 数据合同

execution schema v8–v11 在共享 `media-core` 中追加：

- `execution_media_tasks`：一条员工制作任务，保存统一模型、规则版本、冻结输入/输出合同、来源、取消意图、等待/结果状态。
- `execution_media_channels`：该制作任务的候选/真实通道，保存精确 provider/model、状态、executionRevision、operation/remote/evidence。
- `execution_media_channels` + `execution_operations.mediaTaskId/channelKey`：每条真实生成 POST 仍对应既有 execution operation/attempt；一个通道一次真实提交，一条制作任务最多两次。
- `execution_media_settings`：图片拥堵阈值，默认 30 秒，可在管理员“模型与名额”页调整（0–3600 秒），带 version 冲突保护。
- `execution_media_channel_health` / events：系统临时避让与审计；不写供应商 `enabled`。
- `execution_media_reconcile_actions`：管理员待核对操作、证据摘要、前后状态和幂等键。
- `admissionPriority/admissionCandidateCount/admissionTraceJson`：腾讯共享池的调度优先级证据。

业务表追加统一模型、规则版本、冻结请求、来源/幂等键、取消意图、父任务关联和
`unifiedGenerationId` 生成轮次列。旧行保持 NULL 或原真实身份；启动迁移不回填历史尝试。
人工重试/重新生成必须使用新的生成轮次，不能复用已终结的旧父任务。

## 选路

唯一入口在 `lib/media-core/unified-media/execution.ts` 与 `video-execution.ts`；项目、画布、返工不得复制路由逻辑。

1. 先按冻结合同筛兼容通道；不兼容的组合在付费提交前说明原因。
2. 在兼容、未真实提交过、凭据可用、池映射已核验、管理员启用且未被系统避让的通道中，七牛优先。
3. **Image 2**：若七牛唯一阻塞是真实 `pool_capacity`，写入持久 `nextEligibleAt` 并等待阈值；30 秒前不因拥堵走腾讯。到点先重试七牛，恢复则继续七牛；仍满且有腾讯候选才标 `overflowed` 分流。暂停时间用持久等待平移，不计入阈值。
4. **可灵 3.0**：七牛仅因容量满时立即使用腾讯，不套图片 30 秒阈值。
5. 明确未创建或远端明确失败后，才可换另一条兼容且未用机会的通道；未知、查询失败、下载失败不换。
6. 每次通道尝试创建新 execution operation/permit/价格快照，重新检查账号、模型授权、预算、池容量与公平；不沿用上一通道许可。
7. 两条通道都明确失败才最终失败；最多两次真实 POST，不双发、不循环、不通过隐形代理重试突破。
8. 腾讯池同等调度条件下优先只剩腾讯的任务；本轮老化窗口 30 秒，仍先遵守成员轮转、暂停、预算、个人/公平上限与池容量，不抢占运行任务。
9. 连续三次可归因服务故障（5xx、持续限流、超时、网络、解析失败）可让通道进入系统避让；起始冷却 5 分钟、指数增加至 60 分钟。冷却到期由一条普通任务作为恢复探针，不额外发起付费探测。审核拒绝、输入、权限、预算、下载失败不计入。管理员手动 `provider.enabled=0` 永不被系统自动打开。

## 受理证据、未知与费用

- `confirmed_not_created`、`accepted(remote_id)`、远端终态成功/失败、`unknown` 使用统一证据合同（`lib/media-core/submission-evidence.ts`）。
- 429/408/425/5xx、网络中断、响应解析失败或响应丢失，没有“未创建”证据时必须保持 unknown；名额/未知费用继续占用，不自动重发。
- 有远端 ID 的查询超时、进程重启继续原通道；结果已生成但下载失败只补抓原结果，不新建生成。
- 每次真实通道 attempt 独立记录 provider、pricing、remote ID、费用状态；失败不能假定免费，未知不能显示为零元。
- 员工侧项目/图片/视频/分镜 DTO 走 `lib/client-media-dto.ts` 白名单：不返回 `providerRawResponse`、远端/COS 签名媒体 URL 或本地绝对路径；视频只返回 `hasLocalVideo` 与受控媒体 URL。管理员诊断使用独立授权接口。

## 取消

- 未受理：立即停止选路、名额领取和 POST；重复取消幂等。
- 备用排队中：持久取消意图阻止剩余通道；重启仍有效。
- 已受理：不再开新通道或自动下游，但继续原通道查询、结算和补下载；晚到结果保存在任务记录中，可查看/下载/人工采用。
- 终态任务再收到取消请求是无副作用 no-op；项目级取消只处理活跃任务，不污染成功/失败历史。
- 已取消但已有 remote ID 或结果地址的任务仍可被后台只读查询/补下载；管理员补齐 remote ID 后也进入同一收尾路径，不重新提交。
- 项目图片晚到成功不更新 `shots.latestGeneratedImageId`，不自动追加候选；画布不发布当前节点、不提升下游；返工不自动覆盖人工采用片段。
- 取消不等于远端已停止或退款；页面文案区分“已停止后续生成”与“仍在收尾”。

## 管理员核对

`/team/admin/reconcile`（API：`/api/team/reconcile`）只允许管理员：

- 补远端 ID：只关联原制作任务/原通道/原 attempt，随后续查，不新建生成。
- 确认未创建：写证据并结算原 attempt；未取消且仍有兼容机会时，才允许剩余备用通道接手。
- 确认成功/失败：补结果/费用/占用；成功走原结果查询或补下载；失败按原剩余机会处理。
- 仍无证据：保持 unknown 和占用，不提供超时强制释放/重发。
- 已取消任务只补齐结果/结算，不重启备用或下游。
- 每个操作记录管理员、证据摘要、前后状态、时间、幂等键/版本；并发冲突明确返回，重复操作不重复执行。

## 费用与报表

- 员工任务中心与用量页按一条制作任务展示统一模型、任务状态和合计；自动备用仍是一份作品。
- 管理员可展开每次真实通道 attempt、远端身份、价格快照、费用状态与核账信息。
- 状态区分 `settled / estimated / uncertain / unpriced / released / mixed`；旧记录保留原金额和身份。
- 人员隔离在服务端执行；员工不返回其他成员、attempt 明细、remoteId 或真实通道路由；无 attempt 的排队/未定价任务仍进入任务合计与模型统计。

## 新旧兼容

- 上线前创建的任务没有统一父任务时继续按原供应商/模型快照恢复和重试。
- 旧 Image 2 项目默认值在启动时按精确旧通道身份一次性映射到统一锚点；旧 job 历史不重写。非统一预设尺寸不能静默改写。
- 同 job 的人工重试/重新生成使用新的 `unifiedGenerationId`，不能复用旧父任务的已耗通道或取消意图。
- 服务端新建任务拒绝真实 Image 2/可灵通道身份，包括自定义 provider 中出现的精确同名模型；旧任务恢复仍可使用冻结历史身份。
- 旧项目默认值迁移只改写可执行的完整尺寸组合；`auto` 或不可映射的自定义同模型行不会被猜测迁移，新任务入口返回 `legacy_image2_project_requires_upgrade` 并提示调整尺寸/重建项目。
- 个人本地版不展示统一锚点，仍走原供应商列表与规则。
- 旧画布任务能力键、旧返工 requestId/候选和桌面 Agent 的一次付费守卫保留。
- 管理员核对按模块分发到图片、视频或画布的统一失败 handler；已取消任务只补齐结果与结算。
- 图片/画布恢复探针遇到审核拒绝、输入或权限等非服务性失败时立即释放，不占用通道恢复名额。
- 规范 JSON 哈希统一走 `lib/canonical-json.ts`，避免图片、视频、画布与核对模块的冻结合同身份漂移。

## 配置、启用与恢复

1. 按团队服务器既有流程停止服务、部署新 release、启动应用；readiness 会在共享锁与备份 gate 内执行 execution schema v8–v11，失败时保持旧功能可用并报告具体 code。
2. 管理员确认七牛/腾讯真实供应商行、精确模型、凭据与池绑定；共享 `baseUrl + credential` 仍是同一真实池，不能按模型名虚增容量。
3. 在“模型与名额”页确认图片拥堵阈值、通道健康状态、手动启停与成员模型权限；统一模型授权兼容旧任一精确通道授权，不做前缀扩权。
   统一模型及其画布入口只负责选路，不是独立账号，不持有密钥或名额池；账号与配置检查只统计背后的真实通道，旧画布任务仍按真实通道快照检查。
4. 用 `/api/team/health/ready` 和团队控制台确认服务、执行与模块 readiness；再检查通道健康、待核对、费用页。
5. 恢复时先查 `execution_media_tasks/channels`、`execution_operations/attempts` 与异常中心。已有 remote ID 只续查/补下载；unknown 只核对。不得删除父任务、重置通道次数或手工把旧失败改回可重发。
6. 团队服务器升级/还原使用现有维护与备份流程；本功能没有独立后台服务或外部队列。

## 上游未验证

以下仍是外部事实，代码和模拟测试不能证明：

- 七牛与腾讯真实配额是否独立，共享 LiteLLM、COS 和下载链路的共同瓶颈。
- 当前真实能力组合、可灵智能分镜/4K/尾帧状态及生成效果。
- 最新结算价、失败/取消/未知请求的实际计费与可用账单证据。
- 真实远端取消能力；本实现不承诺即时停止或退款。
- 最佳故障窗口、恢复阈值和公平优先在真实负载下的吞吐/延迟。

模拟通过不等于真实上游恢复、扩容比例或最终账单。
