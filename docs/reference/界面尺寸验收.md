# 界面尺寸验收（林视界面重设计）

一条命令跑完整套界面尺寸检查：起一份隔离的统一生产服务，自动登录员工和管理员，用 Chromium（桌面客户端内核）和 WebKit 两个内核、1536×864 / 1280×720 / 1024×720 三档窗口、浅色深色两主题，逐屏、逐弹窗量三项尺寸要求，最后清理临时数据根与进程。

尺寸要求本身就是需求（功能方案 V04、V05），所以要测：页面不横向滚动、控件不被切掉、视频画面比例正确且够大。这套检查是原型目录 `tools/checks/` 三个脚本（`按钮被切.py`、`工具栏藏内容.py`、`画面比例.py`）的 Playwright 改写，阈值与原型一致。

## 怎么跑

```bash
node scripts/team-server/acceptance.mjs --level ui
```

直接跑（不经过验收编排，证据落在 `outputs/ui-acceptance-local/`）：

```bash
node scripts/ui-acceptance.playwright.test.mjs
```

已有待发布构建时，可设置 `TEAM_ACCEPTANCE_UI_PRODUCTION=1` 使用 `.next/standalone/server.js` 验收，避免 dev 首次编译耗时。仍使用隔离数据根、随机回环端口和断外网守卫，必须先完成 `npm run build`，不会退回 dev 或连接真实用户实例。

只跑自己那一屏（后续 UI 票日常用这个）：

```bash
TEAM_ACCEPTANCE_UI_SCREENS=mixcut-single node scripts/ui-acceptance.playwright.test.mjs
```

必看的前置条件：Windows 上要先重定向 TEMP（ffmpeg 会写 `%TEMP%`，不重定向会 Permission denied）：

```powershell
$env:TEMP="<仓库外的临时目录>"; $env:TMP=$env:TEMP
```

退出码为 0 且打印 `界面验收 passed` 才算通过；`known-failure` 不计入失败，但会在结果里单列，并要求对应的票在修好后删掉标记。

## 产物

| 路径 | 内容 |
| --- | --- |
| `ui-acceptance.json`（`--level ui` 时是运行目录下的 `ui-acceptance.json`） | 每次测量的判定、原因、越界元素、截图名，以及按屏、按检查项的总账 |
| `screens/*.png` | 每屏 × 每内核 × 每窗口 × 每主题一张截图，弹窗再加一张 |
| `server.log`、`live-server.log` | 隔离服务的完整输出（已脱敏：数据根换成 `[isolated-data-root]`，Cookie 换成 `[redacted-cookie]`） |

`checkTotals` 是验收要的那份总账：`horizontalScroll`、`clippedControls`、`hiddenOverflowContent`、`mediaFrames` 各自的 passed / failed / knownFailure 次数。

## 三项尺寸检查具体量什么

原型三个脚本的判据不能照抄，有两处必须先改，否则检查要么永远通过、要么全是误报（本票实测确认）：

1. `工具栏藏内容.py` 用 `getComputedStyle(el).scrollbarWidth === 'none'` 判断滚动条是否被隐藏 —— 那是 Firefox 属性，Chromium 只把它当 legacy 别名返回 `auto`，判据永远不成立。
2. headless Chromium 用 overlay 滚动条，`offsetHeight - clientHeight` 恒为 0，「没有滚动条槽位」不能当作滚动条被隐藏的证据。

所以 `hiddenOverflowContent` 改成量「内容是否真的够不到」：

| 情形 | 判定 |
| --- | --- |
| `overflow-x: auto/scroll` 且 `scrollbar-width: none` | 失败：能滚但没有可见提示 |
| `overflow-x: hidden/clip` 且内容比可视区宽 | 失败：内容被裁掉且滚不到 |
| 同上但 `text-overflow: ellipsis`（Tailwind `truncate`） | 通过：设计上有意的省略号，用户看得见「…」 |
| `input` / `textarea` / `select` 自身内部滚动 | 通过：浏览器原生行为；控件本身被切掉归 `clippedControls` |
| `overflow-x: auto/scroll` 且没关滚动条 | 通过：用户能滚到 |

其余两项按原型：

- `horizontalScroll`：整页 `scrollWidth > innerWidth + 1` 即失败，并列出越界元素（`div.mixcut-shell-module__fjjAuG__shell 右到 1597px` 这种）。
- `clippedControls`：`button` / `input` / `select` / `textarea` / `label` / `[role=button|tab|option|switch|radio|checkbox]` 只要被「祖先可见边界 ∩ 视口」横向切掉一截就失败；被 `overflow-x: auto/scroll` 祖先包着的（用户能滚到）不算。
- `mediaFrames`：`<video>` 与带 `data-output-preset` / `data-preset` / `data-media-frame` 的容器，比例必须与标注（或视频固有尺寸）一致 ±2%、宽 ≥ 100px、不越出窗口。

## 怎么加一屏的检查（05–14 号票）

全部改 `scripts/team-server/ui-acceptance-screens.mjs` 里的 `SCREENS`，一条屏一个对象：

```js
{
  id: 'project-video',                  // 唯一、kebab-case，出现在报告与截图名里
  title: '项目工作台 · 第 4 步 视频生成', // 报告里给人看的名字
  owner: 'ui-08',                       // 哪张票负责这一屏（改坏了找谁）
  audience: 'employee',                 // 'employee' | 'admin'，决定用哪个账号登录
  href: ({ project }) => `/projects/${project.id}?tab=video`,
  ready: async (page) => {              // 必须等「这一屏真的画出来了」再量
    await page.getByRole('heading', { name: '视频生成', exact: true }).waitFor({ timeout: 60_000 });
  },
  actions: [                            // 可选：每弹窗都量，就把「怎么打开它」写这里
    async (page) => {
      await page.getByRole('button', { name: '项目信息', exact: true }).first().click();
      await page.getByRole('dialog').first().waitFor({ timeout: 30_000 });
    },
  ],
  checks: ALL_CHECKS,                   // 想只量某项就写 ['horizontalScroll']
}
```

三条纪律：

1. `ready` 里必须有一个「这一屏特有」的可断言落点（标题、行、按钮），**不要用 `waitForTimeout` 顶替** —— 量到没画出来的页面等于没量。
2. 不要为了让检查通过去改界面。界面归对应的 UI 票，这套清单只负责量出来。
3. 已知问题只能用 `knownFailure: 'ui-NN'` 标记，不许直接放宽阈值。

### 附带弹窗

弹窗写在 `actions` 里：每个动作跑完就会量一次，并单独截一张图。结果在 `outcomes.popup1`、`outcomes.popup2`……与基础态 `outcomes.base` 并列。动作里必须等到浮层真的出现（`getByRole('dialog').waitFor()`），否则量到的是打开前的页面。

### 缺数据时怎么补（05–14 号票）

基础数据够现有全部页面用，由 `scripts/team-server/ui-acceptance-fixtures.mjs` 的 `base` 钩子准备：管理员账号（隔离数据根的首管理员）、员工账号（管理员经正式 `/api/team/users` 创建）、一个项目（员工经正式 `/api/projects` 创建，供应商用 fixture 占位 key）。

分镜组、视频、混剪分组、批次等复杂数据由用到它的票自己补 —— 在 `FIXTURE_HOOKS` 里加一个钩子：

```js
FIXTURE_HOOKS.shotSets = async (ctx) => {
  // ctx.api 是带 CSRF/Cookie 的正式 HTTP 客户端；ctx.employeeSession 是员工会话。
  // 只准走 /api/* 正式接口或隔离数据根里的 SQLite；不许联网、不许碰真实数据根。
  ctx.shotSet = await ctx.api.json(ctx.employeeSession, '/api/shot-sets', 'POST', {
    projectId: ctx.project.id, name: '验收分镜组',
  });
  return ctx;
};
```

然后在屏幕上写 `skipUnless: 'shotSets'`。钩子不存在时该屏记 `blocked`（不是静默通过）。

钩子的红线：只通过正式接口或隔离数据根造数据，不许绕过业务校验；不得触发任何供应商调用（fixture key 提交的任务只受理不执行）；造完数据要让 `ready` 等到它真的画出来。

## 已知失败（当前：无）

本票交付时混剪工作台在 1536 宽横向多出 61px、1280/1024 宽多出 85px（05 号票加左侧栏后变成 64px / 88px），曾记为 `knownFailure: 'ui-09'`。**09 号票已把工作台改成占满侧栏右侧内容区，该项已修好、标记已删除**，现在 `mixcut-single`、`mixcut-batch`、`project-empty-final-edit` 三屏都是硬通过。

标记机制留给后续票用，写法：

```js
knownFailure: 'ui-09',                       // 必须是票号
knownFailureChecks: ['horizontalScroll'],    // 只豁免这几项；别的检查真失败照样算失败
knownFailureReason: '……实测数字与根因……',    // 必填
```

两条硬规矩：

1. `knownFailureChecks` 只列真正属于那个已知问题的检查项。全列等于把这张票的检查全废掉。
2. 修好后**必须删掉标记**。屏幕带着 `knownFailure` 却全部通过时，会记一条 `known-failure-not-reproduced` 让整轮失败 —— 不会出现「修好了却还挂着豁免」。

## 本次没量到的部分（gaps）

有些浮层要「刚好存在的数据」才会出现，例如版本与备份页的清理确认弹窗要先把无用文件扫描出来。隔离数据根里扫不到东西时，这一档量不到。

这类情况记进结果的 `gaps`，命令行也会打印 `GAP`：**页面基础态照样量四项**，只有那个浮层如实标「本次量不到」—— 既不冒充通过，也不让整轮结果作废。

三档别混：

| 记法 | 含义 | 让整轮失败？ |
| --- | --- | --- |
| `failures` | 界面真有尺寸问题（或浮层打不开是真 bug） | 是 |
| `blocked` | 本轮失效：隔离服务中途死掉、屏幕声明的数据钩子没实现、已知失败屏没跑到 | 是 |
| `gaps` | 前置条件不满足，某个浮层这一档量不到；基础态已量过 | 否 |

## 按屏量「自己的区域」，共享外壳单独成屏

左侧栏、顶栏、页工具条在每一屏都出现。如果每屏都把它们量进去，它们一坏就会让全部屏幕同时变红，反而看不出「这一屏自己」的问题（混剪溢出 61px 会被淹没在几十条侧栏报错里）。

所以屏幕声明里有一个 `scope`：

| scope | 量什么 | 用在 |
| --- | --- | --- |
| `page`（默认） | 整页横向滚动按整页算；控件/藏内容/画面只量**外壳以外**的子树 | 全部业务屏 |
| `shell` | 只量 `aside[data-testid=workspace-sidebar]`、`header[data-team-shell]`、`[data-testid=page-toolbar]` 子树 | `workspace-sidebar` 一屏 |
| `all` | 全量，含外壳 | 检查器自测 |

这不改变「量什么」，只改变「在哪一屏量」：外壳的缺陷照样会被抓出来，只是恰好落在负责它的那一屏上。

## 本票实测抓到的两个真实缺陷（均已由 ui-05 修好）

两个都在 `components/team/workspace.module.css`，由 05 号票引入，04 号票只负责量出来、不改界面。**两个都已修复并被这两屏守住了**（修复后 `workspace-sidebar`、`project-video` 都转绿，验证了检查确实有效）：

1. **侧栏工号被切**：`.wsMenuAnchor` 是 grid item，缺 `min-width: 0`，默认 `min-width: auto` 让它无法收缩到内容的 min-content 以下。`.wsUser` 被长工号撑到 235px，溢出 224px 的侧栏并被 `overflow-x: hidden` 切掉。三档窗口 × 浅深 × 两内核全中。修法是给 `.wsMenuAnchor` 加 `min-width: 0`（改 `.wsUser` 无效）。由 `workspace-sidebar` 屏守住。
2. **视频页覆盖规则整条失效**：`workspace.module.css` 写的 `body:has(...) .video-generation-section` 里，`.video-generation-section` 是全局类名（来自 `app/globals.css`），写在 CSS Module 里会被哈希成 `workspace-module__xxx__video-generation-section`，两者永不匹配。于是想压掉的 `left:50% + translateX(-50%) + width:min(100vw-48px,1680px)` 全部生效，1536 宽横向溢出 88px、「选择分镜组」下拉被切。修法是写成 `:global(.video-generation-section)`。由 `project-video` 屏守住。

## 检查器自测
「现有页面全过」不能证明检查有效：一个永远返回 passed 的检查器也会全过。所以每个内核、每档窗口都先用 `page.setContent` 造一组已知好/已知坏的合成页面（`scripts/team-server/ui-acceptance-selftest.mjs`），逐条确认：

- 干净页面：三项尺寸检查 + 画面比例全部通过；
- 2400px 宽的内容：`horizontalScroll` 必须报错；
- 被 `overflow:hidden` 父盒切掉一截的按钮：`clippedControls` 必须报错；
- `overflow-x:auto` 但滚动条被隐藏、内容比可视区宽：`hiddenOverflowContent` 必须报错；
- 比例不对 / 太小 / 越出窗口的画面：`mediaFrames` 分别报错。

自测记录在结果的 `selfTest` 里。自测失败说明检查器本身坏了，和界面无关，先修检查器。

## 硬断言

- **不调用付费模型**：供应商用 `fixture-not-a-real-key` 占位 key，提交的任务只受理不执行；结果里 `realPaidProviderCalls: 0`。
- **不读写真实数据根**：数据根是 `mkdtempSync` 出来的隔离目录，结果里 `isolatedDataRoot: true`，服务进程挂 `scripts/team-server/no-external-network.cjs` 断外网，跑完 `rmSync` 并回填 `cleanup.removed`。
