# 供应商适配器与任务队列 参考

> 从 `AGENTS.md` 下沉的实现细节。新增供应商时按这里的适配器接口实现并注册，**不要改动队列等核心逻辑**。
> 公司网关特有的尺寸吸附、COS 中转与尾帧 allowlist 见 `docs/reference/公司网关与COS中转.md`。

消耗计价与历史回填口径见 [2026-09-30 公司模型账单均价与消耗统计](../2026-09-30-公司模型账单均价与消耗统计.md)：图片按张，视频按 5 秒折算，Luna 新调用按次估算；历史冻结价格不重写。

冻结用量快照的结构、供应商身份与计价组件核验集中在 `lib/usage-snapshot.ts`，图片队列和账本共用。当前计价计划只用于核验身份，不得用当前价格覆盖快照中的历史价格。

## `queue.ts` / `video-queue.ts` — 图片与视频任务队列

- 腾讯共享池的准入偏好由 execution 层统一计算：先执行成员轮转、暂停、权限、预算、个人/公平上限与池容量；同等条件下，当前只剩腾讯可用的任务优先于仍可等待七牛的溢出图片。偏好只作用于未来准入，不抢占运行中任务。
- 偏好依据冻结的 `execution_media_tasks/execution_media_channels` 判定；权限/预算不合格任务不进入合格需求，七牛被停用、健康避让或已明确失败时不构成可用替代通道。可溢出任务等待满 30 秒后升为普通优先级，防止连续单通道任务造成饥饿；实际轨迹写入 operation 的 `admissionPriority/admissionCandidateCount/admissionTraceJson`，管理员可在任务详情查看。

- 统一模型的系统健康状态在 `lib/media-core/unified-media/health.ts`，按“统一模型 + 通道”持久记录，与供应商 `enabled` 手动启停分离。连续 3 次结构化服务故障才临时避让；审核/输入/预算/权限/下载失败不计入。冷却到期后的普通待执行任务作为一次恢复探针，不新增付费探测；管理员在“模型与名额”页面可看到三态并清除系统避让。

- 团队服务器的普通图片/视频项目不再受项目存值 `concurrency` / `videoConcurrency` 的 10 条上限约束。`media-queue-workers.ts` 按项目实际任务涉及的共享池容量启动 worker（同池别名去重、数量不超过任务需求），运行中重新读取容量及新增任务；权限、费用、成员手动/个人上限和自动公平共享仍由 execution 准入裁决。所有媒体池统一适用，容量取配置，七牛 100、其他媒体 50 都只是例子；单人自动继承且任务足够时，一个项目可借用对应池全部空闲名额，多池独立使用容量。
- 旧并发存值与环境变量仅为项目/API 兼容保留；控制台显示「按名额池调度」。下文 `VIDEO_CONCURRENCY` 的 1–10 约束只适用于个人本地版。`node scripts/media-queue-workers.test.ts` 验证单项目 100 条、20/50 混合池、别名共池、动态扩容及成员上限；`node scripts/execution-admission.test.ts` 验证所有媒体池和 LLM/TTS 池按各自容量准入与不超售。均使用隔离数据根和模拟供应商，不发真实付费请求。

- 实拍重组局部返工由持久化 `final_edit_film_reworks` 关系识别。**团队服务端新返工**（workbench 里勾选统一 Image 2 / 可灵 3.0）在 job 上冻结 `unifiedModel/unifiedRequestJson`，走共享选路、健康、容量等待与有限兜底；每通道最多一次、任务最多两次，`requestId` 重放只续跑同一 job。**旧本地/桌面 Agent 返工**没有 unified 标记，继续一次付费提交、未知不重发。统一返工的完成结果只写入原分镜候选，不自动改 `latestGeneratedImageId` 或已采用的成片片段；登记/采用仍是显式人工动作。恢复前与领取时共用 `reassembled-shot-guard.ts`，但守卫跳过 unified 新任务，不能停止其他 worker 的 running 任务。专项命令：`node scripts/unified-team-rework.test.ts`、`node --loader ./scripts/typescript-extension-loader.mjs scripts/reassembled-rework-queue.test.ts`。

- 视频手动「重试」仅在本地 `failed`、远端 `providerStatus=failed` 且无产物时清除旧远端 ID，记录旧 ID 后重新提交；模型、提示词、首尾帧和智能分镜选择保持冻结。未知状态、取消或下载失败保留远端 ID 继续查询；自动恢复不得因此重新提交。`scripts/video-job-retry.test.mjs` 覆盖实际重试路由及重复点击。

- 图片手动「重试」的同一口径：远端已确认终态失败（`providerStatus='failed'`，队列 `failRemoteImageTask` 写入）时清掉旧 `providerTaskId`、写日志后重新提交；结果已生成、仅本地下载失败（`download_failed` + `remoteImageUrl`）时保留远端身份转 `needs_check` 补抓，**不重新提交**，避免重复扣费。`scripts/image-job-retry-route.test.ts` 覆盖。工作台第 1/2 步的「重试」在右栏换了供应商时改走 `/api/jobs/:id/regenerate` 新建一版（原任务的供应商/模型是冻结的）。

- 团队普通项目单条 Image 2 由 `execution_media_tasks/channels` 承载逻辑任务，真实 `execution_operations/attempts` 仍是一通道一笔账：只有明确未创建或远端终态失败才由 `handleUnifiedImageExplicitFailure` 切换另一条未提交通道；未知、查询失败、下载失败留在原通道，取消意图在选路与付费 POST 前各查一次。`prepareUnifiedImageExecution` 会从已结算终态 attempt 恢复结算后、选路前崩溃的备用切换，禁止同一通道二次提交。`listUnifiedImageChannelAttempts` 是管理员核对与费用投影的只读合同，04/11 继续扩展同一选路函数，13/14 复用该 attempt 投影，不另建计数。
- 团队项目图片的所有新任务入口（新建项目首批场景图、场景批量、分镜组“应用场景”、单张重新生成）共用 `lib/media-core/unified-media/project-jobs.ts` 冻结项目和输出合同；统一项目不能从请求里的真实通道绕过锚点，跨项目/跨分镜素材在创建前拒绝。每条任务独立保存 `creationSource`、冻结输入与完整组合，`creationRequestKey/Hash` 让同一创建请求重放返回原 job 列表而不是再建一批；真正重新生成仍创建新 job，通过 `parentJobId/revision` 保留历史候选。
- Image 2 首次选路增加七牛容量等待：只有定向准入精确返回 `pool_capacity`，且后续预算/未知费用门禁也通过时，才写入 `waiting_capacity` 与持久 `nextEligibleAt`（默认 30 秒，管理员在「模型与名额」调整，范围 0–3600 秒）。到点先重试七牛，仍满且有腾讯候选才把七牛标 `overflowed`（无 POST、不消耗机会）并新建腾讯 operation；暂停队列会把剩余等待平移、不把暂停时长计入阈值，重启保留 deadline。`personal_concurrency/fair_share/monthly_budget/cost_unknown/暂停/维护/缺池` 都不触发分池，系统健康避让的七牛也不会开始倒计时。腾讯分流明确失败后可按 03 的机会回七牛，复用无提交的 pending operation，总真实 POST 仍不超过两次。
- 团队普通项目可灵 3.0 统一入口：员工只看到 `unified-kling-3` 锚点（显示「可灵 3.0」），真实执行只走精确公司通道 `qiniuyun/kling-3.0`（七牛优先）与 `kling-3.0`（腾讯）。`video_jobs` 保存统一模型和冻结请求，`execution_media_tasks/channels` 保存逻辑任务与每次真实尝试；普通项目只开放图生视频（首帧＋可选尾帧），时长 3–15 秒、比例/清晰度、首尾帧和智能分镜必须由候选通道完整满足，画布/参考模式不能借统一入口扩权。七牛仅因真实池容量满而阻塞时立即转腾讯（不继承 Image 2 的 30 秒阈值）；明确未创建/远端终态失败可换另一条未用通道一次，unknown 只续查，下载失败只补抓。旧视频任务、直连可灵和其他视频模型不受影响。回归：`node scripts/unified-kling-{contract,create,queue}.test.ts`。

- `queue.ts` / `video-queue.ts` — 图片/视频任务的内存中队列：向供应商提交任务、轮询状态、下载结果、失败重试；支持暂停/恢复。视频并发由 `VIDEO_CONCURRENCY` 环境变量控制（1–10，默认 10，可在视频生成面板按项目调整）。视频下载落盘后过 `video-browser-preview.ts`：HEVC/10bit（Seedance 2.5 1080p 产物）浏览器放不动，就地生成 `<base>.preview.mp4`（libx264/yuv420p/CRF19/+faststart）衍生物；`/api/videos/[...path]?preview=1` 懒生成并服务衍生物（覆盖存量），不带参数的 GET 恒为原件，下载与剪辑渲染链路不受影响。播放侧入口统一带 `?preview=1`：视频生成面板（组件内拼 URL）、混剪素材组与 final-edit 工作区（`mixcut-context.ts` / `workspace.ts` 的 `previewUrl` 构建器），外部导入素材走 `external-assets/[assetId]/media?preview=1`（同一衍生物机制）；渲染产出的成片/预览本身是 H.264，不经过衍生物。批量生产的两条预览路由（`/api/batch-production/preview/[assetId]` 原片分支与 `/api/batch-production/assets/[assetId]/preview`）对视频原片直接服务衍生物（原片内容、H.264 重编码），代理分支不受影响。

## `providers/` — 图片生成适配器

`ark-images` 为 Seedream 5.0 Pro 方舟直连：精确模型 `doubao-seedream-5-0-pro-260628`，同步 JSON `POST /api/v3/images/generations`，不走 LiteLLM。共享请求构造在 `providers/ark-images.ts`，尺寸合同在 `seedream-image.ts`；旧图片队列与画布共用，参考图保持输入顺序。默认预设禁用且无 Key，补种不覆盖用户配置；详见 [直连接入记录](../2026-10-07-Seedream5Pro方舟直连接入.md)。

`gateway-task-image` 对精确模型 `doubao-seedream-5-0-pro-image` 使用方舟同步 JSON 协议，通过既有 `immediateImageUrl` 返回，不进异步任务轮询。Nano Banana 3.0/3.1 保持异步协议并显式传清晰度、画幅；详见 [2026-09-29 接入记录](../2026-09-29-公司模型接入与验证.md)。

### 团队统一模型的待核对任务

管理员「待核对」页面只处理 `execution_media_tasks/channels/operations/attempts` 中已有证据的 unknown/needs-check 任务。动作必须同时指定统一任务、真实通道和原尝试，并携带 `expectedVersion` 与幂等键；补远端 ID、确认未创建、确认成功、确认失败、仍无法确认分别写 `execution_media_reconcile_actions` 审计。补 ID 只关联原 attempt 续查，不新建生成；管理员也可补只在业务行保存的原结果地址用于补下载，该地址不进入审计或接口回传；确认未创建/失败才会复用统一路由选择剩余兼容通道；已取消任务只收尾，不重新进入队列。实际费用可空表示仍未核清，不能按 0 元结算。旧 operation/orphan 无法关联统一任务时单列，不按名称猜归属。实现见 `lib/team-service/unified-reconcile.ts`。

Seedream 同步等待沿用项目 `timeoutMs`（默认 600 秒），队列传递取消信号；`onProgress` 每 5 秒报告本地请求耗时及超时上限，队列写入现有任务日志。返回与异常结束也记录耗时，`finally` 清理等待与超时计时器。这不是远端进度查询，不生成虚构 task ID，也不增加提交次数或 `pollCount`。

- `providers/` — 图片生成适配器：`openai-compatible`、`packy-images`、`packy-gemini-image`、`geekai-json`、`gateway-task-image`（New API 类中转网关把图片模型挂在 `/v1/videos` 异步任务协议下的场景，与 geekai-json 同为提交→轮询→下载三段式）。多图编辑的图片顺序统一约定为**待编辑底图在前（图1）、参考图在后（图2-N）**，与项目默认提示词「图1=分镜图/底图、图2=场景参考图」一致；`geekai-json` 与 `gateway-task-image` 的参考图引导前缀也按此编号。`gateway-task-image` 对公司 `qiniuyun/*` 模型的参考图走免 COS 内联通道：≤20MB 原样转 data URL 不压缩（保细节），超出压到 ≤6MB/4096px/q92，压缩失败回退 COS/本机 URL 链；瓶颈是网关 nginx 请求体上限（2026-08-21 实测 28.3MB 通过、40.8MB 413），阈值见 `CREATIVE_STUDIO_INLINE_*`。

## `script-providers/` — 脚本（LLM）生成适配器

- `script-providers/` — 脚本（LLM）生成：`gemini`、`openai-compatible`（Chat Completions）、`openai-responses`（Responses/SSE，覆盖 Packy GPT 等）与 `anthropic-messages`（`/v1/messages`，覆盖 Packy Kimi 等），配置存库并由 `apiStyle` 选择协议。
- **`temperature=1` 红线**：公司网关推理模型 `GPT-5-6-Luna-*` **只接受 `temperature=1`**，显式传其他值会被上游 400 拒绝，功能直接不可用。三层保障，动任何一层前先把三层都读完：
  1. `openai-compatible.ts:28-30` — 前缀 allowlist `/^GPT-5-6-Luna/i`，命中直接强制 1，不必先挨一次 400。**这里用前缀匹配是有意的**（覆盖 Luna 各变体），与视频尾帧那条「不许放宽成前缀匹配」是两回事，别照搬。
  2. `openai-compatible.ts:150-158` — 未知模型命中 400 特征（错误文本同时含 `temperature` 与 `does not support|unsupported value|not supported`）后，把 `${baseUrl}|${model}` 记入进程内名单并用 `temperature: 1` 重试一次。**名单是内存态：进程重启后每个受影响模型仍会先挨一次 400。**
  3. `script-generation-v3.ts` 的 `generateScriptV3` — 脚本生成调用对所有供应商固定 1，避免与适配层形成双份约定。
- **连带影响：修正循环没有降温这个杠杆。** 分析调用（`script-generation-v3.ts` 的 `analyzeScriptStrategyV3`）本来按 `attempt === 1 ? 0.5 : 0.2` 逐轮降温以求稳定；但脚本生成调用固定 1，Luna 更是三层锁死。所以脚本修正重试拿到的是「另一次随机采样」，不是「更保守的一次」——排查「修正了几轮还是不达标」时先记住这一点，别去猜温度没生效。
- **封面标题规则集中在 `script-cover-title.ts`**：提示词契约、结果校验、措辞沿用与服务端合成兜底住在一起，改规则不能只改一边。普通结构失配允许降级；非法 `visualRefs` / `sellingPointIds` 返回独立结果，由 `generateScriptV3` 继续走 blocking 修正，不得用兜底标题掩盖编造引用。

### 脚本供应商流式约定

`openai-compatible` 的 HTTP 失败通过 `error-diagnostics.ts` 映射为固定的安全类别（参数、上下文、图片读取、限流、额度、审核、模型、鉴权、超时），供脚本降级提示和批量素材分析错误共同展示；未知响应明确显示原因未识别。不得把上游响应正文、任意 `code/param`、提示词、密钥或签名 URL 直接写入错误。温度回退失败以最后一次响应分类；此诊断不新增 400 重试。分类表示上游报告的线索，不等于已验证根因；历史只存 HTTP 状态的错误无法恢复原始原因。

运行时脚本生成由 `completeJson` 的 `onTextDelta` / `onReasoningDelta` 回调驱动。回调契约是**累积全文**，不是增量；三种 `apiStyle` 的 delta schema 如下：

| apiStyle | 正文字段 | 推理字段 | 备注 |
| --- | --- | --- | --- |
| `openai-compatible` | `choices[0].delta.content` | `choices[0].delta.reasoning_content` | 请求带 `stream: true` + `stream_options: { include_usage: true }`，已实测 |
| `openai-responses` | `response.output_text.delta` | `response.reasoning_summary_text.delta` | 正文已实测；推理字段仅按官方 schema 实现，暂未验证 |
| `anthropic-messages` | `content_block_delta` → `text_delta` | `content_block_delta` → `thinking_delta` | 请求带 `stream: true` + `thinking: { type: 'enabled', budget_tokens: 2048 }`，已实测 |

- 共享 reader 在 `lib/script-providers/sse.ts`，统一处理行缓冲、注释行、`[DONE]`、跨 chunk 断行与 abort 中断；各适配层只解析自己的 delta schema。
- 拿不到推理流时 `onReasoningDelta` 从不触发即可，UI 自动不渲染思考块；**不要报错、不要特判**。
- 公司网关 `GPT-5-6-Luna-Standard` 实测**不返回任何推理 delta**（LiteLLM 与直连网关两条路径均无），它的推理段只有前端计时器与阶段行是正常口径；完整推理内容不落库、不进轮询快照，快照只保留 `reasoningTail` 尾部约 1500 字与 `reasoningChars` 总量。
- `streamedContent` / `reasoningTail` 仅供内存快照展示，不参与解析链路；`script_drafts.generationDurationMs` 只记录成功落库耗时，供 UI 显示“上次约 X 秒”的参照。

## `video-providers/` — 视频生成适配器与尾帧能力声明

供应商列表与更新响应经 `video-model-capabilities.ts` 统一输出 `capabilities`（合法时长、尾帧、智能分镜、全能参考），保留旧能力字段；尾帧仍只调用适配器精确 allowlist，参考能力由 `video-reference-contract.ts` 按供应商类型＋精确模型声明。面板经浏览器安全的 `video-generation-options.ts` 解释供应商继承、五秒草稿默认值、最近合法时长及请求字段；旧响应缺少快照时兼容原时长规则与能力字段，缺少参考快照时视为不支持。草稿切换保留显式 `multiShot: false`，不支持时省略请求字段；服务端非法时长拒绝、历史任务 NULL/false 语义不变。

公司 `minimax-h3` / `wan-3.0` 通过 `openai-video` 使用腾讯原生 `FileInfos[].Usage=FirstFrame/LastFrame`，时长分别为 4–15 / 2–30 秒，默认输出 2K / 1080P。Wan 另须显式 `OutputConfig.AspectRatio`；两者都不发送可灵 `multi_shot` / `shot_type`。各一条 4:3 首尾帧付费任务已完成，H3 请求 4 秒实返约 4.459 秒；参数边界、实际像素及验证范围见 [接入记录](../2026-10-28-MiniMaxH3与Wan3公司模型接入.md)。

主工作台中，公司 MiniMax H3 / Wan 3.0 支持切换「首尾帧 / 全能参考」：新草稿默认以当前分镜图走全能参考，已有尾帧或历史任务的显式模式优先，切换模式保留尾帧草稿但提交只携带当前模式字段。其他模型使用首尾帧；不显示参考素材上传器或额外比例/清晰度控件。全能参考覆盖公司 H3 / Wan 3.0、Seedance 2.0 / 2.0 Fast / 2.5 及直连 Seedance 同精确型号：H3/Wan 以有序 `FileInfos[].Usage=Reference` 提交，Seedance 以方舟 `reference_image/reference_video/reference_audio` 提交，公司 Seedance 复用 LiteLLM 的 Ark 透传包装。`video_reference_assets` 保存项目归属的不可变图/视/音素材，`video_job_references` 冻结任务顺序；`referenceAssetIds` 为空时直接读取任务冻结的 `sourceImageId` 原图作为唯一参考，不重复复制/上传到本地素材表；有显式参考列表的历史/API 任务仍只用该列表，海报不混入。创建与执行都验证图片归属、存在性和模型限制，重试不会改读分镜的新图片。比例按分镜图吸附并随任务冻结，清晰度沿用模型默认档。公司参考全量强制回环 LiteLLM＋COS；直连 Seedance 图片可 data URL，视频/音频仍必须 COS，交付失败不得 POST。

- 视频整数秒约束由 `lib/video-duration.ts` 按「供应商类型 + 模型」统一提供（`videoDurationOptions`），界面、单条/批量提交接口与 `jimeng` / `kling` / `openai-video` 适配器共用：Seedance 2.5 为 4–30 秒（方舟直连与公司网关均已实测，2026-10-06 确认），2.0 / Fast 为 4–15 秒，可灵 3.0（含公司 `kling-3.0` / `qiniuyun/kling-3.0` 与直连 kling-v3）为 3–15 秒，未知模型回退 2–15 秒。公司 `openai-video` 精确别名 `kling-2.5` 仅支持 5/10 秒（单首帧、首尾帧一致；直连可灵不受此限）——可灵版本按精确别名区分，不能通用套用最低时长（[官方说明](https://cloud.tencent.com/document/product/1823/135742)，2026-09-30 核对）。
- 工作台逐行与批量抽屉用下拉框只列支持值，批量统一时长取各行支持值的交集，切换供应商时把草稿时长调到最近的合法值；设置页默认时长用 `VideoDurationInput` 秒数框：聚焦全选、仅接受数字、只短暂保留可补成有效两位数的前缀（如 15 的 1、30 的 3），输入或离焦即校正到最近的合法值。非法 API 请求整批拒绝，适配器在任何上传与网络请求前再次拦截，不静默截断。

- `video-providers/` — 视频生成适配器：`kling`（可灵）、`jimeng`（即梦）、`openai-video`（New API 类统一中转网关的 OpenAI 风格 `/v1/videos` 协议，Bearer Key 鉴权）。三个提交入口是**显式合同**：`submit`（首帧＋可选尾帧）、`submitText`（文生，content 只有文本项，无首帧）、`submitReference`（多模态参考 `reference_image`／`reference_video`／`reference_audio`）；**未实现某入口就表示该供应商不开放对应模式**，画布据此注册能力。视频尾帧（`video_jobs.tailImageId`）能力由各适配器 `tailFrameCapability(model)` 按精确模型 allowlist 声明：`jimeng` 仅直连 `doubao-seedance-2-0-260128`（Ark `first_frame`/`last_frame` role）；`openai-video` 仅 `lib/company-gateway-tail-frame.ts` 里已核验的公司别名——可灵 `kling-2.5` / `kling-3.0` 尾帧走腾讯原生 `LastFrameUrl` + `OutputConfig.AspectRatio`/`Resolution='1080P'`（时长走 `OutputConfig.Duration`：网关 LastFrameUrl 分支不透传 `seconds` 落缺省 5s，`OutputConfig` 字段原样透传腾讯，2026-08-18 真实任务验证 10s 生效）（`images[1]` 会被当参考图，已证伪），Seedance `doubao-seedance-2-0(-fast)-260128` 尾帧走 `images[1]`；公司尾帧强制本机回环 LiteLLM + 首帧尾帧双 COS 预签名 URL，门禁或上传失败一律在 POST 前失败关闭。

0.7.1 的默认图片列表仅提供公司预置；退休的 GPT.ge、Packy、GeekAI、方舟直连预置不再补种，旧记录按固定 ID（GeekAI 按原始签名）从列表过滤，保留历史任务引用和用户自建配置。视频列表隐藏官网即梦 2.0、可灵 2.5，新增公司即梦 2.0 标准版（doubao-seedance-2-0-260128）；公司可灵 2.5 保留。旧 core migration 不改写、不删除历史供应商行。

## 统一媒体的取消收尾

- `applyUnifiedImageJobCancel` / `applyUnifiedKlingJobCancel` 是团队普通项目图片、视频业务任务的取消入口；画布继续走 `requestCanvasTaskCancel`。它们只写持久取消意图：尚未受理的任务立即 `canceled`，已有远端身份的任务保持 `running`/`needs_check` 收尾，不伪造“已远端取消”或退款。
- 取消后队列仍沿原通道查询、结算和补下载。晚到成功结果保存在任务自身 `outputImageId`/`localVideoPath`（画布为 `outputAssetId`），状态保留 `canceled`/`cancelled` 并带“已停止后续生成、结果已收尾”文案；普通项目图片不会更新 `shots.latestGeneratedImageId` 或自动写候选，画布不会发布节点当前结果或提升下游任务，返工候选必须人工采用/登记。
- 已提交任务在受理后取消只保留原通道；未知结果继续保留占用。管理员在 13 的核对页只能补齐结果、费用和收尾证据，不能借取消任务重启备用通道或下游。
