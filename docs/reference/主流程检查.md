# 主流程检查

整理架构或改变步骤间的数据交接后，运行 `npm run check:main-path`（Node 22+，先安装项目依赖）。退出码为 0，且最后打印“主流程检查通过”，才算通过；中间某一步的“通过”只代表该阶段完成。

这条检查沿用同一个项目，验证上传 → 建项目 → 场景生成及归库 → 分镜生成 → 脚本保存 → 视频任务 → 智能混剪 → 基础成片发布 → 创意 ZIP。它补充各模块测试，用来发现前一步的输出无法被后一步使用的问题。

## 检查的证据

实际运行路由处理函数、图片和视频队列、SQLite、文件存储、FFmpeg 预览与正式渲染、发布登记和 ZIP 打包。检查会确认：

- 分镜生成带上场景参考图；脚本和视频使用刚生成的分镜。
- 混剪使用已保存脚本和下载的视频；生成可读取、带音轨的预览。
- 发布视频与封面，校验成片尺寸和时长，并抽查每个字幕时间窗内的声音。
- 解压 ZIP 并校验 CRC；包内脚本、分镜、成片和封面与本轮产物一致。

图片、脚本、视频供应商响应以及视觉分析和配音使用固定模拟输出；音轨是测试音。文字图层用透明图片替代浏览器绘制，并显式关闭装饰模板包装。因此通过结果证明基础流程的数据和媒体处理能衔接，**不能代替真实供应商、浏览器交互、字幕视觉质量、模板包装或 Windows 免安装包验收**。当前执行证据来自 macOS。

## 隔离与失败定位

父进程先创建临时数据根，再用清理过的环境启动测试子进程。所有 `fetch` 请求均被本机模拟响应接管，未知请求直接失败。测试不启动 HTTP 服务，不读取 `.env.local`，数据库、日志和产物都写临时目录；结束或 180 秒总超时后清理自身进程与目录。无需停止现有工作台，也无需构建或改写 `.next`。

失败时从最后一条“通过”之后的断言和错误定位，区分模拟素材不满足当前契约与产品逻辑故障。修正模拟数据时保留跨步骤关联、真实渲染和 ZIP 内容断言；不要为了通过而改成直接插入成功状态或跳过失败阶段。
