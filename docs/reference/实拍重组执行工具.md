## 动态任务队列

入口：`scripts/reassembled-film-queue.mjs`。一个工程只启动一个 worker；其他进程可随时入队或记录审核，不争抢生成台账的锁。

```powershell
$filmProject = 'I:\m7-studio\outputs\你的工程'
node scripts/reassembled-film-queue.mjs enqueue $filmProject .\你的任务列表.json
node scripts/reassembled-film-queue.mjs run $filmProject --watch
# 在另一个终端，或由 agent 的后续命令执行：
node scripts/reassembled-film-queue.mjs approve $filmProject S02-image agent '已对照实拍检查结构、材质、方向、人物与背景'
node scripts/reassembled-film-queue.mjs enqueue $filmProject .\返工任务列表.json
node scripts/reassembled-film-queue.mjs status $filmProject
node scripts/reassembled-film-queue.mjs timings $filmProject
```

`approve` 必须在实际审图/审视频之后使用；不是下载成功就自动批准。用户只审最终片，agent 负责逐镜自检。审核绑定文件 SHA256，替换同名文件后旧审核失效。

XQ5A真机执行补充：Windows读取者/防病毒可能短暂锁住JSON目标文件，原子替换遇EPERM/EACCES/EBUSY时有限重试10次，永久失败保留旧台账。worker已读的entries保存在内存，移走inbox文件不会撤销已加载任务；当前工具没有取消接口。需要撤回时先确认没有提交中的同步请求与活动任务，再停止worker、归档被撤回的inbox、启动新worker。Seedream同步响应阶段包含生成，打断无ID请求会失去恢复依据；只按新版本人工返工，不自动重发。

Seedream成功同步返回图片可能没有供应商taskId，不能把成功结果误记成无ID不确定提交，也不能伪造taskId。独立性审核此时检查本地任务ID、输入/输出哈希及归属；远端ID去重只检查实际存在的值。XQ5A首版已被用户拒收，返工及生产时间见 `docs/2026-10-08-XQ5A-四条视频返工与生产记录.md`，不视作用户已认可。

任务文件可沿用旧 job 数组，也可给每项加依赖：

```json
[
  {
    "job": {
      "id": "S02-image", "kind": "image",
      "providerId": "company-gateway-qiniuyun-gpt-image-2-medium",
      "model": "qiniuyun/gpt-image-2-medium",
      "input": "refs/P02.jpg", "references": ["keyframes/scenes/selected.png"],
      "prompt": "prompts/image/S02.txt", "output": "keyframes/shots/S02.png"
    },
    "dependsOn": ["scene-3"]
  },
  {
    "job": {
      "id": "S02-video", "kind": "video", "providerId": "company-kling-2-5",
      "model": "kling-2.5", "durationSec": 5,
      "input": "keyframes/shots/S02.png", "prompt": "prompts/video/S02.txt", "output": "clips/S02.mp4"
    }
  }
]
```

- 引用同一队列或台账内其他任务的输出路径，自动建立依赖并要求审核；`dependsOn` / `requiresReview` 可补充显式依赖，两者都要求被依赖任务审核通过。**复制为 selected.png 等新路径后，要显式写原场景任务 ID**，不能仅靠路径推断。原始实拍、裁图等外部输入由 agent 在入队前检查。
- 视频可用 `tailInput` 指定工程内尾帧路径；与首帧、参考图一样参与依赖与审核门禁、路径检查和内容指纹。尾帧必须生成并审好后才提交；尾帧内容改变会使旧审核失效，并阻止已有任务按旧指纹恢复。
- 快分镜审好即生成对应视频，不等其他候选；返工用新 ID、新提示词文件和新输出路径，随时追加。失败任务本轮只报 `attention`，不会自动重新付费生成。修复网络后重启 worker 复用已保存的远端 ID。
- 10-08按用户要求，新批次**总并发默认50**，图片/普通视频/Seedance池上限均为50，三类共享总共50个名额，不是150个；取消旧2/2/1的额外低上限。队列支持1–50，配置见 `scripts/reassembled-film/defaults.json`；工程可用 `queue/config.json` 覆盖。旧工程记录保留实际用过的并发，新工程不要复制旧3/2/2/1覆盖新默认。50是本地调度能力，上游是否限流及实际提速尚待新批次实测。预算默认图视频累计40元未因并发改变，仍按公司配置估算，**不是实际账单**，不含TTS。
- 图片估价按张；视频按请求时长折算本工具已有估价：可灵 2.5 ¥1.52／5秒、七牛可灵 3.0 ¥3／5秒、Seedance 2.0 ¥2／4秒、2.5 ¥7.6／4秒。七牛可灵10秒预占¥6，超预算在供应商调用前拒绝。历史台账已冻结的 `estimateYuan` 保持原值，恢复不重新计价；这些工具估价不等同于实际账单或工作台用量页的统一单价。
- worker 持有 `review/generation.lock`，只由它写台账；入队写独立原子文件。锁存在则拒绝第二个 worker；异常退出留下的锁须先确认原进程已退出，再清理，不能见锁就删。Ctrl+C 停止接收新任务并排空当前任务，未返回 ID 的提交始终按不确定状态处理。
- `run` 不带 `--watch` 会处理当前能运行的任务后退出，等待审核/依赖时退出码 2，错误为 1。`--watch` 持续接收新任务，每 0.5 秒检查本地队列；远端轮询仍为 10 秒。状态文件的时间与 `worker` 字段用于辨认是否仍在运行。
- 提交前把任务与输入内容指纹、估算预算写入台账。已有 ID 只轮询；没有 ID 的不确定提交禁止自动重发；输出落盘中断可按预写 SHA256 恢复。新任务重放会检查输入和输出哈希。历史任务没有旧指纹，只能检查现有文件与记录大小，不能倒推历史内容已被证明。

旧入口 `scripts/reassembled-film-generate.mjs PROJECT jobs.json 3` 保留，只适合明确已完成前置审核的独立任务列表/历史重放；**没有动态依赖审核，应优先使用新队列**。

## 四种开场与独立包装

G064计时中总并发3、普通视频最多2，是等待原因之一；图片单任务最长9.70分钟、可灵最长4.41分钟，另有审核衔接延迟。不能把整个44分15秒归为并发问题。用户随后明确允许50并发，下一批按总上限50执行，保持预算及付费重试边界；未跑真实上游前不记为50并发产能验证。增加独立素材后需重新测时与估价，旧的共享素材耗时不能直接外推。
