# 打包、桌面运行与快启脚本 参考

> 从 `AGENTS.md` 下沉的实现细节。**改打包脚本、快启脚本或 Electron 桌面壳前读这里。**
> 用户侧的 macOS 安装/卸载/数据位置说明见 `MACOS.md`。

## 终端用户快启脚本与 Windows 免安装包

终端用户快启脚本（非开发用途）：`start.command` / `stop.command`（macOS 网页版）、`start-desktop.command` / `stop-desktop.command`（macOS 桌面版）、`start-windows.cmd`（Windows 桌面版：Electron 壳 + standalone 生产构建，经 `scripts/start-desktop-windows.ps1`）、`stop-windows.cmd`（Windows 桌面版与 sidecar 的统一停止入口）；Windows 网页版入口是 `scripts/start-windows.ps1`（dev server + 浏览器，默认 3000 端口）。Windows 桌面启动脚本优先使用 `node-runtime\node.exe`（免安装包内置的便携 Node 22，gitignored；与包内预编译 better-sqlite3 的 ABI 绑定），缺失才回退系统 Node 并试加载原生模块做版本硬校验。Windows 免安装包由 `scripts/build-windows-portable.ps1 -OutputPath <新目录>` 装配：正式模式固定在 Windows x64 + Node 22 上先跑 `npm ci --include=dev`，确认包内 Node 为 ABI 127 且能加载 `better-sqlite3` / `sharp`，再重建 Next/Electron；之后只复制运行时脚本白名单，递归阻断嵌套 `.env*` / `config.yaml*` / 数据库与密钥副本，在同盘临时目录生成 manifest 后改名发布，目标已存在拒绝覆盖。成品 `portable-manifest.json` 为 schemaVersion 1 / `windows-portable-v1`，记录 appVersion、builtAt、sourceCommit 与关键文件 size/SHA-256；`start-windows.cmd` 固定传 `-Portable` 并在启动前逐项复核。免安装模式只认包内 `python-runtime/`（便携 Python 3.12.10 + LiteLLM 1.89.2，gitignored），损坏时提示重新复制，禁止联网修复、禁止回退 `.venv-litellm` 或系统 Python；`-Rebuild` 在免安装模式直接拒绝。

0.6.0 起成品根还包含 `迁移旧版数据.cmd`：它用 `%~dp0.` 传包根，隔开目录末尾反斜杠与闭合引号，保证中文/空格路径不会把 `"` 污染进 `NewRoot`；随后经 `scripts/migrate-portable-data.ps1` 选择旧包根目录并停止可确认归属的新旧进程树，再由 `scripts/migrate-portable-data.mjs` 使用 SQLite Online Backup 复制 `data/workbench.db`、清空副本中的 `job_logs` 并 `VACUUM`、复制 `storage`（排除顶层 `logs` / `run`）、修复 `image_assets.path/originalPath/processedPath` 与 `video_jobs.localVideoPath` 的旧绝对路径、跑 `quick_check` 并写迁移报告。目标 `data` / `storage` 非空时 fail closed，旧目录永不修改。`lib/storage-url.ts` 另提供只读兼容：若旧绝对路径不在当前根，但当前 `storage` 存在相同安全相对文件，项目缩略图仍可解析。

`portable-manifest.json` 只强校验 Node、Electron、LiteLLM、配置与启停脚本等运行必需文件。`使用说明.txt` 等可编辑文档仍随包交付，但不进入强校验；补充联系人等文字不得禁用公司网关。

Windows 完整装配曾在最终目录改名时出现暂时拒绝访问。发布现在只对同父目录 `.portable-staging-*` 普通目录执行 `Directory.Move`，每次检查目标不存在；可恢复的 I/O/访问异常最多尝试 10 次，总等待 7.5 秒，超限仍失败并沿用暂存清理。`windows-portable-publish.test.mjs` 用真实短进程固定当前目录验证占用释放后恢复、持续占用有界失败与不覆盖；完整 QA 装配实际触发四次重试后成功。具体历史占用进程未定位，这不是对所有 ACL 或磁盘故障的修复。

0.7.0 的配置扫描允许可选的 `CREATIVE_STUDIO_CANVAS_ENABLE=0|1` 与 `CREATIVE_STUDIO_CANVAS_EXECUTOR=disabled|company`；画布开启时必须使用 `company`，禁止分发 fixture 执行器。模型白名单另允许 `doubao-seedream-5-0-pro-image`；旧版不含这些可选配置时仍可通过校验。

### 分发自定义运镜模板

自定义模板是用户数据库中的内容，复制程序或迁移接收者自己的旧数据库不会带上作者的模板。不要靠分发作者的 `data/workbench.db` 解决：其中还有项目与密钥。

- 正式装配可显式追加 `-MotionTemplatesSourceRoot <作者数据根>`：只导出 `isBuiltin=0` 的 ID、名称、描述、提示词及随机池选择，随包附带 JSON、导入脚本与中文入口，并纳入 manifest 和敏感值扫描。未指定时不导出任何用户内容。
- 给已领取程序的用户补发：运行 `node scripts/export-motion-template-presets.mjs --source-root <作者数据根> --output <新补充包目录>`，将该目录的内容压缩后分发。产物不进 Git，不含作者数据库、项目、供应商配置或脚本知识库。
- 接收者先完成旧数据迁移，并至少启动一次新版工作台，正常退出后将补充包内容解压到程序根，双击 `导入自定义运镜模板.cmd`。入口使用包内 Node 和 `%~dp0.`，支持中文/空格路径。
- 导入先做 SQLite Online Backup，再在事务中新增缺失模板；同 ID / 同名内容保留接收者现有版本并报告冲突，重复导入不产生副本。随机池选择按作者数据保留。补充包不替换程序或 manifest，适用于已有的 0.6.2 及以上免安装程序。

## standalone 产物与资源同步

`npm run build` 通过 `scripts/build-production.mjs` 在 `.cache/production-build-*` 内构建。目录只接收源码白名单与已安装的 `node_modules`（优先硬链接，禁止目录链接到项目外），不复制 `.env*`、本机数据库、素材、交付目录或 Python 环境。这样 Next 16.2 的动态文件追踪不会扫描用户积累的大量运行数据；`outputFileTracingExcludes` 仍是必要的负载边界，但单靠它无法限制编译阶段的扫描。Next 的项目根与追踪根显式设为当前构建目录。

编译和类型检查成功后，将 Turbopack 生成的带哈希外部包 junction/symlink 转为真实目录，避免临时目录清理或安装位置变化后原生模块失联；再替换原 `.next`，在原项目目录执行资源同步、禁入检查及构建戳写入。同步失败回滚原产物；Windows 目录暂时占用有界重试，回滚受阻时保留旧产物备份。构建锁阻止同一项目并发构建，异常退出留下的锁只在原 PID 已不存在时清理。临时构建目录在正常退出时清理；`.cache` 不参与项目 TypeScript 检查。增加新的源码顶层目录时须同步维护 `BUILD_DIRS` / `BUILD_FILES`；依赖必须已安装，构建过程不联网安装。

编译 worker 的 `CREATIVE_STUDIO_DATA_ROOT` 指向临时目录，不能继承桌面启动器传入的真实用户数据根。运行成品时仍按启动器提供的数据根读取项目。构建期间检测到受监视源码更新会保留旧产物并要求重新构建，避免把过期快照标记为最新。

- Next 16 Turbopack 的 `instrumentation.js.nft.json` 不经过普通路由的排除过滤；`next.config.ts` 在 `compiler.runAfterProductionCompile` 中按同一禁入清单过滤它，必须发生在 standalone 复制前。否则本地临时文件消失会触发 `copyfile ENOENT`，后置 sync 清理无法补救。守护测试同时覆盖复制前过滤和复制后清理，不能只检查配置数组。

- `next.config.ts` 使用 `output: 'standalone'`，并通过 `outputFileTracingExcludes` 排除数据/文档/脚本目录；禁入清单单一来源是 `scripts/packaging/forbidden-paths.json`（next.config.ts、`sync-standalone-assets.mjs`与各自守护测试共用，改清单只改 JSON）；`ffmpeg-static`、`ffprobe-static` 在 `serverExternalPackages` 中，由 `scripts/sync-standalone-assets.mjs` 强制拷入 standalone（`npm run build` 会自动执行）；sharp 的原生运行时目录 `node_modules/@img` 同样强制拷入（Next 文件追踪只收录 `.node` 会漏掉同目录的 libvips DLL，导致 `ERR_DLOPEN_FAILED`）。sync 末尾还会把受监视源码（`app/`、`components/`、`lib/`、`runtime/`、`public/`、`types/` 与根级构建配置）的最新 mtime 写入 `.next/standalone/.build-stamp`；Windows/macOS 桌面快启脚本启动前用 `scripts/runtime/build-stamp.mjs check` 比对戳与源码，发现更新即自动重建（依赖清单变化先装依赖），`-Rebuild` / `--rebuild` 保留为强制手段；免安装模式不参与构建，跳过戳比对。

## Windows FFprobe

- Windows 默认 FFprobe 使用 `@ffprobe-installer/ffprobe@2.1.2`，x64 平台包锁定 5.1.0；standalone 同步须包含加载器和 `@ffprobe-installer/win32-x64/ffprobe.exe`。旧 `ffprobe-static` 保留供非 Windows 兼容与历史对照，不能把旧二进制存在当作 Windows 新探针已装配。

## Electron 发版顺序与本地服务状态

Windows 源码桌面入口会检查 Electron、Next、TypeScript 与原生模块的关键依赖文件；即使 `node_modules` 目录仍在，缺件也会执行 `npm ci --include=dev`，避免安装中断仅留下 `.bin` 时跳过修复。免安装模式仍禁止联网安装。

- **关闭窗口确认退出**：X 与菜单退出经 `before-quit` → `desktop:quit-requested` → preload 的 `onQuitRequested` 打开 `Header` 现有「停止服务并退出」弹窗。确认才 POST `/api/shutdown` 停止工作台与受控 LiteLLM，服务退出后桌面壳跟随退出；取消不影响 IPC 或任务。页面挂载前的关闭请求由 preload 暂存，连续点击共用同一个弹窗。需要后台运行时最小化窗口。
- **Electron 发版顺序与本地服务状态**：打包脚本先完成 `npm ci`（除非显式跳过）；若目标 `node_modules/electron` runtime 仍缺失，普通分支再用当前 Node 显式执行 `node_modules/electron/install.js`，随后统一做存在性硬断言，显式跳过分支不自动安装。桌面服务在 `CREATIVE_STUDIO_DATA_ROOT/storage/run/electron-service.json` 记录当前 `http://127.0.0.1:<port>` 与 instance，正常退出时清理；停止脚本必须先校验该状态与 `/api/desktop/health` 的 instance，再有限 POST `/api/shutdown`。
- **外观主题与原生控件**：页面主题由 `html[data-theme]` 驱动，但原生 `<select>` 弹出列表、右键菜单等由主进程 `nativeTheme` 绘制，不吃页面 CSS 的 `color-scheme`。`ThemeToggle` 经 `desktop:set-theme-preference` IPC 把偏好（light/dark/system）推给主进程设置 `nativeTheme.themeSource`；纯浏览器环境则靠 globals.css 的 `:root { color-scheme: light }` 与深色 `option` 配色兜底。该 IPC 通道已纳入 `electron-shell-security.test.mjs` 的白名单断言。
- **`ELECTRON_RUN_AS_NODE` 必须清掉**：开发终端、编辑器或宿主进程可能注入 `ELECTRON_RUN_AS_NODE=1`。继承它会让 Electron 以普通 Node 身份启动，`app` 接口为 `undefined`，桌面壳启动即失败且报错难懂。`start-desktop.command` 在拉起桌面壳前 `unset` 该变量（私有 Node 服务已有独立运行时路径，不受影响）；`start-desktop-command.test.mjs` 守着这一行。新增桌面启动入口时同样要清。

## 红线（这几条同时留在 AGENTS.md）

- 免安装包负载不得含 `data/`、`storage/`、`outputs/`、`docs/`、`scripts/`、`.git/`、`.env*`、`config.yaml`、`.venv-litellm/`、`python-runtime/`；构建脚本的裁剪与断言不许删。
- `python-runtime/` 只进 Windows 免安装包（白名单装配），不进 Git、不进 standalone。
- `stop-windows.cmd` 先优雅停机，再仅对可执行路径/命令行确认属于当前包根的进程调用 `taskkill /T /F`；3000/4000 的未知属主只报告并跳过。
- macOS 构建机必须是 arm64 Node 22.x，主版本或架构不对会让 `better-sqlite3`/`sharp` 的原生模块 ABI 不匹配。
- `scripts/*.ps1` 必须存为 **UTF-8 带 BOM**（PS 5.1 按 ANSI 读无 BOM 中文会解析失败）；`storage/run/stack.json` 则是**无 BOM** JSON。
- 免安装包损坏时只提示「重新复制整个包」，禁止联网修复、禁止回退 `.venv-litellm` 或系统 Python。
- 打包出的 `.app` 不含 `config.yaml` 与 `.venv-litellm/`，所以**公司供应商只在源码运行时可用，安装版永远没有**。

实拍成片免安装入口包含 `scripts/reassembled-workbench.mjs`、`scripts/reassembled-launch.mjs`、`scripts/reassembled-launch.ps1` 与 `dist-desktop/reassembled-navigation.js`，进入装配白名单及 manifest 预检。CLI 按指定数据根发现本机桌面实例，不直接改数据库；Windows `connect` 显式注册当前用户/数据根的专属审片协议，其他命令不自行注册。协议宿主隐藏运行并保持到桌面启动链退出，`-ReviewLaunch` 显式等待 Electron 主进程；sidecar 状态/日志使用独立数据根，自定义数据根无状态时不按端口兜底停止。详见 [实拍成片工作台接入](实拍成片工作台接入.md) 与 [审片启动验收](../2026-10-19-实拍重组审片启动-Windows验收.md)。

Windows 源码 Electron 与免安装 QA 包已完成 A 模板合成 P1 真机闭环、包内运行资源、实际中断恢复与 `-Portable` 启停验收，见 [Windows P1 验收](../2026-10-19-实拍重组P1-Windows验收.md)。随后补齐四模板 × 源码/免安装的 [8 组 P1 重渲矩阵](../2026-10-19-实拍重组P1-Windows四模板验收.md)。QA 包复用已验证生产构建，不代表干净主机安装或正式发包验收。

## 内置模板开箱即用

正式装配可传 `-BundledPresetsSourceRoot <已审核目录>`，仅复制 `motion-template-presets.json` 与 `viral-templates.xlsx` 到包根 `bundled-presets/` 并记录 manifest。模板来自显式提供的文件，不能随包分发作者数据库。

启动时运镜只补缺失的 ID/名称，保留同名、同 ID 的用户内容及随机池选择；爆文库在 Script Studio 安全升级 gate 成功后、接口返回前导入，仅在没有当前库时发布。解析期间若用户已经发布新库，事务内复查并保留用户库。内置文件从 `dataRoot()/bundled-presets` 读取，自定义数据根须一并放置该目录；未提供模板的源码环境不自动导入。

配置扫描兼容历史顶层可靠性参数；新版 `router_settings` 只接受 `num_retries=0 / timeout=110`，不能同时混用顶层参数。模型白名单允许精确别名 `minimax-h3`、`wan-3.0`。

随包运镜与内置模板同名时，只更新那条内置行的文案/描述，保留稳定 ID、开场编号及随机池开关；存在用户自建同名/同 ID 内容时仍不覆盖。避免历史自定义模板转内置后，导入被同名判断全部跳过。
