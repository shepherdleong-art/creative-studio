# 视频包装

包装能力由单条智能混剪和批量生产共用。模板源来自用户提供的 0.5.2 包装测试版，界面与导出编号统一为 f1 花字种草、f2 手账拼贴、f3 极简高级、f4 综艺撕纸，内部模板 ID 不变。

## 使用入口

- 单条：智能混剪 → 预览调整 → 右栏「视频包装」。启用后选择模板、字体，在画面中双击改字，拖动、缩放或旋转标题和卖点；时间线可调整正片卖点。导出自动接续包装任务，失败可重试或明确选择发布原片。
- 新建单条组和首次分配的批量成片默认开启包装；存量配置、显式关闭仍保留。包装主副标题优先跟随脚本封面主副标题，手动包装覆盖优先；单条切换脚本后，仅自动标题跟随，手动标题保留。
- 批量：右侧「包装」与单条统一为开关、四套模板卡、字体与恢复操作，不再显示重复的文案输入表单。正片卖点在时间轴字幕与视频之间：新增、拖动、双边修剪、双击改字、Delete/× 删除；修改后需重新确认。完整配置走 `set_packaging` 乐观锁，复用整包撤销。
- 贴纸：包装卡内「包装设置／贴纸」双页签。贴纸页可按分类与中文关键词筛选四种风格共 115 张内置素材，点击或拖入预览新增；预览可移动、等比缩放、旋转、删除，时间轴可移动/修剪/换轨，动效浮窗可选六种效果并「应用到全部」，正文 ≥144 帧可一键布置六张。单条保存在组级包装，批量保存在各成片版本，编辑会递增修订并清除该片审核。跨片复制只替换目标贴纸与新增默认动效，来源与全部目标在同一事务内校验版本/修订，任一冲突整体拒绝。
- 批量进入「包装」页签时中央预览跟随当前选中成片，双击画内文字、拖动版式直接保存；退出包装页签恢复最上层可见成片播放规则。「跳到封面」关闭素材监看并暂停到封面中点。
- 批量时间轴「精调」与右侧「封面」直接打开同一个 `BatchCoverEditorDrawer`：左侧选素材/截帧，中间显示真实包装封面，右侧同屏提供构图、包装模板和字体。画布「编辑文字」支持双击改字、拖动/缩放/旋转；「移动画面」拖动底图。关闭包装时显示原生主副标题样式。
- 统一封面编辑采用本地草稿，取消不改成片；应用时用一个 `set_cover` 同时提交封面和包装，校验打开时冻结的输出版本/修订，一次递增、一次撤销，失败保留草稿。模板/字体仍为整片共享，正片卖点时序不变，应用封面不会自动调用外部卖点提取。
- 关闭包装保留既有剪辑和原封面配置。批量启用时隐藏原封面文字以免叠字；新建单条混剪默认关闭原封面标题，存量组仍沿用封面编辑器中的「显示封面标题」开关。
- 两个入口都支持画内双击浮框改字（Enter/失焦保存、Esc 取消）。主副标题缺失仅在编辑态显示占位，导出前明确确认；空卖点不显示、不参与命中。两个入口均不再提供重复的侧栏文案表单。

## 存储和模块边界

- `lib/media-core/packaging-*`：配置、文案推导、卖点对时、字体、配色、模板解析、透明预览桥与离线管线。批量只能依赖这里，不得导入 `final-edit`。
- 贴纸领域全部在 `lib/media-core/`：`packaging-stickers.ts`（模型/校验/风格与动效解析）、`packaging-sticker-assets.ts`（按实例解析原图与 SHA-256）、`packaging-sticker-timeline.ts`（轨道/移动/修剪/磁吸）、`packaging-sticker-planner.ts`（一键六张）、`packaging-sticker-variants.ts`（跨片变体）、`packaging-sticker-edit-bridge.ts`（iframe 空间编辑）。素材在 `packaging/stickers/`（原图 + `thumbs/` WebP + `catalog.json` + `runtime.js`），由 `scripts/build-sticker-assets.mjs` 从 `--source` 装配。批量跨片事务在 `lib/batch-production/sticker-copy.ts`。
- 贴纸写入必须校验原始请求：`validatePackagingStickers(raw, bodyFrames)` 拒绝非法实例、重复 ID、越界和超过 128 张；`parsePackagingConfig` 的清洗只用于读取旧数据，不能拿来冒充保存成功。单条与批量入口都在清洗前校验。
- 渲染时 `resolvePackagingStickerAssets` 按模板解析实际原图，`package-video.mjs` 只复制快照用到的 PNG 并逐张校验相对路径与 SHA-256；缺图或哈希异常使导出明确失败，不静默漏图。`stickers/runtime.js` 随模板复制，`stickers/` 已加入 `sync-packaging-assets.mjs` 白名单。
- 贴纸静态资源 `/api/packaging/stickers/[...path] GET` 是登录后可读资源（`route-policy.ts` 的 authenticated 分类），个人本地沿用相同语义；目录穿越、非法扩展名按既有 400/415/404 规则拒绝。
- 内置贴纸的 `assetId` 是 catalog 名称，不是私有素材 ID。团队引用扫描只对包装 `stickers[]` 的该字符串字段跳过资源归属查询；恢复快照和复制目标同样限定精确路径。其他嵌套 ID、项目／版本授权和 CSRF 继续检查，回归见 `team-api-auth-matrix.test.ts`。
- 复制弹窗在打开时冻结来源版本／修订，在首次选中时冻结各目标版本／修订。轮询不能升级已选快照或过滤失效目标后部分提交；来源或任一目标变化均整体拒绝，关闭弹窗重试。事务写前再次校验，整体撤销／重做只恢复贴纸字段。
- 单条配置位于 `final_edit_groups.packagingJson`（追加迁移 v11）。单条任务在入队时冻结文案、字体、布局和卖点，沿既有 worker 执行 `render → packaging → publish`。
- 单条包装发布复用 `registerSingleArtifact`，同时登记项目产物、权限范围和受管文件；仅写 `project_artifacts` 会导致成片预览被拒绝。旧任务的视频接口只为项目所有者/管理员补登任务、项目和路径完全匹配且从未登记的包装产物，不恢复已删除或清理的记录。
- 团队联动包装封面在包装任务目录发布独立版本，保留原文件名，受管旧封面不改字节；个人本地按既有规则更新成片目录的同名 JPG，维持成对取件。worker 在同一事务内登记封面版本、切换 render 的 `publishedCoverRelativePath` 并完成包装任务；失败仅清理本次文件并恢复视频预留，提交后的审片同步失败只告警。实际文件哈希、回滚重试、预览与交付回归见 `team-delivery-publication.test.ts`。
- 批量配置位于输出版本 `arrangementJson.packaging`，无需新增表。`set_packaging` 校验当前输出版本与编辑修订，递增 `editRevision`、清除当前审片确认并参与完整渲染契约哈希；撤销快照也包含包装。
- 批量包装发生在完整渲染的私有任务目录里，正式发布仍走原有谱系、完整媒体核验和并发复查。封面与视频使用同一次包装层，不把没有完成包装的视频当成成功产物。
- 用户字体与扫描缓存位于 `dataRoot()/storage/packaging/`，渲染临时目录也基于 `dataRoot()`。字体按内容寻址，历史/排队快照仍可能引用的文件不做全量删除。
- 团队共用字体放 `dataRoot()/storage/fonts/`，字幕与包装共用扫描根。字幕通过登录后的 `/api/system-fonts/[id]/file` 按需交付字体到客户端 Canvas；目录不返回物理路径。服务账号看不到个人安装字体时，用 `scripts/team-server/import-shared-fonts.mjs` 预检/复制，操作方法见 [11 月 10 日修复记录](../2026-11-10-单条预览配乐字体与成员删除修复.md)。

## 模板和时间契约

- 自动布局 v2 只随新内容或显式「一键布置／重新提取」启用；旧 v1 元素可混用，手动固定位置优先。规范 Chromium 求解实际素材、字体与动画外框，开头／中段自动贴纸和正文卖点完整收进上 40%；无解或超预算不写入候选。
- `packaging-auto-layout-service.ts` 在求解前异步冻结模板、贴纸、字体、脚本、浏览器及依赖；资源清单含画幅，按内容寻址存到 `dataRoot()/storage/packaging/layout-{bundles,engines}`，使用独立副本。并发冻结共享进行中的引擎快照，不能阻塞工作区轮询；引擎清单与文件摘要一起绑定身份。
- 预览的 `packaging-layout-resources` 路由先校验当前成片归属，再校验清单与文件哈希；已发出的 HTML 在同一成片下保留原快照资源授权，避免配置切换中断其字体／脚本加载。导出用同一副本，缺失不回退在线资源。
- v2 解析结果是同修订派生缓存，重算不清审核、不新增撤销；结构变化等新布局完成后换文档，几何、撤销和重算继续走原地同步。跨片复制在事务外预检、事务内重验双方；弹窗命令标识绑定候选，计算失败重试不重新抽取。
- v2 单条原片任务只保留内部视频／封面，包装成功后首次发布并登记完整产物；不能提前登记尚未发布的封面。本地首次封面同样返回路径参与登记与失败回滚，旧版先发布封面和团队独立版本行为保留。
- 批量自动重算服从编辑写锁，失败后由「重试布局」显式重试。预览请求撞上 stale 窗口时，带 `data-packaging-layout-pending` 的占位页在 ready 后只补载一次；真实文档不能因此重载。单条重算时长以含口播倍速的实际成片时长为准。

- 模板位于 `packaging/templates/`，共享静态字体位于 `packaging/fonts/`；历史 `overlay-basic` 仅兼容读取，界面显示上述四套。
- 正式视频保持现有 24fps、20 帧封面契约。`pointCues` 时间使用完整成片时间，包含封面偏移；显式空数组代表不显示正片卖点，不能重新自动填充。
- 批量口播准备复用单条 `media-core/packaging-extraction.ts` 的 AI 提炼入口，项目卖点库优先，无库时 AI 提炼，失败按分句筛选具体卖点；结果随口播快照保存并在重试、分配中复用。批量与单条共用词级优先、字幕兜底的对时规则；旧成片点击「重新提取卖点」更新，读取/预览不静默覆盖手改内容。
- 批量卖点轨道使用正文坐标，显示时减去封面时长、写回时加回一次；首次分配即冻结标题和本地对时卖点，预览与正式导出读取相同配置。
- 三个字体槽：主标题、副标题、卖点；不选择时保留模板原生字体。版式按模板保存，封面用 `cover:title/subtitle/point1…3`，正片用 `cue:<稳定 id>`。
- 预览调整大小时，自动适配必须先恢复模板的 CSS 比例字号，再按当前画幅测量；不能缓存初次计算的像素字号或累乘上次适配结果。正文卖点居中也要保留百分比位移；手动版式仍在适配后重放，窗口缩放不修改配置。
- 透明预览父页面驱动 `window.__timelines.overlay`；编辑桥采用 `elementsFromPoint` 命中。批量消息必须同时匹配同源和当前 iframe 的 `contentWindow`。
- 批量包装文档按实际内容更新，不能将 `editRevision` 放进组件 key 或 iframe URL；位置/缩放/旋转、撤销/复位及保存失败回滚通过模板 `__pointLayout.apply` 原地同步。相同版式的后台轮询不能覆盖拖动草稿；文案、模板、字体、时序和封面来源变化仍重载。
- 包装 iframe 与内部文档都固定 `color-scheme: light`，避免夜间主题使 Chromium 为透明画布补白底。模板颜色保持成片本色；回归见 `scripts/packaging-preview-theme.playwright.test.mjs`。
- 团队版 `/api/packaging/templates/[...path] GET` 属于登录后可读资源，不能列入 `server_disabled`：iframe HTML 与字体、GSAP、贴纸、透明遮罩分开请求，拦截后会出现黑底与错误字体。只开放内置模板及共享字体，`fonts/user/` 在团队版仍返回 404；真实授权链回归见 `team-api-auth-matrix.test.ts`。
- 统一封面的 `POST packaging-preview` 只返回草稿 HTML/文案，不写成片配置；同源 `srcDoc` iframe 的消息目标使用父页 origin（它自己的 `location.origin` 是 `null`）。未修改的旧封面标题不会作为空值覆盖提交，避免改变自动文案来源。
- 导出从实际首帧取色；单条预览从封面素材帧、批量预览从受控素材缩略图近似取色。素材不同帧或裁切可能造成配色差异，最终以导出为准。
- 包装封面取封面时段中点；结束前模板会淡出，不能用「封面结束减一帧」合成 JPG。
- 固定渲染命令传 `staticCover: true`，四模板第 0–19 帧完整静止，第 20 帧隐藏封面层；此时 `coverSec` 保留精确的 20/24 秒。工作台调用不传该开关，维持原退场。
- 最终叠加以底片为时长依据：`overlay=0:0:format=auto:eof_action=pass:repeatlast=0`。透明 WebM 的尾部时间戳不得延长底片；透明层先结束时保留后续底片。真实包装测试同时检查解码帧数。
- 单条与批量的包装封面共用 `media-core/cover-compose.ts`，先写临时 JPG 再原子替换；旧 `final-edit/cover-compose.ts` 仅兼容再导出。
- 2026-10-13 的 §20 对齐以用户提供版本的**部署根** `packaging/` 为模板与素材权威源；其 `_src` 镜像仍有同步欠账，不能反向覆盖。目标源码与 `.next/standalone/packaging` 经构建同步；验收详见 [逐文件对齐记录](../2026-10-13-视频包装逐文件对齐与验收.md)。

## 离线运行和发布

开发机首次准备运行资源：

```powershell
npm install
npm run setup:packaging
npm run build
```

HyperFrames 固定为 `0.8.134`，Chrome headless shell 固定为 `152.0.7977.30`。工作台与 [固定渲染命令](固定渲染命令.md) 共用这一份运行时。运行时位于 `packaging/runtime/chrome-headless-shell`，依赖和浏览器不入 Git。安装准备命令会下载组件；工作台渲染阶段禁用自动安装和遥测。

Next 文件追踪通过统一 `forbidden-paths.json` 的 `nextStandaloneExcludes.extra` 排除整个 `packaging/`；随后 `sync-packaging-assets.mjs` 按白名单复制模板、静态字体、锁文件、管线、依赖和浏览器。禁止夹带上传字体、扫描缓存、渲染目录及密钥。缺运行资源时构建明确失败，不能发布缺组件的安装包。

`CREATIVE_STUDIO_PACKAGING_DIR` / `CREATIVE_STUDIO_PACKAGING_NODE` 可覆盖资源和 Node 路径；FFmpeg/FFprobe 沿用应用变量。Windows 子进程隐藏控制台，停机杀本任务进程树，外层总超时 10 分钟。

Windows 的旧 `ffprobe-static` 在嵌套匿名管道中可能卡在输出尾部。包装专用 `win-hide-spawn.cjs` 对 ffprobe 将输出写临时文件、退出后回放，保留退出码、错误流和超时；不能用吞错误或伪造时长代替媒体核验。

2026-10-16 真实素材对照确认文件中转不能消除旧 4.0.2 的全部收尾超时。Windows 默认路径已改为锁定的 `@ffprobe-installer/ffprobe@2.1.2`，包装管线启动子进程时显式传入共享解析器返回的 FFmpeg/FFprobe 路径（2026-10-19 补齐此前缺失的传递，避免子进程回退旧探针，见 [四模板 P1 验收](../2026-10-19-实拍重组P1-Windows四模板验收.md)）；非 Windows 选择逻辑保持原样。详见 [FFprobe 稳定性与 P0 收尾](../2026-10-16-FFprobe稳定性与P0收尾.md)。

## 验证

### 贴纸生产目录验收

使用独立 standalone 和临时数据根，不连接用户实例。两份编辑器脚本设置下列变量后，会继续执行正式渲染、媒体探针、抽帧和下载校验；批量还导出两个复制目标，核对 ZIP manifest 的大小和 SHA-256。

```powershell
$env:STICKER_TEST_STANDALONE='I:\独立生产目录'
$env:STICKER_TEST_EVIDENCE_DIR='I:\验收证据目录'
$env:TEMP='I:\验收临时目录'; $env:TMP=$env:TEMP
node scripts/packaging-stickers-editor.playwright.test.mjs
node scripts/batch-stickers-editor.playwright.test.mjs
# 团队入口在新的隔离数据根创建管理员、员工并走正式登录／CSRF：
$env:STICKER_TEST_TEAM='1'
node scripts/packaging-stickers-editor.playwright.test.mjs
node scripts/batch-stickers-editor.playwright.test.mjs
```

服务 cwd 固定到生产目录，清空 `NODE_PATH`，资源和媒体工具从该目录解析，阻断外网。`sticker-production-guard.cjs` 另对 Node 文件 I/O 和模块加载阻断源码回退（同步、异步、流及复制入口）；这是进程级回归守卫，不是操作系统权限隔离。测试驱动仍在源码中运行。

目录验证逐项读取 115 张原图、115 张缩略图及运行时，并核对生产文件和 catalog 哈希。运行时经模板路径 `/api/packaging/templates/overlay-poster/stickers/runtime.js` 读取；贴纸资源接口不开放 `.js`。团队 fixture 必须同时登记实体归属和受管文件，不能用空权限上下文代替正式授权。

## 成片编号与文件名

新导出在项目基础名后拼接脚本 j 编号、实际首段的开头提示词 k 编号、实际包装 f1/f2/f3/f4，例如 `20261014-X店-型号-AI种草-剪辑师-j1k2f1.mp4`。同一组合再导出追加 `-02`、`-03`，封面使用相同基础名。单条与批量共用目录预留防覆盖；已有历史产物不改名。旧大写 J/K 与 A/B/C/D 快照兼容读取，新导出统一规范化。

共享编号规则位于 `media-core/production-codes.ts`。k1=自然生长、k2=手放家居、k3=纸箱爆炸、k4=毛坯房变身；后台可改编号，创建视频任务时冻结到 `video_jobs.openingCode`。旧 NULL 视频仅按明确内置模板 ID 兼容；空串表示当时没有编号。普通运镜、无出处的外部素材不猜 k 编号。包装关闭不加 f 编号，单条失败后「发布原片」重新预留去掉包装编号的文件名，保留 j/k。

单条渲染快照保存 `exportIdentity.productionCodes`；预览消费服务端按实际时间轴首段算出的编号。独立包装任务使用所选模板编号重新预留名称，历史无导出身份的独立包装继续兼容「-包装」。专项测试见 `scripts/production-codes.test.ts`。
