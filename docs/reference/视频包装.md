# 视频包装

包装能力由单条智能混剪和批量生产共用。模板源来自用户提供的 0.5.2 包装测试版，保留 A 花字种草、B 手账拼贴、C 极简高级、D 综艺撕纸四套设计。

## 使用入口

- 单条：智能混剪 → 预览调整 → 右栏「视频包装」。启用后选择模板、字体，在画面中双击改字，拖动、缩放或旋转标题和卖点；时间线可调整正片卖点。导出自动接续包装任务，失败可重试或明确选择发布原片。
- 新建单条组和首次分配的批量成片默认开启包装；存量配置、显式关闭仍保留。包装主副标题优先跟随脚本封面主副标题，手动包装覆盖优先；单条切换脚本后，仅自动标题跟随，手动标题保留。
- 批量：右侧「包装」与单条统一为开关、四套模板卡、字体与恢复操作，不再显示重复的文案输入表单。正片卖点在时间轴字幕与视频之间：新增、拖动、双边修剪、双击改字、Delete/× 删除；修改后需重新确认。完整配置走 `set_packaging` 乐观锁，复用整包撤销。
- 批量进入「包装」页签时中央预览跟随当前选中成片，双击画内文字、拖动版式直接保存；退出包装页签恢复最上层可见成片播放规则。「跳到封面」关闭素材监看并暂停到封面中点。
- 批量时间轴「精调」与右侧「封面」直接打开同一个 `BatchCoverEditorDrawer`：左侧选素材/截帧，中间显示真实包装封面，右侧同屏提供构图、包装模板和字体。画布「编辑文字」支持双击改字、拖动/缩放/旋转；「移动画面」拖动底图。关闭包装时显示原生主副标题样式。
- 统一封面编辑采用本地草稿，取消不改成片；应用时用一个 `set_cover` 同时提交封面和包装，校验打开时冻结的输出版本/修订，一次递增、一次撤销，失败保留草稿。模板/字体仍为整片共享，正片卖点时序不变，应用封面不会自动调用外部卖点提取。
- 关闭包装保留既有剪辑和原封面配置。批量启用时隐藏原封面文字以免叠字；新建单条混剪默认关闭原封面标题，存量组仍沿用封面编辑器中的「显示封面标题」开关。
- 两个入口都支持画内双击浮框改字（Enter/失焦保存、Esc 取消）。主副标题缺失仅在编辑态显示占位，导出前明确确认；空卖点不显示、不参与命中。两个入口均不再提供重复的侧栏文案表单。

## 存储和模块边界

- `lib/media-core/packaging-*`：配置、文案推导、卖点对时、字体、配色、模板解析、透明预览桥与离线管线。批量只能依赖这里，不得导入 `final-edit`。
- 单条配置位于 `final_edit_groups.packagingJson`（追加迁移 v11）。单条任务在入队时冻结文案、字体、布局和卖点，沿既有 worker 执行 `render → packaging → publish`。
- 批量配置位于输出版本 `arrangementJson.packaging`，无需新增表。`set_packaging` 校验当前输出版本与编辑修订，递增 `editRevision`、清除当前审片确认并参与完整渲染契约哈希；撤销快照也包含包装。
- 批量包装发生在完整渲染的私有任务目录里，正式发布仍走原有谱系、完整媒体核验和并发复查。封面与视频使用同一次包装层，不把没有完成包装的视频当成成功产物。
- 用户字体与扫描缓存位于 `dataRoot()/storage/packaging/`，渲染临时目录也基于 `dataRoot()`。字体按内容寻址，历史/排队快照仍可能引用的文件不做全量删除。

## 模板和时间契约

- 模板位于 `packaging/templates/`，共享静态字体位于 `packaging/fonts/`；历史 `overlay-basic` 仅兼容读取，界面显示上述四套。
- 正式视频保持现有 24fps、20 帧封面契约。`pointCues` 时间使用完整成片时间，包含封面偏移；显式空数组代表不显示正片卖点，不能重新自动填充。
- 批量口播准备复用单条 `media-core/packaging-extraction.ts` 的 AI 提炼入口，项目卖点库优先，无库时 AI 提炼，失败按分句筛选具体卖点；结果随口播快照保存并在重试、分配中复用。批量与单条共用词级优先、字幕兜底的对时规则；旧成片点击「重新提取卖点」更新，读取/预览不静默覆盖手改内容。
- 批量卖点轨道使用正文坐标，显示时减去封面时长、写回时加回一次；首次分配即冻结标题和本地对时卖点，预览与正式导出读取相同配置。
- 三个字体槽：主标题、副标题、卖点；不选择时保留模板原生字体。版式按模板保存，封面用 `cover:title/subtitle/point1…3`，正片用 `cue:<稳定 id>`。
- 预览调整大小时，自动适配必须先恢复模板的 CSS 比例字号，再按当前画幅测量；不能缓存初次计算的像素字号或累乘上次适配结果。正文卖点居中也要保留百分比位移；手动版式仍在适配后重放，窗口缩放不修改配置。
- 透明预览父页面驱动 `window.__timelines.overlay`；编辑桥采用 `elementsFromPoint` 命中。批量消息必须同时匹配同源和当前 iframe 的 `contentWindow`。
- 统一封面的 `POST packaging-preview` 只返回草稿 HTML/文案，不写成片配置；同源 `srcDoc` iframe 的消息目标使用父页 origin（它自己的 `location.origin` 是 `null`）。未修改的旧封面标题不会作为空值覆盖提交，避免改变自动文案来源。
- 导出从实际首帧取色；单条预览从封面素材帧、批量预览从受控素材缩略图近似取色。素材不同帧或裁切可能造成配色差异，最终以导出为准。
- 包装封面取封面时段中点；结束前模板会淡出，不能用「封面结束减一帧」合成 JPG。
- 单条与批量的包装封面共用 `media-core/cover-compose.ts`，先写临时 JPG 再原子替换；旧 `final-edit/cover-compose.ts` 仅兼容再导出。
- 2026-10-13 的 §20 对齐以用户提供版本的**部署根** `packaging/` 为模板与素材权威源；其 `_src` 镜像仍有同步欠账，不能反向覆盖。目标源码与 `.next/standalone/packaging` 经构建同步；验收详见 [逐文件对齐记录](../2026-10-13-视频包装逐文件对齐与验收.md)。

## 离线运行和发布

开发机首次准备运行资源：

```powershell
npm install
npm run setup:packaging
npm run build
```

HyperFrames 固定为 `0.8.21`，Chrome headless shell 固定为 `152.0.7977.30`。运行时位于 `packaging/runtime/chrome-headless-shell`，依赖和浏览器不入 Git。安装准备命令会下载组件；工作台渲染阶段禁用自动安装和遥测。

Next 文件追踪通过统一 `forbidden-paths.json` 的 `nextStandaloneExcludes.extra` 排除整个 `packaging/`；随后 `sync-packaging-assets.mjs` 按白名单复制模板、静态字体、锁文件、管线、依赖和浏览器。禁止夹带上传字体、扫描缓存、渲染目录及密钥。缺运行资源时构建明确失败，不能发布缺组件的安装包。

`CREATIVE_STUDIO_PACKAGING_DIR` / `CREATIVE_STUDIO_PACKAGING_NODE` 可覆盖资源和 Node 路径；FFmpeg/FFprobe 沿用应用变量。Windows 子进程隐藏控制台，停机杀本任务进程树，外层总超时 10 分钟。

Windows 的旧 `ffprobe-static` 在嵌套匿名管道中可能卡在输出尾部。包装专用 `win-hide-spawn.cjs` 对 ffprobe 将输出写临时文件、退出后回放，保留退出码、错误流和超时；不能用吞错误或伪造时长代替媒体核验。

## 验证

配置/对时/配色、单条工作区、批量剪辑编辑/撤销/渲染契约测试沿用 `scripts/*.test.ts`。新增：

- `packaging-render.test.ts`：四模板真实透明渲染、包装封面、音轨、H.264、24fps、时长。产物写入忽略目录 `outputs/packaging-render-verification/`。
- `packaging-probe.test.mjs`：Windows 嵌套同步/异步探针、中文路径、错误保留和临时目录清理。
- `packaging-assets.test.mjs`：发布白名单和个人数据排除。
- `packaging-preview-scale.playwright.test.mjs`：四模板封面与正文卖点在 180/360/720/1080px 预览下保持比例，覆盖默认及保存的位移、缩放、旋转版式；隔离浏览器运行，不依赖用户数据库。
- `review-packaging-source.playwright.test.mjs --cover-only`：真实组件/包装模板的统一封面入口、改字/版式、拖动底图、换素材/截帧、取消、一次保存和失败草稿保留；`--shortcuts-only` 验证单条/批量共享快捷键弹窗。后端原子性、冲突、隔离及整包撤销由 `batch-output-clip-edit.test.ts` 覆盖。

当前真机验证为 Windows。macOS 的浏览器安装、签名和最终 DMG 需要在对应构建机验证；这里不将 Windows 通过视为跨平台通过。

## 成片编号与文件名

新导出在项目基础名后拼接脚本 J 编号、实际首段的开头提示词 K 编号、实际包装 A/B/C/D，例如 `20261014-X店-型号-AI种草-剪辑师-J1K2A.mp4`。同一组合再导出追加 `-02`、`-03`，封面使用相同基础名。单条与批量共用目录预留防覆盖；已有历史产物不改名。

共享编号规则位于 `media-core/production-codes.ts`。K1=自然生长、K2=手放家居、K3=纸箱爆炸、K4=毛坯房变身；后台可改编号，创建视频任务时冻结到 `video_jobs.openingCode`。旧 NULL 视频仅按明确内置模板 ID 兼容；空串表示当时没有编号。普通运镜、无出处的外部素材不猜 K 编号。包装关闭不加字母，单条失败后「发布原片」重新预留去掉包装字母的文件名，保留 J/K。

单条渲染快照保存 `exportIdentity.productionCodes`；预览消费服务端按实际时间轴首段算出的编号。独立包装任务使用所选模板字母重新预留名称，历史无导出身份的独立包装继续兼容「-包装」。专项测试见 `scripts/production-codes.test.ts`。
