# 界面外观规范（林视界面重设计）

改配色、令牌、字体、共用部件，或者新增一屏界面之前先读这一篇。**唯一需求依据**是 [林视界面重设计功能方案](../superpowers/specs/2026-11-07-林视界面重设计-功能方案.md)（下称「规格」）的「外观规范」与「小窗口与画面尺寸」；令牌的**取值以 `app/globals.css` 为准**，本文只解释读代码读不出来的部分。

尺寸验收（不横向滚动、控件不被切掉、画面比例）是另一条线，见 [`界面尺寸验收.md`](./界面尺寸验收.md)。

## 令牌：一份来源、两套取值

浅色是默认值，写在 `app/globals.css` 的 `@theme {}` 里（Tailwind 4 会把它们变成 `--color-*` 等 CSS 变量）。深色只在 `html[data-theme='dark']` 里**覆盖取值**，不新增令牌名。

| 分组 | 令牌 |
| --- | --- |
| 窗口底 | `--color-window` |
| 内容区 | `--color-content` / `--color-surface` |
| 悬停底 | `--color-surface-subtle` / `--color-surface-hover` |
| 卡片 | `--color-card` |
| 侧栏（浅色不透明、深色半透明） | `--color-sidebar` |
| 分组底 / 预览区底 | `--color-group` / `--color-preview` |
| 表格斑马 / 进度条轨道 | `--color-zebra` / `--color-track` |
| 分段按钮底 / 选中块 | `--color-seg` / `--color-seg-on` |
| 正文 / 次要 / 三级 | `--color-ink` / `--color-ink-secondary` / `--color-ink-tertiary` |
| 分隔线 / 细分隔线 | `--color-hairline` / `--color-hairline-soft` |
| 强调（只有一个蓝） | `--color-accent` / `-hover` / `-foreground` / `-solid` / `-solid-hover` |
| 状态文字 + 淡底 | `--color-run` / `ok` / `fail` / `warn` / `idle` / `check`，各带 `-tint` |
| 状态点 | `--color-dot-ok` / `dot-fail` / `dot-warn` / `dot-run` / `dot-idle` |
| 媒体预览底与控制 | `--color-media-background` / `-foreground` / `-control` / `-control-border` / `-scrim` |
| 时间线重复分组（浅深共用语义） | `--color-review-1…8` 与各自 `-tint`（在 `@theme static` 里） |
| 圆角 | `--radius-pill` / `--radius-card` / `--radius-tile` / `--radius-control` |
| 字号 | `--text-body`(13.5px) / `--text-label`(12px) / `--text-input`(13px) |
| 字体 | `--font-sans` / `--font-mono` |

深色下还额外覆盖 `--color-canvas-grid-dot`（画布点阵）与 `color-scheme: dark`。`--color-review-*` 的深色取值在 `html[data-theme='dark']` 块开头，因为它们在 `@theme static` 里没有深色版本。

**红线：新增界面颜色一律引用上表令牌，不要写死浅色值。** 存量硬编码浅色值的深色覆盖只补丁、不扩散。这条有静态契约测试守着：`scripts/ui-14-dark-appearance-contract.test.mjs`、`scripts/ui-appearance-tokens.test.mjs`，以及浏览器端的 `scripts/ui-appearance-browser.playwright.test.mjs`。

## 字号三档与等宽数字

- 正文 `--text-body` 13.5px；工具栏副标题、行内小字、标签用 `--text-label` 12px；输入框 `--text-input` 13px（小于 13px 在 Windows 上会挤）。
- 时长、金额、计数一律加 `.tnum`（`font-variant-numeric: tabular-nums`），数字跳动时列宽不抖。

## 字体：打包切片，构建期不联网

- 中文字体族名是 **`Lins Sans SC`**，不是 `Source Han Sans`。字形仍是思源黑体，改名是 OFL 保留字体名条款（Reserved Font Name）对子集改动的强制要求——**代码里写 `Source Han Sans` 会让字体静默回退到系统字体**。
- `app/fonts.css` 由 `scripts/ui/build-font-slices.py` 生成，**不要手改**。它声明 11 个 `@font-face`：5 个中文 UI 频次片（`lins-sans-ui-1…5`）+ 5 个 GB2312 兜底片（`lins-sans-gb-1…5`）+ 1 个拉丁片（`inter-latin`）。每片带 `unicode-range`，浏览器只下载页面实际用到的切片。
- 字体文件都在 `public/fonts/`，两份许可证 `OFL-Lins-Sans-SC.txt`、`OFL-Inter.txt`；`slices.json` 记录生成参数与每片的字符数/字节数。
- **构建期不联网下载字体**（公司网络受限）。重新生成切片用 `python scripts/ui/build-font-slices.py`，源字体在 `packaging/templates/classic/1/assets/fonts/SourceHanSansCN-VF.ttf`（源文件名可以叫 Source Han Sans，落地族名必须是 `Lins Sans SC`）。
- 字体要能随 standalone 产物与 Windows 免安装包一起发布；打包禁入清单的断言不变。`scripts/final-edit-font-effective.playwright.test.mjs` 与导出前的 `assertFontsEffective` 都是这条红线的守卫。

## 共用部件 API

颜色之外，所有界面都从 `components/ui/` 取部件，不要各页自己写一套壳。签名以源码为准，常改的几个：

```tsx
// components/ui/Appearance.tsx
<PageToolbar title={...} subtitle={...} actions={...} back={{ label, onClick }} />
<ToolbarButton icon="plus" variant="primary" onClick={...}>新建项目</ToolbarButton>
<ToolbarButton icon="search" label="查找" onClick={...} />        // 只有图标时必须给 label
<GroupList><GroupRow label="…" hint="…">{控件}</GroupRow></GroupList>
<GroupHeading action={...}>分组标题</GroupHeading>
<Segmented value={…} options={[{ value, label }]} onChange={…} label="…" size="small" semantics="tabs"|"toggle" />
<Tag tone="ok|warn|fail|run|idle">…</Tag>
<StatusDot tone="ok|warn|fail|run|idle" label="…" />
<EmptyState title="…" description="…" action={…} icon="sparkle" />

// components/ui/Dialog.tsx
<Dialog open title="…" description={…} footer={…} onClose={…} width="default"|"wide">…</Dialog>
```

`Dialog` 已经负责遮罩、圆角卡片、Esc 关闭与焦点收束；业务逻辑留给调用方。图标统一走 `components/ui/Icon.tsx`（唯一图标族），**不要另起一套图标**——需要新图标就加进那个文件。

## 每页工具栏约定

团队版每一页的标题由外壳统一渲染（`components/team/WorkspacePageHeader.tsx` 按 `lib/workspace-navigation.ts` 的导航名解析）。页面自己挂 `<PageToolbar>` 时：

1. 用 `<PageToolbar title={…}>`，**删掉页内自己的 `<h1>`**；
2. `page-toolbar-claim.ts` 会登记占用，外壳那条自动让位，所以过渡期不会出现两条工具栏。

标题文案从 `workspacePageTitle()` 取，不要在页面里再写一份标题表。

## 侧栏与窄窗口收法

- 侧栏宽度单一来源是 `components/team/workspace.module.css` 的 `--workspace-sidebar-width`（宽窗口 224px），主区靠 `margin-left` 让位。**不要另写一份宽度。**
- 宽度小于 1280 时侧栏收起（规格「小窗口与画面尺寸」）。**收法尚未定稿**：三种实现同时存在，由 `components/team/narrow-window.ts` 的 `resolveNarrowStyle()` 选择，可用 `?narrow=icon|hover|drawer` 临时试用；默认 `icon`（规格原文的「图标窄条 + 悬停显示名称」）。用户选定后要删掉另外两套与那个试用开关——见 15 号票 Comments。
- 混剪的「素材调整」在窄窗口下默认收起，由 `components/mixcut/MixcutShell.tsx` 按 `(max-width: 1279px)` + `html[data-deployment-mode='server']` 判定。**个人本地版不受影响**（8 月为小屏监看定的破格宽度是故意设计）；只看当前显示、不写进布局记忆，避免把用户自己的折叠选择永久改掉。

## 深色与三态切换

- 三态（浅色/深色/跟随系统）由 `html[data-theme]` 驱动：令牌覆盖在 `html[data-theme='dark']`，偏好存 `localStorage["creative-studio-theme"]`，水合前初始化脚本在 `app/layout.tsx`，切换按钮 `components/ThemeToggle.tsx`，桌面壳原生主题同步在 `desktop/theme.ts`。**存储键不得改名**。
- 混剪与批量两个 CSS module 各自带暗色覆盖块（它们不在 `app/globals.css` 的令牌体系里，只能补丁存量）。
- 新增深色适配时优先改令牌取值；确实要覆盖组件类，才写 `html[data-theme='dark'] .your-class {}`。

## 改外观之后的必做检查

```bash
node scripts/ui-appearance-tokens.test.mjs            # 令牌定义与深色覆盖的静态契约
node scripts/ui-14-dark-appearance-contract.test.mjs  # 深色下没有写死浅色块
TEAM_ACCEPTANCE_UI_SCREENS=<你那一屏> node scripts/ui-acceptance.playwright.test.mjs  # 尺寸验收
```
