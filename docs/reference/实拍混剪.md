# 实拍混剪 参考

> 改 `lib/live-mixcut/`、`app/live-mixcut/`、`app/api/live-mixcut/`、`components/live-mixcut/` 任何东西前读这里。

## 一句话边界

实拍混剪是**独立模块**：自己的任务、表、迁移流、调度器、API 与四步页面，不关联工作台的 `projects`。`lib/live-mixcut` 只从 `media-core/` 等共享层取能力，不 import 批量生产或 `lib/final-edit`；`components/live-mixcut` 不 import `components/batch-production`。

## 模块地图

| 位置 | 职责与约定 |
| --- | --- |
| `lib/live-mixcut/projects.ts` | 任务增删改查；创建任务时同时创建首批，软删除保留制作记录与文件 |
| `lib/live-mixcut/batches.ts` | 任务内多批次、复制已确认输入、素材说明、人工原声/区间、外部配音与生成设置；不复制成片与制作历史 |
| `lib/live-mixcut/schema.ts`、`schema-v1-sql.ts`、`readiness.ts` | 独立迁移流与共享升级 gate；初始结构已生成，后续迁移只能追加 |
| `lib/live-mixcut/formula/` | 素材与脚本导入、原声识别、选片、声音、时间线、制作设置与导出清单 |
| `lib/live-mixcut/runner.ts`、`bootstrap.ts` | 持久化后台任务与启动恢复；停机顺序为停领取 → 中止在途 → 排空 |
| `app/live-mixcut/` | 任务列表与四步任务页：准备素材 → 脚本与口播 → 检查成片 → 导出成片 |
| `app/api/live-mixcut/` | `projects/` 是界面“任务”的 CRUD；`tasks/` 已用于后台任务，不能混用；其余接口沿用复制来的结构 |
| `components/live-mixcut/` | 复制来的批量审片与编辑界面；保留 `BatchXxx` 命名，方便与批量对照同步 |

## 开关与火山识别

- 只有 `CREATIVE_STUDIO_LIVE_MIXCUT_ENABLE=1` 时才建表、起后台任务、开放接口并显示顶部导航；关闭时不触碰数据根中的模块结构。
- 火山识别配置由 `asr-provider.ts` 合并：设置页数据库优先、`CREATIVE_STUDIO_VOLC_ASR_API_KEY` 环境变量兜底，显式停用不回退环境变量。Resource ID 默认 `volc.seedasr.auc`，按账号授权选择。本地音频转 WAV 后以 base64 提交；密钥不进日志或制作快照。
- 制作请求冻结识别服务身份；后来补配 ASR 需「修改输入 → 生成」新一轮。SeedASR 的空白字词占位可能带 `-1` 时间，适配器仅过滤空白；真实台词仍需完整、有限、有效的时间。错误只展示适配器定义的安全文案，不回显上游任意响应头。
- 火山 HTTP 成功且状态码 `20000003` 是明确的「未检测到人声」结果：记录服务身份与状态依据，进入后续声音编排，不标为配置失败或人工确认。普通空响应、缺字词时间、鉴权和网络失败仍阻塞；详见 `docs/2026-10-26-原声无人声状态与选片流程诊断.md`。

## 表格识别与受阻恢复

- 第一步素材整理也必须显式启动：空批次即显示模型选择，初始不选默认模型；导入、刷新、换模型和修订说明都不自动调用 AI。用户点击「开始整理」才处理未完成项，停止后可换模型再继续，已保存及人工说明保留。
- 内容分析分「根据文件名整理」与「分析视频画面」两路，均写入追加式素材说明，生成时冻结确切版本。画面入口只列视觉模型，核验受控原片后经 `media-core` 抽帧；保留人工说明，不把抽帧观察冒充原声识别或已确认动作区间。
- 选片 `/5` 保留公式编号顺序与人工指定/轮换优先级；同编号有多份时以有效说明和脚本的内容重合排序，无差异仍稳定选取。缺片分析纳入 AI 命名/画面说明并保留证据来源；完全未知的缺号仍不可猜测，可在「去处理」窗口逐镜明确指定替代。
- 第二步导入前就显示模型选择；读入 XLSX 不自动调用 AI，由用户点击识别。识别中更换模型或点「停止识别」会取消旧会话；服务端推进草稿修订并中止本进程请求，迟到结果不能覆盖新模型或人工修改。原表、已确认资料和预览保留。
- 声音等阶段失败但还未生成时间轴时，第三步使用制作进度的真实原因显示「需处理」及可重试任务，不把已完成选片等同于排片完成，不伪造静音或占位时间轴。
- 从制作进度进入人工原声核对时，必须传递 `planId`，按该输出最新选片及内容指纹限定原片；显示脚本/份数、编号、文件名与本次检查原因，优先定位需处理项。GET/PUT 回读保持同一范围，不混用其他输出的识别结果；人工保存仍遵守输入冻结和下一轮生效契约。
- 声音编排歧义从「去处理」进入逐段用途核对，显示实际台词和对应原片试听；原文拆段/合并不改写，明确确认后通过 `manual-audio` 追加单条制作修订。不得自动认定不同台词等价，或默默把正常文案全部设为备注。

## 任务、表与用量

- 代码里的 `projectId` 是**任务 ID**，指向 `live_mixcut_projects`，不是工作台 `projects.id`。一个任务可以有多个批次；`projects.batchId` 只记录首批、供界面默认选中，不再影响导出目录。新建默认复制当前批次的已确认输入与生成设置，也可创建空白批次；归档只影响默认列表，不删除数据或成片。
- 表名使用 `live_mixcut_` 前缀，索引使用 `idx_live_mixcut_` 前缀；不要写回批量 `batch_` 表。
- 配音用量传 `projectId: null`，模型用量不传 `projectId`，不要挂到旧项目账本。
- 任务名在创建时按「日期-店铺-型号-实拍混剪-剪辑师」自动生成（见 `lib/live-mixcut/naming.ts`），同日同身份重名追加 `-02`、`-03`。导出目录名即任务名，创建后不再改；任务改名不改变目录名。
- **包装代号不进任务名**：它在第二步「声音和包装」随机或指定（`lib/live-mixcut/formula/production-settings.ts`），到第四步导出时由实际渲染结果带进成片文件名（`脚本N-第NN份-f1` 等，见 `media-core/export-identity.ts`）。创建任务时不要要求填写包装代号。
- 切换「随机分配包装」默认勾选全部可用模板，用户可缩小候选范围。保存和回读保留随机模式，即使只选一套也不改成统一；单候选会提示所有成片使用同一模板，生成后仍冻结每条实际分配结果。

## 导出

一个任务只有一个 `storage/live-mixcut/exports/<任务导出目录>/成片/`，不再按批次分子目录；所有正式视频、配对封面与 `清单.csv` 都放这里。「同一条」按冻结导出身份（原脚本号、份次、包装）的文件名认，不管来自哪个批次：首次导出不带后缀，再导出叫 `-v2`、`-v3`，上一版的视频和封面挪进同级的 `旧版/`，`成片/` 只留当前这一套。清单按整个任务写，只列 `成片/` 里的当前版本；旧版不列。清单记录原脚本号、素材与源区间、人工偏离、声音、包装及文件校验值；先写临时文件再改名，写清单失败只记日志，不影响已导出成片。目录由 `resolveLiveMixcutBatchExport` 统一解析，发布、工作区、清单和打开文件夹不得各写一份路径；晋级和归档由 `lib/live-mixcut/batch-export.ts` 统一做，正式产物记录的路径随归档同步更新。

## 多批次回归

- `node scripts/live-mixcut-batches.test.ts`：复制/空白批次、最新素材说明及原表依据、人工原声与区间、外部配音身份、归档恢复、REST 归属校验及共享成片文件夹与任务级清单；只用临时数据。
- `npm run build && node scripts/live-mixcut-batches.playwright.test.mjs`：隔离数据根的真实生产模式浏览器流程，覆盖默认复制、空白创建、搜索切换、刷新记忆、归档与恢复。测试启动独立端口的生产服务，结束自动清理。
- 本模块全部单元测试：`node scripts/live-mixcut-port/run-tests.mjs scripts/live-mixcut-*.test.ts`（每个测试用独立临时数据根）。
- 内容流水线：`scripts/live-mixcut-content-pipeline.test.ts`（素材整理两条路径、同编号内容排序、受阻恢复）。
- 浏览器测试（均不需要真实数据；文件名即运行命令，看各自文件头）：`live-mixcut-import`、`live-mixcut-material-model`、`live-mixcut-manual-speech`、`live-mixcut-packaging-settings`、`live-mixcut-content-recovery`。

## 和批量生产的关系

审片编辑器及其后台编辑、渲染、素材预览能力是从批量复制的独立副本，批量生产本身保持 main 的实现。修改批量编辑器时，要逐项判断是否需要同步到实拍混剪；不要通过 import 把两份后端重新耦合。
