# 单条素材分析

首次生成、组内重新分析和旧素材重新分析入口共用 `lib/final-edit/asset-analysis.ts`。它负责媒体探测、内容指纹、分析缓存判断、结果结构校验及完整分析记录的写入。

## 两种意图

| 意图 | 缓存 | 分析失败 |
| --- | --- | --- |
| `prepare`：生成成片前准备素材 | 仅复用指纹、供应商、模型、分析版本一致，且结果结构有效的成功记录 | 写入失败记录，返回降级分析，让原准备流程继续处理 |
| `refresh`：用户明确重新分析 | 始终调用分析适配器 | 抛错，保留原分析记录 |

两者都先读取并探测媒体；读取或探测失败直接报错，不调用 AI，也不更新记录。旧素材路由此前先调用 AI 再探测，现在与工作区一致，避免对不可读取的素材发出无效分析请求。

成功记录一并保存媒体时长/尺寸、指纹、供应商/模型、分析版本和生成结果，并清除旧错误。人工标注与禁用自动使用的设置仍保留。重新分析不修改时间线、字幕、审核或其他剪辑状态。

## 入口仍负责的事情

- 工作区继续按项目与分镜组验证归属、筛选素材，并检查原分析供应商；分析后封面候选抽帧仍属于准备流程。
- 旧素材路由保留指定供应商不可用时选择首个可用视觉供应商的兼容逻辑，以及原成功响应和 400/404/409 错误形式。不能把这一回退套到组内重新分析。
- 输入文件路径由入口的受控素材解析得到；分析模块不绕过归属与路径检查。
- 实拍返工写入的 `rework-metadata/1` 是媒体元信息记录，不属于本轮 AI 分析流程，仍由返工模块负责。

`FINAL_EDIT_ANALYZER_VERSION` 在分析模块定义，工作区保留再导出，兼容既有调用。没有修改已发布迁移或提高分析版本号，已有有效缓存仍可复用。

## 验证

`scripts/final-edit-reanalyze.test.ts` 调用真实分析模块和旧路由处理函数，以内存数据库、临时文件和模拟探测/AI 验证缓存、恢复与错误行为；不再复制产品的成功写入 SQL 自测。

`scripts/final-edit-workspace.test.ts` 保留组内与外部素材恢复、跨上下文拒绝、失败保留旧结果及手工剪辑保护。改动后再运行 `npm run check:main-path` 检查跨步骤数据交接。
