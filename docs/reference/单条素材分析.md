# 单条素材分析

首次生成、组内重新分析和旧素材重新分析入口共用 `lib/final-edit/asset-analysis.ts`。它负责媒体探测、内容指纹、分析缓存判断、结果结构校验及完整分析记录的写入。

准备阶段使用 `media-core/analysis-concurrency.ts` 的 4 路素材分析池；结果按输入顺序交给匹配器，进度按已完成数递增。单项失败停止取新素材，但不取消其他已提交的分析，收完结果并保存成功缓存后才返回首个错误；用户取消或停机仍中断在途任务。取消和执行控制错误不能写成分析失败缓存。单条运行时向抽帧/模型透传取消信号，并为每次调用隔离临时帧目录。已有有效分析缓存仍复用。

分析阶段不再占用整个 prepare 的重媒体租约：只有抽帧与封面截帧占用共享媒体资源；远端模型等待可以重叠。TTS、匹配及预览阶段继续使用原重任务保护。名额不足时单条分析等待原执行请求准入，批量分析保持 deferred 调度语义；不会重试已失败或提交结果未知的调用，也不突破供应商池/成员限额。

## 两种意图

| 意图 | 缓存 | 分析失败 |
| --- | --- | --- |
| `prepare`：生成成片前准备素材 | 仅复用指纹、供应商、模型、分析版本一致，且结果结构有效的成功记录 | 写入失败记录，返回降级分析，让原准备流程继续处理 |
| `refresh`：用户明确重新分析 | 始终调用分析适配器 | 抛错，保留原分析记录 |

两者都先读取并探测媒体；读取或探测失败直接报错，不调用 AI，也不更新记录。旧素材路由此前先调用 AI 再探测，现在与工作区一致，避免对不可读取的素材发出无效分析请求。

成功记录一并保存媒体时长/尺寸、指纹、供应商/模型、分析版本和生成结果，并清除旧错误。人工标注与禁用自动使用的设置仍保留。重新分析不修改时间线、字幕、审核或其他剪辑状态。

## 入口仍负责的事情

- 工作区继续按项目与分镜组验证归属、筛选素材，并检查原分析供应商；分析后封面候选抽帧仍属于准备流程。
- 旧素材路由保留指定供应商不可用时选择首个可用视觉供应商的兼容逻辑，以及原成功响应和 400/404/409 错误形式。不能把这一回退套到组内重新分析。
- 输入文件路径由入口的受控素材解析得到；分析模块不绕过归属与路径检查。
- 实拍返工写入的 `rework-metadata/1` 是媒体元信息记录，不属于本轮 AI 分析流程，仍由返工模块负责。

`FINAL_EDIT_ANALYZER_VERSION` 在分析模块定义，工作区保留再导出，兼容既有调用。没有修改已发布迁移或提高分析版本号，已有有效缓存仍可复用。

共享画面分析器按场景内多个时间点抽帧，避免同机位人物后入镜却只看到前段空镜。每场景最多 12 帧，通常总预算 48 帧；切镜数超过 48 时保持每场景至少一帧。提示词携带每张图所属场景与实际时间；抽帧结果不证明原声或精确动作边界。Luna 实片证据见 `docs/2026-10-26-Luna实片分析验证.md`。

容器时长可能由更长的音轨决定，末尾采样点可能晚于最后一帧时间戳。FFmpeg 此时可以退出 0 却不生成图片。共享分析器检查非空图片是否实际生成；空输出只在同一场景内依次尝试提前 100ms、500ms 和场景起点，去重后最多四次。每次先清除同名旧图片，失败不调用模型；成功后按调整后的取帧位置重新排序图片与时间表。FFmpeg 执行错误和取消直接向上传播，不触发回退。

## 验证

`scripts/final-edit-reanalyze.test.ts` 调用真实分析模块和旧路由处理函数，以内存数据库、临时文件和模拟探测/AI 验证缓存、恢复与错误行为；不再复制产品的成功写入 SQL 自测。

`scripts/final-edit-video-analysis.test.ts` 守护抽帧计划（场景内多点、预算上限、图片与时间对应表）和提示词契约。改动抽帧或提示词后同时跑它。

`scripts/video-analysis-frames.test.ts` 使用真实 FFmpeg 覆盖音轨稍长于视频、单帧短片、正常取帧、遗留图片和取消，只有模型响应被替换。可设置 `VIDEO_ANALYSIS_FIXTURE` 为本地原片路径补充实片验证；不调用真实供应商，不改写原片或工作台数据库。

`scripts/final-edit-workspace.test.ts` 保留组内与外部素材恢复、跨上下文拒绝、失败保留旧结果及手工剪辑保护。改动后再运行 `npm run check:main-path` 检查跨步骤数据交接。

`scripts/analysis-execution-drain.test.ts` 用真实执行台账及模拟传输覆盖一条未知、三条在途成功的场景，防止单项失败把同组调用连带取消为未知。
