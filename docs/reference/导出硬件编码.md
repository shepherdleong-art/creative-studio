# 导出硬件编码

单条智能混剪与批量生产的完整视频导出共用 `lib/media-core/export-video-encoder.ts`。默认优先使用 NVIDIA NVENC（`h264_nvenc`），没有可用硬件时使用 `libx264`。本轮只支持 NVIDIA 硬件编码，其他显卡及 macOS 继续使用 CPU。

## 范围与质量

- CPU 继续负责现有缩放、裁切、字幕、LUT 和音频处理；仅最终视频编码使用 GPU。预览、代理、素材导入转码和封面生成不变。
- 保留 H.264、yuv420p、24fps、AAC 48kHz、MP4 输出契约及现有产物校验、临时文件发布流程。
- NVENC 使用 `preset=p5 / tune=hq / rc=vbr / cq=20 / b:v=0`；CPU 明确使用原先默认的 `preset=medium / crf=23`。CQ 与 CRF 不能按相同数字视为同画质，文件大小与编码字节可能变化；不同机器、驱动和编码器不保证字节一致。

## 探测、回退与停机

- 使用当前 FFmpeg 真正编码两帧，验证编译支持、GPU 和驱动；不能只检查编码器列表。探测不落盘，超时 10 秒，并传递任务 AbortSignal。
- 成功探测缓存 5 分钟，失败缓存 1 分钟；切换 FFmpeg 路径后重新探测。每个任务的探测使用自己的信号，不共享会被其他任务取消的探测进程。
- GPU 正式编码失败后覆盖同一个临时输出，用 CPU 重试一次，进度从零重新报告；GPU 暂停尝试 1 分钟。CPU 仍失败则沿用任务原有失败处理。取消、进程级停机产生的 AbortError 均不触发回退。
- 调用方设置超时时，探测、GPU 编码和 CPU 重试共用原来的总时限。所有 FFmpeg 子进程仍经过 `runFfmpeg`，受统一停机管理。
- 服务进程日志输出 `[export-video] encoder=h264_nvenc` 或 `encoder=libx264`，回退时有固定中文原因提示，不记录输入路径或底层错误内容。

需要排障或对比时，在服务进程环境中设置 `CREATIVE_STUDIO_EXPORT_ENCODER=cpu` 并重启服务，可强制 CPU；删除该变量恢复自动选择。已生成的成片不会自动重编码，新执行的导出任务使用此策略。

## 验证

运行 `node scripts/export-video-encoder.test.ts` 覆盖探测缓存、失败回退、超时预算、取消/停机及真实 GPU/CPU MP4 编码（无 NVIDIA 时自动测试 CPU 回退）。完整链路用 `final-edit-render.test.ts`、`batch-renderer.test.ts` 和 `batch-render-smoke.test.ts` 验证画面、音频、字幕与发布契约。
