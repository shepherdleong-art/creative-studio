**实现要点与红线落实**

- 三类数据分离：`graphJson` 只存编辑定义且有 `schemaVersion`；`currentAssetId`／`activeTaskId`／`nodeEpoch` 等运行投影只在 `creative_canvas_node_states`，客户端提交的图里出现这些字段会以 `runtime_field_not_writable` 拒绝（未知字段同样拒绝，不静默丢弃）。
- 迁移走共享 gate：画布 scope 有自己的备份前缀 `pre-canvas-v1-…`、审计记录、恢复 manifest 校验与中断清理识别；既有 batch／video-gateway／script-studio slug 未变。
- 数据库约束兜底：`UNIQUE(canvasId, requestKey)`；同节点至多一个未结束任务的**部分唯一索引**；一任务至多一个正式输出的唯一索引；输入快照的 `CHECK` 禁止「同时有 assetId 与未解析 upstreamTaskId」等非法组合。
- 复制：服务端重新分配节点身份、映射范围内连线、保留范围外输入引用、固定复制时的 `currentAssetId`，不复制任务／lease／activeTaskId；`snapshotKey` 幂等，重放返回同一结果。跨画布复制明确 403 拒绝（首版不需要）。
- 删除与撤销：删除打 tombstone 并**递增 nodeEpoch**，撤销只清 `deletedAt`（不恢复运行状态、不重置 epoch），因此删除前启动的旧任务永久失去发布权。
- 素材：内容哈希去重、落盘不可变副本（源文件删除后仍可读）、路径经 `resolveStoragePath` + symlink 守卫、视频支持 `Range`（206／416）。
- 开关：`CREATIVE_STUDIO_CANVAS_ENABLE` 默认关闭，关闭时 API 返回 503 `canvas_disabled`，且**不执行迁移、连数据根都不触碰**；`fixture` 执行器只允许在显式标记的临时数据根启用。

- 停机：调度器 `stop()` 先停止领取、再中止在飞任务的 AbortSignal、最后 drain；`gracefulShutdown` 把画布排空接在 SQLite 关闭之前，旧的批量／脚本／FFmpeg／sidecar 行为保持不变（`graceful-shutdown` 回归通过）。
- 用量：eventKey 固定为 `canvas-task:<taskId>:submitted`，同一任务的重试、补下载、查询、复制都不会增加生成调用数；账本异常被完全吞掉，**不可能**把已提交任务改写成失败（本轮实际修到这个缺陷：记账查询抛错曾把提交成功的任务标成 failed）。

### 第三轮：停顿根因与最终数据（2026-09-11）

停顿的定位过程（每一步都有证据，排除了产品侧原因）：

1. 给 harness 加**页面心跳**（每 5 秒一次 `page.evaluate`），并逐步计时每个交互步骤；
2. 结果：停顿期间**页面往返只有 7–50ms**（页面完全响应），而**每个交互步骤最长也只有 200ms** —— 也就是说卡住的既不是渲染器，也不是某个具体操作；
3. 再给心跳加「距上一次心跳的间隔」统计，看到**规律的 15002ms 空洞**与一次 150 秒空洞，同时循环整体仍在推进；
4. 结论：**长观察期间 macOS App Nap／空闲休眠把后台测试进程冻住了**（15 秒正是 App Nap 的定时器合并间隔）。`page.waitForTimeout` 是页面内定时器，也是同一个坑的一部分，已全部改为 Node 侧 sleep；轮次耗时改用单调时钟。
