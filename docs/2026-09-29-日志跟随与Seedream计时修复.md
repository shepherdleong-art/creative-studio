# 日志跟随与 Seedream 计时修复

## 问题与处理

运行日志只取最近 300 条，旧滚动 effect 仅依赖 `logs.length`。达到上限后窗口内容更新而条数不变，滚动逻辑不再执行；列表滚动事件又会在浏览器锚定、布局变化时自动关闭勾选，造成重新开启后再次停下。

`LogViewer` 改为在列表提交后按日志快照、过滤条件、加载状态与勾选状态滚到底部。自动滚动作为明确偏好保持开启；查看历史时取消勾选，再次勾选立即恢复跟随。不会因水平滚动或浏览器布局事件改变开关。

Seedream 5.0 Pro 当前公司通道是同步请求，没有远端任务 ID。适配器新增可选进度回调，发出请求时记录等待开始，随后每 5 秒报告已等待时间，响应返回时报告本次请求耗时；异常结束也记录等待时间。队列接入现有任务日志，生成后继续原有下载与保存流程。同步请求只发送一次，成功/错误/超时均清理计时器，没有伪造远端轮询或进度百分比。

超时补充：取消同步分支硬编码的 120 秒，沿用项目 `timeoutMs`，未提供有效值时默认 600 秒。队列同时传入请求取消信号；日志显示当前超时上限，成功、失败、超时和取消后清理等待计时器与超时计时器。相关假时钟回归验证 120 秒不提前断开、600 秒到点中断、项目自定义 240 秒生效以及主动取消。

## 验证

- `node scripts/log-viewer.test.mjs`：执行实际组件 hooks 和事件处理器，模拟 300 条滑动窗口；修复前在条数不变时跟随断言失败，修复后覆盖首次加载、同条数刷新、浏览器滚动事件、手动关闭、重新开启和过滤切换。
- `node scripts/company-image-adapters.test.ts`：假时钟与延迟响应在修复前捕获等待日志缺失；修复后验证 5/10 秒提示、成功耗时、成功/错误后的计时器清理，以及每次仅一个生成请求。使用假上游，不产生生成费用。
- TypeScript 检查通过；定向 ESLint 无错误，`queue.ts` 有两个原有未使用变量告警。
- 现有 `gateway-task-image` 回归通过；`npm run build` 与 standalone 静态资源同步成功。
- 等正在运行的视频全部结束后优雅重启，关闭端点确认 `pendingTasks=0`；重启后项目页与公司代理健康检查正常。实际浏览器打开 300 条日志，确认自动滚动已勾选、距底部为 0，且显示新版开关说明。
