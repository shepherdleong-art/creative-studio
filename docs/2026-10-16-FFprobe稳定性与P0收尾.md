# FFprobe 稳定性与 P0 收尾

## 处理结果

Windows 默认探针改为锁定的 `@ffprobe-installer/ffprobe@2.1.2`，其 x64 包为 `@ffprobe-installer/win32-x64@5.1.0`（构建标识 `20230213-2296078`）。版本和包完整性进入 `package-lock.json`；standalone 强制复制加载器及本机平台包，Windows 安装负载检查改为验证新路径。保留环境变量优先级，非 Windows 的原有探针选择与回退保持不变。

本轮不更换 FFmpeg 编码器，不增加自动重试，不接受被杀进程留下的 JSON。之前试验的文件句柄和单包解码改动均未保留。

## 复现与排除

失败发生在 RC2C B 模板 `prepare`：旧 `ffprobe-static` 的 Windows FFprobe 4.0.2 已打印流与容器信息，却缺少最外层 JSON 收尾，并最终触发 60 秒超时。

| 对照 | 结果 |
| --- | --- |
| 原 `probeMedia`，八个真实素材循环 | 48 次中 8 次失败 |
| 单一真实素材、原始参数 | 24 次中 5 次失败 |
| 限制线程 / 改控制台继承 | 仍失败 |
| 可读写输出句柄 | 最初 24 次通过，扩大复测后仍失败 3/64，排除为最终修复 |
| 紧凑 JSON / 视频流线程 / 切片线程 | 仍失败 |
| 先解码一包 | 单素材 100 次通过；扩展到八素材仍失败 2/48，排除为最终修复 |
| 新版随包探针，同一真实素材 | 64/64 通过，交替检查元数据与完整解码帧数 |
| 新版随包探针，原八素材循环 | 48/48 通过 |

64 次真实素材回归在修改前失败 5 次；普通合成素材未复现该故障，因此不能用合成测试单独宣称修复。回归脚本支持 `FILM_PROBE_SOURCE` 指向本机失败样本，不将产品视频提交到仓库。

[FFmpeg 4.0.2 源码](https://github.com/FFmpeg/FFmpeg/blob/n4.0.2/fftools/ffprobe.c) 的 `probe_file` 在外层 JSON 收尾前关闭输入和解码器；这与日志停点相符，但本轮没有取得原生线程栈，不声称定位到了某个具体锁。最终依据是同机、同素材、同调用参数更换二进制后的对照。新包来源与平台分发机制见 [上游说明](https://github.com/SavageCore/node-ffprobe-installer/blob/master/README.md)。

复现本机真实素材回归：

```powershell
$env:FILM_PROBE_ROOT = 'I:/m7-studio/outputs/2026-10-16-ffprobe-debug'
$env:FILM_PROBE_SOURCE = 'I:/m7-studio/outputs/2026-10-16-film-followup/RC2C-overlay-review/variants/01/clips/v01-Q2-M03.mp4'

```

其他机器不设置 `FILM_PROBE_SOURCE` 时生成合成素材；它覆盖元数据、帧数与文件清理，但不等同于旧二进制故障的真实复现。原二进制对照可显式设置 `CREATIVE_STUDIO_FFPROBE`，正式运行先清除该覆盖再检查 `doctor` 的实际路径。
