# 预览、开场与画布导入修复

## 行为与原因

1. **全屏**：团队轻客户端之前拒绝全部网页权限，包括 fullscreen。现在只允许可信主页面全屏；旧客户端拒绝或浏览器缺少接口时，用顶层 dialog 铺满窗口，保留播放器及音频图，支持退出和 Esc。
2. **预览尺寸**：单条预览取消 560px/760px 宽度上限，使用中栏全宽；默认高度由 42vh 改为 58dvh，范围为 340–760px。画幅仍等比适配，中栏内容可滚动。
3. **开场**：新建分镜组已有第一张为开场的提示，补充说明它与两种混剪模式的关系。真正的数据缺口在单条匹配输入：现在由当前项目/分镜组的 `shots.indexNum=1` 识别对应视频，先保留合法开场，再分配正文。批量过去只有开场加分，可能被语义高分正文覆盖；改为首镜先选开场角色，规则版本升为 v5。两种模式覆盖短开场接正文、无开场回退、人工锁定和可用性约束。已生成成片不自动重排。
4. **预览恢复**：同一 video 元素 `load()` 后原来没有再次同步时间点，现为每次 metadata 就绪同步当前播放头。恢复钩子增加 loadstart/waiting/stalled/seeking 监测与独立 120 秒上限；成功探测后的媒体请求仍受监测，超时显示重试，换素材取消旧请求。
5. **画布导入**：server 模式仍发送旧 multipart，触发受控上传拒绝。选择、拖入、替换统一经过分片、完整性校验和画布归库回执；本地路径保留。

## 验证边界

测试使用隔离数据库、临时素材与模拟供应商，不产生付费调用。新增测试复现了开场被正文抢占、画布走旧上传入口，以及已加载媒体恢复后丢失时间点；修复后通过。浏览器测试另覆盖原生全屏、被拒后的展开、Esc、挂起请求超时与重试恢复。
