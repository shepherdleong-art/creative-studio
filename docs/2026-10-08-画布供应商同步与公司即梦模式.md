# 画布供应商同步与公司即梦模式

## 问题与修复

画布内测时固定注册 image2-medium 和少量视频模型，未读取主工作台新增的公司图片模型；固定供应商 ID 还可能把用户改成公司协议的即梦行误认成方舟直连。

画布现在读取已启用、有地址和 Key、且协议与精确别名受支持的供应商行，保留用户名称和渠道身份。API 返回当前可选列表，历史能力保留给旧任务；切回画布窗口会更新列表。禁用、改模型或删除供应商不会让任务悄悄换用另一行。

图片补齐七牛 GPT-Image-2 Medium、Seedream 5.0 Pro、Nano Banana Pro/2。Seedream 采用同步 JSON 与持久化结果回执，下载失败可补下载；Nano Banana 发送原生 OutputConfig，参考图强制 COS。清晰度/比例复用主工作台能力表。

视频按设置中的实际型号匹配，包含腾讯可灵 2.5/3.0、七牛可灵 3.0 和公司即梦 2.0/Fast/2.5。可灵 2.5 仅开放 5/10 秒和 1080p。

## 公司即梦

用户在本次会话确认公司 API 使用方舟文档、网关仅负责转接且扩展功能可用。基于该确认，新公司即梦入口复用直连六模式：文生视频、首尾帧、全能参考、智能多帧、智能编辑、视频延长；2.5 还复用样片/固定样片转正式、输出格式、尾帧及来源校验。公司媒体全部走 COS，不回退本机 URL。

能力键增加 `:ark-v1` 合同版本。旧画布/在途任务继续保留历史 images/size 协议；用户在旧节点重新选择模型后启用新模式。新合同使用 `/v1/videos`，原生 content/role/omni/ratio/duration 等字段保留；LiteLLM 普通请求补 prompt/seconds 外层字段，Final 只补空 prompt 以满足代理必填签名，不带原提示词、媒体、时长或比例。

## 验证边界

内存数据库回归覆盖本机五个图片模型、六个视频模型配置，以及改名、停用、Key 清空和旧 ID 改协议。模拟网关回归走 planner → task → adapter → publish，覆盖图片请求、六模式三型号矩阵、COS 门禁与公司 Draft → Final。安装的 LiteLLM 另通过本机 HTTP 替身验证 content、omni、自动时长及 Final 字段透传。

类型检查、相关 ESLint（无错误）、画布供应商/计划器/调度器/恢复与即梦适配器回归通过。生产构建在同盘隔离副本完成；浏览器验收覆盖五个图片模型、公司六模式、切回窗口刷新、样片锁定及 MOV 播放，未发起真实生成请求。构建与浏览器夹具均使用独立数据根，未替换当前运行的桌面产物。

未用真实公司凭据提交计费生成；证据仍为 mapped，真实网关生成效果、各分辨率产物和样片效果需实际使用验收。
