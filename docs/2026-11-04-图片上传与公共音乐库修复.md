# 2026-11-04 图片上传与公共音乐库修复

## 原因与行为

- `TeamFetchBridge` 原先从 `new Request(FormData)` 取出 multipart 头，却把原 FormData 再次交给 fetch 序列化。两次生成的 boundary 不同，导致 BGM 等 multipart 上传解析失败。现在转发同一个已序列化 Request，统一写入 CSRF；管理表单与旧界面共享 token，避免逐首上传时重复轮换 cookie。
- 所有普通项目图片上传入口改用共享 `uploadImages`：server 模式走 `/api/team/uploads` 的创建、分片和 complete；local 模式保留 `/api/upload`。旧 server multipart 拒绝门禁保持。
- team schema 追加 v13，为上传保存图片角色、用途和预处理选项；重试的幂等比较包含这些选项。complete 按原语义生成图片与预处理派生文件，返回预览 URL 和尺寸，不返回服务器绝对路径。场景种子、分镜来源、视频来源、详情页、尾帧和参考图使用同一入口。
- 公共音乐库支持选择文件夹，包含子文件夹；跳过非音频，逐首上传、显示进度、继续处理单首失败，重复文件复用。文件夹总数不受单次 multipart 100 文件限制，每个请求只有一首，每首前端上限 60 MB。
