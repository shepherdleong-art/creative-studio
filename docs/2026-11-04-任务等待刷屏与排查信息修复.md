## 根因与修复

- 图片队列在执行准入前记录 Job started / Calling API。被限额挡住后，deferred 任务被多个 worker 每 100ms 重新领取，导致同一任务反复显示“调用”，实际没有进入发送阶段。
- 图片/视频 deferred 领取按执行记录更新时间至少间隔 1 秒；等待中的任务继续保留调度，释放名额后自动继续。图片的准备日志只在真正进入发送回调时输出，等待原因未变不重复写日志，并在失败/等待时清理 abort 监听。
- 取消尚未发送的任务同时终结 pending/deferred 执行记录，不覆盖已有远端回执；任务列表兼容历史“业务取消、执行仍等待”的数据，筛选与显示一致。
- 团队任务显示制作步骤、项目/画布名称、源文件名和模型；等待原因中文解释，区分个人上限为 0 与名额已满。发送尝试按 intentJournalSeq 计数，不把准入预留计作已传输，也不等同于扣费次数。
- 增加任务搜索与复制排查信息，完整任务/执行编号、模块键、版本移到可展开详情。成员设置明确提示 0 会阻止新生成。
