# 画布缩小后操作区遮挡修复

## 原因与修复

此前允许将生成节点缩到 120 像素，并把整张卡片内容放在可滚动容器中。缩小后，提示词、参数仍占原来的最小空间，生成按钮被推到容器可见区域之外。前一版测试调用 `scrollIntoViewIfNeeded()` 后才检查按钮，不能证明按钮直接可见。

修复为提示词／生成节点的 React Flow 外壳、卡片和内容区共同遵守 `min-height: min-content`；内容区不再整体滚动。节点高度不足时自动撑开，增加的高度仍分给提示词，文字只在文本框内滚动。外壳与卡片同时设定高度下限，使缩放手柄和连线定位也与可见卡片保持一致。素材节点继续使用媒体决定高度的独立规则。

此规则同样适用于旧画布保存的过小高度、模型切换后参数变多，以及任务状态信息增加，无需修改画布数据或数据库结构。

## 复现与验证

命令：`caffeinate -dimsu node scripts/creative-canvas.playwright.test.mjs --suite interaction`。

修复前失败：缩小图片生成节点后，内容区域 y=289、高=98，生成按钮 y=551.5、高=28，明显位于可见内容区之外。加入内容高度下限的临时浏览器样式后，同一用例通过；临时探针随后删除，改为正式样式。

回归检查不再滚动寻找按钮，直接比较操作按钮与内容区、卡片和 React Flow 外壳的矩形边界。覆盖图片／视频节点、刷新恢复、切换到 Seedance 2.5 的较长参数表，同时保留提示词增高、撤销／重做与素材无多余空白的验收。

最终结果：正式生产构建、Playwright `interaction` 和 `editor` 均通过，测试脚本 ESLint 无错误。已目视检查 `outputs/canvas-validation/minimum-height-image-generation.png` 与 `minimum-height-video-generation.png`，缩小后的生成／运行分支按钮均完整显示。无临时布局探针残留。

浏览器使用隔离数据根与 fixture 执行器；Seedance 只注入参数能力，不发送真实生成请求。当前运行窗口未重启。
