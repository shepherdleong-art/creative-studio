## 2. 接入设计（工程适配，非源项目已有）

### 2.1 数据流总览

```
Excel ──导入预览/确认──> 爆文模板库（独立三表，库级不可变修订，指纹幂等）
详情页 ──首次提取（视觉契约 v5，同批输出 标题+factText+详解detail+证据定位）
       ──证据门禁（现有，不放宽）──> 卖点库修订（新增 detailText/detailStatus）
任务创建（productionMode=template_rewrite，模板全文+顺序冻结进 inputSnapshot）
  ──plan：本地编排（合格卖点集 = 证据有效 ∧ 用户保留 ∧ 详解可用；模板结构 source/fallback；
         文风预设本地检测）── 无独立人群分析、无方向轮换、无卖点配额
  ──generate（每模板一个 plan.index，复用并发/恢复/串行保存）：
       筛选(LLM,前600字参考,keep 组ID,降级保留全部) ──持久化──>
       风格分析(LLM,缓存键=内容哈希+模型+提示词版本,降级用预设) ──持久化──>
       首稿(完整参考+风格+结构+白名单+TPL_GEN_HINT) ──>
       字数修正(带当前稿+原约束,≤1) ──> humanize(可选,降级保留) ──> smooth(可选) ──>
       终检字数(超限再修≤1) ──> 残留/完整性检查 ──> 校验(白名单/零引用/相似度/标题) ──>
       标题修复(现有设施,≤2 占余额) ──> 修改说明(首稿 note 优先,有余额才补) ──>
       保存(project_script_revisions, content.templateRewrite 快照, generationPlanIndex 同事务)
  ──结果：对照（LCS 文字差异）、修改说明、编辑、再生成；下游 reader 原样可读。
```

### 2.2 关键契约决策

1. **模板库独立三表**（不进 catalogs 体系）：`script_studio_viral_tpl_libraries`（单行）、`script_studio_viral_tpl_revisions`（库修订，sourceSha256 幂等）、`script_studio_viral_tpl_entries`（条目，含来源模板 ID/类目/名称/标题/参考全文/结构字段及来源/原始列 JSON/来源文件哈希+工作表+行号/内容哈希/可用状态+原因）。理由：catalogs.kind 有 `CHECK(kind IN ('strategy','template'))`，改 CHECK 需重建表；独立表不动既有契约，风险最小。另加 `script_studio_viral_tpl_style_cache`（contentHash+model+promptVersion → analysisJson）。
2. **卖点详解**：`script_studio_selling_points` 追加 `detailText`/`detailStatus`（v10）。视觉契约 v4→v5 同批输出 `detail`。`detailStatus`：missing（空）/ verified（详解中数字与高风险词均能在 factText+evidenceQuote 中找到）/ unverified（否则）。**detailText 只是创作语境，事实仍只来自 factText**；模板改写模式的合格卖点要求 `detailStatus='verified'`；旧库缺详解 → missing，UI 提示重新提取。编辑详解走 `manualEditLibraryRevision` 产生新修订并重算状态。dedupe 合并取首个非空详解。
3. **任务身份**：`productionMode='template_rewrite'` 参与派生 requestKey（与 pain 同机制）；`inputSnapshot.templatePlan` 冻结模板全文快照数组（服务端从条目读取，不信客户端）+ 选择顺序；requestedCount 必须 === 模板数（服务端拒绝矛盾请求）。identity 走现有 inputSnapshot 全量规范化，模板计划自然覆盖。
4. **字数口径**：目标中文字数 = 秒 × 6，容差 ±15%，`cnLen` 只计 CJK；计入标题，不计段名/标点/说明。与现有 `buildScriptDurationBudget` 分开；`durationStatus` 如实计算，UI 明示写作估算，不代表 TTS 时长。
5. **预算**：复用现有 `scriptTextRequestsPerProposal`（默认 8）/标题修复闸门（2）。筛选、风格、首稿、humanize、smooth、字数修复、残留修复、补说明全部计入；可选阶段（humanize/smooth/补说明）reserve 失败即降级跳过并记录；取消信号不被 catch 吞掉。每模板中间态（筛选/风格结果）持久化到 generate 阶段 payload（新增 `mergeStagePayload`），恢复不重新收费。
6. **校验分支**：模板改写模式白名单 = 本模板冻结筛选白名单（不是全库 usableIds）；零引用仍拒绝；无 CTA 强制、无语义审核（`copyCheck.policyVersion='template-rewrite-v1'`，`semanticReview` 如实记 `not_required`）；相似度与标题检查复用现有；参考产品信息残留做确定性 n-gram 重叠检查（连续相同 ≥12 个中文字 → 有余额时定向修复，无余额则该模板失败不保存）。
7. **有意修复的源缺陷**（方案 §4.4）：字数修正带当前稿件；修正保留 TPL_GEN_HINT 原约束；终检修正用冻结白名单而非全量卖点。
8. **供应商参数**：遵现有 adapter 与快照 providerModel；公司 Luna 仅 `temperature=1`，不模仿源项目低温度参数。
