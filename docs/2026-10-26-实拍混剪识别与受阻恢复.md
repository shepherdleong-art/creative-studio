# 实拍混剪识别与受阻恢复

## 问题与修复

- 表格模型选择仅在上传后出现，且上传会直接调用第一个模型。改为导入前可选、导入后显式启动识别；识别中可停止或切换模型。取消接口验证任务和会话归属、推进草稿修订，旧响应不能覆盖新模型或人工修改。
- 真实 SeedASR 响应在中文与产品型号之间包含空白字词，起止时间为 `-1`。原解析器拒绝整段结果。现在只忽略空白占位，保留完整文本并继续严格校验真正台词的时间、长度和对应关系。
- 原声异常此前被覆盖为笼统的人工核对提示。适配器改用固定安全错误，保留格式、时间越界、文字不一致等原因；不展示任意上游响应头。
- 第三步只看选片是否完成，声音失败仍显示「处理中」。工作区现将实际受阻阶段、原因及重试任务交给审片页；没有排片时右栏也展示原因及重试入口，不生成假时间轴。

## 验证边界

- 经用户授权，对同一条约 8 秒原片复测：火山响应成功，返回 28 字文本、22 个字词项，其中一个空格带 `-1` 时间。旧代码复现「逐字时间格式无效」。
- 同一真实响应离线回放：修复后 21 个有效字词，文本内容完整、时间有效；回放没有再次调用供应商。
- 回归覆盖停止后换模型、旧模型迟到结果、跨项目取消拒绝、有效预览保留、空白时间占位、真实台词负时间拒绝，以及声音失败在审片页显示为可重试受阻。
- 类型检查、变更文件 ESLint、导入会话 / ASR / 原声阶段回归、实拍执行回归（含混合配音未配置场景）及 `npm run check:main-path` 通过。
- 隔离生产构建及浏览器导入回归通过：导入前可选模型、上传不自动调用、识别中换模型会停止、迟到结果不能覆盖新模型。浏览器测试使用模拟供应商，未额外上传真实素材。
- 当前桌面仍使用旧生产构建；本次未关闭用户窗口、替换正在运行的构建或自动重跑真实批次。退出后重新运行 `start-desktop.command` 会按源码变化重新构建。
- 这次没有批量重试真实失败任务，也没有人工确认或替换用户台词、镜头与脚本。单条真实响应验证不能代表全部 300 条完成；其余素材编号、原声匹配和配音配置仍须按实际结果处理。
