# 批量素材提取进度与语义降级提示

导入后的「内容分析」原本只走视觉模型，文件名提取是另一条本地路径。文件名接口一次性返回整批结果，未写项目日志；开始生产时的语义匹配失败虽会用关键词兜底，进度卡却直接展示为失败。

## 改动

- 主按钮与素材卡明确标为「AI 画面分析」。文件名提取期间禁用 AI 操作，不显示误导性的「AI 分析中」。
- 文件名提取通过 NDJSON 返回当前素材、已处理/总数及成功/失败数。每条成功回执即时更新素材与已选分析版本；异常断开不能被视为整批成功。原 JSON 调用保持兼容。
- 文件名提取开始、逐条核验与结果、结束写入项目运行日志；AI 分析及语义匹配记录阶段切换和完成，不记录高频百分比与心跳。
- `semantic_fallback` 仍保留失败任务与尝试记录，自动重试上限及分配逻辑不变。日志用 WARN，进度区分等待重试、将用关键词、已用关键词；其他任务错误仍显示失败。
- 保留语义匹配失败的安全分类（连接、鉴权、限流、JSON、矩阵维度等）、句段/场景数量及本轮请求次数，不返回模型原文或凭据。

## 验证

- `batch-filename-analysis.test.ts`：真实 FFmpeg 素材，核验前/保存后进度、去重、部分失败、原有隔离与版本不变约束。
- `batch-filename-analysis-stream.test.ts`：完成前可读进度、中文跨字节分块、断流、错误、旧 JSON 兼容及客户端取消。
- `batch-progress-summary.test.ts`、`batch-semantic-match.test.ts`、`batch-semantic-score-executor.test.ts`、`batch-runner.test.ts`：重试/兜底展示、安全诊断、实际 worker 的 WARN 日志和失败审计状态。
- 全项目 TypeScript 检查及变更模块 ESLint。
- 隔离的本机 Next 开发服务、临时 SQLite 和真实测试视频：浏览器验证中途 1/2、结束 2/2、成功 1/失败 1、成功素材可选；运行日志出现完整 6 条记录。为捕获中途状态，仅在浏览器测试中放慢 NDJSON 交付。截图在 `outputs/batch-feedback-preview/`。

## 边界

没有调用真实付费模型，也未复现他人机器的供应商故障。截图中的旧日志丢失了底层原因，无法反推究竟是哪种供应商错误；更新后再发生时可通过新诊断分类定位。未重新构建桌面安装包。
