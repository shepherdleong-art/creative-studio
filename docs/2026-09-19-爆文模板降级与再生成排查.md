# 爆文模板降级与再生成排查

## 结论

在 `feat/video-bulk-prompt` 分支修复三类问题。排查时工作区干净，原项目数据库只读；真实样本没有加入项目脚本列表。

1. **频繁降级**：截图对应 Gemini 模型为 `gemini-3.8-flash`，通过用户已配置并明确授权的外部网关测试。旧筛选上限 300 token，实测推理已用 284；风格上限 500，推理已用 478/479；润色上限 2000，推理已用 1917。三类响应均捕获 `finish_reason=length` 和不完整 JSON。不是“文案不够好”的评分降级，而是子步骤没有完整结果，只能保留前一稿。
2. **与原文偏离、标题不承接**：风格分析失败时函数提前返回，跳过参考开头/结尾锚点；副标题要求允许泛泛补充任意正文卖点。旧逻辑真实样本复现“久坐追剧腰酸星人 / 双层高靠包全拆洗”。
3. **再生成入口及重复问题**：结果页只有两种模式，模板任务初始化为 standard；模板提交未使用结果页已有的新 action 机制。同模板原有串行传递前稿，但没有最终正文的定向差异修复。本次旧逻辑两条不是逐字相同，但都使用近似的闺蜜霸占沙发开头；不能把这一轮描述为必然复现全文重复。

## 修改

- 模板链各文本子步骤、模板模式标题修复统一保留 8192 token。其余模式标题预算不变；每方案 8 次及任务总请求次数预算不变。保持 temperature=1。
- 风格失败保留原文开头/结尾要求；原文是故事/指南就保留其写法，原文风格优先于文风预设。
- 封面两行围绕同一问题，副标题不混入无关卖点；现有朗读检查同时复核副标题，仅接受 `coverSecondary`，正文和最终标题仍经过原有校验。
- 同模板变体轮换白名单主卖点；最后比较正文的顺序重合与相同开头。重复时共享预算修复一次，修后仍重复不保存该条；修复后再次检查参考成句残留。该检查是确定性文字近似检查，不等于完整语义原创性保证。
- 结果页支持“爆文模板改写 → 挑选模板再生成”；条数从模板份数汇总，复用最新已加载的卖点修订。每次提交新 key，同一次不确定提交重试复用冻结 key/body。
- 执行器版本 24 → 25，模板提示词版本 v1 → v2；保留历史 v1 数据兼容，不迁移旧脚本。

## 真实样本

只读同一商品卖点、同一“这款多功能实木沙发，闺蜜来我家直接霸占不走了”模板，15 秒目标，按生产 generator 串行生成两条；随后运行生产标题修复、标题和正文校验。未通过浏览器创建真实任务，未执行真实数据库保存或 TTS。

- 旧逻辑两条共记录 9 个已返回响应，6 个 JSON 无效。另有上游超时，不计入已返回响应数。
- 修复后生成两条共 12 个已返回响应，全部有效 JSON，筛选/风格/去 AI 味/朗读四类降级字段均为空；第二条触发了最终差异化修复。
- 随后追加 1 次标题修复响应，JSON 有效。两条最终标题问题、正文问题、字数提示均为空。
- 第一条封面：“闺蜜来我家霸占沙发 / 双层高靠包托颈松腰”，正文主讲腰颈支撑。
- 第二条封面：“闺蜜来家横躺赖着 / 六十公分大座深随便窝”，正文主讲盘腿与横躺空间。

原始响应、token 用量及最终两条内容保存在本地 gitignored `outputs/2026-09-19-template-diagnosis/` 的 `baseline.json`、`fixed.json`、`fixed-validated.json`；`live-probe.ts` 为本次诊断工具。文件中不含 API Key。样本只证明本次一个商品/一个模板的表现，不保证所有模板永远无降级或语义重复。
