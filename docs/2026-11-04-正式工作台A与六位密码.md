### 现场部署兼容问题与处理

- Windows PowerShell/.NET 解压受长路径限制，改用旧版已带的 Node/unzipper 解压已核验 ZIP 到新 release 目录。
- Python 探针会因解压后的时间戳重新生成 `.pyc`，触发发布清单防篡改校验。仅从原 ZIP 恢复缓存，探针进程设置 `PYTHONDONTWRITEBYTECODE=1` 后通过；没有修改 manifest 或绕过哈希校验。
- 旧版首次部署没有 `current-release.json`，按已核验旧版 manifest 初始化旧指针，再执行受控切换。Node 模块类型警告经 WinRM 被当作终止错误，本次维护进程设置 `NODE_NO_WARNINGS=1` 后续跑。
- 现场 LocalService 下 WinSW 在应用主动退出时报告 SCM 访问被拒绝，包装器仍显示 Running。受控升级在 `start_maintenance` 和 `resume` 阶段各按依赖顺序停止 Caddy、停止 App、启动 App、启动 Caddy 后继续完成。没有扩大服务账号权限；该包装器退出状态问题仍需在后续运维版本修复，下一次升级需注意，不能只凭 SCM 的 Running 判断应用健康。
