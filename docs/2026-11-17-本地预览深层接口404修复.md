# 本地预览深层接口 404 修复

## 现象与根因

`127.0.0.1:3410` 的混剪页面出现 `MixcutPanel.tsx` 的 `HTTP 404` 未捕获异常；批量审片停在“正在载入成片安排”，素材与封面为空。

现场确认进程使用当前仓库的 Next 16.2.7 开发服务。源码中存在的 270 个 API 路由，有 29 个未进入 `.next/dev/types/routes.d.ts`，包括单条混剪 external-assets、批量 arrangement 和 media。请求返回框架 HTML 404，尚未进入团队授权层。触发 app 目录文件事件后全部路由恢复，原请求成功；这与 Next 上游记录的[首次扫描竞态](https://github.com/vercel/next.js/issues/96139)及[动态子路由漏注册](https://github.com/vercel/next.js/issues/97894)表现一致。

另一个前端缺陷放大了错误：`Promise.all` 的数组元素内先 `await fetch`，导致前面的 `readJson` 已拒绝时，后面的请求尚未完成，整个聚合尚未接管拒绝，触发 unhandledRejection。

## 修复

- 本地预览启动及复用入口增加 API 路由完整性检查。发现缺项时，在 app 下写临时非路由文件触发补扫，确认完整后才打开浏览器；等待最长 30 秒，成功与失败均清理临时文件。保留原生监听，不修改 Next 依赖、源码内容、权限规则或业务数据。
- 混剪上下文请求改为立即交给 `Promise.all` 的 fetch Promise，统一接管 HTTP 失败、网络失败及取消。

## 验证

- 修复前两个回归分别捕获 `HTTP 404` 未处理拒绝和深层接口框架 404。
- `node scripts/dev-route-readiness.test.mjs`：部分扫描恢复、就绪时无多余触发、超时及清理、源码保留通过。
- `node scripts/mixcut-context-loading.test.ts`：快速 HTTP 失败、网络失败、取消均不产生游离拒绝。
- `node scripts/local-preview-routes.test.mjs`：270 个源码 API 路由完整，单条素材和批量安排/媒体接口均到达认证边界，匿名请求为 401。
- `node scripts/team-mixcut-context-route.test.ts`、TypeScript noEmit 和修改文件 ESLint 通过。
- 真正重启后日志显示“接口路由已就绪：270 个（已自动补全首次扫描）”，本机 4410 网关就绪。原项目的批次 3 恢复素材、封面、字幕、约 20 秒成片安排和预览视频；视频 readyState=4，浏览器错误日志为空。
