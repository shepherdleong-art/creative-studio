# 无限画布：公司模型接口核对

> 产品口径更新（2026-09-09）：当前范围见[创作画布 PRD](superpowers/specs/2026-09-09-infinite-canvas-prd.md)。本文接口研究和案例依据保留；下文“历史结果在原节点查看”等产品表述已被“只保留当前结果，需要保留时复制整个节点”替换。

研究日期：2026-09-08。本文记录官方接口资料与画布接入判断，未发起模型生成、上传素材或修改供应商配置。

项目沿用已经存在成功案例的「工作台 → 本机 LiteLLM → 公司网关 → 平台」链路，并以腾讯云 COS 交付参考素材。下面的原生接口用于核对能力和字段语义；公司兼容接口的实际请求仍应以项目适配器、转发实现与已有成功记录为准。

## 一、腾讯云 VOD：已明确的合同

本次用户提供的是 **云点播 VOD，产品编号 266**。创建接口使用 `vod.tencentcloudapi.com`、版本 `2018-07-17`，需要点播应用 `SubAppId`。这些字段属于平台原生协议，不能直接替换工作台已经使用的公司兼容协议。[创建图片任务](https://cloud.tencent.com/document/product/266/126240)、[创建视频任务](https://cloud.tencent.com/document/product/266/126239)

### 1. 图片模型与输入

| 模型 | VOD 原生标识 | 输入合同 |
| --- | --- | --- |
| Image2 三档 | `ModelName=OG`；`image2_low` / `image2_medium` / `image2_high` | `FileInfos` 可省略；无图时必须提供 `Prompt`。参考图上限表没有列出 OG 的具体数量。 |
| 可灵图片 3.0 | `ModelName=Kling`；`ModelVersion=3.0` | 参考图最多 1 张。 |
| 可灵图片 3.0-Omni / O1 | `ModelName=Kling`；`3.0-Omni` / `O1` | 两个版本均最多 10 张参考图。 |

以上数量只针对**生图**，不能套给同名视频模型。OG 的多图上限缺项不等于不支持多图；已有实测能力继续保留，不从其他模型的数量反推上限。[创建图片任务：ModelVersion、FileInfos、Prompt](https://cloud.tencent.com/document/product/266/126240)

OG 的 `ExtInfo` 还公开了自定义 `size` 与透明背景参数；自定义尺寸的总像素范围为 655,360–8,294,400。文档关于 16 整除的措辞及示例需要结合现有尺寸实现核对，本文不新增宽、高必须各自如何取整的结论。[创建图片任务：ExtInfo](https://cloud.tencent.com/document/product/266/126240)

### 2. 视频输入语义

创建视频任务明确列有 `Kling 3.0`、`3.0-Omni`、`O1`。`FileInfos` 定义了下列模式，但文档同时要求按具体模型版本核对支持范围。[创建视频任务](https://cloud.tencent.com/document/product/266/126239)

| 模式 | VOD 表达 | 明确限制 |
| --- | --- | --- |
| 首帧 / 首尾帧 | 图片 `Usage=FirstFrame` / `LastFrame` | 首尾各最多 1 张；可以只有首帧，不能只有尾帧；生成比例参考输入图。 |
| 参考生成 | `Usage=Reference` | 接口可表达图片、视频、声音参考；参考模式可以设置输出比例；这里没有给出各可灵版本的完整数量及组合上限。 |
| 视频编辑 | 传入视频，可配参考图片 | 创建接口列明 Vidu、Kling 可进行视频编辑；具体版本仍需核对。 |

图片输入通用限制为不超过 10 MB、JPEG/JPG/PNG。旧字段 `LastFrameUrl` 另写了小于 5 MB 的限制，不应把两种输入表达的要求混为一条。[创建视频任务：FileInfos、LastFrameUrl](https://cloud.tencent.com/document/product/266/126239)

数据结构还区分 `Category=Image/Video/Audio`；可灵视频的 `ReferenceType=feature/base` 分别表达特征参考和待编辑视频，`KeepOriginalSound` 控制视频原声。**这些是通用输入结构，不能证明每个模型都接受所有媒体。** [AigcVideoTaskInputFileInfo](https://cloud.tencent.com/document/product/266/31773#AigcVideoTaskInputFileInfo)

腾讯计费表分别列出 3.0-Omni、O1 的有参考视频档位，支持「VOD 有对应能力」这一判断；计费档位不能替代输入数量、文件时长、音频组合的合同。[VOD 账单模型档位](https://cloud.tencent.com/document/product/266/42048)

### 3. 输出参数

| 对象 | 已公开参数 |
| --- | --- |
| OG 图片 | `Resolution=1K/2K/4K`；`OutputImageCount=1–8`。 |
| 可灵图片 | 3.0 为 `1k/2k`；3.0-Omni、O1 为 `1k/2k/4k`；`OutputImageCount=1–9`。 |
| 图片通用 | `AspectRatio` 按模型枚举；Omni/O1 另有 `auto`；`OutputFormat=jpeg/png`。OG 输入另有 `ReferenceType=mask`。 |
| 可灵视频通用表 | `Duration=3–15` 秒，默认 5；`Resolution=720P/1080P`；文生比例 `16:9/9:16/1:1`。这里是模型族表，不能据此扩展所有版本。 |
| 音频与存储 | `AudioGeneration` 是输出声音开关；`StorageMode=Temporary/Permanent`，临时产物 URL 有效期 7 天。 |

来源：[图片输出及输入结构](https://cloud.tencent.com/document/product/266/31773#AigcImageOutputConfig)、[视频输出结构](https://cloud.tencent.com/document/product/266/31773#AigcVideoOutputConfig)。完整比例枚举以源表为准。

视频分辨率有资料差异：上述类型表只列 720P/1080P，但现行计费说明另有可灵 3.0/3O 原厂 4K 的开放说明。画布不能仅看到 4K 计费项就把公司路由标成已支持；也不能据旧枚举宣称平台绝无 4K。[VOD 现行计费说明](https://cloud.tencent.com/document/product/266/95125)

### 4. 创建、查询与重复提交

创建图片、视频均先返回 `TaskId` 和本次 `RequestId`。`SessionId` 最长 50 字符，同码在 3 天内再次提交会返回错误；省略或空串不去重。它不承诺重复请求自动拿回原任务 ID。[创建图片任务](https://cloud.tencent.com/document/product/266/126240)、[创建视频任务](https://cloud.tencent.com/document/product/266/126239)

`DescribeTaskDetail(TaskId)` 可查询最近 3 天提交的任务；顶层状态为 `WAITING/PROCESSING/FINISH/ABORTED`，图片、视频结果分别在 `AigcImageTask`、`AigcVideoTask`。[查询任务详情](https://cloud.tencent.com/document/api/266/33431)

`FINISH` 只是结束状态，还应核对任务错误字段和输出文件；产物在 `Output.FileInfos`。[图片任务结构](https://cloud.tencent.com/document/product/266/31773#AigcImageTask)、[视频任务结构](https://cloud.tencent.com/document/product/266/31773#AigcVideoTask)

### 5. 对画布的影响与少量待核对项

以下为接入判断，不是腾讯接口的额外规定：

1. 节点保存显式的生成模式和素材角色：首帧、尾帧、参考图、参考视频、待编辑视频、音频。不能只保存一个无角色的素材列表。
2. 同名图片、视频模型分别配置能力；切换模型保留素材，并对不兼容项给出可操作提示，提交时按模型与模式校验。
3. 首版沿用单个生成节点每次输出一个产物的已定范围。平台支持多张输出可留作扩展能力，不据此新增批量输出需求；历史结果仍在原节点查看。
4. 每次运行冻结输入、模型、参数及本地素材引用；公司适配层将其转换成已支持的请求。COS 签名地址按提交时机生成，不充当画布永久素材身份。
5. 本地保存远端任务 ID、错误和产物；恢复时先查已创建任务，再决定是否重提。原生平台查询及临时 URL 都有时间窗口，画布历史依赖本地结果归档。

尚未由本组 VOD 文档确定的只有：OG 的参考图数量上限；可灵各视频版本的多图/视频/音频数量及组合条件；新增字段经过当前公司路由时的映射与开放情况。这些补核只影响新增组合，不推翻已有成功链路。

### 6. 资料可读性与范围

创建图片页已通过网页抓取读取；创建视频页抓取超时后，通过普通浏览器读取。用户给出的 API 数据结构地址抓取超时，已读取腾讯同一文档的 `document/product/266/31773` 版本。三项关键资料均已取得正文。

补充的 AI 生视频概览已读取，但没有可灵逐版本限额；可灵原厂站搜索返回 robots 限制，未绕过。其他腾讯产品（如 MPS 862）的类似字段或限额未当作 VOD 266 的事实写入。

## 二、即梦 / Seedance：按 2.0 与 Fast 整理

用户提供的[创建任务](https://ark.volcengine.com/region:cn-beijing/docs/82379/1520757?lang=zh)与[查询任务](https://ark.volcengine.com/region:cn-beijing/docs/82379/1521309?lang=zh)均已在普通浏览器读取，并展开所需字段。两页显示更新时间均为 2026-09-08 01:20:46。页面同时介绍 2.5、2.0、Fast 等版本，以下聚焦项目现有 2.0 / Fast，不因文档新增版本而扩大模型范围。

### 1. 输入模式与多参

原生创建入口是 `POST /api/v3/contents/generations/tasks`，使用 `model` 与 `content`。`content` 用类型和角色区分文本、图片、视频、音频；这描述的是方舟原生字段，画布仍经公司兼容接口提交。

| 模式 | 原生表达 | 2.0 系列要保留的约束 |
| --- | --- | --- |
| 文生视频 | 只有文本项 | 无需占位首帧。 |
| 首帧 | 一张 `image_url`，`role=first_frame` 或省略 | 单图。 |
| 首尾帧 | 两张图片分别标 `first_frame` / `last_frame` | 两图都必须写角色；不同宽高比时按首帧适配尾帧。 |
| 多模态参考 | `reference_image` / `reference_video` / `reference_audio` | 图片最多 9 张；视频、音频各最多 3 段，每段 2–15 秒，各类总时长分别不超过 15 秒；音频必须搭配图片或视频。 |

**首帧、严格首尾帧、多模态参考三种模式互斥。** 多模态中可用提示词描述某图作为开头或结尾，但这不能冒充严格的首尾帧约束。上述数量是分类上限，不能理解成所有上限任意叠加必然成功。[创建任务：content、图片/视频/音频信息及 role](https://ark.volcengine.com/region:cn-beijing/docs/82379/1520757?lang=zh)

素材预检至少覆盖：图片小于 30 MB；视频不超过 200 MB、MP4/MOV、24–60 fps；音频不超过 15 MB、WAV/MP3。还须按源文校验尺寸、像素数、编码和请求体大小。页面对真人素材另有授权素材入口要求；若以后接人物素材，应按对应入口设计，当前家居产品素材流程不扩展人物功能。[创建任务：各类素材来源](https://ark.volcengine.com/region:cn-beijing/docs/82379/1520757?lang=zh)

### 2. 输出参数

| 参数 | 2.0 / Fast 原生文档能力 | 画布接入判断 |
| --- | --- | --- |
| 分辨率 | 2.0：480p / 720p / 1080p / 4k；Fast：480p / 720p | 按精确模型显示；不能给 Fast 直接套 2.0 的全部选项。公司路由中新增输出档位仍需单独映射。 |
| 时长 | 4–15 秒，或 `-1` 自适应 | 首版可优先使用明确时长，界面值和冻结参数保持一致。 |
| 比例 | 16:9、4:3、1:1、3:4、9:16、21:9、adaptive | 结合模式校验；公司调用不能继续依赖“总能从首图取比例”的假设。 |
| 声音 | `generate_audio` 控制是否生成同步音频 | 与输入参考音频分开保存和展示。 |
| 返回尾帧 | `return_last_frame=true` 可随查询取得尾帧 PNG | 可作为未来视频接力能力；本轮不据此新增首版功能。 |

以上为[创建任务对应输出参数](https://ark.volcengine.com/region:cn-beijing/docs/82379/1520757?lang=zh)；画布栏为实现建议。当前网页还介绍 2.5 专用字段和更大素材限额，不能套到项目的 `doubao-seedance-2-0-260128` / `doubao-seedance-2-0-fast-260128`。

### 3. 任务与归档

创建返回任务 `id`，再用 `GET /api/v3/contents/generations/tasks/{id}` 查询。官方查询页列出排队、运行、取消、成功、失败状态；成功输出在 `content.video_url`，可选尾帧在 `content.last_frame_url`，错误在 `error`，用量在 `usage`。[查询视频生成任务](https://ark.volcengine.com/region:cn-beijing/docs/82379/1521309?lang=zh)

查询窗口为最近 7 天，视频 URL 有效期 24 小时；原生取消只适用于尚在排队的任务。画布应及时下载产物并保留任务身份和本地记录，不能让长期历史依赖临时 URL，也不能把关页或本地停止显示成远端任务已取消。[查询视频生成任务：说明与 status](https://ark.volcengine.com/region:cn-beijing/docs/82379/1521309?lang=zh)

## 三、与现有项目的对照：复用基础，补输入表达

本节以画布分支 `codex/infinite-canvas-beta`、提交 `1a52913` 为代码基线。本会话上一轮已只读核对日常目录数据库：关联本机 LiteLLM 供应商的历史记录中，Image2 Medium 成功 29 条、可灵 3.0 成功 27 条、Seedance 2.0 Fast 成功 2 条；抽查的带参考图图片、普通及首尾帧视频都有远端任务 ID，产物文件仍存在。这是已有使用证据，本轮没有重新调用模型。

| 现有实现 | 可以复用的部分 | 画布需要补的部分 |
| --- | --- | --- |
| [公司图片适配器](../lib/providers/gateway-task-image.ts) | 底图 + 多参考图的 `images` 列表；异步提交、查询、下载 | 无图模式；引用顺序/用途的明确转换。它已有 `referenceGuidanceMode=none`，可避免给自由创作强加旧风格参考前缀。 |
| [公司视频适配器](../lib/video-providers/openai-video.ts)与[尾帧合同](../lib/company-gateway-tail-frame.ts) | 可灵 `LastFrameUrl + OutputConfig`；Seedance `images[0/1]`；双 COS 交付 | Omni/O1 的多参映射，以及没有首帧时的输出参数；保留已实测的首尾帧字段。 |
| [视频请求类型](../lib/video-providers/types.ts) | 现有首图、尾图、时长和多镜头开关 | 目前强制首图；需扩展显式生成模式和有类型、有角色的媒体引用列表。`multiShot` 不能代替多参考素材。 |
| [直连方舟适配器](../lib/video-providers/jimeng.ts) | 可参考其 Ark `content` 与首尾帧编码 | 当前固定 1080p/adaptive 且强制首图，不能原样用于 Fast 多模态；不把公司请求自动切到直连方舟。 |
| [COS](../lib/cos-media.ts)、[尺寸处理](../lib/company-gateway-size.ts)、[结果规整](../lib/image-output-normalize.ts) | 签名、去重、上传、尺寸合同与原生画质交付 | 为参考视频/音频补正确 MIME、格式、时长及大小预检，核对大文件传输；临时签名不进入图的永久引用。 |
| [图片队列](../lib/queue.ts)、[视频队列](../lib/video-queue.ts) | 已有远端 ID 时续查、产物下载、用量记账的成熟逻辑 | 画布定义、节点运行、输入快照、分支依赖和历史归属需独立实现；旧队列绑定项目和分镜，不直接充当图执行器。 |

七牛 PNG 与尺寸实测继续按[公司网关参考](reference/公司网关与COS中转.md)复用。昨晚某份本地配置没有同名路由，是该配置快照的缺项，不能据此说七牛从未跑通；部署时核对实际生效的路由即可。

## 四、用于下一步实现的产品约束

以下沿用[已认可的交互交接](2026-09-08-无限画布-交互与模型部署交接.md)，结合本轮文档形成接入建议：

1. 生成节点内选择模型与模式。参考素材可以排序、标用途；不兼容的组合保留并提示调整，不静默丢图或改换引用。
2. `@参考N` 背后绑定稳定素材身份。提交时冻结引用版本、顺序、用途及提示词，再由模型适配器转换为当前请求需要的表达；排序不能让原引用指向另一素材。
3. 默认手动生成，可执行选定分支；图片、视频独立任务能并行，有依赖的节点等上游产物下载保存完成后再开始。
4. 结果与历史留在原节点；首版不因为平台支持多图输出、视频编辑、视频延长或返回尾帧而自动扩大功能范围。
5. 按「现有案例覆盖的参数直接复用 → 新输入组合补请求映射与校验 → 接入画布保存和执行」拆实现。验证针对新增组合，不把已有公司链路当作从零接入。

目前没有需要用户重新寻找平台资料的阻塞项。落到具体新增组合时，若缺少公司转发字段或组合限额，再提出精确问题；本轮研究不修改已有生成合同。
