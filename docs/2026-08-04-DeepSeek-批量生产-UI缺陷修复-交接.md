## 1. ★ 根因:批量生产里所有按钮的样式被清空

### 1.1 现象

截图里「确认整体输入」「开始批量生产」「重新扫描」「曲目(可手动指定)」全部渲染成**没有背景、没有边框的纯文字**,用户完全看不出那是可点的按钮 —— 这就是问题 5「没有选项可以调整」的真相:按钮在,但看不出来。

### 1.2 根因(已定位)

`components/mixcut/mixcut-shell.module.css:59`:

```css
.shell button { font-family: inherit; cursor: pointer; border: none; background: none; color: inherit; }
```

- 这条重置原本只服务单条模式 —— 单条所有按钮都用 CSS Module 的 `styles.btn`,重置无害
- M4 之后**批量生产也被包进了 `MixcutShell`**(`BatchPreparationPanel.tsx:1285`)
- 但批量用的是全局 Tailwind 工具类 `btn-primary` / `btn-secondary` / `btn-danger`
- **CSS 优先级**:`.shell button` = (0,1,1) 类+元素,`.btn-primary` = (0,1,0) 仅类 → **`.shell button` 胜出**
- 结果:`background`、`border` 被清空,按钮退化成文字

这是 M3 骨架抽取时埋下的回归。

### 1.3 修法

**不要**给每个按钮加 `!important`,那会污染整个代码库。选下面任一方案:

**方案 A(推荐):把重置限定在单条模式自己的按钮上**

```css
/* 只重置没有携带全局按钮类的按钮 */
.shell button:not([class*="btn-"]) {
  font-family: inherit; cursor: pointer; border: none; background: none; color: inherit;
}
```

**方案 B:在 shell 内恢复全局按钮类的样式**

在 `mixcut-shell.module.css` 里追加,用 `:global()` 提高针对性:

```css
.shell :global(.btn-primary),
.shell :global(.btn-secondary),
.shell :global(.btn-danger) {
  border: revert; background: revert; color: revert;
}
```

> 选 A 更干净。无论选哪个,都要确认**单条模式的按钮外观完全没变**(铁律:不改单条行为)。

### 1.4 验收

- 批量生产四步里,所有 `btn-primary` 按钮是**蓝底白字圆角**,`btn-secondary` 是**浅灰底**
- 禁用态有 45% 透明度
- **单条精准混剪的按钮外观与修改前完全一致**(逐步对比截图)
- 全局搜索确认没有为了修这个问题而新增 `!important`

## 2. P0:卡片重叠(问题 1 和 3)

### 2.1 现象

- 第 1 步:素材卡片"漏"出容器,盖住下方「画质与调色」版块
- 锁定状态:「素材区」「已锁定素材」「画质与调色」几张卡片叠在一起,文字互相覆盖

### 2.2 根因

**双层滚动容器 + flex 高度冲突**:

| 层 | 位置 | 样式 |
|---|---|---|
| 外层 | `mixcut-shell.module.css:185` `.mainCol` | `display:flex; flex-direction:column; overflow-y:auto` |
| 内层 | `BatchStepMaterials.tsx:296` 素材列表 | `min-h-[520px] flex-1 overflow-y-scroll` |
| 内层 | `BatchStepMaterials.tsx:233` 已锁定素材列表 | `min-h-0 flex-1 overflow-y-scroll` |

`min-h-[520px]` 与 `flex-1` 同时存在时,flex 容器无法正确收缩子项;外层 `.mainCol` 虽然有 `overflow-y:auto`,但子项的实际高度超出后,兄弟节点的定位就错位了,视觉上就是重叠。

这也违反了 PRD 的 **AC-S1**:「页面任意位置滚动鼠标滚轮,只有一个滚动容器响应」。

### 2.3 修法

**确定一层滚动,只留一层。** 用户已明确表示接受"素材池内部上下滚动",所以:

1. **让步骤内容区不滚**,把滚动交给素材池:
   - 批量的 step 容器(不是 `.mainCol` 本身 —— 那是单条共用的,不要动)加 `overflow: hidden`
   - 或者在 `MixcutShell` 上为批量模式提供一个 `data-` 变体,只对批量关闭 `.mainCol` 的滚动
2. **素材池改用明确的高度约束**,不要 `min-h-[520px]` 和 `flex-1` 混用:
   - 推荐 `flex-1 min-h-0` + 父容器提供确定高度
   - 或者干脆 `h-[clamp(360px,50vh,720px)]` 给一个自适应的固定高度
3. **「画质与调色」放在素材池之外**,不参与高度竞争(它默认收起,展开时让外层滚动即可)
4. 检查锁定分支(`frozen`)的布局,它和未锁定分支应该用**同一套容器结构**,不要各写一套

> **不要动 `.mainCol` 的样式** —— 那是单条模式共用的,改了会影响单条。

### 2.4 验收

- 1440px 宽窗口下,第 1 步没有任何文字或卡片互相覆盖
- 批次**锁定后**的第 1 步同样没有重叠
- 滚轮在素材区内:只有素材列表滚动
- 滚轮在素材区外:只有步骤内容滚动
- 素材池一屏能完整看到至少 2 行卡片,缩略图不被裁

## 3. P1:BGM 版块重做

### 3.1 现象

当前 BGM 区是一段说明文字 + 两个(失去样式的)文字按钮,排版松散,和整体不协调。

### 3.2 参照:单条模式的 BGM 卡片

`components/mixcut/BgmCard.tsx` 是成熟设计,**照它的信息结构做**:

```
┌─ 背景音乐                                    [12 首] ┐
│  [曲目下拉 ▾]                                        │
│  [+ 导入]  [试听]                                    │
│  · 状态行(aria-live)                                 │
│  ───────────────────────────────────────────────── │
│  音量  ●━━━━━━━━━  -18 dB                            │
│  淡入  ●━━━━━━━━━  1.0 s                             │
│  淡出  ●━━━━━━━━━  1.5 s                             │
└──────────────────────────────────────────────────┘
```

关键元素(见 `BgmCard.tsx:149-265`):
- 标题行右侧一个**曲目数量徽标**(`bgmCount`)
- 控制行统一为 `标签 + 滑杆 + 数值` 三段式(`ctlRow` / `ctlLab` / `ctlVal`),**当前批量的三个滑杆排版松散,应对齐这个结构**
- 试听按钮有**播放/停止**两态

### 3.3 批量版的差异

批量不是选单曲,而是**曲库自动分配**,所以:

| 元素 | 批量的做法 |
|---|---|
| 曲目数量徽标 | `曲库 12 首` |
| 下拉选曲 | 换成一行状态:`12 首 · 8 条成片将自动分配` |
| 导入按钮 | 换成 `[重新扫描]`(文件放进 `storage/bgm/` 后刷新) |
| 曲目列表 | 可展开,每首:文件名 + 时长 + 试听 + 勾选框(手动指定用) |
| 空曲库 | 卡片内醒目提示 + `[重新扫描]`,并让第 2 步开始按钮禁用 |
| 音量/淡入/淡出 | 保留,但排版对齐 `ctlRow` 三段式 |

**默认路径必须零操作**:曲库非空时,用户什么都不用点就能开跑;手动指定默认收起。

### 3.4 验收

- BGM 区是一张结构清晰的卡片,与第 2 步其他卡片视觉一致
- 三个滑杆左对齐、数值右对齐,不再松散
- 曲库非空时显示数量和分配预期
- 曲库为空时提示醒目,且开始按钮禁用并说明原因
- 展开曲目列表能试听、能勾选

## 4. P1:已完成/已取消的任务无法清除

### 4.1 现象

「低清预览片」区堆着 5 行「已完成」,一直挂着不消失,没有关闭入口。用户称之为"死任务"。

### 4.2 根因

`BatchStepMaterials.tsx:426-440` 的操作按钮只覆盖三种状态:

| 状态 | 有的操作 |
|---|---|
| `failed` | 重试 |
| `queued` / `running` | 暂停、取消 |
| `queued` | 继续 |
| **`succeeded`** | **无** |
| **`cancelled`** | **无** |

已完成和已取消的任务没有任何出口,只能永久堆积。

另外这些行的文案是清一色的「已完成」,**看不出是哪个素材的任务**,信息量为零。

### 4.3 修法

1. **默认只显示进行中的任务**(`queued` / `running` / `failed`),已完成的自动收起
2. 提供 `[显示全部 (N)]` 开关查看历史,以及 `[清除已完成]` 一键清理列表
3. **每行补上素材标识**:显示素材文件名或前 8 位 ID,不要只有状态词
4. 如果任务状态长时间停在 `running` 但调度器已重启(僵尸任务),应能被取消 —— 确认 `onProxyControl(id, 'cancel')` 对这类任务有效;若后端拒绝,给出可读原因而不是静默失败

> 这里的"清除"只影响**列表展示**,不要删除 `batch_tasks` 表里的审计记录。

### 4.4 验收

- 跑完几个预览片任务后,列表默认不再堆积「已完成」
- 「显示全部」能看到历史,「清除已完成」能清空列表
- 每行能看出对应哪个素材
- 卡在 running 的任务点取消后确实变为已取消,或给出明确原因

## 5. P1:确认流程的引导

### 5.1 现象

界面提示「暂时无法开始:请先确认整体输入」,但用户找不到该点哪里。

### 5.2 根因

主因是 §1(按钮没样式)。修完 §1 后「确认整体输入」会恢复成可见按钮。

但还有一个次要问题:**提示文字和它指向的按钮距离过远** —— 提示在版块底部,按钮在版块右上角,中间隔着大段说明文字和三个滑杆。

### 5.3 修法

- 提示文案直接指明位置:`请先点击上方「确认整体输入」`
- 或者把提示移到按钮**紧邻处**
- 当 `startDisabledReason` 存在时,给「确认整体输入」按钮加一个高亮/脉冲提示,让用户一眼看到下一步该点什么

### 5.4 验收

- 新建批次 → 选素材 → 选脚本 → 第 2 步,能在 3 秒内找到该点哪个按钮
- 提示文案和对应按钮在视觉上关联
