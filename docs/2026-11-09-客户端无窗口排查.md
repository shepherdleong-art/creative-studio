# 客户端启动后无窗口排查

## 现场与恢复

用户报告 `outputs/02-客户端/客户端目录/team-client-studio-prod-20261105-members-r1/Creative Studio.exe` 打不开，远程电脑的入口也打不开。当前客户端指针为 `studio-prod-workbench-fixes-20261109-r1`。

现场本机 Electron 进程存在、健康文件为 true，但原生窗口列表没有客户端。调用同目录 `launcher.mjs` 后窗口出现，读取原生无障碍树确认控制台已加载、保留登录状态且显示正常接收任务。随后正常关闭客户端，再直接启动原 EXE，也能显示控制台。没有替换程序、清除 Cookie 或设备状态，没有重启生产服务或提交生成任务。

## 已验证与未确定

- 本机和远程服务器本机的 HTTPS 登录页与 readiness 接口均为 200，ready=true、maintenance=false；服务器 App、Caddy、LiteLLM、Maintenance 均 Running。
- 旧 EXE 的反射检查发现它为中间启动进程设置 Hidden，但隔离测试及现场再次启动均通过，不能据此断言这就是此次根因。
- 健康文件只证明主进程握手兼容，不能单独证明窗口可见。现场日志没有提供足以解释无窗口状态的错误，初始问题未能稳定复现。
- 远程公共桌面的“Creative Studio 工作台”“Creative Studio 管理入口”实际使用 Chrome app 模式，共用 `E:\CreativeStudio\browser-profile`，不是截图中的 Electron EXE。已询问用户具体失败入口；远程入口的视觉恢复尚未验证，不能以服务健康代替验收。
