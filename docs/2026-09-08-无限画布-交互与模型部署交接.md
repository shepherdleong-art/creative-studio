### 原型的实际边界

- 当前是单 HTML 交互演示：模拟排队、并发、失败和结果；示例视频是运镜示意，不是供应商生成视频。本地上传的视频、音频可预览。
- 原型已有输入快照、引用校验、分支依赖、历史结果和断线交互的前端逻辑；这些还没有对应的正式数据库、worker、API 或重启恢复。
- **刷新会重置本次演示。** 主题偏好会保存，图和任务尚未自动持久化。
- 原型里的“图片模型 A/B、视频模型 A/B”及 6 图、4 图 + 1 视频 + 1 音频等上限都是演示配置，不能用作真实模型能力表。
- 用户已反馈“基本没啥要改的了”，可视为主要交互方向认可。此前的语法、模型逻辑和 DOM 替身检查不等于真实浏览器全面验收；自动浏览器曾拒绝访问该 `file://` 原型，本轮未绕过该限制，也没有重新开展浏览器回归。

## 6. 部署方式和本轮现场状态

### 6.1 公司模型链路

```text
浏览器 / Electron
  → Creative Studio 本机 Node 服务
  → 本机 LiteLLM，默认 http://127.0.0.1:4000
  → 公司统一网关 /v1
  → 云厂商服务（腾讯云 / 七牛云 / 火山方舟）

需要公网 URL 的本地参考素材
  → COS 中转副本 + 临时签名 URL
  → 上游读取；原始素材和最终结果仍保存在本地
```

本轮本机配置能确认到“公司统一网关”这一层；网关内部到各云厂商的具体路由归属来自用户说明与相关文档，尚未读取或验证公司网关后台配置。

- 公司图片/视频预设的 `baseUrl` 为本机 LiteLLM；上游真实凭据由本机 `config.yaml` 持有。多参接入继续保留这层边界。
- 仓库锁定 LiteLLM `1.89.2`、`socksio 1.0.0`，按 Python 3.12 部署。日常配置本轮确认 `router_settings.num_retries=0`、`router_settings.timeout=110`、`litellm_settings.drop_params=true`。应用请求超时各适配器不同，不能把脚本模型的 120 秒等待套到所有生成任务。
- `drop_params=true` 提醒后续必须检查网关真正收到的多参字段；配置存在不证明字段会完整保留。本轮没有认定它已经丢弃了某个字段。
- LiteLLM 启动只清除其子进程的大小写 HTTP/HTTPS/ALL 代理变量，保留 Codex/父 shell 环境。公司网络或 VPN、TUN 下的 DIRECT 与公司 DNS 仍需按目标机器核对。
- 公司首尾帧强制双 COS 交付，上传/门禁失败应在生成提交前停止。七牛图片在现有代码中另有内联 data URL 通道；新增视频/音频交付仍需补校验，不能把本机服务暴露到公网。

## 7. 正式实现需要补的内容

这些是下一阶段技术工作，不是今晚已经交付的功能。

1. **精确模型能力表。** 按供应商身份、网关别名、接口版本声明输入模式、类型/数量/时长限制、首尾帧、输出参数、查询与取消能力；区分文档支持、假上游验证、真实验证。未知能力保持未验证状态。
2. **统一多媒体输入。** 视频请求从单一首图/尾图扩展到有顺序和用途的引用列表；图片补无底图模式。画布保留稳定引用标识，再由 Adapter 转换成原生字段，继续兼容旧工作台调用。
3. **独立画布数据与执行器。** 画布定义、一次分支运行、节点尝试、素材分别保存；使用版本与不可变输入快照。旧 `jobs` / `video_jobs` 绑定项目、分镜和必填首图，不伪造这些记录来承载自由画布。
4. **跨节点并发与依赖。** 已有图片队列、视频队列各自并行；视频默认并发 10、可调 1–10。图片并发函数目前只是规范请求数值，不是账号全局限流器。新调度器要在共享配额下让独立任务并行，等待所有依赖完成并成功保存后才启动下游。
5. **运行结果可追溯。** 固定模型、供应商、模式、提示词、输入素材版本、顺序、用途及关联的上游尝试；草稿改动不影响当前运行。断线或删除画布引用不抹掉已提交任务的输入记录。
6. **保存与恢复。** 图/视口自动保存，任务在后端持续推进；接入启动恢复和统一停机。有远端 ID 的任务续查或补下载；提交结果不明时进入核查状态，不自动重发付费生成。停止本地等待不能宣称远端已经取消。
7. **状态与消耗。** 展示等待输入、等待名额、提交、生成、下载、成功/失败等真实阶段；上游没有进度百分比时不套用原型计时器伪造百分比。按节点尝试记账，下载重试不产生第二次生成或重复费用。

候选实现目录沿用早期评估的 `app/canvas/`、`app/api/canvas/`、`components/creative-canvas/`、`lib/creative-canvas/`；React Flow 仍是候选，未安装。`CREATIVE_STUDIO_CANVAS_ENABLE` 仍是提议中的功能开关，当前代码没有实现。数据库迁移需独立追加式版本流和共享升级 gate，保留原工作台行为。
