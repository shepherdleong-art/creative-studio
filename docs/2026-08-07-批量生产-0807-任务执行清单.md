# T4 · 断句句数对齐（口播优先的前置）

## 🔴 先读这一段：两种形态是有意设计，不许统一成一种

仓库里有两套断句，**这是设计，不是历史遗留**（用户 2026-08-07 确认）：

| 位置 | 行为 | 用途 |
|---|---|---|
| `lib/batch-production/narration.ts:56` `splitScript` | 零宽 lookbehind，**保留标点** | 脚本内容预览、TTS 朗读、句段 id |
| `lib/batch-production/allocator.ts:463` `splitAllocationScriptBody` | **吃掉标点** | 分配、语义匹配 |

设计意图：字幕不能出现多余标点。（实际上标点在展示层还会再清一次 —— `splitNarrationForDisplay` 会把 `"周末午后，她窝在洒满阳光的客厅沙发里。"` 变成 `"周末午后"` / `"她窝在洒满阳光的客厅沙发里"`，所以字幕无论走哪条路径都不带标点。）

**所以：本卡要保留两种形态，只是让它们出自同一次切分。谁把两种形态合并成一种，就是把用户的设计砸了。**

## 目标
两个切分器在**句数**上可能分叉，而 T7 要按序号把口播句段映射到分配句段 —— 句数必须是单一事实。

已实测的分叉（只有连续终止标点会触发）：

```
"A。。B"   带标点 → ["A。","。","B"]  3 句 ｜ 去标点 → ["A","B"]  2 句   ❌
"A！？B"   带标点 → ["A！","？","B"]  3 句 ｜ 去标点 → ["A","B"]  2 句   ❌
其余常规文本（含 "A。B" / "A、B，C" / "A。\nB" / "A；B；" / 无终止标点）全部一致 ✅
```

**现网 24 条批量脚本快照，句数不一致 0 条**（验收人已跑过全表核对）。所以这是**防御性改动，不是救火** —— 不要因为紧张而扩大改动范围。

## 改动清单

### 1. 新建 `lib/batch-production/script-sentences.ts`

```ts
export function splitBatchScriptSentences(bodyText: string): Array<{
  text: string;                // 去标点，给分配器与语义矩阵
  textWithPunctuation: string; // 带标点，给 TTS 朗读、脚本预览、句段 id
}>
```

一次切分产出两种形态，数量与顺序**结构上不可能**再分叉。

**句界规则**：以「去标点」侧的句界为准 —— **连续终止标点归到前一句**。即 `"A。。B"` = 2 句，其 `textWithPunctuation` 为 `["A。。", "B"]`。（这样才符合直觉；现网数据不含该情形，所以不会改到任何既有句段。）

### 2. 两处改调它，导出签名与行为对外不变
- `narration.ts` 的 `splitScript` 内部改成调新函数、取 `textWithPunctuation`

# T11 · 封面标题卡布局挤压 + 预览失真

## 现象
封面标题卡里控件挤成一团（「描边」竖排折成两行、数字框压在滑块上、字体名被截成 `PingFan`），右侧预览显示不正确（本该是黄色带黑描边的斜体标题，实际渲染成全黑、两行叠在一起）。

## 根因 A：预览与成片本质不同（`BatchStepScripts.tsx:772-779`）

1. 预览用 CSS `WebkitTextStroke`，描边画在**填充之上**（CSS 无 `paint-order` 保证）；渲染端 `lib/batch-production/cover-title.ts` 的 SVG 用 `paint-order: stroke fill`（描边在下）。**两者本质不同，不是参数没调准。**
2. 描边宽度还多乘了一个 2：`style.stroke.widthPx * previewScale * 2`。预设 `fontSizePx=99`、`previewScale=1/5` → 20px 字号配 2.4px 居中描边，而 CJK 笔画本身才约 2px 宽 → **黄色填充被完全吞掉，这就是截图里全黑的原因。**
3. 预览用 `flex flex-col gap-1` 从顶部堆叠，**完全忽略 `style.y`** → 用户拖「纵向位置」（22% / 32%）预览不动。
4. `previewScale` 硬编码成 `1/8.5` 或 `1/5`，与预览框实际尺寸（`maxHeight: 220` + `aspectRatio`）无关 → 容器宽度一变比例就错。

### 修法：预览改成内联 SVG
`viewBox` 用真实输出尺寸（`BATCH_OUTPUT_PRESETS[preset]`），fontSize / strokeWidth / y 全部按**输出坐标**写，浏览器负责缩放 —— 不需要任何 `previewScale`，且 `paint-order="stroke fill"` 与渲染端一致。预览与成片从此**同构**，不是"近似"。

🔴 **关键约束**：`cover-title.ts` 里的 `textStyleToSvgElements` 正是渲染端用的那份实现，但该文件 `import sharp` —— **直接在客户端组件里 import 会把 sharp 打进浏览器 bundle**。必须先把纯字符串构造抽到一个无 Node 依赖的新模块（例如 `lib/final-edit/title-svg.ts`：只 import `types.ts` / `domain.ts` 这类纯类型与纯函数），由 `cover-title.ts` 与客户端组件共同 import。

抽取时**不得改变产出的 SVG 字符串** —— `scripts/batch-cover-title.test.ts` 锁着渲染结果，它必须继续通过而不用改断言。改断言就说明你改坏了成片。

预览文案「预览仅为样式近似」在同构之后可以去掉"近似"的说法。

## 根因 B：布局在窄容器下崩塌

1. 外层 `flex flex-wrap gap-4`（`:810`）+ 左侧 `grid min-w-64 flex-1 lg:grid-cols-2`（`:811`）塞两个样式编辑器，编辑器内部又是 `grid grid-cols-2`（`:652`）→ 每个字段实际只有约 95px
2. 描边那一行（`:705-739`）要在一行里塞 checkbox + 「描边」+ 颜色块(`w-10`) + 数字框(`w-14`)，约需 145px → 「描边」竖排折成两行（截图里的"描/边"）
3. 描边格因折行变高，同 grid 行的「纵向位置」格（`:740-755`）滑块随之错位，视觉上与数字框重叠
4. 字体 `select`（`:655-663`）无最小宽度也无 `truncate` → `PingFang SC` 被截成 `PingFan`

### 修法
- 描边行拆成两行：第一行 checkbox + 标签，第二行 颜色 + 宽度；或让描边格 `col-span-2`
- 字体 select 给 `min-w-0` + `truncate`，或直接 `col-span-2`
- 数字框不要硬写 `w-14`，用 `min-w-0 flex-1` 之类让它随格子伸缩
- 左侧编辑器容器把 `lg:grid-cols-2` 的断点提高到 `xl:`，窄容器下主/副标题竖排，避免 95px 的死胡同
- **验收标准**：在 1440px 视口下（用户实际使用宽度），任何标签都不折行、滑块与数字框不重叠

## 禁止
- ❌ 不要改 `lib/batch-production/cover-title.ts` 的合成结果（成片封面正常，用户已确认「封面做对了」）
- ❌ 不要改 `normalizeTextStyle` / `cleanFraming` / 预设表结构
