## 三轮复核里被推翻的两个判断

留档，避免以后重走弯路：

1. **「批量的编辑器是另起炉灶，没法照搬单条」** —— 错。批量侧本来就是照着单条抄的：共用 `mixcut-content.module.css`、共用 `components/final-edit/timeline-edit.ts` 与 `preview-playback.ts`、`Waveform` 组件原样复制。方案原文写着「照抄模式，不改它的文件」（`docs/2026-08-24-batch-output-timeline-edit-plan.md` §2）。

2. **「字幕样式在批量里没有落点，要中等工作量」** —— 错得更多。`lib/media-core/cover-domain.ts:22` 的 `defaultTextStyle` **已经有 `'subtitle'` 分支**，SVG 生成函数 `textStyleToSvgElements` 也在 `media-core/` 里且批量已在用。批量却在 `batch-renderer.ts:604` 手抄了一份更弱的硬编码版。这块是所有缺失项里**最便宜**的。

真正的架构约束只有一条，且它不阻止照搬：

> `lib/batch-production/` 绝不 import `lib/final-edit/`。**要复用就把东西提到 `lib/media-core/`。**  
> UI 层共享是被明确允许的（见 `docs/reference/批量生产模块.md` 关于 `BatchTimelinePreview` 的说明）。

`lib/media-core/` 就是为跨模块复用而存在的目录，已经沉淀了 `cover-framing` / `cover-domain` / `cover-title-svg` / `cover-title-presets` / `cover-types` / `render-contract` / `tts-speed` / `scene-detect` / `export-identity` / `storage-path`。

## 使用建议

- **先做 01**（两个正确性缺陷），它们独立于任何界面改造，可单独出一个 PR。
- **再做 02 的 A–B 两项**（封面 + 字幕样式），后端就绪度最高，用户感知最强。
- **03 的 8 条已在 `b79a1df` / `187cae2` 落地**（#2 除外），继续做之前先读 [04-其余反馈-实现复核.md](04-其余反馈-实现复核.md)：里面有 3 个待修项、2 条小的，以及一份「已确认做对、不要返工」清单。
- 详情页脚本生成独立开线，不与上面混在同一个分支。
