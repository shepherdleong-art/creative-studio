### 0.1 你要做什么

把「第五步 · 智能混剪」下的**批量生产**模式:

1. **M1** 清掉界面上的研发术语,让报错说人话(不碰后端、不碰数据库)

### M1-C 报错人话化 + 同因合并

**定位**:`publishSelected()` 函数内(~952-956)

现状:
```ts
const skippedReasons = result.items.filter(({ status }) => status === 'skipped').map(({ reason }) => reason).filter(Boolean);
setFeedback({
  kind: result.published > 0 ? 'success' : 'error',
  message: `已发布 ${result.published} 条，跳过 ${result.skipped} 条${skippedReasons.length ? `：${skippedReasons.join('；')}` : ''}`,
});
```

**问题**:同一条内部报错会按卡片数重复 N 遍,且含 `productionReady=true` 这类内部字段名。

**改为**:
1. 在文件顶部常量区新增错误翻译表:

```ts
/** 后端原始错误 → 用户可读文案。匹配用 includes，避免依赖完整字符串。 */
const EXPORT_SKIP_REASONS: Array<{ match: string; text: string }> = [
  { match: 'productionReady', text: '还没有配音' },
  { match: 'narration', text: '还没有配音' },
  { match: '原片来源', text: '找不到原始素材文件' },
  { match: '内容指纹', text: '原始素材已被修改' },
  { match: 'LUT', text: '调色滤镜已丢失或被修改' },
  { match: '已存在', text: '成品文件已存在，不覆盖' },
];

function humanizeSkipReason(reason: string | undefined): string {
  if (!reason) return '未知原因';
  const hit = EXPORT_SKIP_REASONS.find(({ match }) => reason.includes(match));
  return hit ? hit.text : '导出前检查未通过';
}
```

2. 汇总时**按原因归类计数**,不逐条重复:

```ts
const skipped = result.items.filter(({ status }) => status === 'skipped');
const grouped = new Map<string, number>();
for (const item of skipped) {
  const text = humanizeSkipReason(item.reason);
  grouped.set(text, (grouped.get(text) ?? 0) + 1);
}
const detail = [...grouped].map(([text, count]) => `${count} 条${text}`).join('；');
setFeedback({
  kind: result.published > 0 ? 'success' : 'error',
  message: `已导出 ${result.published} 条${result.skipped > 0 ? `，跳过 ${result.skipped} 条：${detail}` : ''}`,
});
```

**验收**:10 条全部缺配音时,提示为 `已导出 0 条，跳过 10 条：10 条还没有配音`,而不是同一句英文重复 10 遍。

## 3. M2 · 打通配音与 BGM ★ 价值锚点

**目标**:批量首次导出**合格成片** —— 有配音、有字幕、有 BGM、有封面,且时长符合各脚本设定。

这一批改动最深,分四段。**建议每段单独提交**,便于二分定位。

### M2-A 迁移 v17

**加三个字段**(照抄迁移 v9 的写法,见 `lib/batch-production/schema.ts:336-341`):

```sql
ALTER TABLE batch_scripts ADD COLUMN targetDurationSec INTEGER NOT NULL DEFAULT 15;
ALTER TABLE batch_script_snapshots ADD COLUMN targetDurationSec INTEGER NOT NULL DEFAULT 15;
ALTER TABLE batch_productions ADD COLUMN archivedAt TEXT;
```

**约束**:
- 追加为 v17,**不改 v1–v16**
- 走既有的批量迁移网关(锁 + 备份 + 审计),不要新开路径
- `archivedAt` 是**独立维度**,不要塞进 `status` 枚举
- `archivedAt` 本批只建字段,UI 在 M4 用

**测试**:参照 `scripts/db-migrations.test.ts`,验证 v16 库升到 v17 后历史行的 `targetDurationSec` 为 15、`archivedAt` 为 NULL。

### M2-B 时长链路(容易漏一步)

**四处都要改,漏任一处都会导致时长永远是 15:**

| # | 位置 | 改动 |
|---|---|---|
| B1 | `lib/batch-production/script-catalog.ts` `syncProjectScripts()` | metadata 补 `targetDurationSec: script.targetDurationSec` —— **最容易漏的一步** |
| B2 | `lib/batch-production/scripts.ts` `createProjectScript()` | 接收并落库该字段(参照现有 `coverTitleJson` / `shotSetId` 的写法) |
| B3 | 快照创建逻辑(`scripts.ts` 里 INSERT 进 `batch_script_snapshots` 的地方) | 把字段带进快照 |
| B4 | `lib/batch-production/allocator.ts` `normalizePlan()` | 改为从 plan 自身的脚本快照读时长;`normalizeInput` 的整批值降级为兜底默认 |

**兼容**:历史快照没有该字段 → 回落 15,不得抛错。

**测试**:两份不同时长(15s / 30s)的脚本进同一批次,产出的 arrangement 里 `targetDurationUs` 分别正确。

### M2-C 配音执行器

**好消息**:两边数据形状几乎一致,不用重新设计。

单条 TTS 适配器输出(`lib/final-edit/adapters/tts-registry.ts`):
```ts
{ relativePath, absolutePath, durationUs, segmentTimings: [{ segmentId, startUs, endUs }], wordTimings }
```

批量需要(`lib/batch-production/narration.ts` 的 `BatchLocalNarrationArtifact`):
```ts
{ audioRelativePath, audioFingerprint, durationUs, segmentTimings: [{ sourceSegmentId, startUs, endUs }] }
```

**差异只有**:字段改名 + 补一个 SHA-256 指纹(`lib/batch-production/fingerprint.ts` 有现成工具)。

**要做的四件事**:

| # | 位置 | 改动 |
|---|---|---|
| C1 | `allocator.ts:162-164` | `narration` 字段的字面量类型 `{ ready: false; productionReady: false; status: 'pending' }` 放开为 boolean,**否则类型层面永远接不上** |
| C2 | 新增 `lib/batch-production/narration-executor.ts` | 读冻结脚本 → 调 TTS 适配器 → 算指纹 → `createLocalNarrationSnapshot()` → 写回 arrangement |
| C3 | `scheduler.ts` / `executors.ts` | 注册 `narration` 任务类型,排在 `allocation` 之后、`render` 之前 |
| C4 | `batch-renderer.ts:122-125` | 接收 `productionReady: true` 的 narration,`audioMode` 自然变成 `'narration'`,`batch-export.ts:224` 的闸门随之打开 |

**参照实现**:
- provider 解析与适配器调用:`lib/final-edit/runtime.ts:75-90`
- 调用方式与缓存复用:`lib/final-edit/workspace.ts:1076-1096`

**必须做的优化 —— 同脚本多份共用一条配音**:

批量的「份数」语义是同一文案出 N 条、画面不同口播相同。按 `hash(脚本正文 + 音色 + 语速)` 只合成**一次**,N 条复用同一音频。单条已有 `narrationHash` 范式可照搬。

> 漏掉这一条,一份脚本出 10 条就会调 10 次 TTS —— 又慢又贵。

**音色语速按脚本设置**:每份脚本有自己的音色和语速(PRD FR-S2-14),所以复用键的范围是单份脚本内。

**测试**:一份脚本设 10 份,断言 TTS 适配器只被调用 1 次。

### M2-D BGM

**现状**:分配器**已实现**轮询挑曲(`allocator.ts:851-853`),但曲目列表从未被传入(`musicTrackIds` 在分配器之外零引用),且渲染器完全不混音轨(`batch-renderer.ts` 里 `music`/`bgm`/`amix` 零命中)。

**产品规则**:
- BGM 是**必选项**(与配音、字幕、封面并列)
- **默认全自动** —— 用户往 `storage/bgm/` 放曲子,不做选择,系统自动分配
- **可选手动指定** —— 每份脚本可挑 1–N 首收窄范围

**要做的四件事**:

| # | 改动 |
|---|---|
| D1 | 曲库扫描接进批量:复用 `lib/final-edit/bgm.ts` 的 `scanFinalEditBgm()`,**共用 `storage/bgm/` 与 `final_edit_bgm_tracks` 表,不建批量专属曲库** |
| D2 | 锁定批次时确定性打乱曲库,接进 `musicTrackIds`(依序取的逻辑已就绪) |
| D3 | `batch-renderer.ts` 移植单条混音链(见下) |
| D4 | 曲目指纹纳入锁定与渲染前校验(参照 `lib/final-edit/renderer.ts:90`) |

**关键约束 —— 「随机」必须是确定性随机**:

```
锁定时:
  seed = hash(batchVersionId)
  pool = shuffle(曲库或手动指定的曲目, seed)      // 确定性打乱
  第 i 条成片 → pool[i % pool.length]            // 依序取，天然均匀
  写入 arrangement.music.trackId 并冻结曲目指纹

渲染时:
  只读 arrangement.music.trackId，不做任何选择
```

不能实现成每次渲染现掷骰子 —— 否则同一批次重跑会出不同音乐,「锁定输入」对 BGM 就不成立。打乱后依序取还保证使用均匀(3 首出 9 条 = 每首各 3 次)。

> `allocator.ts:564` 已有 `.sort()`,接入时**不要绕过它**,那是确定性的前提。

**混音链**(照搬 `lib/final-edit/renderer.ts:117-118, 152-153`):

```
[bgm] aresample=48000
    → loudnorm=I=-16:TP=-1.5:LRA=11      # 响度归一化，保证人声不被盖
    → volume=<gainDb>dB                   # 默认 -18dB
    → atrim=duration=<成片时长>
    → afade(in/out)                        # 默认淡入 1.0s / 淡出 1.5s
    → [music]
[narration][music] amix=inputs=2:duration=longest:dropout_transition=0
```

循环用输入侧 `-stream_loop -1` 解决。

**闸门位置**:BGM 缺失是**输入问题**,拦在**第 2 步开始按钮**,不要等到导出口才拒绝:
- 曲库为空 → 禁用开始,提示曲库位置与刷新入口
- 手动模式下指定为空的脚本 → 禁用开始,指明是哪几份

**测试**:
- 同种子重跑,每条成片分到的曲目完全相同
- 3 首出 9 条,每首恰好用 3 次
- 曲目指纹不一致时该条渲染失败并给出可读原因
