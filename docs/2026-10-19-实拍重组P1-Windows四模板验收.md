## 发现与修复

首轮源码 B 的 v3 在 HyperFrames 包装 WebM 时长探针处发生 deadline，矩阵停止且旧 v2 保留。失败记录保留在 matrix.log、matrix-CbYWBF/sB/；不计作通过。随后发现 runPackagingPipeline 未向子进程传递共享解析器选出的工具：应用诊断显示新版探针，package-video.mjs 却默认回退旧 ffprobe-static。快速回归在默认环境与无效覆盖变量两种情况下均失败，实际子进程路径证据见 tools-default-before.log / tools-before.log。

修复为启动包装子进程时显式传入 resolveFfmpegPath / resolveFfprobePath 的结果，保留现有版本选择、失败和中止语义，不修改第三方二进制或增加重试。新增 packaging-runtime-tools.test.ts 检查真实子进程边界；修复后通过。短合成 WebM 对新版直接、新版 shim、旧版 shim 各 30 次探针均通过，因此不声称该短样本稳定复现原超时或定位旧二进制内部死锁；本次确证的是工具选择不一致，修复后的完整失败流程和 8 组矩阵全部通过。

包装构建器哈希随修复变化，重新生成 synthetic-fixed 基准，未改写旧 spec / render-manifest。新生产构建和 TypeScript 通过，仍有 124 条动态路径追踪警告；ESLint、包装版本锁与 P1 投影回归通过。新免安装包用官方 SkipBuild 测试模式装配，依赖和生产构建复用本机已验证资源，配置仅为无效测试凭据，移出多余 lib/app/components 开发源码，保留冻结构建器来源归档。上轮 Windows 导入分隔符与重试目录长度修复继续保留。

证据根：`outputs/2026-10-19-p1-matrix/`。`synthetic-fixed.log` 和 `synthetic-fixed/results.json` 为基准双次渲染；`matrix-fixed.log` 与 `matrix-6VOCpL/matrix-results.json` 为完整矩阵。每个 sA–sD / pA–pD 子目录保留 integration.log、desktop.log、隔离 fixture、desktop-result.json、render-manifest.json、checks.json、cleanup.json 和界面截图。抽帧总图为 `matrix-6VOCpL/source-visual-sheet.png`、`portable-visual-sheet.png`。

复跑使用新目录，不复用已被编辑的夹具：

```powershell
$env:FILM_E2E = '1'
$env:FILM_OVERLAY_ROOT = '<尚不存在的合成工程目录>'
Remove-Item Env:FILM_OVERLAY_TEMPLATE -ErrorAction SilentlyContinue
node scripts/film-render-overlay.e2e.test.ts

$env:FILM_MATRIX_SYNTHETIC_ROOT = $env:FILM_OVERLAY_ROOT
$env:FILM_MATRIX_PORTABLE_ROOT = '<已验证的免安装QA包根>'

```

矩阵脚本每次创建新的 matrix-* 目录；某组失败即停止并保留日志，不把部分通过算作全矩阵通过。可用 FILM_MATRIX_WAIT_BASELINE=1 与基准渲染交错执行，逐模板等待成功结果，仍逐组执行桌面验收。
