公司调用仍经本机 LiteLLM，真实凭证只在忽略的 `config.yaml` 中。Seedream Pro 增加对应代理路由；示例配置同步四款模型。启动补种仅插入缺失的 canonical ID，不覆盖已有连接、模型或启用状态。新增图片供应商单价留空，实际账单未核验。

三款图片模型保留底图在前、参考图在后的顺序，总输入上限 14 张。Banana 强制使用 COS 预签名参考图，配置或上传失败在提交前终止。Kling 2.5 首尾帧按下述腾讯文档补充开放；智能分镜仍不开放。

## Kling 2.5 首尾帧补充（2026-09-29）

腾讯 [Kling 调用指南](https://cloud.tencent.com/document/product/1823/135742) 明确 V2.5 Turbo 支持首尾帧，首尾帧要求 1080p、时长 5/10 秒。[VOD 创建接口](https://cloud.tencent.com/document/api/266/126239) 列出 Kling 2.5 与 `LastFrameUrl` 参数，尾帧 URL 图片要求小于 5 MB。

精确别名 `kling-2.5` 开放 `company-gateway-kling` 能力，API 与 UI 复用已有上传/校验链路；首帧为 `images[0]`、尾帧为 `LastFrameUrl`，`OutputConfig` 显式传 `Resolution=1080P`、`Duration` 与可解析的首帧比例。尺寸探测失败仍发送 1080P；尾帧不放 `images[1]`，不加入智能分镜字段。首尾帧都经 COS，保留本机 LiteLLM 与 COS 失败关闭门禁。

本次验证为官方文档核对及本地模拟请求回归，覆盖精确白名单、5/10 秒请求、首尾帧字段与 COS 门禁；未额外提交真实付费视频，Kling 2.5 的公司网关透传及末帧收束仍待真实任务验证，不能把 Kling 3.0 的历史实测当成 2.5 的实测。

时长补充：`lib/video-duration.ts` 为界面与提交入口提供共享约束，精确 `openai-video + kling-2.5` 仅允许 5/10 秒（单首帧、首尾帧一致）。单条/批量行只展示支持值，批量总控取各行支持值的交集，切换模型调整草稿时长；单条/批量创建 API 拒绝非法值，批量在落库前整批校验，不静默截短。适配器再次拦截，避免旧任务重试绕过限制。回归：`scripts/video-duration.test.mjs`、`scripts/openai-video-adapter.test.ts`。

新建项目按模型展示清晰度：Seedream 不提供 4K。方舟官方还支持 1.5K，本次 UI 沿用工作台已有标准档位，仅开放 1K/2K。Banana 3.1 的 720P 和额外极端画幅同样不加入现有清晰度菜单。图片比例取公司网关现有表与官方支持范围的交集，使用八种常用比例。

## 官方依据

- [腾讯云 VOD 创建 AIGC 图片任务](https://cloud.tencent.com/document/product/266/126240)：GG 3.0/3.1 及参考图约束。
- [腾讯云 VOD 数据结构](https://cloud.tencent.com/document/api/266/31773)：图片 `OutputConfig` 的清晰度与画幅、Kling 视频的 `Resolution` / `Duration`。Kling 默认 720P，因此应用必须显式发 1080P。
- [腾讯云 VOD 创建 AIGC 视频任务](https://cloud.tencent.com/document/api/266/126239)：Kling 2.5 模型版本。
- [火山方舟图片生成 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)：Seedream 5.0 Pro 的 1K/1.5K/2K 档位、JSON `image` 以及推荐的「档位 + 提示词比例」方式。

这些是下游协议依据，公司别名与实际转发是否生效由以下真实调用复核。

## 真实任务结果

经本机临时 LiteLLM 端口 4001、公司 Key、COS 参考图调用；不在用户项目中插入测试任务。测试内容为产品椅子场景图，图片编辑增加蓝色抱枕，视频使用轻微镜头运动。

| 模型 / 请求 | 原始产物 | 验证 |
| --- | --- | --- |
| Kling 2.5，1080P，5 秒 | 1920×1076，H.264，24fps，5.042 秒 | 下载及完整 ffmpeg 解码成功 |
| Nano Banana Pro，4K | 5504×3072 JPEG | 下载及 sharp 解码成功 |
| Nano Banana 2，4K | 5504×3072 JPEG | 下载及 sharp 解码成功 |
| Seedream Pro，具体像素 `1280x720` | 2848×1600 JPEG | 编辑成功，但落入上游默认 2K，不能用于 1K 请求 |
| Seedream Pro，`size=1K` + 提示词 16:9 | 1424×800 JPEG | 成功，最终实现采用此方式 |

Kling 的 1080P 是上游清晰度档位，本次源图比例导致高为 1076，不承诺所有比例都输出 1920×1080。图片采用现有 `nativeDelivery`：只裁齐比例、不缩放到名义像素，保留原生画质。上表记录的是裁切前原始产物；并非每一档、每个比例都做了付费穷举。

原始记录与媒体在本机忽略目录 `outputs/company-model-probe-2026-09-29/`：`integration-results.json`、`seedream-tier-1k.json` 和对应图片/视频。前序测试另已验证两款 Banana 的 2K 产物均为 2752×1536。

上述检查均通过。`npm run build` 生产构建与 standalone 资源同步成功（现有动态文件追踪仍有告警）。桌面应用已重启，正式 4000 代理包含四个模型路由，供应商 API 显示四项均已启用且配置完成，COS 与代理健康状态正常。浏览器实际切换三款图片供应商，确认清晰度菜单分别为 1K/2K、1K/2K/4K、1K/2K/4K；未创建测试项目。临时 4001 代理已停止。
