# 保留轻客户端，集中四类生产模块，本地实拍重组分期接入

为统一多人并发、排错与更新，员工通过工作台轻客户端连接统一生产服务，常规项目、批量生产、详情页智能脚本和创作画布均纳入服务器首版。保留轻客户端是为了支持指定目录自动下载、原设备重连补下载及本机文件操作；主要业务与页面集中提供。本地实拍重组继续由本机 Agent 与本地工作台协作，后续另期接入，以避免把其任务执行责任与交付路径重构同时纳入首版。

## 考虑过的做法

- 浏览器作为唯一员工入口：减少桌面分发，但需要重新限定已确认的本机自动交付体验。
- 员工运行完整本地工作台，中央服务只做管理：保留分散生产及维护负担，不符合本轮集中生产目标。
- 所有功能一次迁移，包括本地实拍重组：可更早统一生产范围，但会同时重开 Agent 队列、工程位置和交付约定。

## 影响

- 复用现有页面与桌面壳，增加连接公共服务的运行形态；窗口退出与公共服务生命周期分开。客户端外壳仍有独立的版本兼容和更新需求。
- 创作画布需要纳入员工身份、文件访问、共享供应商资源和用量控制，不能只把页面部署到服务器。
- 这是对 [9 月 20 日基线](../2026-09-20-轻客户端与服务器统一生产方案梳理.md) 的增量：员工正式入口仍统一提交服务器；本地实拍重组是明确保留的分期例外，不是员工客户端的离线回退模式。
- 保留本地实拍重组延续 [10 月 12 日共识](../superpowers/specs/2026-10-12-实拍重组Skill与五步工作台接入-需求共识.md)。两条路径分别分配可执行的上游并发预算，额度及限流措施核实前先错峰；不能据此承诺已实现全部门所有调用的统一计数。
- 2026-11-02 原型评审更新：负责人明确选择成员“费用额度＋并发上限”，替代此前首版不做金额限制的规则。管理员按人配置月度金额与云端并发，服务端统一准入时执行；等待并发不预留费用，受理不明保留占额，已有调用不因降额而终止。本地 Agent 仍在统计与控制范围之外。
- 服务器从新项目开始，旧项目和素材保留原处；首版不迁移可编辑历史工程，不做双向同步。新服务使用独立数据根，不能复制整个旧库或覆盖旧目录来完成初始化。
- 客户端外壳采用员工一键更新，更新前保存传输状态，重启后可恢复。兼容旧版可暂缓，不兼容时需升级；服务器已接受的任务不因客户端更新停止。
- 本决策记录已确认的目标边界，不代表账号、调度、传输或部署已经实现。完整规则与技术设计方向见 [首版需求共识](../superpowers/specs/2026-11-02-服务器统一生产-需求共识.md)，访谈依据见 [11 月 2 日讨论记录](../2026-11-02-服务器集中部署-重启讨论.md)。
- 目标主机明确为现有内网 Windows Server（3060／64GB）后，已补充 [技术方案](../superpowers/specs/2026-11-02-服务器统一生产-技术方案.md) 和 [实施、部署及验收计划](../superpowers/plans/2026-11-02-服务器统一生产/README.md)；现场参数与性能仍按计划核验。
