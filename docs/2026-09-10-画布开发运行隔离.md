# 画布开发运行隔离

本配置只隔离 macOS 源码开发环境，不决定画布最终作为工作台模块还是独立产品；未制作或部署新安装包。

## 使用

- 网页版：当前目录双击 `start.command` 或 `npm run dev`，地址固定 `http://127.0.0.1:3100`；停止用当前目录 `stop.command`。
- 桌面版：当前目录双击 `start-desktop.command`；源码变更后用 `bash start-desktop.command --rebuild`。停止用当前目录 `stop-desktop.command`。
- `start.sh` / `stop.sh` 转发到对应 `.command`；`npm run dev:desktop` 使用相同隔离入口。
- 网页版与桌面版使用同一份画布数据，启动锁禁止重复运行。端口被占用时拒绝启动，不自动跳到另一端口或打开另一项目。

## 边界

| 项目 | 画布开发版 |
| --- | --- |
| 网页服务 | 127.0.0.1:3100 |
| LiteLLM | 127.0.0.1:4100，当前目录独立 `.venv-litellm` |
| 数据根 | 启动入口明确指定当前画布项目根，覆盖父 shell 遗留值 |
| 模型配置 | 当前目录 `config.yaml` 与 `.env.local`，禁止提交 |
| 供应商连接 | 当前画布 DB 中本机公司路由指向 4100 |
| 桌面服务 | 独立回环随机端口，状态写入画布 `storage/run` |
| 桌面用户目录 | `~/Library/Application Support/CreativeStudioCanvas` |
| 桌面身份 | `Creative Studio Canvas` / `local.creative-studio.canvas`，在单实例锁之前设置 |
| 停止边界 | 监听进程须通过目录归属检查；桌面还须匹配健康接口 instanceId；不扫描原工作台安装目录 |

两个目录共用 Git 对象与分支引用，但源码工作区、node_modules、DB、storage 独立。后续同步 main 仍须独立评估、回归；运行隔离不能阻止主动同步带入代码问题。不得把旧项目 `.next`、`storage/run` 或虚拟环境整体复制进来。更新模型配置时同步检查精确模型路由，不能只看设置页已有供应商。

本次仅调整画布目录已有公司回环路由，不修改原目录数据库。数据库变更前备份：`outputs/canvas-isolation/workbench-before-routing.db`；YAML 备份：`config.yaml.backup-canvas-isolation`，两者均在 Git 忽略范围。复制的原 YAML 缺少七牛可灵及 Seedance 2.5，本次已补齐，沿用既有公司网关连接。

## 验证

- 进程归属与端口工具测试通过。
- 临时双目录真实进程验证：其他目录占用 3100 时不误停，本目录占用时正常停止；原目录数据根环境变量被覆盖。
- 供应商补种、适配器、桌面入口/停止合同、安全检查通过；TypeScript 与生产构建、桌面编译通过。
- 实际桌面服务健康 instanceId 匹配；4100 代理健康 200，模型列表包含两个新增别名；Electron 打开的缓存文件位于独立 Canvas 用户目录。用户确认桌面已显示。
- 网页实际 HTTP 200、代理健康 200；网页停止后 3100/4100 均关闭，排查时记录的三个旧项目进程仍存在。
- 桌面停止实测：私有服务优雅退出，desktop 状态、启动锁均清理，4100 代理关闭；随后重新打开桌面版。
- 未提交付费生成任务；未验证 Windows 或新 DMG/安装包。
