让部署人员拿到新 release 后，按包内说明完成新环境安装、管理员初始化、供应商及资源池配置；员工和管理员找到真实入口，四类模块能够生产、无人打开页面时重启恢复，最终交付可用的轻客户端及更新包。

本轮先交付 spec 和 tickets，不执行代码修复、服务器安装、凭据生成、付费调用或发布。后续 agent 使用各 ticket 的范围和验收标准实施；现场授权与参数由 ticket 12 收敛。

## 3. 范围与产品入口

保持一个 server Web 应用、一个受信 HTTPS origin。员工和管理员使用同一登录页，角色决定导航、可见数据及操作权限；“双端”不意味着两个 Next 服务或两个独立端口。

- 员工：正式轻客户端连接服务器；浏览器可用于部署诊断及网页能力验收，不能代替原生传输与更新的签收。
- 管理员：登录后可到账号、供应商/资源池、任务、错误、用量、公共资源和回收站入口。
- 部署人员：包内说明给出配置、预检、安装、状态、初始化、停止、备份与恢复入口，脚本名称与打包路径一致。
- 常规五步、批量、详情页脚本、画布四类模块均属于首版；缺一不能声明完整交付。

不做 A/B/C 视觉重构、独立管理程序、历史数据库搬迁、实拍重组迁入服务器或绕过 HTTPS/鉴权/执行准入。常规运维继续用受控脚本，不把浏览器扩展为任意命令或远程 shell。

## 4. 行为合同

### R01 资源池可配置且受统一预算约束

提供管理员可操作的配置服务和受控 CLI，07 接入正式 UI。枚举所有调用面实际需要的池及映射；配置结果持久化、重启保留，缺少容量/映射/可信定价时展示可修复原因并阻止新付费步骤。

共享上游容量按已核实账户/配额关系归池；不同模型、不同 Key 或不同供应商记录不能自动获得独立容量。为别名映射至同一真实池保留能力；容量由管理员显式确认，不预置 70 或假定无限。本地预算和其他调用者的份额不能重复分配。

配置变更具有版本/冲突检查，旧操作继续使用其冻结映射和回执身份；减少容量/禁用不会释放已受理或受理不明的占额，不阻断结果收取。凭据只在服务端解析，不输入日志、响应或报告。不得为过测试在 SQL 中手工 seed 生产池。

### R02 一次性凭据与会话

首次/重置凭据只允许消费一次；校验后在同一数据库事务内条件消费并建立改密会话。并发请求最多一个成功；建会话失败回滚消费，不能出现两个有效首次会话。KDF 后仍重新核验凭据版本、账号状态及消费条件，覆盖重置/停用竞争。

首次会话仅有改密/退出等必要权限；成功改密后保留当前会话并撤销其他会话。响应丢失或退出导致无法继续改密时，通过既有受控重置/恢复重新发凭据，UI 给明确引导，不重新启用旧凭据。

### R03 资源软删除与物理清理

建立路由＋方法＋领域语义清单，包括 DELETE 和通过 POST/PATCH 实现的删除。持久生产资源在 server 模式删除后隐藏并可恢复，任务冻结依赖继续可读，新生产不能引用已删除资源。

取消未完成上传、取消任务、撤销会话和移除关联分别维持各自语义；不按 HTTP 动词一刀切。无法安全覆盖的生产资源入口先明确拒绝并提示，不能静默硬删；全部必需资源覆盖后才能通过本项验收。

永久清理由管理员执行，检查跨模块历史版本、共享文件、在途任务和备份 pin；文件与库操作有可重试记录。删除不取消已受理任务，已删项目的结果不自动交付；local 行为保持兼容。

### R04 四模块生命周期与配置

server 按“独占 owner/fence → schema/readiness → 注册恢复 → 恢复 → 启动 worker”顺序接入四类模块。批量、详情页脚本无需页面/API 触发即可恢复。重复 bootstrap/API 访问不创建重复 worker。

部署配置显式声明模块开关，映射到环境；local 默认规则保持原样。关闭模块无 worker，readiness/诊断准确显示状态；用于首版签收的配置必须启用四类模块。维护恢复模式保持禁新付费，不能因补开关自动重提未知调用。

停机沿用统一编排，任务信号、lease、fence 和独立回执日志保持合同；重启只能续查、续下载或恢复已证明可重试的阶段。

### R05 已受理任务的有限权限

新操作使用当前用户状态/权限/预算。已受理结果回收使用持久任务身份和冻结的 scope、资源及版本，独立于登录会话和后续角色变化。

降权、停用、删除资源仍允许收取原受理结果，但不授予新付费阶段或任意跨用户访问；升权不能扩大旧任务的依赖范围。旧记录缺少充分授权证据时进入待核查，不能从当前 admin 身份推导历史全局权限。若需新增字段，采用追加迁移并说明旧记录兼容策略。

### R06 首次安装可靠且可诊断

预检区分“新目录待创建”和“目录不安全/不可写”，支持全新安装；验证目录隔离、release manifest 身份、实际端口与证书/账号条件。应用与 LiteLLM 只绑定回环；HTTPS 入口只对获准内网开放。Caddy 管理端口显式检查或受控配置，不能误占现有服务。

安装在数据根判定通过后创建运行/日志目录，按最小权限准备服务账号访问。外部证书私钥验证账号读取能力；不扩大为全员可读。执行前显示解析计划，dry-run 不修改系统；重复执行只认领本部署可验证对象。

启动后有界等待应用 ready，超时返回失败阶段和脱敏定位信息；“服务进程存在”不等于可用。配置 releaseId、manifest 和目录约定一致，环境写入准确发布身份。半途失败留有可恢复状态，不以清空数据根解决重试。

### R07 正式双端操作闭环

沿用正式应用布局和主题令牌，提供角色导航及可用功能入口：
- 员工：四模块入口、本人任务/错误/用量、回收站恢复、连接与不可用原因。
- 管理员：账号与额度引导、供应商及池映射/容量、按人用量、任务/错误、公共资源发布、回收站与受保护永久清理。
- 备份/维护：显示可获得的真实状态和运维入口说明；危险动作继续由受控脚本完成。备份 pin 与内部屏障不做面向普通用户的原始编辑器。

新账号沿用 CNY、Asia/Shanghai 账期、零额度/零并发策略；创建后明确提示“未开放生成”，引导管理员显式授权。停生成不等于停登录、编辑或下载。
公共资源使用原需求已支持的资源类型，发布/权限/版本均走真实 API；不存在的能力显示未配置或不可用，不能用原型模拟成功。浏览器与轻客户端能力有清楚区分。

### R08 可分发客户端与可信更新

交付稳定 launcher、start-client.cmd、版本负载、固定服务器配置、公钥、签名更新 manifest/ZIP；签名私钥仅在受控发布环境。测试密钥只用于隔离验收。

实现同源 HTTPS 更新托管并接通 capabilities 的受控 manifest URL；目录穿越/任意 URL/密钥暴露被阻止。manifest 发布应在包就绪及校验后完成，旧客户端不会读到半份更新。更新故障保留原状态、下载结果和可回退版本。

正式 origin、证书信任和签名材料未齐备时可以完成代码及测试包，但标记正式产物阻断，不使用测试公钥冒充正式交付。

### R09 每日备份能自动运行

提供显式启用、dry-run、幂等注册和状态检查的每日计划任务入口。参数包含部署身份、运行账号、执行时间/时区与目标根；不假设任务主机时间即账期时区。
作业不依赖交互登录或用户 PATH，重复运行受锁约束；失败告警可定位，保留最近 14 个成功 daily，manual/pre-upgrade 独立。恢复到独立新根，核查完成前禁新付费。首次安装说明须包含启用及验证动作。

### R10 从空环境验证完整交付

隔离验收从空数据根、真实安装配置生成和正式管理接口开始，使用假供应商和测试证书/密钥；不直接写 DB 配池/建策略来绕过缺失入口。四模块至少各有一条可执行链及可核验产物，关闭页面/客户端和服务重启不丢任务。

分别验证隔离、凭据竞争、软删除、授权变更、共享预算、不确定提交禁重提、下载不触发再生产、客户端更新失败恢复和备份恢复。记录实际执行、跳过、失败及证据位置。自动化通过不能代替 SCM/证书/两设备/真实供应商验收。

### R11 发布包可找到入口

生成新 releaseId，不原地修改 3b84378 包或覆盖旧数据。包根提供中文开始说明或只读入口导航，使用包内运行时和实际脚本路径，明确 server 与 client 为不同产物。

提供配置模板和参数说明，未知现场值保持待填写；配置生成先验证再写入受控外部位置。按顺序覆盖校验包、目录配置、预检、安装、ready、初始化管理员、授权额度/池、登录、检查与停止。仅凭包和说明、不依赖源码目录能够走完流程。

白名单显式纳入必要说明/模板；原禁入数据、凭据与其他目录断言保留。交付清单记录 sourceCommit、releaseId、哈希、实际测试和现场缺口。

### R12 现场签收

在获准的独立新根/端口/账号上验证目标服务器副本、SCM、证书、ACL、开机无人登录、RDP 注销、GPU/媒体、可选 LiteLLM 降级、真实供应商和两设备客户端。
完成旧验收矩阵要求的容量、备份恢复及回退，保留完整证据。付费样本先确定模型、素材和预算；未知参数只阻断相关现场步骤，不阻断可独立完成的本地代码工作。
