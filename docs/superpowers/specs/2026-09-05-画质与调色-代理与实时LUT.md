# 画质与调色模块：代理预览打通 + LUT 实时化

日期：2026-09-05
状态：设计已确认（与作者逐轮 grill 后定案），待实现

---

## 1. 背景与问题

「画质与调色」弹窗（`BatchStepMaterials.tsx:498-683`）的后端是完整的：代理执行器
（`lib/batch-production/proxy-executor.ts`，proxy-v1 规格）、代理缓存与请求
（`proxy-cache.ts`）、预览解析（`preview.ts`）、LUT 目录（`lut-catalog.ts`）、
色彩管线（`color-pipeline.ts`）、调度器注册（`bootstrap.ts`）全部就绪，但**从未被真实使用过**
（本机库 `batch_proxy_requests` / `batch_proxy_cache_items` / proxy_generate 任务三张表全空）。
前端接了入口但被门禁锁死，具体问题：

1. **门禁锁死**：弹窗生成按钮和素材卡生成按钮要求"批次有已确认版本且输入未再修改"
   （`BatchStepMaterials.tsx:248-249`；"确认整体输入"在第二步 `BatchStepScripts.tsx:1515`；
   任何输入改动触发 `markInputChanged()` 重新上锁）。用户导入素材后无法直接生成代理。
2. **两个预览入口行为不一致**：素材网格"预览"永远播原片（`BatchPreparationPanel.tsx:843`，
   走 `assets/[assetId]/preview`），冻结池卡片预览才走代理自动解析（同文件 857 行，
   走 `preview/[assetId]`）。
3. **没有手动切换入口**：全库没有"代理/原片"切换控件，徽标只展示状态
   （`BatchPreparationPanel.tsx:1650-1683`）。
4. **弹窗任务列表误导**：列表未按类型过滤（403 行），显示的"已完成 7 条"是
   asset_prepare 分析任务，不是代理任务。
5. **LUT 与代理耦合**：代理键含完整色彩快照，换 LUT 就要重转码；LUT 效果只能等代理
   生成完才能看到，违背调色需要即时反馈的直觉。

## 2. 设计共识（合同，实现不得偏离）

**代理管流畅，LUT 管颜色，两者正交、各自独立开关；预览层全部实时生效，正式渲染路径不变。**

### 代理（低清预览片）

1. 核心诉求是**流畅预览**；不是省磁盘、不是批量工作流硬门槛。
2. 代理**归属素材，不绑批次**。缓存键简化为 `素材 + 原片指纹 + 规格版本`，摘掉色彩快照
   与批次维度。缓存表天然跨批次，只需给请求表追加迁移放宽批次绑定。
3. **手动生成**，三个入口：素材卡常驻按钮（无确认门禁）、播放器内引导按钮（无代理时显示
   "生成低清代理"，完成后自动切换）、弹窗批量按钮。
4. **应用级总开关「低清代理」**：所有播放位共享，控件嵌在各播放器标题栏，localStorage
   持久化，**默认开**；无代理的素材自动回退原片。关 = 全局播原片（核对画质场景）。
5. 播放覆盖面：素材网格预览、编排卡片预览、时间线实时预览统一走代理解析；开关只影响
   播放，不影响分析与正式渲染。
6. **手动清理维持现状**（弹窗两个清理按钮 + 使用计数延后删除），不加自动淘汰。
7. **正式渲染永远用原片**（现有指纹核验保留）；**渲染产物不做代理**。
8. proxy-v1 规格保留不动：高≤720 只缩不放、H.264+yuv420p、CRF26+veryfast、GOP50 固定、
   音频 AAC 128k/48k、MP4+faststart、单并发 FIFO（`proxy-executor.ts:19-56`）。

### LUT（调色滤镜）

9. LUT 从代理里拆出，变成**预览层实时效果**：`.cube` 解析为 WebGL 3D 纹理，播放器 shader
   三线性采样叠加——与 ffmpeg `lut3d trilinear` 同数学。**0 等待、0 磁盘、换 LUT 即点即看**。
10. 接受**"预览 ≈ 成片，成片为准"**：实时预览与正式渲染在色彩空间边界处理上可能有肉眼级
    差别，不追求比特一致，正式渲染仍是唯一基准。
11. LUT 控制保持素材卡现有下拉：选哪个 LUT 即生效、选"无"即关，预览实时刷新；不加全局
    LUT 开关。对比 LUT 效果不再依赖"切原片"。
12. **正式渲染路径不动**：冻结色彩快照 + ffmpeg `lut3d` 烘焙，原样保留。

### 后端退役项

13. 代理规格退回**纯低清版**（滤镜链摘掉 LUT）；代理请求一律不带 LUT。
14. 删除"确认整体输入时自动为 LUT 素材请求代理"的行为（`BatchPreparationPanel.tsx:1062`）。
15. `preview.ts` 的 `original_pending_lut` 暂览分支退役（preview.ts:20、76-83）。
16. 孤儿 LUT 代理文件不专门迁移，由现有手动清理处理（本机库为空，实际无存量）。

## 3. 明确排除（本次不做）

- 自动生成代理、LRU/TTL 自动清理。
- 代理用于分析/正式渲染、渲染产物代理。
- 多级清晰度；时间线实时预览保持"近似参考"定位，不做 4K 全保真。
- 逐素材 LUT 指纹进代理键（随 LUT 维度退役自然消失）。

## 4. 实现方案

### A. 后端

#### A1. 代理键简化（`lib/batch-production/proxy-cache.ts`）

- `computeProxyKey`（proxy-cache.ts:81-92）摘掉 `colorIdentity` 与 `colorPipelineVersion`：
  键 = `{ assetId, contentFingerprint, profileVersion }` 的 sha256。
- `ComputeProxyKeyInput` 同步精简；`colorJson` 列保留（NOT NULL，避免重建 cache 表），
  新请求固定写入 LUT 关闭的默认快照。
- 不需要推进 `PROXY_PROFILE_VERSION`：键简化本身已使全部旧键失配，旧缓存行成为清理候选。
- 更新函数 doc（76-80 行"代理身份"注释）——它描述的是旧行为。

#### A2. 迁移 v25：`batch_proxy_requests` 放宽批次绑定（`lib/batch-production/schema.ts`）

当前约束（schema.ts:650-676）：`batchId` / `batchVersionId` NOT NULL + 外键 +
`UNIQUE(batchVersionId, assetId, proxyKey)`。SQLite 不能 ALTER 列约束，**重建表**：

- `batchId` / `batchVersionId` 改可空，外键保留。
- 唯一约束拆成两个部分唯一索引：
  - `WHERE batchVersionId IS NOT NULL`：`UNIQUE(batchVersionId, assetId, proxyKey)`（批次级行为不变）
  - `WHERE batchVersionId IS NULL`：`UNIQUE(projectId, assetId, proxyKey)`（素材级请求幂等）
- 表级 CHECK：`batchId IS NULL = (batchVersionId IS NULL)`，防止半空脏行。
- 数据搬迁：现存行原样拷贝（本机为空，但迁移必须对任意存量正确）。
- **同步更新 schema.ts:1900-2045 的结构校验断言**（PRAGMA 检查列/外键/索引），否则
  readiness 会误判。
- 走既有 schema-upgrade gate（备份 + 跨进程锁 + 审计），迁移只追加，不改已发布条目。

#### A3. 素材级代理请求 API

- 新建 `app/api/batch-production/assets/[assetId]/proxies/route.ts`：POST 为单个素材创建
  代理请求（batchId/batchVersionId 为 NULL）并排 proxy_generate 任务。**不要求批次存在或
  已确认**。响应与批次级 `batches/[id]/proxies` 对齐（请求 + 任务状态）。
- `proxy-cache.ts` 的请求创建函数放宽批次参数（可空），素材级路径的幂等靠 A2 的部分唯一
  索引，冲突时返回现存请求。
- `tasks.ts:237-261` 的 proxy_generate 谱系校验分两支：批次绑定请求维持现有
  project→batch→version→request 校验；素材级请求只校验 projectId + assetId 归属。
- 批次级 API 保留（弹窗批量按钮继续用），但其请求也改为不带色彩快照（共识 13）。

#### A4. 退役 LUT 代理维度

- `proxy-executor.ts:324`：滤镜链摘掉 `colorFilters`，只留 `scale=-2:min(720\,ih)` +
  `format=yuv420p`；移除 `buildColorFilterFragments` / `COLOR_PIPELINE_VERSION` /
  `upgradeColorSnapshot` 相关 import 与请求冻结色彩快照的重验逻辑；**保留**原片指纹重验、
  磁盘预检、写租约、原子发布。
- `preview.ts`：`PreviewSource` 删除 `original_pending_lut` 分支；
  `ResolvePreviewSourceInput` 删除 `colorSnapshot` / `colorPipelineVersion` 参数；
  解析顺序简化为 代理 → 原片 → 不可用。所有调用方（`preview/[assetId]` 路由等）同步改。
- `BatchPreparationPanel.tsx:1062`：删除确认输入时自动为 LUT 素材请求代理的行为。
- `luts` 路由与 `lut-catalog.ts` 保留（LUT 导入/验证/存储仍是实时预览与正式渲染的来源）。

### B. 前端

#### B1. 代理总开关

- 新 `components/batch-production/proxy-playback-preference.ts`，照抄
  `components/font-preferences.ts` 模式：localStorage key `creative-studio-proxy-playback`，
  `useSyncExternalStore` 快照，同页写入主动通知 + 跨标签页 `storage` 事件同步，**默认开**。
- 播放器标题栏切换控件（代理/原片），嵌在：素材网格预览、冻结池预览、编排抽屉卡片
  （`BatchOutputEditor.tsx:537` 附近）、时间线预览。无代理素材显示"原片"且控件不可切
  （tooltip 引导生成）。
- 开关只决定 `resolvePreviewSource` 结果与素材预览 URL 的取用，不影响任何后端行为。

#### B2. 门禁拆解与按钮常驻（`BatchStepMaterials.tsx`）

- 删除 248-249 行 `inputConfirmed` 门禁：弹窗两个批量按钮、素材卡生成按钮（472 行附近）
  不再要求"已确认整体输入"，改为始终可用。
- 素材卡按钮文案按状态切换：无代理"生成低清代理" / 生成中显示进度 / 已有代理显示
  "重新生成"（原片指纹变了才需要）+"已就绪"。
- 弹窗任务列表（403 行）按 `workType === 'proxy_generate'` 过滤，不再混入分析任务。

#### B3. 预览入口统一

- 素材网格"预览"（`BatchPreparationPanel.tsx:843`）改走 `preview/[assetId]` 代理解析，
  与冻结池卡片（857 行）一致；总开关关时强制原片。
- 播放器空状态放"生成低清代理"引导按钮（共识 3）：点击调 A3 的素材级 API，轮询任务
  完成后自动切到代理源。

### C. WebGL 实时 LUT

#### C1. `.cube` 解析与纹理（纯逻辑，可单测）

- 新 `components/batch-production/lut-3d.ts`：解析 .cube（SIZE + 数据体，兼容注释/空行/
  DOMAIN 头）为 `Float32Array`；上传为 WebGL2 3D 纹理（`texImage3D`），shader 内
  `texture()` 采样即硬件三线性，与 ffmpeg `lut3d trilinear` 同数学。
- WebGL2 不可用时回退"无 LUT 预览 + 提示"，不引入 WebGL1 模拟路径（保持简单）。
- LUT 文件来源：现有 `luts` 路由的下载端点；按 lutId 缓存解析结果。

#### C2. 播放器包装组件

- 新 `LutVideoPlayer`：包 video + 叠加 WebGL canvas，`requestVideoFrameCallback` 逐帧
  采样；无 LUT 或开关关时直通（不创建 GL 上下文，零成本）。
- 覆盖播放面：素材网格预览、冻结池预览、编排抽屉卡片。
- 素材卡 LUT 下拉（现有）变更即切换纹理，预览实时刷新。

#### C3. 时间线实时预览（`BatchTimelinePreview.tsx`）

- 现状：2 个隐藏 video + canvas 2D 逐帧合成（272 行）。
- LUT 是素材级设置，逐片段可能不同：每个 video 帧先过各自 LUT（离屏 WebGL canvas
  逐段处理）再进 2D 合成管线。实现时验证性能（720p 代理下逐帧 GL 采样成本低；
  原片 4K 无代理时允许掉帧降级并提示"生成代理以获得流畅调色预览"）。

### 8.6 高欺骗风险点（reviewer 重点盯）

1. **测试真实性**：要求实现者贴测试命令的完整输出；缺失视为未做。
2. **死代码冒充退役**：功能删除后，残留的无人调用函数/分支/类型（如旧色彩入参、
   暂览分支的幽灵类型）必须一并清除；用 `npx tsc --noEmit` + grep 双重确认。
3. **门禁假拆**：把 `inputConfirmed` 恒置 true、或把校验挪到更隐蔽处，都算未拆。
4. **幂等假实现**：素材级请求若靠先查后插，并发双击会产生重复请求——审查事务边界。
5. **键简化半途而废**：proxyKey 里若仍掺着色彩身份的任何成分（lutId、快照哈希、
   管线版本），换 LUT 会静默失配代理，违反共识 9/13。
6. **开关外泄**：代理开关若被写进批次输入身份/快照，会让"确认整体输入"幂等性出现
   幽灵变化——检查 `matchesCurrentInput` / `createBatchSnapshot` 无相关改动。
7. **预览路径私搭**：前端绕过 `preview/[assetId]` 自行拼代理文件 URL，会跳过
   pendingDelete/租约保护——grep `cache/proxies` 应只命中服务端代码。
