# 脚本生成 V3 产品需求文档（PRD）

> 日期：2026-07-27  
> 状态：评审稿，待确认后进入技术设计与实施  
> 产品位置：Creative Studio 第三步 `脚本生成`，并与第五步 `智能混剪` 联动  
> 关联基线：脚本生成 V2、智能混剪 V1/V2、现有 `final_edit_*` 工作流

## 0. 文档效力

本文件定义“脚本生成 V3”的产品范围、用户流程、数据语义、兼容边界和验收标准，重点解决以下三个已确认问题：

1. 第三步提前理解分镜图片并逐句绑定画面，与第五步智能混剪对真实视频素材的理解和匹配重复，且前者质量更低。
2. 用户选择 15 秒等目标时长后，脚本文案仍可能明显超量，真实 TTS 和最终成片可达到 25 秒以上。
3. 脚本只稳定提供单一标题，智能混剪只能机械拆分，不能保证每份脚本都拥有语义合理的主标题和副标题。

文档优先级：

1. 用户流程、产品行为和验收标准以本 PRD 为准。
2. 后续技术设计负责确定具体模块、接口、迁移和任务执行细节，不得改变本 PRD 的产品口径。
3. 旧脚本 V2 和已创建的智能混剪草稿继续兼容；不得为了 V3 静默改写历史内容或覆盖用户修改。

## 1. Problem Statement

### 1.1 视觉理解职责重复

当前脚本流程先分析卖点、目标人群和平台，再由用户选择卖点、模板、时长和分镜组。生成脚本时，多模态模型会同时：

- 理解候选分镜图片；
- 选择和排序图片；
- 写口播；
- 将一句口播绑定一张图片；
- 输出画面理由和未使用分镜。

进入智能混剪后，系统又会对真实视频素材做场景分析，并基于真实 TTS 时间、场景语义和素材质量重新匹配画面。

这造成两个问题：

- 同一项画面决策被做了两次，增加生成成本和用户理解成本。
- 第三步基于静态分镜的低质量绑定会作为先验影响第五步，可能削弱智能混剪对真实视频素材的判断。

### 1.2 目标时长不是可执行约束

当前目标时长主要作为提示词和草稿元数据存在。模型返回后，系统不会校验内容字符数或预计朗读时长；真实 TTS 完成后，也不会因为明显超时而自动修正或阻断。

本地真实案例中：

- 用户选择目标总时长 15 秒；
- 脚本含 116 个原始字符、106 个去标点后的内容字符；
- 1.0x 真实 TTS 为 24.75 秒；
- 最终成片为 25.58 秒。

同一文案在不同已配置 TTS 下，1.0x 的真实语速约为每秒 4.2～4.4 个中文内容字符。由此可见，10 秒级偏差主要来自脚本超写和缺少硬门禁，而不是 TTS 的随机波动。

### 1.3 封面标题生成过晚且不可控

脚本数据结构允许保存主标题和副标题，但当前生成契约没有强制要求模型返回。智能混剪只能在创建草稿时把单一标题按标点或中点机械拆成两段。

机械拆分可以保证字段存在，却不能保证：

- 主标题具备吸引力；
- 副标题提供产品证据；
- 两段语义完整、不重复；
- 长度适合封面安全区和单行展示。

## 2. Solution

脚本生成 V3 将第三步重新定义为“内容策略与口播生产”，将第五步智能混剪定义为“真实素材理解与剪辑决策”的唯一负责人。

V3 的核心方案：

1. 卖点分析继续结合目标人群和平台，但不分析图片。
2. 脚本生成不再选择、排序或逐句绑定具体分镜；只生成带自然标点的口播、抽象画面意图和匹配关键词，字幕显示文本由系统确定性派生。
3. `shotSetId` 继续保留，专门负责脚本与素材组的上下文隔离，不代表逐句画面绑定。
4. 智能混剪根据真实视频分析、真实 TTS 时间和语义矩阵完成最终画面匹配。
5. 目标时长升级为贯穿“脚本预计时长 → 真实 TTS 时长 → 最终成片时长”的硬约束。
6. 每份新脚本必须生成语义独立的主标题和副标题；服务端保留确定性兜底，保证新旧脚本始终可获得两段标题。
7. 口播与字幕采用双文本策略：TTS 和对齐使用带标点口播，屏幕字幕在切句和对齐后去除展示标点。

## 3. 产品目标

### 3.1 核心目标

1. 用户选择 15、20、30、45 或 60 秒后，系统生成与目标总时长相符的口播，而不是只展示一个无约束的时长标签。
2. 第三步不再用较弱的静态图片理解决定最终剪辑画面。
3. 智能混剪对实际视频素材的分析和匹配结果成为画面编排的唯一自动决策来源。
4. 所有脚本在生成、复制、下载和进入智能混剪时都具有明确的主标题和副标题。
5. 新能力不破坏历史 V2 脚本、历史成片组、用户手动修改过的文案和封面。
6. 自动生成的屏幕字幕不显示多余标点，但 TTS 仍保留自然停顿和语气。

### 3.2 成功指标

- 100% 新生成的 V3 脚本包含非空主标题和副标题。
- 100% V3 脚本段落不包含自动生成的具体 `shotId` 绑定。
- 新生成的 15 秒脚本不再出现未经提示直接导出为 25 秒的情况。
- 在用户未明确选择“按实际时长继续”时，最终成片不得静默超出目标时长容差。
- V3 脚本进入智能混剪后，仍能按同一 `shotSetId` 使用模块 4 素材，并完成语义匹配。
- 历史 V2 脚本和已创建的智能混剪组仍可打开、编辑和导出。
- 100% 由脚本自动生成的新字幕 Cue 不以逗号、句号、问号、感叹号或分号结尾。

## 4. 非目标

本 PRD 不包含：

- 重写智能混剪的视频分析、场景检测、语义矩阵或全局匹配算法。
- 改变模块 4 的图片转视频生成流程。
- 新增 TTS 供应商、音色或鉴权协议。
- 用超过 1.15x 的自动加速强行压缩超长文案。
- 自动跨分镜组寻找或补充素材。
- 删除历史脚本、历史数据库字段或已生成成片。
- 自动重写已经被用户手工修改的智能混剪文案或封面标题。
- 新增模板市场、模板编辑器或复杂封面动画。
- 从 TTS 口播、强制对齐文本或内部句段边界中移除标点。

## 5. 核心产品原则

1. **文案与画面解耦**：第三步决定“说什么”，第五步决定“配什么画面”。
2. **真实素材优先**：最终画面选择只能基于真实视频素材，而不是静态分镜的早期判断。
3. **音频是剪辑主轴**：字幕、视频和 BGM 围绕真实 TTS 时间组织。
4. **目标时长是总时长**：用户选择的时长指最终成片总时长，包含封面，不只指脚本提示词中的模糊时长。
5. **先预计、后实测**：脚本阶段用校准语速控制内容预算，TTS 阶段用真实音频时长做最终门禁。
6. **不静默修坏内容**：压缩、扩写、改速和超时继续都必须有明确状态；不能为了满足时长直接截断句子。
7. **两段标题是正式产物**：主标题和副标题是脚本输出契约，不是智能混剪临时推导字段。
8. **口播与字幕分层**：口播保留标点保证 TTS 韵律和可靠切句，自动字幕去除展示标点保证画面简洁。
9. **历史数据只兼容、不回写**：旧数据按原行为读取；新能力通过新脚本版本提供。

## 6. 用户与核心任务

主要用户是需要批量制作产品短视频的内容制作人员。

核心任务：

> 输入产品卖点、人群和平台，选择模板与目标总时长，获得一份时长可控、主副标题完整、屏幕字幕无多余标点、能直接进入智能混剪并由真实素材自动配画面的口播脚本。

## 7. 详细需求

### 7.1 三阶段工作流

脚本生成继续保持三个用户阶段：

1. `输入卖点与受众信息`
2. `策略配置`
3. `脚本结果`

#### 7.1.1 第一阶段：卖点分析

输入：

- 产品卖点；
- 目标人群；
- 平台；
- 分析模型。

AI 输出：

- 卖点优先级和理由；
- 人群洞察；
- 平台建议；
- 综合推荐模板及推荐理由。

要求：

- 本阶段不读取、上传或分析分镜图片。
- 推荐模板应基于全部卖点、人群和平台形成一个综合建议，不再只在每条卖点下分散显示互相冲突的模板建议。
- 综合推荐模板默认被选中，用户仍可手动更换。
- 默认勾选优先级最高的卖点，但用户拥有最终选择权。

#### 7.1.2 第二阶段：策略配置

用户确认：

- 需要使用的卖点；
- 脚本模板；
- 目标总时长；
- 当前分镜组；
- 脚本生成模型。

要求：

- 目标总时长继续提供 15、20、30、45、60 秒选项。
- 时长控件旁明确说明“包含封面；实际正文预算会自动扣除封面时长”。
- 选中 15 秒时，应显示类似“预计口播正文约 14.2 秒”的提示。
- 分镜组必须选择，保证后续模块 3、模块 4 和智能混剪处于同一 `shotSetId`；它不再用于逐句绑定图片。
- 生成前显示预计内容字符范围，帮助用户理解短时长无法容纳过多卖点。
- 当用户选择的卖点数量明显超过时长容量时，生成前给出提示，允许用户减少卖点或让 AI 自动聚合表达。

#### 7.1.3 第三阶段：脚本结果

结果页展示：

- 脚本名称；
- 封面主标题；
- 封面副标题；
- 平台、语气、模板和目标总时长；
- 内容字符数；
- 预计口播时长；
- 时长状态；
- 分段口播、无标点字幕、使用卖点、抽象画面意图；
- 完整配音稿（保留标点，可展开查看）；
- 完整字幕稿（默认展示，不含展示标点）；
- 复制、TXT 下载和 JSON 下载。

V3 结果页不再展示：

- 每段绑定的具体分镜图片；
- “为什么使用这张图片”的画面理由；
- “未使用的分镜”列表；
- 由脚本模型决定的素材顺序。

### 7.2 V3 脚本契约

每份 V3 脚本至少包含以下业务字段：

| 字段 | 要求 |
|---|---|
| 脚本版本 | 固定为 V3，用于与历史 V2 区分 |
| 脚本名称 | 用于草稿列表和文件名，不等同于封面标题 |
| 主标题 | 必填，面向封面展示 |
| 副标题 | 必填，面向封面展示 |
| 平台、语气、模板 | 保存本次生成策略 |
| 目标总时长 | 用户选择的最终成片目标时长 |
| 目标正文时长 | 目标总时长扣除封面后的正文预算 |
| 内容字符数 | 去除标点、符号和空白后的可朗读内容计数 |
| 预计口播时长 | 根据校准语速计算的预计值 |
| 分镜组 | 当前 `shotSetId`，只负责上下文隔离 |
| 脚本段落 | 包含稳定段落 ID、带标点口播、派生字幕文本、卖点引用、画面意图和画面关键词 |
| 完整配音稿 | 必须由标准化后的带标点段落口播顺序派生，不信任模型单独返回的另一份全文 |
| 完整字幕稿 | 必须由标准化后的字幕 Cue 顺序派生，不由模型自由生成 |

V3 段落禁止包含自动生成的具体素材绑定：

- 不保存具体 `shotId`；
- 不保存具体图片 ID；
- 不声明某一句必须使用某张图；
- 不输出未使用素材列表。

抽象画面意图示例：

- `靠背承托状态特写`
- `人物下班后放松使用场景`
- `皮面材质与走线细节`

这些信息只用于帮助智能混剪理解内容，不拥有素材选择权。

### 7.3 文案与真实素材的职责边界

#### 7.3.1 第三步负责

- 卖点取舍；
- 平台、人群和语气适配；
- 模板叙事结构；
- 口播与字幕；
- 时长预算；
- 抽象画面意图和关键词；
- 主标题与副标题。

#### 7.3.2 第五步负责

- 读取当前 `shotSetId` 下的真实视频素材；
- 场景切分和真实时长探测；
- 画面描述、标签、卖点和质量分析；
- 基于真实 TTS 时间进行语义评分；
- 全局选择素材、场景和源时间段；
- 节拍吸附、复用约束、缺口和人工锁定；
- 最终时间线和成片渲染。

#### 7.3.3 自动匹配规则

- V3 脚本进入智能混剪后，不使用历史分镜绑定先验。
- 自动匹配以真实素材语义、质量、可用时长、复用限制和首镜头吸引力为依据。
- 用户的显式手动锁定继续拥有最高优先级。
- V2 历史脚本可以继续保留原有弱分镜先验，以避免历史行为突然变化。
- 无法匹配的句段必须显示真实缺口和原因，不得回退到其他 `shotSetId`。

### 7.4 目标时长语义

#### 7.4.1 总时长口径

用户选择的 `目标时长` 指最终成片总时长：

> 最终总时长 = 封面时长 + 真实 TTS 正文时长

当前封面为 20 帧、输出为 24fps，即约 0.83 秒。产品文案显示可四舍五入，但预算计算必须使用实际帧数，不得写死为整数 1 秒。

当用户选择 15 秒时：

- 目标总时长：15 秒；
- 目标正文时长：约 14.17 秒；
- 口播、字幕和视频正文均围绕约 14.17 秒组织。

#### 7.4.2 内容字符口径

内容字符数只统计实际朗读内容：

- 中文、英文、数字计入；
- 标点、符号、空白和换行不计入；
- 数字、英文缩写和特殊参数仍可能产生不同朗读耗时，预计值必须保留安全余量。

脚本阶段使用校准后的中文语速估算。没有足够历史样本时，1.0x 默认采用保守值，不得继续使用“25 个中文字固定等于 5 秒”的单一假设。

基于当前真实样本，15 秒总时长、1.0x 语速的脚本建议控制在约 55～60 个中文内容字符；具体预算由当前校准值和安全余量计算。

#### 7.4.3 脚本生成门禁

模型首次返回后，系统必须：

1. 从标准化段落重新派生完整口播稿；
2. 计算内容字符数；
3. 计算预计口播时长；
4. 检查主标题和副标题；
5. 检查段落、卖点和模板结构。

预计口播时长应落在目标正文时长的 90%～100% 内。

- 超过 100%：要求模型精简，不得直接保存超量草稿。
- 低于 90%：要求模型在不引入新卖点的前提下补足表达。
- 每次生成最多自动修正两次。
- 两次后仍不合格时，显示明确失败原因、实际字符数和目标字符范围；不得把不合格结果伪装成成功脚本。
- 自动修正必须重写完整自然句，不允许从字符串末尾硬截断。

#### 7.4.4 真实 TTS 门禁

进入智能混剪并选择真实 TTS 音色和语速后，系统必须以探测到的真实音频时长重新检查。

允许容差：

> `max(0.5 秒, 目标总时长的 5%)`

例如：

- 15 秒目标允许约 ±0.75 秒；
- 30 秒目标允许约 ±1.5 秒；
- 60 秒目标允许约 ±3 秒。

处理规则：

1. 在容差内：正常进入素材匹配和预览。
2. 超出容差：停止进入最终匹配，显示目标、预计、实际和偏差。
3. 系统提供一次“智能贴合时长”，按真实偏差压缩或补足文案，并重新合成 TTS。
4. 自动贴合优先修改文案，不静默修改用户选择的音色和语速。
5. 如果计算出的加速需求超过 1.15x，不得建议仅靠加速解决。
6. 自动贴合后仍超限：用户可以继续精简/补足、手动修改语速，或明确选择“按实际时长继续”。
7. 只有用户明确选择“按实际时长继续”后，系统才可用超出目标的真实时长生成成片，并在导出前再次提示。

#### 7.4.5 用户编辑后的时长状态

- 用户在智能混剪中修改口播后，原预计时长立即标记为失效并重新估算。
- 文案发生变化后，不得复用旧 TTS 作为正式时长依据。
- 重新生成 TTS 后再次执行真实时长门禁。
- 用户只修改封面、字幕样式或画面时间线时，不触发文案时长重算。

### 7.5 两段式封面标题

#### 7.5.1 标题职责

- `脚本名称`：用于草稿列表识别和下载文件名，可以较完整。
- `主标题`：承担情绪钩子、核心利益点或用户痛点。
- `副标题`：承担产品证据、关键参数或补充承诺。

三者相互独立。脚本名称不得被直接当作唯一封面标题。

#### 7.5.2 生成规则

每份 V3 脚本必须返回两段标题：

- 主标题建议 4～10 个中文字符；
- 副标题建议 6～14 个中文字符；
- 两段都必须非空；
- 不得包含换行；
- 不得完全重复；
- 不得只是把一个完整词语从中间切断；
- 副标题应补充主标题，而不是换一种说法重复主标题；
- 标题不得包含文案和卖点中没有依据的承诺。

示例：

- 主标题：`下班就该这样躺`
- 副标题：`5芯软弹·112°稳稳承托`

#### 7.5.3 服务端兜底

- 如果模型漏掉任一标题，服务端根据脚本名称和核心卖点生成或确定性拆分。
- 如果只能机械拆分，结果必须标记为“系统拆分”，方便用户识别和修改。
- 新脚本保存前必须保证两段均非空。
- 历史脚本在读取和展示时可以派生两段标题，但不得静默修改原始草稿 JSON。

#### 7.5.4 与智能混剪联动

- 创建新的智能混剪组时，直接复制脚本的主标题和副标题形成组级快照。
- 脚本后续重新生成或修改，不得覆盖已经创建的成片组标题。
- 用户在封面编辑器中手工修改后，任何上游同步都不得覆盖其修改。
- 主标题和副标题继续使用独立的文字、颜色、字号、正斜体、描边和位置设置。

### 7.6 无标点字幕显示

#### 7.6.1 双文本职责

同一段内容保留两种用途明确的文本：

- `配音口播`：保留逗号、句号、问号、感叹号、分号等自然标点，用于 TTS、停顿、句段拆分、强制对齐和语义匹配。
- `字幕显示文本`：从配音口播确定性派生，用于脚本结果页、字幕 Cue、预览和最终导出；默认不显示语言标点。

脚本模型只负责生成配音口播。字幕显示文本不得作为第二份独立文案交给模型自由改写，以免出现口播与字幕内容不一致。

#### 7.6.2 处理时机

字幕去标点必须发生在：

1. 带标点口播完成自然切句；
2. TTS 完成并取得真实时间；
3. 字幕完成句段或 Cue 边界计算；
4. 写入自动字幕 Cue 之前。

不得在 TTS、切句或强制对齐之前删除标点，否则会造成语气变平、停顿丢失、长句难拆和字幕时间边界变差。

#### 7.6.3 显示规范化规则

自动字幕按以下顺序处理：

1. 句号、问号、感叹号、分号等句尾标点用于确定边界后直接移除，不在字幕末尾留下空格。
2. 逗号、顿号、冒号等句中停顿优先作为 Cue 拆分边界；如果仍位于同一个 Cue 内，则替换为一个半角空格。
3. 引号、书名号和成对括号不显示；去除后不得吞掉括号内部正文，必要时以一个空格分隔相邻内容。
4. 连续空格合并为一个，去除 Cue 首尾空格。
5. 规范化后为空的 Cue 不得保存。
6. 自动字幕不得以语言标点或空格结尾。

示例：

- 配音口播：`忙碌一天回到家，只想陷进这26斤满铺鹅毛的怀抱。`
- 自动字幕 Cue 1：`忙碌一天回到家`
- 自动字幕 Cue 2：`只想陷进这26斤满铺鹅毛的怀抱`

#### 7.6.4 必须保留的语义符号

“无标点字幕”只移除语言表达中的展示标点，不得破坏参数、比例、型号和单位。

默认保留：

- 小数点：`3.5cm`
- 百分号：`20%`
- 角度：`112°`
- 比例：`9:16`
- 范围：`5～8小时`、`5-8小时`
- 产品型号：`A-01`
- 单位组合中具有实际含义的符号

如果无法可靠判断某个符号是否属于参数，优先保留并在字幕编辑器中允许用户修改，不得把 `3.5` 错误变成 `3 5`。

#### 7.6.5 用户手工字幕

- 脚本来源或自动重新生成的字幕默认执行无标点规范化。
- 用户在智能混剪字幕编辑器中手工输入的文本按用户原文保存；如果用户主动加入标点，不得在保存或导出时再次静默删除。
- 已标记为手工修改的字幕 Cue 不得被重新生成或上游脚本同步覆盖。
- 提供“恢复自动字幕”时，才重新应用无标点规范化规则。

#### 7.6.6 结果页与智能混剪

- 脚本结果页默认显示无标点字幕稿。
- 带标点配音稿作为可展开内容保留，便于检查 TTS 语气和停顿。
- 智能混剪在创建自动字幕 Cue 时执行同一套规范化规则，预览和最终渲染不得各自实现不同规则。
- 历史 V2 脚本创建新的智能混剪组时也使用该规则；已经创建的历史组不批量重写字幕。

### 7.7 复制与下载

#### 7.7.1 一键复制

默认按钮命名为 `复制字幕稿`，复制内容依次包含：

- 脚本名称；
- 封面主标题；
- 封面副标题；
- 完整无标点字幕稿。

另提供 `复制配音稿`，复制带自然标点的完整口播，供外部 TTS 或人工审阅使用。

不得把画面理由、具体素材 ID 或内部诊断信息混入面向用户的复制文本。

#### 7.7.2 TXT 下载

TXT 至少包含：

- 脚本策略摘要；
- 主标题与副标题；
- 目标总时长、预计口播时长和内容字符数；
- 完整配音稿；
- 完整无标点字幕稿；
- 分段口播、字幕、卖点和抽象画面意图。

#### 7.7.3 JSON 下载

- 新脚本导出完整 V3 契约。
- 历史 V2 脚本保持其原始版本标识，同时允许在展示层提供派生的主副标题。
- 下载内容不得包含图片 base64、API Key 或供应商鉴权信息。

### 7.8 错误和状态文案

以下状态必须对用户可见：

- `时长合格`
- `预计偏长，正在精简`
- `预计偏短，正在补足`
- `模型两次修正后仍未达到时长要求`
- `真实 TTS 时长超出目标`
- `文案修改后需要重新生成配音`
- `主副标题由系统拆分，建议检查`
- `已明确按实际时长继续`

错误信息必须包含可行动信息，例如目标字符范围、当前字符数、目标秒数和实际秒数。

## 8. User Stories

1. 作为内容制作人员，我希望卖点分析只关注卖点、人群和平台，以便得到清晰的内容策略，而不是被低质量图片理解干扰。
2. 作为内容制作人员，我希望分析结果给出一个综合推荐模板，以便不必从每条卖点的不同建议中自行猜测。
3. 作为内容制作人员，我希望推荐模板默认被选中但仍可更换，以便提高效率又保留控制权。
4. 作为内容制作人员，我希望目标时长明确表示最终成片总时长，以便正确理解 15 秒设置的含义。
5. 作为内容制作人员，我希望看到扣除封面后的正文预算，以便知道脚本实际可以朗读多久。
6. 作为内容制作人员，我希望生成前看到建议字符范围，以便理解卖点数量与时长之间的冲突。
7. 作为内容制作人员，我希望 AI 自动聚合过多卖点，以便短视频不会变成参数堆砌。
8. 作为内容制作人员，我希望脚本模型只负责写口播，不提前决定具体画面，以便最终剪辑使用真实视频素材做判断。
9. 作为内容制作人员，我希望每个脚本段落提供抽象画面意图，以便智能混剪理解希望表达的视觉方向。
10. 作为内容制作人员，我希望脚本仍绑定当前分镜组，以便不同产品或场景的素材不会混在一起。
11. 作为内容制作人员，我希望系统在保存前检查文案长度和预计时长，以便避免 15 秒脚本实际朗读 25 秒。
12. 作为内容制作人员，我希望超长文案被自然重写，而不是从末尾直接截断，以便口播保持完整。
13. 作为内容制作人员，我希望模型连续修正失败时看到明确原因，以便决定减少卖点或调整目标时长。
14. 作为内容制作人员，我希望智能混剪用真实 TTS 时长进行第二次检查，以便不同音色和停顿不会破坏目标时长。
15. 作为内容制作人员，我希望轻微或严重超时被区别处理，以便系统不会用极快语速强行压缩长文案。
16. 作为内容制作人员，我希望超时后可以一键智能贴合，以便减少手工删改文案。
17. 作为内容制作人员，我希望系统不静默改变已选择的音色和语速，以便保持预期听感。
18. 作为内容制作人员，我希望必要时可以明确选择按实际时长继续，以便特殊内容不被硬性限制。
19. 作为内容制作人员，我希望修改口播后立即看到预计时长失效，以便知道需要重新生成配音。
20. 作为内容制作人员，我希望每份脚本都有独立主标题和副标题，以便直接进入智能混剪封面编辑。
21. 作为内容制作人员，我希望主标题负责吸引、副标题负责证明，以便封面信息层级更清晰。
22. 作为内容制作人员，我希望系统在模型漏标题时自动兜底，以便任何脚本都不会出现空标题。
23. 作为内容制作人员，我希望知道标题是 AI 正常生成还是系统机械拆分，以便优先检查低质量结果。
24. 作为内容制作人员，我希望脚本结果页直接显示主副标题，以便进入智能混剪前先完成审核。
25. 作为内容制作人员，我希望复制和下载内容包含主副标题，以便在外部工具中继续使用。
26. 作为内容制作人员，我希望智能混剪直接继承主副标题，以便不用再次手工拆分。
27. 作为内容制作人员，我希望已经手工修改过的封面标题不被上游脚本覆盖，以便保护我的编辑结果。
28. 作为内容制作人员，我希望 V3 不显示具体分镜绑定和未使用分镜，以便结果页聚焦文案质量。
29. 作为内容制作人员，我希望智能混剪对 V3 完全按真实素材语义匹配，以便较弱的静态图判断不再影响成片。
30. 作为老项目用户，我希望历史 V2 脚本仍可打开和使用，以便升级不会破坏已有工作。
31. 作为老项目用户，我希望历史成片组保持原样，以便已经确认的配音、字幕、时间线和封面不会变化。

33. 作为系统管理员，我希望下载内容不包含图片原文或鉴权信息，以便本地数据和 API Key 保持安全。
34. 作为内容制作人员，我希望屏幕字幕不显示句号、逗号等语言标点，以便字幕画面更简洁。
35. 作为内容制作人员，我希望 TTS 配音稿继续保留标点，以便声音仍有自然停顿和语气。
36. 作为内容制作人员，我希望字幕先按标点切分再去除标点，以便字幕边界自然，而不是每固定字数生硬切开。
37. 作为内容制作人员，我希望 `3.5cm`、`20%`、`112°` 和 `9:16` 等参数不被错误拆开，以便字幕不改变产品信息。
38. 作为内容制作人员，我希望默认一键复制无标点字幕稿，同时仍能单独复制带标点配音稿，以便适配不同外部用途。
39. 作为内容制作人员，我希望手工加入的字幕标点被保留，以便自动规则不会覆盖我的明确修改。
40. 作为老项目用户，我希望用历史脚本新建成片时也能得到无标点字幕，但已有成片组不被批量改写。

## 9. Implementation Decisions

### 9.1 版本与兼容

- 新生成脚本使用 V3 契约。
- 历史 V2 脚本继续通过兼容读取路径进入智能混剪。
- 不对历史脚本执行批量数据迁移，不重写原始草稿。
- 已创建的智能混剪组继续使用创建时的脚本、TTS 和封面快照。

### 9.2 供应商适配

- 所有脚本供应商共享同一份 V3 输入和输出契约。
- 原生 Gemini、OpenAI Chat Completions 和 OpenAI Responses 路径必须得到一致的标准化结果。
- 供应商返回内容不能直接被信任；时长、标题和全文都由统一标准化层验证。
- V3 脚本生成默认不向模型发送候选分镜图片，不再要求供应商具备视觉能力。

### 9.3 时长预算

- 目标总时长是唯一用户时长来源。
- 目标正文时长根据当前封面实际帧数和输出帧率派生。
- 字符预算采用可校准的语速参数和安全余量，不在各供应商提示词中复制多套计算逻辑。
- 脚本生成阶段最多自动修正两次；真实 TTS 阶段最多提供一次自动贴合重合成。
- 真实 TTS 超限不允许静默进入最终渲染，除非用户明确接受实际时长。

### 9.4 标题规范化

- 主标题和副标题在 V3 中为必填字段。
- 标题标准化由共享规则负责，保证非空、单行、长度合理和语义不完全重复。
- 历史脚本缺失时使用兼容拆分，但只在展示或新组快照中派生。

### 9.5 智能混剪联动

- V3 段落不携带具体分镜绑定，因此不会触发旧的同分镜自动匹配先验。
- V2 段落继续保留旧先验，确保兼容性。
- 手动素材锁定与用户时间线修改继续高于自动结果。
- 真实 TTS 时长门禁位于素材语义匹配之前，避免为最终会被重写的音频浪费完整匹配计算。

### 9.6 字幕文本分层

- 带标点口播是 TTS、强制对齐、句段拆分和语义匹配的标准文本。
- 自动字幕文本是从标准口播和已经确定的 Cue 边界派生的显示文本。
- 字幕规范化使用一套共享规则，同时服务脚本结果页、智能混剪预览、字幕画布和最终渲染。
- 自动字幕不得信任模型独立返回的另一份改写文本。
- 标准化必须区分语言标点和数字、单位、比例、型号中的语义符号。
- 手工字幕继续按现有人工修改保护规则保存，不被自动规范化二次覆盖。

### 9.7 持久化与安全

- 脚本草稿继续本地持久化。
- 输入快照记录生成时的卖点、平台、人群、模板、目标时长、字符预算和使用模型，便于追溯。
- 不在日志、下载文件或前端响应中保存 API Key、鉴权头或图片 base64。
- 真实供应商验收涉及项目文案、媒体衍生信息和外部调用，必须在执行前取得明确授权。

## 10. Testing Decisions

### 10.1 测试原则

- 优先测试用户可观察行为和持久化结果，不锁定提示词的具体措辞。
- 使用最高可行接缝覆盖“请求 → 供应商响应 → 标准化 → 草稿入库”。
- 使用智能混剪工作区接缝覆盖“草稿 → TTS → 真实时长门禁 → 素材匹配”。
- 浏览器测试只覆盖关键交互和状态，不重复底层纯函数断言。
- 真实供应商、真实 TTS 和真实 FFmpeg 验收必须与模拟测试分层报告。

### 10.2 脚本生成主接缝

通过脚本生成 API 的完整请求路径，模拟供应商返回并验证：

- V3 草稿成功入库；
- 不需要视觉能力或图片输入；
- 分段不含具体素材绑定；
- 完整口播稿由分段派生；
- 无标点字幕稿由带标点口播确定性派生，不信任模型独立字幕；
- 主副标题均非空；
- 15 秒目标的超长返回触发自动精简，而不是直接成功；
- 两次修正仍失败时返回可行动错误；
- 三种脚本 API 协议得到一致结果；
- `shotSetId` 所有权和隔离仍生效。

### 10.3 智能混剪主接缝

通过智能混剪任务创建和准备路径，注入可控 TTS 时长并验证：

- V3 脚本不应用旧 `shotId` 先验；
- V2 脚本仍保持兼容行为；
- 实际时长在容差内时继续匹配；
- 15 秒目标、25 秒 TTS 被阻断；
- 用户明确接受实际时长后可以继续；
- 文案修改使旧 TTS 失效；
- 自动贴合重合成后重新执行门禁；
- 主副标题正确复制为组级快照；
- 上游脚本变化不覆盖组级标题和用户修改。
- 送入 TTS 的文本仍保留自然标点；
- 自动字幕 Cue 不以语言标点或空格结尾；
- 句中语言标点被用于边界或转换为空格；
- 小数、百分比、角度、比例、范围和型号符号保持语义完整；
- 手工修改字幕不被自动去标点规则覆盖。

### 10.4 浏览器验收

浏览器测试覆盖：

- 综合推荐模板默认选中且可更换；
- 目标总时长和正文预算文案正确；
- 结果页显示主副标题、字符数和预计时长；
- V3 不显示具体分镜绑定、画面理由和未使用分镜；
- 超时状态、智能贴合入口和实际时长确认可用；
- TXT、JSON 和一键复制包含两段标题；
- 默认复制得到无标点字幕稿，另有带标点配音稿入口；
- 字幕预览和最终导出均不显示自动句尾标点；
- 历史 V2 草稿仍可选择和进入智能混剪。

### 10.5 真实验收场景

在获得外部调用授权后，使用现有沙发项目的真实 15 秒脚本场景验收：

1. 生成 V3 脚本，内容字符数处于建议范围。
2. 使用现有 TTS 音色 1.0x 合成。
3. 最终总时长落入 15 秒目标容差，不再达到约 25 秒。
4. 智能混剪基于真实视频分析完成匹配，无跨组素材。
5. 主标题和副标题进入封面编辑器，可独立修改。
6. TTS 仍按带标点口播产生自然停顿，自动字幕 Cue 不显示语言标点。
7. `112°`、百分比、小数和产品型号等语义符号在字幕中保持正确。
8. 真实 FFmpeg 成片可解码，无黑屏、异常定格和音频截断。

## 12. 风险与缓解

### 12.1 不看静态图片后，文案可能缺少画面支撑

缓解：

- 脚本只使用用户确认的产品信息和卖点，不允许新增无依据参数。
- 每段输出抽象画面意图和关键词。
- 第五步用真实视频分析判断是否存在可匹配场景；没有则明确显示缺口。
- 后续如确有必要，可新增“不绑定素材的视觉覆盖检查”，但不得恢复一句一图的自动绑定。

### 12.2 字符数无法完全预测 TTS

缓解：

- 字符预算只作为第一道门禁，保留安全余量。
- 第二道门禁使用真实 TTS 探测时长。
- 持续用真实样本校准不同语言和语速的估算值。

### 12.3 自动贴合可能改变文案质量

缓解：

- 限制自动修正次数。
- 保留卖点和模板结构，不允许新增事实。
- 展示修正前后的字符数和时长。
- 最终仍由用户确认文案后进入成片。

### 12.4 新旧脚本行为不一致

缓解：

- 草稿列表显示脚本版本。
- V2 走原兼容路径，V3 走新职责边界。
- 不批量迁移历史数据；需要 V3 能力时重新生成脚本。

### 12.5 误删参数中的语义符号

缓解：

- 不使用“删除所有 Unicode 标点和符号”的粗暴规则处理字幕。
- 为小数、百分比、角度、比例、范围、型号和单位组合建立明确保留规则。
- 对无法可靠分类的符号优先保留，避免改变产品事实。
- 用真实电商参数文本建立回归用例。

## 13. Out of Scope

除第 4 节所列非目标外，本期明确不处理：

- 为脚本结果重新增加图片左右对照审阅。
- 让脚本模型直接操作智能混剪时间线。
- 用静态图片分析覆盖真实视频分析结果。
- 将智能混剪的语义矩阵提前到模块 3 执行。
- 自动修改用户手动锁定的素材。
- 为满足目标时长裁掉句尾、字幕或音频。
- 从 TTS、强制对齐或语义匹配使用的标准口播中删除标点。
- 重新定义 BGM、字幕样式、封面画布和导出命名。

## 14. Further Notes

### 14.1 与旧设计的关系

脚本 V2 曾以“一句口播对应一张分镜”为核心，以解决当时成片编排缺少素材理解的问题。当前智能混剪已经具备真实视频分析、真实 TTS 时间轴、语义矩阵和全局素材匹配，原有绑定职责已不再适合继续作为新脚本的主模型。

V3 不是删除分镜组概念，而是把 `shotSetId` 从“逐句画面绑定”收敛为“上下文和数据隔离边界”。

### 14.2 待评审重点

本评审稿默认采用以下口径，确认后进入技术设计：

1. V3 生成不再发送候选分镜图片。
2. 综合推荐模板默认选中，用户可修改。
3. 预计时长合格区间为目标正文的 90%～100%。
4. 真实总时长容差为 `max(0.5 秒, 目标总时长的 5%)`。
5. 超时默认优先改文案，不自动改变用户音色和语速。
6. 主标题建议 4～10 字，副标题建议 6～14 字。
7. 历史 V2 不迁移、不回写，只做兼容读取。
8. 自动字幕在完成切句和对齐后去除语言标点；TTS 口播保留标点，参数类语义符号保留。
