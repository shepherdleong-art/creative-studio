# 痛点解决型15秒脚本生产

## 产品范围

在工作台第三步增加可选的「痛点解决型 · 15秒」生产模式。默认仍为「多方向生成」。新模式只支持15秒，目标数量沿用1–6条。首次提取、卖点库复用和再生成均可使用，不增加必经的人工确认环节。

依据：`docs/「痛点解决型」15s AI脚本生产标准 V1.0.md`。本文定义该标准与现有工作台的接入边界，不改写原标准。

## 生产流程

通过核验且未排除的产品事实 → 内容机会分析 → 本地校验与明确重复过滤 → 内容命题与三种子路径 → 四段口播 → 本地校验与语义审核 → 标题修复与保存。

每个机会保存人群、场景、核心问题、作用、使用利益、内容命题、主卖点、辅助卖点、证据引用、匹配理由与评分。主辅卖点是内容概念，各自可以引用多条原子事实，不按原子事实条数判断卖点是否超量。主卖点必选一个，辅助卖点最多一个，两难型必须有辅助卖点和真实顾虑；原因诊断型必须说明有依据的可能原因。

评分使用1–3档：痛点强度至少2（具体困扰），事实匹配必须3（直接证据），场景明确度必须3（具体情境与需求）。这些评分属于模型策划判断，不等于事实证明。正文审核仍要核对功效、作用、原因解释与利益是否受输入事实支持。

## 三种子路径

| 子路径 | 四段职责 |
| --- | --- |
| 直接解决 | 场景痛点 → 产品与主卖点 → 作用解释 → 使用结果 |
| 原因诊断 | 现象 → 有依据的可能原因 → 针对性设计 → 结果或判断 |
| 两难解决 | 真实冲突需求 → 解决策略 → 主辅卖点协同 → 两种利益落地 |

55–70字是文案目标。工作台继续显示按共享口播速度与片头预算计算的估算时长，偏离时长只提示，不宣称已完成配音验收。本次不新增自动TTS调用，最终成片时长仍以实际配音为准。

## 质量与数量

- 一条只解决一个核心问题；结果或购买判断可以收尾，不强制CTA。旧模式的CTA规则保持原样。
- 沿用事实白名单、标题规则、正文相似度检查；新模式增加四段结构、主卖点引用、两难型辅助引用与机会引用边界检查。
- 语义审核检查事实支持、单一问题、人群匹配、具体产品特征、主辅聚焦、结构闭环、语言自然、批内实质差异和标题命题一致。响应缺项、矛盾或审核不可用时不得保存为合格脚本。
- 任意两条在痛点、主卖点、路径三项中至少两项不同。本地处理明确重复；同义改写等语义差异交给模型审核。换品/换人测试不要求特征绝对独占或人群完全互斥。
- 目标数量为上限。零机会也可以完成分析，但不会调用正文生成。结果页明确展示目标数、机会数、已保存数及少产原因。
- `failedCount`只统计已规划机会的执行或校验失败，`plan.shortageCount`单独记录内容机会不足。所有机会处理成功时任务为`succeeded`，不因少产制造补跑任务。

## 任务与版本

新字段`productionMode=pain_solving_15s`进入任务身份、幂等键与冻结快照。标准模式省略该字段，兼容历史请求身份。原有不可变卖点库修订、脚本版本及下游统一读取接口继续复用，无数据库迁移。

内容机会写入`plan.painPlanning`并绑定版本、卖点修订及输入指纹。恢复时重验引用后复用；已保存的方向仍按现有`generationPlanIndex`恢复，避免重复产出。

整组再生成冻结所选模式和完整请求体。单条再生成保留原模式、内容机会与证据修订；补跑只重试失败机会，并保留已完成机会用于批内差异审核。新模式不显示「换一个框架/钩子」，其结构由内容机会决定。

## 验证

- `scripts/script-studio-pain-solving.test.ts`：无效/越界/禁用证据、评分与子路径门禁、明确重复、提示词与审核协议、模式幂等、少产与零机会、拒绝无证据结果、恢复去重。
- 原有runner、generation-contract、direction-briefs、audience-profile、cta-ending及title-repair回归。
- `scripts/script-studio-progress.playwright.test.mjs`：生产前端加API夹具，验证模式选择与提交、整组再生成、少产提示、策划展开、15秒限制及旧流程进度行为。
- 上述测试不调用真实模型；真实商品的选题质量和配音时长需要后续样本验证。
