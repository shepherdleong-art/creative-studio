# 服务器性能优化

**状态：** `ready-for-agent`

**日期：** 2026-11-14（UTC+8）  
**用途：** 根据本次代码审查直接整理，交给其他 AI 实现；执行入口见[任务索引](../plans/2026-11-14-服务器性能优化/README.md)。

## Problem Statement

员工在批量生产和视频预览时感到卡顿；页面切换、列表和总览已优化过，但仍有剩余延迟。当前实现存在空闲执行位不能及时补位、同步读取全部历史快照、衍生预览重复完整读盘、代理流丢失背压、工作区逐卡重复查询及任务页扫描排序等开销。同步工作占用服务端事件循环，多人使用时会使无关请求一起等待。

2026-11-14 使用真实业务函数、临时 SQLite 数据库和合成文件得到以下基线；没有访问生产服务器或调用付费供应商：

| 场景 | 本机观测 |
| --- | --- |
| 调度补位 | 分析任务挂起时，后来入队的通用任务保持 queued，尽管两个通用执行位空闲；释放分析后才启动 |
| 执行准入 | 2000 条已完成历史、每条约 64 KiB 输入快照：延期准入中位 525 ms；无历史约 20 ms，已隔离 journal 开销 |
| 衍生文件重复登记 | 同一已登记 64 MiB 文件，每次仍同步读取完整 64 MiB，约 43–47 ms |
| 代理流 | 客户端未消费响应，250 ms 内已读取全部 64 MiB；无 onClose 包装的对照仅预读 128 KiB |
| 批量工作区 | 100 张成片卡片一次读取 1507 条 SQL，中位 401 ms；活跃时每 3 秒重取 |
| 页面查询 | 最近 12 条约 230 ms、活动统计 226 ms、任务首屏 573 ms、状态筛选 1053 ms；仅测试库补排序索引后最近 12 条约 6 ms |

上述数字是少量局部采样，不能外推为生产端到端速度或线上 SLA。

## Solution

保留现有工作流，让空闲执行位及时处理合格工作，预览按需读取已核验文件，任务查询与批量工作区减少无关历史和重复处理。员工继续使用现有入口，获得更及时的状态与预览；管理员继续看到完整、准确的团队数据。

本轮覆盖六项优化，按任务索引顺序交付。先处理预览流、衍生文件复用和页面查询，再处理批量补位、准入与工作区聚合。已有权限、费用、并发、公平轮转、冻结输入、审核及恢复规则为验收前提。

## User Stories

1. 作为员工，我希望批量生产有空闲执行位时及时开始新任务，以便减少无效排队。
2. 作为员工，我希望长时间素材分析不拖住空闲的通用执行位，以便其他生产阶段继续推进。
3. 作为员工，我希望新加入的分析任务能使用空闲分析执行位，以便不等待其他任务全部结束。
4. 作为员工，我希望等待名额的任务适度退避，以便不因频繁重试拖慢工作台。
5. 作为管理员，我希望多人继续公平共享名额，以便性能优化不造成成员饥饿。
6. 作为员工，我希望历史已完成任务不拖慢新任务准入，以便长期使用后速度仍稳定。
7. 作为管理员，我希望预算、停用和模型权限继续生效，以便优化后生产规则可靠。
8. 作为管理员，我希望未知调用仍按真实预约和既有策略处理，以便不重复调用或误改费用。
9. 作为员工，我希望生产暂停、停止和重启恢复仍可靠，以便优化不会丢失结果。
10. 作为员工，我希望重复打开衍生视频不反复完整读盘，以便首帧和拖动跳转更及时。
11. 作为员工，我希望首次需要转码时只执行一次，以便多个窗口不会重复处理同一素材。
12. 作为员工，我希望视频播放按消费速度读取，以便慢网络不会让服务器堆积整段视频。
13. 作为员工，我希望关闭或跳转预览能停止旧读取，以便及时释放资源。
14. 作为员工，我希望代理正在读取时受到清理保护，以便播放不中途失效。
15. 作为员工，我希望缓存命中也逐次检查权限，以便项目素材不会跨成员泄露。
16. 作为员工，我希望素材内容变化后不会误用旧登记，以便预览与实际素材一致。
17. 作为员工，我希望大批次的成片卡片快速刷新，以便生产期间还能顺畅审片。
18. 作为员工，我希望状态刷新保留当前选择与编辑，以便后台更新不覆盖操作。
19. 作为员工，我希望封面、字幕或画面变更后审核状态及时失效，以便不误导出旧方案。
20. 作为管理员，我希望任务列表覆盖全部历史和完整制作任务组，以便翻页与筛选不漏记录。
21. 作为员工，我希望我的任务、数量角标及详情使用一致范围，以便看到准确状态。
22. 作为管理员，我希望总览和任务筛选继续正确计算取消、回队及历史调用状态，以便判断可靠。
23. 作为维护者，我希望有可重复的前后性能证据，以便判断优化收益和回归。
24. 作为个人版用户，我希望共享模块仍兼容本地运行，以便团队性能改造不破坏既有功能。

## Implementation Decisions

1. **范围和兼容。** 优化集中在统一生产服务、共享媒体响应及其调用者。复用现有适配器与领域边界；批量模块只能向共享媒体基础取能力。维持现有执行位和资源容量，不通过整体提高并发、降低画质或跳过验证达标。

2. **预览流背压。** 采用由消费者驱动的读取或保持背压的流转换；预读有固定上界，不随文件或 Range 长度线性增长。取消传播至底层文件流，关闭文件描述符。代理读取租约覆盖全部实际读取，正常结束、错误或取消只释放一次。保持完整读取、Range、条件请求及 200/206/304/416 语义；团队响应继续遵守既有私有缓存规则。

3. **衍生文件登记复用。** 将衍生物生成、完整内容指纹核验和原子发布后的登记，与后续读取分开。稳定的已登记不可变版本不在每次 Range 请求重新计算全文件哈希；每个请求仍校验当前用户权限、来源谱系和文件身份。不能只凭路径相同判断内容未变；缺少可信版本/身份、文件替换或身份变化时重新核验或明确拒绝。并发首次访问去重，失败和半成品不能作为 ready 复用。不要为实现预览优化而全局放宽通用文件登记约束。

4. **页面查询。** 为管理员和员工各自的可见范围评估匹配排序的索引；先选合法 ID，再读取该页完整记录。继续按制作任务组分页，同组执行记录不拆页。计数、搜索、状态筛选、活动统计与详情覆盖全量授权历史，不采用固定历史上限。减少重复分组扫描，必要时提供可回填、可恢复的轻量汇总；缓存或汇总必须有明确失效规则，不改变有效状态口径或数据事实来源。

5. **批量调度补位。** 各执行位独立持续运行，空闲时可被入队或资源释放唤醒；也可使用有界定时检查，但不能等待其他长任务整轮结束才补位。分析/通用领取范围继续互斥。等待统一准入或媒体名额时按原因退避，让其他合格任务推进，禁止忙循环。维持单例、原子领取、租约、心跳、过期恢复、暂停、取消、停止和停机排空；多个执行位不增加实际允许并发。

6. **准入轻量化。** 只读取参与当前真实需求的记录及必要策略字段，完整输入在获准后按 ID 加载；结束的历史快照不参与反复搬运和解析，本轮缓存不长期保留完整历史。个人覆盖、公平共享、成员轮转、预算、权限、维护和实例 fence 仍由服务端裁决。unknown 的并发需求按真实预约判断，保留既有自动过期释放与晚到回执策略，成本预约和未知费用不因优化被清除。

7. **工作区聚合和刷新。** 按批次集中读取任务、尝试、产物、素材与冻结配置，复用同次请求中的契约结果，减少逐卡查询。已有工作区、详情和任务接口优先保持兼容；如增加轻量状态/修订协议，缺少旧缓存时能返回完整合法快照，每次仍执行授权。前端同类请求最多一个在途，忽略切批次后的旧响应；编辑、重试和发布后立即刷新。活跃可见页面状态时效不劣于当前约 3 秒刷新；隐藏时可降频，恢复可见时立即刷新。同源提示、契约新鲜度、审核失效、当前成片与历史正式产物保持一致。

8. **数据升级。** 新索引或字段只追加迁移，按所属模块使用现有安全升级流程；不修改已发布迁移，不把独立模块迁移塞回旧 core runner。涉及新汇总时明确回填、并发写入、失败和重启恢复，迁移失败不得伪装就绪。

9. **工程性能目标。** 同机、同数据、同版本依赖，预热后至少采样 20 次并保存 p50/p95、读取字节和峰值内存。最近 12 条查询以较重基线下降至少 80% 为目标；排除 journal 后，2000 条完成历史下准入 p50 下降至少 80%；100 张卡片工作区 p50 下降至少 60%，关联读取避免随每张卡追加一套查询，目标不超过 100 条 SQL。任务首页、状态筛选和总览各自报告前后值，不能拿近期列表的收益替代其他接口。数字是本轮工程目标，权限和业务一致性是硬门槛；未达目标应保留证据并写明剩余热点，不能宣称全部完成。

## Testing Decisions

优先在三个既有边界验证：**调度器/执行 facade、真实 SQLite 查询与工作区聚合、经过授权的媒体路由及 Range 响应**；最后用浏览器验证首帧与拖动。无需为了统一测试而新增贯穿全仓的抽象层。

| 边界 | 必须观察的行为 |
| --- | --- |
| 调度与准入 | 受控长任务未释放时，新入队的另一 lane 工作已启动；延期任务不阻塞合格任务；并发不超限、公平性不退化；暂停/停止/租约丢失不接受迟到结果；重启不重复付费提交 |
| 历史扩容 | 保持活跃任务相同，增加 500/2000 条大快照完成历史，核对同一准入结果、读取/解析量、时延和内存；真实已占额 unknown 与已释放 unknown 分开测试 |
| 媒体响应 | 64/128 MiB 文件的慢读及未消费响应均只有限预读；取消与断流关闭 fd，租约只释放一次；清理不删除在读代理；完整/前缀/后缀/非法 Range 与条件请求兼容 |
| 文件登记 | 首次登记完成完整指纹核验；后续多次 Range 不重复全文件哈希；替换文件、来源变化和未登记衍生物不会误命中；缓存与并发复用不绕过跨用户权限 |
| 工作区 | 1/25/100 张卡片及带历史产物的大批次，优化前后领域视图一致；封面 A→B→A、返工、失败、停止、审核失效、同源提醒与导出资格一致；慢接口不叠加轮询，切批次旧响应无效 |
| 列表和总览 | 管理员/两名员工、超过 500 条历史、同组多记录、搜索/状态筛选/末页、取消/回队/晚到回执；数量和详情不依赖当前页，员工隔离不变 |
| 浏览器集成 | 空闲/批量运行中、首次/再次预览、连续播放/拖动、开关预览、代理切换均实际出帧；保存请求时序、首字节与首帧数据，不能只检查 video 元素存在 |

复用现有批量 runner/scheduler、执行 admission/contention、媒体 response、团队文件、工作区、任务分页、公平共享、未知占用与浏览器预览测试。增加针对真实故障模式的回归；不依赖源码字符串、SQL 文本或内部类名一致来证明正确。SQL 次数、读取量及内存只作为性能预算/证据测量。

正式测试遵守临时数据根先于模块加载设置的规则；不接触生产库、不读密钥、不调用付费供应商。局部通过后完成主流程检查、TypeScript 和改动文件 ESLint；具体测试入口由任务单给出。

## Out of Scope

- 本轮不实现 journal 分段检查点/增量校验。其全量校验有约 77 ms/万条事件的本机开销，但关系到防重复调用、哈希链与恢复可信度，另立规格评审；本轮保留全部校验、fsync 和损坏拒绝。
- 不改费用算法、unknown 判定/自动重试或既有名额过期规则，不清理历史调用或账本以获得性能数字。
- 不更换数据库、引入 Redis/外部后台，不做通用任务框架重写。
- 不改变供应商、生成质量、正式渲染参数、冻结输入、剪辑交互和 UI 外观。
- 不包含服务器操作、线上压测、发布、打包、重启或部署；实现后的生产验证另行安排。
