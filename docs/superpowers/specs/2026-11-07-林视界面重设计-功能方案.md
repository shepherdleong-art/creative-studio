# 林视界面重设计

**状态：** `ready-for-agent`

**确认日期：** 2026-11-07（UTC+8）  
**交付阶段：** 需求规格；尚未实施、测试、打包或部署。  
**范围：** 工作台改名「林视 Lin's Vision」并换上新标识；统一生产服务的员工端（林视创作台）和管理员端（林视控制台）换成定稿外观「方案一 Mac 原生」；带上原型评审中确认的几项小功能；超时、并发、图片预处理改由服务器统一管理。所有编辑操作保持不变。  
**设计依据：** 本机原型目录 `outputs/prototypes/2026-11-07-林视品牌与界面方案/`（目录不进 Git）。`方案一-Mac原生.html` 是能点的定稿；`direction-approved.md` 记录八轮评审的用户原话；`tools/checks/` 里是原型的点按清单和尺寸检查脚本。外观以原型为准，规则以本文为准；两者冲突时以本文为准，并在任务的 Comments 里记下。

## Problem Statement

部门约 20 个同事天天用工作台做产品图和短视频，电脑全是 Windows。现在的界面是 Codex 拼出来的，用户原话是「丑丑的」。具体问题：

- **名字乱。** 同一个工具有四个名字：Creative Studio、产品素材工作台、团队生产控制台、我的创作空间。图标是深底白 C 加三个色块，没有品牌规范。
- **看不到图。** 选场景图、看分镜时，原图和结果不在一起，要来回翻才能比。
- **入口平铺。** 侧栏入口排成一长列（管理员端 13 到 14 个），顶栏又放了一排重复的链接。修改密码、回收站和功能入口混在一起。
- **工程师用语外露。** 员工新建项目要填超时、并发、图片预处理，第 1 步和第 4 步还要设并发。这些本该服务器统一管。「异常中心」「模型与并发」「等待并发空位」这类叫法也不直白。
- **控制台难管。** 「模型与并发」列出 17 行，其实只有 5 个上游账号，13 个模型共用一个公司网关账号。改一个账号的名额要在好几行里找。
- **混剪页被盖住。** 团队版里混剪页按整个窗口居中加宽，左边一截被侧栏盖住；1440 宽的窗口横向多出 85 像素，1536 宽多出 61 像素。
- **导出页不好用。** 每张成片卡片里嵌一个小播放器，画面小；成片只能一条一条下载。
- **字体靠运气。** 页面用系统字体，员工的 Windows 电脑上显示效果不一致。

同时有一条硬约束：混剪时间轴、截取条、批量审片这些操作，同事已经用熟了。第七轮评审时用户说：「剪辑界面的操作逻辑你也用回原来的那一套，降低学习成本」。

## Solution

- **改名换标。** 正式写法「林视 Lin's Vision」，副题「AI 产品图与短视频创作工作台」。员工端叫「林视创作台」，管理员端叫「林视控制台」。标志是绿色圆角方块里一片白色叶子，叶子中间是眼睛。内部名 `creative-studio` 和所有数据位置都不改。
- **定稿外观「方案一 Mac 原生」。** 浅灰底，白色内容区，左侧分组侧栏，按钮和选中用蓝色，绿色只用在标志和「成功」状态。字体打包思源黑体和 Inter。浅色、深色、跟随系统三档都保留。品牌感只出现在登录页、桌面客户端启动画面和应用图标，干活的页面标题直接写事实。
- **结构理顺。** 员工端侧栏分创作、进度、账目三组，管理员端分总览、生产、资源、团队、系统五组。修改密码、回收站、外观、退出登录收进头像菜单。「异常中心」改叫「出错的任务」，「模型与并发」改叫「模型与名额」。
- **逐屏改进。**
  - 首页先显示出错的任务，再显示「接着做」和「正在生产」。
  - 选场景图和分镜默认把原图和结果并排。
  - 视频页点哪条视频，右栏就显示它当时用的设置。
  - 脚本页的爆文模板内容直接摊开。
  - 导出页点成片卡片弹出大预览，并新增「一键下载全部」。
  - 控制台「模型与名额」改成一个账号一行。
- **操作照旧。** 单条精准混剪和批量审片的全部交互沿用现有做法，包括时间轴拖拽、截取条、右键菜单和快捷键，只换外观。
- **参数归服务器。** 超时、并发、图片预处理从员工界面拿掉，由服务器按统一默认值执行。

## User Stories

### 名字与标识

1. 作为员工，我希望窗口标题、任务栏图标、登录页和侧栏都写「林视创作台」并用叶子标志，这样我不会被四个旧名字搞糊涂。
2. 作为管理员，我希望管理员端叫「林视控制台」，和员工端用同一个标志，这样一看就知道是同一套工具的两端。
3. 作为员工，我希望品牌只出现在登录页、启动画面和应用图标上，干活的页面标题直接写事实，这样品牌不占干活的地方。
4. 作为员工，我希望登录页写着「出片交给 AI，眼光留给你。」，这样我知道这个工具的用法：AI 出片，人来判断。
5. 作为员工，我希望客户端升级到新名字以后，登录状态、下载目录、外观偏好和本机数据都还在，这样改名不用重新设置。
6. 作为员工，我希望试听配音时语音助手报的是新名字，这样声音和界面一致。
7. 作为员工，我希望桌面客户端启动时先看到标志、名字和「正在连接服务器」，连不上时写清原因，这样不会对着一个空白窗口。

### 外观

8. 作为员工，我希望在 Windows 上看到的字体和设计稿一致（中文思源黑体，字母和数字 Inter），这样不同电脑显示一样。
9. 作为员工，我希望浅色、深色、跟随系统三档还在，原来的选择继续生效，这样升级后外观不突然变。
10. 作为员工，我希望 Windows 上还是系统自带的标题栏和最小化、最大化、关闭按钮，这样用法和别的软件一样。
11. 作为员工，我希望在 1920×1080、缩放 125% 的屏幕上，每一页都不用横向滚动，按钮也不会被切掉。
12. 作为用小笔记本的员工，我希望窗口缩到最小（1024×720）时侧栏能收成图标条、面板能收起，这样小屏也能干活。
13. 作为员工，我希望鼠标停在任何小图上都能弹出大图，这样不用点开就能看清。
14. 作为员工，我希望深色模式下所有页面颜色都对，没有刺眼的白块，这样晚上用不累眼。

### 侧栏与头像菜单

15. 作为员工，我希望侧栏分成「创作」（工作台、我的项目、创作画布）、「进度」（我的任务、下载与交付、出错的任务）和「账目」（我的用量）三组，这样我按要做的事找入口。
16. 作为管理员，我希望侧栏分成「总览」「生产」「资源」「团队」「系统」五组，这样管理功能不和创作入口混在一起。
17. 作为员工，我希望「我的任务」和「出错的任务」旁边显示数量，这样不点开也知道有几件事。
18. 作为员工，我希望修改密码、回收站、外观和退出登录都在侧栏底部的头像菜单里，这样它们不占侧栏。
19. 作为员工，我希望头像菜单里写着「关闭窗口不会中断服务器任务」，这样我放心关窗口。
20. 作为员工，我希望叫法直白：「出错的任务」替代「异常中心」，「模型与名额」替代「模型与并发」，状态写「排队中」而不是「等待并发空位」。
21. 作为员工，我希望客户端需要更新时，侧栏底部出现提示，一键就能修复并更新，这样不会漏看。
22. 作为员工，我希望画布功能没开时侧栏里不出现「创作画布」，这样不会点进空页面。

### 登录

23. 作为员工，我希望登录还是「工号＋密码」，首次登录强制改密码，记住登录的规则不变，这样不用重新学。
24. 作为员工，我希望没填工号、没填密码、新密码太短、两次不一致时，提示直接写在输入框旁边，这样不用对付弹窗。

### 员工首页（工作台）

25. 作为员工，我希望首页最上面列出出错的任务，写清哪一步错了、可以怎么办，这样先处理要紧事。
26. 作为员工，我希望首页有「接着做」，显示最近项目的封面、做到第几步、什么时候改过，这样一点就能接着干。
27. 作为员工，我希望首页有「正在生产」，显示每个任务实际做到哪一步、第几条，这样我知道还要等多久。
28. 作为员工，我希望只有能真实测量的阶段（比如渲染）才显示百分比，其他阶段写正在做什么、第几条，这样不被假进度骗。
29. 作为新员工，我希望首页空的时候告诉我第一步该做什么，这样不会对着空页面发呆。
30. 作为员工，我希望首页有常规项目、批量生产、详情页脚本、创作画布四个开工入口（画布按开关显示），这样开工只点一下。
31. 作为员工，我希望首页能看到本月已用金额和我的额度，这样不会用超了才知道。

### 新建项目

32. 作为员工，我希望新建项目只填店铺、型号、子型号、生产类型、剪辑师，以及图片的模型、画面比例、清晰度和质量，剪辑师默认是我，这样建项目很快。
33. 作为员工，我希望边填边看到服务器生成的项目名（日期-店铺-型号-子型号-生产类型-剪辑师），这样能确认命名对不对。
34. 作为员工，我希望没填完时，按钮旁边写清还差什么，这样不用猜。
35. 作为员工，我不想再看到超时、并发和图片预处理，这样我只管做内容。
36. 作为员工，我希望创建后直接进第 1 步，空页面告诉我先放一张原始场景图。

### 第 1 步 新场景图

37. 作为员工，我希望默认把原图和选中的候选图并排放，下面一排候选小图，左右键切换，这样一眼看出新图像不像原图。
38. 作为员工，我希望也能切到网格看全部候选，这样一次比较很多张。
39. 作为员工，我希望能把候选标成可用或不可用，并设一张为场景参考图，这样后面的分镜知道用哪张。
40. 作为员工，我希望选类目后提示词跟着换，改数量后按钮写「生成 N 张」，这样点之前就知道会发生什么。
41. 作为员工，我希望生成中的候选先占位显示「生成中」，好了自动换成图片，这样知道还在跑。
42. 作为员工，我希望没上传原图就点生成时被提醒先上传，这样不会白点。

### 第 2 步 分镜

43. 作为员工，我希望左栏有「上传原始分镜图」，能拖进来，也能一次选多张，这样分镜素材好放。
44. 作为员工，我希望新建分镜组的窗口里能继续上传和删图，有「全选」，再点一次取消全选，这样素材多的时候不用一张张点。
45. 作为员工，我希望全选以后，把鼠标放到任意一张上就能点「设为开场」，这样能换开场的产品全景图。
46. 作为员工，我希望点选顺序就是镜头顺序，第一张标「开场图」，再点一次取消，这样顺序一目了然。
47. 作为员工，我希望分镜默认原图和结果并排，显示「第 N 版（共 M 版）」并能切回旧版，这样重做不怕丢好结果。
48. 作为员工，我希望左右键切分镜，能标「待返工」，改提示词后重做会多一版、旧版保留，这样返工有据可查。
49. 作为员工，我希望没生成出来的分镜写清原因、能重试，而且不能被标成可用，这样不会误用坏结果。
50. 作为员工，我希望删除分镜组前要确认，这样不会误删。

### 第 3 步 脚本

51. 作为员工，我希望边改脚本边看到字数和预计时长（按现有的每秒字数和片头时长规则），并提示偏长还是在预算内，这样写出来的长度合适。
52. 作为员工，我希望手动改过的脚本自动成为新的项目脚本版本，能切回旧版，这样改坏了能找回。
53. 作为员工，我希望卖点库默认收起、默认全选，点开才逐个排除，这样不用每次都勾一遍。
54. 作为员工，我希望选「爆文模板改写」时，模板的参考文案、结构和匹配原因直接摊开，长的能展开全文，这样一眼看清模板讲什么。
55. 作为员工，我希望勾模板时能调每个模板出几条，合计不超过现有上限，这样一次生成适量方案。
56. 作为员工，我希望「再生成一组」复用已有卖点库、不重新识图，只有上传了新详情页才重新识图，这样省时间也省钱。

### 第 4 步 视频

57. 作为员工，我希望点哪条已生成的模块 4 素材，右栏就显示它当时用的提示词、模型、秒数和首尾帧，这样我知道这条是怎么来的。
58. 作为员工，我希望在这条视频的设置上改完再生成时，系统提示「会多做一条」，原来那条不变，还能一键还原，这样不怕改乱。
59. 作为员工，我希望批量检查窗口顶部就能统一选供应商、统一选秒数（只列出所选模型都支持的秒数），也能逐条改提示词，这样一组分镜一次设好。
60. 作为员工，我希望「一键填充」只填空着的提示词，「全部生成」只提交还没有任务的分镜，这样不会重复花钱。
61. 作为员工，我不想在视频页看到并发设置，这样只关心画面。
62. 作为员工，我希望秒数只能选当前模型支持的值，尾帧、智能分镜、全能参考只在支持的模型上出现，这样不会提交注定失败的任务。
63. 作为员工，我希望剔除视频时写原因，能恢复，也能隐藏已剔除的，这样素材干净又有据可查。

### 第 5 步 单条精准混剪

64. 作为剪辑师，我希望混剪的操作和现在一样，这样不用重新学：
    - 左栏「素材调整」：先选素材，再替换当前片段或添加到缺口。
    - 时间轴有字幕、卖点、视频、口播、配乐五条轨道。
    - 单击选中，拖动排序，拖两端修剪。
    - 双击视频片段打开截取条，双击字幕或卖点直接改字。
    - 右键菜单和快捷键不变。
65. 作为剪辑师，我希望右栏还是一列卡片，顺序和现在一样（选中视频片段时最上面是倍速和画面调整），这样找设置的位置不变。
66. 作为剪辑师，我希望改字幕样式时直接在中间的预览上看到效果，这样不用另看小预览。
67. 作为剪辑师，我希望混剪页占满侧栏右边的整块区域，不被侧栏盖住，也不横向滚动，同时保留为小屏监看加宽的空间。
68. 作为用小窗口的剪辑师，我希望打开截取条时预览画面不会缩得看不清（至少约 200 像素高），放不下时中间一栏可以上下滚动。
69. 作为剪辑师，我希望导出成功后点成片就弹出大预览，有声音，能拖进度条，空格播放暂停，这样导出完马上能检查。

### 批量生产

70. 作为剪辑师，我希望在第 5 步顶上用分段按钮切换「单条精准混剪」和「批量生产」，这样两种模式入口清楚。
71. 作为剪辑师，我希望批量生产还是四步（准备素材、脚本与口播、检查成片、导出成片），内容和现在一样，只换外观。
72. 作为剪辑师，我希望统一审片的操作和现在一样：
    - 素材拖到片段上替换，拖到空位插入，拖到末尾追加。
    - 拖片段两端修剪，拖中间移动。
    - 鼠标在素材缩略图上左右滑，可以看画面。
    - 成片属性分五页（包装、字幕、画面、封面、配音BGM），改完点「应用」。
    - 筛选、全选、通过已选、返工、撤销审核和区间重复提示都在。
73. 作为剪辑师，我希望在导出页点成片卡片就弹出大预览：画面按 3:4 显示，能拖进度条，空格播放暂停，左右键换上一条、下一条，这样一批成片能连着看完。
74. 作为剪辑师，我希望预览按成片状态播放不同内容：
    - 已导出的，播放当前成片。
    - 改过但还没重新导出的，播放上一版正式成片，并写明这一点。
    - 从没导出的，写明播放的是检查成片里的合成预览，也不给下载按钮。
75. 作为剪辑师，我希望点「一键下载全部」时能选「成片和封面」「只要成片」「只要封面」，这样一次把这批东西拿下来。
76. 作为剪辑师，我希望一键下载的文件这样处理：
    - 存到我设置的下载目录，按项目和导出版本分好，同名不覆盖。
    - 本机已经下过的不重复下。
    - 下载失败只补下载，不重新渲染。

### 控制台

77. 作为管理员，我希望运行总览显示以下内容，这样一眼掌握团队状态：
    - 正在跑、在排队、今天已完成和出错的数量。
    - 一张最近任务表。
    - 「今天的成员」各自在做什么。
78. 作为管理员，我希望运行总览有「开工前还差几件事」清单（公司模型代理、参考图中转、模型名额等），每件写清状态和去哪里处理，这样新环境能很快配好。
79. 作为管理员，我希望服务器上什么都还没跑时，运行总览显示全 0 的空状态和下一步提示，而不是一堆空表。
80. 作为管理员，我希望暂停生产前先看到说明（暂停后不再开始新的生成，已经在跑的继续），确认后才暂停，这样不误操作。
81. 作为管理员，我希望在运行总览点一行任务，就跳到全员任务里它的详情，这样排错少点几下。
82. 作为管理员，我希望全员任务能按项目、模型或编号搜索，按发起人和状态筛选，打字时搜索框不丢焦点，没结果时有说明和「清除筛选」。
83. 作为管理员，我希望任务详情写清错误编号、失败在哪一步、用的模型和调用记录，能直接重试，这样处理出错的任务更快。
84. 作为管理员，我希望「模型与名额」一个上游账号一行，名额只填一次，展开能看到哪些模型共用这个账号、谁在用、占用多少，这样改名额不用找好几行。
85. 作为管理员，我希望每个账号的状态用大白话写（可以用、还没设名额、缺密钥、已停用），内部编号默认藏起来，这样不懂技术也能管。
86. 作为管理员，我希望同一个上游账号被拆成两个名额池时页面提醒我，这样上游实际并发不会超过账号额度。
87. 作为管理员，我希望以下页面也换成同一套外观，功能不变，这样整个控制台看起来是一个东西：创作画布、成员与账号、团队用量、供应商配置、公共资源、版本与备份、下载与交付、回收站、修改密码、出错的任务。

### 服务器统一管理

88. 作为管理员，我希望超时、并发和图片预处理由服务器按统一默认值执行，员工看不到也改不了，这样排队和花费可控。
89. 作为管理员，我希望旧客户端仍然提交这些参数时，服务器照样按统一默认值执行，这样升级期间不乱。
90. 作为部署人员，我希望默认值写在服务器配置里，起步值和现在客户端的默认值一样，这样升级前后行为不变。

### 个人本地版

91. 作为用个人本地版的同事，我希望本地版照常能用：名字、标志和配色跟着换，原来的顶栏和本地设置先不动，这样团队版改版不影响我。

## Implementation Decisions

### 名字与标识

- 显示名要换的地方：页面标题、侧栏品牌区、登录页、桌面客户端窗口标题、启动画面和启动失败提示、应用显示名和快捷方式名、Windows 免安装包的说明文字、配音试听文案。员工端页面标题用「林视创作台」，管理员端用「林视控制台」，个人本地版用「林视 Lin's Vision」。
- 不改的内部标识（改了会丢数据或断连接）：
  - 包名和仓库名 `creative-studio`。
  - 数据根和应用数据目录名。
  - 所有 `CREATIVE_STUDIO_*` 环境变量。
  - 浏览器存储键（例如外观偏好键）和会话 Cookie 名。
  - 桌面可执行文件名和 IPC 通道名。
  - 路由地址，以及项目和成片的命名规则。
- macOS 源码桌面版的应用显示名换成新名字以后，停止脚本要同时认新旧两个应用路径；配音试听文案也换成新名字。这两处各有守护测试断言旧名字，要一起改。
- 标志：
  - 绿色渐变圆角方块（#46A97B 到 #1D6A4B），中间是白色叶子形眼睛，旋转 -45°。
  - 矢量源图取自原型。
  - 现有的图标生成流程改用新源图，重新产出网页图标和桌面应用图标（Windows、macOS 两种格式）。
- 品牌出现在三个地方：登录页、桌面客户端启动画面、应用图标；侧栏顶部只放小号标志和端名。主张「出片交给 AI，眼光留给你。」只放在登录页。
- 和母品牌的关系：视觉独立，不用 LINSY 的标志和颜色。登录页底部最多写一行归属，文案待用户确认。
- 启动画面：桌面运行壳在连上服务前显示一个本地页面，内容是标志、端名和连接状态。连不上时写清原因，再给一个重试按钮。这个页面不依赖服务器上的任何资源。

### 外观规范

- 颜色全部走设计令牌，令牌名和取值以原型为准。关键取值：
  - **浅色：** 窗口底 #E9E9EE，内容区 #FFFFFF，侧栏半透明 #F7F7FA，分组底 #F5F5F7，正文 #1D1D1F，次要文字 #5F5F64，分隔线为 9% 透明度的黑色。
  - **深色：** 窗口底 #0E0E10，内容区 #1E1E20，卡片 #2A2A2D，正文 #F5F5F7，次要文字 #AEAEB3。
  - **强调色只有蓝色：** 浅色 #0071E3，深色 #0A72E0。按钮、选中、进度都用它。
  - **状态色：** 绿色只给标志和「成功」（成功文字 #1C7A33，状态点 #34C759）；警告 #9A5300；错误 #C4001A。深色模式下各自换亮一档。
- 现有的外观机制保留：
  - 页面根元素上的主题属性。
  - 同一个本机存储键。
  - 首屏渲染前的初始化脚本。
  - 桌面运行壳同步原生控件主题。
  - 三档开关（跟随系统、浅色、深色）从顶栏挪进头像菜单。
- 新增颜色只用令牌，不写死浅色值；混剪和批量样式里原有的深色覆盖改成引用新令牌。
- 字体：
  - 中文用思源黑体（Source Han Sans SC，即 Noto Sans SC），拉丁字母和数字用 Inter，都是 SIL OFL 许可。
  - 字体文件随服务一起发布，页面按需加载。中文字体按 Unicode 区段切成多个小文件，用到哪段才下载哪段。
  - 字体栈依次是 Inter、思源黑体，最后退到微软雅黑和苹方。所有平台都优先用打包字体。
  - 时长、金额、计数用等宽数字。
- 字号：正文 13.5px；标签和次要说明不小于 12px；输入框不小于 13px。
- 窗口：桌面客户端用系统自带的标题栏。原型里画的窗口按钮只是示意，不做自绘标题栏。
- 圆角、阴影、间距、分组列表（类似 macOS 设置里的白底分组行）、分段按钮、标签、状态点、空状态的样子以原型为准。
- 小图悬停看大图统一用现有的悬停放大组件。

### 工作区外壳与导航

- 团队版去掉顶部全局顶栏，改成「左侧栏＋每页自己的工具栏」：
  - **侧栏：** 顶部是小标志和端名，中间是分组导航，底部是头像（点开是头像菜单）。
  - **每页工具栏：** 左边是页面标题，或者「返回＋项目名」；右边放本页操作，例如「新建项目」。
- 原顶栏功能的去处：
  - 「新建项目」放到首页和「我的项目」的工具栏。
  - 「修复并更新」放到侧栏底部的提示条。
  - 退出登录和外观开关进头像菜单。
  - 「停止服务」只属于个人本地版，团队版不出现。
- 员工端分组：
  - **创作：** 工作台、我的项目、创作画布（按画布开关显示）
  - **进度：** 我的任务（显示数量）、下载与交付、出错的任务（显示数量）
  - **账目：** 我的用量
- 管理员端分组：
  - **总览：** 运行总览
  - **生产：** 项目空间、创作画布、全员任务、下载与交付、出错的任务
  - **资源：** 模型与名额、供应商配置、公共资源
  - **团队：** 成员与账号、团队用量
  - **系统：** 版本与备份
- 头像菜单：修改密码、回收站、外观（跟随系统 / 浅色 / 深色）、退出登录，底部一行「关闭窗口不会中断服务器任务」。
- 改名对照（路由地址不变）：
  - 异常中心 → 出错的任务
  - 模型与并发 → 模型与名额
  - 团队生产控制台 → 林视控制台
  - 我的创作空间 → 林视创作台
- 团队版页面不再套全局 980 像素的居中栏，宽度由各页自己决定。五步工作台、单条精准混剪、批量生产工作区占满侧栏右侧。
- 个人本地版保留现有顶栏结构，只换名字、标志和令牌。

### 逐屏决定

每屏写明保留什么、改成什么、新增什么。外观细节看原型里对应的屏。

**登录**
- 背景用真实产品场景图并虚化，中间是登录卡片：标志、名字、主张、工号、密码。
- 首次登录改密码、记住登录、错误提示的规则不变。
- 校验提示写在输入框旁，不用浏览器弹窗。

**员工首页（工作台）**
- 工具栏：问候语和「还有几条在生产，关掉窗口也不会停」；右边是「找项目」和「新建项目」。
- 左栏：出错的任务（写明哪一步错了、能怎么办，带「去看看」）→ 接着做（最近项目的封面、店铺和生产类型、做到第几步）。
- 右栏：正在生产（链到我的任务）→ 新建（四个开工入口）→ 本月用量（已用金额和额度，只读）。
- 「正在生产」遵守任务进度的规则：只有能真实测量的阶段（目前只有渲染）才显示百分比；其他阶段写正在做什么、第几条。原型里每项都画了百分比，那只是示意。
- 有空状态，写明下一步。
- 「等你处理」跨项目汇总属于第二批，本次不做。

**新建项目**
- 保留店铺、型号、子型号、生产类型、剪辑师（默认当前登录人），以及图片的模型、画面比例、清晰度、质量。
- 项目名由服务器按现有规则生成，填写时实时预览。
- 校验提示写在按钮旁，不用浏览器弹窗。
- 拿掉超时、并发、图片预处理（见「服务器统一管理的生产参数」）。
- 创建后进入第 1 步，显示空状态和下一步提示。

**项目工作台（五步共用）**
- 工具栏放「返回」、项目名、五步分段按钮（场景图、分镜、脚本、视频、混剪）、项目信息、导出项目包。
- 每步的布局：左栏是列表或素材，中间是对照或预览，右栏是设置。新项目每步都有空状态。

**第 1 步 新场景图**
- 默认「对照」视图：原图在左，选中的候选在右，下面一排候选小图，左右键切换。也可以切到网格视图。
- 保留：标可用 / 不可用、设为场景参考图、选类目带出提示词、数量调节（按钮写「生成 N 张」）、生成中占位、上传多张原图。
- 拿掉并发设置。

**第 2 步 分镜**
- 左栏加「上传原始分镜图」：可以拖入，也可以多选。
- 新建分镜组窗口：
  - 能继续上传和删图。
  - 「全选」再点一次就取消。
  - 点选顺序就是镜头顺序，第一张标「开场图」。
  - 鼠标放在任意一张上出现「设为开场」，点了把它移到第一位，其余顺序不变。这套顺序沿用现有「第 1 张为开场产品全景图」的规则。
- 结果默认原图和结果并排，显示「第 N 版（共 M 版）」，能切换历史版本。
- 失败的分镜写明原因，能重试，不能标可用。

**第 3 步 脚本**
- 字数和预计时长随输入实时更新，并提示「偏长」或「在预算内」。规则沿用现有的每秒字数和片头时长。
- 手改形成新版本，能切换版本。
- 卖点库默认收起、默认全选；点「展开卖点」才能逐个排除。
- 「爆文模板改写」模式：模板的参考文案、结构和匹配原因直接显示，长文能展开全文。
- 勾选模板、调每个模板的条数，合计上限沿用现有规则。

**第 4 步 视频**
- 点选一条已生成的模块 4 素材，右栏切到「这条视频用的设置」：提示词、模型、秒数、首尾帧、智能分镜等。这些都来自视频任务已经保存的字段，不改数据结构。
- 改动后提示「改过了，再生成会多做一条，原来那条不变」，并提供「还原」。
- 批量检查窗口：
  - 现有的「统一供应商」和「统一秒数」放到窗口顶部显眼处。统一秒数的选项取所选分镜的模型都支持的秒数（交集）；现在只按第一行的模型取，要改。
  - 每个分镜的提示词能直接在窗口里改，打字时不丢焦点。
  - 「一键填充」只填空着的提示词；「全部生成」只提交还没有任务的分镜。实施时先核对现有规则，不一致的在 Comments 记下再定。
  - 保留逐条改秒数。
- 秒数、尾帧、智能分镜、全能参考按各模型现有的能力表限制。
- 拿掉并发设置（单条和批量两处）。

**第 5 步 单条精准混剪**
- 交互一律沿用现有组件的行为：
  - 素材调整：替换当前片段、添加到缺口、预览、重新分析。
  - 实时合成预览。
  - 截取条：拖动选框，回车应用，Esc 取消。
  - 五轨时间轴：单击选中、拖动排序、拖两端修剪、双击、右键菜单、磁吸。
  - 快捷键：空格、V、B、⌘B、N、左右键走帧、Shift 走 10 帧、Delete、⌘Z / ⌘⇧Z、Esc。
- 右栏顺序不变：视频倍速和视频画面调整（选中片段时）、视频包装、字幕样式、背景音乐、口播音频变速、口播音量、视频封面设置。
- 字幕样式卡片不另放小预览；改动直接显示在中间的预览上。
- 页面宽度见「不能动的东西」里的混剪加宽一条。
- 导出成功后点成片打开预览对话框（见下文），播放真实导出的成片，有声音。

**批量生产**
- 第 5 步工具栏的分段按钮可以在「单条精准混剪」和「批量生产」之间切换。
- 四步的内容、规则和交互都不变，只换外观。统一审片的全部操作（见用户故事 72）沿用现有实现。
- 导出页：
  - 成片卡片显示封面，鼠标移上去出现播放图标，点卡片打开预览对话框。
  - 卡片里不再嵌播放器。
  - 新增「一键下载全部」（见下文）。

**控制台：运行总览**
- 顶部是数量卡：正在跑、在排队、今天已完成、出错。
- 中间是最近任务表：任务、项目、发起人、模型、状态、时间。点一行跳到全员任务的详情。
- 右栏放三块：
  - 名额占用。
  - 「今天的成员」：谁在做什么，链到团队用量。
  - 「开工前还差几件事」：公司模型代理、参考图中转、模型名额等。每件写明状态和去处，数据来自现有的就绪检查。
- 全 0 的空状态。
- 「暂停生产」先弹出说明，确认后才生效。

**控制台：全员任务**
- 搜索项目、模型或编号，打字时不丢焦点。
- 按发起人和状态筛选。没有结果时显示说明和「清除筛选」。
- 详情写错误编号、失败阶段、模型、调用记录，能重试。

**控制台：模型与名额**
- 一个名额池（同一个上游账号）一行，显示账号名、类别、名额、当前占用（已占、已受理、可能已发、未发）、状态、共用的模型数量。展开显示模型列表和正在使用的成员。
- 名额对整个池生效，改一次保存一次。保存时沿用现有的版本号防冲突。
- 状态用大白话：可以用、还没设名额、缺密钥、已停用。映射问题写成一句话并给去处。
- 内部池编号默认隐藏，可以点开看。
- 同一个上游凭据被绑到不同名额池时显示提醒，建议合并。
- 准入计数规则不变，本来就按池计数。

**没出原型的页面**
- 创作画布、成员与账号、团队用量、供应商配置、公共资源、版本与备份、下载与交付、回收站、修改密码、出错的任务。
- 只换外观（令牌、字体、侧栏、工具栏、分组列表、表格、空状态），功能和信息结构不变。

### 服务器统一管理的生产参数

- 团队版下，新建项目、提交图片任务和视频任务时，超时、并发、图片预处理（开关、最长边、压缩质量）一律用服务器配置的默认值。请求里带了这些字段也忽略，这样旧客户端也受统一管理。
- 起步默认值等于现在客户端的默认值：超时 600 秒，项目并发 10，图片预处理开启，最长边和压缩质量沿用现在的默认。
- 实际能同时跑几条，仍由名额池、成员并发上限和自动公平共享决定（ADR-0001）。项目并发不会越过这些限制。
- 默认值写在服务器运行配置里，首版不做修改界面。
- 员工界面拿掉这些控件的位置：新建项目、第 1 步场景图、第 4 步视频（单条和批量两处）。员工可见的状态文字里，「等待并发空位」改成「排队中」。
- 个人本地版保持现状。

### 导出预览与一键下载全部

预览对话框（批量导出页，以及单条导出成功后）：

- 画面宽高按可用高度直接算出来（成片是 3:4），不靠浏览器从比例推宽度。原因：原型在 Safari 里被挤成一条细缝（第八轮）。
- 控件：
  - 播放暂停、可点可拖的进度条、时间。
  - 批量预览多一组「上一条 / 下一条」。
  - 空格播放暂停，左右键换条，Esc 关闭。预览开着时方向键不翻页。
- 播放内容：
  - 已导出：播放当前成片。
  - 改过但没重新导出：播放上一版正式成片，并写明这一点。
  - 从没导出：播放检查成片里的合成预览，写明这一点，不显示下载按钮。
- 旁边的信息：脚本、时长、画幅、状态、文件名。

一键下载全部：

- 选项：成片和封面（打包下载）、只要成片、只要封面。
- 服务端提供「本批次可下载文件清单」：
  - 只列可导出成片的当前正式产物，按选项筛视频和封面。
  - 改过未重新导出的，给上一版正式产物。
  - 每项带文件名和大小。
  - 在服务端检查身份与归属，只能拿到自己可见的批次。
- 工作台轻客户端：
  - 把清单交给现有的交付下载，写到员工设置的下载根目录，按项目和导出版本分目录，同名不覆盖。
  - 本机已经下载成功的跳过。
  - 失败只补下载，不重新生成或渲染。
  - 服务器生成成功和本机下载成功分开记录（沿用现有规则）。
- 没有轻客户端、只用浏览器访问时，服务端先打包成 ZIP 再下载。
- 没有可下载的成片时提示「还没有导出过的成片」。

### 小窗口与画面尺寸

- 设计尺寸 1536×864（1920×1080 缩放 125%）。最小要支持桌面客户端的最小窗口 1024×720。
- 宽度小于 1280 时，侧栏收成只有图标的窄条（悬停显示名称），混剪的「素材调整」默认收起。原型没有覆盖这一条，实施时先出截图请用户确认。
- 任何宽度下：
  - 页面不横向滚动。
  - 按钮、标签、输入框不被切掉一截。
  - 工具栏放不下时，先藏次要说明文字，再收紧间距。
- 视频画面：
  - 所有画面保持 3:4 或 9:16。
  - 剪辑区预览至少约 200 像素高，放不下就让中间一栏上下滚动。
  - 预览对话框的宽高直接算出来。

### 不能动的东西

- 混剪与批量的交互行为、快捷键和操作顺序（第七轮定）。
- 8 月定的混剪加宽，目的是给小屏监看留出最大画面：
  - 个人本地版保留原样的破格宽度和按窗口高度撑满。
  - 团队版改成占满侧栏右侧的内容区。
- 内部名、数据目录、环境变量、存储键、Cookie、路由地址。
- 统一生产服务在服务端检查身份与归属。新加的文件清单和 ZIP 接口也一样。
- 已有的守护测试断言保持不变，例如打包禁入清单。只有两条例外，就是上面说的停止脚本应用路径和配音试听文案。

## Testing Decisions

**好测试的标准：** 只测用户能看到、能点到的行为和 HTTP 接口约定，不测类名、组件内部状态或像素位置。以下几条尺寸要求本身就是需求，所以要测：页面不横向滚动、控件不被切掉、视频画面比例正确。

**主要检查面（页面级）：**
- 在现有的团队验收程序上扩展：单独启动一份隔离的服务（独立数据根、测试账号），用浏览器模拟真人操作。
- 不调用付费模型，沿用现有「付费调用次数为 0」的断言。
- 准备测试数据：
  - 一个项目：有场景候选、分镜组、项目脚本、几条模块 4 素材和一条单条精准混剪。
  - 一个批次：成片状态里有已导出、修改未导出、从没导出、失败四种。
- 原型的点按清单（`tools/checks/e2e-点按清单.py`，约 200 个检查点、运行时 315 项）按屏改写到正式界面。
- 浏览器：Chromium（桌面客户端的内核）和 WebKit 都跑。
- 窗口尺寸：1536×864、1280×720、1024×720，浅色和深色。
- 尺寸检查跟着页面级检查一起跑，照原型的「按钮被切」「工具栏藏内容」「画面比例」三个脚本改写：每屏、每个弹窗都量。

**服务器规则（接口级，三处）：** 照现有 `scripts/team-*.test.ts` 的写法，用内存数据库或隔离服务。
1. 团队版下，新建项目和提交任务忽略客户端传来的超时、并发、预处理，改用服务器默认值；个人本地版行为不变。
2. 名额池管理按池汇总模型；改一次名额对整个池生效；同一凭据分属不同池时给出提醒；版本号冲突时拒绝保存。
3. 「本批次可下载文件清单」只含当前正式产物，按视频和封面筛，修改未导出时给上一版，拿别人的批次被拒绝；ZIP 的内容和清单一致。

**回归（证明操作没变）：** 现有混剪、批量、包装、脚本、画布、团队验收的浏览器测试全部要通过。允许改的只有因外层结构变化而失效的选择器；不许放宽行为断言，不许删掉检查。

**守护测试：**
- 停止脚本的应用路径断言改成同时认新旧路径。
- 配音试听文案断言改成新名字。
- 字体文件要能随 standalone 产物和 Windows 免安装包一起发布，打包禁入清单的断言保持不变。

**人工验收：** 在一台员工的 Windows 电脑上（1920×1080、缩放 125%）人工走一遍：
- 登录。

- 控制台三页。
- 深色模式。
- 最小窗口。
- 字体确实显示为思源黑体和 Inter。

## Out of Scope

- 第二批新能力：首页「等你处理」跨项目汇总、成片「通过 / 这条重做」、成片多版本并排比较。原型里用「加新能力」开关看它们的样子，本次不做。
- 混剪和批量的任何交互改动。
- 个人本地版的结构重设计；本次只换名字、标志和令牌。
- 改超时、并发、预处理默认值的管理界面。
- 改内部名、数据目录、环境变量、存储键或路由。
- 商标检索、对外宣传物料；原型里的品牌页只作为设计规范参考，不做成产品页面。
- 本地实拍重组（ADR-0001 的分期例外）。
- 原型专用的东西：底部评审条、「第一批 / 加新能力」开关、「Mac 样子 / Windows 样子」开关、示例数据和模拟生成。
- 没出原型的页面的功能和信息结构变化。
