# 团队用量分析页面 PRD

**状态：** `ready-for-agent`
**日期：** 2026-11-05

## Problem Statement

统一生产服务已经有成员额度、费用预留、实际执行尝试和调用明细，但“费用与用量”页面仍主要是一张个人额度区加调用明细表。管理员无法在同一页面快速判断团队本月额度、哪个模型消耗最多、费用怎样变化，以及费用由哪些成员产生；进入某位成员的用量也需要跳转或自行组合查询。

普通员工只需要看清自己的额度、模型消耗与调用记录，不能因页面新增团队分析能力而看到其他成员的数据。此前的正式实现曾出现模型权限函数导出缺失的构建错误，首版图表排版也未通过评审，已停止并回退。本轮从已确认的本地版分区原型重新拆清范围，不把原型中的模拟数字当成真实统计。

## Solution

补齐服务器模式的团队用量页面，采用已确认的 `local`（本地版分区）信息层级：团队额度 → 筛选条件 → 模型消耗排行与趋势 → 成员用量。

- 管理员默认可查看全团队的模型统计、趋势、成员用量和调用明细，并可从成员行进入该成员的下钻视图。
- 普通员工只查看自己的额度、模型统计与明细；没有团队范围开关、成员列表或成员下钻入口。
- 团队额度按北京时间自然月计算，不随分析筛选条件变化；模型、趋势、成员和调用明细共用当前分析范围。
- 复用现有分区、卡片、表格、表单、设计令牌和趋势图风格。图表与模型统计采用清晰的上下或左右分区，保证图表有足够可读空间，不照搬原型中的模拟值。
- 已结算、预留、已释放、未定价与不确定费用保持既有统计语义。未定价和不确定不能展示成零元，预留包含在已计金额中，不重复相加；页面继续注明本地 Agent 不计入、金额不等于供应商最终账单。
- 使用统一的服务端查询入口提供以上数据，权限必须在服务端执行，不依赖前端隐藏。

## User Stories

1. 作为管理员，我想在页面顶部看到团队本月已计费用，以便快速掌握本月实际使用规模。
2. 作为管理员，我想分别看到已结算费用与待结算预留，以便区分已完成费用和在途占用。
3. 作为管理员，我想看到有限额度成员的额度合计，以便了解已分配的可用预算。
4. 作为管理员，我想看到有限额度成员的剩余额度，以便发现团队预算是否接近耗尽。
5. 作为管理员，我想知道有多少成员不限额，以免把有限额度合计误认为团队总预算。
6. 作为管理员，我想看到额度统计所属的北京时间自然月，以便确认当前账期。
7. 作为管理员，我不希望团队额度随“今日”或模型筛选而变化，以便保持月度额度口径稳定。
8. 作为管理员，我想按今日、近 7 天、本周、本月和自选日期筛选，以便观察不同时间范围的消耗。
9. 作为管理员，我想按模型筛选，以便单独检查某个模型的费用和调用。
10. 作为管理员，我想按成功或失败结果筛选，以便区分不同结果的调用与费用。
11. 作为管理员，我想刷新当前统计，以便在任务执行后查看最新数据。
12. 作为管理员，我想看到模型消耗排行，以便找出主要费用来源。
13. 作为管理员，我想看到每个模型的调用次数、已计费用和占比，以便比较模型消耗结构。
14. 作为管理员，我想看到按日拆分的模型费用趋势，以便识别消耗上升或异常的时间。
15. 作为管理员，我希望趋势包含没有调用的日期且金额为零，以便正确理解连续时间变化。
16. 作为管理员，我想看清趋势图的坐标、图例和模型对应关系，以便不把颜色或折线误读为其他模型。
17. 作为管理员，我想在同一图表区域看到模型统计，以便从趋势直接定位到具体模型。
18. 作为管理员，我想看到未定价和不确定调用数量，以便知道统计中存在不能折算为金额的记录。
19. 作为管理员，我想看到成员用量列表，以便了解每位成员的调用、已计费用、额度和剩余可用。
20. 作为管理员，我想区分员工与管理员账号，以便正确理解成员列表。
21. 作为管理员，我想从不限额成员的显示中明确识别不限额，以免显示为零或空白额度。
22. 作为管理员，我想从成员行进入该成员用量，以便继续追查其模型消耗和明细。
23. 作为管理员，我想在成员下钻中看到成员身份和本月额度摘要，以便确认当前查看对象。
24. 作为管理员，我想在下钻中沿用日期、模型和结果筛选，以便按同一口径检查成员。
25. 作为管理员，我想在成员下钻中看到该成员的模型排行和趋势，以便定位其费用来源。
26. 作为管理员，我想在成员下钻中看到该成员的调用明细，以便核对具体执行尝试。
27. 作为管理员，我想从成员下钻返回全团队，以便继续检查其他成员。
28. 作为管理员，我想看到调用时间、成员、模型、模块、结果和费用，以便识别一笔调用。
29. 作为管理员，我想按需展开任务、上游请求、重试与错误关联，以便进一步诊断，而不让表格默认过载。
30. 作为管理员，我想沿用团队用量导出能力，以便把同一范围的明细用于核查。
31. 作为普通员工，我想看到自己的本月已计、月度额度、预留和剩余可用，以便判断能否继续生成。
32. 作为普通员工，我想看到自己的模型排行与趋势，以便理解个人费用构成。
33. 作为普通员工，我想按日期、模型和结果筛选自己的统计，以便找到特定记录。
34. 作为普通员工，我想看到自己的调用明细和诊断关联，以便配合定位失败任务。
35. 作为普通员工，我不应看到其他成员的姓名、工号、用量、额度或明细，以便保护团队数据边界。
36. 作为普通员工，我即使直接构造团队范围或他人员工参数的请求，也只能查询自己或得到明确拒绝，以便权限不依赖界面约束。
37. 作为普通员工，我不应看到成员下钻和团队导出能力，以便页面只呈现与本人有关的操作。
38. 作为使用者，我想在无数据、加载中和读取失败时看到明确状态，以便区分没有调用与系统异常。
39. 作为使用者，我想看到已释放、未定价和不确定的明确文字，而不是误导性的零元，以便正确理解费用。
40. 作为使用者，我想在窄屏幕上横向查看完整表格，并不丢失关键操作，以便使用现有工作区的不同窗口宽度。
41. 作为负责人，我希望本轮页面基于真实执行尝试统计，以便原型确认能转化为可验收的功能。
42. 作为维护者，我希望本轮不引入第二套计费或权限模型，以便页面与准入、成员管理保持同一口径。

## Implementation Decisions

- 仅补齐统一生产服务的团队用量页面。本地版没有账号与团队身份，不增加本地版团队用量入口，也不改变本地实拍重组边界。
- 采用已确认的 `local` 原型结构，不采用趋势优先或成员优先方案。原型只作为信息层级与交互参考，不复用模拟数据、原型调试工具条或一次性样式实现。
- 团队额度是独立的北京时间自然月摘要，包含团队已计、已结算、待结算预留、有限额度合计、有限额度剩余及不限额成员数。有限额度合计与剩余只聚合设置月度上限的成员；不限额不作为无穷大金额参与求和。
- 团队额度与现有成员月度门禁共用费用口径。已计包含已结算及仍有效的费用预留，预留不再额外加入已计；已释放不计入。
- 分析区支持今日、近 7 天、本周、本月和自选日期。日期均按北京时间自然日计算，周从周一开始，查询区间为左闭右开。团队额度固定为当前自然月，分析区可独立选择时间。
- 模型统计以执行尝试及其操作、实际成员和核心模型身份为权威来源，覆盖真实重试和内部协议回退，不使用旧用量镜像作为另一套聚合来源。
- 模型费用趋势按北京时间自然日分桶，以当前筛选范围为上限；逐日补零。模型筛选生效时只展示相应模型，结果筛选同步作用于模型统计、趋势与调用明细。
- 成员列表为管理员能力。成员的调用数与筛选费用属于分析范围；成员的月度额度、已计、预留和剩余属于当前自然月，页面需分别标明，避免混合账期。
- 管理员选择成员后，使用同一页面查询入口传入目标成员，返回该成员的月度摘要、模型统计、趋势和明细。前端不得从全团队响应中自行推导员工数据权限。
- 普通员工的查询范围在服务端固定为当前登录人；团队开关、成员列表和成员下钻均不可用。直接请求团队范围不得返回团队数据，直接请求他人员工必须拒绝。
- 复用现有团队用量 GET 接口作为唯一主要数据入口，按当前身份与筛选返回额度、模型统计、趋势、成员摘要和调用明细。保持既有响应字段兼容，新增字段而非另建平行统计接口。
- 复用现有成员列表与成员摘要能力，不新建成员管理或额度编辑入口。本轮只读，不修改费用额度、并发、模型权限、暂停状态或任何生产策略。
- 调用明细保留现有稳定倒序与任务、请求、错误关联。若补充分页，采用现有用量记录的服务端稳定分页方式，不以大列表客户端截断冒充分页。
- 团队 CSV 继续仅限管理员，并沿用查询过滤和权限；不把未定价或不确定导出为金额零。
- 费用以整数最小单位在服务端聚合，展示层再格式化人民币。占比在总额为无时为零，不把未知费用纳入已知金额分母。
- 趋势图使用轻量 SVG 或既有展示能力，不新增图表依赖。图表有清晰坐标、图例、空状态及足够尺寸；模型排行与趋势不在窄列中挤压。
- 新增 UI 颜色使用设计令牌，保持浅色、深色和跟随系统行为，不新增硬编码浅色值。
- 不修改数据库结构，不改变迁移、执行尝试、预留、定价、供应商或生产调度逻辑。
- `actorModelAllowed` 缺失是现工作区中执行准入模块删除导出而调用方仍引用的问题。实施前单独恢复或正确重建该既有导出，并运行准入相关测试；不得通过删除权限检查、放宽模型白名单或绕过准入来消除构建错误。该修复与用量统计分离，不将权限函数重新实现于用量模块。
- 保留并核实现工作区的其他未提交修改，不回滚无关变更，不将原型路由加入正式生产入口。

## Testing Decisions

- 主要测试接缝是带真实认证身份的现有团队用量 GET 接口。一次测试准备多成员、多模型、已结算、预留、已释放、未定价和不确定记录，验证同一响应的额度、模型、趋势、成员与明细外部行为，而非 SQL 或组件内部实现。
- 权限在同一个接口接缝验证：管理员可查全团队与指定成员；员工默认只查本人；员工请求团队范围不能得到他人数据；员工请求他人员工被拒绝；成员列表与 CSV 仍受原权限约束。
- 账期测试覆盖北京时间自然月、周一起算、月末跨 UTC 日期、左闭右开边界、近 7 天与自选日期。团队额度不随筛选变化，分析区数据随筛选一致变化。
- 聚合测试验证真实重试与协议回退分别形成执行尝试、模型汇总与明细一致、趋势逐日补零、成员调用数正确、总额为零时占比为零。
- 费用测试验证已释放不进入已计、预留不重复相加、未定价与不确定不按零元展示、有限额度合计不含不限额成员、后补实际费用保持既有语义。
- 复用团队用量路由、团队用量管理、日期范围、执行准入及团队用量 UI 合同测试。优先扩展这些测试，不新建与现有接缝平行的测试体系。
- 页面合同覆盖已确认的分区顺序、管理员成员下钻、员工无团队入口、筛选、图表可读结构、表格与错误/空/加载状态；不以源码字符串存在代替真实权限测试。
- 视觉验收至少覆盖管理员全团队、管理员成员下钻、普通员工三种视图，以及桌面与窄窗口、浅色与深色。重点核对首版出现问题的图表比例、图例、长模型名称和表格横向滚动。
- 实施验证包含定向 Node 测试、TypeScript 检查、定向 ESLint 和生产构建。构建必须验证 `actorModelAllowed` 导入解析，且执行准入测试通过。
- 测试使用临时数据根与内存/临时数据库，动态导入前设置环境，不连接真实供应商，不产生真实付费调用。

## Out of Scope

- 不修改本地版消耗看板的固定模型范围或计价规则。
- 不接入本地 Agent 与本地实拍重组的服务器用量统计。
- 不新增或调整供应商、价格、Token 计量、费用预留、额度准入、并发或模型权限规则。
- 不新增账号、编辑成员额度、暂停生成或修改成员策略的界面。
- 不对接供应商账单，不承诺工作台金额与供应商最终结算一致。
- 不新增数据库表、迁移、后台调度器或独立图表服务。
- 不改造团队任务、错误中心、账号与权限等其他页面的布局。
- 不保留趋势优先、成员优先方案，不把原型模拟数据或调试切换器带入正式页面。
- 不在本轮提交、回滚或清理工作区既有无关变更。

## Further Notes

- 已确认的页面顺序是团队额度 → 筛选条件 → 模型消耗排行与趋势 → 成员用量；管理员成员下钻保留该成员的额度、筛选、模型统计与调用明细。
- 当前正式页面已具备个人额度、团队/本人范围、基础筛选和调用明细；现有成员接口已经有月度摘要，实施以扩展与组合为主，不重建账本。
- 当前工作区的执行准入模块存在 `actorModelAllowed` 导出删除，而调用方仍有引用。这是必须在正式构建前处理的真实阻断，不属于 UI 样式问题。
- 本规格只描述需求与验收，不代表正式页面已经修改或验证通过。后续按仓库任务单约定拆实施任务，每项写清范围与验收后再动工。
