# 团队版统一模型调度：Image 2 与可灵 3.0

**状态：** `ready-for-human`

**确认日期：** 2026-11-10（UTC+8）  
**阶段：** 产品规则已逐项确认，本文整理供审阅；尚未实施、测试、打包或部署。  
**当前授权边界：** 用户明确要求“只跳过试点，暂不改代码”。本文不代表开始实施或部署的授权。  
**范围：** 团队版服务端负责的 Image 2、可灵 3.0 生成入口；个人本地版不在本次范围内。

## 1. 要解决的问题

员工目前需要在同名模型的不同供应商之间选择，并在部分失败后自己换供应商。用户希望客户端只提供一个 Image 2、一个可灵 3.0，由后台优先使用七牛，在拥堵或符合条件的失败时使用腾讯。

这项功能同时追求简化模型选择、提高任务完成率和利用备用通道的空闲容量。实际吞吐增幅取决于两条通道的真实配额、生成耗时和共同网关的限制，不能把应用配置的两个池容量相加后直接承诺扩容比例。

统一后，员工关注一条制作任务及其结果；管理员能够追溯该任务在各通道的真实执行和费用。

## 3. 范围与概念

### 3.1 三种身份分别保留

- **统一模型**：员工选择的 Image 2、可灵 3.0，承载模型授权和产品能力。
- **通道**：后台实际执行的七牛或腾讯供应商及精确模型身份，承载接入配置、真实池归属、健康状态和计价。
- **制作任务与尝试**：一条员工任务可以有最多两次通道尝试。尝试分别保存远端身份和费用，不能将两次尝试显示成两份用户主动创建的作品。

轮询、查询恢复和结果补下载不属于再次生成，不消耗新的通道生成机会。重复点击、重启恢复和同一个幂等请求不能重新获得两次机会。

### 3.2 入口边界

团队服务端的普通项目场景图、分镜图片及重新生成、单条与批量提交视频、创作画布、新建实拍局部返工，都应遵守同一套产品规则。

批量创建表示每条独立生成任务各自遵守上限，不是整批只能提交两次。只分析、剪辑、包装或渲染已有素材的步骤，不因此新增一次模型生成。仓库外独立 Agent/CLI 的付费调用不自动纳入团队服务端的管理范围。

其他模型继续使用原有能力；本次不把不同模型版本、质量档或名称相似的自建供应商自动合并。

## 4. 候选能力与输出合同

每次提交前，先根据冻结的输入与输出要求判断哪些通道能够完成，再进行优先级和名额调度。

“能力合集”必须是**可执行参数组合的合集**，不能分别合并清晰度列表和比例列表后任意组合。例如当前代码中，七牛支持 9:16，但没有 1K；腾讯支持 1K，但没有 9:16。因此不能从两张表拼出两家都无法执行的“1K + 9:16”。前端选项和服务端校验要表达同一套组合约束。

合同至少覆盖输入素材及顺序、提示词、清晰度档位、画幅、视频时长、生成模式、首尾帧、智能分镜，以及入口已明确选择的其他输出要求。跨通道允许采用各自的协议字段和已验证的素材交付方式，不改变这些业务要求。

两家同时满足全部要求才可互为备用。只有一家满足时直接选择该家；没有一家满足时，在付费提交前说明不支持的组合。

“保持清晰度和比例”不保证随机生成内容相同，也不等于两家原生返回像素完全一致。沿用已验证的原生交付和比例裁切合同，不通过放大低档位结果冒充高档位，也不为凑齐备用通道而自动关闭智能分镜或丢弃尾帧。

## 5. 调度规则

### 5.1 首次通道选择

| 条件 | Image 2 | 可灵 3.0 |
| --- | --- | --- |
| 两家兼容、七牛可准入 | 七牛 | 七牛 |
| 两家兼容、仅七牛因名额不足暂不能准入 | 先等七牛；达到 30 秒后允许腾讯接单 | 允许腾讯直接接单 |
| 只有腾讯兼容，或七牛已被停用／暂时避开 | 腾讯可准入时直接接单，不等拥堵阈值 | 同左 |
| 只有七牛兼容 | 按七牛名额排队 | 同左 |
| 可用候选通道均没有名额 | 等待可用资源 | 等待可用资源 |
| 没有兼容或启用的通道，或不满足权限／预算条件 | 显示具体原因及处理提示，不伪装成正常生成 | 同左 |

30 秒只计入任务本来可以执行、仅受七牛容量限制的等待。个人额度、模型权限、预算或管理员暂停等限制，不能通过计时或换通道绕过。阈值到达只是允许分流，不是强制选择腾讯；七牛重新可用时仍遵守七牛优先。

### 5.2 共享池与公平

实际通道使用真实共享池名额，保留已有成员轮转、自动公平份额、个人上限和容量边界。不同模型名称不能凭空获得独立容量；切换通道需要重新通过目标池准入，不能沿用原池的许可。

腾讯池同等调度条件下，优先处理只剩腾讯可用的任务，包括原本只有腾讯的模型／规格，以及七牛已经明确失败、只剩腾讯机会的任务。仍可等待七牛的普通 Image 2 溢出任务优先级较低。

这一优先规则不能越过成员公平和预算，也不取消、抢占已经提交的任务。同等条件的判断、排队顺序和防止长期饥饿的实现，应在执行设计与验收中具体化。

### 5.3 故障避让与恢复

连续服务故障可以使相应通道暂时退出新任务候选；恢复后重新参与，重新遵守七牛优先。正在执行或结果未知的任务仍归原通道查询，不能因健康状态变化被搬到另一通道重发。

单素材审核拒绝、用户输入问题不作为整个通道故障。健康判断应区分模型通道、共享网关与公共素材交付环节，不能把一个模型的问题无依据扩大为同供应商全部模型故障。

管理员启停与系统临时避让分别表达。系统恢复逻辑不得重新打开管理员手动关闭的通道。失败窗口、冷却时间、恢复检查方式等数值属于后续实现设计，当前尚未冻结。

## 6. 失败、兜底与未知结果

### 6.1 统一判断标准

| 证据或情况 | 行为 |
| --- | --- |
| 通道明确未创建任务，且另一通道可能满足原请求 | 可进入另一通道的候选与准入流程 |
| 远端明确终态失败，包括本次请求明确的审核拒绝 | 在另一通道支持原请求且仍有机会时，使用原素材、原提示词和原参数再尝试一次 |
| 请求可能已被受理，无法确认是否创建 | 标记结果确认中，不自动再次生成 |
| 已有远端 ID，查询超时或临时断网 | 继续原通道查询，不把本地超时当成远端失败 |
| 已生成结果，只是下载或落盘失败 | 查询／补下载原结果，不新建远端生成 |
| 素材损坏、原始请求不合法或缺少权限／预算 | 显示可处理的具体原因，不盲目尝试其他通道 |
| 可用通道已经明确失败且没有剩余候选 | 展示最终失败与处理建议 |

不能仅凭任意 HTTP 状态、错误字符串或超过本地等待时间，就断定远端没有创建任务。限流、5xx、网络中断需要结合受理证据分类；普通项目、画布、返工各入口必须采用一致标准。

用户提出的审核拒绝兜底不包含自动修改提示词、素材或输出要求。每条素材的拒绝只影响自身任务，不据此停用所有人的通道。

### 6.2 次数、顺序与中间状态

- 通常顺序为七牛到腾讯；因溢出先走腾讯时，也允许腾讯明确失败后再走七牛。
- 同一任务不能在两条通道之间循环，不能双发竞速取先返回结果，不能通过代理内部隐形重试突破两次生成提交上限。
- 备用通道名额满时保留原任务等待，显示“等待可用资源”；排队不消耗提交机会。
- 中间一次失败由后台处理，员工无需手动选择通道；管理员仍能看到这次失败。
- “两家失败后再告诉用户”不意味着隐瞒预算不足、权限变化、没有兼容通道或无法确认受理结果。这些情况应显示真实状态和可行动提示。

## 7. 身份、授权与费用

### 7.1 冻结与追溯

制作任务保存统一模型、不可变输入、输出要求及适用的规则版本；每次真实尝试分别保存实际供应商、精确模型、配置／凭据版本引用、池身份、远端任务 ID、价格快照和结算状态。

具体数据结构在执行设计阶段确定。不得为了显示统一模型而覆盖旧尝试的真实供应商、远端 ID 或计价记录。服务器重启不能丢失已使用的通道、取消意图或已有远端身份。

### 7.2 模型授权

员工获准使用 Image 2，就能通过后台使用管理员启用的对应七牛／腾讯通道；可灵 3.0 同理。旧任一对应通道的授权映射为该统一模型授权。迁移按可信精确身份匹配，不通过任意显示名称或宽泛前缀扩权。

模型授权不覆盖账号停用、管理员暂停、预算不足或通道禁用。每次新生成提交前重新检查当前权限和预算，包括自动备用尝试。

### 7.3 费用展示和结算

按实际执行通道记录各次尝试，任务层汇总。员工看到自己的统一模型和任务合计用量／费用；管理员能展开各通道尝试和核对状态。员工接口与页面都应采用这一展示口径，同时保留原有人员数据隔离。

失败尝试不能直接假定免费；费用未知不能显示为已确认的零元。估算与实际核账费用明确区分。备用尝试重新检查预算，不能通过提前释放仍未核清的第一次占用为第二次腾出额度。

不设员工固定统一售价，也不把所有通道按七牛价统计。同样规格因实际通道不同而产生不同费用，是用户已经接受的产品行为。

## 8. 取消与管理员待核对

### 8.1 取消

未提交的任务取消后不再发起生成。已提交的任务取消后，不再启动新提交、备用尝试或自动后续生产步骤；已有远端任务继续核对、必要时补下载，保留结果与费用。

页面可以说明“已停止后续生成，已提交任务仍在收尾”。晚到成品保留在任务记录，供查看或使用，不因取消而抹掉已经发生的结果和成本。

取消不能承诺远端立即停止或没有费用。未知受理状态下不能仅因本地取消就释放真实名额或预算；已有远端取消能力也必须根据响应证据完成状态核对。

### 8.2 管理员核对

统一待核对列表应关联成员、项目／画布、任务、统一模型、真实通道、尝试、已知远端 ID、等待原因、最近检查时间、费用与名额占用。员工不需要在日常流程中理解这些执行细节。

| 核对证据 | 处理 |
| --- | --- |
| 找到远端任务 ID | 关联原尝试后续查，不创建新的生成 |
| 确认远端未创建 | 修正原尝试状态；任务未取消且仍满足规则时，允许剩余备用通道接手 |
| 确认远端已成功 | 补齐结果并核对费用、占用；已取消任务不推进下游 |
| 确认远端已失败 | 补齐终态与费用证据，按原任务剩余机会及取消状态处理 |
| 仍无证据 | 保持待核对，不仅因时间长就标记失败重发 |

核对操作限管理员，记录操作者、依据和变更，重复操作幂等。不得提供用“强制失败”绕过证据核对并重新获得两次机会的入口。

## 9. 新旧任务与实拍返工

启用前已经创建的任务，无论排队、运行、失败、补抓或结果未知，均维持原规则、供应商冻结身份和费用记录。旧任务的恢复或原语义重试不能被误认成新任务。

用户重新生成创建的新任务使用统一调度。任务创建边界应覆盖普通项目与画布，不能通过回填新默认值改写已有画布任务的能力键或供应商快照；尚未创建任务的草稿与已创建执行记录需明确区分。

新建实拍局部返工适用两条通道各一次的上限，这是用户明确接受的既有“一次付费提交”合同变更。旧返工任务继续原上限，同一 requestId 的继续执行不形成新付费授权。返工原有输入冻结、归属隔离及明确关闭智能分镜等要求继续作为该任务合同，不因换通道改变。

## 12. 全量启用与尚待验证的事实

用户确认跳过小范围试点。完成未来获准的实施和必要验证后，方案按团队版全量启用设计；这不等于省略验证，也不等于现在已经允许修改代码或上线。

以下尚待后续验证或技术设计，不应写成已确认的线上事实：

1. 七牛与腾讯的上游配额是否独立，以及共享网关、素材交付和下载环节是否形成共同瓶颈。
2. 当前真实能力组合、可灵智能分镜状态、生成模式／输出质量是否满足统一模型合同。
3. 最新结算价、失败／取消／未知请求的实际计费方式及管理员可取得的核对证据。
4. 通道故障窗口、恢复阈值、核对节奏、排队优先实现及客户端兼容处理的具体设计。
5. 如何在现有冻结快照、幂等与账本设施上表达一条任务的多通道尝试，而不改变旧任务语义。

功能效果按任务完成耗时、自动兜底挽回率、每个成功成品的累计成本、其他模型等待时间及未知占用数量观察，不以“备用通道被调用了多少次”单独判定成功。
