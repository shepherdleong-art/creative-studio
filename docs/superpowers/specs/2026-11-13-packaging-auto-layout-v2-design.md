# 贴纸与正文卖点自动布局 v2 设计规格

> 迁移说明（2026-11-17）：本文保留旧分支的设计来源；其中历史评审评分不是本次验证结果。迁移基于 PR #12–15 合并后的 main，末段槽位沿用主线的 65%／81%，闪屏实现沿用 PR #14。本次实现、修复和证据以 `docs/2026-11-17-贴纸2.0独立迁移与验收.md` 为准。

> 日期：2026-11-13
> 状态：设计评审通过，进入实施
> 独立评审：可靠性 96、精准性 96、人性化 95，总评 96

## 1. 目标

今后新生成的自动布局必须减少贴纸和正文卖点对模特、产品的遮挡：

- 开头和中段自动贴纸的完整可见外框位于实际视频画面的上 40%。
- 全片正文卖点的完整可见外框位于实际视频画面的上 40%。
- 结尾阶段两张自动贴纸固定使用下半部 62%／72% 槽位，不受上 40% 限制。
- 同时可见且视觉外框冲突的自动元素进行紧凑避让，不要求明显拉远。
- 手动调整仍可把贴纸和卖点放到任意位置。
- 预览、撤销重做、跨片复制和正式导出读取同一布局结果，不重新随机。

本设计不是单纯修改中心点或静态槽位，而是建立可版本化、可预检、可恢复的共享布局能力。

## 2. 明确范围

### 2.1 纳入

- 单条精准混剪与批量统一审片。
- 一键基础布置、换一组、跨片自动变体、正文卖点初始生成与显式重新提取。
- 1080×1440、1080×1920、1920×1080 三种实际输出画幅。
- 四套当前 HyperFrames overlay 模板。
- 自动贴纸六动效和正文卖点现有动效。
- 新旧元素混合、手动元素、撤销重做、后台恢复、任务快照和正式发布。

### 2.2 不纳入

- 结尾贴纸的上 40% 限制。
- 点击素材库直接新增贴纸的默认居中行为。
- 封面 20 帧、封面卖点、主副标题的新布局规则。
- classic/1、`lib/film-render` 和 classic 构建资产。
- AI 主体识别、自动缩小、非等比拉伸、镜像或新增视觉风格。
- 跨项目或跨批次复制。
- 旧数据后台批量迁移。

## 3. 用户行为契约

| 操作或元素 | 行为 |
| --- | --- |
| 开头、中段自动贴纸 | 完整可见外框默认位于上 40% |
| 新版正文卖点 | 完整可见外框默认位于上 40% |
| 结尾自动贴纸 | 固定下半部 62%／72% 槽位 |
| 点击素材库新增贴纸 | 保持当前居中逻辑 |
| 手动贴纸、已固定自动贴纸 | 位置不受自动安全区限制 |
| 手动卖点布局 | 始终覆盖自动默认布局 |
| 跨片复制手动或已编辑自动贴纸 | 复制实际持久化位置，不强制上移 |
| 跨片复制未编辑自动贴纸 | 生成新版变体，随机一次确定 |
| 旧成片、旧任务 | 未经明确重新生成，不改变布局版本 |
| 固定元素之间的重叠 | 原样保留，不制造自动求解失败 |

自动布局只允许平移，不改变素材、尺寸、旋转、动效、所在左右半区或阅读顺序。

## 4. 版本与持久化模型

### 4.1 自动贴纸版本与位置语义

自动贴纸 `origin` 增加：

- `layoutVersion`：当前支持值 `2`；缺失表示 v1。
- `positionPinned`：`true` 表示当前 `centerXPct/centerYPct` 是实际固定中心；新生成的未编辑 v2 自动贴纸缺省为 `false`。

未固定的 v2 自动贴纸：

- 持久化中心是规划器生成的基准中心。
- 规范布局服务产生运行时解析中心。
- 随机素材、时间、动画和基准槽位只生成一次并持久化。

固定的自动贴纸及手动贴纸：

- 持久化中心就是实际中心。
- 不参与自动区域约束或被动移动。

任何会使自动贴纸变为已编辑状态的操作，包括空间拖动、移动、修剪、换轨、风格、单张动画和全组动画修改，必须在同一次命令中：

1. 取得当前有效的解析中心。
2. 写入 `center = resolvedCenter`。
3. 写入 `positionPinned = true`、`autoEdited = true`。
4. 应用目标修改。

无法取得有效解析中心时整次不写，不得回退到基准中心。删除不需要固定位置。

### 4.2 正文卖点版本

包装配置增加独立的 `pointCuesLayoutVersion`：缺失表示 v1，新生成或显式重新提取为 v2。

以下操作可以升级：

- 全新混剪组或全新批量 output plan 的初始布局。
- 用户显式重新提取正文卖点。
- 新自动贴纸或新自动变体使用各自的贴纸版本。

以下操作必须保留原版本：

- 既有 output version 派生。
- 口播哈希变化导致的自动失效重建。
- 导出前自动刷新。
- 缓存恢复、普通配置保存或任务恢复。

贴纸与卖点版本互不强绑。重新提取卖点不升级旧贴纸，换一组不升级旧卖点。

### 4.3 成片级运行时版本

包装配置增加 `layoutRuntimeBundleVersion`：

- 全 v1 使用 legacy bundle。
- 任一新元素升级为 v2 后使用 v2 bundle，不自动降级。
- v2 bundle 明确保留 v1 兼容槽位、fit、视觉外扩和运行时行为。
- 元素版本只决定自身是否可移动和是否受上 40% 约束，不分别隐式选择共享模板资源。

未知版本必须保留原始数据，并在相关包装预览、编辑、预检或导出边界明确拒绝；不得静默清洗成 v1，也不得阻塞不依赖该包装的旧功能。

所有新增字段必须穿透配置清洗、命令重写、批量 arrangement、预览变量、任务快照白名单、worker、时间线变量、历史快照和导出 manifest。

## 5. LayoutResolution

规范布局服务返回不可变 `LayoutResolution`，至少包含：

- `inputHash`、`runtimeBundleVersion`、`geometryManifestHash`。
- 实际 `outputWidth/outputHeight`。
- 全部参与正文包装渲染或碰撞的元素，而非只包含可移动元素。
- 每个元素的规范 fit 参数、位置、缩放、旋转和资源身份。
- 未固定自动元素的 `resolvedCenter`。
- 固定元素的规范几何；固定仅表示不改变位置。
- 可确定重建逐帧 VisualBox 所需的信息及验证摘要。
- 引擎、模板、字体、贴纸和布局运行时身份。

Resolution 随包装 JSON 或批量 after 快照持久化，并进入撤销重做和正式任务快照。

浏览器只重放有效 Resolution，不独立决定 v2 自动位置或 fit。手动浏览器拖拽只按预览缩放换算实际输出坐标，提交后成为固定布局。

`inputHash` 或 `geometryManifestHash` 不匹配、Resolution 缺失、版本不受支持或逐帧验证失败时，不得展示完成态预览或正式导出。

## 6. 规范布局服务 CLS

### 6.1 统一执行环境

所有包含 v2 元素的以下路径使用同一 bundled Chromium、共享布局代码和资源 manifest：

- 规范预览所需的 fit、测量和解析。
- 自动命令预检。
- 跨片目标预检。
- 正式导出前的逐帧验证。

普通浏览器不得独立测量并生成另一套 v2 自动几何。

CLS 必须幂等、可等待、可取消。初始化顺序统一为：

1. 淘汰旧 generation。
2. 等待 `document.fonts.ready`、相关 `img.decode()` 和模板 fit。
3. 等待 ResizeObserver 初始稳定。
4. 批量测量。
5. 求解。
6. 批量应用。
7. 逐帧验证。
8. 发布 overlay 时间线与 layout ready 结果。

现有字体回调、延时 refit 和 ResizeObserver 必须进入同一调度器，不得事后绕过求解器重放旧基准。HyperFrames 必须等待布局 ready；失败或超时不得开始正式渲染。

### 6.2 画幅与数值

支持实际输出 1080×1440、1080×1920、1920×1080。

安全区为 `0 <= y <= 0.4 * outputHeight`，所有几何使用实际输出像素。

令 `s = min(outputWidth / 1080, outputHeight / 1440)`：

- 最小间距：`8s`。
- 双方各外扩：`4s`。
- 粗搜索网格：`4s`。
- 精细搜索网格：`1s`。
- 浮点 epsilon：`0.01s`。
- 最终位置量化：`max(0.1, 0.1s)` 输出像素。

### 6.3 完整 VisualBox

贴纸使用有效 Alpha 包围框，并纳入素材宽高比、视觉宽度、旋转和实际特效。

正文卖点使用文字适配后的元素盒，并添加模板声明且经测试的视觉外扩，覆盖伪元素、描边、阴影、滤镜、底板和装饰图。

不得直接把未补偿的 DOM rect 当成完整视觉外框。

### 6.4 逐帧可见性

统一采用 24fps 整数帧、`frameTime(f) = f / 24` 和结束帧开区间。

从同一 GSAP 时间线求每个输出帧的透明度、位移和缩放：

- 只检查实际 `opacity > 0` 的帧。
- 安全区和碰撞均按实际可见帧计算。
- 包含卖点额外退场时间和 `back.out` 过冲。
- 不使用原始 cue 时间代替实际可见区间。
- 不使用全时段保守运动包络造成过度避让。

布局器与播放共用帧时间和可见性解析。

## 7. 碰撞与搜索

### 7.1 固定与可移动集合

固定元素：

- 手动贴纸和带手动布局的卖点。
- `positionPinned=true` 的自动贴纸。
- v1 元素。
- 结尾阶段自动贴纸。

潜在可移动集合：

- 未固定的 v2 开头、中段自动贴纸。
- 第二阶段允许参与求解的未手动覆盖 v2 正文卖点。

硬碰撞约束只覆盖至少一端属于潜在可移动集合的元素对。固定—固定重叠原样保留，不计入无解或评分，但固定元素仍是可移动元素的障碍。

全固定时只生成 fixed-only 规范几何，不调用自动求解；固定元素可任意位置、重叠或越出自动安全区。

### 7.2 紧凑避让

1. 第一阶段只搜索贴纸位移不超过 `32s` 的候选，有解则采用最小位移贴纸解。
2. 提前返回前同时检查卖点重叠和当前完整外框是否越界；需要调整时先固定第一阶段贴纸结果，只移动卖点。
3. 只有卖点单独无解或贴纸局部无解时才进入全量联合求解，不接受“贴纸很远但卖点不动”的次优解，也避免多卖点手账进入不必要的大搜索树。
4. 联合目标依次为：零硬约束违反、最小最大实际位移、最小总位移、保持阅读与左右顺序、稳定 ID。
5. 结尾贴纸与新版卖点冲突时移动卖点。
6. 手动或旧版元素与自动元素冲突时只移动自动元素。

冲突图对所有可见帧的冲突取并集，每个元素全片只有一个解析中心。可见外框可以相对模板锚点偏移，但持久化锚点必须位于画布 0–100% 内，避免负百分比被 Resolution schema 整体拒绝。

候选只允许平移，使用有限网格、MRV 和前向检查。节点预算按元素与候选数确定性计算，不使用墙钟时间决定随机结果。

穷尽候选为 `infeasible`；预算耗尽为 `budget_exceeded`。两者分别报告，均不得返回未经验证的位置。

批量测量和写入避免布局抖动；缓存元素逐帧运动数据，播放或 seek 不重新求解。

## 8. 命令、并发与恢复

### 8.1 自动命令 CAS

所有 initial、自动候选、重提、哈希重建、模板或字体变化、版本派生、单条、批量和跨片 CLS 命令捕获：

- `scopeId`。
- `groupId` 或 `outputVersionId`。
- `expectedRevision`。
- `preInputHash`。
- `clientOperationId`。

提交时同时 CAS 当前修订和输入哈希。客户端再以 operation generation 淘汰旧响应。自动候选必须先获得有效 Resolution，再原子提交配置、Resolution 和 manifest ID。

### 8.2 两类 pending

`commandPending`：

- 用于一键布置、换一组、跨片复制、显式重提等自动候选命令。
- 锁当前 scope 的冲突编辑与导出。
- 显示处理中状态并允许取消。
- 失败零写入。

`revalidatePending`：

- 用于手动保存后的后台重解析。
- 不锁移动、删除、固定等恢复性手动编辑。
- 禁止完成态预览、自动候选和正式导出。
- 后续编辑递增修订并淘汰旧结果，只有匹配当前修订与输入哈希的 Resolution 可提交。

禁用包装取消当前 scope 两类 pending，使旧响应失效后立即保存开关；无包装允许预览和导出。重新开启按最新修订重新验证。

取消、失败或进程异常只释放 pending，不改变最后已提交配置。

### 8.3 手动保存与 stale

手动移动、删除和禁用包装始终先保存用户明确要求的固定坐标、删除或开关结果，不因剩余自动元素无解或预算耗尽而拒绝。

若剩余未固定自动元素的 Resolution 因此失效：

- 保存后标记 `stale/unresolved`。
- 后台重新解析。
- pending 或失败时禁止完成态预览和正式导出。
- 用户可继续移动、删除、固定或重试，不必撤销自己的手动修改。

自动哈希重建失败时，旧配置只用于恢复；旧卖点键与当前输入不匹配时必须显示 stale，导出前刷新失败直接终止，不得把旧卖点冒充当前结果。既有 output version 派生失败则保留旧版本。

## 9. 失败候选与重试

自动候选失败时保留内存 draft，拆分为：

- 不可变 `candidatePayload`：候选 ID、实例 ID、素材、基准中心、时间、动画、随机版本等。
- 生成时 `baseRevision/baseInputHash`。
- `draftCompatibilityHash`。

重试保留 candidatePayload，基于当前已提交配置重新计算 expectedRevision 和 preInputHash，并重新 CLS 预检，不要求换一组重抽。

compatibility 只包含会使候选本身失效的结构：

- scope 和 target IDs。
- 模板、输出尺寸、正文时长和素材目录版本。
- 跨片来源贴纸集合、来源时长和默认动画。
- 被替换自动组是否已被另一自动命令改变。

手动障碍移动或删除、手动卖点布局和普通修订变化不妨碍 rebase。目标文案或字体变化可由新 CLS 重评；候选素材或时间语义失效则按结构冲突。

结构不兼容时明确提示重新生成，不静默重抽。审核状态、自动编辑确认等现有门禁按当前修订重新检查。刷新或取消可丢弃未提交 draft。

## 10. 跨片复制事务

1. 预检前冻结来源 batchVersionId、outputVersionId、editRevision、完整贴纸哈希、正文时长哈希、stickerDefaults 和 inputHash。
2. 冻结所有目标对应 IDs、revisions 和完整目标 inputHash，包括模板、字体、文案、卖点、手动障碍、输出尺寸和时长。
3. 一次生成随机候选，每个目标的 Resolution 引用上述哈希及 manifest ID。
4. 在数据库事务外用 CLS 对每个目标执行 layout-only 预检，不渲染完整视频。
5. 全部成功后进入原有批次事务。
6. 事务内同时重验来源和全部目标；任何变化整批零写入。
7. manifest ID 和 Resolution 进入 after 快照、撤销重做和后续正式任务。

失败候选不持久化，不形成半批结果。

## 11. 失败与发布门禁

删除“最小重叠并继续导出”的降级。

`infeasible`、`budget_exceeded`、资源缺失、哈希异常、布局 ready 失败或未知版本时：

- 不提交自动候选。
- 不展示完成态预览。
- 不正式导出。
- 不自动缩小。
- 不移到下半部。
- 不修改固定元素。

错误使用中文指出成片、贴纸中文名或卖点文本、冲突帧区间和可执行恢复动作。`budget_exceeded` 不得误报为空间不足。

单条和批量都在任何封面或视频正式产物发布前完成布局验证，封面不得先发布形成半套交付。

## 12. 运行资源冻结

v2 及混合版本任务冻结：

- LayoutResolution。
- 模板及几何相关 HTML、CSS、fit 和视觉外扩资源。
- 实际字体和文字适配参数。
- 贴纸 PNG、Alpha 几何、宽高和 SHA-256。
- GSAP 与布局运行时。
- Chromium 精确版本、平台、架构和分发包哈希。
- 相关组件和全部资源 SHA-256。

worker 只能读取 manifest 和物化资源，不得执行时重读可能变化的目录。

已发布 bundle 所需引擎以内容寻址方式保留。应用升级新增 engine 或 bundle ID，不用新引擎重新 fit 旧 Resolution。引擎或组件不匹配、旧引擎缺失必须明确阻断，不静默升级。

v2 缺失字体、图片、runtime、ready 或哈希不匹配全部 fail closed；legacy/v1 保持本次改造前路径。

共享运行时进入预览、离线复制、打包负载和守护测试。

## 13. 测试与验收

### 13.1 领域测试

- 版本清洗、未知版本拒绝、版本升级时机。
- 基准中心、解析中心、位置固定和完整历史恢复。
- 开头、中段和卖点上 40%；结尾固定下半部 62%／72%。
- 点击素材新增保持居中。
- 跨片手动及已编辑位置不变，未编辑自动生成 v2。
- 固定—固定重叠不判无解，混合碰撞按潜在可移动集合处理。
- 候选 rebase 不重抽，结构冲突明确拒绝。
- 所有输入哈希、快照白名单和 manifest 穿透。

### 13.2 几何与搜索测试

- 四模板、三画幅、全部自动素材和六动效。
- 入场、稳定、退场和 easing 过冲的实际输出帧。
- 描边、伪元素、阴影、滤镜和装饰外扩。
- 时间重叠但空间不冲突不移动，空间相交但时间错开不移动。
- 小幅贴纸优先，再固定贴纸只解卖点，最后才全量联合求解；无过远次优解或多卖点性能退化。
- `infeasible` 与 `budget_exceeded` 分离。
- 相同输入重复计算一致，无循环或随机重排。

### 13.3 浏览器与并发测试

- 单条和批量的一键、换组、显式重提、模板和字体变化。
- 修改动画、修剪、换轨和风格后位置不跳变。
- 手动拖到下半部后保存、刷新和导出保持。
- commandPending 和 revalidatePending 的锁、取消和迟到响应。
- 手动保存 stale 后可继续恢复，禁用包装可取消 pending。
- 跨片预检期间来源或任一目标变化时整批零写入。
- 撤销重做、刷新和正式导出不重抽。

### 13.4 兼容与真实导出

- 全 v1 和四种混合版本逐帧金样。
- 旧冻结任务不静默升级引擎或布局版本。

## 14. 实施边界

本功能不新增数据库表或迁移，不增加日常设置项。实现应优先复用现有贴纸目录、规划器、编辑桥、HyperFrames 运行时、批量事务和渲染快照设施，但不得为降低改动量而省略版本、CAS、资源冻结或发布前验证。
