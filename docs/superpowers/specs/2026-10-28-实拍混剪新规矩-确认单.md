## 用户已确认（2026-10-28）

1. 「旧版」文件夹放在「成片」**旁边**，不放进「成片」里。这样拷走「成片」就是干净的一套。
2. 插入的补镜**最短 1 秒**，不会一闪而过。代价：配音只差 0.6 秒时，画面比声音多出约 0.4 秒，下一句稍等一下再开始。
3. 生成前，公式用到的素材必须都已「分析画面」。还有没分析的，生成入口提示先去分析，并写明还差几段；不会偷偷退回「固定掐头去尾」。
4. 验收方式（见「测试决定」）：规矩集中在一个单独的「排片计算」里验。给它一条脚本、素材清单和 AI 的判断，检查排出来的成片对不对；AI、配音、渲染不在这个计算里跑。最后用真实素材新建一个批次出片、导出，你来看片。

## 问题

10-26 用 ps889 的真实素材测了一整天：1 个任务、6 个批次，5 次生成、每次 300 条，正式导出 0 条。

- **声音环节卡住。** 现在的做法是让 AI 把整段文案切开，和口播镜头逐字核对，对不上就停下来等人。可是 300 条脚本里有 209 条的文案根本没写口播台词；演员也不会逐字背词，57 段识别出来的原声只有 7 段和台词一字不差。批次 6 进入声音环节的 170 条里，55 条通过，80 条等人工，35 条失败。
- **缺素材卡住。** 公式里有 29 个编号没有素材，130 条卡在选片，等人一个个指定替代。
- **设置和窗口太多。** 时长规则三选一、目标秒数、计时范围、原声前后保留毫秒；人工核对原声、声音逐段用途核对、缺片逐个指定。用的人说不清哪个该点、点了有什么用。
- **背后也乱。** 两个早就不跑的批次还标着「运行中」；10-26 的改动没提交；参考文档写的还是旧规矩；模块约 4.2 万行，一半从批量生产复制来，很多用不上。

## 方案

照手工剪辑的做法把规矩定死。程序按规矩一口气排完 300 条，不停下来等人。AI 只在几处做判断：素材哪一段能用、哪行文案和哪段口播意思相近、挑补镜和替代镜头、挑口播。AI 拿不准也自己定。人只在审片时看 AI 动过手的地方，不对就一键恢复。

规矩的一句话版：

- 画面跟公式走，声音跟文案走。
- 公式里的口播按文案用：文案里写了它的台词、或 AI 判断意思相近的，放原片，那一行不配音；其余口播不用；一段都没用上，AI 挑最搭的一段。
- 其余文案一行配一个非口播镜头，用配音读；文案最后一行永远在片尾。
- 时长以读完为准。配音比镜头长不到半秒，这个镜头多用一点原片；超过半秒，插一个相关的补镜。任何地方都不静帧。
- 缺素材用替代镜头顶上，不等人。
- 一个任务只有一个「成片」文件夹；同一条再导出出 `-v2`，旧版挪进「旧版」。
- 去掉用不上的设置和窗口。

原型用 300 条真实脚本、两种声音方式各跑了一遍：0 行漏读、0 处静帧、0 处声音重叠，需要配音的最后一行都在片尾。估算的成片时长中位数：淘宝、抖音约 18 秒，小红书约 32 秒，详情页约 29 秒。

## 实现决定

### 1. 排片：一个新的深模块

- 新建一个「排片」模块，把「一条脚本怎么排成一条成片」的规矩全部集中在这里。它是纯计算：不读数据库、不调 AI、不调配音、不碰文件；需要的东西都由调用方作为输入给它。
- 它取代两样旧东西：AI 切分整段文案的声音映射（连同它「等原声」「待人工」的状态），以及时间轴里按目标时长挑区间、按时长规则排片的逻辑。执行检查、渲染、封面、包装照旧，从它的结果往下走。
- 同一套规矩分两次调用：
  - **定声音**（配音前）：决定哪些口播放原片、哪些文案行被原声覆盖（被哪段口播、逐字还是相近）、哪些行要配音、每行配在哪个画面上（含最后一行挪到片尾）、缺号用什么替代。配音步骤只为要配音的行合成。
  - **排时间**（配音后）：用实际配音时长和有效片段，算出每个镜头取哪一截、哪里多用一点原片、哪里插补镜、结尾镜头和收尾，生成画面轨、声音轨、字幕和审片标记。
- 输入：
  - 一条脚本：文案（按行）、编号公式、原脚本号和份次。预估时长只做显示，不参与计算。
  - 素材清单：每个素材编号对应的文件（可以多份）、类别（编号去掉数字后的部分，如 S、P、VO）、是不是口播镜头、口播台词（来自文件名）、是不是全景展示或全景体验（来自文件名）、有效片段；口播镜头还带原声（清洗后的文字、逐字时间、说话起止）。
  - AI 判断（见第 3 节）和替换表（有的话）。
  - 声音方式；审片时恢复了的行。
  - 第二次调用再加：每行配音的实际时长和逐字时间。
- 输出：画面轨（每段画面用哪个文件、从第几秒到第几秒、属于公式镜头/口播/替代镜头/补镜/结尾镜头哪一种）、声音轨（原声和配音的先后）、字幕、审片标记、公式里没用上的镜头和原因。
- 模块放在实拍混剪模块里，只用 `media-core` 的共享能力，不从批量生产和成片剪辑导入；开关关着时不建表、不跑后台（守住现有红线）。

**规矩**（照搬原型，已用 300 条真实脚本验过）：

a. **公式里的口播按文案用**（「原声＋配音」）
   - 文案某行逐字包含某段口播的口播台词（比之前去掉标点、空格和表情）：这一行由那段口播说，不配音。按公式顺序往后找，每段口播最多顶一行。
   - AI 判断某行和某段口播意思相近：同样不配音，标成「AI 判断相近」。
   - 这两种用到的口播都放原片；公式里其余口播不用。
   - 一段都没用上：AI 挑和整段文案最搭的一段放原片，文案照常全部配音。
   - 缺素材的口播不算口播，按缺号处理（见 e）。
b. **统一配音**：全部文案配音。公式里的口播只留 AI 挑的一段，静音，当一个非口播镜头用，同样配一行文案；其余口播不用。
c. **一行一个镜头**：按公式顺序，以「放原片的口播」为界把画面分成几段。每段该读的文案，是上一段口播顶掉的那行之后、这段口播顶掉的那行之前的行，依次一行配一个非口播镜头。
   - 文案比镜头多：多出的行接在这一段最后一个镜头上；如果是最后一段（后面没有口播了），多出的行放到片尾。
   - 镜头比文案多：多出的镜头不用。
   - 这一段没有非口播镜头、却有要读的行：中间段配补镜；最后一段放到片尾。
d. **最后一行在片尾**：文案最后一行要配音、而它后面还有放原片的口播时，把它挪到片尾读。
e. **缺号**
   - 有替换表就按表。
   - 缺非口播镜头：从同一类素材里，按这一镜要读的文案挑替代镜头（用 AI 给的相关排序，本条没用过的优先），放在原位。同一类里没有可用的，再依次从全景展示、全景体验、其余非口播素材里挑。
   - 缺口播镜头：当一个普通镜头位置，配一行文案；替代镜头先从全景展示挑，再从全景体验挑。
   - 缺的位置排到时文案已经读完（这个位置用不上）：不替代。
f. **同号轮换**：一个编号有多份文件时，用第 `(原脚本号 + 份次) mod 文件数` 份（从 0 数）。
g. **时间**
   - 放原片的口播：取原声说话起止那一段，整段放完。说话起止前后各留一点固定余量（沿用现在的 0.12 秒，不做成设置），余量不能伸进被剪掉的倒数和口令。
   - 非口播镜头：从有效片段开头取，长度等于它要读的行的配音总长。有效片段不够时：差 0.5 秒以内、且原片后面还有，就多用这一点原片；差超过 0.5 秒，镜头放满有效片段，然后在它后面插补镜，直到读完。
   - 补镜：从 AI 给的这行文案的相关素材排序里，取本条没用过的第一个；都用过了，就从排序第一个起重复用。时长取还差的部分，但不少于 1 秒、不超过它的有效片段；还不够就再插下一个。
   - 片尾的文案配在结尾镜头上：先用公式里没用上的非口播镜头（从公式靠后的开始），再全景展示，再全景体验。全景里按原脚本号和份次轮流挑，本条没用过的优先；全都用过了允许重复。
   - 声音一句接一句，不重叠；画面比声音长时，下一句等画面放完再开始。
   - 最后一句声音之后，最后一个画面多放 0.75 秒收尾。
h. **每条成片都要满足**（测试逐条检查）
   - 文案每一行要么被原声覆盖，要么配音读一次；不漏，不重。
   - 每段画面都在素材文件的范围内；没有静帧、倒放或变速。
   - 原声和配音不重叠。
   - 公式镜头严格按公式顺序（用不上的跳过）；补镜只插在镜头后面或片尾。
   - 需要配音的文案最后一行，是成片最后一句声音。

常量（原型定的）：收尾 0.75 秒；多用原片的上限 0.5 秒；补镜最短 1 秒。

下面两段摘自原型（略有简化），比文字说得准：

```js
// 公式里的口播按文案用
const talking = slots.filter(s => s.vo && !s.missing);
let keep = mode === 'mixed'
  ? talking.filter(s => s.anchor != null || similarCodes.has(s.code)) // 逐字写着的 + AI 判断相近的
  : [];
if (!keep.length && talking.length) keep = [aiBest(talking)];          // 一段都没用上，或统一配音：AI 挑一段
for (const s of talking) if (!keep.includes(s)) s.unused = true;       // 其余口播不用

// 以放原片的口播为界，一段一段地「一行一个镜头」
function place(stretch, lines, isLastStretch) {
  const pics = stretch.filter(x => x.kind === 'pic');
  if (!pics.length) return isLastStretch ? toEnding(lines) : addFillerStretch(stretch, lines);
  pics.forEach((p, k) => (k < lines.length ? p.lines.push(lines[k]) : (p.dropped = true)));
  const extra = lines.slice(pics.length);
  if (extra.length) isLastStretch ? toEnding(extra) : pics.at(-1).lines.push(...extra);
}
```

### 2. 素材准备：每段素材只做一次

- 导入时直接按文件名读：素材编号、口播台词、全景展示（文件名同时含「整体外观」和「无人出镜」，ps889 是 S1～S10、S12）、全景体验（P 镜头且文件名含「全景」）。去掉「根据文件名整理」按钮和它的后台。
- 「分析画面」：用户选视觉模型、点开始。AI 为每段非口播素材判断有效片段，并留下简短的画面描述，供第 3 节挑补镜和替代镜头用。结果按素材内容指纹存在任务下，换批次不重复分析。
- 口播镜头的有效片段不看画面，按原声说话起止。
- 原声：每段口播镜头用火山识别一次，跨批次复用（现有能力）。识别后清洗：
  - 按标点把识别文字切成小句。开头最多去掉 3 小句倒数或口令。倒数是「三二一」「321」「一二三」「123」「二一」「21」，后面可以跟「开始」「走」「开」「来」；倒数和台词连成一句时，只去掉倒数那几个字。
  - 结尾最多去掉 2 小句口令，如「OK」「来」「看」「好」「好的」「可以」「行」「停」，以及只有一个字的小句。
  - 口播台词本身以这些字开头或结尾时，不去。
  - 清洗后的文字、逐字时间、说话起止存下来。
- 生成前检查：本批公式用到的素材里还有没分析画面的，生成入口提示先去分析，并写明还差几段。原声识别不用用户点，随生成自动跑。

### 3. AI 判断：每条成片一次，存下来，不停下来等人

- 每条成片在定声音之前调用一次文本模型（沿用生成时选的模型），一次给出三样：
  1. 文案哪一行和公式里哪段口播意思相近。对照的是这段口播原声实际说的话，台词一起给作参考。
  2. 口播一段都没用上时（以及「统一配音」时），最搭的是哪一段。
  3. 每行文案相关的非口播素材排序（依据文件名和分析画面留下的描述）。补镜和缺非口播镜头时的替代镜头都从这里按规矩挑。
- 结果按内容存：同样的文案和同样的素材直接复用，不重复问。排片模块只读这份结果，自己不调 AI。
- AI 回了就照用，没有「拿不准就等人」的出口。答案里对不上号的条目丢掉不用；整份答案格式不对，重试后仍不对，或者调用本身报错，这条成片才失败，写明原因、可重试，同批其他成片照常。

### 4. 生产流程

- 每条成片的步骤改成：选片 → 识别原声（口播，复用）→ AI 判断 → 定声音 → 配音 → 排时间 → 执行检查 → 封面 → 审片 → 导出。
- 选片不再因为缺号停下：缺号记下来，交给定声音时替代；同号按轮换规则取文件。
- 配音只合成要配音的行，每行一段，便于恢复某一行时只补这一行；同样的文字、同样的声音直接复用（现有能力）。
- 去掉「等原声」「待人工」这类停下等人的状态。每一步的结果只有两种：做好了，或者失败（带原因、可重试）。
- 声音方式只剩「原声＋配音」「统一配音」，默认「原声＋配音」。
- 去掉时长设置（时长规则、目标秒数、计时范围、原声边距）。
- 旧批次不迁移、不重排。10-26 的 6 个批次照原样留着能看；新规矩只用于新建的批次。排片结果标新的算法版本，旧结果按旧版本读，旧批次存着的「只用原声」等旧设置照常能读出来。
- 数据库只追加迁移（模块自己的迁移流）。去掉的功能只删入口和代码，旧数据表先不删，旧批次还要能看。

### 5. 审片

- 沿用现有的统一审片工作台，不重做。
- 排片结果自带审片标记，工作台显示三类：
  - **省掉的文案行**：哪一行、被哪段口播说了、是「文案逐字写着」还是「AI 判断相近」。
  - **替代镜头**：顶替了哪个缺号、从哪里挑的（同一类、全景展示、全景体验或替换表）。
  - **补镜**：因为哪一行配音比镜头长，或者是片尾的结尾镜头。
- 成片列表能筛出「有标记的」；全选通过沿用现有的。
- 「恢复这一行」只出现在「AI 判断相近」省掉的行上。恢复后，这条成片把这一行当普通文案，按同一套规矩重新定声音：那段口播如果不再顶任何一行，就按「一段都没用上」处理。然后只给这一行合成配音，重新排时间、重新渲染，成为这条成片的新版本，回到待审。只影响这一条。
- 「文案逐字写着」的行不提供恢复，因为那段口播本来就在说这句。

### 6. 导出

- 位置不变，仍在任务的导出目录下。
- 一个任务只有一个「成片」文件夹，不再按批次分子文件夹。
- 「同一条」指同一个原脚本号、同一份次，用现有冻结的导出身份算出的文件名来认，不管来自哪个批次。
- 第一次导出不带后缀；同一条再导出，新的叫 `-v2`、`-v3`，上一版的视频和封面挪进「旧版」。这取代现在 `-02`、`-03` 在同一个文件夹里并存的做法。
- 「旧版」在「成片」旁边。
- `清单.csv` 在「成片」里，只列当前这一套。
- 10-26 没有正式导出过，不需要搬旧文件。

原型里的版本规则：

const versionName = (key, v) => (v > 1 ? `${key}-v${v}` : key);
