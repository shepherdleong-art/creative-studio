# 创作画布 PRD：个人内测 v1.0

日期：2026-09-09；更新：2026-09-10（必需模型与开发隔离边界）。状态：产品选择已确认，本文为整理后的文档评审稿；正式功能尚未完成开发与验收。

创作画布用于在公司内网中同时推进多组图片、视频创作。例如，用户正在修改一张沙发的场景图，同时用另一张沙发图生成视频。两组任务分别运行，用户可以继续修改其他节点、复制满意的结果、切换画布，并在完成后下载素材。

本文替代早期评估和交接中与当前选择冲突的产品口径，尤其是“节点历史版本”“以整图执行为主”和“复杂多参后置”。接口研究与历史成功案例继续作为技术依据，不能把本文的需求写成已经实现的功能。

## 1. 目标与验收场景

首版面向用户本人，在独立的内测环境中使用。当前开发环境已独立配置端口、代理、数据根和桌面身份；这不预先决定最终作为工作台功能还是拆成独立产品。每个创作主题建立一张画布，同一画布可以包含多组素材和多条生成分支。画布不要求创建旧工作台的项目或分镜组。

核心验收场景：

1. 创建“沙发场景探索”画布，拖入两张不同的沙发图片。
2. 图片一连接图片生成节点，填写场景修改要求并点击生成。
3. 图片二连接视频生成节点，填写动作或运镜要求并点击生成。图片任务仍在运行时，视频任务可以独立开始。
4. 两个任务运行期间，继续编辑提示词、移动节点、添加参考素材；修改不影响已经启动的任务。
5. 对满意的节点执行复制粘贴，副本保留当前结果与完整生成设置。原节点继续生成，新结果成功后覆盖原节点当前结果，副本保持不变。
6. 切换到另一个主题画布继续工作，之前的任务继续推进；通过全局任务入口查看状态，完成提示可跳回对应节点。
7. 单独下载结果，或框选多个结果节点，一次下载 ZIP 包。刷新后，画布、当前结果、连线和已保存的编辑仍在。

验收判断以可操作的完整过程为准：图片与视频能并行、编辑不中断、结果不串节点、不重复提交同一次任务、保存与恢复可靠。模型生成的主观美感不作为软件正确性的唯一标准。

## 2. 已确认的产品选择

| 编号 | 选择 | 首版要求 |
| --- | --- | --- |
| Q1 | 多个任务异步生成、互不打扰 | 独立图片和视频任务可以并行；单支失败不阻塞其他独立分支，画布始终可编辑。 |
| Q2 | 下游用上游当前结果；不要节点历史版本 | 节点只显示当前结果，新结果成功后覆盖；用户通过复制节点保留满意的方案。 |
| Q3 | 上游运行中可等待，否则提示 | 单独启动下游时，上游没有结果但有进行中的任务，可等待该次结果；没有可等待任务则提示先生成上游。 |
| Q4 | 不接旧工作台素材 | 首版通过本地上传、文件拖入和画布内生成获得素材；不提供旧项目素材浏览或双向同步。 |
| Q5 | 复制整个生成节点 | 副本包含当前结果、模型、模式、提示词、参数和输入参考，可独立继续生成。 |
| Q6 | 默认 10 个任务 | 所有创作画布的图片、视频任务共享默认 10 个并行名额；超过名额时排队。 |
| Q7 | 按创作主题分画布 | 允许在多张主题画布之间切换；切换不停止已经启动的任务。 |
| Q8 | 首版按 50 个节点验收 | 用单张画布 50 个节点、全局 10 个任务并行验证流畅性；50 是验收样本，不是节点硬上限。 |
| Q9 | 单个下载和选中结果打包下载 | ZIP 只包含显式选中节点的当前可用结果，不递归收集上游参考或过去的生成结果。 |
| Q10 | 全局任务入口与完成轻提示 | 集中查看跨画布的等待、排队、进行中与失败任务；完成时轻提示，可定位对应节点。 |

沿用此前已确认的方向：中文界面、Apple 极简风格、浅色／深色／跟随系统；默认各节点手动生成，可一键运行所选分支；模型、提示词和主要参数集中在生成节点内；多参考素材属于首版核心范围。

以下章节把上述选择展开为可验收的默认细则。未在访谈中逐字讨论的复制连线、导出失败和恢复边界等细节属于本文的实现评审内容。

## 4. 页面与节点

### 4.1 画布列表与编辑器

画布列表按创作主题组织入口，显示名称和最近修改时间。新建画布直接进入编辑器，不要求填写产品项目、分镜或其他旧工作台信息。

编辑器以画布为主体，提供名称、保存状态、返回列表、添加节点、视图控制和全局任务入口。详细参考信息和任务列表可展开查看，不遮挡持续编辑所需的主要操作。主要生成操作、模型、提示词和常用参数可直接在节点中完成。

UI 使用现有主题令牌和三态主题偏好。错误、等待和完成状态须有文字，不能只用颜色表达。

### 4.2 节点与输入

| 节点 | 用户可做什么 | 输出 |
| --- | --- | --- |
| 素材节点 | 上传或拖入本地图片、视频、音频；命名、预览、连接到兼容的生成节点。 | 已保存的本地媒体引用。 |
| 提示词节点 | 编写可复用文本，连接到一个或多个生成节点。 | 文本；不调用模型。 |
| 图片生成节点 | 选择图片模型、生成模式、比例／清晰度等参数；填写提示词、组织参考素材、手动生成。 | 一张当前图片。 |
| 视频生成节点 | 选择视频模型、生成模式、比例／分辨率、时长及模型支持的声音选项；组织输入并手动生成。 | 一个当前视频。 |

生成节点可以直接填写提示词，不强制额外创建提示词节点。连接文本的组合顺序应稳定且可查看；启动任务时保存真正提交的完整文本。

文生模式不能通过上传空白占位图片实现。参数只展示当前精确模型和模式可用的选项；参考音频与“生成视频声音”是两个独立概念。

导入素材后由内测环境保存可持续使用的本地副本。源文件后来被移动，不应让已经成功导入的素材失效。文件类型、格式及模型限制需在提交前校验；导入失败要指出具体文件和原因。

### 4.3 连接与编辑

- 默认连线、改提示词、换模型、移动节点都不触发生成。
- 从输出端拉线到空白处松手，弹出与右键添加一致的兼容节点菜单；选择后在落点创建并连接。Esc 取消，创建与连接合为一次撤销。
- 点击连线或参考缩略图上的 ×，或选中连线后删除，只解除引用。已有节点和当前结果保留。
- 拒绝循环和明确不兼容的端口连接。切换模型造成已有输入不兼容时，保留素材并显示问题，等待用户调整。
- 支持 Cmd／Ctrl+C、V、D 复制粘贴或复制节点，Delete 删除，Cmd／Ctrl+Z 撤销及重做。焦点在文本框时优先保留正常文字编辑行为。
- 撤销重做作用于画布编辑，不撤销已经提交的模型任务或自动启动新的任务。删除运行中的节点不删除任务身份，也不把迟到结果写入其他节点。

## 5. 当前结果、覆盖与复制

### 5.1 每个生成节点只有一个当前结果

节点首次生成前显示空状态；生成期间显示任务状态。已有结果的节点再次生成时，旧结果继续可见、可预览、可复制和下载。

新结果完成下载、必要校验及本地保存后，才替换该节点当前结果。生成失败或下载失败不清空旧结果。界面不提供历史版本列表、版本编号选择器或“恢复上一版”入口；需要保留某次结果时，由用户复制节点。

运行中编辑模型、提示词或参数，修改保留为下一次生成的草稿。当前任务继续使用启动时的设置，完成回写只更新本次结果和状态，不覆盖用户后来编辑的文本或参数。若当前草稿与产出该结果的设置不同，应有简短提示，避免误认为当前画面由尚未提交的新提示词生成。

### 5.2 完整节点复制

复制发生时，副本保留当时可见的当前结果、当前编辑设置、提示词和输入参考，获得独立节点身份。原节点之后重新生成、改名或删除，不改变副本已经保留的结果。

复制规则：

- 不复制或再次提交原节点正在进行的任务；副本处于可手动生成状态。原任务后来返回的结果只更新原节点。
- 单节点复制保留其输入引用；不把副本自动连接到原节点的既有下游。
- 多选复制时，所选节点之间的连线映射到对应副本；来自选择范围外的输入继续引用原来源，不向选择范围外新增输出连线。
- 输入连接仍遵守“下一次生成使用来源当前结果”的规则。副本的已保存画面不会因为输入来源变化而自动更新。
- 素材文件可以复用不可变内容；原节点结果覆盖不得直接改写副本或进行中任务仍在使用的同一份文件。

首版必需验收同一画布内的复制粘贴；跨画布复制不列入本次交付必需项。保留必要任务记录用于恢复和消耗核对，不等于提供用户可浏览的历史结果库；文件清理必须保护副本、当前结果、进行中任务及导出仍引用的素材。

## 6. 多参考素材与下游输入

### 6.1 多参考表达

图片生成支持多图输入；视频按模型接收图片、视频、音频。每份参考在节点内显示可识别的缩略图或媒体标识、用途、顺序和可选说明，并允许排序、断开及通过 @参考N 提及。

引用在节点内具有稳定身份。排序可以改变提交顺序，但不能把原提示词中的 @参考N 悄悄指向另一份参考。断开被提及的参考时，标记为失效引用并阻止无效提交；重新编号不能掩盖缺失输入。

“产品、主体、角色、风格、运镜”等用途用于表达创作意图。具体通过专用参数还是提示词传递，由模型适配决定，不能声称每个平台都原生理解这些标签。

首帧、首尾帧和多模态参考按精确模型区分；模型规定互斥时不能混用。切换模式保留原素材和文本，明确指出数量、类型、用途或参数冲突，不静默丢弃素材。

### 6.2 单独启动下游节点

设图片节点 A 连接到视频节点 B，用户单独点击 B 的“生成”：

| A 的状态 | B 的行为 |
| --- | --- |
| 已有可用当前结果 | 使用点击生成时 A 的当前结果，并在 B 中显示这张输入。 |
| 已有当前结果，同时正在重做 | 仍使用当时可见的当前结果；不自动改为等待尚未完成的新图。 |
| 没有结果，但有已启动的任务，包括正在排队 | B 等待该次任务的结果；同时固定 B 的提示词、模型、参数和其他已就绪输入。 |
| 没有结果，也没有可等待的任务 | 提示先生成 A；不自动补跑上游，也不提交 B 的模型请求。 |
| 等待的 A 任务失败或被停止 | B 显示上游未完成及原因，停止推进；不会自动改等 A 后来新建的另一项任务。 |
| B 已接受运行后，A 更新结果或连线被修改 | B 继续使用启动时固定的素材，或已绑定的那次上游任务；草稿变化只影响以后新启动的任务。 |

多个输入同时存在时，全部必需输入可用后才允许提交。上游“供应商已完成、文件尚未下载保存”仍不算输入可用。

## 7. 执行、并发与分支

### 7.1 默认手动运行

一个生成节点同时只允许一个活跃任务，包括等待输入、排队、提交、生成和下载阶段。提交结果待核查、或本地请求停止但远端尚未确认结束时，也不能假定该任务已经结束。重复点击不能生成重复请求。需要同时试另一组参数时复制节点，再分别启动。

用户点击生成即固定本次输入、模型、模式、提示词和参数。等待并发名额期间也不能重新读取后来修改的草稿代替已启动任务的设置。

### 7.2 所有画布共享默认 10 个并行名额

图片与视频共用画布模块的全局上限，默认 10。跨画布切换不能增加或重置名额；具体供应商或模型可用名额更低时，仍遵守其限制。这里是当前本地内测实例的上限，不代表公司所有用户的账号配额。

等待上游输入的任务不占生成名额，避免下游占满名额后上游无法启动。已进入准备提交、远端排队／生成、下载保存的任务计入并行工作；确认远端已经结束且需要用户处理的失败任务释放名额。已提交但结果不明的任务保守保留可能占用的名额，核查后再释放；停止本地等待不等于释放远端名额。重启时，仍在远端进行的已有任务也必须计入，不能通过重启再额外提交 10 个。

队列优先推进较早进入且输入与供应商名额均就绪的任务。某个任务缺输入或某一模型无名额，不阻止其他符合条件的独立任务继续。首版不增加手工优先级编排功能。

### 7.3 一键运行所选分支

从一个选中起点运行其可达的下游分支，启动前展示起点、将运行的节点、复用项以及新增生成任务数。起点已有结果时默认复用当前结果，也可以选择重新生成起点。素材节点本身不产生生成任务。

分支规则：

1. 范围内需要执行的生成节点各生成一次；除显式复用起点外，不因某节点以前成功就自动跳过。不存在自动跨运行缓存。
2. 范围内依赖绑定本次分支对应的上游任务；即使上游节点已有旧结果，也等待本次计划要求的新结果。
3. 范围外输入必须有可用当前结果，并在启动时固定；缺失时提示补齐，不静默扩大分支范围或新增上游任务。
4. 启动前校验整份计划。循环、不兼容输入、缺失参考或范围内节点已有活跃任务时，不部分提交后再补报前置错误。
5. 提交前可以继续编辑；正式启动时重新校验当前计划与展示的范围，范围改变时更新预览，不按过期的任务数量偷偷提交。
6. 独立节点并行，有依赖的节点等待。某节点失败只阻塞依赖它的后代，其他独立部分继续；分支可以部分完成。
7. 运行中编辑、添加连线或节点，不改变这次已经确定的分支计划。

如果能可靠估算消耗，运行前可以同时显示估算；无法取得时明确显示未知，不虚构金额或以下载次数重复计算生成消耗。

## 8. 全局任务入口、保存与恢复

### 8.1 任务状态与反馈

全局任务入口在画布列表与编辑器中均可进入。每项任务显示画布名称、节点名称、媒体类型和实际状态；点击可打开对应画布并定位节点。节点已经被删除时说明该事实，不自动重建节点。

| 状态文案 | 含义与可操作反馈 |
| --- | --- |
| 等待上游 | 显示正在等待哪个节点的哪次已启动任务；可停止本次等待。 |
| 排队中 | 等待全局或模型名额；可停止尚未提交的任务。 |
| 准备／提交中 | 校验并交付素材、创建模型任务。 |
| 生成中 | 供应商已接受，正在排队或生成；能区分时显示真实阶段。 |
| 下载保存中 | 远端结果已生成，本地文件尚未完全可用。 |
| 已完成 | 当前结果已保存，可预览与下载。 |
| 失败／上游未完成 | 展示具体原因与对应处理入口；保留原有当前结果。 |
| 待核查 | 提交结果不明，尚不能确定远端是否已创建任务；不伪装成安全重试。 |

没有真实百分比时只显示阶段，不使用计时动画伪造进度。完成时给应用内轻提示，不抢焦点、自动切页或打断输入；失败在任务入口中明确可见。首版不要求系统通知权限、声音提醒或常驻历史任务档案。

### 8.2 自动保存

节点内容、位置、连线和视口自动保存，界面显示保存中／已保存／保存失败。失败不能错误标为已保存；刷新和重新打开须恢复最后成功保存的状态及当前结果。后台任务状态更新不能覆盖用户正在编辑的草稿。

切换画布、返回列表、刷新或关闭浏览器页面，在本地应用服务仍运行时不停止后端任务。整个应用关闭或电脑休眠期间不承诺本地任务仍持续推进。

### 8.3 恢复与停止

- 应用重启后，已有远端任务身份的任务继续查询或补下载，不重新提交相同生成请求。
- 提交已经发出但结果不明的任务进入待核查；没有可靠幂等或核查依据时，禁止自动重发。
- 应用退出后，尚未提交的付费任务等待用户继续；继续原任务使用原设置，使用新草稿应启动新任务。
- 下载失败提供补下载原产物的路径，不能通过再次生成解决下载问题。
- 停止等待或未提交任务后，不再为其新增请求；被它阻塞的后代停止推进，其他独立任务照常运行。
- 已交给供应商的任务按真实取消能力处理；不支持取消时说明远端仍可能继续，并保留身份收尾。不能把关闭页面、删除节点或中止本地等待显示为远端已取消。
- 真正失败后的“重新生成”是新的任务；用户需要明确触发，不自动循环重试生成。

## 9. 预览与下载

图片可放大查看，视频可播放并按需加载；上传的参考音频可预听。结果预览和下载基于本地已保存产物，不依赖短期有效的供应商链接。

单个下载返回该节点当前结果文件，保留已有交付链路的实际格式与画质，不以缩略图替代成品，也不为下载重复调用模型。

框选打包规则：

1. 点击打包时固定显式选中节点及其当前结果。打包期间节点产出新结果，不改变已经开始的这一份导出内容。
2. 每个有可用结果的选中节点导出一份文件；名称可对应回节点，重名时区分，扩展名与实际媒体类型一致。
3. 不包含未选中的上游参考、过去结果、模型密钥或签名 URL。文本节点、空结果节点说明为不可导出；全部无可用结果时不生成空 ZIP。
4. 节点正在重新生成但仍有旧结果时，可导出其当前可见结果；下载不等待也不触发新生成。
5. 选中的可用结果在读取时发生文件缺失或读取失败，要指出具体项，不能静默少文件后报告全部成功。补救导出不能重新生成素材。

## 10. 公司模型与接入边界

首版必须纳入公司七牛可灵 3.0（`qiniuyun/kling-3.0`）与公司 Seedance 2.5（`doubao-seedance-2-5-260628`）。七牛与腾讯可灵按不同渠道身份维护能力；七牛尾帧使用 `end_image_url`，支持单提示词智能分镜，首尾图必须走 COS。Seedance 2.5 默认 1080p，双图按参考图模式处理，不承诺像素级首尾帧锚定。详细合同与已验证边界以公司网关参考及 2026-09-10 七牛验证记录为准。现有成片记录不代表画布运行验收已完成。

沿用已有成功案例的工作台 → 本机 LiteLLM → 公司网关 → 平台链路。本地参考素材需要公网 URL 时通过腾讯云 COS 交付；已有适配器验证过的特定内联通道继续按原合同使用。画布与旧工作台的数据独立，但不另建一套凭据交互或绕开公司路由。

已记录的公司 Image2、可灵 3.0、Seedance 2.0／Fast 及七牛图片案例，证明既有参数链路已经使用过。Omni／O1 等多参考能力、新的纯文本模式和新增输出组合，需按精确模型与公司路由验证后开放。

| 核对项 | 已有依据 | 上线要求 |
| --- | --- | --- |

多参考验收至少覆盖：一种图片模型的两图及以上输入，以及视频模型可支持的多图参考、图片加参考视频、图片或视频加参考音频。不同输入类型可以由不同已验证模型覆盖；每一类都需有可用样例，不能仅以首帧／首尾帧成功替代视频多参考验收。若某类没有可用公司模型或转发支持，明确列为该项未完成并回到范围评审。

## 11. 持久化与内测隔离约束

画布定义、一次分支运行、节点任务、当前媒体分别保存；任务具有稳定身份，记录实际输入、参数、远端任务 ID 及必要消耗信息。删除连线或覆盖当前结果不得破坏进行中任务与副本的素材引用。

正式实现复用现有供应商、COS、下载、图片规整和账本基础，新增画布自己的调度与持久化边界。旧任务绑定项目和分镜，不能伪造旧项目记录承载自由画布。

个人内测使用独立 worktree 与数据根，旧工作台数据库、素材和运行进程不被接管。所有本地路径遵守 dataRoot()；迁移沿用仓库的追加式迁移、备份和升级约束。前端不回显密钥，图文件与日志不保存完整签名地址。

本机应用和 LiteLLM 只绑定回环地址。首轮以内网下的本机 Web 形态验收，不包含公网部署、安装包发布或与同事分支合并；环境准备和真实样本执行另有具体实施记录。

| A17 | 提交发出但响应丢失 | 显示待核查，不自动重发；不能错误提示“安全重试”。 |

| A22 | 内测与旧工作台隔离、浅深色主题 | 旧工作台数据和功能不受影响；各主题下操作与状态清楚可读。 |

性能验收采用缩略图和按需媒体加载，避免视口外视频持续解码，默认只保留一个正在播放的预览。50 节点是用户接受的测试规模，不宣称已测通过或无上限性能。

验收记录分别标注：本地逻辑／假上游自动验证、真实浏览器操作、真实公司模型样本、用户体验确认，以及失败与未跑项。真实模型验证需先明确素材、模型、次数与额度，文档整理本身不代表已经执行这些调用。
