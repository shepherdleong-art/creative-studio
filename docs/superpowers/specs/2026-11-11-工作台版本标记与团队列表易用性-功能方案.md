# 工作台版本标记与团队列表易用性

**状态：** `ready-for-agent`

**日期：** 2026-11-11（UTC+8）  
**用途：** 用户已要求整理 spec 和 tickets，交给 DeepSeek 实现，完成后由 Codex 审查。本次文档交付不包含功能代码、打包或部署。  
**执行入口：** [任务索引](../plans/2026-11-11-工作台版本标记与团队列表易用性/README.md)。产品行为以本文为准；修改范围和逐票验收见各 ticket。

## 1. 目标与范围

解决五件事：分镜图版本不醒目；待核对信息难懂；分流设置名称不清楚；团队用量详情挤压表格、长列表和图表位置不合理；全员任务过长。

- 分镜版本标记作用于共用分镜工作台，覆盖个人版和团队版。
- 其余改动作用于团队版；全员任务与我的任务、团队用量与我的用量共用的界面同时验收。
- **任务和用量明细直接做服务端分页，覆盖全部可见历史。** 不采用先取最近 500 条再在浏览器切页的方案。
- 保留现有生成、重试、选图持久化、计价、核对写入、权限与调度规则。本次不调整默认分流秒数，不改现有配置值，不扩大阈值的模型适用范围。
- 不改创作画布、场景图和视频工作台的版本交互；不扩展为全产品版本管理。

## 2. 已核实的实现约束

| 现状 | 本次必须处理的关联 |
| --- | --- |
| `ShotSetStep` 的绿点表达生成状态，版本箭头 PATCH `selectedImageAssetId` | 版本标记与成功状态分开；箭头切换是实际选用，不是临时预览 |
| `listTeamTasks` 按执行记录取最近 500 条，前端再按统一任务分组 | 先按制作任务选页，再加载该页完整执行记录；不能先分页执行记录再拼组 |
| 任务页搜索在前端，选中详情从当前 `items` 查找 | 搜索移至服务端；详情按编号独立读取，不依赖当前页 |
| 侧栏、总览、员工首页、详情接口也消费任务查询 | 分页改造必须检查这些调用者，数量不能缩成一页，旧任务链接必须有效 |
| `unified-usage.ts` 的任务查询也有 `LIMIT 500` | 制作任务计数、历史查询、下钻和图表不得继承这个截断 |
| `queryTeamUnifiedUsage` 用已返回任务 ID 集合判断未映射记录 | 改用真实父任务关联及权限校验，不能把另一页或另一账期的父任务判成缺失 |
| 用量表格把通道详情放在最后一列；图表在制作任务表后面 | 详情移至独立对话框；图表固定在明细之前 |

## 3. 分镜版本

- 对照视图缩略图及“全部”网格使用一致版本计算。未生成时不显示 V0；有一个结果显示 `V1`；有多个结果时版本标签使用强调色淡底，单版标签使用中性样式。
- 缩略图编号与版本分开，例如 `6 · V3`；保留现有绿点、失败点、选中边框、“开场”标签的原含义。用文字和颜色共同表达，不只靠颜色。
- 大图显示 `当前使用 V3 · 共 3 版`；若当前选用旧版，另显示 `最新 V3`。悬停或无障碍名称提供“分镜 6，当前使用第 1 版，共 3 版”等完整信息。
- 顺序沿用已有结果候选顺序及过滤规则；基于实际候选数和选用 asset ID 计算，刷新后不依赖临时前端状态。没有候选数组但有旧结果的兼容数据按现有回退规则显示 V1。
- 版本按钮名称明确为“使用上一版 / 使用下一版”，旁边说明“切换即用于后续制作”。沿用既有切换规则和 PATCH 契约；请求失败仍显示服务端已选中的版本，不假装切换成功。
- “有多个版本”只表示保留了多个结果，不承诺像素内容发生变化。此次不新增“看过 / 未看过”状态，也不新增数据库字段。

## 4. 待核对与分流设置

### 待核对

默认仍为“只看待核对”；“全部统一任务”改为“全部记录”，补充“包含已完成的统一模型任务”。默认卡片只显示模型、项目/发起人、当前状态、通俗原因、费用状态及详情入口。

- 无待处理记录时显示“目前无需人工处理”；查看全部记录且待核对数为 0 时，明确“以下是历史记录，无需逐条核对”。空列表文案区分“没有待核对项”与“没有历史记录”。
- 原因来自现有 `attentionReasons`、业务状态和通道证据，转换成中文解释。例如“供应商是否接单还没有确认”“生成结果已就绪，但下载未完成”“费用尚未核实”。仅凭未知状态，不能声称后台正在自动查询或保证稍后成功。
- “核对详情”展开后才显示通道、远端 ID、规则版本、技术错误等；“人工核对”表单再独立折叠。保留原有 legacy 未知记录入口及所有合法操作。
- 候选且未提交的通道写明“备用通道，未提交”，不能暗示重复生成或扣费。生成成功与费用核实是两个维度，成功但待核账仍可进入核对。
- 仅改变展示。未知提交不能因为等待时间长被推定失败、释放占用或触发重发；证据必填、版本校验、幂等和审计契约保持有效。

### 模型通道分流

区块标题改为“模型通道分流”，字段名为“Image 2 排队等待时间”，单位秒。说明为：“七牛名额满时先等待；达到设定时间仍满，且腾讯通道可用时，才转交腾讯。仅适用于 Image 2 的提交前排队，不是生成超时。”

校验、成功提示、aria-label 同步改名。继续接受 0–3600 的整数，0 表示不额外等待；保留既有默认 30 秒及用户已存的 10 秒等配置。可灵 3.0 的直接分流规则和其他模型不受此次文案修改影响。

## 5. 分页公共合同

任务页和用量明细共用以下合同，03 号票建立服务端参数解析及分页类型，05 号票建立共用分页控件。

| 项目 | 约定 |
| --- | --- |
| 请求 | `page` 从 1 开始，缺省 1；`pageSize` 缺省 25，只接受 25、50 |
| 非法参数 | 非整数、负数、0、超安全整数及不支持的 pageSize 返回 400；所有 SQL 参数绑定 |
| 响应 | `pagination: { page, pageSize, total, totalPages }`，total 为当前筛选范围的分页单位总数 |
| 空结果 | total=0、totalPages=1、page=1；显示“共 0 条”，翻页按钮禁用 |
| 超出末页 | 服务端归到有效末页并返回实际 page，前端同步；不循环重请求 |
| 数据查询 | 授权和筛选在计数及 LIMIT/OFFSET 之前；详情投影只加载选中页的实体 |
| 一致性 | 单次响应内计数与选页用一致读视图；同时间值有 ID 作为排序第二关键字 |
| 实时变化 | 无更新时连续遍历不重不漏；刷新后新任务或状态更新可以改变排序。不实现跨请求长事务或历史快照 |
| 交互 | 页码、上一页/下一页、每页条数、总数；超过 7 页收起中间页码，可输入页码跳转 |
| 状态变化 | 搜索/业务筛选/pageSize 改变回第 1 页；手动刷新保留当前页，越界时按响应收敛 |
| 请求竞态 | 取消或忽略过期响应；不能把旧筛选/旧页数据覆盖到新页。失败展示重试，不伪装空结果 |

不需要把完整历史执行明细加载到 Node 或浏览器后再 `slice`。SQL 可使用共享 CTE、分组 ID 查询和聚合；复杂状态/模型归一化抽成可复用查询或投影，避免列表、搜索和计数各写一套含义。

## 6. 全员任务 / 我的任务

### 服务端与身份

- 延用 `GET /api/team/tasks`，增加 `q/page/pageSize`，保留 `actorUserId/status`。响应保留 `items`（执行记录投影），增加 `pagination` 和 `totalRecords`。
- 分页单位：有 `unifiedTaskId` 时为 `unified:<id>`，否则为 `operation:<operationId>`。一页 25 个制作任务可返回超过 25 条执行记录，但这些记录必须只属于该页完整任务组。
- 任务组按其最新执行记录的 `updatedAt DESC`、稳定组 ID 排序，组内按 `updatedAt DESC, operationId DESC`。列表代表记录仍按既有最新记录规则选取。
- 状态筛选与列表实际显示的有效状态一致，保留取消、重试已回队等现有投影规则。关键词命中组内任一可见记录后，返回整组，不裁掉其其他通道。
- 搜索在完整可见历史中覆盖目前 `SEARCH_FIELDS` 的字段和中文任务/步骤名称；大小写不敏感、首尾去空格，`%`、`_` 按普通搜索文字处理。模型名称和任务中文名称应与 UI 同源。
- `totalRecords` 为当前匹配任务组内的执行记录总数。为控制本次范围，侧栏任务角标继续表示全可见范围的执行记录数，改读全范围计数，不能读一页的 `items.length`。页面同时明确“X 个制作任务，Y 条执行记录”。
- 总览和员工首页保留已有卡片业务口径，通过独立聚合及有界最近列表查询提供数据；不套用分页列表的长度，也不为一个角标加载全量详情。
- 延用 `GET /api/team/tasks/detail?taskId=<operationId>`，按 ID 和权限直接查询。任意页、500 条之外、当前列表筛选外的合法任务都可打开；不存在或员工无权读取时仍为 404。
- 员工只能读取本人；管理员可读全员或按成员筛选。直接调用分页、搜索、详情也必须执行同样权限和现有字段脱敏。

### 界面

默认每页 25 个制作任务；先分页，再对当前页按发起人分组。组标题标注“本页 N 项”，平铺/分组切换只改变展示，不额外分页。关键词输入做约 300ms 防抖并保持焦点，Enter 可立即搜索。

详情通过现有 `taskId=<operationId>` 深链接独立加载。翻页不改变已打开详情；关闭详情保留列表页和筛选；重试后同步刷新详情及当前页。刷新失败不会把旧任务状态当作新状态。

## 7. 团队用量 / 我的用量

### 查询与统计

`GET /api/team/usage` 增加 `section`，省略时为 `summary`；原有账期、模型、结果、scope、actorUserId 规则继续生效。04、05 两票配套交付，清查所有调用者与契约测试。

| section | 返回内容 / 分页单位 | 权限 |
| --- | --- | --- |
| summary | 额度、totals、counts、模型排行、趋势、成员统计、模型选项等摘要；不携带全量任务/尝试数组 | 保留现有个人/团队范围 |
| tasks | `{ items: TeamUnifiedTaskView[], pagination, range, scope, canViewTeam }`；每条统一制作任务一项 | 员工本人；管理员可选范围 |
| channels | 同结构 items 为已关联统一任务的真实调用；每 attempt 一项 | 管理员 |
| legacy | 同结构；非统一模型调用，每 attempt 一项 | 员工本人；管理员可选范围 |
| unmapped | 同结构；父任务身份确实缺失或关联不可用的记录，每 attempt 一项 | 管理员 |

- 摘要、成员统计、CSV 对完整筛选范围求值，不受页码或 section 影响；额度卡仍为原有自然月口径。模型选项取授权范围内的完整候选，不受分页或当前已选模型裁剪，避免选中一个模型后无法换选。页签切换/翻页只请求明细；账期/模型/成员/结果变化重新请求摘要和明细。
- 制作任务按 `createdAt DESC, mediaTaskId DESC`；尝试按 `createdAt DESC, attemptId DESC`。已有账期边界和任务/尝试日期归属规则保留，不改计价算法或费用落账日期。
- `channels/legacy/unmapped` 互斥，关联分类从数据库真实身份及授权判断；父任务在别页或创建于别的账期不等于未映射。缺失身份保留诊断语义，不猜测关联。
- 全范围统计与任务明细的费用仍以执行账本及 `unified-usage-contract.ts` 为依据；未知、未定价、估算、已释放不能混成 0 元成功。自动兜底仍是一条制作任务、若干真实通道调用。
- 任务页补充统一任务费用时，按该页实际 mediaTaskId 定向查询；不能再取“最近 500 个统一任务”做 Map，也不能仅按可能重名的业务 taskId 关联。
- CSV 保留当前导出字段及调用账本口径，覆盖完整筛选范围，并与页面的个人/团队权限及 scope 一致；分页参数不截断导出。

### 界面结构

顺序固定为：额度卡 → 账期与筛选 → 模型消耗排行与趋势 → 成员统计（现有可见条件）→ 明细页签。

- 明细页签为“制作任务”“通道调用”“其他记录”，默认制作任务；员工不显示通道调用。
- “其他记录”默认非统一模型，管理员可切换“待映射记录”；两种记录各自请求和分页。任意时刻只呈现一个明细列表，隐藏页签不预加载全量数据。
- 切换页签或其他记录类型回第 1 页，保留业务筛选；分页控件放列表上方和下方。
- 制作任务每行仅放时间/成员、模型/来源、状态、调用摘要、费用、查看详情；远端 ID 和长错误不进入表格列宽计算。
- “查看详情”使用共用 `Dialog` 的 wide 规格，内部展示通道摘要、费用和按需展开的技术字段；显示中文状态，备用未提交单列说明。对话框长文本换行、内容区可滚动，Esc 关闭并归还焦点。
- “模型”筛选仍为筛选控件，不改成多级导航树。二级页签指明细分区，而不是给模型选项再套多层菜单。

## 8. 统一验收与交付

1. 采用隔离 SQLite/数据根，伪供应商；不得读取生产账本或调用付费模型造测试数据。数据库测试先设置数据根再动态 import。
2. 造 **503 个制作任务，其中一个有 3 条执行记录（共 505 条执行记录）**，覆盖跨页搜索、整组分页、末页、同时间排序、权限、旧链接。另造超过 500 条用量任务及跨页/跨账期父子关联。
3. 对翻页前后的金额、排行、趋势、CSV 进行实际数值校验；不是只断言出现“分页”文本或某段源码。
4. UI 在 1536×864、1280×720、1024×720，浅色/深色，Chromium/WebKit 验收。覆盖详情展开、长项目名/远端 ID、空结果、末页和多个版本；整页不横向滚动、控件可达。运行前读 `docs/reference/界面尺寸验收.md`（Windows TEMP 要求）。
5. 逐票运行列出的相关检查，最后统一跑类型检查、lint、外观契约及 `npm run check:main-path`；后者用于本次跨查询/页面数据交接改造。相同检查无变更时不用重复全跑。失败记录原因及是否基线问题，不把未运行写成通过。
6. DeepSeek 将实际改动、命令结果、截图/报告路径、已知缺口追加到每票 `Comments`，在 README 更新交付检查列；完成实现的票标为 `ready-for-human` 等待 Codex 审查。本轮无部署要求。
