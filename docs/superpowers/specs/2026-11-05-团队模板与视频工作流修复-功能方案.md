# 团队模板与视频工作流修复

**状态：** `ready-for-agent`

本规格记录 2026-11-05 用户反馈及本轮确认；本次交付为规格与任务单，功能尚未实施。执行入口：[任务索引](../plans/2026-11-05-团队模板与视频工作流修复/README.md)。本规格是这五项变更的行为依据，取代旧文档中“H3/Wan 主工作台固定全能参考、隐藏尾帧”的要求。

## 1. 已确认的目标

1. 管理员在「公共资源」直接上传爆文模板 `.xlsx`，预览后点击「发布给团队」，不需要查找或输入资源 ID。员工统一使用当前已发布版本；新导入切换新版本，历史任务与已生成脚本保留旧快照。
2. 修复客户端和服务器管理页面的视频结果缩略图。
3. 团队任务默认按发起人分组，展示姓名、工号和任务数，可展开/收起、筛选某个人；保留平铺视图和状态筛选。
4. H3/Wan 默认展示首帧和可选尾帧的双卡片样式。只有单图时自动参考生视频；有效尾帧上传成功后自动首尾帧生视频；移除尾帧后恢复参考生视频。用户不切换模式。
5. 修复 H3/Wan 大图在自动压缩前被原图大小限制拦截的问题。

上述目标均已获用户确认。本轮不实施业务代码、不替用户部署；后续执行者按任务单实施并提供独立验收证据。

## 3. 公共爆文模板合同

### 管理员操作

- 正式入口为 `/team/admin/resources` 的「爆文模板库」卡片；复用现有 XLSX 解析/报告能力。上传、预览、发布、当前版本与可用条目数在同一流程内完成。
- 预览显示总数、可用/不可用/待检查数量和解析问题；取消、解析失败、发布失败均不改变当前团队版本。新文件发布替换当前有效版本，不自动累计合并旧文件。
- 重复提交同一内容幂等；旧内容已存在但不是当前版本时，明确激活该版本，不只返回 created:false 就误报发布完成。并发发布需检测基准版本冲突，避免无提示覆盖其他管理员刚发布的版本。
- 当前版本指针、该修订及其条目的可读权限必须一致地生效。不能只公开库根而留下私有条目，也不能批量公开管理员或员工的私人历史资源。
- 提供按文件名、版本、条目数识别的既有模板版本入口，让管理员能把此前已导入的目标版本发布给团队；内部 ID 由程序传递，不要求手填。多库不能凭创建时间随意挑一个作为团队库。

### 员工读取及历史

- 推荐、搜索、模板详情和新脚本任务创建均解析同一个明确的团队当前版本，不受员工个人空库或私人非空库遮挡。管理员在制作项目时也使用同一团队当前版本。
- 没有团队版本时返回真实空状态并提示联系管理员发布，不再引导员工去无权访问的设置页；只读请求不能为员工顺手创建空私人库。
- 员工不能导入、发布、切换团队版本或修改公共条目；服务端验证权限及既有 CSRF/来源策略。local 模式保留原设置入口和个人库行为。
- 历史任务继续按已冻结修订/条目/文案执行；曾经正式发布的旧版本保留必要读取能力，不能因为切换当前版本导致已接受任务重试失败。未发布的私人修订保持隔离。
- 页面选择模板后若管理员切了版本，提交时明确提示刷新选择或采用经验证的已冻结快照，不能静默替换用户选择。执行者选定一致策略并写入验收记录。

建议新增团队专用上传发布编排入口，复用领域解析函数；不要简单把个人 import 接口挂进公共页面。持久化团队库/当前版本的方式由实现者确定，必须具有明确唯一身份、原子切换和可验证升级；如需 schema 变更，遵守独立模块追加迁移及共享升级 gate。

## 4. 视频缩略图合同

- 目标是第四步已完成视频卡片中的海报正常显示。优先保持现有 sourceImageId 对应分镜海报语义，不要求重新抽取或重新生成全部视频。
- 受保护图片应经浏览器带会话的同源请求读取。可在对应组件使用 unoptimized 或等效的受保护图片展示方式；不通过公开文件接口、取消鉴权或传递 URL 中的会话凭据解决。
- 缩略图失败时显示明确占位和可恢复状态，不能保留破图图标，也不能无界重试。视频播放和下载保持可用。
- 管理员、图片所属员工可读取；其他员工及未登录者无权读取。同一浏览器切换账号后不能泄露上一账号图片。
- 顺带检查相同受保护图片展示模式的调用点，只修与该鉴权缺陷直接相关的路径，避免全站关闭优化。

## 5. 团队任务合同

- 默认按 `actorUserId` 分组，姓名＋工号为显示值；同名成员不能混组。组默认展开，按组内最新任务更新时间降序，组内保持当前任务排序；支持单组折叠。
- 保留“按发起人／平铺”切换。成员筛选使用服务端 actorUserId，与状态条件组合后再执行 LIMIT；成员选项不能仅来自当前最近 500 条任务，低频成员仍可选。
- 组任务数明确为“当前结果 N 条”，总提示明确最近记录上限；不把截断结果标成某成员所有历史任务数。平铺、分组使用同一结果集和状态口径。
- 搜索、刷新、展开详情、复制排查信息继续可用；同页刷新保留当前视图、筛选与尚存在组的折叠状态。历史停用但仍有任务的成员应可辨认。
- 员工查询仍仅本人，不能通过 actorUserId 绕过权限。本轮不增加报表统计、费用计算或全历史分页系统。

## 6. H3/Wan 自动模式合同

仅对供应商类型 `openai-video` 且精确模型 `minimax-h3`、`wan-3.0` 应用下表；其余模型沿用既有能力声明与行为。

| 草稿状态 | UI | 新任务执行行为 |
| --- | --- | --- |
| 首图有效、没有尾图 | 首帧卡＋添加尾帧卡 | reference-to-video，当前冻结首图作为唯一 Reference |
| 尾图上传中/删除中/失败/无效 | 保留操作状态和重试/移除入口 | 阻止提交，不因 tailImageId 暂为空自动退回单图 |
| 首图与尾图均有效 | 同一双卡片布局 | image-to-video，FileInfos Usage=FirstFrame/LastFrame |
| 用户明确移除尾图 | 恢复添加尾帧卡 | reference-to-video |

- 不增加模式切换开关；允许简短提示当前会按单图或首尾帧生成。点击、拖拽尾帧共用状态；逐行生成与批量生成逐条决策。
- 前端提交与服务端创建共用可测试规则。服务端从受控工作台请求的模型、已授权素材和尾帧状态确定/核对模式，不能只信前端 generationMode，也不能全局重写所有 API 请求。
- 兼容边界：已有数据库任务、重试/续查按冻结 generationMode、sourceImageId、tailImageId、referenceAssetIds、比例和清晰度执行；画布、显式多参考素材 API、外部集成的既有合同保持稳定。需要自动意图标记时由实现者定义向后兼容的字段。
- 任一无效/跨项目尾图均在付费 POST 前失败；已选尾图不能静默丢弃。切换供应商保留合法草稿，不合法时提示处理；批量中混合单图/双图正常分流。
- H3 保持 2K、Wan 保持 1080P 默认；时长、比例、精确 allowlist、COS 与回环 LiteLLM 门禁保持各自既有合同。

## 7. 图片预处理合同

- 本轮对象为这两个模型的新工作台任务的源图与可选尾帧。原图仍原样保存并保持素材归属；仅生成发往上游的派生副本。首尾帧和单图参考两条路径都须验证。
- 区分“本机可安全接收/解码的原图限制”与“上游实际交付限制”。本机文件大小、像素、格式等保护仍生效；允许处理的图片先规整/压缩，再按模型校验实际交付 MIME、字节、尺寸。原图超过 10 MiB 但可以压到合法大小的情况应成功通过。
- 创建任务和执行任务都要调整：不能创建阶段仍按原图上游上限拒绝，而只在队列补压缩；也不能为绕过检查把 byteSize 改成 null 或伪造较小数值。
- 用有限、确定性的压缩/缩放策略保证输出真正满足预算；适合的小图尽量原样。PNG 透明通道/格式转换遵守模型支持格式，错误扩展名按实际字节探测；损坏、动画或超出本机保护上限的图片给明确错误。
- 达不到上游预算、转码失败或 COS 失败时不提交生成；该模型链路不能沿用“压缩失败就发送不合格原图”的兜底。既有关闭可选 COS 压缩的设置不得绕过硬性模型限制：原图合规则可原样，不合规则仍须得到合规副本或明确拒绝。
- 并发、取消与清理有界；派生物路径基于 dataRoot，并遵循团队文件登记/读取权限。临时产物不更换原图身份、不进入用户导出作为原件、不写签名 URL 到持久化日志。
- 不全局改变所有图片供应商的压缩规则。若修改共享 helper，提供兼容回归；创建与执行共用预算合同，避免两套阈值。

## 8. 验收与交付边界

每张功能票先通过自己的定向测试，再由 06 做跨功能验收。测试先在内存库/临时数据根、假 COS 与假供应商完成；真实调用只用于最终协议/画面确认，遵守届时授权范围，并清楚区分 mock 与实测。

交付至少包括代码、定向测试结果、管理员与员工真实会话浏览器证据、历史任务兼容说明、服务器源码/运行版本对照和未完成项。按 AGENTS.md 跑跨步骤 `npm run check:main-path`；lint/build 的失败区分本轮引入与既存问题。部署与重启另按用户实际交付范围执行，不因完成文档就视为允许操作生产实例。
