# 抖音品牌包装（E）设计规格

> 日期：2026-11-18
> 状态：需求与交互已确认；已纳入首轮 M1–M8、第二轮 R1–R4、第三轮 T1–T3、第四轮 F1–F3、第五轮 V1–V4、第六轮修正与优化，待实施
> 视觉依据：`抖音视频账号字体应用规范0907.pdf`、用户提供的封面与正文参考图、`H:\抖音视觉` 原始素材

## 1. 目标

在现有四套 HyperFrames 包装之外新增第五套独立模板「E 抖音品牌」，用同一套模板资源完成：

- 首帧品牌 LOGO、产品名称主标题、品牌色括号和产品卖点次标题；
- 正文卖点自动生成、重点词彩色高亮、重点词放大、自由位置调整；
- 尾帧品牌 LOGO 与独立必备的箭头 GIF 引导；
- 单条精准混剪与批量统一审片的编辑、预览、审核、正式导出。

整套方案只支持 1080×1920（9:16）。预览、封面 JPG、20 帧片头和正式视频必须读取同一份持久化配置，并由同一模板排版，不再为封面另写一套 sharp SVG 文字布局。

## 2. 范围

### 2.1 纳入

- 新模板 `overlay-douyin`，UI 名称为「E 抖音品牌」，生产码为 `E`。
- 单条精准混剪与批量统一审片。
- 封面、正文卖点、尾帧箭头、首末 LOGO。
- AI 生成卖点文案与高亮建议，现有口播对齐数据决定时间。
- 右栏全卖点清单直编、单词编辑、片内跨卖点批量选择与批量应用。
- 手动编辑、撤销重做、刷新恢复、审核失效、任务快照与正式导出。
- 字体、LOGO、箭头帧序列的离线物化、内容哈希和打包负载。

### 2.2 不纳入

- 现有四套模板、classic/1、`lib/film-render` 和 classic 构建资产的视觉改动。
- 3:4、16:9 适配。
- 独立片尾页或额外延长视频。
- 现有贴纸素材库、贴纸轨道或跨片贴纸复制。
- AI 主体识别、自动避让人脸或产品。
- 跨成片共享生成结果、跨片内容继承或跨片批量样式修改。
- 自由字号输入、非等比拉伸、镜像、旋转和额外装饰符号。

## 3. 已确认的用户契约

| 模块 | 契约 |
| --- | --- |
| 模板关系 | 与现有 A/B/C/D 互斥，不叠加；旧配置与旧任务不迁移 |
| 画幅 | 仅 9:16；其他画幅选择本模板时需显式确认切换 |
| 封面主标题 | 产品名称，不从口播正文猜测 |
| 封面次标题 | 产品卖点，不从口播正文猜测 |
| 产品文案初始化 | 从 AI 卖点库、旧 `projects.productName` 等已有数据一次性预填，之后读取本包装自身配置 |
| 正文卖点 | AI 写文案、高亮与放大建议；时间由口播对齐句段计算 |
| 卖点层级 | 主卖点 1–2 行，可有高亮和放大；可选一行补充小字，默认白色、随基础色切换、始终正常字号 |
| 高亮色 | 品牌色、营销红、亮黄色三类；红黄只能使用规范四阶色板 |
| 普通文字 | 白色；浅色底图可使用规范黑色 |
| 默认位置 | 水平居中、垂直中下部，避开抖音 UI；可自由拖动 |
| 放大 | 首版固定为普通文字的 1.35 倍，只提供开关 |
| 尾帧 | 不延长视频，末约 2.5 秒显示 LOGO 与箭头；卖点是否出现由自身时间决定 |
| 箭头 | 独立必备，不能因没有卖点而省略或报错 |
| 箭头颜色 | 有可用高亮卖点时跟随；无卖点或无高亮时每条包装配置随机一次并固定；手动改色后不再自动变化 |
| 随机配色 | 片内批量编辑时按卖点分组随机，同一条卖点内的高亮词始终同色 |

## 4. 总体架构

### 4.1 一个渲染源

新增 `packaging/templates/overlay-douyin/`，与现有模板共用 HyperFrames、Chromium、字体物化、透明层渲染和 FFmpeg 合成链路。

- 浏览器编辑预览直接加载该模板 HTML 与共享编辑桥。
- 正式视频由同一模板生成透明 WebM，再叠加到底片。
- 封面文字与 LOGO 也由该模板渲染为透明覆盖层，禁止再用独立 SVG 重排标题。
- sharp 继续负责底图抽帧、裁切和 JPG 合成，但不负责抖音标题的字体排版。

封面元素在 20 帧片头内保持稳定可见，不使用首帧透明入场。封面 JPG 取既定封面参考帧，保证与片头视觉一致。

### 4.2 共享封面生成器

新增共享的抖音封面覆盖层生成能力，供三个入口调用：

1. 单条正式包装后的封面 JPG；
2. 批量完整渲染后的封面 JPG；
3. 批量独立封面任务。

批量独立封面任务目前不运行 HyperFrames，这是本方案必须补齐的入口。该任务只生成封面所需的静态透明覆盖层，不渲染整段正文视频。

抖音模板启用时，底图阶段抑制旧 `title.png`，避免旧标题与抖音标题叠加。

批量独立 `coverContractHash` 必须额外包含：包装启用状态、模板、`douyin.cover`、画幅和封面资源身份（封面字体、LOGO、括号及 fit）。合同变化后排新任务，迟到旧任务不得成为当前封面。正文 runs、正文位置、尾帧颜色和箭头时机不属于独立封面合同，修改它们不得重排封面；完整渲染合同仍包含完整抖音配置。

**旧合同兼容**：仅当 `packaging.enabled && template==='overlay-douyin'` 时才把上述 E 字段加入独立封面或完整渲染合同。A–D 的历史输入，以及携带休眠 `douyin` 数据的 A–D 输入，在其他有效配置相同的情况下必须得到与改造前完全相同的任务键。启用 E 后只改正文更新完整渲染键、沿用独立封面键，改封面文字则两者都更新。

### 4.3 存储作用域与“一次预填”

不新增数据库表，不新增跨脚本内容层。

- 单条继续保存于当前 final-edit group 的包装 JSON；组内 variants 的共享行为保持现状。
- 批量继续保存于当前 output version 的 `arrangement.packaging`。
- 本规格中的“独立”是指配置初始化后不再读取项目或脚本的实时产品数据，也不依赖其他成片。
- 新建包装配置时一次性预填产品名称、产品卖点和可用的随机默认值；后续项目数据变化不静默改写已有包装。
- 单条入队继续使用不可变任务快照；批量继续使用 outputVersion、editRevision 和完整渲染合同，发布前继续 CAS。

可信预填优先级为：**当前可用且资格合格的详情页修订卖点库 → 旧 `projects.productName/sellingPointsJson` → 留空并手动必填**。禁用或不合格条目不预填。旧 `coverTitle`、脚本封面标题及其拆分结果不作为产品名称／产品卖点的可信来源。初始化同时冻结实际采用的证据文本、来源 ID 和库修订；旧数组使用来源索引标识，修订库保留资格信息，后续生成只读这些持久化输入并计入 `inputHash`。

单条组内 variants 可以独立编辑口播。自动生成共享卖点时，只采用所有受影响 variants **共同可听、且映射到相同成片时间区间**的来源句段；同一来源句若在不同 variant 中时间不同，同样跳过并说明。手动共享卖点不因音轨差异被自动删除，但界面应提示该差异。候选必须记录全部参与计算的 variant IDs、revisions 和音轨输入哈希，任一变化都使旧候选失效。

启用 E 的历史是“包装＋每个受影响 variant 画幅”的复合历史，不得只恢复组级包装或只恢复 variant 时间线。批量恢复对应快照也必须包含 `preset`。

### 4.4 模板能力与提前分流

用集中式模板能力表声明 `legacyPointCues`、`stickers`、`autoLayoutV2` 和 `douyinPoints`，不得在多个入口散落模板特判。

- E 不进入旧卖点自动提取、贴纸解析／槽位规划和 v2 自动布局门禁。
- 单条预览 GET、包装保存后和入队前必须先按能力分流；打开 E 预览不得调用供应商或写数据库。
- E 没有卖点也可入队，不显示旧“正在更新自动布局”等待态。
- 从带 v2 贴纸的 A–D 切到 E 时保留旧字段但不执行；撤销启用并恢复原画幅时可恢复原 Resolution，主动切回但保留新画幅时只恢复内容并重新验证布局。
- 贴纸相关模板类型与映射只接受支持贴纸的模板，新增 E 不得迫使伪造一套贴纸风格或槽位。
- 跨片贴纸复制在 UI 排除不支持贴纸的来源与目标，服务端在规划前对来源和全部目标统一复核；任一目标不支持时整批零写入，不能用部分成功绕过。

### 4.5 预览底图与更新责任

- 单条 Canvas 在 E 启用时不得再按旧 `group.coverTitle.enabled` 绘制旧标题。
- 批量必须区分裸底图与已含 E 标题的成品 JPG；成品 JPG 回退分支不得再次叠加 E 标题。
- E 的 runs、颜色、放大、文案、封面和尾帧配置纳入包装预览结构签名或编辑桥实时更新，不能只监听旧 `pointCues/stickers`。
- 几何拖动不重建 iframe；结构变化只重载包装 iframe，不重建底片视频组件。
- 批量预览画布、画布内拖动和安全区从实际显示的 `previewFilm` 读取尺寸；右栏检查器与封面抽屉从实际编辑的 `activeFilm` 读取尺寸，并保存到该 output version。普通预览仍取第一条眼睛可见成片，包装页签优先预览选中行，不能用同一画幅覆盖两种目标。

## 5. 配置与领域模型

### 5.1 独立命名空间

在 `FinalEditPackagingConfig` 增加版本化的 `douyin` 配置。旧 `pointCues` 不承载分段高亮，避免影响旧模板。

建议结构：

```ts
interface DouyinPackagingConfig {
  version: 1;
  cover: {
    productName: string;
    sellingPoint: string;
    logoVariant: 'auto' | 'dark' | 'white';
    layout: DouyinCoverLayout;
  };
  points: DouyinPoint[];
  evidence: Array<{
    sourceKind: 'script-studio-library' | 'legacy-project';
    sourceId: string;
    sourceIndex?: number;
    revision?: string;
    eligible: boolean;
    qualification?: string;
    text: string;
  }>;
  ending: {
    arrowStartSec?: number;
    arrowColorMode: 'auto' | 'manual';
    arrowColor: DouyinArrowColor;
    fallbackArrowColor: DouyinArrowColor;
  };
}

interface DouyinPoint {
  id: string;
  originPointId?: string;
  runs: Array<{
    text: string;
    highlighted: boolean;
    scale: 'normal' | 'large';
  }>;
  caption: string;
  baseColor: '#FFFFFF' | '#000000';
  highlightColor: string;
  startSec: number;
  endSec: number;
  layout: { x: number; y: number };
  sourceCueIds: string[];
  timingOrigin: 'ai-aligned' | 'manual';
  timingBasisHash: string;
  edited: {
    text: boolean;
    style: boolean;
    layout: boolean;
    timing: boolean;
  };
}
```

### 5.2 为什么颜色放在卖点级

PDF 要求同一画面克制用色，用户又确认“每条卖点随机一个颜色”。因此：

- `highlightColor` 属于整条卖点；
- `runs[].highlighted` 决定哪些字使用该颜色；
- 普通 run 使用 `baseColor`，默认为白色，浅色底图可切换为规范黑色；补充小字使用同一基础色；
- `scale='large'` 与是否高亮相互独立，未高亮文字也可放大；
- 修改某条卖点的高亮色会统一该条所有高亮 run，不产生同条多色脏数据。

自动生成的卖点在时间上不重叠。用户手动制造时间重叠时，若同屏超过两种字体颜色，界面给出提示但不阻断手动编辑。

### 5.3 校验与兼容

- `version` 缺失的旧配置不视为抖音配置；未知版本明确拒绝，不静默降级。
- runs 拼接结果是主卖点全文；不允许空 run，相邻同样式 run 在保存时合并。
- `large` 固定映射 1.35，不接受任意倍率。
- 高亮色只能来自规范色板；小字默认白色、随 `baseColor` 切换、始终正常字号。
- 时间继续与现有卖点轨道使用秒，渲染边界统一量化到 24fps 整帧。
- 配置清洗、严格写入、历史恢复、预览变量、任务快照和渲染合同必须完整保留新字段与冻结证据。

### 5.4 稳定选区与 runs 拆合

批量选区使用 `{pointId, startOffset, endOffset}`，偏移基于 runs 拼接后的完整文案，不绑定 run 下标或 DOM 节点。

- 颜色或放大只改变分段样式，不改变全文，因此应用高亮后原选区仍可用于一键放大。
- 一次选区可以跨多个 runs，应用时先按全文偏移拆分，再合并相邻同样式 runs。
- 文案发生编辑时，重新按新全文计算选区；无法可靠对应则只清除该卖点的临时选区，不改错其他文字。
- 临时选区只属于 UI，不进入数据库或任务快照；样式结果才持久化。

首次单击的词块由全文确定性派生，不持久化、不依赖当前 runs 边界：

- 连续数字、小数、百分比及其紧邻单位必须作为整体，例如 `61cm`、`2000元`、`5折`；
- 中文使用统一的 Chromium 分词规则，分词不可用时退回稳定的最小字符规则；空白与标点不单独形成误导性词块，可通过划词选择；
- 刷新、runs 合并和重新打开编辑器后词块边界一致；单击选择完整词块，划词仍可选择其中任意字符。

## 6. 视觉规范

### 6.1 字体

使用用户提供的三款字体并纳入离线资源：

- 方正兰亭粗黑 GBK：`FZLTCHK.TTF`；
- 方正兰亭中粗黑 GBK：`FZLTZCHK.TTF`；
- 方正兰亭准黑 GBK：`FZLTZHUNHK.TTF`。

封面主标题和正文主卖点使用粗黑／中粗黑，封面次标题和补充小字使用准黑。字体文件、括号符号字体和实际 fit 参数进入冻结清单。

### 6.2 色板

- 品牌色：`#3AEFD0`。
- 黑色：`#000000`，仅用于浅色背景的普通说明文字。
- 营销红：`#FF0000`、`#FF2323`、`#FF3C3C`、`#FE5252`。
- 亮黄色：`#FFC800`、`#FFD300`、`#FFE800`、`#FFF589`。
- 普通文字白色：`#FFFFFF`。

自动语义配色：价格、优惠、促销使用营销红；材质、功能和核心卖点使用品牌色；需要特别强调的利益点使用亮黄色。AI 只能在上述色板内选择，语义不确定时使用品牌色，不自行创造颜色。

随机配色按色系均衡分配，默认使用品牌色及 PDF 搭配示例中的 `#FE5252`、`#FFE800`；AI 和手动色板可选择规范内的其他阶色。

### 6.3 封面

- 左上品牌 LOGO，使用原始横版 PNG 等比缩放。
- `logoVariant='auto'` 时分别测量封面与尾帧 LOGO 区域亮度：浅底使用深色字，深底使用白字，不强制尾帧沿用封面。预览、封面 JPG 和 MP4 使用同一解析器，解析出的两个实际版本随任务快照冻结；P0 用“浅封面＋深尾帧”和“深封面＋浅尾帧”签样确认。
- 主标题为产品名称，可两行；两侧使用品牌色括号，不添加阴影。
- 次标题为产品卖点，位于主标题下方。
- 封面不添加正文卖点、箭头或其他贴纸。

### 6.4 正文卖点

- 默认水平居中、垂直中下部。
- 主卖点可使用高亮和放大；补充小字可选，默认白色、随基础色切换且保持正常字号。
- 不默认添加底框、括号、阴影或额外装饰。
- 位置可自由拖动；自动布局避开顶部、右侧交互栏和底部 UI 安全区。
- 多条同时出现时只做紧凑平移避让，不自动缩小、不改变颜色或字号。

### 6.5 安全区与字号标定

PDF 的 16–25 不是输出像素，不能直接用作 CSS 字号。

实施第一阶段必须用实际 TTF 在 Chromium 中完成字体度量，并以用户参考图在 1080×1920 下的视觉尺寸标定：

- 封面主标题、次标题和括号间距；
- 正文主卖点、补充小字和 1.35 倍强调；
- 顶部、右侧、底部安全区；
- 默认居中偏下位置和 LOGO 尺寸、边距。

这些数值集中为一份模板常量，不在组件中散落硬编码。标定样本通过后再进入完整模板开发。

## 7. AI 卖点生成

### 7.1 输入与输出

输入：

- 当前成片的口播对齐句段和句段时间；
- 本包装已持久化的产品名称、产品卖点；
- 初始化时冻结在 `douyin.evidence` 中的卖点文本、来源 ID 和库修订，不重新读取实时卖点库；
- 字数、语义配色、层级和事实校验约束。

AI 只返回：

- 选中的来源句段 IDs；
- 主卖点分段及高亮建议；
- 整条卖点的高亮色系；
- 可选补充小字；
- 建议放大的一处重点词；
- 事实证据锚点。

AI 不返回开始或结束时间。服务端根据来源句段的真实对齐时间计算卖点起止，并处理片头偏移、音轨修剪、实际可听见区间、倍速和 24fps 量化。有效真实锚点在倍速下必须正确换算；估算字幕、均分时间、匹配失败回退和已剪掉／已静音句段均不可使用。

可信时间只来自原始口播快照中**未降级**的句级或词级对齐：能证明整句边界时可用整句，定位句内片段时必须有该片段本身的可靠词级依据。显示字幕按字数拆分的时间即使标为 `aligned` 也不可信；TTS 原始 `degraded` 标记必须随快照保留，不能被统一的 `timingSource='aligned'` 覆盖。历史快照无法证明来源时按不可信处理并跳过受影响句段。

单条多 variants 时，先求所有受影响 variants 的共同可听句段，再要求这些句段映射到相同成片时间区间；不满足共同时间依据的句段跳过并说明，不把某一个 variant 的时间强加给整组。

### 7.2 校验

硬校验：

- 结构、字数上限、色板和时间边界合法；
- 数字、价格、单位必须与对应属性共同出现在声明的精确事实锚点中，不能只做全证据文本的关键词包含；例如“靠背高 61cm”不能证明“坐深 61cm”。无法可靠确认属性对应关系的改写沿用“请核对”；
- 来源句段属于当前成片，时间可解析；
- 每条卖点最多一处 AI 建议放大。

软提示：

- 材质、功效等改写无法字面匹配时标记“请核对”，允许用户确认，不反复自动重写。

无可用供应商、生成失败或校验失败时，可降级文案提取与规则高亮，并明确标识结果来源；不得把失败候选冒充 AI 完成结果。文案降级不等于时间降级：没有有效真实锚点时，不自动生成定时卖点，保留已有手动内容、封面和独立箭头，并说明未生成原因。

### 7.3 候选与提交

- 用户点击生成后，AI 结果先形成不可变候选，携带 scope、expectedRevision 和 inputHash。
- 候选通过校验后按 CAS 一次事务自动提交，不再增加额外确认弹窗；期间配置变化则候选失效，不覆盖新编辑。
- 只有用户显式点击生成才执行写命令，不在后台静默修改已审核内容。
- 实质修改按现有规则递增 revision、清审核并进入一次历史记录。
- 新旧卖点优先按 `originPointId` 对应，其次要求 `sourceCueIds` 唯一匹配；一对多、多对多或来源歧义时不自动覆盖，也不能只按改写后的文案猜 ID。
- 文案、样式、位置、时间分别记录编辑状态，但 runs 是“文案＋样式”共同体：`textEdited` 或 `styleEdited` 任一为真时，未经确认不得用 AI 新 runs 替换；位置和时间可独立保留。
- 重新生成默认只覆盖未编辑部分；候选重试必须重新验证 revision、输入证据和来源句段。单条还必须重新验证全部参与计算的 variant IDs、revisions 和音轨输入哈希，AI 等待期间任一 variant 音轨变化均零写入。
- 若重新生成会替换已编辑内容，必须显式确认，并提供一次整体撤销。

### 7.4 保存后的音轨变化与 stale

自动卖点除了 `sourceCueIds`，还保存 `timingOrigin='ai-aligned'` 和 `timingBasisHash`。哈希只包含真正影响时间的输入：实际使用的对齐、倍速、音轨修剪与单条参与 variants 的音轨身份；不得直接使用整个 variant revision，否则只改封面也会误报。手动卖点使用 `manual`，不依赖自动 stale。

- 保存后任何相关音轨变化只派生并显示 stale，不后台自动改写卖点、revision 或审核。
- 预览可继续显示过期内容，但必须明确标记“时间需重新对齐”；正式导出预检发现 stale 自动卖点时阻断，不得静默隐藏或按旧时间导出。
- 用户可显式“重新对齐”、手调时间或删除过期卖点。重新对齐重新校验 revision、冻结证据和全部音轨身份；手调后转为 manual；删除按普通编辑处理。
- 单条已入队任务可按其冻结快照完成旧版本导出，不受新 stale 追溯影响。
- 批量任务即使已入队，结果提交和正式发布仍受当前 outputVersion、editRevision 与完整渲染合同约束；音轨变化导致合同变化后，旧结果不得成为当前候选或当前正式成片。
- 单条与批量共用 stale 识别规则，但不共用完成结果语义；单条多 variants 必须重新满足共同可听与共同时间区间。

## 8. 右栏卖点清单与编辑

### 8.1 独立版块

抖音模板下，右栏提供「封面／卖点／尾帧」版块。

「卖点」页按时间顺序展开当前包装作用域的全部卖点，每张卡片包含：

- 起止时间；
- 可直接编辑的主卖点词块；
- 可选补充小字；
- 定位与删除操作。

编辑不再以“先在预览或时间轴选中卖点”为前置条件。正在编辑的卡片只与预览和时间轴做高亮联动，不强制跳转播放头；点击“定位”才跳转。

空清单必须提供“手动新增卖点”入口：在当前播放头创建一条 `timingOrigin='manual'` 的卖点，使用默认时长和默认位置，时间可继续拖动；保存写入 `douyin.points` 而不是旧 `pointCues`，刷新可见，一次撤销可回到空清单。零卖点时仍保留箭头并可导出。

### 8.2 单点即改

默认状态：

- 单击词块，使用当前默认高亮色切换高亮；
- 划词可选择任意字词范围；
- 选中后可改色、切换放大，或使用“强调”一次完成默认高亮＋放大；
- 白色文字也可只放大。

### 8.3 批量选择

打开「批量选择」后：

- 点击词块只切换选中，不立即修改；
- 可跨多条卖点选择多个词；
- 顶部显示已选数量和清空入口；
- 「一键高亮」统一使用默认色；
- 「随机配色」按卖点分组分配色系，同一条卖点的全部高亮词统一颜色；
- 「一键放大」将选中词统一放大；若全部已放大，再次执行则统一还原；
- 应用高亮后保留基于全文偏移的选择，便于继续一键放大；runs 拆合不得改变目标文字；
- 每轮应用为一次保存、一次 revision、一次历史记录，可整体撤销。

批量仅指当前包装作用域内的多条卖点，不跨成片。

随机结果立即持久化，刷新、撤销后重做和正式导出不重抽；再次点击随机配色才是用户主动换一组。

### 8.4 预览与时间轴

- 预览负责选中、拖动位置和实时视觉反馈。
- 时间轴负责起止时间调整。
- 右栏不堆位置、字号、帧数等数值输入。
- 编辑卖点样式不得重建底片视频组件或引发封面闪动。
- 切换成片或审核前必须显式 flush 当前片的最后输入，使用发起编辑时的 planId/outputVersionId/editRevision 保存；保存成功后才能审核或自动推进，失败则停留当前片并提示，审核对应用户实际看到的新修订。

## 9. 尾帧 LOGO 与箭头

### 9.1 必备且独立

模板启用时，尾帧引导始终包含 LOGO 和箭头：

- 没有卖点、卖点全部删除或没有高亮词，箭头仍存在；
- 不强制创建收尾卖点，不自动延长末条卖点；
- 不单独提供删除箭头的入口；包装总开关仍可整体关闭包装。

默认开始时间为结尾前 60 帧（24fps 下 2.5 秒）；正文不足 60 帧时夹到正文开始。开始时间可修改，但不能进入 20 帧片头，最晚只能取全片最后一个可见帧。预览使用其实际时间线总帧数，正式包装使用实际渲染总帧数，不能用组期望时长替代成片时长。箭头动画相位从箭头自身开始帧起算，与播放头是否从中间 seek 无关。

### 9.2 颜色解析

`arrowColorMode='auto'` 时：

1. 若当前配置存在带高亮词的卖点，按 `startSec` 再按稳定 ID 排序，取最后一条卖点的高亮色系；
2. 否则使用已持久化的 `fallbackArrowColor`；
3. fallback 必须在创建配置的写命令中从品牌色／营销红／亮黄色随机一次并持久化，预览、撤销重做和冻结任务只读取结果，不能临时补抽。

`arrowColorMode='manual'` 时只读用户选择的 `arrowColor`，不再被卖点变化覆盖。

箭头颜色按色系匹配源 GIF；源素材固定颜色不额外重染色。

### 9.3 确定性 GIF 渲染

不能直接在正式渲染中播放 GIF。构建期执行：

1. 正确处理 GIF 透明合成和 disposal；
2. 逐帧解码并裁切非透明包围框；
3. 记录每帧在 1080×1920 画布中的原始偏移、尺寸和时长；
4. 输出小尺寸 PNG 帧序列与 manifest（含 SHA-256）；
5. 保留三色各自的原始时长表，不强行统一动画节奏。

运行时按输出时间查累计时长表并选择唯一帧，按原始锚点贴回画面。预览、seek、撤销重做和正式导出使用同一帧序列，不依赖 GIF 播放状态。

## 10. 画幅与模板原子启用

现有单条和批量没有可直接复用的“已有成片就地切画幅”命令，本需求必须显式新增 `enable_douyin_packaging`，不得假定前端 `setOutputPreset` 能完成。

- 用户选择 E 时，若当前不是 9:16，明确提示切换画幅会使当前渲染结果和审核状态失效。
- 用户确认后，由**一个原子命令**同时校验版本条件、写入 1080×1920 和选择 E；不得拆成“画幅已成功、模板写入冲突”的两步操作。
- 单条命令同时携带 group 与相关 variant 的 expectedRevision。由于包装属于 group，组内存在多个 variants 时必须明确提示“整组统一到 9:16”，并在同一事务处理所有 variants；不得出现 E 已作用于组、其他 variant 却仍是非 9:16 的非法状态。
- 批量只修改当前 output version，并携带 `expectedOutputVersionId + expectedEditRevision`，按现有规则使渲染与审核失效。启用事务同时处理根 `arrangement.preset` 与所有显式 `clip.preset`，成功条件是每个片段的有效输出均为 1080×1920；复合历史保存每个片段原值及“显式设置／继承根画幅”的状态，撤销与重做后可分别按原画幅和 E 画幅真实导出。
- 任一步校验或写入失败，整次零写入；刷新后重试仍以当前 revision 重新预检。
- 服务端在模板保存、预览和正式导出边界均校验实际输出为 1080×1920。

### 10.1 撤销启用与主动切回不是同一操作

- `enable_douyin_packaging` 必须生成复合 before/after 快照，包含完整包装、每个受影响 variant 的原／新画幅、E 随机值和旧布局资源身份；批量快照额外包含 `preset`。
- **撤销启用**：一次恢复原模板和各成片各自原画幅，旧 Resolution 只在原画幅和原 inputHash 仍匹配时恢复 resolved；重做恢复同一份 E 与 9:16，不重抽、不重新生成。
- **主动从 E 选回 A–D**：保留当前 9:16，恢复旧模板、贴纸和手动内容，但旧 Resolution 必须标记 stale 并按 9:16 重新求解和验证；不得把其他画幅的冻结几何冒充可导出结果。只有撤销启用 E 才恢复各成片原画幅。
- 撤销、重做和主动切回都执行对应 revision/CAS；存在更新编辑时拒绝覆盖，不用旧快照静默回滚用户后续工作。
- 批量每条历史在命令成功时记录 `outputVersionId + expectedEditRevision`，恢复事务同时校验两者；不得用刷新后当前视图的 revision 给旧历史背书。撤销成功后以返回的新 revision 作为重做条件，V1 换到同修订号 V2、另一窗口修改 V1 后刷新等场景均须零写入。

## 11. 失败与恢复

- 字体、LOGO、括号资源、箭头帧或 manifest 缺失：相关预览显示可恢复错误，正式导出 fail closed。
- 单条基础渲染得到的裸封面只留在任务临时目录。完整 E 配置、冻结证据和资源身份必须随首次快照传入包装子任务；首次正式发布和素材登记的 JPG 必须已通过 E 封面校验。包装失败或进程重启不得留下已登记裸封面，重试继续使用原快照。
- 包装待完成时，任务详情、直接视频下载与直接封面下载均返回“E 产物未就绪”，不得回退内部裸 MP4 或 JPG；包装成功后同一下载入口返回同一次通过校验的 E 视频与封面。失败但用户尚未选择后续操作时，两条下载路径同样不可用。
- E 的视频与封面必须作为一对正式产物发布，封面生成、校验或发布失败不得降级为素封面。优先复用现有成对发布、预留和失败清理设施，不重构全站发布系统。
- “跳过包装、发布原片”只能由用户在包装失败后显式触发，任务标记 `skipped`，按无 E 生产码登记原片与封面；不得把它当作自动失败降级。跳过成功后下载返回该次原片发布结果。
- 重试与跳过必须在任何文件副作用前，通过同一个原子状态转换取得失败任务执行权：重试仅允许 `failed → queued`，跳过仅允许 `failed → publishing_original`，二者只能一方成功。跳过成功后重复请求返回第一次的结果，不重复发布或登记；`publishing_original` 中断后按原快照与预留身份恢复或回滚。
- 取得跳过执行权后先生成任务级 `reservationId`，预留函数用 `wx` 创建包含 `reservationId + jobId + 实际目标路径` 的锁元数据；成功取得锁后才持久化实际 MP4/JPG 发布计划并复制文件。争用失败方继续下一个候选名，不得覆盖或删除他人锁。
- 恢复时同时校验 reservationId、jobId、锁内目标与数据库计划；若锁已创建而数据库计划尚未写入，则根据 reservationId 和锁元数据重建计划。只有锁归属匹配时才允许清理；`publishing_original` 纳入前端进行中轮询，完成前两路下载均未就绪。
- 文件已落盘但数据库未登记、数据库已登记但文件缺失等中断窗口必须按原快照与内容指纹恢复，不重复命名、不缺件、不冒充成功。E 的恢复就绪判断必须使用 SHA-256 等内容身份，同字节但内容错误的 JPG 不得通过。
- AI 失败：不影响已有卖点、LOGO、箭头和手动编辑。
- 封面产品名称或产品卖点为空、仍为占位文字时，明确标为必填并禁止正式导出；不得从口播正文猜测补齐。单条入队、批量导出编排和 worker 都直接校验 `douyin.cover`；旧 `allowPackagingPlaceholder` 对 E 无效，旧字段为空不得误拦合法 E，旧字段完整也不得放行非法 E。
- 候选 CAS 失败：保留未提交候选供重试，不覆盖新修订。
- 手动保存的样式、位置和时间始终优先于后续自动重放。
- 关闭包装保留全部抖音配置，重新开启后恢复。
- 旧四套模板与 classic 不读取 `douyin` 配置，旧任务不自动升级。

## 12. 测试与验收

### 12.1 领域与资源

- 配置清洗、未知版本拒绝、runs 合并、色板、1.35 倍映射。
- 文案／样式／位置／时间独立编辑标记。
- AI 时间锚定、证据校验、候选 CAS 与降级；有效真实锚点在倍速下正确换算，无真实对齐、仅估算字幕、来源句剪掉或静音时不生成估算时间。
- “靠背高 61cm，坐深 50cm”不得通过“坐深 61cm”；属性无法可靠确认的改写只提示。
- 长句拆成两条显示字幕时，按字数推算的第二条起点不能作为真实锚点；真实与降级词时间混合时仅可信句段生成，历史快照来源不明则跳过。
- 重新生成的 `originPointId/sourceCueIds` 对应、歧义零覆盖、手改 runs 保护。
- 同组两条 variants 只从共同可听且共同时间区间生成；AI 等待期间再剪任一 variant 音轨，旧候选零写入。
- 保存成功后改为 1.5 倍速或删除来源句，自动卖点 stale、显式重算、手调转 manual、删除恢复和导出阻断；只改封面不触发 stale。
- 单条已入队后改音轨仍可按冻结快照完成；批量合同变化后旧结果不得提交为当前候选或正式发布。
- 保存 A–D 改造前哈希基线；历史输入与携带休眠 E 数据的输入沿用旧键。启用 E 后只改正文更新完整键、沿用封面键，改封面文字同时更新两键。
- 只读小样使用 `readonly + fileMustExist` 连接并显式注入供应商配置，成功与失败路径均不经过 `getDb()`／补种且项目库零写入。
- 片内批量选择、跨 runs 全文偏移、按卖点随机配色、合并后继续放大原选区、一次撤销重做；`61cm` 等数字单位词块刷新后边界一致，词内划词正常。
- 箭头自动／手动颜色、无卖点随机固定、开始时间边界。
- GIF 帧映射、透明包围框、锚点和 manifest 哈希。

### 12.2 浏览器

- 单条与批量的封面文案、AI 生成、清单直编、划词、批量选择、放大和拖动。
- 应用高亮后继续一键放大，选择状态不丢；空清单手动新增第一条写入 `douyin.points`、来源为 manual、刷新可见、一次撤销回到空清单。
- 撤销重做、刷新、切换成片不重新生成或重抽。
- 无卖点时仍有尾帧箭头，能够预览和导出。
- 编辑卖点不重建底片；在正文中段实际操作时同时观测播放头、封面图层、包装 iframe 和可见画面，不以组件 key 或 E2E 通过替代闪动验收。
- 非 9:16 的取消、原子启用成功、revision 冲突零写入和刷新重试；单条多 variants 不出现部分 9:16。
- 启用→撤销→重做恢复原画幅和随机值；主动选回 A 且保留 9:16 时恢复内容、重新验证布局，并真实导出恢复后的 A。
- 分别从只有根画幅、根与片段均有画幅启用 E，实际导出 1080×1920，撤销后按原画幅渲染，重做后同一 E 再次导出。
- V1 换成碰巧同 revision 的 V2、另一窗口修改 V1 后刷新再撤销，均零写入；正常连续撤销重做使用返回的新 revision。
- 眼睛停在 3:4 A、选中 9:16 E 打开封面抽屉时，编辑器使用 E 的画幅并保存到 E；切到包装页签后画布按既有优先级切到 E，刷新后位置与导出一致。
- A 同时向 B 与 E 复制贴纸时整批拒绝，B 的贴纸和审核态不变。
- E 预览 GET 零供应商调用、零数据库写入；撤销启用并恢复原画幅后旧贴纸和 Resolution 可恢复，主动切回新画幅时重新验证。
- 旧标题已开启、批量回退到已合成 JPG、正文帧连续改色时均无重影，样式即时生效且播放头稳定。
- 输入最后一个字后立即切 B 或审核 A，先 flush A；保存失败不推进，B 保持原值，审核对应对用户可见修订。
- “浅封面＋深尾帧”和“深封面＋浅尾帧”分别选择合适 LOGO 版本，预览、JPG 与 MP4 一致。

### 12.3 封面与真实导出

- 单条正式封面、批量完整渲染封面、批量独立封面任务三者使用同一底图、裁切、资源与配置时覆盖层像素一致。
- 连续修改两次封面并让第一次任务迟到返回，工作台与正式发布只采用第二次结果；只改正文词块或尾帧不改变独立封面合同。
- P2 先用一张封面、一条卖点和一种箭头完成冻结副本 seek／渲染试通，再执行完整矩阵。
- 首帧无旧标题重影，20 帧片头无正文卖点或箭头。
- 三种高亮色、白色放大、多行主卖点、可选小字、无卖点成片均完成真实 1080×1920 MP4＋JPG 导出。
- 尾帧箭头位置、动画帧和颜色与预览一致，视频总时长不增加；裁剪后正文不足 60 帧时按实际总帧数核对第 19／20 帧和最后一个可见帧，中间 seek 后相位一致。
- 单条已排队任务读取冻结配置，后续编辑不影响旧任务；批量后续编辑导致合同变化时，旧结果按 runner CAS 被拒绝。
- 包装运行中、失败未处理、包装成功、显式跳过成功四种状态下，父任务详情与直接视频／封面请求均只返回对应状态的正式产物或“未就绪”，绝不回退内部底片。
- 两个窗口同时重试与跳过时只有一方执行；跳过成功后响应丢失再提交，返回第一次结果且文件与登记不重复。
- 分别在“正式 MP4 已写入、JPG 尚未发布”和“两文件已落盘、数据库尚未登记”中断并重启，重试后文件、任务状态与素材登记一致，无重复或缺件。
- 显式跳过包装后任务为 skipped、产物为无 E 生产码的原片与封面；封面发布失败不得留下包装视频＋素封面的组合。
- 预先放入同名历史成片迫使改名，分别在刚预留、仅写完 MP4、两文件完成但数据库未登记时中断；重启后原同名成片完好，本次只发布并登记一对文件，预留清理且另一窗口持续显示发布进度。
- 两个不同失败任务同时发布同基础名原片，分别在一方取得预留前后中断；重启后各自得到正确文件对，不覆盖他人文件、不删他人锁，重发幂等返回各自首次结果。
- 放入同字节数但内容不同的错误 JPG 后重试，错误文件不得被登记或呈现为成功的 E 封面。

## 13. 实施边界

本需求允许新增模板、共享模块、构建脚本、测试和必要 API，但不新增数据库表，不改变现有存储所有权，不复制一套 React 专用导出动画，不修改 classic 冻结域。

先在只读小样上验证 AI 文案与高亮质量，再接入正式生成命令；先完成字体和安全区标定，再开展完整 UI 与导出联调。
