# 批量混剪与桌面化 V1 产品需求文档（PRD）

- 日期：2026-07-31
- 状态：产品评审稿
- 所属产品：Creative Studio（产品素材工作台）
- 所属位置：第五步「智能混剪」
- 本阶段目标：先确认产品范围和用户流程，再进入技术方案与开发计划
- 最新补充：数量与素材构成由用户决定；默认全速；公司供应商经本地 LiteLLM 且故障隔离；安装包在核心稳定后再做

## 文档效力与边界

本 PRD 是现有「单条精准混剪」能力的扩展，不是推翻重做。

- 现有「单条精准混剪」继续保留，继续遵守原有分镜组和素材隔离规则。
- 新增「批量生产」模式，负责多素材、多文案、多条成片的统一生产。
- 项目素材库只会把用户明确选择的素材交给当前批次，不会偷偷跨分镜组、跨批次自动取材。
- 当本文与旧版混剪 PRD 在“批量生产、项目素材库、桌面交付方式”上发生冲突时，以本文为准。
- 旧版 PRD 中与单条精准混剪、字幕、封面、背景音乐、成片渲染等有关且未被本文修改的规则继续有效。

## Problem Statement（要解决的问题）

Creative Studio 已经能够完成从 AI 素材生成到单条视频混剪的流程，但未来真实使用场景会明显扩大：用户可能一次导入几十条手机或相机拍摄的视频，再准备多份文案，要求系统连续生成十几条甚至几十条不同成片。

如果继续只在现有单条流程上不断叠加按钮，会出现四类问题。

### 1. 单条流程无法承载真实批量生产

用户现在需要逐条处理文案、逐条挑素材、逐条等待导出。即使界面上增加一个“生成多条”的数字输入框，也不等于真正的批量混剪，因为不同文案、不同份数、素材复用平衡、成片差异和失败重试仍然没有统一管理。

### 2. 大量实拍素材需要更可靠的本地文件能力

几十条手机 4K 或相机素材可能占用几十 GB，不能要求全部上传进浏览器，也不适合全部复制一份到项目目录。用户还会遇到移动硬盘断开、文件夹改名、素材迁移、预览卡顿、相机 Log 素材需要 LUT 等问题。

浏览器界面本身不是主要性能瓶颈，真正消耗资源的是视频解码、分析、转码和 FFmpeg 渲染；但普通浏览器无法提供足够自然的文件夹选择、原文件引用、后台常驻、系统生命周期和桌面交互。因此产品需要桌面应用形态，同时继续复用现有本地后端和网页界面。

### 3. 长任务如果没有真实状态，用户会以为程序卡死

批量分析、配音、字幕对齐和导出可能持续很久。用户不应该先阅读一张复杂的预估确认表，也不能只看到一个一直旋转的加载图标。系统需要点击开始后立即自检并开跑，持续显示当前正在做什么、已经完成多少、哪一条失败以及还能否继续。

### 4. 继续堆叠现有大组件会进一步增加维护风险

现有混剪功能已经包含工作区、素材分析、时间线、字幕、封面、背景音乐、渲染任务等多类职责。如果把项目素材库、批量分配、桌面文件能力和持久化任务队列继续塞进同一层，后续任何改动都会更难验证。

本次产品设计必须同时满足两个目标：让普通用户觉得“设置好默认值后点开始即可”，也让工程结构能够分阶段迁移、持续验证，而不是一次性重写。

## Solution（产品方案）

### 1. 产品形态

Creative Studio 保持一个产品、一个项目体系和同一套本地数据，最终提供真正的 macOS 与 Windows 桌面应用。批量核心与供应商链路先在现有本地开发运行形态中做稳，安装包和 Electron 封装放到最后交付阶段。

桌面应用采用“薄桌面壳”方式：桌面层只负责应用窗口、原生文件和文件夹选择、应用启动与退出、后台任务提醒等系统能力；现有 React/Next 界面、本地 Node 服务、SQLite 数据和 FFmpeg 处理链继续复用。

用户不再需要手动打开 Chrome 或 Safari，但看到的仍是熟悉的 Creative Studio 界面。

### 2. 智能混剪的两个模式

进入第五步「智能混剪」后，用户先看到两个清晰入口。

#### 单条精准混剪

适合对一条视频进行细致调整。保留现有工作流、分镜组隔离、时间线编辑、字幕、封面、背景音乐和单条导出能力。

#### 批量生产

适合一次导入或选择多条素材、准备多份文案，并生成多条不同成片。它拥有独立的批次状态和批量界面，但复用已经稳定的分析、配音、字幕、封面、背景音乐和 FFmpeg 渲染能力。

### 3. 批量生产五阶段

批量生产采用五个阶段，界面只突出用户当下需要处理的内容。

1. **准备素材**：从项目素材库选择已有素材，或导入、链接新素材；按需启用代理文件或 LUT。
2. **分析素材**：系统识别时长、画面方向、可用区间等信息；素材分析可以在用户整理文案时后台进行。
3. **准备文案**：智能混剪自动载入项目上游已经保存的脚本文案和标题；用户只需勾选要使用的文案并设置生成条数。批量粘贴和手动新增只作为外部文案的补充入口。
4. **联合分配与卡片检查**：系统结合所有文案统一分配素材，尽量降低重复；用户通过成片卡片快速检查，必要时重分配某一条。
5. **批量导出**：系统按用户选择的性能模式和硬安全上限排队生成，持续显示总进度、当前阶段和单条进度，完成后统一进入批次文件夹和项目产物。

素材分析与文案准备不必严格串行。用户可以一边输入文案，一边等待素材分析完成。

### 4. 用户的最小操作

用户只需要完成四类决定：

1. 选择本批次使用哪些素材。
2. 从自动同步的模块 4 文案中勾选本批次要使用的内容，并设置每份生成几条。
3. 设置一套批次默认值。
4. 点击开始，并在卡片结果中处理少量异常。

批次默认值包括：画面比例与清晰度、声音与语速、字幕样式、封面样式、背景音乐池与音量、目标时长。默认值对整个批次生效，用户不需要逐份文案重复配置。

智能混剪打开时自动同步项目脚本文案、普通标题和结构化封面标题，不要求用户再次复制粘贴。当前正式工作台中，这些数据由第 3 步「脚本生成」保存；第 4 步「视频生成」保存成功视频，两者都按分镜组进入智能混剪。封面标题优先使用项目脚本已有的结构化标题；只有外部粘贴或手工输入且没有标题的文案才由系统自动提炼。同一份文案生成的多个版本使用相同标题文字，但尽量选择不同的封面底图。

批次尚未开始时，项目脚本更新可以同步到待生产列表；批次开始后保存独立快照，不会被上游后续修改静默覆盖。若上游出现新版本，界面提示用户选择是否更新本批次。

### 5. 即刻开始、后台自检

用户点击“开始批量生产”后，系统立即进入任务页并开始后台自检，不再额外弹出一张要求用户确认的复杂预估表。

只有以下问题会阻止任务继续：

- 必需的原始素材已经离线且无法找到。
- 所需 AI 或语音供应商尚未配置。
- 磁盘空间不足以安全完成任务。
- 当前选择中没有任何可用素材。
- 没有启用任何有效文案。

不会阻止任务的提醒，例如部分素材过短、相似度可能偏高、代理未生成、某些分析结果可信度较低，会以轻量提示显示。预计耗时、预计空间、费用、重试记录和诊断信息统一放入可展开的「任务详情」。

## 产品原则与统一术语

### 产品原则

1. **默认简单**：普通用户设置一次批次默认值即可，不要求理解并发、编码器或代理格式。
2. **过程透明**：不伪造精确百分比；能计算的显示百分比，不能计算的显示真实阶段和完成数量。
3. **原片安全**：任何分析、代理、LUT、裁剪和导出都不能修改用户原始文件。
4. **失败可继续**：一条失败不应让整个批次报废；已经完成的结果必须保留。
5. **结果有差异**：批量生成不是重复复制同一时间线。
6. **逐步迁移**：每完成一层都要保证单条精准混剪仍可使用。
7. **跨平台设计**：从第一天同时考虑 macOS 和 Windows，不把 Windows 留到最后补救。

### 统一术语

- **项目素材库**：当前项目可复用的全部视频素材，包括 AI 生成素材、复制进项目的素材和原位置链接素材。
- **托管素材**：已复制进项目数据目录、由 Creative Studio 管理的文件。
- **链接素材**：仍保留在用户原文件夹或移动硬盘中，项目只保存可靠引用的文件。
- **批次**：一次批量生产的完整工作单，包含素材快照、文案快照、默认设置、分配结果、任务状态和成片结果。
- **成片卡片**：批量结果的主要检查单位，一张卡代表一条计划中、生成中或已完成的视频。
- **代理文件**：只为流畅预览而生成的低负担副本，可以删除和重建，最终导出不使用它。
- **LUT**：用户主动选择的色彩转换文件，用于 Log 等素材的预览与最终输出。
- **任务详情**：承载预计耗时、空间、费用、技术诊断、重试历史等非主要信息的折叠区域。

## User Stories（用户故事）

### A. 进入与模式选择

1. 作为已有用户，我希望继续使用原来的单条精准混剪，不因批量功能升级而改变已有项目的操作方式。
2. 作为需要大量出片的用户，我希望在智能混剪中直接选择「批量生产」，不必把单条编辑器当成批量工具使用。
3. 作为不懂技术的用户，我希望两个模式的适用场景写得清楚，能一眼知道应该选哪一个。
4. 作为老项目用户，我希望直接在旧项目中创建新批次，不必重新导入全部内容。

### B. 项目素材库

5. 作为用户，我希望 AI 生成的视频自动出现在项目素材库中，并标明来源。
6. 作为用户，我希望把体积较小或需要长期保存的素材复制进项目管理。
7. 作为用户，我希望几十 GB 的手机或相机素材可以保留在原文件夹，只在项目中建立链接。
8. 作为用户，我希望同一份素材只分析一次，后续多个批次可以直接复用分析结果。
9. 作为用户，我希望素材库同时容纳 AI 素材、手机实拍和相机实拍，并能按来源筛选。
10. 作为用户，我希望当前批次只使用我明确勾选的素材，不会自动混入其他分镜组或其他批次的素材。
11. 作为用户，我希望把素材从当前批次移除时，不会删除项目素材库里的文件。
12. 作为用户，我希望某个批次对素材的裁剪、排除和锁定只影响该批次，不改变其他批次。
13. 作为用户，我希望能看到素材是否已经分析、是否在线、是否有代理、是否启用了 LUT。

### C. 原文件引用与重新定位

14. 作为使用移动硬盘的用户，我希望硬盘断开后项目仍然存在，而不是素材和剪辑记录一起消失。
15. 作为用户，我希望离线素材有明确标识，并知道它会影响预览还是最终导出。
16. 作为用户，我希望重新接入硬盘或移动文件夹后，可以选择一个新文件夹批量找回素材。
17. 作为用户，我希望系统结合文件特征核对素材身份，而不是仅凭同名文件静默替换。
18. 作为用户，我希望已有的代理或缓存仍可用于临时查看，但最终导出前必须确认原文件在线。
19. 作为用户，我希望系统在无法确认新旧文件相同时停下来提醒我，避免导出错误画面。

### D. 代理文件

20. 作为主要使用手机 4K 素材的用户，我希望系统默认直接播放原片，不要一导入就耗时生成代理。
21. 作为遇到预览卡顿的用户，我希望可以对当前素材、选中素材或全部素材一键生成代理。
22. 作为用户，我希望代理任务显示进度，并支持暂停、继续和失败重试。
23. 作为用户，我希望可以在原片预览和代理预览之间切换，以便判断画质与性能。
24. 作为用户，我希望所有代理都集中保存在应用统一的代理缓存文件夹中，并在前端看到代理占用空间，能够清理选中素材、当前项目或全部代理。
25. 作为用户，我希望清理代理后预览自动回退到原片，最终导出始终读取原片，并且原始素材、剪辑记录和正式成片完全不受影响。

### E. LUT 色彩转换

26. 作为使用普通手机视频的用户，我希望 LUT 默认关闭，素材不会被自动改色。
27. 作为拍摄 Log 素材的用户，我希望可以导入并选择 LUT，首版至少支持常用的 `.cube` 文件。
28. 作为用户，我希望 LUT 文件被安全保存到项目中，原始 LUT 文件移动后项目仍可使用。
29. 作为用户，我希望可以把 LUT 应用到当前素材、选中素材或全部素材。
30. 作为用户，我希望预览和最终导出使用同一套 LUT，避免“预览一种颜色、成片另一种颜色”。
31. 作为用户，我希望更换 LUT 后，系统明确提示并自动处理受影响的代理预览。
32. 作为用户，我希望无论是否使用 LUT，原始视频都不会被修改。

### F. 多文案和生成份数

33. 作为用户，我希望进入智能混剪后自动看到项目中已经保存的全部可用脚本文案及标题，不需要再次复制粘贴。
34. 作为用户，我希望重复进入或刷新智能混剪时，同一个项目脚本不会被重复导入。
35. 作为用户，我希望只需启用或停用自动同步的文案，并分别填写生成份数，例如文案 A 生成 3 条、文案 B 生成 5 条。
36. 作为用户，我希望项目脚本在批次开始前发生更新时，待生产列表能够同步；批次开始后则保持已确认快照，不被上游修改静默覆盖。
37. 作为用户，我希望外部文案仍可通过批量粘贴或手动新增补充，但这不是使用项目内文案的必经步骤。
38. 作为用户，我希望批次中修改过的外部文案只有在我明确选择“保存为项目文案”后才写回项目。
39. 作为用户，我希望所有启用文案共享当前批次选中的素材池，不必在开始前逐份文案手工分素材。

### G. 批次默认值与自动处理

40. 作为用户，我希望一次设置整个批次的比例、清晰度、声音、语速、字幕、封面、背景音乐和目标时长。
41. 作为用户，我希望这些默认值自动应用到所有文案，而不是逐条重复填写。
42. 作为用户，我希望项目已有结构化标题时直接用于对应视频封面。
43. 作为批量粘贴文案的用户，我希望系统自动从每份文案提取封面标题。
44. 作为用户，我希望同一文案的多个版本保持标题文字一致，但封面底图尽量不同。
45. 作为用户，我希望生成完成后仍能手动修改某条视频，但不需要在生成前逐条设置。

### H. 联合分配与差异性

46. 作为用户，我希望系统阅读所有文案后再统一分配素材，让画面与文案尽量匹配。
47. 作为用户，我希望同一批次中的不同成片不要使用完全相同的时间线。
48. 作为用户，我希望不同成片尽量拥有不同的开场镜头、素材顺序和封面底图。
49. 作为用户，我希望素材池足够时，不同成片使用不同背景音乐。
50. 作为用户，我希望同一个长素材被多次使用时尽量截取不同区间。
51. 作为用户，我希望系统平衡素材使用次数，避免少数素材被反复使用而其他素材闲置。
52. 作为用户，我希望素材不足时系统仍能继续生产，但明确告诉我哪些成片相似度可能偏高。
53. 作为用户，我希望可以对某一条成片执行“重新分配”，不必重做整个批次。
54. 作为用户，我希望可以锁定满意的片段、替换不合适的片段，或排除某条素材后再重分配。

### I. 开始、进度与资源控制

55. 作为用户，我希望点击开始后任务立即运行，不再被一张复杂的确认清单拦住。
56. 作为用户，我希望系统先在后台检查素材、供应商、磁盘和任务条件，并直接告诉我当前正在检查什么。
57. 作为用户，我希望主界面看到批次总进度、当前阶段和每条成片进度。
58. 作为用户，我希望视频导出进度根据真实已处理时长计算，而不是显示虚假进度。
59. 作为用户，我希望 AI 分析无法计算精确百分比时，界面显示真实阶段和完成数量。
60. 作为用户，我希望系统持续观察电脑 CPU、内存、磁盘和实际响应；普通压力升高时提醒我选择，而不是擅自降速。
61. 作为用户，我希望默认全速处理，出现压力提醒后可以选择继续全速或降低速度，并能随时重新切换。
62. 作为有经验的用户，我希望高级设置里可以手动限制并发，但普通用户不需要看到它。
63. 作为用户，我希望磁盘确定不足或内存进入危险状态时，系统先保护性暂停新的重任务并告诉我如何继续，避免任务损坏。
64. 作为用户，我希望可以开始、暂停、继续和停止整个批次，也可以单独重试失败条目。
65. 作为用户，我希望应用意外退出或电脑重启后，重新打开仍能恢复批次，已完成内容不会丢失。
66. 作为用户，我希望费用、空间、耗时估算、重试日志和技术诊断放在任务详情里，不干扰主要操作。

### J. 卡片检查与局部编辑

67. 作为用户，我希望每条成片以卡片显示封面、文案名、版本、时长、状态和问题。
68. 作为用户，我希望按状态筛选卡片，例如仅查看失败、待检查或已完成的成片。
69. 作为用户，我希望在卡片上直接播放、选择、确认、重试或重新分配。
70. 作为用户，我希望一键选中所有可导出的成片，不必逐条进入编辑器确认。
71. 作为用户，我希望只有在需要细调时才打开详细编辑器，调整时间线、字幕、封面、背景音乐、替换或裁剪片段。
72. 作为用户，我希望单条成片的修改不会意外改变同批次其他成片。

### K. 导出、历史与清理

73. 作为用户，我希望一个批次导出到一个独立文件夹，方便整体交付。
74. 作为用户，我希望文件名包含项目的产品标识（productCode／型号）、日期、文案身份和版本，能够直接看懂来源。
75. 作为用户，我希望视频和对应封面使用相同主文件名，便于平台上传。
76. 作为用户，我希望重新导出时不覆盖旧文件，并能在项目中看到所有正式产物。
77. 作为用户，我希望导出完成后可以一键打开批次文件夹。
78. 作为用户，我希望批次自动保存，重新进入时回到上次阶段并显示各状态数量。
79. 作为用户，我希望删除批次时绝不删除手机、相机或移动硬盘中的原始文件。
80. 作为用户，我希望删除批次时默认保留已经导出的正式成片，只清理临时文件、代理和中间产物。
81. 作为用户，我希望如果确实要删除正式成片，系统必须单独说明并再次确认。

### L. 桌面应用与跨平台

82. 作为用户，我希望像普通软件一样从桌面或开始菜单打开 Creative Studio，不需要先启动命令行和浏览器。
83. 作为用户，我希望选择文件和文件夹时使用系统原生窗口，并能自然访问移动硬盘。
84. 作为用户，我希望关闭窗口、退出应用和后台任务之间的关系清晰，不会误关窗口就损坏任务。
85. 作为 macOS 用户，我希望首个正式验证版本优先在 Mac 上稳定运行。
86. 作为 Windows 用户，我希望每个阶段都同步验证 Windows 路径与文件引用，核心稳定后再统一验证安装包，不必等全部做完后才发现基础不兼容。
87. 作为已有用户，我希望桌面版继续使用原来的项目、数据库和产物目录，不需要手工迁移。

### M. 公司供应商运行环境

88. 作为使用公司模型的用户，我希望一个启动入口自动准备 Creative Studio、LiteLLM 和必要的媒体传输，不需要分别维护多个命令窗口。
89. 作为用户，我希望不在公司内网或公司链路启动失败时，软件仍能正常打开，并继续使用本地功能与已经配置的外部供应商。
90. 作为用户，我希望界面明确显示“公司供应商当前不可用”及真实原因，而不是把整个批次或软件笼统显示为失败。
91. 作为用户，我希望只有选择公司供应商的任务才经过公司链路，外部供应商仍按各自 adapter 直接调用。

## Implementation Decisions（实现决策）

本节只锁定产品要求对应的技术边界，不展开具体文件、类名和编码步骤；详细技术方案在本 PRD 确认后另行编写。

### 1. 采用薄 Electron 桌面壳

- Electron 只负责桌面窗口、原生文件选择、应用生命周期、后台状态和少量安全桥接。
- 现有 React/Next 界面、本地 Node 服务、SQLite 和 FFmpeg 继续作为核心。
- 不迁移到参考项目的 Python 后端，也不复制其界面技术栈。
- 桌面渲染层只能访问经过明确授权的最小原生能力，业务逻辑不放进 Electron 主进程。
- 首先验证 macOS，但架构、路径模型、任务恢复和安装方式必须从一开始兼容 Windows。

### 2. 项目素材库采用统一素材引用

项目素材库需要用统一概念描述三种素材来源：

- Creative Studio 生成的素材。
- 复制进项目的托管素材。
- 保留在原位置的链接素材。

上层批量功能只面向统一素材引用，不应自行判断文件路径格式。链接素材保存可重新定位的信息和可靠文件特征；离线时保留项目记录，重新定位时核验身份。

项目素材库是跨批次复用层，但不是无边界公共素材池。每个批次必须保存“用户当时明确选择的素材快照”。

### 3. 批次是独立、持久化的生产聚合

批次位于单条成片、渲染任务之上，负责保存：

- 选中素材及其当时的分析和处理设置。
- 文案快照、启用状态和每份生成条数。
- 批次默认设置。
- 联合分配结果与差异性报告。
- 每条成片的状态、重试、局部修改和正式产物。
- 批次总状态、进度、暂停与恢复信息。

批次不能借用或覆盖现有单条混剪的临时编辑状态，也不能让同一分镜组下的不同历史版本互相污染。

### 4. 引入可恢复的持久化任务调度

- 批量分析、代理生成、AI 调用、配音、字幕对齐和成片渲染都进入统一可追踪的任务模型。
- 任务状态至少覆盖等待、运行、暂停、完成、失败、停止和可重试。
- 应用启动时能够识别上次未完成任务，并安全恢复到等待或暂停状态。
- 已完成任务和正式产物不因其他条目失败而回滚。
- 停止任务需要真正停止后端处理和子进程，而不只是隐藏前端进度。

### 5. 资源控制采用“持续监测 + 用户选择”

资源监测的依据包括：

- CPU 核心数与当前压力。
- 可用内存。
- 数据盘与输出盘的剩余空间和压力。
- 素材的编码、分辨率、位深、帧率和总时长。
- 前两到三个实际任务的处理速度和资源变化。
- 外部供应商允许的并发与速率限制。

系统默认在硬件安全上限和供应商限制内全速处理。普通高负载只提示用户选择“继续全速”或“降低速度”；用户没有操作时保持全速，不静默改变模式。选择降低速度后，只减少后续领取和并发，用户可以随时切回全速。

磁盘确定不足或系统内存进入危险状态属于安全红线：停止领取新的重任务并保存可恢复状态。具体提醒阈值和安全红线必须在目标 macOS／Windows 真机上校准，不能使用一个跨平台固定 CPU 百分比。

### 6. 进度必须来自真实可观测状态

- 批次总进度由各阶段和条目真实状态汇总。
- 阶段进度显示当前步骤和完成数量。
- 单条进度显示该条正在分析、配音、对齐、渲染、校验或失败。
- FFmpeg 渲染按已处理媒体时间与总时长计算。
- 外部 AI 调用若无法获得连续进度，只显示请求、等待、返回、处理结果等真实阶段，不生成虚假百分比。

### 7. 联合分配是批量模式的核心能力

分配器以本批次全部启用文案、生成份数、选中素材和默认设置为一次输入，输出多条独立成片计划。

必须同时考虑：

- 文案与画面语义匹配。
- 每条成片目标时长。
- 素材可用区间和最短片段约束。
- 不同成片的开场、顺序、区间、封面和音乐差异。
- 全批次素材使用次数平衡。
- 已锁定、已排除或用户手工替换的内容。

素材不足时返回可解释的相似度警告，不把任务直接判为失败。重新分配单条成片时，只重新计算必要范围并尊重用户已经锁定的内容。

### 8. 项目脚本自动同步到智能混剪

- 智能混剪以项目上游已经保存的可用脚本为项目内文案主来源，进入页面时自动读取正文、普通标题、结构化封面标题、分镜组归属和版本信息。
- 当前数据来源是第 3 步「脚本生成」保存的项目脚本；第 4 步「视频生成」提供按同一分镜组关联的成功视频。产品界面可以把二者呈现为连续流程，但技术实现不能把视频任务误当成脚本存储。
- 自动同步只是把脚本放进可选择列表；批量生产仍由用户明确启用哪些脚本，并设置每份生成条数。
- 同一个上游脚本以稳定身份去重，重复进入、刷新或同步不会产生副本。
- 单条精准混剪继续只读取当前分镜组脚本；批量生产可以列出项目内可用脚本，但不会因此改变单条模式的隔离规则。
- 批次开始前可以同步项目脚本的最新版本；批次开始后固定脚本与标题快照，后续上游更新只产生提示，由用户决定是否创建更新版本。
- 批量粘贴和手工新增继续保留，用于尚未保存为项目脚本的外部文案，而不是项目内脚本的必经步骤。

### 9. 代理文件是可重建缓存

- 默认不生成，用户遇到卡顿后主动启动。
- 支持当前、选中和全部三种范围。
- 代理状态与任务进度可见。
- 预览可以切换原片或代理。
- 最终渲染始终使用原片。
- 所有代理集中存放在应用数据根目录下的专用代理缓存文件夹中，不散落到原素材文件夹、项目产物文件夹或导出文件夹。
- 专用代理缓存文件夹内部按项目和素材身份隔离，避免同名文件冲突，同时仍可一次性整体清理。
- 项目素材库提供“清理代理”入口，支持清理选中素材或当前项目；存储管理提供清理全部代理的入口，并显示预计释放空间。
- 正在被任务使用的代理不能被直接删除；系统应要求先暂停相关任务，或跳过占用文件并明确提示。
- 删除后相关素材立即标记为“无代理”，预览自动回退到原片。
- 删除代理不影响原始素材、分析结果、剪辑计划、批次快照和正式成片，后续可以重新生成。

### 10. LUT 是显式、非破坏性处理

- 默认关闭，只有用户选择后才生效。
- V1 至少支持导入和选择 `.cube` LUT。
- 导入后保存项目托管副本，避免原 LUT 文件移动导致项目失效。
- LUT 绑定到素材在当前项目中的处理设置，并支持批量应用。
- 预览和最终渲染共用同一设置。
- 原素材永不改写。
- LUT 变化后，受影响的代理文件标记为过期并重建。

### 11. 封面标题自动继承文案

- 智能混剪打开时自动载入项目脚本文案、普通标题和结构化封面标题，不要求复制粘贴。
- 已有项目文案优先使用项目脚本保存的结构化标题。
- 粘贴或手工输入且没有标题的文案自动提取标题。
- 同一文案的所有版本保存相同标题快照。
- 每个版本独立选择封面底图，并尽量避免相同。
- 用户可以在生成后修改单条封面，但这不是开始批次前的必填操作。

项目脚本与智能混剪之间以稳定脚本身份去重。批次开始前允许同步上游更新；批次开始后使用独立快照，若检测到上游新版本只提示用户选择，不自动改写正在生产或已经完成的成片。

### 12. 批次产物与删除采用安全规则

- 每个批次拥有独立导出文件夹。
- 文件名包含项目产品标识（productCode／型号）、日期、文案身份和版本号。
- 视频与对应封面使用相同主文件名。
- 重复导出生成新版本，不覆盖已有文件。
- 正式结果同时登记为项目产物，并提供打开所在文件夹的入口。
- 删除批次时默认保留正式产物，只清理可重建的临时文件、代理和中间产物。
- 删除正式产物必须作为单独操作再次确认。
- 任何产物管理操作都不能修改或删除用户原始素材。

### 13. 兼容现有数据并采用追加式迁移

- 旧项目、旧素材、旧文案、单条混剪历史和已导出结果必须继续可用。
- 新批量功能继续使用同一数据根目录和项目身份。
- 新数据库结构通过追加迁移建立，不修改已经发布的迁移记录。
- 首次执行新结构迁移前自动备份数据库。
- 迁移失败时停止进入新功能，并保留可恢复的旧数据，不能带着半完成结构继续运行。

### 14. 分阶段迁移而非一次性重写

推荐顺序为：

1. 建立项目素材库和统一素材引用。
2. 建立可恢复任务调度与真实进度。
3. 实现多素材、多文案和联合分配。
4. 实现批量卡片工作区与批量导出。
5. 接回已有字幕、封面、背景音乐、配音、对齐和 FFmpeg 能力。
6. 做稳外部供应商旁路、公司 LiteLLM 运行环境和受控媒体传输，并完成真实媒体与经授权的真实供应商验收。
7. 核心稳定后加入薄 Electron 桌面壳、原生文件能力和一键 sidecar 管理。
8. 最后构建 macOS／Windows 候选安装包，以用户选择的真实规模完成跨平台验收和性能调整。

每一阶段都设置单条精准混剪回归门槛，未通过时不能继续扩大迁移范围。

### 15. 公司供应商作为可选运行环境

- 公司供应商只在公司内网可用，本地 LiteLLM 是连接公司模型中转站的必要桥接，不尝试绕过或移除。
- 一键启动可以统一看管 LiteLLM 与媒体传输 sidecar，但它们不是 Creative Studio 核心启动的硬依赖。
- 公司链路失败只把公司供应商标记为不可用；本地功能、项目数据和外部供应商继续可用。
- 批量任务只面向统一供应商能力和健康状态，不直接依赖 LiteLLM、Cloudflare 或腾讯云实现。
- 当前 Cloudflare 只作为开发期媒体传输 Adapter；正式方案不得暴露完整工作台端口，应只传输任务需要的媒体，并具备限时授权与清理能力。
- 腾讯云具体方案待公司侧约束确认后再锁定，不在信息不足时猜测实现。

## Testing Decisions（测试决策）

### 1. 最高价值端到端测试边界

最高价值的用户级测试先从真实本地批量项目开始，核心稳定后再用同一流程验收桌面候选包，覆盖：

> 选择项目素材 → 准备多份文案与份数 → 启动批次 → 查看真实进度 → 暂停或重启恢复 → 卡片检查 → 局部重分配 → 批量导出 → 在项目产物和文件夹中找到结果

该测试验证用户能否完成工作，不以内部函数是否被调用为成功标准。

### 2. 项目素材库测试边界

针对统一素材引用分别验证生成素材、托管素材和链接素材：

- 导入、复用、移除和批次选择。
- 外置盘断开后的离线状态。
- 文件夹重新定位和文件特征核验。
- 同名错误文件不得静默替换。
- 批次裁剪、排除和 LUT 设置不得污染其他批次。
- 删除批次不得删除原片。

### 3. 项目脚本同步测试边界

- 进入智能混剪后自动出现项目的可用脚本文案、普通标题和结构化封面标题。
- 脚本数据来自第 3 步保存的项目脚本，第 4 步成功视频仍按分镜组独立读取；测试不得混淆两种来源。
- 单条精准混剪只同步当前分镜组的可用脚本；批量生产按项目列出可用脚本，但仍由用户明确启用。
- 重复进入、刷新或再次同步不会产生重复文案。
- 批次开始前能够获取上游更新；开始后的批次快照不被上游修改静默覆盖。
- 上游出现新版本时能够提示并由用户选择是否更新。
- 外部粘贴和手工新增仍可用，但项目内脚本不需要经过复制粘贴。

### 4. 持久化任务调度测试边界

使用临时数据库和临时文件验证：

- 提交、领取、报告进度、暂停、继续、停止、失败、重试。
- 应用异常退出后的恢复。
- 已完成条目保持完成，未完成条目安全回到可继续状态。
- 停止后对应 FFmpeg 或其他子任务真正结束。
- 默认全速、用户选择降低速度和再次切回全速都真实改变后续并发，并且不会突破硬安全上限或供应商限制。
- 普通高负载只提醒；磁盘不足或内存危险会保护性暂停新的重任务，并保留可恢复状态。

### 5. 联合分配测试边界

使用固定素材分析结果和固定文案快照，验证输出计划可重复检查：

- 多文案和不同生成份数能得到正确成片数量。
- 不同成片不产生完全相同时间线。
- 开场、顺序、取材区间和素材使用次数达到设定的差异目标。
- 素材不足时继续输出，并附带相似度告警。
- 单条重新分配不改动已锁定条目。
- 重新分配前后的变化可以向用户解释。

### 6. 媒体处理测试边界

- 使用真实 FFmpeg 测试代理生成、原片导出、进度解析和停止。
- 使用正常手机 4K、常见相机编码、竖屏和横屏样例。
- 对 Log 样例验证 `.cube` LUT 在预览代理和最终导出中的一致性。
- 验证 LUT 和代理流程不修改原文件。
- 验证缺少原片时最终导出会被明确阻止。
- 验证所有代理只写入统一代理缓存目录，并按项目与素材身份避免冲突。
- 验证前端可以清理选中素材、当前项目和全部代理，并准确更新已释放空间和代理状态。
- 验证正在使用中的代理不会被误删，清理后预览回退原片且最终导出不受影响。

### 7. 桌面与跨平台测试边界

- 桌面壳与安装包测试属于最后交付门禁，不阻塞批量核心在现有本地运行形态中的分阶段开发与验证。
- macOS 验证应用启动、原生选择器、移动硬盘引用、退出与任务恢复、安装包运行。
- Windows 在每个完成阶段验证路径、盘符变化、文件夹选择、任务恢复和安装包运行。
- 桌面壳只暴露允许的最小能力，普通页面不能任意访问本机文件或执行命令。
- 应用升级后继续读取旧项目和同一数据目录。

### 8. 验收证据分级

测试报告必须明确区分以下证据，不得互相替代：

1. **纯逻辑测试**：证明数量、状态、分配和差异规则正确。
2. **数据库测试**：证明迁移、事务、幂等、暂停和崩溃恢复正确。
3. **本机真实媒体测试**：证明 FFmpeg、代理、LUT 和导出链路可用。
4. **macOS 安装包测试**：证明 Apple Silicon 正式交付形态能够安装、升级、运行和恢复。
5. **Windows 安装包测试**：证明 Windows x64 正式交付形态能够完成同等真实运行，不能由 Mac 或静态脚本替代。
6. **真实供应商测试**：只有逐次说明数据、供应商、请求／费用与持久影响并获得明确授权后，才调用外部 AI 或语音供应商并记录实际结果。
7. **用户验收**：由用户按真实工作方式检查操作是否简单、进度是否可信、电脑是否可用以及结果是否符合预期。

公司供应商验收还必须分别记录公司内网状态、LiteLLM 健康、公司中转站响应和媒体传输 Adapter；任何一层的 mock 成功都不能替代真实链路验收。公司链路不可用时，还要证明工作台与外部供应商没有被连带阻塞。

### 9. V1 可变规模真实场景验收

V1 不规定固定素材比例、脚本数量或目标成片数。每次验收由用户选择真实项目素材、脚本和每份生成数量，系统按合计 `N` 建立恰好 `N` 个成片计划；测试数字不得成为产品默认值或上限。

- macOS Apple Silicon 与 Windows x64 的候选安装包各连续完成三次代表性真实批量运行，并记录每次实际输入 manifest 与 `N`。
- 覆盖明显不同的用户选择规模，同时证明重试、恢复和重新分配不会改变 `N`。
- 至少包含一次链接素材重新定位、暂停与继续、应用重启恢复以及单条失败重试。
- 包含默认全速、压力提醒后的继续全速／降低速度，以及磁盘不足或内存危险的保护暂停。
- 包含按需代理和可选 LUT 验证。
- 最终产物按批次正确命名、无覆盖，并进入项目产物记录。
- 真实供应商只在逐次说明数据范围、目标服务、请求／费用和持久影响并取得用户明确许可后执行。

## V1 验收标准

### 功能完成

- 用户能在旧项目或新项目中进入批量生产。
- 用户能从项目素材库选择多条素材，并安全使用链接素材。
- 智能混剪能自动载入项目脚本文案和标题，用户无需再次复制粘贴，并能为每份设置不同生成条数。
- 系统能为共享素材池生成对应数量的不同成片计划。
- 用户能在卡片页处理失败、重新分配和批量导出。
- 代理默认关闭但可按范围生成；全部代理集中存放并可从前端按范围清理，最终导出只使用原片。
- LUT 默认关闭但可导入、选择、批量应用，并在预览和导出中一致。
- 封面标题自动来自对应文案，同文案各版本只更换底图。
- 批次可以暂停、继续、停止、重试和在应用重启后恢复。

### 安全与兼容完成

- 原始视频和原始 LUT 文件不被修改。
- 删除批次不删除原始素材，正式成片默认保留。
- 旧项目、旧单条混剪记录和旧产物可继续访问。
- 数据迁移前有备份，失败时不会破坏旧数据库。
- 单条精准混剪的核心流程通过回归验证。

### 体验完成

- 用户不需要理解并发或编码参数即可启动任务。
- 点击开始后立即看到后台自检和真实阶段。
- 主界面只显示必要进度，复杂信息收进任务详情。
- 单条失败不会让用户重新开始整个批次。
- 用户无需逐条打开详细编辑器即可导出所有合格成片。

## Out of Scope（V1 不做）

- 不用云端保存用户项目、素材或 API Key。
- 不建设多人协作、云端共享素材库或团队权限系统。
- 不自动上传成片到抖音、小红书、视频号等平台。
- 不自动替用户删除、移动或重命名原始素材。
- 不默认对全部素材生成代理。
- 不自动识别所有相机 Log 类型并替用户决定 LUT。
- 不把浏览器完全移除为开发与诊断方式，但正式用户入口以桌面应用为主。
- 不把当前 Cloudflare 全应用端口隧道作为正式媒体基础设施。
- 不重写现有全部混剪、字幕、封面、背景音乐和渲染能力。
- 不在 V1 同时并行渲染多条成片；先以单路稳定导出为默认。
- 不要求 V1 提供复杂专业调色界面；只提供 LUT 导入、选择、应用与关闭。
- 不承诺素材不足时仍能产生低相似度结果，只保证继续生产并清楚提示风险。
- 不在本 PRD 中锁定数据库表、接口字段、代码目录或每个阶段的开发工期。

## Further Notes（补充说明）

### 1. 为什么不是“把网页直接改成另一个项目”

现有 Creative Studio 已经拥有项目、脚本、视频分析、配音、字幕、封面、背景音乐、FFmpeg 渲染和本地安装包基础。参考项目证明了多素材、多文案、联合分配、卡片检查和批量导出这条产品路径是可行的，但它的后端和界面技术与当前项目不同。

正确方向是迁移能力和产品流程，不是复制参考项目代码，也不是把当前系统整体换掉。

### 2. 为什么桌面版仍然可以使用网页技术界面

桌面版不等于必须重写成原生界面。真正消耗资源的视频工作仍由本机 Node 和 FFmpeg 执行；Electron 负责把现有界面放进独立应用窗口，并补足浏览器不擅长的本地文件和应用生命周期能力。

### 3. 为什么手机 4K 不默认生成代理

大多数现代电脑可以直接预览常见手机 4K 素材。全部自动生成代理会浪费等待时间和磁盘空间。因此 V1 默认先播放原片，只有用户发现卡顿时才主动对所需范围生成代理。

### 4. 为什么 LUT 必须由用户主动开启

普通手机素材通常不需要 Log 色彩转换，系统也不能可靠替用户决定具体相机和拍摄配置应该使用哪一套 LUT。默认关闭能避免正常素材被错误改色；相机 Log 用户仍能明确导入和选择所需 LUT。

### 5. 本轮已经锁定、不再反复讨论的产品决定

- 同时支持多份文案、多个素材和每份不同生成条数。
- 保留单条精准混剪，新增独立批量生产模式。
- 建立项目素材库，但批次只使用用户明确选择的素材。
- 同时支持托管素材和原位置链接素材。
- 正式交付仍采用薄 Electron 桌面壳并复用现有核心，但安装包等核心与供应商链路稳定后再做。
- 公司供应商必须经过公司内网与本地 LiteLLM；一键联动但故障只影响公司供应商，外部供应商继续直连。
- 当前 Cloudflare 只是可替换的开发期媒体传输方式，腾讯云正式方案等待公司侧信息后再决定。
- 点击开始后后台自检并直接开跑，不设置繁琐确认页。
- 分析和导出都有真实进度，技术细节放入任务详情。
- 系统默认全速处理；普通高负载提醒用户选择继续全速或降低速度，只有磁盘不足或内存危险才保护性暂停。
- 批量结果以卡片为主，详细编辑器按需进入。
- 批量分配必须降低重复，素材不足时告警但不强制停止。
- 项目脚本文案和标题自动同步到智能混剪，复制粘贴只作为外部文案补充方式。
- 封面标题自动继承对应项目脚本，同文案版本只更换底图。
- 代理默认关闭，遇到卡顿后再按范围生成；全部代理集中存放，并可从前端清理。
- LUT 纳入 V1，默认关闭，由用户导入和选择后才启用。
- 兼容旧项目和旧混剪数据，按阶段迁移，不进行一次性重写。

### 6. 本 PRD 通过后的下一步

下一份文档应是技术实施方案，重点回答：

6. 各阶段如何以小步提交实施，并设置回归与验收门槛。
