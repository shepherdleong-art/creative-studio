# 一键成片封面换图与全景封面功能方案

**状态：** `ready-for-agent`

**日期：** 2026-11-26

## Problem Statement

在一键成片的「审片与导出」阶段，启用封面后系统当前固定复制正文第 1 帧作为片头 20 帧底图与包装取色来源，界面上也没有提供更换封面图片的入口。

在真实电商种草视频生产中，这种做法会带来三类高频问题：

1. **首帧普遍不适合做封面**：种草片开篇常是痛点引入、人物局部动作或产品局部特写（例如只露半截沙发或带遮挡的起手帧），而画面后半段往往才有完整工整的产品全景镜头，结果首帧封面拉低了整条成片的点击质感。
2. **无法复用项目已有实拍图或人工挑帧**：剪辑师在「素材与脚本」阶段本来就上传了清晰的产品图与场景图，或在审片播放时看到了非常合适的一帧，却无法像普通项目的单条精准混剪或批量生产那样手动挑选画面、切换原图并微调构图。
3. **极端成片缺全景且缺竖版好图**：部分成片从头到尾都是人物互动近景或局部功能特写，同时项目已有图片的构图又容易被上方花字标题压住产品主体，缺少按需生成一张构图留白合理的竖版产品全景封面的救场手段。

## Solution

为一键成片建立统一的封面底图管理能力，把「**自动提取全片全景帧**」「**手动挑选本片画面或项目图片并调构图**」「**按需使用 GPT Image 2.6 生成产品全景封面**」收口到同一套封面来源模型与编辑入口中：

1. **默认自动挑帧替代硬编码首帧**：原片切点识别完成并准备包装草稿时，系统从各镜头采样候选帧，交由视觉模型选出一张产品主体最完整、清晰、构图最接近全景的帧作为默认封面；若视觉服务不可用、触发内容过滤或全片无更佳画面，则静默回退到正文第 1 帧，不阻塞审片与包装。
2. **审片与包装工作台补齐「更换封面」入口**：在右侧「花字包装」面板的封面区域（以及点击时间轴「封面」片段时）提供封面编辑入口，支持：
   - **从本片选帧**：按已切分镜头浏览缩略图、在镜头内滑动微调时间点抽帧，并提供「取当前播放画面」一键设为封面；
   - **从项目图片选图**：直接选用当前项目已有的托管场景图或详情页图片；
   - **取景构图微调**：在预览画布中支持切换「调整封面底图」模式，对选定封面图进行缩放与拖拽位移，避开上方标题和贴纸，并可一键重置构图或恢复自动默认封面。
3. **内置按需触发的「AI 生成全景封面」**：在同一个封面面板提供按需生成标签，使用公司网关已接入的 GPT Image 2.6 模型，结合当前项目的产品参考图、产品外观描述、成片画幅以及当前包装模板的标题留白要求，生成构图清晰、上方留白的竖版产品全景封面候选；仅在剪辑师主动点击时执行，不随整批成片默认自动生成。
4. **预览、成片卡片与导出全链路一致**：审片预览在片头 20 帧区间实时展示所选封面底图与构图效果、成片卡片同步显示对应静态封面；最终渲染将选定封面源规整为 20 帧 24 fps 静帧片头拼接在正文之前，并将同一张封面图送入视频包装取色与合成，保持正文 360 帧、含封面 380 帧与原有音画偏移契约不变。

## User Stories

1. 作为剪辑师，我希望一键成片生成原片并完成切点识别后，系统自动从全片各镜头中挑选一张产品全景最完整的画面作为默认封面，而不是永远取正文第 1 帧，以便大多数成片无需手动换封面就能直接达到可交付水准。
2. 作为剪辑师，我希望自动挑帧避开每个镜头开头和结尾容易出现转场模糊的边缘帧，以便挑出的封面画面清晰、无残影。
3. 作为剪辑师，我希望当视觉模型未配置、超时、触发 451 内容过滤或整片只有一镜到底且无明显全景时，系统安全回退到正文第 1 帧并正常进入审片，而不是报错卡住包装草稿。
4. 作为剪辑师，我希望在右侧「花字包装」面板一眼看到当前封面的来源类型（自动挑帧、本片画面、项目图片或 AI 生成）与缩略预览，以便快速判断这条封面是否需要更换。
5. 作为剪辑师，我希望在「花字包装」面板或点选时间轴上的「封面」块时，能直接打开「更换封面」控制区，以便不用离开当前审片界面就完成封面调整。
6. 作为剪辑师，我希望在审片播放正文看到满意的瞬间时，可以一键点击「取当前播放画面作为封面」，以便用最少操作锁定最佳瞬间。
7. 作为剪辑师，我希望在「本片画面」来源里看到按镜头 01 至 0N 排列的缩略图列表，点击某个镜头即可预览该镜头画面并拖动时间滑块精调到具体帧，以便快速对比不同镜头作为封面的效果。
8. 作为剪辑师，我希望在「项目图片」来源里直接浏览并选用当前项目在「素材与脚本」阶段已经上传的场景图与详情页图片，以便当视频帧存在运动模糊或局部裁切时直接用高清原图做封面。
9. 作为剪辑师，我希望选定任意封面来源（视频帧、项目图片或 AI 生成图）后，可以在预览画布中拖动底图位置与调整缩放比例，以便把产品主体挪到画面中下部、完美避开包装主副标题与贴纸。
10. 作为剪辑师，我希望画布在「编辑文字/贴纸」和「调整封面底图」两种交互之间有清晰切换，以便移动底图时不会误拖标题，拖标题时也不会误移底图。
11. 作为剪辑师，我希望可以一键「重置构图」把缩放和位移恢复到默认居中填满，以便调乱后迅速复原。
12. 作为剪辑师，我希望随时可以点击「恢复默认封面」回到系统自动挑选的最佳全景帧（或重新触发一次自动挑帧），以便手动尝试不满意时一键回退。
13. 作为剪辑师，我希望在成片全片都是局部特写且项目原图比例不适合竖屏封面时，可以在更换封面面板中切换到「AI 生成全景封面」，以便按需补救封面缺失问题。
14. 作为剪辑师，我希望 AI 生成全景封面默认不随批量成片自动执行，只有在我主动点击生成时才发起付费调用，以便控制整批生成的成本和等待时间。
15. 作为剪辑师，我希望发起 AI 生成全景封面时，系统自动带入当前项目的产品参考图、已确认的产品名称与外观线索、当前成片画幅以及当前包装模板的标题留白方向，以便我不用从零写复杂提示词。
16. 作为剪辑师，我希望在发起 AI 生成前可以选择使用哪几张项目图片作为参考图、选择已启用的 GPT Image 2.6 通道（Flare 或 Sunburst），并可补充一句简短的场景或构图偏好，以便在需要时精细控制画面。
17. 作为剪辑师，我希望 AI 生成全景封面期间界面有明确的进行中状态且不阻塞我查看其他成片或继续调整字幕与花字，以便减少干等时间。
18. 作为剪辑师，我希望单条成片生成的全景封面以候选列表保留，我可以对比多张已生成候选并一键切换采用，而无需重复花钱重新生成同一张图。
19. 作为剪辑师，我希望 AI 生成失败、被内容策略拦截或超出个人费用额度/并发上限时，能看到清晰的中文原因提示，同时保留当前正在使用的封面不被清空，以便我可以改选本片帧、选项目图或稍后重试。
20. 作为剪辑师，我希望更换封面图片后，预览播放器在片头 20 帧封面时段立刻显示新封面底图与新构图，并叠上当前模板的花字包装，播放到正文起点时再无缝切到正片视频，以便做到所见即所得。
21. 作为剪辑师，我希望更换封面图片后，花字包装的自动配色也随之参考新封面底图重新预览，以便确认文字在换图后依然清晰易读。
22. 作为剪辑师，我希望返回「审片与导出」成片卡片总览页时，每条成片卡片展示的静态封面与我保存的封面设置保持一致，以便在卡片墙上就能一眼验收所有封面。
23. 作为剪辑师，我希望关闭「封面」勾选开关后导出时不输出片头 20 帧，但重新勾选打开时仍保留之前挑好或生成的封面设置，以便来回对比带封面与不带封面的效果时不丢工作。
24. 作为剪辑师，我希望我在草稿里尝试更换封面但未点击「保存草稿」直接离开或放弃时，不会污染已保存的包装配置；点击保存时通过版本校验防止覆盖他处更新。
25. 作为剪辑师，我希望在审片阶段对某个镜头做了局部替换采用或整条重抽后，如果原封面依赖自动挑帧，系统会自动针对新成片重新选择全景帧；如果原封面是我手动选的项目图片或 AI 生成图，则继续保留我的明确选择，以便返工画面时不反复丢失已定好的封面。
26. 作为剪辑师，我希望当原封面是手动选定的本片时间点、而返工重抽导致新成片长度短于原时间点时，系统能自动校正到有效范围内并给出轻提示，而不是在渲染时崩溃。
27. 作为剪辑师，我希望正式渲染导出后的 MP4 成片严格保持 24 fps、正文 360 帧、启用封面共 380 帧及原有音轨对齐，其中前 20 帧准确呈现我选定并裁切好的封面底图与花字包装，第 20 帧起完整呈现正文画面。
28. 作为剪辑师，我希望每次正式导出记录都会冻结当时的封面来源与修订信息；更换封面重新导出后生成新的独立交付记录，历史已导出的正式产物和 ZIP 下载摘要保持不变。
29. 作为团队管理员，我希望一键成片里的自动挑帧与 GPT Image 2.6 全景封面生成都纳入统一生产服务的成员费用额度、云端并发上限、模型权限与用量统计，以便统一管控部门算力与成本。
30. 作为团队管理员，我希望每个员工在更换封面或读取生成封面图时，服务端严格校验项目归属与受管文件权限，确保无法跨项目引用或读取他人项目的图片与生成封面。

## Implementation Decisions

### 模块边界与职责

- **遵循既有隔离边界**：所有一键成片封面领域状态、自动挑帧、AI 封面生成与封面渲染继续完全收口在一键成片独立模块内，只从共享媒体核心、脚本供应商、图片供应商与统一执行控制模块取用共享能力，绝不从单条混剪的成片状态模块导入，也不写入旧项目分镜或批量生产表。
- **复用共享封面合成单实现**：封面底图的 EXIF 方向矫正、取景构图几何计算（`scale`、`offsetX`、`offsetY`）及目标画幅裁切，直接复用共享媒体核心中的封面合成与取景几何能力，禁止在一键成片中再写第二套裁切公式，确保预览与最终导出构图一致。

### 统一封面来源模型与数据持久化

- **统一配置结构**：在一键成片包装选项（`PackagingOptions`）中新增可选字段 `coverMedia`，作为该条目封面的单一真相来源，并与现有 `cover: boolean` 开关正交（关闭 `cover` 时保留 `coverMedia` 不清空）：
  - `kind: 'auto_frame'`：自动挑帧结果，记录选取的正文时间点（微秒/帧索引）、来源成片签名、所选镜头标识、是否已回退首帧的标记，以及可选取景构图 `framing`；
  - `kind: 'video_frame'`：手动指定的本片帧，记录正文时间点、可选来源镜头标识与 `framing`；
  - `kind: 'project_image'`：手动指定的当前项目图片，记录项目内图片素材标识与 `framing`；
  - `kind: 'generated_image'`：按需生成的全景封面图，记录本模块封面资产标识与 `framing`。
- **向后兼容**：历史包装记录缺失 `coverMedia` 时，按默认自动策略解析并在渲染与预览中平滑回退到正文第 1 帧居中填满，不破坏既有草稿与历史导出记录。
- **数据库追加迁移**：按一键成片独立迁移流红线追加新版本迁移（走共享迁移备份、跨进程锁与审计门禁，不改已发布迁移条目），新增一张一键成片封面资产表用于记录本条目按需生成（及后续可扩展）的封面候选：包含资产 ID、所属运行与项目 ID、条目 ID 与编号、任务状态（排队/运行/就绪/失败）、请求去重键、所用模型与供应商标识、参考图列表、提示词快照、相对存储路径、宽高、错误信息及时间戳。
- **受管文件登记**：AI 生成的全景封面图落盘在基于统一数据根的一键成片封面存储目录下，并作为项目衍生文件完成受管文件登记，纳入团队版权限隔离与生命周期管理。

### 自动提取全景产品帧

- **触发时机与幂等**：在原片切点识别完成并准备包装草稿时自动触发（亦可由剪辑师在封面面板点击「重新自动挑选」主动触发），按当前成片签名与镜头切分结果做缓存和并发去重；同一成片签名不重复发起视觉模型调用。
- **候选帧采样策略**：基于当前成片的镜头区间，在每个镜头避开起止边缘的安全位置（例如镜头中段与偏后稳定点）抽样若干代表帧；若镜头数较多则按均匀分布将总候选帧控制在合理上限内（例如最多 8–10 帧），缩放为轻量预览尺寸后随编号一起发送给视觉模型。
- **视觉模型调用与容错**：复用现有支持图片识别的脚本视觉通道（与素材分析共用模型选择、团队执行准入、请求锁与用量记录上下文），传入产品名称与外观线索，要求模型从候选帧中选出最能完整展示产品全貌、画面清晰、遮挡最少的一帧并输出结构化 JSON。任何异常（未配置视觉模型、超时、网络错误、451 过滤、JSON 解析失败或返回越界编号）均记录告警并安全降级为正文第 1 帧，不阻塞草稿创建或打开。
- **非破坏更新**：如果剪辑师已经手动修改过封面（`video_frame`、`project_image` 或 `generated_image`），后台补齐或重新同步自动挑帧结果绝不静默覆盖剪辑师的手动选择。

### 手动挑选封面与构图交互

- **入口整合**：在「花字包装」面板的封面区域增加封面缩略图卡片、当前来源标签与「更换封面」展开/抽屉交互；在时间轴点击「封面」块时自动聚焦到该区域。
- **三大来源页签**：
  1. **本片画面**：展示所有镜头缩略图卡片，选中镜头后可在该镜头时间区间内拖动滑块精调帧时刻；顶部提供「取当前播放画面」按钮，直接取播放器当前正文时间点作为封面帧；
  2. **项目图片**：列出当前项目已有的托管场景图与详情页图片（复用当前项目图片列表），点选即刻生效；
  3. **AI 生成全景**：提供参考图勾选（默认勾选项目场景图，不超过公司网关最大参考图上限）、模型通道选择（默认优先已启用的 GPT Image 2.6 Flare / Sunburst）、可选简短构图偏好输入、当前模板留白提示、生成按钮以及本条目的历史生成候选画廊（点击任意历史候选即可切换采用）。
- **画布构图模式**：当播放头位于片头封面区间且启用封面时，工具条提供「编辑文字/贴纸」与「调整底图构图」切换；在底图构图模式下，指针拖拽更新 `offsetX`/`offsetY`，缩放控件更新 `scale`，并受共享取景几何边界约束，避免画面露出黑边。
- **预览同步**：审片播放器在片头 20 帧时段按所选 `coverMedia` 渲染对应底图与构图（`video_frame`/`auto_frame` 定位到对应视频帧或服务端抽帧图，`project_image`/`generated_image` 加载对应受权图片资源），进入正文时段立即切回视频播放。预览包装 HTML 请求同步携带当前封面底图摘要/来源，用于预览期近似取色。
- **成片卡片同步**：成片总览卡片优先展示当前已保存草稿的封面底图（若是本片某时刻则抽该时刻帧，若是项目图或生成图则展示对应图片并应用构图），保持卡片与编辑器一致。

### GPT Image 2.6 按需全景封面生成

- **模型与协议复用**：复用公司网关图片任务协议与已登记的 `qiniuyun/gpt-image-2.6-flare`、`qiniuyun/gpt-image-2.6-sunburst` 供应商配置、尺寸白名单吸附与规整能力；若两个通道都未配置或未启用，则界面明确提示原因并禁用生成按钮，同时保留本片选帧与项目选图功能可用。
- **参考图与安全边界**：参考图必须严格校验归属于当前项目；经由既有媒体传输 Adapter（COS 预签名中转）交付给公司网关，遵守不暴露本机公网地址、签名参数不落日志的既定安全红线。
- **提示词组装**：服务端按当前产品名称、外观与场景线索、成片画幅比例、包装模板标题区域位置（如顶部标题留白约束）以及用户可选补充说明，组装面向竖版产品全景封面的结构化生图提示词，明确要求保持产品外观结构、材质与配色与参考图严格一致，不做无关装饰字（文字统一由视频包装层叠加，避免画面自带乱码文字）。
- **准入、并发、用量与锁**：生图调用统一接入服务端执行准入（检查成员模型权限、月度费用额度、云端并发公平共享池）与用量计费记录，使用基于请求键的幂等锁防止连点重复扣费；结果采用后才通过包装编辑接口写入草稿并递增修订号。

### 渲染与导出管线统一

- **基准封面准备**：在包装渲染阶段，当启用封面时，根据 `coverMedia` 解析并产出唯一一份与正文同分辨率的基准封面图：
  - `auto_frame` / `video_frame`：从已合成的正式正文视频（已包含局部替换与高清素材）在对应时间点精确抽帧，再按 `framing` 经共享封面合成能力规整；
  - `project_image` / `generated_image`：校验文件归属与存在性后，按 `framing` 经共享封面合成能力规整到正文分辨率。
- **片头 20 帧拼接替代 `tpad` 克隆**：将基准封面图编码为 20 帧、24 fps、与正文同像素格式和分辨率的静帧片头，与正文视频按帧精确拼接后再叠加音频延时、背景音乐与贴纸；随后将同一份基准封面图传入共享视频包装管线完成首帧取色与透明层合成。
- **严格媒体校验不变**：导出后继续执行既有帧数（360 或 380 帧）、帧率（24 fps）与音轨完整性校验；封面来源变化会更新包装修订号，导出记录的 `versionJson` 同步冻结当前封面来源类型与关键标识，确保历史交付记录不可篡改且可追溯。

### API 契约调整

- **既有包装接口扩展**：在现有项目级一键成片包装路由下扩展封面相关动作与返回字段，保持鉴权、项目归属校验与 CSRF 保护一致：
  - 读取与打开草稿时返回当前 `coverMedia`、自动挑帧状态、本条目已生成的 AI 封面候选列表、以及当前可用的 GPT Image 2.6 通道信息；
  - `edit` 动作校验并保存 `coverMedia`（含来源归属校验与构图范围钳位），继续强制乐观锁修订号校验；
  - `preview` 动作接受草稿中的 `coverMedia`，使取色与封面层预览随草稿即时生效；
  - 新增动作：
    - 触发/重试自动全景挑帧（带当前成片签名幂等）；
    - 发起 GPT Image 2.6 全景封面生成（带请求去重键，返回生成状态或已就绪候选，等待并发名额时返回明确等待态而不报错）；
    - 查询本条目封面生成候选状态。
- **受权文件访问**：AI 生成封面图通过受控的受管媒体路由读取，校验当前登录用户对所属项目的读取权限，不暴露磁盘物理路径。

### 成片换源与失效处理

- 当局部返工采用或整条重抽导致成片签名变化时：
  - `auto_frame` 标记过期，在下次打开或同步时针对新成片重新自动挑帧（未完成前先回退到新成片首帧）；
  - `video_frame` 检查原时间点是否超出新正文时长，超界时钳位至有效区间并保留可编辑状态；
  - `project_image` 与 `generated_image` 不受正片重抽影响，原样保留。

## Testing Decisions

### 测试原则

- 只测试外部可观测行为与契约（HTTP 接口、持久化状态、渲染后的真实视频帧像素与媒体属性、真实浏览器交互与导出文件），不针对内部私有辅助函数编写脆弱单元测试。
- 不在业务代码中新增测试专用 mock 钩子；所有外部 AI 模型依赖统一收敛在**单一供应商 HTTP 边界**上，其余环节（SQLite 迁移与事务、受管文件权限、FFmpeg 抽帧与拼接、HyperFrames 透明包装合成）全部跑真实实现。

### 测试接缝与覆盖模块

1. **端到端员工贯通验收接缝（主接缝）**：复用现有的一键成片员工 Playwright 端到端验收套件及其本地 HTTP Mock 供应商：
   - 在同一个 Mock 供应商上扩展两类 HTTP 响应：① 视觉挑帧请求（返回指定的非首帧全景镜头编号，并覆盖异常/451 安全回退）；② 公司网关 GPT Image 2.6 图片任务提交、轮询与样本图下载（验证参考图与模板留白指令传参、团队准入与用量入账）。
   - 在真实浏览器里覆盖完整操作路径：自动挑帧落位 → 手动切换镜头帧与「取当前播放画面」 → 切换项目图片并拖动/缩放构图 → 触发 AI 生成全景封面并从候选采用 → 保存草稿与验证成片卡片封面同步 → 正式渲染导出。
   - 对导出的真实 MP4 执行 FFmpeg 媒体校验与抽帧像素比对：核验 24 fps、总 380 帧、音轨完整、第 0–19 帧（封面中点）呈现选定/生成封面的特征色与包装层、第 20 帧起呈现正文画面且未偏移。
2. **包装与交付域逻辑接缝**：复用现有的一键成片交付域测试套件（独立临时数据根 + SQLite）：
   - 覆盖 `coverMedia` 四种来源的解析、构图参数边界钳位、旧记录无 `coverMedia` 的兼容回退；
   - 覆盖修改封面递增修订号、并发修订冲突返回 409 拒绝、跨项目图片/封面资产引用拒绝；
   - 覆盖成片换源后 `auto_frame` 过期失效、`video_frame` 越界钳位以及 `project_image`/`generated_image` 保持不变；
   - 覆盖导出版本快照冻结封面信息、修改封面再导出生成新记录且历史交付摘要不变。
3. **团队权限与受管文件边界**：复用现有的团队 API 权限矩阵测试先例，验证封面生成动作、自动挑帧动作与生成封面图读取路由均受项目读写权限、CSRF 及受管文件归属校验保护，阻断跨项目访问。

### 仓库先例

- 一键成片端到端员工贯通验收（隔离团队服务 + Playwright + 本地 HTTP Mock 供应商 + 真实 FFmpeg/HyperFrames 抽帧比对）。
- 一键成片包装与交付域测试（独立数据根 + 迁移 + 状态/版本/导出幂等断言）。
- 普通精准混剪与批量生产的统一封面编辑 Playwright 回归（构图拖拽、换素材/截帧、取消不脏数据、一次保存）。
- 团队 API 授权与受管文件矩阵测试。

## Out of Scope

- **不随一键成片批量流程默认自动生图**：不为所有条目自动批量调用 GPT Image 2.6 生成封面，避免高成本、长等待与未经人工核对的产品形变风险。
- **不新增独立的封面自由画板或 PS 级局部修图工具**：本次仅提供封面底图选择、取景缩放/拖拽构图与按需生成整张全景封面，不做画笔擦除、局部重绘或滤镜调色。
- **不把封面独立导出为额外成对 JPG 到一键成片 ZIP**：沿用一键成片当前交付契约（ZIP 内为成片 MP4 及其已登记记录），如需额外随包输出独立封面 JPG 作为后续独立需求评估。
- **不改动普通单条精准混剪与批量生产的现有封面编辑器**：本次范围限定在一键成片模块，仅单向复用共享封面合成与取景几何能力。
- **不引入新的外部图片供应商协议**：AI 生成全景封面仅使用公司网关已接入的 GPT Image 2.6 系列模型，不在此需求中扩展第三方新适配器。

## Further Notes

- **封面与正片的色彩/观感衔接**：AI 生成全景封面时，提示词应主动带上项目分析产出的场景线索与产品外观描述，减少前 20 帧与正文首镜头的环境跳变感。
- **高分辨率原图与内存控制**：选用项目原图或 AI 高清生成图作为封面时，渲染阶段应按正文输出分辨率一次性规整，不把超大原始图片直接喂给 FFmpeg 循环编码；审片编辑器列表加载缩略图而非原图全尺寸，避免多条成片切换时卡顿。
- **离线与打包兼容性**：新增封面能力不引入新的本地二进制依赖或外部运行资源，完全基于现有 FFmpeg、Sharp、共享封面合成能力及公司网关配置运行，不影响既有桌面打包白名单与离线包装运行约束。
