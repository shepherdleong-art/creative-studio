## 实现决定

### 1. 独立应用备份到 GitHub

- 用已登录的 `gh` 在 `shepherdleong-art` 下建私有仓库 `live-mixcut`。GitHub 仓库名不能用中文。
- 独立应用现在没有远端。加远端 `origin`，推送全部 16 条本地分支。现在没有标签。
- 网页默认分支设为主干 `integration/live-mixcut-extraction`。本机的 `main` 只停在第一次提交（规格文档），不改它。
- 不改本机任何分支，不碰工作区里未提交的改动。推送前确认那边没有进行中的 Git 操作：没有未完成的合并或变基，没有残留的锁文件。
- 做完的标准：远端每条分支的提交号和本机一致；仓库是私有的；默认分支是主干。

### 2. 资料放进独立应用

## 测试决定

- **好测试只看外部行为：** 页面和接口还在不在；主流程能不能从上传素材一路走到导出 ZIP；正式构建过不过。不为「删干净了」另写检查代码，也不加扫字符串的守护测试。
- **测试落点（用户 10-30 已确认）：**
  1. **全部自动测试：** 删除之前先跑一遍，拿到基线。删除以后，除了被删掉的测试，其余结果和基线一样，都应该通过。范围是 `scripts/` 下的自动测试，不含 Playwright 和验收脚本。每个测试独立进程、带超时，因为有的会真跑 FFmpeg。
  2. **类型检查：** 全项目 0 错误。用隔离构建的方式跑，避开旧 `.next` 类型文件对已删页面的引用。
  3. **代码检查（lint）：** 改动过的文件不新增错误。
  4. **主流程检查：** `npm run check:main-path` 通过。
  5. **正式构建：** 隔离的正式构建通过，不碰用户正在开的桌面版和它的 `.next`。
  6. **浏览器冒烟：** 用隔离构建在临时数据根上起一个临时服务，打开首页、设置页、画布页。导航里没有「实拍混剪」，设置页没有「语音识别」，`/live-mixcut` 打不开（找不到），其余页面正常。
  7. **「升级前先备份」测试：** 换了例子以后通过。先例是这份测试现有的写法，以及画布、详情页智能脚本各自的就绪检查。
- **打包边界：** Windows 免安装包和 standalone 的边界测试都在第 1 条的自动测试里，照常要过。
- **数据清理的核对（手动、做一次）：**
  - 备份完整性核验通过；
  - 删表后完整性检查和外键检查通过；
  - 其余表的行数不变；
  - 用户重开桌面版后首页能打开，项目都在。

  - 远端分支和本机一致；
  - 默认分支是主干；
  - 资料提交前后，那边的未提交改动清单完全一样；
