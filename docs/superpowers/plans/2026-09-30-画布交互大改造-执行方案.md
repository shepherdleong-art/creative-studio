# 画布交互大改造执行方案

> 状态：**已实施完成（A/B/C/D 四期全部交付，2026-09-30）**。验证记录见文末「实施结果」。
> 范围：bug 修复 + 交互升级 + 架构收敛 + 并发多变体。脚本分镜节点、框选播放列表→混剪**不在本期**（后续单独立项）。

## 一、背景与目标

对标 LibTV/TapNow 等主流 AI 节点画布，当前创作画布存在 12 项已确认的交互痛点，根因已全部定位到代码。本方案分四期实施：先治病（A）、再收敛架构（B）、后升级交互（C）、最后动 schema 做并发多变体（D）。

三个方向性决策（用户已拍板）：

1. **导航范式对标主流节点画布**：滚轮缩放、左键拖空白=框选、空格/中键拖=平移、触控板捏合缩放——放弃早期"左键拖拽=平移"旧约定；
2. **做并发多变体**（完整对标 LibTV）：schema v2 放开"同节点至多一个活跃任务"唯一索引，节点可同时跑 N 个变体，结果成候选列表；
3. **分期交付**：每个切片可独立发版，D 期（schema 迁移）最后合入。

## 三、硬约束（红线）

- 迁移只追加（v1 不动，v2 起步），走 `lib/schema-upgrade/` 共享 gate（readiness 已统一接入，零改动即覆盖）。
- 画布模块绝不从 `lib/final-edit/` 导入；共享能力只从 `lib/media-core/` 取。
- 三条语义红线不变：`parseCanvasGraph` 严格校验、runs 幂等重放先于一切校验、nodeEpoch 防迟到发布。
- 新颜色一律设计令牌（浅色 `:root` + 深色 `html[data-theme='dark']` 成对）；React Flow 深色覆盖写在 `@layer` 之外；`sc-canvas-*` 在 `@layer components` 内。
- `CanvasEditorController` 公开接口与既有 `data-testid` 尽量保持（Playwright 四个 suite 依赖）；确需改的列入测试更新清单。
- UI 文案中文；Apple 极简风格；本地路径走 `dataRoot()`。

## 四、Phase A 基础修复（先治病，子项可并行，A1 收益最大）

### A1 输入本地化根治 IME

- 新增 `components/creative-canvas/use-node-text-field.ts`：**聚焦期间完全本地 state 驱动**（忽略 value prop 变化，不经 React Flow data 往返）；防抖 500ms 或失焦提交 `updateNodeData`；未聚焦时同步外部值（撤销/重载生效）。不再需要 composition 分支，天然覆盖 IME。
- `nodes.tsx`：删 `useImeGuardedValue`，四处输入全部换新 hook——TitleInput、PromptNode textarea、GenerationNode prompt、ReferenceRow note（现为 defaultValue+onBlur，顺势统一受控语义）。
- `editor-store.ts` `updateNodeData` 加**快速路径**，判定规则：

| patch 内容 | 跳过 reconcile？ | 依据 |
| --- | --- | --- |
| keys ⊆ {title, text, prompt, modelKey, generationMode, parameters} | 跳过 | 不参与槽位对账 |
| 含 references / referenceLabelCounter | 走全对账 | 低频点击，不敏感 |
| 结构变化（nodes/edges/position）→ `commit` 全路径 | 走 | 连线增删是槽位对账唯一真实触发源 |
| uploadIntoNode 写 assetId/mediaKind | 走 | mediaKind 影响端口类型 |

- 安全网：服务端 `saveCanvasGraph` 保存时无条件 `reconcileCanvasGraph` 不变，最终一致性服务端兜底。

### A2 导航范式重配

## 七、Phase D 并发多变体（schema 级，最高风险，最后做）

### D1 schema v2 迁移

追加进 `lib/creative-canvas/schema.ts`（v1 一字不动）：

```sql
DROP INDEX IF EXISTS idx_cct_node_active;                       -- 放开"同节点至多一个活跃任务"
ALTER TABLE creative_canvas_tasks ADD COLUMN variantIndex INTEGER NOT NULL DEFAULT 0;
CREATE INDEX IF NOT EXISTS idx_cct_node_results ON creative_canvas_tasks(canvasId, nodeId, phase, createdAt);
CREATE INDEX IF NOT EXISTS idx_cct_node_phase ON creative_canvas_tasks(canvasId, nodeId, phase);
```

不改表不重建；走共享 gate 自动纳入；`schema_too_new` 前向保护天然覆盖"旧版本打开 v2 库"场景（画布禁用但不阻塞旧工作台）。

**node_states 语义调整**：

| 字段 | 旧语义 | v2 语义 |
| --- | --- | --- |
| `activeTaskId` | 唯一活跃任务（发布门禁之一） | 最近创建的任务（展示用；退出发布门禁） |
| `currentAssetId` | 活跃任务成功后写入 | 最近发布成功者（最后完成者胜，LibTV 同款） |
| `nodeEpoch` | 防迟到发布门禁 | **唯一发布门禁**（红线强化） |

**`repository.ts publishCanvasNodeResult` 新门禁**：删 `activeTaskId===taskId` 检查；保留 nodeEpoch 匹配 + 新增防御性断言（任务属于该节点、同 epoch、已 succeeded 且 outputAssetId 匹配）；`activeTaskId` 改条件更新（仅等于本次 taskId 时清 NULL，其他变体仍在跑时保留指向最新任务）。epoch 相等 ⇒ 节点未被删除重建 ⇒ 迟到发布的唯一真实危害（跨代污染）仍被拦截。

**`tasks.ts createCanvasRun`**：busy 检查仅 branch 模式保留；single 支持 variantCount ∈ {1,2,4}（API 层校验）+ 单节点活跃任务上限 8（新错误码 `node_variant_limit`）；single 变体同 nodeId 插 N 行（variantIndex 0..N-1），行间无 task_inputs 互联；branch 每节点一任务的上游绑定映射不变。

### D2 planner

`CanvasPlanRequest` 加 `variantCount`（仅 single 生效；branch 强制 1 并入指纹 canonical，`[t,t] ≠ [t]` 指纹区分成立）；`node_busy` 检查移到调用方按 mode 决定；新 problem code `variant_count_invalid`。

### D3 runner/recovery/scheduler

- scheduler **零改动**：名额按任务行粒度，N 变体各自领名额/lease/fence，全局 10 名额自然约束并发总量。
- recovery 逐任务行语义不变；`releaseNodeActiveTask` 已是 `WHERE activeTaskId = ?` 条件更新，天然兼容。
- 多变体同时 polling 且 lease 过期的重启接管竞态：依赖既有每任务独立 fence，无需新代码但**必须显式测试覆盖**。

### D4 UI 候选列表

- `runtime-store.ts`：NodeRuntime 扩展 `activeTasks[]`（taskId/phase/variantIndex/errorMessage）+ `candidates[]`（taskId/assetId/variantIndex/createdAt）。
- `nodes.tsx`：生成按钮 → 数量分段控件（1/2/4，默认 1）+ 状态文案（生成/追加变体/重新生成）；NodeStatus 升级多任务徽章行。
- 新增 `ResultCandidates.tsx`：候选缩略图横行、点击切换预览（本地态）、逐个下载、状态徽章；主结果 = `currentAssetId`，本期**不做手动设主**（需新写路径与门禁，列为后续扩展）。
- `runNode` 请求体带 variantCount。

### D5 API 候选投影（服务端维护，符合"运行投影服务端维护"约定）

- `repository.ts` 新增 `listCanvasNodeCandidates`（succeeded 任务按 nodeId 取最近 12 条，走 v2 新索引）。
- `app/api/canvas/[id]/route.ts` 返回体加 `nodeCandidates`（GET/PATCH 都带）；runs 路由校验 variantCount（branch 传 >1 时 400）。
