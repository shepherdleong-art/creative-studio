## Question

薄 Electron 壳、本地 Next 服务和媒体子进程各自负责什么，如何安全启动、退出、选择文件、恢复任务，并在 macOS 与 Windows 上保持同一行为？

## Dependencies

- 被 [先画出现有工程的安全边界](./01-先画出现有工程的安全边界.md) 阻塞。
- 被 [定义批量生产的数据模型](./02-定义批量生产的数据模型.md) 阻塞。

## Resolution

- 研究资产：[Electron 官方资料研究：桌面壳与本地服务边界](./assets/03-Electron官方资料研究.md)。
- 进程边界：Electron main 管窗口、原生选择和生命周期；preload 只提供白名单 Interface；现有 Next 服务继续管理 React、SQLite、任务、AI 和 FFmpeg。
- 运行边界：单实例启动私有 Node 服务，绑定 loopback 随机端口并使用每次启动认证；main 通过精确健康身份识别和持有自己的服务进程。
- 安全边界：renderer 保持无 Node 权限、隔离和沙箱开启，IPC 校验 sender，导航、新窗口和原生路径能力默认拒绝。
- 文件边界：原生对话框由 main 打开，页面只获得登记后的媒体身份，不能提交任意绝对路径要求后端读取。
- 退出边界：关窗只隐藏并继续后台任务；明确退出时暂停并保存未完成任务，再优雅回收服务和媒体进程；异常退出依靠持久化恢复。
- 兼容边界：Electron 不加载 `better-sqlite3`、`sharp` 等业务原生模块，继续沿用私有 Node 22 ABI 和既有数据根；V1 不承诺自动更新。
- 后续修正（2026-08-01）：公司供应商模式还会由同一启动入口看管必要的 `LiteLLM` 和媒体传输 sidecar，但它们属于可选供应商运行环境；任一 sidecar 失败只禁用公司供应商，不阻塞工作台、本地能力或外部供应商启动。
