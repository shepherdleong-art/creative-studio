# 现有工程安全边界审计

- 审计日期：2026-07-31
- 审计分支：`mixcut01`
- 审计性质：只读架构审计，不代表批量混剪已经实现
- 对应票据：[先画出现有工程的安全边界](../01-先画出现有工程的安全边界.md)
- 可视化报告：`/tmp/architecture-review-creative-studio-20260731-104423.html`

## 给非技术人员的结论

Creative Studio 不需要推倒重做。现有项目已经拥有一套可以继续使用的“视频生产内核”，包括视频分析、配音、字幕对齐、时间线、封面、背景音乐、真实 FFmpeg 渲染、成片校验和正式产物登记。

真正的问题是：这些能力目前主要围绕“一个分镜组、一次生成、一个编辑工作区”组织。批量生产需要项目级素材、多个脚本、很多长期任务和桌面文件能力，不能继续把它们直接塞进现有混剪主界面和现有工作区实现。

因此安全路线是：

1. 冻结单条精准混剪的外部 interface 和数据规则。
2. 新建项目素材库 module，统一模块 4 素材、托管素材和链接素材。
3. 新建持久生产调度 module，统一长任务状态、进度和资源控制。
4. 新建独立批量生产 module，复用下层能力，不复用现有单条页面状态。
5. 最后加入薄 Electron Runtime Host，替换“启动本地服务后打开浏览器”的交付方式。

## 已核实的现状

| 现状 | 证据 | 判断 |
|---|---:|---|
| 单条混剪工作区实现 | 2,129 行、108 次直接 SQL、13 个公开操作、32 类编辑命令 | 外部 interface 有价值，但内部职责过多；不得继续加入批量职责 |
| 单条混剪主界面 | 972 行、33 组 `useState`、21 次 `fetch` | 不适合作为批量模式的状态容器 |
| 成片相关 HTTP 路由 | 25 个路由直接访问数据库 | 不要求先全面重写，但新增批量路由必须通过新的 deep modules |
| 长任务执行 | 图片队列、视频队列、混剪准备、渲染 worker／全局重活锁分开存在 | 缺少统一暂停、停止、恢复和资源调节 interface |
| 浏览器素材导入 | 单文件 256 MB、单请求 512 MB，并依赖 `Request.formData()` | 适合小文件复制导入，不适合几十 GB 实拍原片 |
| 桌面安装包 | 已内置 Node、Next standalone 和 FFmpeg，但启动后打开系统浏览器 | 桌面运行基础可复用，正式窗口与原生文件能力需要 Electron Runtime Host |
| 聚焦测试 | 42 个混剪、成片和安装包相关测试文件 | 已有较强回归基础，应作为每阶段门槛而不是重写 |

## 可以直接复用的 deep modules

### 1. 数据根 module

统一决定数据库和 `storage` 的本地根目录。桌面化后必须继续使用它，旧项目才不需要搬家。

**保留原因**：interface 很小，调用方不需要知道开发、安装版和自定义数据根的差异，具有高 leverage。

### 2. FFmpeg 解析与运行 module

已经统一解析内置二进制、环境变量和系统路径，支持超时、错误尾部和真实媒体进度。

**保留原因**：渲染、预览、探测都从同一 seam 获得能力。

**必须补强**：运行 interface 还没有取消信号。未来“停止任务”必须能够真正结束 FFmpeg 子进程，不能只改数据库状态。

### 3. 成片渲染 module

能够从不可变快照生成视频和封面，按真实媒体时间报告进度，并校验最终时长。

**保留原因**：这是已经有真实 FFmpeg 测试的核心实现，批量生产应调用它而不是复制另一套渲染器。

### 4. 单条音频优先匹配 module

现有匹配实现使用纯输入和纯结果，返回时间线计划与可解释诊断，不直接访问数据库、文件系统或供应商。

**保留原因**：确定性和测试 locality 较高，可以作为联合分配器生成单条成片计划的内部原语。

**使用限制**：它只解决一条成片内部的匹配，不能直接承担多条成片之间的素材用量平衡、区间错开和相似度控制。

### 5. 素材复制导入与路径安全 module

现有导入实现已经包含格式白名单、内容核验、文件指纹、临时文件、符号链接防护、真实路径 containment 和缩略图处理。

**保留原因**：删除它会让安全复杂度重新散落到每个调用方。

**使用方式**：作为未来项目素材库中的“托管素材 adapter”，不能强行承担原位置链接素材。

### 6. 脚本解析与快照 module

现有智能混剪能够读取可用项目脚本，按分镜组隔离，并把正文、普通标题和结构化封面标题保存到混剪快照。

**保留原因**：已经解决上游变化不能静默覆盖成片的问题。

**术语纠正**：当前正式工作台第 3 步是「脚本生成」，第 4 步是「视频生成」。脚本文案和标题来自第 3 步保存的项目脚本，第 4 步提供成功视频；技术实现不能把视频任务当成脚本存储。

### 7. 分析、TTS 与字幕对齐 adapters

视觉分析、语义评分、TTS 和字幕对齐已经通过 adapters 接入不同供应商。

**保留原因**：供应商差异已经位于真实 seam，批量任务只应调度这些 adapters。

### 8. 安全导出与正式产物 module

现有实现能够预留不冲突的文件名、先在内部目录渲染、校验后原子发布，并登记视频和封面产物。

**保留原因**：批量导出只需扩展批次命名和文件夹组织，不能绕过预留、校验和登记步骤。

## 不能继续扩大的现有位置

### 1. 单条混剪工作区实现

它同时负责脚本、素材、分析、配音、匹配、预览、时间线编辑、字幕、封面、背景音乐、版本、数据库和任务启动。删除它会让大量复杂度扩散，说明它不是无价值的浅 module；但它的内部 locality 已经很低。

**安全决定**：保留它作为单条精准混剪兼容入口，后续只允许把内部职责迁移到新的 deep modules；禁止直接加入批次、项目素材库、代理或桌面生命周期方法。

### 2. 单条混剪主界面

它目前集中管理页面步骤、分镜组切换、素材选择、脚本编辑、供应商设置、任务轮询、历史版本和导出跳转。

**安全决定**：批量生产必须拥有独立工作区状态和持久化批次身份，只共享下层 modules；不得在现有主界面继续增加几十组状态和请求。

### 3. 全局重活锁和渲染 worker

现有全局 Promise 队列能够避免多个重任务同时挤占机器，渲染 worker 也能把重启前的 `running` 任务恢复为 `queued`，但它们没有统一的任务 interface、暂停、停止、资源档位或单条占用信息。

**安全决定**：未来持久生产调度 module 应替换这部分职责，而不是在外面再叠一套批量队列。

### 4. 浏览器 FormData 大文件导入

当前实现适合复制小视频到项目，但不能成为手机和相机原片的主入口。

**安全决定**：桌面原生文件选择直接创建链接素材引用；只有用户选择“复制进项目”时才调用托管素材 adapter。

### 5. 现有启动器

macOS 和 Windows 启动器已经能启动内置 Node 服务、设置数据根和写日志，但最终动作仍是打开默认浏览器。

**安全决定**：复用本地运行时和数据根规则，Electron Runtime Host 接管窗口、原生对话框与生命周期；不把业务实现迁入 Electron。

### 6. 当前数据库启动与迁移

正式数据库打开后会立即执行迁移；旧核心迁移通过捕获异常兼容“字段已经存在”，但也可能把真正的迁移错误一起吞掉。目前也没有在第一份新批量结构落库前自动备份数据库。

**安全决定**：第一份批量数据库迁移之前，必须先建立数据库启动与迁移 module，完成备份、执行、验证和失败停止。不能先建批量表、以后再补备份。

## 四个 deepening 候选

| 候选 | 推荐强度 | 核心 seam | 为什么现在需要 |
|---|---|---|---|
| 深化项目素材库 module | **Strong** | 统一素材身份、在线状态、分析复用和批次选择 | 三种素材来源形成真实 adapters，是代理、LUT 和批次的共同基础 |
| 深化生产任务调度 module | **Strong** | 长任务状态、领取、进度、暂停、停止、恢复和资源档位 | 当前四套执行机制无法支撑批量生产的一致体验 |
| 冻结单条 interface，另建批量生产 module | **Strong** | 单条按分镜组、批量按明确选择的项目素材池 | 避免继续扩大现有工作区和主界面 |
| 深化桌面 Runtime Host module | **Worth exploring** | 桌面窗口、原生文件选择和应用生命周期 | 已有安装包基础可复用，但具体进程关系需要独立技术调查 |

**首要推荐**：先深化项目素材库 module。所有批量流程首先依赖可信的素材身份；没有它，链接素材、代理、LUT、分析复用和批次快照都会各自发明规则。

**硬前置**：数据库启动与迁移 module 必须在第一份批量数据库迁移前完成。

## 绝对不能破坏的数据红线

1. **旧数据继续可读**：沿用同一数据根，不迁走旧项目、旧脚本、旧混剪版本和正式产物。
2. **追加迁移**：现有发布过的数据库迁移不修改；新结构只追加，并在首次新迁移前备份数据库。
3. **单条隔离**：单条精准混剪继续要求素材、脚本和视频共享 `projectId + shotSetId`。
4. **历史身份**：历史版本以生成组身份区分，不能仅凭分镜组判断“同一个版本”。
5. **不可变输入**：开始生产后使用脚本、素材、时间线和输出设置快照；上游变化不能静默改写进行中或已完成结果。
6. **乐观锁**：编辑命令继续携带预期版本，旧页面状态不能覆盖新修改。
7. **文件安全**：所有托管文件和产物继续经过数据根 containment、真实路径和符号链接检查。
8. **原片安全**：链接素材、代理和 LUT 永不修改原始视频。
9. **原子发布**：内部渲染完成并校验后才发布正式产物；发布失败不能留下看似成功的半成品。
10. **产品身份**：正式文件命名继续以项目 `productCode` 为产品身份，不读取图像模型字段代替。

## 绝对不能破坏的行为红线

1. 单条精准混剪继续可以选择当前分镜组、自动载入项目脚本、生成、预览、调整和导出。
2. 同一个分镜组的多个历史生成版本可以分别打开，不能被当前编辑草稿覆盖。
3. 结构化封面标题、人工字幕、封面取景、背景音乐和时间线修改继续保存在正确版本中。
4. 分析失败、语义降级、预览失败和渲染失败继续留下可诊断状态，不伪装成成功。
5. 已完成任务不会因为应用重启被重新执行；未完成任务只能通过真实队列恢复。
6. 停止批量任务最终必须贯穿前端、调度 module、供应商请求和 FFmpeg 子进程。
7. 删除批次、代理或缓存不能删除原片；删除正式产物必须单独确认。
8. macOS 和 Windows 安装包不得包含开发数据库、用户素材、日志或密钥。

## 后续每个阶段的最低验证门槛

| 验证层 | 必须证明什么 |
|---|---|
| 领域与数据库 | 新旧数据能共存，迁移可重复，失败可停止，隔离规则不变 |
| module interface | 调用方和测试通过同一 seam；不依赖内部 SQL、路径拼接或函数调用次数 |
| 单条混剪集成 | 项目脚本、模块 4 视频、外部托管素材、历史版本和乐观锁继续工作 |
| 真实媒体 | 真实 FFmpeg 预览、渲染、时长、封面、字幕、BGM 和停止行为通过 |
| 正式 UI | 真实页面完成单条主流程；批量 UI 不污染单条状态 |
| 桌面交付 | macOS 与 Windows 安装包使用同一旧数据根，原生选材、退出与恢复正确 |
| 外部供应商 | 只在明确授权后验证真实分析、TTS 或大模型调用，不能用 mock 结果冒充 |
| 用户验收 | 用户完成真实规模任务并确认操作、结果和等待反馈符合预期 |

## 现有最高价值测试 seam

- 数据库迁移：版本表与重复初始化测试。
- 单条混剪上下文：内存 SQLite、临时目录和真实媒体探测。
- 单条混剪工作区：从脚本、素材到生成组、编辑命令和恢复的真实 interface。
- 真实渲染：真实 FFmpeg、Sharp、字幕、封面、语速和成片时长。
- 正式页面：Playwright 覆盖准备进度、预览、历史版本和导出状态。
- 真实纵向链路：生产服务、真实媒体渲染、下载解码、SQLite 状态和正式产物登记。
- 桌面安装包：macOS payload 与 Windows installer 静态和运行约束。

这些测试不是全部验收，但它们应成为后续每次小步迁移的固定回归门槛。
