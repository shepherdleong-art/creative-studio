# 集中式代理缓存与 LUT 链路设计

- 决定日期：2026-07-31
- 决定性质：代理缓存、LUT 身份、预览与最终导出链路设计，不代表数据库或生产代码已经实现
- 对应票据：[设计集中式代理缓存与 LUT 链路](../07-设计集中式代理缓存与LUT链路.md)
- 上游依据：[项目素材库与原文件引用设计](./04-项目素材库与原文件引用设计.md)、[可恢复任务调度与自动资源控制设计](./05-可恢复任务调度与自动资源控制设计.md)

## 给非技术人员的结论

手机 4K 素材默认直接预览，不提前浪费时间和硬盘空间生成代理。用户发现相机 LOG、高码率或特殊编码素材播放卡顿后，可以点击“为本批素材生成代理”，系统才在后台批量处理并显示真实进度。

代理只是为了让预览更流畅的低负担副本：

- 所有代理集中放在一个缓存目录，可以从前端清理。
- 清理代理不会删除手机、相机、移动硬盘里的原文件，也不会删除素材分析、批次或正式成片。
- 最终成片永远读取原片；即使代理还在，原片离线时也不能正式导出。

LUT 是用户主动选择的色彩转换文件。导入 LUT 不会自动给任何素材调色；用户只给选中的相机 LOG 素材应用。为了让浏览器看到接近最终结果的颜色，选择 LUT 后系统自动生成带该 LUT 的色彩预览代理；最终导出则从原片重新应用同一个 LUT。

## 已确认的十六个场景

本票使用一个不读取真实视频、不生成真实代理、不导入真实 LUT 的终端逻辑原型逐步验证，用户确认以下行为符合预期：

1. 新批次默认关闭代理，手机与相机素材都先直接预览原片。
2. 相机素材实际卡顿后，用户可以为当前批次素材批量开启代理。
3. 普通代理生成后，预览自动采用与当前素材完全匹配的代理。
4. 损坏的 `.cube` 文件在导入时被拒绝，不等到正式导出才报错。
5. 合法 LUT 导入后进入受管列表，但不自动应用到素材。
6. 用户可以一次把 LUT 应用到选中的相机 LOG 素材，手机素材保持关闭。
7. LUT 色彩预览代理完成后，浏览器预览使用它；生成前明确标注当前原片尚未显示 LUT。
8. 批次开始时固定素材内容身份与每份素材的 LUT 选择。
9. 原片离线但匹配代理仍在时可以预览，正式导出必须阻塞。
10. 重新定位并核验原片后，正式导出恢复可用。
11. 同名但内容不同的新 LUT 形成新身份，不覆盖运行中批次引用的旧 LUT。
12. 正在播放的代理拥有使用锁，清理时先跳过并标记稍后删除。
13. 前端清理当前项目代理时，只删除可清理缓存并报告实际释放空间。
14. 预览关闭、使用锁释放后，待删除代理完成清理。
15. 被运行中或历史批次引用的 LUT 只归档，不物理删除受管文件。
16. 代理全部清空后，正式导出仍读取原片并应用批次快照中的受管 LUT。

原型已经完成验证并按抛弃式原型约定删除，本文件保留其决定。

## 1. 当前工程与参考项目的真实现状

Creative Studio 当前没有正式代理或 LUT 业务：

- `components/final-edit/FinalEditPreview.tsx` 通过浏览器视频元素直接读取素材预览地址。
- `lib/final-edit/video-frame.ts` 已有受控路径、哈希缓存、并发限制、临时文件与原子改名，可复用这些安全模式，但它只生成单帧 JPG。
- `lib/final-edit/renderer.ts` 从不可变快照读取原视频并构建 FFmpeg filter graph；这是最终色彩转换必须接入的位置。
- `lib/ffmpeg.ts` 已统一解析 FFmpeg、运行进程和报告进度。本机随项目提供的 FFmpeg 已确认拥有 `lut3d`、`colorspace` 和 `zscale` filter。

参考项目 `short-video-mashup-tool` 的批量规划文档提到“卡片预览用低码率代理缩略”，但源码中没有可直接迁移的媒体代理缓存或 LUT 实现。因此只参考其产品意图，不复制 Electron、Python 或不存在的处理链。

## 2. 三个对象必须分清

| 对象 | 身份依据 | 能否清理 | 是否参与最终导出 |
|---|---|---|---|
| 原片／项目素材 | 项目素材身份与完整内容指纹 | 按项目素材库规则，链接原片永不删除 | 是，最终导出的唯一视频来源 |
| 代理文件 | 原片内容、代理规格、色彩转换和实现版本共同形成的派生键 | 可以集中清理并重新生成 | 否 |
| LUT 资产 | 导入文件的完整内容指纹 | 无引用时可清理；有批次引用时只能归档 | 是，以批次快照引用作用于原片 |

代理不能成为新的项目素材身份，不能产生自己的素材分析历史，也不能在原片丢失时升级成“正式原片”。移动原片、生成代理或清理代理都不改变项目素材身份。

## 3. 代理默认关闭，用户按需批量开启

- 新项目和新批次的代理默认关闭。
- 手机 4K、相机素材和模块 4 视频先尝试直接预览。
- 浏览器解码失败、拖动明显卡顿或用户自己判断需要时，界面提供“为本批素材生成代理”。
- 该动作针对用户已经选入当前批次素材池的素材，不擅自处理整个硬盘或项目素材库。
- 用户仍可在素材列表里勾选部分素材再批量生成，适合只处理相机 LOG 文件。
- 开启后，生成、失败、暂停、继续和重试通过 `ProductionScheduler` 记录为真实生产任务；主界面显示完成数量和单文件真实进度。

点击 LUT 应用属于另一个明确动作。即使普通代理开关仍为默认关闭，用户给素材选择 LUT 后也会请求匹配的色彩预览代理，因为原片直读无法显示已经选定的 FFmpeg LUT 效果。

## 4. 统一缓存目录与派生身份

所有代理统一位于：

```text
dataRoot()/storage/cache/proxies/<projectId>/<mediaId>/<proxyKey>.mp4
```

路径始终基于 `dataRoot()`，通过现有 storage 安全路径规则校验，不接受页面提交的任意绝对路径。目录按项目和素材隔离，避免一个项目错误读取另一个项目的缓存。

`proxyKey` 至少由以下事实确定：

- 项目与素材身份。
- 原片完整内容指纹。
- 代理规格与规格版本。
- LUT 关闭，或所选 LUT 的完整内容指纹。
- 色彩处理链版本。

文件名、原路径和素材显示名称都不参与身份判断。同一路径换成新内容、LUT 内容变化、代理规格升级或色彩链升级都会形成新键；旧代理只能成为清理候选，不能冒充新结果。

代理先写入同目录临时文件，成功探测时长、尺寸、可解码性和完整性后原子改名为正式缓存。崩溃残留的临时文件可在启动恢复时安全清理。

## 5. 代理规格的业务合同

本票不提前锁死码率和分辨率，但所有代理规格都必须满足：

- macOS 与 Windows 安装包内置浏览器能够稳定解码和拖动。
- 时间从零开始，时长与原片保持在后续镜头区间映射允许的误差内。
- 不修改原片，也不成为正式输出或对外导出选项。
- 可供交互预览，以及经过能力声明的轻量抽帧；最终镜头时间和导出仍以原片为准。
- 生成进度来自 FFmpeg 实际处理时长，不伪造百分比。

默认分辨率、码率、软件或硬件编码器、GOP 和音轨保留策略，要在 [确定验证矩阵与真实规模验收](../11-确定验证矩阵与真实规模验收.md) 中用手机 4K、相机 LOG 和目标电脑校准后确定。

## 6. LUT 资产的导入与身份

V1 支持受管的 3D `.cube` LUT，面向标准 SDR 社交视频输出；HDR、ACES 和专业多级色彩管理不在 V1 范围。

导入必须通过桌面原生文件选择器进入白名单桥，不能让页面提交任意本机路径。LUT 导入 Module 执行：

1. 验证普通文件、扩展名、大小上限和安全路径。
2. 计算完整 SHA-256；同一内容重复导入复用同一 LUT 资产。
3. 用本地 FFmpeg `lut3d` 对小型测试画面做真实验证，拒绝损坏或不支持的文件。
4. 先复制到临时文件，核验后原子写入 `dataRoot()/storage/luts/` 受管目录。
5. 保存独立显示名称和内容身份；同名不同内容形成新 LUT，绝不覆盖。

导入只让 LUT 出现在选择列表，不对任何素材生效。用户在批次素材池中选中一条或多条素材后，才能执行 LUT 应用；未选择的手机直出素材继续关闭。

## 7. 一个色彩转换快照贯穿预览和导出

每份批次素材的色彩转换只有两种状态：关闭，或引用一个已经验证的 LUT 资产。启用状态至少固定：

- LUT 资产身份和完整内容指纹。
- 色彩处理链版本。
- FFmpeg `lut3d` 插值方式。
- V1 标准 SDR 输出约束。

同一个色彩转换快照被三条链路共同消费：

1. 代理生成：原片解码 → 应用 LUT → 缩放与代理编码。
2. 视频关键帧与视频来源封面：从原片或匹配代理取得画面时应用同一 LUT 选择。
3. 正式渲染：原片解码 → 应用同一 LUT → 取景、缩放、拼接、文字叠加与最终编码。

普通浏览器预览不另写一套 WebGL 调色器，以免两套实现产生颜色差异。LUT 预览代理完成前，界面可以暂时显示原片，但必须明确标注“当前尚未应用 LUT”；不能把原始 LOG 画面冒充最终颜色。

## 8. 预览来源选择与安全回退

预览 Module 按以下顺序解析：

1. 存在与当前原片内容、代理规格和 LUT 快照完全匹配的可用代理时，使用代理。
2. LUT 关闭、原片在线且浏览器可解码时，直接使用原片。
3. LUT 已启用但匹配代理尚未完成时，允许显示带明确警告的原片暂览，并提供生成进度或重新生成入口。
4. 原片离线但匹配代理仍在时，可以继续预览，同时明确标注原片离线、正式导出不可用。
5. 原片和匹配代理都不可用时，预览不可用并引导重新定位原片。

代理失败不会把素材本身标成失败。用户可以继续尝试原片预览、重试代理或关闭代理；这些选择不改变批次素材身份。

## 9. 正式导出只读原片

批次开始时保存每份素材的内容指纹与 LUT 快照，不保存“正式导出要读取的代理路径”。

正式渲染前必须重新核对：

- 至少一个原片来源在线且完整内容指纹一致。
- 快照引用的 LUT 受管文件存在且内容指纹一致。
- 本地 FFmpeg 支持固定的色彩处理链。

任何一项不满足都把任务设为阻塞并给出处理入口。系统不能为了“尽量导出”而改用低清代理、关闭 LUT、采用同名新 LUT或继续使用内容已经变化的原路径。

代理清理、代理失败或代理规格升级均不影响正式导出。原片离线即使仍能看代理，也必须先重新定位原片才能导出。

## 10. 前端清理与正在使用的文件

界面提供两个清理范围：

- 项目内的“清理代理”：清理当前项目缓存，清理后当前素材回到原片预览；已选择 LUT 的素材显示原片暂览警告和“重新生成色彩预览”。
- 设置中的“清理全部代理”：显示全局可清理大小并明确说明不影响原片与正式成片，再清理所有项目的可释放代理。

清理动作由 `ProxyMediaCache` Module 统一执行：

- 先停止或取消尚未开始的代理任务；正在运行的任务通过调度器合作取消，不能一边写一边删。
- 正在被浏览器、抽帧任务或其他允许的读取者使用的代理先标记待删除，释放后再删。
- 只删除受控代理目录中的已核验缓存和临时文件，拒绝符号链接、越界路径和任意绝对路径。
- 返回实际删除数量、实际释放空间和暂时跳过的文件数；详细文件放任务详情。
- 清理后关闭对应的代理使用请求，避免刚清完就自动重新生成；LUT 选择仍保留，用户可明确重新生成色彩预览。

清理永远不能删除原片、项目素材记录、分析版本、LUT、批次快照、渲染任务目录或正式产物。

## 11. LUT 归档与安全清理

- 同一 LUT 内容重复导入只保留一个受管内容身份，可以拥有不同显示来源。
- 同名但内容不同的文件建立新的 LUT 资产；旧批次继续引用旧内容。
- 没有任何草稿、批次版本、成片版本或历史任务引用时，用户才可以物理清理 LUT 受管文件。
- 仍被引用时，“删除”在用户层表现为归档：从新选择列表隐藏，但文件和历史关系继续保留，可以恢复。
- LUT 文件缺失或内容改变时，不能静默关闭 LUT；相关预览和导出明确阻塞并要求恢复正确内容。

## 12. Module、Interface、Seam 与 Adapter

### `ProxyMediaCache` Module

它把代理身份、统一路径、生成请求、来源解析、使用锁和安全清理藏在一个深 Implementation 中。外部 Interface 只表达：

- 为明确选择的素材和色彩转换请求可恢复代理任务。
- 为预览解析当前最合适且安全的媒体来源。
- 查询项目或全部缓存用量并执行清理。

页面、媒体 route、分析代码和 renderer 不得自行拼接代理路径或重新判断代理是否匹配。

### `LutCatalog` Module

它的 Interface 只表达导入并验证 LUT、列出可选 LUT、读取已核验内容以及归档／安全清理。桌面文件选择 Adapter 提供用户明确授权的源文件，生产中使用受管文件 Adapter，测试使用临时文件 Adapter。

### `ColorPipeline` Module

它以固定色彩转换快照生成 FFmpeg filter 片段，供代理、视频关键帧、视频封面和正式 renderer 复用。LUT 路径转义、插值、处理顺序和输出约束集中在 Implementation 内，避免每条 FFmpeg 链路各写一套。

`ProxyMediaCache` 不直接运行无限 FFmpeg worker，而是通过 `ProductionScheduler` 的代理任务 Adapter 执行。这样代理与正式导出共享资源令牌、暂停、恢复、进度和清理协议，不会再出现一套隐藏队列。

## 13. 实现验收

1. 新项目和新批次不自动生成代理。
2. 用户为 50 条批次素材开启代理后，只有这 50 条建立任务并显示真实完成数量。
3. 同一代理请求重复提交只形成一个有效缓存结果，失败重试不制造重复文件。
4. 项目 A 无法读取或清理项目 B 的代理。
5. 原片内容、代理规格、LUT 或色彩链版本变化后，旧代理不会被误用。
6. 代理临时文件中途崩溃后不进入可用状态，重启可安全恢复或清理。
7. 损坏、越界、符号链接或不受支持的 LUT 在导入阶段被拒绝。
8. 同一 LUT 内容重复导入复用身份；同名不同内容不覆盖。
9. LUT 导入后不自动应用，批量应用只影响明确选择的素材。
10. LUT 代理生成前明确显示原片尚未应用 LUT，生成后预览采用匹配代理。
11. 代理预览、视频来源封面和正式渲染消费同一个 LUT 快照。
12. 批次开始后选择新 LUT，不改变旧批次和已建立的成片计划。
13. 原片离线但代理在线时可以预览，正式导出明确阻塞。
14. 重新定位并验证同一原片后，无需重分析即可恢复导出。
15. 清理当前项目或全部代理不删除原片、分析、LUT、任务、批次和正式产物。
16. 清理遇到正在读写的代理时不会竞争删除，释放后完成清理。
17. 代理全部清空后，原片在线且 LUT 完整的批次仍可正式导出。
18. 有历史引用的 LUT 只能归档，无引用 LUT 才能物理清理。
19. 最终 renderer 的快照和任务日志不包含任意未核验的用户绝对路径。
20. 手机 4K、相机 LOG、中文路径和外置磁盘场景在 macOS 与 Windows 安装包通过真实 FFmpeg 验证。

## 本票明确不决定的内容

- 不决定 SQLite 表名、字段名、索引和迁移 SQL。
- 不把原型中的文件大小当作真实容量估算。
- 不决定默认代理分辨率、码率、GOP、音轨、软件或硬件编码器。
- 不保证专业调色软件级别的色彩管理，也不支持 V1 范围外的 HDR／ACES 多阶段工作流。
- 不决定批量工作区与存储管理界面的最终视觉布局。
- 不代表代理、LUT 或桌面文件选择已经写入正式业务代码。
