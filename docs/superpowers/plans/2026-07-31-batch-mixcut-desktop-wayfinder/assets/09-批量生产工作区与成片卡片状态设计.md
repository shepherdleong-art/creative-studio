- 决定日期：2026-07-31
- 决定性质：批量生产工作区、持久状态映射和成片卡片交互设计，不代表数据库、API 或正式界面已经实现
- 对应票据：[设计批量生产工作区与卡片状态](../09-设计批量生产工作区与卡片状态.md)
- 上游依据：[批量生产数据模型](./02-批量生产数据模型.md)、[可恢复任务调度与自动资源控制设计](./05-可恢复任务调度与自动资源控制设计.md)、[项目脚本同步与批次快照设计](./06-项目脚本同步与批次快照设计.md)、[联合分配器与差异性规则设计](./08-联合分配器与差异性规则设计.md)

## 给非技术人员的结论

用户确认采用原型 B「成片总览」作为批量生产主界面。它不是一个要求用户反复点“下一步”的向导，而是一张会随生产进度变化的工作台：上方永远先说这批正在做什么，中间显示真实数量和五个阶段，下方只展示当前最需要看的设置、进度或成片卡片。

这张工作台有三个主要画面：

1. **准备中**：把本批素材、项目文案和整批默认值并列放好。代理与 LUT 默认关闭，用户设置好后只点一次“开始批量生产”。
2. **生产中**：后台自检后自动开跑，主界面显示当前阶段、真实完成数量、运行／等待／失败数量和可用成片；电脑性能、磁盘、重试记录等放进“任务详情”。
3. **待检查**：以成片卡片为中心，按已完成、处理中、需处理和失败筛选。成功一条就能先播放或导出，不必等待整批全部结束。

原型 C 的三栏检查界面不作为常驻主页面。它有价值的部分被收进“点击一张成片卡片后打开的侧边详情”：只有用户想处理某一条时，才显示单条重试、重新分配、分配说明和“进入详细编辑器”。这样日常界面简单，深度能力仍然找得到。

## 原型结论

本票用不接 API、不读数据库、不运行 FFmpeg 的抛弃式网页原型比较了三种方向：步骤向导、成片总览和三栏检查工作台。用户依次确认了方案 B 的准备中、生产中和待检查三个状态：整体视觉好看，生产进度看得懂，检查与处理入口也清楚。

被确认的方案 B 包含：

- 顶部批次摘要和唯一主操作。
- 四个最重要的数量，不在首页堆技术指标。
- 横向五阶段进度轨道。
- 准备阶段的三块编号设置区。
- 生产阶段的真实进度、后台队列摘要和逐条出现的成片卡片。
- 检查阶段的状态筛选、多选导出和结果卡片网格。
- 批次任务详情与单条成片详情分层。

原型已经回答布局问题并删除；本文件是后续正式实现的依据。

## 1. 一个批次只有一个长期工作区

一个批次从草稿、开跑、暂停、部分完成到全部完成始终使用同一个工作区和同一个批次身份。刷新页面、关闭窗口或重启应用后，重新进入该批次必须回到真实状态，不能回到初始假页面。

工作区不是调度器状态表的直接翻版。它读取批次、当前批次版本、成片计划、当前成片版本、生产任务和正式产物，形成面向用户的汇总视图。React 页面只消费这份视图，不自行猜测“完成”或拼接任务状态。

建议由独立的批量生产工作区 Module 提供以下 Interface，具体数据库表和 route 在兼容迁移票中落定：

```text
getBatchWorkspace(projectId, batchId) -> BatchWorkspaceView
startBatch(projectId, batchId, expectedDraftRevision) -> StartResult
setBatchIntent(projectId, batchId, run | pause | stop) -> BatchWorkspaceView
retryOutput(projectId, batchId, outputPlanId, failedTaskId) -> BatchWorkspaceView
reallocateOutput(projectId, batchId, outputPlanId, reason) -> BatchWorkspaceView
setCurrentArtifact(projectId, batchId, outputPlanId, artifactId) -> BatchWorkspaceView
```

`projectId + batchId` 是工作区的访问边界；从第 4 步视频引入的来源继续保留自己的 `shotSetId`，不能跨分镜组自动补素材。组件不直接查询 SQLite，桌面壳也不解释业务状态。

## 2. 主界面固定分成四层

### 第一层：批次摘要

只回答三个问题：这是哪一批、现在正在做什么、用户此刻最重要的操作是什么。

- 准备中：显示“准备本次批量生产”和“开始批量生产 N 条”。
- 生产中：显示真实当前阶段和“暂停批次”。
- 已暂停：显示暂停事实和“继续生产”。
- 部分完成或待检查：显示“X / N 条可用”和“导出选中”。
- 已停止：显示已经保留的成功数量，不提供误导性的继续按钮；如需再次生产，应形成明确的新批次版本或新动作。

这里始终只有一个视觉主按钮。“任务详情”是次要入口。

### 第二层：四项关键数量

四项数量随阶段变化，但都来自持久事实：

- 准备中：本批素材、启用文案、计划成片、性能模式。
- 生产中：素材已分析、正在处理、计划成片、电脑负载。
- 待检查：可导出、处理中、需处理、失败待重试。

不能把动画、估算百分比或尚未落库的临时计数当作真实数量。

### 第三层：五阶段轨道

固定使用“准备素材 → 分析素材 → 准备文案 → 联合分配 → 批量导出”。轨道只告诉用户生产走到哪里，不要求每一步人工确认，也不是新的任务状态机。

### 第四层：当前内容

- 准备中显示三块设置。
- 生产中显示当前真实进度、后台任务摘要和已经建立的成片卡片。
- 待检查显示筛选器、批量选择与成片卡片网格。

## 3. 五阶段如何映射到持久事实

| 用户阶段 | 读取的持久事实 | 主界面怎么显示 | 完成条件 |
|---|---|---|---|
| 准备素材 | 批次草稿选择、素材身份、来源在线状态、代理与 LUT 选择 | 素材数量、来源摘要、代理／LUT 默认值 | 开跑时本批素材池已经冻结并通过必要核验 |
| 分析素材 | 批次采用的素材分析版本及分析任务 | 已完成素材数／总数、当前分析文件、运行与等待数 | 每份必需素材已有可用分析版本，或受影响项已进入明确阻塞 |
| 准备文案 | 自动同步的项目脚本、外部文案、启用状态、生成份数和脚本快照 | 文案数量、计划成片总数、标题自动继承 | 开跑时正文、标题、来源版本和份数已经冻结 |
| 联合分配 | 分配运行、成片计划、当前成片版本、差异报告和锁定冲突 | 已建立卡片数、可继续项和需处理项 | 每张目标卡片已有候选版本，或有明确的单条阻塞原因 |
| 批量导出 | TTS、字幕、渲染、校验、发布任务和正式产物 | 每条的等待／处理／可用／失败状态，FFmpeg 真实媒体时间进度 | 每条计划拥有可用正式产物，或稳定停在失败、需处理、暂停、停止状态 |

后台自检不是第六阶段。用户点击开始后，先持久化批次版本和“正在检查生产条件”的任务，再在批次摘要区域直接显示这件事；通过后自动进入分析。只有必须补素材、密钥、磁盘或 LUT 的问题才打断用户。

项目文案和素材分析可能早已准备好，因此轨道允许某阶段瞬间完成或复用旧结果。轨道的当前项由尚未完成的必要工作推导，不能只靠前端按时间顺序递增。

## 4. 批次整体状态与工作区画面

批次保存自己的整体状态和用户期望，界面再将其映射为简单画面：

| 持久事实 | 主画面 | 用户看到的结论 |
|---|---|---|
| 尚未建立冻结批次版本 | 准备中 | 仍可修改素材、文案、份数和默认值 |
| 已开始且存在等待／运行／重试等待任务 | 生产中 | 当前阶段、真实进度与已成功结果 |
| 用户期望暂停，仍有任务在安全收尾 | 正在暂停 | 正在保存可恢复状态，不假装已暂停 |
| 所有活动任务稳定为暂停 | 已暂停 | 已完成结果保留，可以继续 |
| 部分计划已有正式产物，部分稳定失败、阻塞或停止 | 待检查／部分完成 | 成功项可用，失败项单独处理 |
| 所有计划都有通过校验的当前正式产物 | 待检查／已完成 | 可以播放、选择和批量导出 |
| 用户已停止未完成工作 | 已停止 | 已成功结果保留，未完成项不再自动运行 |

批次不使用一个百分比决定是否“完成”。例如用户要求 `N` 条，其中 `N-2` 条成功、2 条失败，就是稳定的部分完成；页面不能把整个批次涂成红色失败，也不能隐藏已经成功的结果。

## 5. 成片卡片是稳定计划，不是一次任务

一张卡片永久对应一个 `Output Plan`。用户重试、重新分配、进入编辑器或重新导出，都只是在这张卡片下面增加任务尝试、成片版本或正式产物，不新建一张“第 N+1 条”卡片。

卡片始终显示：

- 脚本快照标题；同一脚本的多条成片标题相同。
- “文案 X · 第 Y 条”和当前成片版本。
- 当前正式产物的封面底图或明确占位图。
- 可用时长。
- 一个用户状态标签和一句下一步说明。
- 与当前状态匹配的少量操作。

封面标题自动来自脚本快照；批量差异只尝试更换封面底图，不篡改标题。

## 6. 卡片状态是汇总结果，不直接等于任务状态

工作区 Module 根据“是否有可用当前产物、是否有更新版本、必要任务状态、阻塞和差异提醒”计算卡片状态。前端不能把最后一条任务行的状态直接当作成片状态。

按以下优先规则显示：

| 卡片状态 | 条件 | 卡片主操作 |
|---|---|---|
| 已完成 | 有通过校验的当前正式产物，且没有必须展示的提醒 | 播放、选择导出、更多 |
| 需处理 | 有非阻塞差异提醒；或有可用旧产物但新版失败／修改后待重新导出；或存在需要用户决定的锁定、离线、LUT 等阻塞 | 查看原因；能导出的旧产物仍明确标出“旧版可用” |
| 处理中 | 当前版本存在运行任务，且尚无更高优先级的用户问题 | 显示当前阶段；FFmpeg 可测时显示真实百分比；进入任务详情 |
| 等待中 | 任务已建立但仍在等待依赖、资源或队列 | 显示在等什么；进入任务详情 |
| 已暂停 | 批次暂停导致该条不再继续领取工作 | 跟随批次继续，不提供重复的单条继续按钮 |
| 失败待重试 | 没有可用当前产物，必要任务已经失败且允许人工重试 | 重试这一条、查看详情 |
| 已停止 | 没有可用产物且用户已经停止这条未完成链路 | 查看详情；不自动重启 |

如果旧版本已经成功而新版导出失败，卡片不能退化成“整条失败”并藏掉旧结果。它显示“需处理：新版导出失败，旧版仍可播放／导出”，让用户选择重试新版或把旧版继续设为当前成片。

“素材区间可能重复”等非阻塞提醒不等于失败。卡片可标为“需处理”，同时清楚说明当前成片是否仍可导出。

## 7. 筛选、选择与逐条可用

待检查区提供固定筛选：全部、已完成、处理中、需处理、失败。等待中、已暂停和已停止可按数量需要归入“处理中”视图，但标签保留自己的准确文字；任务详情可进一步精确筛选。

卡片在联合分配建立计划后就出现，不等整批完成。任何一条通过发布校验后立即可以播放和选择导出。批量选择只选择“用户要导出的卡片”，不改变卡片状态，也不默认把失败项混入导出。

点击“导出选中”时：

- 已有可导出正式产物的卡片进入本次导出集合。
- 只有非阻塞提醒的卡片允许导出，但动作前用简短摘要说明提醒数量。
- 没有正式产物、正在处理或被阻塞的卡片不会进入导出集合，并明确说明跳过了哪些项。
- 不能为了凑齐用户勾选数量而导出临时文件、失败文件或旧未校验文件。

## 8. 点击卡片后的轻量详情

主界面不常驻三栏专业编辑器。点击卡片或“更多”打开侧边详情，显示：

- 当前状态、当前版本和仍可用的历史正式产物。
- 快速播放或查看封面。
- 失败时的“重试这一条”。
- 非失败状态下的“重新分配这一条”。
- “进入详细编辑器”。
- 本条用了多少镜头和原素材、封面底图、分配提醒摘要。
- “查看分配与任务详情”的深层入口。

侧边详情中的文案必须重复说明：“只修改这条成片，不会改变同批次其他成片。”

进入现有详细编辑器时传入明确的项目、批次、成片计划和成片版本身份。编辑器保存产生新的成片版本；只有通过正式渲染与发布校验后，才更新当前成片。返回工作区时恢复原筛选、滚动位置和选中卡片。

## 9. 重试、重新分配和历史版本

### 重试这一条

- 对失败的同一生产任务创建新任务尝试。
- 不改变生成份数、成片计划身份、已确认镜头或其他卡片。
- 有远端任务 ID 时先确认旧任务结果，避免重复付费。
- 成功后更新当前版本的结果；旧失败尝试留在任务详情。

### 重新分配这一条

- 只为目标成片计划建立新的分配运行结果和成片版本。
- 其他卡片、用户锁定和已有正式产物保持不变。
- 新版本完成前旧版继续可用；新版本失败也不覆盖旧版。
- 结果说明换了哪些镜头和原因；没有更好组合时保持旧版并说明。

### 历史版本

- 卡片默认展示“当前成片”，不是简单展示最后一次尝试。
- 历史正式产物可播放并可重新设为当前成片，文件不因切换而删除。
- `Output Revision` 和 `Artifact` 身份决定历史版本，不依赖文件名、任务序号或最后更新时间猜测。

## 10. 主界面与任务详情的信息边界

### 主界面只保留

- 当前阶段和一句正在做什么。
- 真实完成数量或可测百分比。
- 可用、处理、需处理和失败数量。
- 卡片状态与一个明确下一步。
- 暂停／继续、导出选中和任务详情入口。

### 批次任务详情保存

- 每个任务的阶段、依赖、等待原因、尝试次数和真实进度。
- 远端供应商确认、自动重试、失败代码和可操作建议。
- 当前自动性能档位、升降档原因、内存压力和并发令牌。
- 项目盘剩余空间、预计临时空间、代理缓存占用和清理入口。
- 分配差异、被迫复用、素材不足和具体受影响卡片。
- 可用时的 ETA 范围；没有可靠历史样本时不显示。

主界面不显示 CPU 百分比、内存数字、线程数、FFmpeg 命令、供应商原始错误或不断跳动的不可靠倒计时。

## 11. 真实进度与刷新恢复

- 素材分析显示“已完成素材数 / 总素材数”。
- TTS 和字幕显示“已完成句段数 / 总句段数”。
- FFmpeg 导出使用 `out_time / 成片总时长` 的真实百分比，并同时显示“已处理 X / Y 秒”。
- 远端供应商没有百分比时只显示阶段和已等待时间，不伪造数值。
- 批次汇总来自各任务已持久化的最后真实进度；实时推送中断时页面回退为定时读取快照，不把任务误判为失败。

页面首次进入先读取完整 `BatchWorkspaceView`，之后再接收增量更新。每条更新携带任务或工作区版本；旧消息、旧租约和迟到回调不能覆盖较新状态。刷新或应用重启后，以 SQLite 中的稳定状态和恢复流程为准，不依赖浏览器内存、`localStorage` 或尚未完成的动画。

## 12. 暂停、关闭窗口与停止

- 点击暂停后立即显示“正在暂停”，直到运行任务进入稳定可恢复状态；不能瞬间谎称已暂停。
- 已暂停后，用户可继续，已经成功的分析和成片不会重做。
- 关闭桌面窗口不暂停批次，工作区重新打开后继续显示后台进度。
- 明确退出应用时，由桌面 main 按既定规则请求活动批次安全暂停。
- 停止是最终动作，必须二次确认；它停止未完成工作，但保留已经成功的分析、成片和历史记录。

## 13. Seam 与 Adapter

### 工作区查询 Seam

`BatchWorkspaceService` 读取批次及相关对象，生成稳定的 `BatchWorkspaceView`。SQLite 是生产 Adapter；测试使用内存仓储。页面不知道表名和任务租约细节。

### 实时更新 Seam

页面通过统一的工作区事件 Interface 接收更新。正式实现可以使用 SSE、轮询或桌面 IPC Adapter，但事件语义必须相同；切换传输方式不能改变卡片状态规则。

### 播放与文件操作 Seam

浏览器开发形态使用受控本地媒体 URL；桌面形态通过白名单文件桥播放、打开目录或导出。React 组件不接收任意绝对路径，也不直接调用 Node 文件 API。

### 详细编辑器 Seam

批量工作区只传递稳定身份和打开意图，复用现有详细编辑能力。编辑器不直接改写其他成片计划，返回的新版本必须经工作区 Module 登记。

状态聚合、可导出判断和主操作选择暂时只有一套正式业务规则，属于工作区 Module 的 Implementation，不为 Web 与桌面复制两套判断。

## 14. 实现验收

1. 准备中同时显示素材、自动导入文案、生成份数和整批默认值；代理与 LUT 默认关闭。
2. 用户点击一次开始后先后台自检，再自动进入生产；没有额外确认页。
3. 刷新准备中、生产中、暂停中、部分完成和已完成批次，均恢复到数据库真实状态。
4. 五阶段轨道由真实持久事实推导；复用已有分析时允许阶段直接完成。
5. 素材分析显示真实数量，FFmpeg 显示真实媒体时间比例，远端未知阶段不伪造百分比。
6. 计划 6 条时始终只有 6 张稳定卡片；失败重试和单条重新分配不会增加卡片。
7. 一条成片先成功时立即可播放和导出，不必等其他五条。
8. 4 条成功、1 条失败、1 条处理中时，批次显示部分完成，成功项不被失败项回滚。
9. 筛选数量与卡片实际状态一致；刷新和增量更新后不会重复、丢失或跳回旧状态。
10. 有可用旧版但新版失败时，卡片明确显示旧版仍可用，不把整条误报为失败。
11. 非阻塞差异提醒说明是否仍可导出；锁定冲突、离线素材或磁盘不足提供明确处理入口。
12. “重试这一条”只增加目标任务尝试；“重新分配这一条”只增加目标成片版本。
13. 进入详细编辑器、保存、返回后保持原批次、筛选和卡片位置，其他成片不变。
14. 任务详情能查看性能保护、空间、代理、重试和差异诊断；主界面不堆这些信息。
15. 暂停、继续、停止、关闭窗口和应用重启遵守已确定的持久调度规则。
16. 卡片操作使用键盘可达，状态不仅依赖颜色，进度条具有可读名称和真实数值。
17. 单条精准混剪入口和行为保持不变；批量工作区不引入 `mixcut_sessions` 或第二套编辑状态机。
18. 用户用真实规模验收时，能够一眼回答“现在做到哪、多少条可用、哪几条要处理、下一步点哪里”。
