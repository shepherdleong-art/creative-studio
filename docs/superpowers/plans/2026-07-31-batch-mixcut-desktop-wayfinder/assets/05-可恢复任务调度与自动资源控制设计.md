# 可恢复任务调度与资源模式控制设计

- 决定日期：2026-07-31
- 决定性质：持久任务、用户控制、进度与本机资源调度设计，不代表正式调度器已经实现
- 对应票据：[设计可恢复任务调度与自动资源控制](../05-设计可恢复任务调度与自动资源控制.md)

> **决定修正（2026-08-01）**：本票原型曾采用普通压力自动升降档。用户在真实验收评审中最终确认：默认全速；普通压力只提醒并让用户选择继续全速或降低速度；只有磁盘不足或内存危险才保护性暂停。本文以下内容已按最终决定修正。
- 上游依据：[批量生产数据模型](./02-批量生产数据模型.md)、[项目素材库与原文件引用设计](./04-项目素材库与原文件引用设计.md)

## 给非技术人员的结论

批量混剪不能像一个网页按钮那样“点下去后希望它自己跑完”。它需要一本一直写在本地数据库里的任务账本：

- 每一项分析、配音、字幕、规划和导出都知道自己正在做什么。
- 每次真正执行都会留下任务尝试，失败重试不会偷偷多出一条成片。
- 浏览器页面刷新、桌面窗口关闭甚至应用崩溃，都不会抹掉任务账本。
- 系统根据电脑硬件先设硬安全上限，默认全速；持续负载偏高时提醒用户决定是否降低并发。
- 普通界面只显示“正在分析素材 12/48”“正在导出成片 3/20 · 42%”等必要信息，复杂性能数据放在任务详情。

这套设计不会承诺每一种远端供应商任务都能被强行取消。若供应商已经接收任务但没有取消能力，系统必须诚实显示“正在暂停”，等待唯一一次远端结果确认；它不会重复提交和再次扣费。

## 已验证的十三个场景

本票用一个不接数据库、不运行 FFmpeg 和 AI 的终端逻辑原型逐步验证，用户确认以下行为：

1. 开始后后台自检并直接开跑，不增加多余确认页面。
2. 多个 worker 原子领取任务，不会重复执行同一项工作。
3. 连续压力偏高后出现提醒，系统不擅自降低普通任务速度。
4. 用户选择降低速度后只影响后续领取，真实减少并发，已经运行的普通任务不被突然杀掉。
5. 用户可以再次选择全速，但永远不超过硬件安全上限与供应商限制。
6. 暂停遇到不可取消的已提交远端任务时，不假装立即停止。
7. 远端确认结束后进入稳定暂停，不启动配音、字幕和导出。
8. 继续时复用已完成分析、规划、配音和字幕，只做剩余工作。
9. 导出高负载时继续当前 FFmpeg，暂缓下一条导出。
10. 异常重启后旧尝试失效，任务恢复为可领取状态，不残留假 `running`。
11. 恢复后的执行是新的任务尝试，失败可以单独重试。
12. 多次尝试仍对应同一个成片计划，成功校验后才原子发布正式产物。
13. 停止剩余任务后，已发布成片保留，批次稳定显示部分完成。

原型已经完成验证并按抛弃式原型约定删除，本文件保留其决定。

## 1. 现有工程可以保留什么

当前工程并非没有队列，而是能力分散：

| 现有位置 | 已有能力 | 当前缺口 |
|---|---|---|
| `lib/queue.ts` | 图片任务并发、原子条件领取、AbortSignal、重试、项目暂停 | 暂停只阻止新领取，运行状态主要在内存，缺少统一进度和资源控制 |
| `lib/video-queue.ts` | 视频任务提交、远端任务 ID、轮询、取消信号、崩溃后回到等待 | 与图片和成片使用另一套状态，供应商不支持取消时缺少统一确认状态 |
| `lib/final-edit/workspace.ts` | 成片准备阶段与单调进度、输入快照、分析／配音／字幕／匹配 | 大准备任务内部包含很多工作，无法独立暂停、重试和调度资源 |
| `lib/final-edit/worker.ts` | 渲染原子领取、真实 FFmpeg 进度、重启恢复、校验后原子发布 | 单进程布尔锁，没有租约、统一取消、任务尝试和动态资源档位 |
| `lib/final-edit/heavy-job-lock.ts` | 在本进程中串行化重任务 | 状态不持久，无法说明为何等待，也不能跨重启恢复 |
| `lib/ffmpeg.ts` | 子进程超时、真实输出时间进度、错误尾部 | 没有统一 AbortSignal、优雅停止和跨平台进程树回收 Interface |

实现方向不是再写一套“批量队列”，而是把现有成片任务、worker 和重任务锁深化为统一的持久 `ProductionScheduler` Module。现有 FFmpeg 进度、不可变任务目录、原子发布、供应商 Adapter 和缓存能力继续复用。

模块 1–4 的图片／视频生成队列不在首轮强制迁移范围，避免一次改动整个产品；但新的调度状态与 Adapter Interface 应允许后续逐步接入，不能再复制一种新状态机。

## 2. `ProductionScheduler` 是一个深 Module

外部调用者只需要学习一个小 Interface：

- 提交一组带输入快照的生产任务。
- 读取批次的主进度与任务详情。
- 对批次或单个失败任务执行暂停、继续、停止和重试。
- 唤醒调度，领取当前允许执行的工作。
- 在应用启动和退出时执行恢复或优雅停机。

原子领取、租约、尝试、退避、资源令牌、供应商确认、进度聚合和发布检查都藏在 Module 的 Implementation 中。页面、route、桌面 main、FFmpeg renderer 和各供应商 Adapter 不得各自重新解释任务状态。

调度 Module 内部有两个真实 Seam：

### 执行 Adapter Seam

分析、指纹、代理、AI 规划、TTS、字幕、预览和正式渲染实现同一个任务执行 Interface。每个 Adapter 声明：

- 自己接受的任务种类和资源类型。
- 能否合作取消，是否支持远端取消，是否拥有远端任务 ID。
- 如何执行或确认已经提交的远端工作。
- 如何报告真实阶段、数量或百分比。
- 成功结果如何校验，哪些输出可以复用。

生产 Adapter 与内存测试 Adapter 同时存在，因此这是一个真实 Seam。测试通过调度 Module 的外部 Interface 观察结果，不越过它检查内部队列数组。

### 资源探测 Adapter Seam

macOS、Windows 和确定性测试各有资源探测 Adapter，统一返回 CPU、内存压力、项目盘空间和程序响应指标。不能把 macOS 专属命令或 Windows 专属统计直接散落到调度逻辑中。

`os.freemem()` 之类原始“空闲内存”不能单独作为判断依据：macOS 会把可回收缓存算成已使用，健康电脑也可能显示极低空闲值。调度只消费操作系统内存压力与本进程实际占用等经过 Adapter 归一化的指标。

## 3. 一套任务与尝试模型

生产任务保存“要完成什么”，任务尝试保存“某一次实际做得怎样”。两者不能合并。

### 生产任务必须保存

- 稳定任务身份、项目、批次版本和可选的成片计划／成片版本身份。
- 任务种类、输入快照、资源类型、优先级和依赖任务。
- 当前稳定状态、当前阶段、真实进度、重试策略和结果引用。
- 幂等请求键，防止同一用户动作重复建立等价任务。
- 用户期望状态：运行、暂停或停止。

### 任务尝试必须保存

- 尝试身份、序号、领取者和有限期租约。
- 开始、心跳、结束时间与退出原因。
- 执行 Adapter 版本、实际采用的来源和资源档位。
- 远端供应商任务 ID、轮询状态和最后确认时间。
- 最后一次真实进度、输出候选、错误代码和可重试判断。
- 本次预估／实际成本信息；重试不能抹掉旧尝试的成本记录。

重试只为同一生产任务增加任务尝试。它不能增加成片计划、生成份数或成片卡片。

## 4. 状态与原子领取

生产任务的稳定状态为：

| 状态 | 含义 |
|---|---|
| 等待 | 依赖满足后可以被领取 |
| 运行 | 当前存在一个有效租约与运行尝试 |
| 暂停 | 用户要求保留任务但暂不执行 |
| 阻塞 | 缺少素材、磁盘、供应商配置或其他用户可处理条件 |
| 重试等待 | 失败可重试，但要等待退避或限流窗口 |
| 成功 | 结果已校验并登记 |
| 失败 | 当前没有自动重试机会，需要查看或人工重试 |
| 已停止 | 用户结束未完成工作，不再自动领取 |

领取任务必须在一个数据库事务中完成：只有状态、依赖、用户期望、可执行时间和资源令牌同时满足时，才能把任务改为运行并创建尝试。条件更新只允许一个 worker 成功。

租约拥有到期时间，worker 定期续租。只有持有有效租约的尝试能写入进度和成功结果；过期尝试的迟到回调不能覆盖新尝试。

## 5. 后台自检

用户在前面已经选好素材、脚本、条数和默认值后，点击开始不再进入一个新的确认向导。调度器先建立“后台自检”任务，并在主进度直接显示“正在检查生产条件”。

自检至少核对：

- 批次输入快照完整，所选素材在线且内容已核验。
- 需要的分析、AI、TTS 供应商已启用并配置。
- FFmpeg 可以真实执行，输出目录可写。
- 项目盘剩余空间高于预计任务空间与安全预留。
- 用户启用的代理或 LUT 文件可以读取。
- 不存在同一幂等请求键的已运行任务。

全部通过后自动进入分析，不要求用户再次点击。普通警告写入任务详情；只有必须补素材、密钥、磁盘或 LUT 的问题才把相关任务设为阻塞，并在主界面给出一个明确处理入口。

## 6. 真实进度，不制造“看起来在动”的假数字

每个执行 Adapter 使用统一进度报告：

- 当前阶段与用户可读说明。
- 已完成数量／总数量，或已处理媒体时长／总时长。
- 可测时提供 `0–1` 百分比；不可测时明确标为未知。
- 可选的速度、预计范围和诊断信息只进入任务详情。

具体例子：

- 素材登记／分析：`已完成素材数 / 总素材数`，单素材可继续显示抽帧或分析阶段。
- TTS／字幕：`已完成文案段数 / 总段数`。
- FFmpeg：使用 `out_time / 成片总时长` 的真实比例。
- 远端 AI：如果供应商只返回“处理中”，显示阶段和已等待时间，不伪造 37%、68% 等数字。
- 文件复制／指纹／代理：使用已处理字节或媒体时长。

批次总进度只聚合已经完成或能够真实度量的阶段。不可测远端任务运行期间，总进度可以暂时不动，但当前阶段必须持续可见。

### 主界面

只显示：当前阶段、总进度条、成片完成数量、运行／等待／失败数量和一个任务详情入口。例如：

> 正在分析素材 12/48 · 总进度 21%

> 正在导出成片 3/20 · 42%

### 任务详情

展示每个任务、尝试次数、真实阶段、性能保护原因、远端确认状态、错误、已等待时间和可用时的 ETA。ETA 只有在拥有足够历史样本后才显示范围，不能在主界面用一个不可靠倒计时制造焦虑。

进度写入要节流，例如阶段变化、百分比跨过可见刻度或间隔一定时间才落库，避免 FFmpeg 高频输出持续占用 SQLite；界面仍可在本地平滑显示最后一个真实区间，但不得写出超过真实进度的数值。

## 7. 资源监测、提醒与用户选择

### 开跑前计算硬安全上限

使用以下事实确定每一类资源的最大并发：

- 操作系统允许使用的 CPU 并行度与逻辑核数。
- 总物理内存和当前系统内存压力。
- 项目所在磁盘的剩余空间，而不是系统其他磁盘空间。
- 供应商自己的并发、速率和费用限制。
- 任务是轻本地、重本地、磁盘密集还是远端请求。

16GB 内存加 SSD 是大批量稳定性的标准验收线；8GB 电脑可以运行，但不承诺相同规模或速度。远端请求并发由供应商上限决定，不能因为电脑 CPU 多就无限增加。

用户选择的“全速”是在硬安全上限内尽可能领取工作，不是无限创建 FFmpeg 或突破供应商限流。默认模式为全速，不再从保守档自动升档。

### 运行中动态反馈

调度器周期采样：

- 一段窗口内的 CPU 利用率，不使用单次尖峰。
- 操作系统归一化内存压力和本地进程实际占用。
- Next 本地服务事件循环延迟，反映页面和任务控制是否卡顿。
- FFmpeg 实际处理速度、任务耗时和错误率。
- 项目盘剩余空间与预计尚需空间。

温度不作为 V1 核心依据，因为 macOS／Windows 的稳定、无特权温度来源并不一致。原始空闲内存、单次 100% CPU 和风扇声音也不能单独触发调度决定。

### 提醒、选择与安全红线

- 指标连续多个采样窗口偏高后显示一次清楚提醒，避免瞬时尖峰反复打扰用户。
- 提醒提供“继续全速”和“降低速度”；用户没有操作时保持全速，不静默改变模式。
- 用户选择降低速度后，只停止领取新的重任务或减少轻任务并发，不杀掉已经执行到一半的普通工作。
- 用户可以随时重新选择全速，但不会突破开跑前硬安全上限和供应商限制。
- 磁盘剩余空间低于“预计剩余写入量 + 安全预留”或操作系统内存压力进入危险级别时属于安全红线：停止领取新的重任务，并按安全协议保存为可恢复尝试。
- 每次提醒、选择与保护暂停都记录原因；主界面只显示用户可理解的提示，具体指标留在任务详情。

原型使用的采样窗口只验证监测和降并发机制，不作为生产阈值。具体提醒窗口和安全红线必须在 [确定验证矩阵与真实规模验收](../11-确定验证矩阵与真实规模验收.md) 中用目标电脑和可变真实素材校准。

## 8. 暂停、继续与停止

### 暂停

1. 先持久化批次的期望状态为暂停，立即停止领取新任务。
2. 本地可中断任务收到 AbortSignal；FFmpeg 通过统一子进程 Interface 真实停止。本次尝试记为已中断，继续时创建新尝试。
3. 可取消的远端请求调用 Adapter 的取消能力，并确认取消结果。
4. 已提交但供应商不支持取消的任务保存远端任务 ID，批次显示“正在暂停”；系统只保留一次结果确认，不再提交相同请求。
5. 所有需要确认的任务稳定后，批次进入已暂停。成功结果继续保留。

### 继续

- 先核对远端确认结果、素材在线状态和安全自检。
- 成功任务不重做；已中断或仍等待的任务重新进入可领取状态。
- 无法从中间检查点继续的 FFmpeg 会从本次任务开头重新执行，但不会重跑素材分析、配音或其他已成功任务。

### 停止

- 持久化批次为停止，未领取任务进入已停止。
- 运行中的本地任务真实终止；可取消远端任务请求取消。
- 不可取消的远端任务继续只做结果确认和成本登记，不再触发后续生产，也不能在停止后自动发布新成片。
- 已成功分析、配音、正式产物和历史尝试继续保留；停止不是删除。
- 部分成功的批次显示部分完成，用户仍可使用已发布成片。

关闭桌面窗口不触发暂停。明确退出 Creative Studio 时，桌面 main 请求所有活动批次暂停并等待稳定状态，再回收本地服务和子进程。

## 9. 重试与远端重复付费防护

- 失败重试创建新的任务尝试，同一任务和成片计划身份不变。
- HTTP 429、临时网络错误和服务端错误按 Adapter 策略退避，并尊重供应商 `Retry-After`。
- 输入无效、素材离线、密钥缺失和磁盘不足进入阻塞，不进行无意义自动重试。
- 远端任务一旦取得供应商任务 ID，超时、断网或崩溃后必须先查询该 ID；不能直接重新提交。
- 只有供应商明确返回失败／不存在，且幂等与费用规则允许时，才创建新的远端尝试。
- “远端已经成功、本地下载失败”保留远端结果位置并尝试恢复下载，不重新付费生成。
- 自动重试次数、实际尝试次数和成本都在任务详情可见。

## 10. 异常退出与恢复

应用启动时执行一次恢复：

1. 找出租约已经过期或属于旧运行实例的运行尝试。
2. 把这些尝试结束为已中断或待确认，不允许继续显示运行。
3. 有远端任务 ID 的尝试进入远端确认；没有远端任务的本地工作回到等待／重试等待。
4. 正式渲染使用不可变任务目录；未校验的临时文件不能登记为正式产物。
5. 成功输出在原子发布与项目产物登记完成后才算成功；发布过程恢复时先核对登记和目标文件，避免重复文件。
6. 所有依赖已成功且批次期望为运行的任务重新进入调度；暂停或停止的批次不会被擅自启动。

单实例桌面壳降低双调度器风险，但数据库原子领取和租约仍然必须存在；正确性不能只依赖“理论上只有一个进程”。

## 11. 多批次公平与优先级

调度是整个应用级的，不为每个项目分别启动一个无限 worker pool。

- 资源令牌在所有项目和批次间共享。
- 同一优先级按批次轮转领取，防止一个大批次长期饿死其他批次。
- 用户刚点击继续或手动重试的任务可以获得一次交互优先机会，但不能永久压过其他任务。
- 正式导出不和代理生成同时抢占多个重任务令牌；V1 的 16GB 安全档通常一次只运行一个。
- 供应商并发按供应商身份分别计数，避免两个批次共同突破限流。

## 12. 与现有单条精准混剪的兼容

- 保留 `final_edit_jobs` 的输入快照、真实阶段进度和不可变 render job 目录语义。
- `FinalEditWorkspace` 继续拥有单条精准混剪业务规则；调度 Module 只决定任务何时执行和如何恢复，不把领域逻辑搬进 worker。
- 现有 prepare 大任务应逐步拆成可复用分析、TTS、字幕、匹配和预览任务，拆分期间保留兼容 Adapter，不能一次性破坏单条模式。
- `final_edit/worker.ts` 的原子领取、FFmpeg 进度、原子发布和重启回队列逻辑吸收到新 Module，不再并行维护第二套解释。
- `heavy-job-lock.ts` 最终由持久资源令牌替代，避免内存 Promise 链成为不可观察的生产队列。
- 具体表、迁移顺序和旧任务回填交给 [设计兼容迁移与桌面打包](../10-设计兼容迁移与桌面打包.md)。

## 13. 必须通过的实现验收

1. 两个 worker 同时竞争同一任务时，只有一个任务尝试获得有效租约。
2. 旧租约回调不能覆盖新尝试的进度或成功结果。
3. 用户本批选择的素材分析进度显示真实完成数量，远端未知进度不出现伪百分比。
4. 用户暂停后不再领取新任务，本地 FFmpeg 和支持取消的请求真实停止。
5. 不支持取消的远端任务只提交一次，暂停和重启后都先确认远端 ID。
6. 继续不重做已成功分析、配音、字幕和正式产物。
7. 重试三次仍只有一条成片计划和一张成片卡片，并保留三次尝试记录。
8. 进程在渲染 50% 时崩溃，重启后不存在旧 `running`；临时文件不能作为正式产物。
9. 渲染成功后原子发布并登记；此后停止其他任务不删除成功成片。
10. 连续普通压力触发提醒而不是静默降档；用户选择降低速度后并发真实下降，重新选择全速仍不超过安全上限。
11. 磁盘不足或内存危险的安全红线可以暂停新的重任务，并把相关状态保存为可恢复而不是永久失败。
12. 两个项目的批次共享资源但保持数据隔离，不发生长期饥饿。
13. 关闭窗口继续任务；明确退出暂停并回收服务、FFmpeg 和代理子进程。
14. 现有单条精准混剪的准备、预览和导出结果保持兼容。

## 本票明确不决定的内容

- 不决定 SQLite 表名、列名、索引、迁移 SQL 和旧任务回填脚本。
- 不把原型中的 CPU、时间和并发数字直接定为生产默认值。
- 不决定代理编码规格、LUT 缓存键和是否启用硬件编码。
- 不决定批量工作区的最终视觉样式、任务详情抽屉布局和通知形式。
- 不代表跨平台进程树停止、真实供应商取消或目标规模性能已经验收。
