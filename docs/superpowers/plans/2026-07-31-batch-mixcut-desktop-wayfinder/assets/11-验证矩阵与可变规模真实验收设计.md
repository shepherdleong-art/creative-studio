# 验证矩阵与可变规模真实验收设计

- 决定日期：2026-08-01
- 决定性质：批量生产验证分层、可变规模、真实进度、资源提醒、故障恢复、跨平台与真实供应商验收设计，不代表生产代码或真机验收已经完成
- 对应票据：[确定验证矩阵与真实规模验收](../11-确定验证矩阵与真实规模验收.md)
- 研究依据：[规模验收官方资料与现有测试审计](./11-规模验收官方资料与现有测试审计.md)

## 给非技术人员的结论

批量生产不能被固定成“60 条素材、8 份文案、20 条成片”。实际项目可能只要 10 条成片，也可能需要 50 条；素材可能全来自手机，也可能以相机 Log 为主。产品只接受用户本次选择的素材、脚本与每份生成数量，最终计划数 `N` 是这些选择的合计，系统不得擅自增减或把某个测试数字变成产品上限。

验证也不能只靠一句“测试通过”。逻辑、数据库恢复、真实 FFmpeg、macOS 安装包、Windows 安装包、真实供应商和用户实际操作必须分别给出证据。任何一层没有通过，都只能报告对应层级的结果。

性能默认采用“全速处理”。普通高负载只提醒用户选择“继续全速”或“降低速度”，系统不擅自降速；只有磁盘确定不足或系统内存进入危险状态时，才暂停领取新的重任务以保护数据。进度必须来自真实完成数量或 FFmpeg 已处理媒体时间，无法测量的远端阶段宁可只显示状态，也不能伪造百分比。

## 1. 数量与素材不设固定范式

### 用户决定数量

- 用户决定本批选多少素材、启用多少脚本以及每份脚本生成几条。
- 系统把每份生成份数相加得到 `N`，并在开跑前建立恰好 `N` 个稳定成片计划和 `N` 张成片卡片。
- 重试、恢复、重新分配和重新导出只增加任务尝试或成片版本，不得产生第 `N+1` 张卡片。
- 产品不设置固定素材比例、固定成片数或由压力测试数字推导的默认上限。
- 数量很大时可以展示工作量、空间和可能耗时较长的提醒，但不能擅自减少用户选择。
- 只有输入缺失、磁盘确定不足、供应商未配置等无法安全执行的硬问题才能阻塞相关任务，并给出可操作原因。

### 真实验收不规定素材构成

每次用户验收直接使用当期真实项目素材，不要求手机、普通相机、Log、横竖屏或编码格式达到预设比例。开跑前系统扫描并记录本批实际事实：

- 数量、文件身份、来源和在线状态。
- 容器、视频与音频编码、分辨率、帧率、位深、色彩信息、旋转和时长。
- 是否启用代理、选用哪个 LUT、目标输出规格和每份脚本生成数量。
- 无法识别、损坏、无视频流或暂时离线的素材及其处理结果。

测试报告保存本次输入 manifest 与摘要，使结果可追溯，但 manifest 只描述这一次运行，不变成产品范式。

### 内部回归样本与真实验收分开

工程可以保留一小套确定性的正常与问题媒体，用于快速发现升级后的格式、路径、代理、LUT 和错误处理退化。它只属于本地回归证据，不能冒充用户真实素材、真实规模或跨平台验收。

## 2. 电脑基线与产品承诺

- 16GB 内存加 SSD 是 V1 大批量稳定性的标准验收线。
- macOS 至少需要一台较早的 Apple Silicon 16GB 电脑和一台常用配置真机；当前较新的开发机不能独自证明最低基线。
- Windows 至少需要一台普通 x64、16GB、SSD 电脑实际安装验证，静态检查不能替代真机。
- 8GB 电脑不被禁止使用，但不承诺与 16GB 电脑相同的批量规模或速度；仍默认全速，出现普通压力时由用户选择是否降速。
- 不在获得真实样本前承诺固定完成分钟数。验收先证明稳定、可信、可恢复，再记录真实耗时和资源趋势形成后续性能基线。

## 3. 七层验证矩阵

| 层级 | 必须证明什么 | 不能替代它的证据 |
|---|---|---|
| 1. 逻辑 | `N` 个计划、联合分配、锁定、重试、差异事实和状态聚合正确 | 页面看起来正确 |
| 2. 数据库 | 追加迁移、事务、租约、暂停、崩溃恢复、幂等与历史隔离正确 | 仅内存对象测试 |
| 3. 真实媒体 | 打包同源 FFmpeg 能探测、分析、代理、应用 LUT、渲染、校验并发布真实文件 | mock、短路 Adapter 或 job 显示成功 |
| 4. macOS 安装包 | 正式交付形态能安装、升级、读取旧数据、运行批量任务、暂停恢复与卸载保留数据 | `npm run dev` 或 payload 静态检查 |
| 5. Windows 安装包 | Windows x64 真机完成同类安装、路径、盘符、进程和媒体验收 | macOS 通过或 Inno 脚本文本测试 |
| 6. 真实供应商 | 经单独授权后，真实视觉、LLM、TTS 协议的成功、限流、取消／待确认、缓存和成本证据成立 | mock fetch 或本地替身 |
| 7. 用户验收 | 用户用自己的工作方式确认设置简单、进度可信、电脑可用、失败可处理、结果可交付 | 开发者代操作或自动化绿灯 |

每次汇报必须逐层写明“通过、未执行、失败或被外部条件阻塞”，不得把下层证据包装成上层完成。

## 4. 数量可变时的统一硬条件

无论用户选择的 `N` 是多少，都必须满足相同合同：

1. 开跑前恰好建立 `N` 个成片计划；页面、数据库和任务报告数量一致。
2. 任意时刻，等待、运行、可导出、失败、阻塞、暂停和停止等互斥终态的汇总可以解释全部 `N` 条。
3. 单条失败不拖垮其他计划；部分成功结果可以提前检查和导出。
4. 重试仍属于原计划，应用重启后不会多卡片、重复发布或重复收费。
5. 成功 MP4 非空、可完整解码、时长与输出计划一致；封面可读、标题来自对应脚本快照。
6. 每条采用的脚本、素材区间、代理／LUT 身份、任务尝试、产物路径和错误原因可追溯。
7. 项目、分镜组、批次版本和历史版本不串数据。
8. 测试使用多组明显不同的用户选择验证数量变化，但任何测试数字都不成为产品限制。

## 5. 真实进度验收

- 素材登记与分析显示 `已完成素材数 / 本批需处理素材数`；缓存命中标为真实复用完成。
- 当前素材可以显示探测、抽帧、等待 AI、校验和写入等可验证阶段。
- 配音与字幕显示 `已完成句段 / 总句段`。
- 单条 FFmpeg 导出使用 `out_time_us / 计划输出总时长` 计算真实百分比。
- 整批导出显示 `已导出条数 / N`；正在导出的卡片显示自己的真实媒体进度。
- 远端服务没有返回百分比时，只显示提交、等待、校验和已完成数量，不用定时器制造上涨数字。
- 只有进程正常结束、产物校验通过、原子发布完成并登记项目产物后，才能显示 100% 和“可导出”。
- 主界面只保留当前阶段、真实进度和状态数量；速度、等待、错误、重试、成本与技术指标进入任务详情。

## 6. 资源模式与压力验收

### 默认行为

- 性能模式默认是“全速处理”，含义是在应用和供应商的硬安全上限内尽可能领取工作，并非无限创建进程或突破供应商限流。
- 系统持续观察内存压力、应用响应、项目盘剩余空间、FFmpeg 处理表现、电源和平台可用的降速信号。
- 普通 CPU 高占用、界面变慢或持续压力触发提醒：用户选择“继续全速”或“降低速度”。
- 用户没有操作时继续全速；系统不能因为普通压力提示而静默降档。
- 选择“降低速度”后只减少后续领取和并发，不因普通波动突然杀死已经运行的工作；用户可以随时切回全速。

### 安全红线

- 当项目盘剩余空间低于预计剩余写入量与安全预留时，停止领取新的重任务并明确提示清理或更换输出位置。
- 当系统内存进入危险状态、继续领取极可能导致应用或系统崩溃时，停止领取新的重任务并保存可恢复状态。
- 已完成结果不得删除；处于原子发布边界的任务按安全协议完成或回滚，不能留下“数据库成功但文件不存在”。

### 验收方式

在 macOS 与 Windows 正式安装包运行期间分别制造普通高压、用户选择降速、再次切回全速、磁盘不足和危险内存信号。必须证明提醒准确、用户选择生效、界面和暂停入口仍可响应，且安全红线不会损坏任务账本或产物。

具体提醒阈值、持续窗口和硬红线数值由目标真机的多次测量校准并版本化；不使用一个跨平台 CPU 百分比或单次空闲内存快照作为永久规则。

## 7. 差异性验收不设统一及格线

用户要求的数量、素材池大小和人工锁定每次都不同，因此不设置“相似度低于某个百分比才允许导出”的统一阈值。

差异报告只记录可解释事实：

- 时间线是否完全相同。
- 是否采用相同开头和相同来源区间。
- 同一时间位置与全部素材集合的重合程度。
- 镜头顺序、素材区间、封面底图和音乐是否重复。
- 重复来自用户锁定、素材不足，还是算法本可避免却没有避免。

系统以语义和合法时长为前提尽量降低重复。所有相似风险都是可见提醒，不阻止生成或导出；用户可以接受、补素材、解除锁定、手工替换或只对目标成片重新分配。

## 8. 必须覆盖的故障注入

| 场景 | 必须结果 |
|---|---|
| 混入损坏、无视频流、特殊路径或离线素材 | 单条问题可解释，其余素材继续；重开后状态不丢 |
| 视觉／LLM 返回 429、500、超时、无效结构或断连 | 按策略重试；未知远端任务先确认，不能重复提交或伪造进度 |
| 某个脚本或句段 TTS 失败 | 只影响相关计划；已完成项不重做，可单独重试 |
| FFmpeg 非零退出、超时或用户取消 | 子进程回收，临时文件不发布为成功，卡片保留重试入口 |
| `ENOSPC`、`SQLITE_FULL`、I/O 错误 | 停止领取新重任务，成功产物保留，不出现假成功 |
| 数据库事务提交前后故障 | 成片、任务和产物登记要么完整存在，要么完整回滚 |
| 分析中、远端等待中、渲染中或发布边界退出应用 | 重启后旧 `running` 被审计，恢复／待确认，不重复卡片、文件或费用 |
| 暂停、退出、重开、继续 | 成功缓存复用，未完成任务从持久状态继续，进度不倒退 |
| 对某一条重试或重新分配 | 只改变目标计划及其历史，其他计划保持不变 |

这些测试由工程环境主动注入，不要求用户破坏自己的项目。

## 9. 跨平台稳定性

- 同一个候选安装版本必须分别在 Apple Silicon macOS 和 Windows x64 上验收。
- 每个平台至少连续完成三次代表性真实批量运行，排除偶然成功；每次可由用户选择不同素材、脚本和数量，并完整记录实际输入。
- 每个平台还要覆盖全新安装、旧版升级、暂停重开、原文件重新定位、代理／LUT、卸载重装保留数据。
- “连续三次”是平台稳定性证据，不是用户批次数量、成片数量或素材构成限制。
- 只有两个平台都满足相同硬条件，才能报告跨平台通过。

## 10. 真实供应商必须逐次授权

真实测试不是永久授权。每次调用前必须向用户说明：

1. 目标供应商与具体协议／模型。
2. 将发送的视频抽帧、图片、脚本文字或配音文本范围。
3. 预计请求数量、可能费用和供应商侧保留边界。
4. 将在本地创建的持久任务、缓存、日志和产物。

只有收到本次明确许可后才能执行，并只发送完成测试所需的最少数据。真实供应商验收覆盖正常成功、限流／可重试错误、取消或超时后的状态确认以及重启缓存复用；它不能替代本地确定性故障注入。

## 11. 用户最终验收

技术层通过后，由用户用真实项目完成一次完整工作：

1. 自主选择素材、脚本以及每份生成数量。
2. 点击开始，确认后台自检与主进度容易理解。
3. 性能提醒出现时分别验证继续全速和降低速度。
4. 中途暂停或关闭应用，重开后继续。
5. 整批未结束前先检查已经完成的部分结果。
6. 对一条成片重试或重新分配，确认不会增加多余卡片。
7. 选择部分或全部可导出成片完成批量导出。
8. 若本批使用代理或 LUT，验证效果、原片导出和代理清理。

只有用户确认操作不繁琐、进度可信、电脑仍可操作、异常能处理且结果可交付，才标记“用户验收通过”。

## 12. 统一报告与禁止误报

每次报告至少保存构建与提交身份、运行形态、OS／架构、电脑配置、输入 manifest 摘要、用户选择的 `N`、是否真实供应商、请求与费用范围、开始／结束时间、各卡片终态、产物 manifest、失败与重试、性能提醒、用户模式选择和日志位置。

结论只能使用以下分层语言：

- 静态通过。
- 本地逻辑／数据库通过。
- 本机真实媒体通过。
- macOS 安装包通过。
- Windows 安装包通过。
- 真实供应商通过（注明供应商与协议）。
- 跨平台通过。
- 用户验收通过。

禁止以下误报：

- mock 页面通过就宣称真实后端通过。
- 开发服务器通过就宣称安装版通过。
- macOS 通过就宣称桌面版或跨平台通过。
- 某一固定小样通过就宣称任意数量、任意素材都稳定。
- job 写着成功但没有核验卡片、MP4、封面和项目产物就宣称成片完成。
- 一次真实供应商调用成功就宣称长期稳定。

## 13. 当前工程事实

当前仓库已有大量单条精准混剪的领域、数据库、供应商 Adapter、真实 FFmpeg 小样和浏览器流程测试，且现有 FFmpeg 封装已经能够解析真实媒体进度。这些能力说明媒体内核具有迁移价值。

但批量领域模型、持久统一调度、用户选择式资源提醒、薄 Electron 运行壳、可变规模批量测试、Windows 真机运行和本票定义的用户验收都尚未实现。现阶段只能报告“验证方案已确认”，不能报告批量混剪已经完成或真实规模已经通过。

## 本票完成标准

1. 产品数量由用户决定，不再使用固定 60／8／20 或固定素材比例作为产品要求。
2. 16GB + SSD 作为大批量标准验收线，8GB 可运行但不承诺相同规模或速度。
3. 七层验证证据分别报告。
4. 分析、TTS、FFmpeg 和批次进度都有真实来源，未知阶段不伪造百分比。
5. 默认全速；普通压力提醒并由用户选择，磁盘不足或内存危险才触发保护暂停。
6. 差异事实可解释、可提醒、可重分配，但没有统一及格线，也不阻止导出。
7. 故障注入、两个平台连续三次运行、逐次授权的真实供应商测试和用户最终操作都有明确验收合同。

以上决定已由用户逐项确认。本票只完成验证设计，不代表任何测试已经执行。
