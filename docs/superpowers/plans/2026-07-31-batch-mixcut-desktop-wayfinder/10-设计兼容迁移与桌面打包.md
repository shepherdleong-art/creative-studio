## Question

如何在备份和可回退前提下增加新数据结构，把 Electron、本地运行时和 FFmpeg 纳入 macOS 与 Windows 安装包，并确保旧项目和单条精准混剪继续工作？

## Resolution

- 官方资料：[兼容迁移与桌面打包官方资料研究](./assets/10-兼容迁移与桌面打包官方资料研究.md)。
- 决定资产：[兼容迁移与桌面打包设计](./assets/10-兼容迁移与桌面打包设计.md)。
- 数据升级：首个批量 schema 前必须使用 SQLite Online Backup 建立并验证一致快照；新批量迁移走独立版本表和事务，失败回滚并关闭批量入口，不能进入半迁移状态。
- 兼容原则：旧项目、素材、单条精准混剪和正式产物继续可用；首版 Electron 只追加结构，不同时搬迁 macOS 或 Windows 既有数据根。
- 桌面边界：Electron 只做窗口、单实例、窄 preload Bridge 和私有 Node 监管；Next、SQLite、任务调度、原生模块与 FFmpeg 继续运行在私有 Node 22 服务。
- 升级体验：默认自动备份和升级，明显等待时才显示真实阶段；失败显示旧数据安全并提供重试、恢复备份和详情，旧功能进入兼容模式。
- 安装目标：首版只承诺 macOS Apple Silicon 与 Windows x64 内部测试包；Node、原生模块和媒体二进制放在 ASAR 外并按平台真实构建、加载和转码验收。
- 发布范围：首版手动安装升级，不做自动更新；正式签名、公证与 Windows 证书暂缓，内部包不得宣称公开可发布。
- 卸载规则：普通卸载只删除程序并保留项目、成片、配置、升级备份和代理；彻底删除本地数据是独立的二次确认操作，且永不删除链接原片。
- 基线证据：旧数据库迁移、成片迁移、macOS／Windows 安装规则和现有 macOS 安装负载测试通过；Electron 代码、Windows 真机包、双平台桌面运行和批量规模验收尚未实现。
- 后续顺序修正（2026-08-01）：安装包和 Electron 实施延后到批量生产核心、供应商运行环境和真实媒体链路稳定之后；桌面仍是最终交付目标，但不再作为早期开发前提。
- Sidecar 边界：未来安装版可统一看管私有 Node、公司必需的 `LiteLLM` 和媒体传输 Adapter；公司 sidecar 失败只改变该供应商的可用状态，不能拖垮应用或外部供应商。
