## Question

如何统一表示分析、代理、AI、配音、字幕和渲染任务，并提供原子领取、真实进度、暂停、继续、停止、重试、重启恢复以及可观测的资源模式控制？

## Dependencies

- 被 [先画出现有工程的安全边界](./01-先画出现有工程的安全边界.md) 阻塞。
- 被 [定义批量生产的数据模型](./02-定义批量生产的数据模型.md) 阻塞。

## Resolution

- 决定资产：[可恢复任务调度与自动资源控制设计](./assets/05-可恢复任务调度与自动资源控制设计.md)。
- Module 边界：把现有成片准备、重任务锁和渲染 worker 深化为一个持久 `ProductionScheduler` Module，以任务 Adapter 统一分析、代理、AI、配音、字幕和渲染，不新增第四套批量队列。
- 状态边界：生产任务与任务尝试分离；原子领取使用有期限租约，重启后旧尝试不能继续显示 `running`，远端已有任务 ID 时先确认结果再决定重试。
- 进度边界：主界面只显示当前阶段、真实进度和完成数量；没有百分比的供应商阶段不伪造进度，性能、尝试、错误和 ETA 放入任务详情。
- 控制边界：暂停可恢复，停止结束未完成工作但保留成功产物；可中断的本地与远端请求真实停止，已提交且供应商不支持取消的任务进入“正在暂停”并只做一次结果确认。
- 资源边界：开跑前以 CPU、总内存、项目盘空间和供应商上限计算硬安全上限；默认全速，普通持续压力只提醒用户选择继续全速或降低速度，磁盘不足或内存危险才保护性暂停新的重任务。
- 决定修正：票据 11 的真实规模评审已取代原型中的“普通压力自动降档”；原型仍证明降并发机制可以真实生效，但是否启用由用户决定。
