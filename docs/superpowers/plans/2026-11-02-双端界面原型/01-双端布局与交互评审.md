# 01 双端布局与交互评审

**状态：** `ready-for-human`

**类型：** prototype

**日期：** 2026-11-02

**问题：** 员工创作端与服务器管理端分别优先展示哪些信息，布局 A/B/C 哪些部分值得进入正式产品？

## 评审来源

- Git 原型分支：`codex/prototype/team-ui-20261102`，源代码入口 `app/prototype/team/page.tsx`。
- [运行与交互说明](../../../../app/prototype/team/README.md)。命令为 `npm run prototype:team`，默认回环端口 3317。
- 技术与范围沿用 [服务器技术方案](../../specs/2026-11-02-服务器统一生产-技术方案.md)，这次只探索界面，不实现真实后台。

## 三种结构

| 布局 | 员工端 | 管理端 |
| --- | --- | --- |
| A 工作台 | 侧栏导航、四类创作入口、最近项目、任务与交付 | 侧栏导航、概况、异常提醒、队列和资源 |
| B 任务优先 | 顶部导航、任务筛选、集中列表、最近项目 | 顶部导航、任务处理桌、资源检查区 |
| C 流程看板 | 待制作／制作中／完成交付，卡片进入详情 | 待调度／执行中／需要介入／已完成，按阶段排查 |

## 目前结论

两端职责与几条关键提示已经可以通过点按检查：维护暂停新受理，任务不随客户端离线终止，新设备不自动拉历史成片，更新先保存传输状态。它们是既定需求的界面表达，不是后台机制已实现的证据。

尚未得到用户对布局的选择；默认 A 不等于批准采用 A。保留所有变体为一手评审资料，不将可丢弃代码直接提升为生产代码。
