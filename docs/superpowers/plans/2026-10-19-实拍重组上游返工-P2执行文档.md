# 实拍重组上游返工 P2 执行文档

## 范围与依据

承接 2026-10-12 需求共识第 4.5、9 节和 Windows P1 四模板验收。P2 处理已登记成片的单镜头上游返工；配音、字幕、包装编辑仍保持 P1 边界。验收只用隔离数据库、合成图片/视频和本机假供应商，不读取生产密钥、不调用付费服务。

现状：`reassembled/import.ts` 已保存原图、生成图和真实提示词出处，但没有伪造图片任务；`shots` 的选择及 `latestJobId` 更新没有 CAS；图片队列通过 `latestJobId` 自动切图；视频任务冻结首帧但提交没有版本检查。第五步已有 `expectedRevision`、修订历史及保持时长的候选替换，直接复用。

## 执行合同

1. 第五步按稳定 `clipId → shotId` 定位第二步/第四步的单镜头返工面板，保留成片上下文并可返回第五步。提示词初值来自该镜头的导入出处或已创建任务，不使用项目通用提示词覆盖。展示真实原图、当前图、供应商和模型；参考图显式选择。
2. 追加 final-edit 迁移，逐镜头存版本与操作记录，生成请求保存不可变参数和来源版本。每次创建任务、采用图片、登记视频均校验 `expectedRevision`。事务内检查与写入，过期返回 409；前端保留未提交输入并要求刷新后重试。
3. 新图片任务不抢占 `shots.latestJobId`，完成结果按返工记录关联为候选。图片采用是显式操作并增加版本；迟到结果只增加候选。视频任务使用明确选择的当前图片，冻结来源、提示词、模型和时长。一次提交仅创建一个镜头的任务。
4. 本阶段采用保守一致规则：人工和 Agent 的生成结果都先成为候选。Agent 接口可生成、读取、登记候选，不能采用图片或直接修改已接管的时间线。人工明确采用后生效。Agent 身份由已有实例/数据目录/token 检查；人工采用由同源工作台入口发起，不信任 body 的 actor 字段。
5. 视频完成后，核验项目、分镜组、镜头、来源图和成功状态，复制到新的托管路径并核验 SHA256、实际时长和审核区间，再追加到原绑定的候选/输入哈希集合；绝不改原 spec、原候选文件或旧交付。异步探测结束后重新校验版本，防止等待期间覆盖。
6. 第五步明确选择新候选并使用现有 CAS 替换，默认保持该片段时长。其他镜头、顺序、裁剪、脚本、字幕、包装与已确认交付均不自动改变。新镜头仍须实际审片，尤其 classic 标注位置和人物避让。
7. 已接管分镜组的旧批量换景、无版本切图及破坏性删除入口拒绝写入并指向返工入口；普通项目维持原行为。旧视频提交入口对接管镜头要求版本校验。保护落在共享服务/路由，不能只隐藏按钮。

## 实施顺序

- A：追加迁移、共享镜头版本/归属保护、不可变返工记录及候选接管服务。
- B：本机 API、现有队列接入及旧写入口保护；复用已有供应商校验和队列，不增加生产假供应商。
- C：第二/四/五步上下文导航和单镜头返工面板，冲突提示、真实出处、候选选择。
- D：隔离服务/路由测试及 Windows 桌面闭环；必要时修复，再记录通过范围与尚未验证边界。

## 验收矩阵

- 单镜头图→视频→登记候选→第五步替换→本地渲染；其他镜头和脚本/包装完整快照相同，旧成片 SHA256 不变。
- 返工前实际保存人工标题、字幕和音乐音量；返工、候选登记和替换后深比较这些已保存内容，不能仅比较两个未设置的内容字段。组合验收已有人工修改时直接保留其基线。
- 手工选择后旧图片任务晚到、Agent 续跑、并发请求同版本：旧请求不覆盖，候选不丢失，无额外任务。
- 异步媒体探测期间人工改动：提交 409；不得残留已登记候选或变更绑定。
- 跨项目/组/镜头视频、未成功任务、短视频/越界区间、文件变更：拒绝，无时间线副作用。
- 过期版本、重复请求、重启读取：操作记录/真实提示词完整，禁止重复付费提交；候选登记可幂等重试。
- 数据库关闭重开后重放旧图片生成与候选登记请求：返回原回执，镜头、任务、候选、返工记录和含人工内容的时间线逐表保持不变；不恢复旧选择、不新增任务。
- 旧无版本入口及 Agent 直接写时间线拒绝；普通项目原测试不回归。
- TypeScript、相关 ESLint 与专项测试；验收记录清楚区分真实本地队列闭环、合成媒体验证与未执行的付费生成。

落地细化：旧视频提交入口对接管镜头统一拒绝，改走同一个 P2 版本化入口，避免保留第二套可绕过的 CAS 逻辑；生成结果统一先做候选，不启用异步自动采用。已有任务的续跑重放不可变原请求，不更换任务 ID。全量包装编辑、付费供应商验收和 macOS P2 仍不在本轮范围。
