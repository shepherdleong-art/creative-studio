## 1. 执行约束与变更边界

- 每个阶段结束提交可检查的变更、验证结果及 PRD ID 覆盖。一个阶段失败先修复或明确记录原因，不跳过后宣称整体完成。
- 保持现有业务、旧批次和单条精准混剪可用。UI 可以拆组件，数据与渲染使用正式领域接口；原型的全局数组、索引 clip ID、假字体/波形、内存审核、JSON 下载不能当正式实现。
- 工程选择由执行者完成并记录。只在必须改变 PRD 已确认交互/范围时向用户说明具体冲突；不能把每个内部命名或拆分选择变成确认问题，也不能默默改产品行为。
- 2026-09-26 后续修订：按 PRD W-02/T-01 补字幕伸缩和三种分割入口、放开分隔线固定上限；对应 A02/A17/A18/A23 追加验证。字幕复用原编辑器一帧边界，下面 0.5 秒约束用于新视频/音频手势，不强加到字幕。
- 修改产品规则时同步 PRD、需求映射及受影响验收项。后续用户明确修订优先于冻结基线；没有修订时按 v14 执行。
- 不自动提交、推送、合并或发布安装包；这些与实现验收是不同动作。保留已有无关工作。

## 3. 状态与数据设计边界

### 3.1 分离状态

| 状态 | 归属与约束 |
| --- | --- |
| 成片、版本、媒体引用、视频/音频片段、字幕、属性、审核 | 后端持久化，带稳定身份及修订保护 |
| `visiblePlanIds` / 当前可见顺序 | 预览 UI 状态，决定最高可见成片，不决定导出 |
| `editingTarget` | `{planId, outputVersionId, trackKind, clipId/cueId}`；与预览目标分离 |
| `previewMode` / 素材预览 | 主成片、单素材、封面三种状态，返回时恢复上下文 |
| 统一播放头、缩放、面板尺寸、重复定位、工具模式 | 会话 UI 状态；帧/像素转换集中处理 |
| 导出选择 | 独立集合，提交前重验资格和内容身份 |
| 拖动 draft | 会话临时状态，松手提交一次，Esc/失焦取消 |
| 撤销/重做 | 会话历史，回放正式命令或受保护版本快照；刷新可清空历史，但已保存编辑不丢失 |

稳定 clip ID 不能使用“第几行-第几个片段”：分割、删除、排序后索引会变化。任何迟到回调必须验证 plan/version/clip/source/seek 代际，不能应用到新选中的对象。

### 3.2 时间、音频及历史兼容

- 使用现有整数时间单位；显示以正文时间为准。片头 20 帧的换算放在一处，在预览、字幕和音频渲染路径各核对，不重复加偏移。
- 音频模型须明确 `sourceStart/sourceEnd` 与 `timelineStart/timelineEnd`；字段名可沿代码约定。BGM 还绑定真实 source identity；旧只有可听区间的数据按原时间恢复，不把被删区间重新播放。
- UI 新操作遵守 0.5 秒最短及帧网格。旧音频 API 当前允许 0.01 秒分割，已有更短合法片段继续可读/播放，不能为 UI 新约束批量破坏历史或单条混剪。
- 旧 `audioCutFilter` 只按原时间静音，无法实现移动后的重排音频。音频新模型必须同时落到预览调度和真实渲染的取源、裁切、延时/拼接、音量与淡入淡出，不能只移动画出来的波形。
- 一次编辑只改目标成片；实质内容变化使相应审核/渲染身份失效。纯结构分割沿用既有内容等价优化；撤销恢复内容也必须经过正式修订/冲突门禁，不倒写旧 revision。

### 3.3 素材角色与冻结版本

- 开场/正文属于显式项目素材角色，不通过文件名推断。生成完成事件与目录登记校验项目/来源身份、文件完整性和可播放性；幂等身份应包括来源结果及内容指纹。
- 冻结批次输入保持不可变。为 M-04 提供**成片编辑新增素材引用**：导入先登记项目素材，再以当前成片版本/编辑修订记录受控引用或派生编辑版本，不直接改冻结素材池。
- 后端 replace/insert 当前只读冻结池：必须扩展成“合法冻结引用或合法编辑新增引用”的可用性判断，并将新增素材指纹、路径、角色与版本身份纳入审核、render contract、导出前检和回收保护。校验强度不能降低。
- 可以使用既有合适的版本机制代替新增表，但必须证明：新素材可用于当前成片、其他成片不重排、旧正式产物/历史版本不变、刷新可恢复、导出可追溯。不得靠前端白名单绕过后端校验。
- 是否追加迁移由 P1 的实际数据设计决定。需迁移时只能追加，走共享备份/锁/审计 gate；路径基于 `dataRoot()`；`lib/batch-production/` 不新增对 `lib/final-edit/` 的依赖。

## 4. 分阶段执行

### P0 — 对照与影响清单

1. 读取本文件、PRD、仓库约定和对应源码；打开冻结 v14，实际操作面板、素材拖入、音视频修剪、快捷键和重复高亮。
2. 确认真实批量页面入口、工作树、当前运行代码及实际测试命令。读取涉及的测试文件头，不凭本文件复制过时环境参数。
3. 建立实施记录，逐项列出 PRD ID → 现有能力 → 缺口 → 拟修改文件 → 验收场景。

完成条件：所有 PRD ID 有映射；明确两个重点缺口（音频源/位置分离、编辑新增素材合法引用）；旧数据与单条混剪影响已列出。产物建议放 `outputs/batch-unified-review-acceptance/implementation-log.md`，评审用摘要进入最终交付记录。

### P1 — 正式状态与编辑契约

1. 建立批次级统一审片状态，稳定区分预览对象、编辑对象、眼睛与导出选择。
2. 设计并实现音频兼容模型、trim/move 等命令，完善 parse/validate、版本/修订与 source identity。
3. 落实编辑新增素材引用机制，补齐所有读取、渲染契约、导出与素材回收调用方；如需迁移完成 gate 和旧库副本验证。
4. 建立共享命令/撤销接口，覆盖视频替换/插入/修剪/移动/分割/删除与音轨操作；失败恢复、冲突、过期目标要可观测。

完成条件：源边界/邻接/最短限制由后端守住；旧数据读写兼容；撤销不是覆盖整个全局对象；无 UI 的领域验证可证明其他成片未改变。满足 M-04、T-04/T-05/T-06、R-01 的数据基础。

### P2 — 素材池、开场库与自动登记

1. 复用正式导入、媒体探测、缩略图和预览路由；按当前角色展示，错误状态可操作。
2. 为自定义开场生成成功结果补角色和受控目录登记；覆盖重试、重复同步、失败、文件缺失、跨项目和旧数据无角色情况。
3. 新批次首镜读取可用开场集合并分散分配；结合既有 allocator 保留语义匹配与合法区间。开场库变化不改写已有成片。
4. 实现自适应网格、单素材悬浮滑动和显式预览；补目标明确的拖拽替换/间隙插入/末尾追加。

完成条件：真实本地视频可导入、刷新后仍存在并可用于当前成片；4 个受控开场样本成功归库后新批次首镜能引用，重复事件不重复登记；全流程不需要恢复已删除的大操作栏。满足 M-01～M-04。

### P3 — 统一工作台与完整属性复用

1. 把检查入口接为同屏工作台，拆分布局、预览、素材池、属性、成片行，保持批量步骤导航与异常/重试入口。
2. 实现三条分隔线、边界、双击复位、键盘调整与区域滚动；时间轴统一标尺、封面列、字幕/视频/TTS/BGM 顺序。
3. 复用现有完整属性，不减字段；字幕和封面编辑、真实字体选择、恢复默认及草稿切换继续工作。
4. 分离眼睛、编辑目标、当前预览标记、审核和导出选择，支持全隐藏、短片越界及显示全部。

完成条件：W-01～W-03、T-01/T-02、E-01 在真实批次内可操作；默认、加宽素材池、加高时间轴、加宽属性的截图与冻结基线对照通过。窄窗口仍可操作；深浅主题使用现有令牌。

### P4 — 时间轴手势、磁吸、键盘与重复提示

1. 视频与音轨连接 P1 命令，支持主体拖动、双边修剪、分割工具、删除；拖动中 draft 即时反馈，松手持久化一次。
2. 磁吸统一坐标转换，覆盖视频/字幕/音频边界和播放头；按屏幕距离判定，Alt 临时取消，取消拖动还原。
3. 快捷键跟随焦点与选中对象；输入/下拉/字体弹层内不误触；音视频切换选择后命令不会作用于上一个对象。
4. 建立全批次的素材引用/源区间索引，更新次数、成片数、颜色、斜纹与重复定位。普通素材保持正常亮度。

完成条件：T-03～T-06 全部通过鼠标/键盘和保存后重读验证；不只看 CSS 类。移动、修剪、分割、替换、音频删除及撤销后索引准确；隐藏/未挂载行仍参加统计。

### P5 — 真实连续预览与音视频一致性

1. 将最高可见成片 arrangement 绑定现有 `BatchTimelinePreview`，保留双 slot/canvas、LUT、封面、字幕、画面参数与实时音频能力。
2. 对换源、seek、素材悬浮、切成片、全部隐藏设置资源代际取消；旧回调不得上屏或继续发声。
3. 新音频源/位置模型接入真实播放调度；处理剪掉的静音、移动、分割后的源连续性和音量，不把 TTS 时间自动拖着字幕跑。
4. 在已知非黑色视频样本的连续交界上做帧采样；新画面就绪前保留有效画面，真正空位仍黑场，资源失败明确呈现。

完成条件：P-01 与 T-01/T-02/T-05 的真实媒体部分通过；完整播放、连续多次边界切换、暂停恢复与快速 seek 无意外黑帧/串音/永久定格。用像素、时间推进及音频证据，不只断言 `readyState` 或 canvas 存在。

### P6 — 确认、导出与恢复

1. 审核绑定有效编辑身份，失败/未保存/冲突不能通过；保存成功后按实际内容变化清相应审核。
2. 统一导出提交独立选择集，复用正式前检、渲染、发布与稳定 artifact 媒体身份；眼睛与选中片段不参与导出资格推断。
3. 把视频/音频编辑、新增素材、字幕/封面等全部纳入真实 render contract；导出需与预览一致，历史产物在失败时仍可访问。
4. 覆盖刷新、重试和中断后恢复。复用执行时已存在的持久导出意图/恢复机制，不能照搬旧记忆中“选择只在前端”的过时限制。

完成条件：R-01/R-02 完成；真实导出的 MP4/封面通过时间、画面、声音检查；发布身份与用户所确认版本一致，失败不会切换为坏产物。

### P7 — 总验收与交接

1. 完成下表 A01～A27，并运行受影响领域回归、lint、类型检查及构建。静态页面通过不替代真实媒体验收。
2. 用动态素材/成片数量、小/大视口、浅/深主题、缺失素材和旧批次执行边界验证。建议规模样本为 6 条、30 条成片，素材数量至少覆盖 4/8/20；这是验收样本，不是产品数量限制。
3. 输出最终交付记录：基线/最终 commit、需求覆盖、实际命令与结果、截图/音视频证据路径、未执行环境与剩余问题。只把已执行场景标 PASS。

完成条件：所有必需条目通过或问题已明确解决；真实声音与正式导出仍未验收时不能写“全部完成”。本次不要求重新做剪映式完整非线性编辑器。
