## 服务器统一管理的生产参数（V06）

**唯一裁决点**：`lib/team-service/production-defaults.ts`

```ts
productionParamsFor(config, requested?)
// → { timeoutMs, projectConcurrency, videoConcurrency, imagePreprocess: { enabled, targetMaxSide, jpegQuality } }
// server 模式丢弃 requested；local 模式保留「请求值 > 默认值」
```

起步默认值 `BUILTIN_PRODUCTION_DEFAULTS` = 改动前客户端默认：`600000ms / 10 / 10 / 开启 1536 85`。
与 `lib/image-preprocess.ts` 的 `DEFAULT_OPTIONS` 由测试断言对齐，别单独改一边。

**已覆盖的落点**（07/08 不需要再补，也不要在页面里重新发这些字段）：

| 落点 | 行为 |
| --- | --- |
| `POST /api/projects` | 新建项目的 `concurrency` / `videoConcurrency` / `timeoutMs` 用服务器值 |
| `POST /api/projects/[id]/run`（start + resume） | 请求里的 `concurrency` / `timeoutMs` 被丢弃；仍经 `getEffectiveImageConcurrency` |
| `POST /api/upload`（本地版） | 预处理三项用裁决值 |
| `POST /api/team/uploads`（团队版） | `imageOptions.preprocessEnabled/targetMaxSide/jpegQuality` 被替换成服务器值；`role`/`usage` 仍由客户端决定 |
| `video-run` / `shot-sets/[id]/video-jobs` / `.../batch` / `video-jobs/[id]/retry` | 视频并发用服务器值 |
| `lib/legacy-media-lifecycle.ts`（重启恢复） | 队列恢复同样用服务器值 |

**07（第 1 步 / 第 4 步）要做的**：只把界面上的并发控件**拿掉**，不需要改接口。
`GET /api/projects/[id]` 返回的 `concurrency` / `timeoutMs` 是落库值（团队版=服务器默认），可直接只读展示。

**08（第 4 步视频）**：`project.videoConcurrency` 在团队版恒等于服务器默认值，
所以界面上的「并发」读出来是只读的同一数字，可以直接删控件。

**运维改默认值**（首版无界面）：`CREATIVE_STUDIO_PRODUCTION_TIMEOUT_MS`、
`_PROJECT_CONCURRENCY`、`_VIDEO_CONCURRENCY`、`_IMAGE_PREPROCESS_ENABLED`、
`_IMAGE_MAX_SIDE`、`_IMAGE_JPEG_QUALITY`。写错（例如 0 并发）会让 `readRuntimeConfig` 抛错、
服务启动即失败——这是有意为之，不要改成静默回退。

## 员工首页（V07）——`/api/team/dashboard`（新增只读聚合）

```ts
GET /api/team/dashboard   // 员工身份；管理员调用也只返回本人数据
{
  greetingName: string,
  errors: Array<{ errorId, stage, safeMessage, actionHint, scopeName, taskHref, createdAt }>,
  running: { items: Array<{ operationId, label, detail, percent: number | null }>, total: number },
  projects: Array<{ id, name, storeCode, productionType, productCode, thumbnailImageUrl,
                    progress: { step: 1..5, label, empty }, totalJobs, completedJobs, lastOpenedAt }>,
  usage: { monthChargedMinor, monthSettledMinor, monthlyLimitMinor, remainingMinor, accountingPeriod },
}
```

**进度规则（红线）**：`running.items[*].percent` 只有真实可测的阶段（目前只有成片渲染/包装）
才非 null。JSON 里出现的 `percent: null` 表示「写文字，不要画百分比」。
规则在 `lib/task-progress.ts`（`describeRunningTask` / `renderPercent`），
`scripts/team-dashboard.test.ts` 与 `scripts/workbench-progress.test.ts` 钉住了这条。
