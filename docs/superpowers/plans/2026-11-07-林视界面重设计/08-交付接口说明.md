## 1. 新增的纯函数（可直接复用，别另写一份）

| 导出 | 位置 | 用途 |
| --- | --- | --- |
| `intersectDurations(models)` | `lib/video-duration-intersection.ts` | 多个模型的秒数数组 → 交集（升序去重）。空输入/任一空列表/无交集都给 `[]` |
| `describeDurationIntersection(durations)` | 同上 | 交集的中文说明：「4–7 秒」/「5 / 10 秒」/「没有共同支持的秒数」 |
| `scriptLiveMetrics(text, targetTotalSec)` | `lib/script-studio/panel-rules.ts` | 字数、预计口播、预算上下限、「在预算内/偏长/偏短」；口径来自 `script-duration-policy.ts`（4.2 字每秒、20 帧片头） |
| `defaultSelectedSellingPointIds(points)` / `summarizeSellingPoints(points)` | 同上 | 卖点库默认全选与「默认全选 / 排除 N 个」摘要 |
| `toggleTemplateEntry` / `setTemplateEntryCount` / `describeTemplateSelection` | 同上 | 模板勾选与合计条数上限（沿用 `SCRIPT_GENERATION_MAX_COUNT` = 6） |
| `savedSettingsFromJob(job)` / `videoSettingsDiffer(saved, draft)` / `VIDEO_SETTINGS_CHANGED_HINT` | `components/video-job-settings.ts` | 从 `video_jobs` 已保存字段读「这条视频用的设置」，并判断草稿是否改过 |

**09/10 若要在其它地方显示「时长交集」或「脚本字数预算」，请直接用上面这些函数**，
不要再各自实现一套口径。

## 2. 第 4 步（视频）对外的落点与接口

| 东西 | 位置 / 契约 |
| --- | --- |
| 三栏工作台 | `.video-workspace`：`minmax(320px,400px) | minmax(0,1fr) | minmax(220px,280px)`，占满内容区（**不再**按 `100vw` 居中） |
| 外壳 | `.video-generation-section`：`width:100%; flex:1`。**别改回 `left:50%/translateX(-50%)`**——那会在 1280/1024 下把「选择分镜组」推出视口 |
| 「这条视频用的设置」 | `data-testid="video-saved-settings"`；改动提示 `data-testid="video-settings-changed"`（文案逐字：`改过了，再生成会多做一条，原来那条不变`） |
| 结果卡 | `data-testid="video-result-card"` + `data-job-id` + `data-selected`；`VideoGenerationResults` 新增 `onSelect(job)` 回调 |
| 批量检查窗口 | `role="dialog"` `aria-label="批量检查分镜"`；顶部 `data-testid="bulk-provider"` / `bulk-duration` / `bulk-duration-hint` |
| 分镜组下拉 | `aria-label="选择分镜组"`（验收工具靠它选中夹具分镜组） |
| 剔除/恢复 | 沿用 `/api/video-jobs/[id]` 的 `action: 'reject' | 'unreject'`，`rejectedAt/rejectReason` 字段；已剔除默认隐藏，`显示已剔除（N）` 可找回 |
| 并发 | 单条与批量两处控件已删除，也不再 PATCH `videoConcurrency`；并发只由 `lib/team-service/production-defaults.ts` 裁决 |

**批量检查的三条规则**（本票已核对并落地，与原型一致）：

1. **统一秒数 = 所选分镜模型的秒数交集**；换统一供应商后自动重算；交集为空时下拉给出说明项 + 提示文案，不静默。
2. **一键填充只填空着的提示词**（`planBulkPromptFill({ onlyFillEmpty: true })`）。之前自动填过但已有内容的行也算「已有内容」，不再重洗。
3. **全部生成只提交还没有任务的分镜**（沿用 `planBulkVideoGeneration` 的 `shotsWithExistingJobs`）。

## 3. 第 3 步（脚本）对外

- 卖点库 `data-testid="selling-point-library"`，副标题 `data-testid="selling-point-summary"`
  （文案形如 `2 个有效卖点，默认全选 · V1 · 已保存` / `1 个有效卖点，排除 1 个 · V2 · 已保存`）。
  **默认收起**，点「展开卖点」才逐个排除。
- 爆文模板卡片 `data-testid="viral-template-card"`，内含
  `viral-template-ref`（参考文案，默认摊开、长文 4 行截断 + 展开全文）、
  `viral-template-structure`、`viral-template-reasons`。
- 手改配音稿：`data-testid="script-live-metrics"` / `script-budget-status` / `script-character-count`；
  保存仍走 `POST /api/projects/[id]/script-studio/scripts/[scriptId]`，`origin: 'manual_edit'` → 新版本，可切回旧版。
- 「再生成一组」仍复用卖点库（`mode: 'reuse'`），只有上传了新详情页才走 `first_extraction`。
