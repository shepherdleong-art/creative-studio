# 03：品牌：名字、标志、登录页、启动画面

**状态：** `ready-for-agent`

**What to build：** 除了侧栏和顶栏，所有显示名都换成林视：员工端叫林视创作台，管理员端叫林视控制台，个人本地版叫林视 Lin's Vision。同时换上叶子标志和新应用图标，登录页带上品牌和主张，桌面客户端启动时先显示标志和连接状态。员工升级后数据、登录和设置都还在。

**Blocked by：** 02。

**Parent：** [01 父规格任务](01-林视界面重设计.md)  
**需求依据：** [功能方案](../../specs/2026-11-07-林视界面重设计-功能方案.md)「名字与标识」「逐屏决定 · 登录」；V01、V18。  
**原型对应：** 品牌页（标志和用法）、登录页。

## 实施边界

- **侧栏和顶栏不动。** 这两处的品牌区和改名由 05 负责，本任务不改这两个组件，避免和 05 冲突。
- **要换的显示名：**
  - 根布局里的页面标题和图标。
  - 桌面启动失败的标题、客户端显示名。
  - 配音试听文案。
  - 启停脚本里的提示文字。
  - Windows 免安装包的说明文字。
  - 面向用户的说明文档。
  - AGENTS.md 由 15 统一更新，本任务不改。
- **不改的内部标识：** 包名和仓库名、数据根和应用数据目录名、`CREATIVE_STUDIO_*` 环境变量、浏览器存储键、会话 Cookie 名、桌面可执行文件名、IPC 通道名、路由、项目和成片的命名规则。新增一条守护测试，锁定应用数据目录名和外观存储键。
- **停止脚本：** macOS 源码桌面版改了显示名以后，停止脚本要同时认新旧两个应用路径；相关守护测试和配音试听文案的守护测试一起改。
- **标志和图标：**
  - 源图用原型目录的 `落地素材/林视标志.svg`；需要单色时用 `落地素材/林视叶子-单色.svg`。
  - 用现有的图标生成流程重新产出网页图标，以及 Windows、macOS 两种应用图标。
- **登录页：**
  - 背景用真实产品场景图（原型目录 `落地素材/登录页背景.jpg`）并虚化，中间是登录卡片：标志、名字、主张「出片交给 AI，眼光留给你。」、工号、密码。
  - 首次登录改密码、记住登录、错误规则都不变。
  - 校验提示写在输入框旁，不用浏览器弹窗。
  - 底部一行归属文字：动手时先问用户要文案，没给就先不放，并在 Comments 记一笔。
- **启动画面：**
  - 桌面运行壳在连上服务前显示一个本地页面，内容是标志、端名和连接状态。
  - 连不上时写明原因，再给一个重试按钮。
  - 跟随外观偏好显示浅色或深色，不依赖服务器上的任何资源。
- **注意：**
  - 改桌面目录和说明文档前，先看工作区有没有用户未提交的改动，有就先问用户。
  - `.ps1` 文件保持 UTF-8 带 BOM。
- 实现入口见父任务「显示名与图标」「不能改的内部标识」「登录」「启动画面」四行。

## 验收条件

- [ ] 浏览器标签、桌面窗口标题、任务栏图标和登录页都显示新名字和新标志；员工端和管理员端的标题分别是林视创作台和林视控制台。
- [ ] 旧显示名「产品素材工作台」「Creative Studio」不再出现在界面文字和启停提示里；文档里的历史记录不算。
- [ ] 在同一数据根上升级后，登录状态、下载目录、外观偏好和本机数据都还在；新守护测试通过。
- [ ] 停止脚本能停掉新旧两个名字的桌面应用；改过的守护测试通过。
- [ ] 登录页：空工号、空密码、新密码太短、两次不一致，提示都写在输入框旁；首次登录改密码流程通过；Chromium 和 WebKit、浅色深色下截图没有错位。
- [ ] 启动画面：服务正常时先显示标志和「正在连接服务器」，连上后进入页面；服务不可达时显示原因和重试按钮，重试成功后进入页面。

## 可演示结果

打开桌面客户端，先看到启动画面和新图标，然后进入带林视品牌的登录页。
