# 12：控制台运行总览和全员任务

**状态：** `ready-for-agent`

**What to build：** 管理员的运行总览和全员任务按定稿改版。

- 运行总览：
  - 数量卡和最近任务表，点表里一行跳到任务详情。
  - 名额占用、今天的成员、开工前还差几件事。
  - 什么都没跑时显示全 0 空状态。
  - 暂停生产前先确认。
- 全员任务：
  - 能搜索、能按发起人和状态筛选。
  - 详情写清错误编号、失败阶段、模型和调用记录，能重试。
  - 能用链接直接打开某一条任务。

**Blocked by：** 05。

**Parent：** [01 父规格任务](01-林视界面重设计.md)  
**需求依据：** [功能方案](../../specs/2026-11-07-林视界面重设计-功能方案.md)「逐屏决定 · 控制台：运行总览、全员任务」；V16 的这两页。  
**原型对应：** 控制台运行总览（含评审条里的「全是 0」状态）、控制台全员任务。

## 实施边界

- **数量卡：** 正在跑、在排队、今天已完成、出错。
- **最近任务表：** 任务、项目、发起人、模型、状态、时间。点一行打开全员任务里这一条的详情。
- **右栏：**
  - 名额占用。
  - 今天的成员：谁在做什么，链到团队用量。
  - 开工前还差几件事：公司模型代理、参考图中转、模型名额等，数据来自现有的就绪检查；每件写明状态和去处。
- **暂停生产：** 沿用现有的生产暂停逻辑，只在前面加一层说明和确认。
- **全员任务：**
  - 搜索项目、模型或编号，打字时不丢焦点。
  - 按发起人和状态筛选；没有结果时显示说明和「清除筛选」。
  - 详情能通过链接直接打开，供总览和其他页面跳转。
- 实现入口见父任务「首页与运行总览」「控制台」两行。

## 验收条件

- [ ] 数量卡和任务数据一致；点最近任务表的一行，打开全员任务里这一条的详情。
- [ ] 开工前清单每一项的状态都和就绪检查一致，并链到对应页面；全部就绪时显示「已就绪」或收起。
- [ ] 没有任务时显示全 0 空状态和下一步。
- [ ] 暂停生产先显示说明：点取消不暂停，点确认才暂停，暂停后能恢复。
- [ ] 全员任务：
  - 搜索时不丢焦点；发起人和状态筛选正确。
  - 没有结果时有说明和「清除筛选」。
  - 失败任务的详情有错误编号、阶段、模型和调用记录，重试后回到排队。
- [ ] 员工看不到全员任务，也看不到别人的数据；沿用现有的权限测试。
- [ ] 在验收工具里加上这两页的检查；两种内核、三种窗口、浅色深色都通过尺寸检查。

## 可演示结果

管理员登录，看到运行总览；点一条出错的任务，直接到详情并重试。
