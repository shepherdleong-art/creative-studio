### 2026-11-08 第一次提交：窄窗口收法待用户选（本票停在这里等确认）

**这一条必须先由用户决定，所以状态改成 `needs-info`。** 规格原文：「宽度小于 1280 时，侧栏收成只有图标的窄条（悬停显示名称），混剪的『素材调整』默认收起。**原型没有覆盖这一条，实施时先出截图请用户确认。**」

三种收法都已在 `1024×720` 下实现并量过（Chromium，浅色与深色），截图见下表。**三种都只是可运行的候选，选定一种后要删掉另外两套与试用开关**（见文末「选完之后要做什么」）。

#### 方案 A · 图标窄条 + 悬停浮出名称（= 规格原文的写法，当前默认）

侧栏固定 68px，只留图标；分组标题收成一条细线分隔；鼠标悬停或键盘聚焦到某一行时，在该行右侧浮出它的名称（`role="tooltip"`）。主区让位 68px，内容宽度最大。

| 步骤 | 截图 |
| --- | --- |
| 收起态（浅色） | `docs/design-assets/2026-11-08-narrow-window/01-icon-rail-light.png` |
| 悬停某行 → 浮出名称 | `docs/design-assets/2026-11-08-narrow-window/02-icon-rail-hover-name-light.png` |
| 收起态（深色） | `docs/design-assets/2026-11-08-narrow-window/03-icon-rail-dark.png` |

- 优点：最省横向空间；和规格原文一致；名称只在需要时出现，平时最安静。
- 缺点：看名称要一次悬停一行；分组标题没了（只剩分隔线），新用户不容易建立「创作 / 进度 / 账目」的地图。

#### 方案 B · 图标窄条 + 悬停整条展开

收起态与 A 相同（68px 图标条），但指针进入侧栏（或键盘聚焦）时**整条平滑展开成 224px 完整侧栏**，浮在内容之上；移开就收回。纯 CSS（`:hover` / `:focus-within`），不依赖 JS。

| 步骤 | 截图 |
| --- | --- |
| 收起态（浅色） | `docs/design-assets/2026-11-08-narrow-window/04-hover-expand-collapsed-light.png` |
| 悬停 → 整条展开 | `docs/design-assets/2026-11-08-narrow-window/05-hover-expand-expanded-light.png` |
| 收起态（深色） | `docs/design-assets/2026-11-08-narrow-window/06-hover-expand-dark.png` |

- 优点：一次就能看到全部分组与名称，最接近完整侧栏的体验；主区仍是 68px 让位，画面不缩水。
- 缺点：展开层会盖住内容左下角（上图能看到项目卡片被遮一部分）；鼠标在侧栏与内容之间来回移动时会反复展开/收起，容易误触。

#### 方案 C · 窄轨 + 覆盖式抽屉

让位收成 44px，侧栏内容全部收起，只在左上角留一个开关按钮；点开关弹出 224px 的完整侧栏（带遮罩，点遮罩或 Esc 收起）。

| 步骤 | 截图 |
| --- | --- |
| 收起态（只剩开关） | `docs/design-assets/2026-11-08-narrow-window/07-drawer-closed-light.png` |
| 点开关 → 抽屉展开 | `docs/design-assets/2026-11-08-narrow-window/08-drawer-open-light.png` |
| 收起态（深色） | `docs/design-assets/2026-11-08-narrow-window/09-drawer-closed-dark.png` |

- 优点：主区让得最少（44px），画面最大；导航结构只在需要时占屏，最干净。
- 缺点：比 A/B 多一次点击才能导航；没有图标作常驻提示，新用户可能不知道左上角那个按钮是导航。

#### 三种方案对照

| | A 图标 + 悬停浮名 | B 图标 + 悬停展开 | C 窄轨 + 抽屉 |
| --- | --- | --- | --- |
| 主区让位 | 68px | 68px | 44px |
| 看到名称 | 逐行悬停 | 悬停整条 | 点开后全见 |
| 常驻可见导航 | 图标 + 分组线 | 图标 + 分组线 | 只有一个开关 |
| 遮挡内容 | 不遮 | 展开时遮左下角 | 打开时遮 + 遮罩 |
| 操作步数 | 直接点 | 直接点 | 多一次开关 |
| 与规格原文一致 | 是 | 否（仍是「图标窄条」，但展开方式不同） | 否 |
| 实现复杂度 | 低 | 低（纯 CSS） | 中（开关 + 遮罩 + Esc） |

**我的建议（仅供参考，由用户定）**：A 与规格原文一致、最省事，适合「员工已经熟悉入口」的日常使用；如果担心新员工找不到入口，选 B（一次悬停看全，代价是偶尔盖住左下角）。C 画面最大但导航多一步，除非用户特别在意 1024 宽的编辑画面。

#### 三种收法共有的部分

- 悬停/聚焦都能拿到名称（`aria-label` 与 `title` 本来就在，A 另加 `role="tooltip"` 浮层）。
- 头像菜单从窄轨外弹出（`position: fixed`），不会被 68px 的 `overflow` 裁掉。
- 「客户端版本过旧」这条必须看到的提示改成浮在内容区左上角的横幅，不随窄条一起藏。
- 混剪的「素材调整」在**团队版**窄窗口下默认收起（`MixcutShell` 按 `(max-width: 1279px)` + `html[data-deployment-mode='server']` 判定）；用户点 › 可临时展开，且不写进布局记忆——回到宽窗口时用户自己的折叠选择还在。个人本地版的破格宽度与按窗口高度撑满保持不变（8 月为小屏监看定的有意设计）。
- 窄窗口截图（混剪页，素材调整已收起）：`docs/design-assets/2026-11-08-narrow-window/10-mixcut-narrow-light.png`
