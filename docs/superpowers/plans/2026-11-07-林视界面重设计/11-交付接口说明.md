# 11 → 15 交付接口说明（批量导出页：大预览 + 一键下载全部）

**状态：** 11 号票已完成导出页改造。本文给 15 号票写文档与做全量验收用。

## 1. 新增的两个接口

### 1.1 本批次可下载文件清单

```
GET /api/batch-production/batches/[id]/downloads?projectId=<id>&scope=both|video|cover[&delivery=1]
```

- `scope` 缺省 `both`；未知值 → **400**（`invalid_download_scope`），不静默按 `both` 处理。
- 缺少 `projectId` → **400**（`missing_project_id`）。
- 归属：`withTeamRoute` 的 `batch` scope。**别人的批次在 handler 之前就被拒**（403 / 404），
  响应里不会出现对方的文件名或导出目录名。伪造 `projectId` 同样被拒。
- 只列**当前正式产物**（`batch_output_plans.currentArtifactId` 指向的视频 + 同一导出对的封面）。
  「从没导出」「渲染失败」的成片不在清单里。
- **改过但没重新导出**：给**上一版正式产物**，该条 `outdated: true`；清单里所有条目都是上一版时
  顶层 `outdated: true`。
- 没有任何可下载成片时：`items: []` + `emptyMessage: "还没有导出过的成片"`（**仍是 200**）。

响应形状：

```json
{
  "batchId": "…",
  "projectId": "…",
  "scope": "both",
  "exportDirName": "ACC-1-20261101",
  "outdated": false,
  "items": [{
    "planId": "…",
    "seq": 1,
    "scriptTitle": "脚本标题",
    "kind": "video",
    "filename": "ACC-1-01.mp4",
    "relativeName": "ACC-1-20261101/01-v1/ACC-1-01.mp4",
    "byteSize": 4096,
    "sha256": "…64 位小写 hex…",
    "checksum": "sha256:…",
    "outputVersionNumber": 1,
    "outdated": false
  }],
  "totalBytes": 6144,
  "emptyMessage": "还没有导出过的成片"
}
```

字段口径：

| 字段 | 含义 |
| --- | --- |
| `relativeName` | 下载根下的相对名：`<导出身份目录>/<两位序号>-v<成片版本>/<文件名>`（**按项目与导出版本分目录**） |
| `byteSize` | 现场 `lstat` 的真实字节数，不信任数据库登记值 |
| `sha256` | 裸 hex，轻客户端下载后校验用 |
| `checksum` | 正式产物登记的 `sha256:<hex>` 指纹（保持内部格式） |
| `outputVersionNumber` | 这套产物属于第几版成片（不是第几次导出） |
| `outdated` | `true` = 改过还没重新导出，给的是上一版 |

`delivery=1` 是**轻客户端**分支：把清单里的正式产物登记为 `delivery` 引用，并额外返回
`deliveryManifests`（现有交付下载的 `TeamFileManifest`，`displayName` 用上面的 `relativeName`）：

```json
"deliveryManifests": [{
  "fileId": "…", "seriesId": "…", "version": 1, "size": 4096,
  "sha256": "…", "etag": "\"…\"", "displayName": "ACC-1-20261101/01-v1/ACC-1-01.mp4"
}]
```

客户端把这份数组交给 `desktopBridge.createDownloads(manifests)` —— 下载、校验、回执全部复用
现有 `/api/team/files/[id]`、`/api/team/downloads/receipts` 链路，**没有新造下载通道**。
`delivery=1` 只在 server 模式可用（本地版返回 404，与其它团队接口一致）。

### 1.2 服务端打包 ZIP（只用浏览器时）

```
GET /api/batch-production/batches/[id]/downloads/zip?projectId=<id>&scope=both|video|cover
```

- **内容与 1.1 的清单一致**：两者共用同一个 builder，ZIP 里每个 entry 名就是清单的
  `relativeName`；不存在第二套查询。接口级测试逐项比对文件名与解压后字节数。
- 响应头：`Content-Type: application/zip`、`Cache-Control: no-store`、
  `Content-Disposition: attachment; filename*=UTF-8''<导出身份目录>-成片[-视频|-封面].zip`。
- 打包前先把产物登记为受管文件（`export` 引用）——`buildGenericZipStream` 只允许打包
  已登记、且当前主体有权读取的文件（沿用 `lib/zip-download.ts` 的既有约束）。
- 没有可下载成片 → **404** + `{"error":"no_exported_films","message":"还没有导出过的成片"}`，
  不生成空 ZIP。

## 2. 页面（导出页，第 4 步「导出成片」）

- **卡片不再嵌播放器**：封面 + 悬停播放图标，点卡片打开大预览。
- 预览复用 09 的 `FilmPreviewDialog`（**11 只调用，未改一行**）：
  - 已导出 → 播当前正式成片（`source=artifact&artifactId=<videoId>`）；
  - 改过没重导 → 播**上一版正式成片**，信息栏写明「上一版正式成片」；
  - 从没导出 → 播检查成片里的**合成预览**（`source=candidate&renderAttemptId=<attemptId>`），
    写明是合成预览，**不显示下载按钮**。
  - 多条时左右键 / 「上一条·下一条」换条；空格播放暂停；Esc 关闭；预览开着时方向键不翻页。
  - 画面按容器可用高度算宽高并显式写死（不靠 `aspect-ratio`，Safari 兼容）。
- 「一键下载全部」三个选项：成片和封面 / 只要成片 / 只要封面。
  - 桌面工作台：`delivery=1` → `createDownloads`，存到下载根目录的
    `<导出身份目录>/<序号>-v<版本>/`；**同名不覆盖**（内容不符时拒绝覆盖并留在可重试失败态）；
    已下过的跳过；失败只补下载、**从不重新渲染**。
  - 只用浏览器：点选项直接走 1.2 的 ZIP 地址。
  - 没有可下载成片时提示「还没有导出过的成片」。

- `FIXTURE_HOOKS.batchExportStates`（`scripts/team-server/ui-acceptance-fixtures.mjs`）：

  版次与计划走正式 `/api/batch-production/batches`，成片计划/版本/正式产物/渲染任务
