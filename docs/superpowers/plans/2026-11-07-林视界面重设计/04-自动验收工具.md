# 04：自动验收工具

**状态：** `done`

**What to build：** 一条命令就能完成整套检查：启动一份隔离的统一生产服务，用 Chromium 和 WebKit、三种窗口（1536×864、1280×720、1024×720）、浅色和深色，自动登录、点页面。检查包括三项：页面有没有横向滚动、按钮和输入框有没有被切掉一截、视频画面比例对不对和够不够大。后面每张界面任务都往里加自己那一屏的检查。

**Blocked by：** 无（可以马上开始）。

**Parent：** [01 父规格任务](01-林视界面重设计.md)  
**需求依据：** [功能方案](../../specs/2026-11-07-林视界面重设计-功能方案.md) Testing Decisions；V04、V05 的检查手段。

## 实施边界

- 复用现有的团队验收程序：隔离数据根、测试账号、证据目录，以及「付费调用次数为 0」的断言。
- 尺寸检查照原型目录 `tools/checks/` 里的三个脚本改写：「按钮被切」「工具栏藏内容」「画面比例」。
- 提供准备测试数据的入口：员工和管理员账号、一个项目。分镜组、视频、混剪、批次等复杂数据，由用到它的任务自己补。
- 定好按屏组织检查的写法，并写一段说明：后续任务怎么加某一屏的检查。说明放在验收脚本的文件开头，或者放进主流程检查的参考文档。
- 原型的点按清单（`tools/checks/e2e-点按清单.py`）是各屏检查的参考，本任务不全量改写。
- 不改界面。当前的已知问题记为已知失败，不阻塞本任务，例如混剪页在 1440 和 1536 宽时横向多出滚动。09 修好后，这条改为必须通过。
- 实现入口见父任务「页面级验收」一行。

## 验收条件

- [ ] 一条命令完成：启动隔离服务、登录员工和管理员、遍历现有页面，在两种内核、三种窗口、浅色深色下运行，结束后清理干净。
- [ ] 三项尺寸检查对现有页面都给出结果，而且能复现混剪页横向滚动这个已知问题，证明检查真的有效。
- [ ] 付费调用次数为 0，不读写真实数据根。
- [ ] 有一段说明，告诉后续任务怎么加一屏的检查和测试数据。
