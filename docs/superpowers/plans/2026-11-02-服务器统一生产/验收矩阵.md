# 服务器首版验收矩阵

日期：2026-11-02  
状态：测试设计，尚未执行。实施入口见 [任务16](16-全链路压测与试点.md)。每项记录runId、release、配置、数据根、实际命令/步骤、断言、证据和结果，不以空白代表通过。

## 1. 分层与数据隔离

L1：原生Node测试、临时SQLite/文件、模拟供应商，禁止外网及真实凭据。L2：本机HTTP与Electron/浏览器、真实FFmpeg合成测试媒体。L3：目标Windows服务账号、SCM、网络证书、设备更新、真实供应商的小样本。L4：两人试点、20逻辑用户负载、完整备份恢复。

L1/L2不复用运行中的工作台或真实数据根。L3破坏性故障注入在服务器独立验收根/端口执行；真实供应商样本按已授权的模型、素材与预算运行。数据根在模块动态导入前设置。测试脚本若有loader或Playwright特殊启动方式，按文件头执行。

## 3. 容量试验与初始验收目标

以下是实施阶段的起始验收目标，可根据实测定位和修复；不是声称现有3060/64GB已达到。

| 试验 | 负载与目标 |
| --- | --- |
| 控制面 | 20个独立用户会话，混合列表/进度/编辑/任务受理，持续60分钟；排除模型耗时及大文件传输，API p95≤2s、受理p95≤3s，非人为故障阶段5xx<0.1%。 |
| 公平队列 | 多用户持续有ready操作，释放名额后不让其他仍有额度的用户无限饥饿；在可用资源相同的情况下，一个轮转周期覆盖所有合格用户，记录授予序列。 |
| 数据库 | 记录写入耗时、busy等待、事件循环延迟、WAL尺寸；无未处理SQLITE_BUSY、无限增长或阻塞请求堆积；定位长事务而非只增timeout。 |
| 媒体资源 | 先1路，再按同一素材/规格逐级提高；记录耗时、成功率、CPU/GPU/内存、磁盘吞吐与控制面响应。达到保护阈值即停止提高，冻结可持续上限。 |
| 传输 | 小图、多文件夹和至少一个大于现有256MB限制的视频；使用现场最大常见文件再扩测。断线/升级续传文件hash完全一致，无OOM或全批次内存缓冲。 |
| 磁盘保护 | 使用可控小配额测试根模拟不足，暂停新上传/新执行阶段且保留状态；已有写入有预留和恢复证据，不靠自动删生产素材解压。 |
| 长时间运行 | 试点连续运行至少一个完整工作日，记录资源曲线、日志增长、任务堆积和恢复；已完成任务名额最终归零，未知调用单列而非偷偷释放。 |

平台额度测试默认使用模拟供应商证明机制；真实平台只验证合同、结果和已批准的并发档位，不为了达到负载数量无控制地付费。20用户在线不等于20路渲染。未达到上表时报告瓶颈和建议资源限制，不能自行减少已确认模块或用户范围后宣称完成。
