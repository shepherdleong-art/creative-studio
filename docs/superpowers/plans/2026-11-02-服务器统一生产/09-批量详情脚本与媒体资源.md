# 09 批量详情脚本与媒体资源

**状态：** `ready-for-human`
**依赖：** [06 统一准入与调用台账](06-统一准入与调用台账.md)、[08 普通脚本与LLM持久执行](08-普通脚本与LLM持久执行.md)  
**目标：** 统一批量/详情页的子调用与所有本地重处理，覆盖 TTS、对齐、试听和懒预览。

## 改动范围

修改 `lib/batch-production/{executors,runner,narration-executor,proxy-executor,batch-render-executor,packaging,semantic-match}.ts`、`lib/script-studio/{runtime,scheduler,request-budget}.ts`、`lib/media-core/adapters/`、`lib/final-edit/{worker,runtime,heavy-job-lock}.ts`、TTS preview 和视频预览入口。

## 实施步骤

1. 每个实际子调用注册操作，不让一整个批量任务占云端名额到渲染结束；actor/attempt/step 与原租约贯通。链内等待记录 continuation 并让出编排槽，下一次领取从检查点续跑；deferred 不计业务失败或预算消耗。
2. 详情脚本保存方案预算，补 interval tick 防重入；未准入/取消等待不扣已执行调用预算。
3. TTS segment/chunk 稳定身份、完成音频复用；试听 cache miss、转录重试和包装 LLM 均接入。
4. 媒体资源闸门放 media-core，覆盖渲染/包装/分析/代理/懒转码/抽帧；去重并防嵌套锁死，先授权后执行。
5. 启动恢复 prepare/render，不依赖页面触发；保留停机共用 AbortController 与三个既定短信号例外。

## 完成标准

- 批量、单条成片和预览竞争同一实测媒体容量；不会因同时打开预览无限起 FFmpeg。
- 并发 scheduler tick 不突破活跃上限；暂停、停用、停机、明确取消的语义可区分。
- 已成功 TTS 分块不重复付费，未知同步请求可核查，等待不耗脚本预算；全部模块依赖仍从 media-core 方向取共享能力。

## Comments

### 2026-11-02 实现交付

- 批量语义分块、画面分析、口播与包装 LLM 均贯通原 task/attempt/actor/scope/step。`lib/batch-production/{runner,scheduler}.ts` 新增专用 deferred 落账：保存操作/continuation 检查点、让出编排槽，续跑复用原 attempt 与 lease 身份，不增加 attemptCount，也不进入失败/业务重试。语义和包装的执行等待不再被转成关键词/启发式伪成功。
- Script Studio 的 step 显式包含方案、用途及请求序号；文本与独立阶段预算移到真正获准后占用，成功操作重放不重复扣额。scheduler interval/手动 tick 单轮互斥，deferred 续跑不增加 attempt，runner 回 queued 而非把等待记成方案失败。
- 新增 `media-core/execution/sync-operation.ts`，把豆包与 V-API 的每 segment/chunk TTS POST、试听 cache miss、每次转录/对齐 HTTP 尝试接入 06。成功音频、原生词级时间和非降级对齐缓存均可恢复；V-API 生成回执先释放名额再补 OSS 下载；同步 unknown 禁止自动重提。明确 5xx 重试逐 POST 登记且失败细节可重放。
- 新增 `media-core/media-resource-gate.ts` 统一批量、final-edit prepare/render/packaging、分析、代理、TTS 本地处理、懒转码和抽帧容量；默认沿用串行容量 1，可由 `CREATIVE_STUDIO_MEDIA_CONCURRENCY` 按实测上调。可重入 lease 防止嵌套锁死，批量等待转 deferred，local 模块依赖方向未改变。
- core 追加 `media_derivative_jobs` 迁移（未改旧条目），懒预览先走 03/04 文件授权，再复用或登记稳定去重任务；running 租约、失败退避和过期恢复持久化，未完成入口返回 202/retryAfterMs，不再每个 GET 启动 FFmpeg。后台视频下载仍等待预览完成，原件/下载/正式渲染不变。
- `final-edit/lifecycle.ts` 接入团队 runtime `start` 阶段，在 06 开放后主动恢复 prepare 并唤醒 render/packaging worker，不依赖页面。停机仍走唯一 graceful shutdown 和原共用 AbortController；`lut-catalog`、`project-asset-media`、`video-frame` 三个短信号例外保持原样。
