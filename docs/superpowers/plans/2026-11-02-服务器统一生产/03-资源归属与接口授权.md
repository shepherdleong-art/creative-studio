# 03 资源归属与接口授权

**状态：** `ready-for-human`
**依赖：** [02 账号会话与管理入口](02-账号会话与管理入口.md)  
**目标：** 覆盖全部 API、服务端页面与任务发起人，实现项目和画布各自的个人隔离。

## 动手前

阅读 [技术方案](../../specs/2026-11-02-服务器统一生产-技术方案.md) 中对应章节与仓库 AGENTS.md；改动具体模块前读取其 docs/reference 文档。先核实依赖任务的完成证据，再将状态调整为可实施。本任务单描述待做工作，不代表功能已存在。

## 改动范围

拟新增 `lib/team-service/{resource-scopes,task-principals,route-policy}.ts`、`lib/media-core/access-context.ts`、`scripts/team-api-coverage.mjs`；修改 `app/api/`、受管创建服务、`lib/creative-canvas/repository.ts` 及各模块任务创建入口。

## 实施步骤

1. 按路由和 HTTP 方法生成可追踪权限清单；当前基数 204 个 route.ts、29 组，实施时重算。未分类使检查失败，server 禁用同机桌面/实拍入口。
2. 实现根 scope 与子资源继承；项目、画布、未绑定图片、私人全局资源创建时登记，缺 scope 拒绝；多态记录增加一致性检查。
3. 项目/画布/复制/派生/重试与 scope、task principal 在同一事务提交。管理员代操作区分资源 owner 与实际 actor。
4. 列表查询、请求引用、批量操作、后台执行及服务端页面逐项检查归属；通过注入的 media-core 合同保持模块依赖方向。

## 完成标准

- 员工 A 不能通过替换 URL/body ID、批量 ID 列表或跨画布引用访问 B 的数据；管理员可按规则操作。
- 先上传的无项目素材不能被另一用户认领；登记失败回滚实体与初始任务。
- 权限清单对全部方法覆盖，无待分类入口；新路由遗漏有守护测试；用户名/客户端 userId 不充当身份来源。

## 验证

新增 API 权限矩阵及原子创建失败注入；复用 `creative-canvas-schema.test.ts`、项目/批量/脚本创建相关测试。完成后运行 `npm run check:main-path`。

新增行为测试使用临时数据根并在动态导入前设置环境；具体运行方式以已有测试文件头为准。完成时记录修改文件、测试命令/结果、剩余阻断和依赖变化，不把未执行的检查写成通过。
