# 13 用量诊断与管理台

**状态：** `ready-for-human`
**依赖：** [03 资源归属与接口授权](03-资源归属与接口授权.md)、[06 统一准入与调用台账](06-统一准入与调用台账.md)、[07 旧图片视频队列接入](07-旧图片视频队列接入.md)、[08 普通脚本与LLM持久执行](08-普通脚本与LLM持久执行.md)、[09 批量详情脚本与媒体资源](09-批量详情脚本与媒体资源.md)、[10 创作画布接入](10-创作画布接入.md)、[11 续传与设备交付](11-续传与设备交付.md)、[12 轻客户端与可信更新](12-轻客户端与可信更新.md)  
**目标：** 管理员查看和控制每人的月度费用与并发，并按错误编号定位问题；员工只能查看自己的用量、额度和任务。

## 动手前

阅读 [技术方案](../../specs/2026-11-02-服务器统一生产-技术方案.md) 中对应章节与仓库 AGENTS.md；改动具体模块前读取其 docs/reference 文档。先核实依赖任务的完成证据，再将状态调整为可实施。本任务单描述待做工作，不代表功能已存在。

## 改动范围

修改 `lib/{usage-ledger,usage-query,usage-llm,usage-tts,logger}.ts`、画布usage及用量API/UI；拟新增团队任务/错误中心、诊断包与客户端错误上报。

## 实施步骤

1. 执行操作与业务任务/actual actor/版本/上游请求建立关联；指标和错误字段在前置任务即采集，此项完成聚合与UI。
2. 覆盖全部计费入口、重试及未知费用；显示已知预估、未定价和不确定，支持日/月/自选日期、管理员CSV。
3. 错误编号关联人员、项目或画布、任务、阶段、客户端/服务端版本；上传下载/更新错误不假装成供应商失败。
4. 默认诊断不携带素材原文、密钥或签名URL，个人与管理员权限一致；本地Agent用量明确不在服务器统计范围。
5. 成员列表增加今日费用、本月已计／额度、在途预留、剩余可用、当前并发／上限及状态；支持姓名／工号搜索、需要关注筛选、按模块明细。管理员可设置月度金额、个人并发、不限额或暂停新付费生成，保存接入任务 06 的服务端策略接口。
6. 员工端只读额度和阻止原因，提额后重新检查可恢复；降低额度／并发不取消已受理任务，仍允许登录、编辑、查看和下载。金额与未知费用的提示不混同供应商账单。

## 完成标准

- 同一失败可由员工错误编号在管理员端查到实际阶段与版本，普通员工无法查他人。
- 账本与实际尝试有可核对关系，未知费用不显示零；统计故障不绕过强制调度门禁。
- 日志保留/磁盘占用有配置和有界行为，首版只用客户端内通知，不扩充额外管理员审计产品。
- 员工不能通过直接 API 修改自己或他人的策略；管理员修改后所有窗口按最新策略准入，个人和管理端可核对同一账期的已计／预留／并发。余额不足和并发等待有不同的原因提示。
