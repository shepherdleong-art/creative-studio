## 1. 固定部署对象与目录

目标是用户现有 Windows Server 电脑，3060、64GB 内存、公司内网，管理员已有 RDP 管理通道。具体 CPU、磁盘、Windows 版本、IP／域名、账号与 GPU 驱动填入任务 00 的实际报告，不从 9 月记录复制。

```text
<部署根>/
  releases/<releaseId>/        不可变服务器程序及锁定运行时
  service/                    稳定宿主/SCM配置/签名工具清单
  config/                     受ACL保护的部署与供应商配置版本
  client-releases/<releaseId>/ 已签名的轻客户端完整更新包
<数据根>/
  deployment.json             server模式与部署身份
  data/                       SQLite及伴随文件
  storage/                    受管媒体、staging、运行状态、执行回执日志
<备份根>/
  daily/                      最近14个成功日常版本
  pre-upgrade/                升级前备份
  manual/                     人工保留的备份
```

三处根目录可以在同机不同目录；备份是否具备独立物理故障域须记录。现有程序与旧数据路径原处保留，新根不得落在其内部，也不得用整个旧 workbench.db 初始化。所有版本内的业务路径从 dataRoot 解析，不能随 release 工作目录变化漂移。

## 2. 首次上线步骤与结束条件

| 步骤 | 执行动作 | 本步完成证据 |
| --- | --- | --- |
| D01 预检 | 运行拟交付的只读 preflight，核对旧服务／新目录／端口／账号／磁盘／目标网络 | 报告有来源和时间；没有凭据；无旧进程或目录被修改。 |
| D02 隔离验证 | 在测试数据根与独立端口加载待发 server 包；禁止使用生产凭据，执行原生模块与媒体资源探针 | Node ABI、SQLite、sharp完整DLL、FFmpeg/FFprobe、字体与包装资源可用；构建manifest校验通过。 |
| D03 目录与身份 | 创建服务运行账号和新根，设置程序只读、数据/运行状态可写、配置和控制凭据受限ACL | 以服务账号验证读写；程序发布与用户素材不混放；未知目录不清理。 |
| D04 配置与信任 | 生成固定回环app/代理端口、部署ID、受信origin；配置证书、员工根信任与内网访问规则 | 员工机器可验证HTTPS证书，只有入口端口对获准网段开放。 |
| D05 安装服务 | 用锁定的正式WinSW安装入口代理、应用、可选LiteLLM三个SCM服务 | 服务定义固定可执行文件、工作目录、账号、环境来源、日志轮换、失败退避和受控停止合同。 |
| D06 初始化 | 新数据根运行迁移与管理员初始化；管理员配置供应商并发布公共模板/BGM/知识库 | 权限、开放模型、共享池和资源检查通过；未准备的资源有明确不可用状态。 |
| D07 服务验证 | 开机无人登录、RDP断开及注销、SCM重启/停止、代理故障降级、真实编码探针 | 有现场证据；后台不依赖RDP会话，无误停旧服务或FFmpeg/Python残留。 |
| D08 客户端与试点 | 分发可信初始轻客户端和证书信任，负责人及另一同事验收四模块与交付/更新 | 完成验收矩阵功能项、错误定位和两设备恢复，凭据未进入客户端包。 |
| D09 容量与恢复 | 完成20逻辑用户负载、实测资源上限、备份恢复和更新回退 | 已记录资源参数、吞吐与恢复结果；全部必测门槛通过后开放其他员工。 |

云端真实样本使用已经获准的素材、模型和额度；模拟测试不能替代真实平台验证。D02隔离环境和D07/D08现场阶段的证据分开，不能因为RDP中能运行就跳过无人登录与服务账号测试。

## 3. SCM、网络与代理具体合同

应用服务启动独立固定回环端口入口，不能复用强制随机端口的桌面 server-entry。服务宿主向进程显式传入 server 模式、独立数据根、部署ID、应用根及受控配置位置。配置不依赖管理员的交互登录环境、映射盘符或用户级PATH。

入口代理仅转发业务HTTP/SSE/文件流，阻断本机运维、原shutdown和仅本地桌面接口；限制分片请求大小与超时，保持流式转发，避免代理一次缓冲整个素材批次。应用根据受信外部origin验证会话/CSRF；仅信任来自已配置回环代理的转发头。

LiteLLM始终显式绑定127.0.0.1。独立代理服务故障只禁用公司供应商，不关闭应用或外部供应商；应用重启不擅自停止这个SCM服务。停止整套环境时，先停新受理并排空应用，再停止其依赖代理；所有停止都核验服务名、实例、可执行路径与退出状态，不认领未知端口进程。

WinSW stop helper经受ACL保护的控制通道触发gracefulShutdown；设置的SCM停止超时必须覆盖应用排空与子进程退出预算。超时处置限定为该服务已记录的进程树，不按可执行名称全局taskkill。服务退出与异常恢复报告旧实例及在途恢复状态，重复启动在独占锁前被阻止。

## 4. 拟交付的运维接口

以下是任务实现范围，脚本存在且通过测试后才填入对应release的实际调用命令。

| 脚本（位于 scripts/team-server） | 参数与行为合同 |
| --- | --- |
| `preflight.ps1` | 输入选定部署配置和输出目录；只读检查，不打印配置秘密，不安装/停服务。 |
| `install.ps1` | 输入已验证release、部署配置；先显示解析后的根目录/服务名/端口，幂等安装明确服务，不覆盖既有数据。 |
| `status.ps1` | 结合SCM、live/ready、实例ID和受控进程树报告；不只判断端口打开。 |
| `stop.ps1` | 输入部署ID，触发受控停止、等待有界退出，报告残留与恢复影响。 |
| `backup.ps1` | 显式daily/pre-upgrade/manual类型，生成一致性清单、校验与成功标记；轮换规则只作用对应类型。 |
| `release.ps1` | 输入已验证新release和当前部署；执行维护、停机、备份、切换、迁移、自检和恢复接单，阶段可恢复。 |
| `restore.ps1` | 输入明确成功备份、全新恢复目录和目标release；默认停调度恢复，完成核查后才能接单。 |

脚本使用原生PowerShell文件操作；递归清理前校验解析后路径在对应暂存或备份根内，拒绝根目录、链接和越界路径。PS1为UTF-8 BOM，状态JSON无BOM；配置与签名私钥不加入Git或分发包。

## 5. 日常备份

每日作业采用技术方案中的短发布／配置变更／清理屏障。屏障内固定数据库快照、releaseId、配置副本及哈希、执行日志水位和媒体引用pin，解冻后复制这些不可变对象。完成数据库完整性、文件清单/哈希和必要配置校验后，才写success并参与最近14个成功daily版本轮换。

备份失败报告缺失对象、空间或权限问题，不淘汰仍需保留的有效副本。旧manual与pre-upgrade目录不参与daily清理。执行回执日志保留满足恢复水位的记录，不能随数据库快照回退；独立日志并不保证同盘损坏时仍有证据，证据丢失的任务保持未知并禁止自动重提。

## 6. 服务端更新与回退

1. 在隔离数据根完成新release及迁移验证，准备兼容性报告；生产先进入维护状态，拒绝新任务，继续查询和保存已受理任务。
2. 确认本次维护可处理的在途状态，保存执行表与独立回执日志证据；运行gracefulShutdown并确认旧实例和所有写入子进程退出。
3. 创建并验证pre-upgrade完整备份；切换服务指向新release，保持维护状态启动，执行追加迁移和readiness检查。
4. 验证登录、权限、模块就绪、恢复清单、媒体资源和文件读取；确认无不确定调用被重提，再恢复接单。
5. 若代码兼容当前schema且没有不可逆状态变更，回切上一已验证release；若不兼容，恢复成功备份到新根，保留原库和日志供核查。两种回退均先停止新版，再切换。
6. 恢复后默认禁止新付费调度，核对快照之后的提交／回执及供应商状态。没有足够证据的操作留在待核查，不能为了尽快恢复把它们重新POST。

程序回切不等于数据恢复。预检失败、迁移失败、配置错误和容量不足分别记录，不自动回退成无认证local模式。保持一份已验证可用的release和对应恢复说明。

## 7. 轻客户端更新

首次包由可信渠道分发，内置发布验证公钥和固定服务配置。后续员工在客户端点击更新，助手核验签名/包哈希/API及本机状态schema兼容范围，暂存新版本，暂停传输并等待旧进程退出，保存客户端状态快照，再切换版本。

新版本机健康确认前不恢复传输；失败先停新进程，再按兼容规则恢复状态和旧版本。健康提交后才继续上传下载，不能恢复旧快照覆盖新交付记录。旧助手正在使用的目录延后清理；稳定状态和用户下载目录始终独立。旧版不兼容服务器时进入修复入口，不绕过最低版本校验。

## 8. 部署签收记录

交付时填入：实际主机与OS、CPU/GPU/内存、磁盘与故障域、网络入口及证书、服务账号、服务名/端口、release和依赖哈希、数据根、备份根、池预算、媒体资源上限、客户端协议/版本范围、首批验收与恢复证据。文档中的示例值不得自动变成部署实值。
