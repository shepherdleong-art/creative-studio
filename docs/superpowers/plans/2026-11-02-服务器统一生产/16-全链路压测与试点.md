## 动手前

阅读 [技术方案](../../specs/2026-11-02-服务器统一生产-技术方案.md) 中对应章节与仓库 AGENTS.md；改动具体模块前读取其 docs/reference 文档。先核实依赖任务的完成证据，再将状态调整为可实施。本任务单描述待做工作，不代表功能已存在。

## 改动范围

拟新增 `scripts/team-server/*.test.{ts,mjs}`、独立浏览器测试与验收驱动；证据目录 `outputs/team-server-acceptance/<runId>/`；矩阵见同目录 `验收矩阵.md`。

## 实施步骤

1. 先运行隔离模拟供应商的全API身份/共池/故障测试，再运行真实FFmpeg与浏览器传输，最后在目标服务账号下做受控真实供应商与设备验收。
2. 20个逻辑用户分别操作四模块、上传/下载与任务查询；记录并发与延迟分位、错误、CPU/GPU/内存/磁盘/数据库等待和任务公平性。
3. 执行启动/注销/断网/崩溃/磁盘不足/取消停用/未知提交/更新回退/备份恢复矩阵，保留每次断言与失败原因。专测各模块先迁移后恢复、链内等待释放编排槽、回执日志不随DB回退、备份屏障内固定配置，以及客户端状态迁移后启动失败的兼容回退。
4. 负责人和另一位同事跑完整流程，身份隔离、结果交付、诊断和更新都通过后再开放全员；真实付费样本按已批准额度和素材执行。

## 完成标准

- 验收矩阵全部必测项有证据或明确阻断；任何越权、重复付费提交、超额、数据破坏、错误恢复或未知后台实例均不签收。
- 服务端实际版本/依赖/数据根/预算/资源上限记录齐全；20个用户通过不被表述为20路同时渲染。
- 模拟、真媒体、真实供应商、两人试点、容量与恢复分别报告，不能用主流程模拟通过代替其他验收。

## 验证

按验收矩阵运行目标模块测试、`npm run lint`、`npm run build`、`npm run check:main-path`；现场检查只面向隔离验收部署，既有生产数据不参与破坏性故障注入。

新增行为测试使用临时数据根并在动态导入前设置环境；具体运行方式以已有测试文件头为准。完成时记录修改文件、测试命令/结果、剩余阻断和依赖变化，不把未执行的检查写成通过。
