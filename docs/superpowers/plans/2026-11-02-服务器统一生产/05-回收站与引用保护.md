# 05 回收站与引用保护

**状态：** `ready-for-human`
**依赖：** [03 资源归属与接口授权](03-资源归属与接口授权.md)、[04 文件与公共资源隔离](04-文件与公共资源隔离.md)  
**目标：** 落实员工软删除、任务继续、管理员永久清理及备份引用保护。

## 动手前

阅读 [技术方案](../../specs/2026-11-02-服务器统一生产-技术方案.md) 中对应章节与仓库 AGENTS.md；改动具体模块前读取其 docs/reference 文档。先核实依赖任务的完成证据，再将状态调整为可实施。本任务单描述待做工作，不代表功能已存在。

## 改动范围

修改项目/图片/画布/批量/脚本删除接口和列表查询；拟新增 `lib/team-service/lifecycle/`、回收站/清理 API；对接 `team_resource_scopes` 与 `team_file_references`。

## 实施步骤

1. server 模式 DELETE 仅标记隐藏，不复用现有直接 unlink/级联删除；本地行为保持原合同。
2. 新任务不能选择已删除资源；已接受任务按快照读取依赖，已删项目结果抑制自动下载。
3. 管理员清理先建立可恢复清理任务并确认全部模块、历史版本、在途操作和备份引用；有引用时延期，不先删文件。
4. 设计恢复与清理幂等，数据库/文件系统中断能对账；为任务 15 提供发布/清理屏障和备份 pin。

## 完成标准

- 删除正在用的图片不会使任务失败；界面不再展示，且不能作为新任务输入。
- 一个文件被多个版本或备份引用时物理清理延期；重复清理和崩溃恢复不误删。
- 普通员工无永久清理权限；生产数据无自动到期删除，自动临时文件回收仅清理已证明无引用的 staging。

## 验证

复用 `project-delete.test.ts`、`image-delete-policy.test.ts` 的 local 回归；新增 server 软删除、跨模块引用与清理中断测试。

新增行为测试使用临时数据根并在动态导入前设置环境；具体运行方式以已有测试文件头为准。完成时记录修改文件、测试命令/结果、剩余阻断和依赖变化，不把未执行的检查写成通过。
