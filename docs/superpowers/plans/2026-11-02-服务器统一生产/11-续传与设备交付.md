# 11 续传与设备交付

**状态：** `ready-for-human`
**依赖：** [04 文件与公共资源隔离](04-文件与公共资源隔离.md)、[05 回收站与引用保护](05-回收站与引用保护.md)  
**目标：** 交付分片上传、按设备下载账本、不可变文件版本和可恢复发布。

## 动手前

阅读 [技术方案](../../specs/2026-11-02-服务器统一生产-技术方案.md) 中对应章节与仓库 AGENTS.md；改动具体模块前读取其 docs/reference 文档。先核实依赖任务的完成证据，再将状态调整为可实施。本任务单描述待做工作，不代表功能已存在。

## 改动范围

拟新增 `lib/team-service/transfers/`、`app/api/team/{uploads,files,devices,downloads}/`；修改普通/批量/详情脚本/画布导入出口，关闭 server 的绝对路径导入及 reveal explorer；复用 `lib/media-core/file-response.ts`。

## 实施步骤

1. 实现技术方案第6节上传协议，流式分片、缺片查询、重复完成幂等；不再一次 formData 解析整个大批次。
2. staging/ready发布及实体/scope/file登记对账，源文件变化、哈希冲突、取消、磁盘不足有稳定结果。
3. 导出产生固定manifest和版本，客户端Range续传所需ETag/哈希完整；设备订阅起点、回执与账号隔离。
4. 原设备补下载、新设备按需、同名不覆盖、已删项目抑制自动下载；下载失败不调用生成或渲染。

## 完成标准

- 断网/重启/重复分片/重复complete只生成一个正确实体，未完成文件不能进入生产。
- 服务器路径参数无法读取任意文件；两个用户的uploadId/deviceId/fileId不可交换使用。
- 两设备分别记录下载，更新或登出后不串号，旧版本文件不能混入新的.part；空间预留与临时清理可恢复。

新增行为测试使用临时数据根并在动态导入前设置环境；具体运行方式以已有测试文件头为准。完成时记录修改文件、测试命令/结果、剩余阻断和依赖变化，不把未执行的检查写成通过。
