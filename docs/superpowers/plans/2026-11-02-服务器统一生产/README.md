## 先改什么

1. **01 运行模式与共享迁移**：先分清本地／公共服务、数据根和单实例执行权，建立无 worker 提前启动的基础。00 现场核验与此阶段并行，未得到远端证据不猜参数。
2. **02 → 03 → 04**：账号会话 → 原子归属与全接口权限 → 文件及公共资源隔离；在这些完成前不向员工开放服务。
3. **06 与 05／11**：一边建立持久准入／调用回执，一边实现软删除、文件引用保护和续传。两边合并时校验同一 actor／scope／file 身份。
4. **07／08／09／10 → 12／13**：接入全部生产与付费入口，再完成轻客户端更新、用量和错误管理。诊断身份字段在前面任务就采集。
5. **14 → 15 → 16**：隔离环境装配、Windows 常驻与 HTTPS、备份发布恢复，再做全模块、两人试点及目标规模验收。

任务 00 的状态反映目标服务器和平台证据尚未取得。01 已具备开始本地实现所需边界；其余任务在依赖验收后核对具体合同，再把状态转为 ready-for-agent。状态是任务准备程度，不表示代码已完成。无任务完成证据时不能跳到生产部署。

## 交付物与质量门槛

- 代码：明确 local/server 模式；新增团队与共享执行设施；四类模块接入；不破坏本地实拍重组及原有模块依赖。
- 产物：服务器包、免安装轻客户端包、签名更新包；每包有版本、依赖锁定、哈希和独立白名单校验。
- 运维：受控安装／停止／状态／维护／备份／恢复脚本，服务账号与证书步骤，当前 release／数据根／预算记录。
- 证据：各任务行为测试、现有模块回归、主流程检查、真实 Windows 服务／媒体／传输、容量和恢复报告。

所有本机测试先设置临时数据根再动态导入；部署和恢复对明确的新目录操作。迁移只追加，代码/运行数据/配置/备份分离。只在确有新增失败或修改时扩展重跑测试；文档计划阶段不启动付费任务或把未运行测试写成通过。

## 可并行与串行边界

00 的事实采集不阻塞本地开发。03 完成后，04/05/11 文件线与06调度线可以在明确接口后分别推进；07/08/10可在06稳定后并行，但08的公共LLM合同先于09。涉及同一 schema、启动组合根和共享执行接口的修改串行整合，避免各分支自创不同主体或额度含义。

14 可先完成打包及服务脚本的隔离验证；正式安装依赖00现场结果与核心业务验收。15的在线一致性备份依赖05/11的不可变文件和引用保护。16只有在所有依赖具备证据后才能签收；模拟供应商、真实媒体、真实平台与两人试点分别记录。
