# 01 运行模式与共享迁移

**状态：** `ready-for-human`
**依赖：** 无；以已确认需求和技术方案为输入。  
**目标：** 建立 local/server 运行隔离、独占执行、团队与执行设施迁移入口，先保证新服务不会误用旧库或提前启动 worker。

## 动手前

阅读 [技术方案](../../specs/2026-11-02-服务器统一生产-技术方案.md) 中对应章节与仓库 AGENTS.md；改动具体模块前读取其 docs/reference 文档。先核实依赖任务的完成证据，再将状态调整为可实施。本任务单描述待做工作，不代表功能已存在。

## 改动范围

修改 `instrumentation.ts`、`lib/db.ts`、`lib/shutdown.ts`；拟新增 `runtime/team-server-entry.cjs`、`lib/team-service/{config,schema,readiness,bootstrap}.ts`、`lib/team-service/runtime/`、`lib/media-core/execution/{schema,readiness,contracts}.ts`。复用 `lib/schema-upgrade/`；保留 `runtime/server-entry.js` 本地合同。

## 实施步骤

1. 实现显式运行模式、部署标识与独立数据根检查；server 根被 local 入口打开时拒绝启动。
2. 独占锁在业务数据库初始化及恢复前获取；定义 instance/fence、live/ready 和维护状态。重复实例不能通过锁超时接管存活实例。
3. 新增两个独立追加式迁移流与 readiness；关闭 server 模式时不启动团队 worker，不改已发布迁移。先冻结技术方案第 3/5 节类型合同，后续任务在各自 schema 追加。
4. 改启动/停机注册接口；server 禁用旧 instrumentation 自动启动，把每个模块拆成只迁移、注册恢复、恢复、启动四步，先通过模块 schema 再复核公共占额，最后启动 worker。补恢复与 drain 合同；身份/调度 readiness 失败关闭业务入口，本地兼容行为保留。

## 完成标准

- 两个子进程竞争同一根，只有一个进入恢复/付费入口；不同根互不影响，异常退出后可重新取得权利。
- 迁移重复执行无变化，故障有备份与审计；失败不能开启无认证公共 API。
- 固定端口服务入口与随机端口桌面入口分开；停止及重启无真实生产任务被触发。
