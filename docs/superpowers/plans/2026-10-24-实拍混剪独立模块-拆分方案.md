# 实拍混剪独立模块：拆分方案（第二版）

- 日期：2026-10-24。第二版按用户的 8 条意见和「编辑器复制一份」的选择修订。状态：已确认，交给 DeepSeek 执行，具体步骤见[执行清单](2026-10-24-实拍混剪独立模块-执行清单.md)。
- 起因：Codex 在分支 `live-action-formula-mixcut`（提交 `9a44481`）把「实拍公式混剪」做成了批量生产里的第二种剪辑方式。批量生产因此变重，入口也和批量混在一起。现在改成像创作画布那样的独立模块。
- 和第一版的区别：第一版打算精简重写。现在审片要用批量那套编辑器，外部配音导入、花字识别、包装锁定也都要，所以改成把 Codex 的公式代码和批量编辑器整体搬进新模块，不再重写。
- 以后不再按 Codex 写的功能方案和开发计划执行，但规则细节照样能查：PS866 的素材核对数字、29 个缺号清单在那份功能方案的 §1 和附录 A。

## 1. 已定的

| 项 | 定了什么 |
| --- | --- |
| 入口 | 顶部导航加「实拍混剪」，和「创作画布」并列 |
| 任务 | 不关联已有项目，产品名在新建任务时填 |

| 代码边界 | 批量的审片编辑器复制一份进实拍混剪，它背后的编辑、渲染、素材预览代理和后台任务也一起复制；批量生产恢复成 main 的样子，一行不改 |

## 2. 用户怎么用

1. **新建任务**：填任务名和产品名。
2. **导入素材**：选视频文件夹，可以同时导入素材命名表。页面列出编号齐全、缺号、同号多版本、没有编号四类。
3. **原声识别**：把 VO 素材送火山识别，得到台词和每个字的时间，都可以手改。
4. **导入脚本表**：沿用 Codex 已经做好的 AI 识别表头，识别不对时手动指定列。脚本可以逐行修改，也可以导入已有的替换建议。
5. **生成**：选脚本和份数，设置声音、音色、包装、封面和 BGM，然后点「生成」，后台逐条制作。
   - 声音有三种模式：原声优先 + 其余配音（默认）、统一配音、纯原声。
   - 包装和封面各自可以整批统一，也可以每条随机。
   - 统一配音模式下，可以给某条脚本导入现成的整篇配音（音频加 SRT）。
6. **审片**：用批量那套工作台。成片上会标出「替换 N 处」「人工改编」「目标 / 实际时长」「需处理」。包装和封面可以分别锁定，没锁定的可以一键重新随机分配。看完点确认。
7. **导出**：勾选已确认的成片，统一导出到任务文件夹 `storage/live-mixcut/exports/<任务名>-<日期>/成片/`。
   - 视频和封面放在一起，另附一份清单 CSV，记录每条用了哪些素材、哪里替换过。
   - 文件名格式：`<产品名>-脚本141-第02份-f3.mp4`。

制作规则的默认值如下，审片时都能看到，也都能改：

- **选片**：按公式顺序，按编号精确匹配。同号有多个版本时，按固定顺序自动选一个。缺号时先用替换建议；没有建议，就让模型从命名表里挑同卖点或同动作的候选。所有替换都标「替换·待审」；实在找不到，这条就标「需处理」，不硬凑。
- **口播镜头**：保留原声，剪掉话前话后的空白，各留约 0.12 秒。
- **非口播镜头**：不用开头和结尾。默认去掉开头 3 秒、结尾 2 秒，从剩下部分的正中间取需要的长度。素材不够长时，开头最少也去 2 秒；还不够，就少去一些，并在审片里标出来。
- **配音**：剩下的文案由模型分配到非口播镜头上，只用原句，原声已经说过的不再配。
- **花字**：模型识别文案里哪些是要上屏的花字、哪些是拍摄备注。花字放到对应镜头的卖点轨道上；备注既不配音，也不上屏。
- **时长**：完整台词优先。超出目标时长时，按实际长度出片并标出差异，不加速、不截话、不循环。
- **输出**：3:4、1080×1440、24fps，片头 20 帧封面，字幕按真实声音生成。PS866 素材是竖屏 9:16 拍的（2160×3840），出 3:4 会把上下各裁掉约 12.5%，口播镜头要留意别裁到头。

## 3. 不做

- ZIP 导出包：Codex 已经写的 `export-package*`、产物包接口和对应面板都删掉。
- 新的防护逻辑一律不加。Codex 已经写的防护先原样带着，真碍事了再删。
- 批量生产里的「剪辑方式」选项、`planningMode`、公式开关和所有公式分支，随批量恢复成 main 一起去掉。

## 4. 模块结构

目录照搬批量的布局，文件之间的相对路径不变，这样搬过来基本不用改 import。以后要整理再整理：

```text
app/live-mixcut/                    任务列表、任务页（四步：准备素材 → 脚本与口播 → 检查成片 → 导出成片）
app/api/live-mixcut/                接口，结构和 app/api/batch-production 一样，另加 projects/（任务的增删改查）
components/live-mixcut/             复制来的批量界面（审片工作台在 review/ 下），公式面板在 formula/ 下
lib/live-mixcut/                    复制来的批量后端，公式逻辑在 formula/ 下
  config.ts                         开关
  schema.ts schema-v1-sql.ts        独立迁移流：v1 由脚本从 Codex 的迁移结果生成，以后只追加
  projects.ts                       任务（界面上叫"任务"，代码里沿用 projectId）
lib/media-core/adapters/volc-asr.ts      新写：火山极速版识别
```

**表**：把 Codex 的 26 版公式迁移，连同公式用到的那几张批量表（成片计划和版本、素材、后台任务等），整理成一版 v1 一次建齐。表名统一以 `live_mixcut_` 开头，索引以 `idx_live_mixcut_` 开头，以后只追加。任务表叫 `live_mixcut_projects`，因为复制来的代码处处用 `projectId`，正好对上。

**外部服务**：

- 配音：用设置页里配好的配音供应商，只读 `final_edit_tts_providers` 表。
- 模型调用：走 `media-core/adapters/text-json.ts`。
- 火山识别的 Key：只读 `.env.local` 里的 `CREATIVE_STUDIO_VOLC_ASR_API_KEY`。

## 5. 搬家清单

做法是先整体复制，再剪掉用不上的部分：把这条分支上的三个批量目录（已经带着 Codex 的公式代码，以及它给审片界面加的原声轨、换片、包装锁定）整体复制成 `live-mixcut`，统一改表名、接口和路径，再删掉只属于普通批量的部分。

| 内容 | 怎么处理 |
| --- | --- |
| 公式后端、公式界面、公式接口 | 全部带过来，只有 ZIP 导出包相关的删掉 |
| 批量的审片界面、编辑命令、渲染、工作台视图、后台任务、素材、封面、字幕、BGM | 带过来，原样用 |
| 只属于普通批量的部分：语义分配、整篇口播、脚本导入、素材分析、代理管理等 | 搬完后删掉。用检查脚本找出没人用到的文件，逐个删 |
| 导出 | 沿用批量的「正式导出到文件夹」，路径改成实拍混剪自己的，再补一份清单 CSV |
| media-core 里 Codex 新加的文件 | 留在 `lib/media-core/`：`subtitle-svg`、`music-ducking`、`music-timeline`、`audio-edges`、`audio-protection`、`audio-stereo`、`adapters/text-json`、`bgm-catalog`。`verified-zip` 只有 ZIP 用，删掉 |
| 公式测试（49 个） | 39 个搬成 `scripts/live-mixcut-*.test.ts`，作为搬家后的回归；测旧迁移流和 ZIP 的 10 个删掉 |
| 公式的浏览器测试（7 个）和 PS866 验收脚本（2 个） | 都走旧的批量入口，删掉。新入口由你亲手点一遍来验收 |
| 两个 PS866 只读工具（核查两张表和素材目录、按公式抽帧） | 改名为 `live-mixcut-ps866-*`，继续用 |

复制完以后，批量生产自己的三个目录（`lib/batch-production`、`components/batch-production`、`app/api/batch-production`）整体恢复成 main 的版本。

## 6. 规模和代价

- 从批量复制过来的代码大约 1.5 万行，其中界面约 9 千行。以后两边各有一份：批量编辑器加功能、修 bug，实拍混剪要手动跟一遍。当初批量照搬单条的编辑器，代价也一样。
- 实拍混剪整个模块预计 2.5 万行上下，和批量差不多大。
- 批量生产回到 main 的样子，里面不再有任何公式分支。
- 等两边都稳定了，可以再把编辑器抽成两边共用的一份，这次不做。
