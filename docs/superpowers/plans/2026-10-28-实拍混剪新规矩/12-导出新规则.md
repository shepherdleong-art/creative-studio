# 12：导出新规则

**要做什么：** 导出位置不变。一个任务只有一个「成片」文件夹，不再按批次分。「同一条」指同一个原脚本号、同一份次，按现有冻结的导出身份算出的文件名来认，不管来自哪个批次。同一条第一次导出时不带后缀；再导出时，新的叫 `-v2`、`-v3`，上一版的视频连同封面挪进「成片」旁边的「旧版」文件夹。`清单.csv` 在「成片」里，只列当前这一套。这取代现在 `-02`、`-03` 在同一个文件夹里并存的做法。

## 完成记录

- **一个任务一个「成片」**（`lib/live-mixcut/batches.ts`）：`resolveLiveMixcutBatchExport` 不再按批次算子目录，所有批次都返回任务的 `exportDirName`；兼容字段 `batchExportDirName` 保留但恒为空。工作区、打开文件夹、发布和清单仍统一走这个解析入口。
- **版本规则**（`lib/live-mixcut/batch-export.ts`）：首次导出 `<身份>.mp4`；同一条再导出 `<身份>-v2.mp4`、`-v3.mp4`。版本号取「成片」和「旧版」里同名文件与正在占位的 `.publish.lock` 的最大值加一，所以不同批次、同一条身份也接着排；同时预留会拿到不同版本号，不会互相覆盖。身份就是现有冻结导出身份（原脚本号、份次、包装）。
- **旧版归档**（同文件）：新版本发布后，把「成片」里同一条的旧版本视频和封面挪进同级的 `旧版/`（不在「成片」里面），旧文件不删除。首次导出不创建 `旧版`。归档中途失败会把已挪的文件退回并撤销新文件；「旧版」重名时加 `-2` 后缀，不覆盖。
- **正式产物路径同步**（`lib/live-mixcut/phase-e.ts`）：归档成功后在登记新正式产物的同一事务里，把旧 artifact 的 `relativePath` 改到「旧版」，旧版下载入口继续可用。注册事务失败或并发重复发布时把已归档文件退回原处，再清理本次多复制的文件。
- **清单按任务写**（`lib/live-mixcut/formula/export-manifest.ts`、`app/api/live-mixcut/batches/[id]/exports/route.ts`）：`writeFormulaExportFolderManifest(db, projectId)` 扫描整个任务（含归档批次，排除软删除）的当前正式产物，只收「成片」里这一层的文件；跨批次同一条按身份去重，留最高版本。清单仍在 `成片/清单.csv`，旧版不列。非公式批次不掺进公式清单。
- **测试**：`scripts/live-mixcut-export-identity.test.ts` 在真实渲染/发布流程后追加一次修改再导出，断言 `-v2`、旧视频和封面进 `旧版`、「成片」只剩当前这一套、清单列出 v2 不列 v1、首次导出没有 `旧版` 文件夹；公共预留接口断言 `-v2`、`-v3`，并用另一个批次 ID 断言跨批次接着排。`scripts/live-mixcut-batches.test.ts` 改成断言两个批次共用任务目录、只有一个任务级清单、发布路径不再有批次子目录。`scripts/live-mixcut-execution.test.ts --publish` 的返工后缀改为 `-v2`、旧版存在且原路径不再有文件、清单只列当前版本。`scripts/live-mixcut-external-narration.test.ts` 跟着新签名取任务级清单。
