# 06：AI 判断

**要做什么：** 每条成片在定声音之前调用一次文本模型，沿用生成时选的模型。一次给出三样：

1. 文案哪一行和公式里哪段口播意思相近；
2. 口播一段都没用上时（以及「统一配音」时），最搭的是哪一段；
3. 每行文案相关的非口播素材排序。补镜和替代镜头按规矩从这里挑。

结果按内容存：同样的文案、同样的素材直接复用，不重复问。AI 回了就照用，不停下来等人。这一步做出能单独调用的 AI 判断和它的缓存；接进生产流程在任务 08。

## 完成记录

- **追加迁移 v4**：`lib/live-mixcut/schema-v4-sql.ts` 新建 `live_mixcut_formula_judgments`，按 `(projectId, contentFingerprint)` 唯一；存三样判断的 JSON、模型身份、提示词版本和时间。只追加，不改 v1–v3。
- **判断模块**：`lib/live-mixcut/formula/judgment.ts`，`judgeFormulaFilm(db, projectId, input, model, signal)`。
  - 输入：文案各行、口播（编号 + 原声实际说的话 + 文件名台词作参考）、非口播素材（编号 + 文件名 + 画面描述，描述可为空）。
  - 提示词要求只回 `similar` / `bestVo` / `related` 三个字段；`similar` 对照 `speechText`，`plannedLine` 只作参考；`related` 每行最多 20 个并说明依据文件名和描述。资料里的指令一律不执行。
  - 解析时丢掉对不上号的条目：不存在的行号、口播编号、素材 assetId，重复项只留第一次；空排序不留。整份格式不对（含适配器报「无效 JSON」）重试一次，仍不对就失败并提示重新生成；调用本身报错不重试，失败信息写明模型名，可重试。没有「等人工」。
  - 缓存指纹 = 提示词版本 + 模型 id/model + 文案行 + 口播（按编号排序）+ 素材（按 assetId 排序）。同样的内容再问直接读缓存；文案、素材描述、模型任一变化都重新判断。只写缓存、不调 AI 的路径由任务 08 接进生产。

- **长度上限**：判断要按行排 20 个素材，回复比一般脚本调用长。`lib/media-core/adapters/text-json.ts` 的 `resolveTextJsonModel` 增加可选的 `{maxTokens, timeoutMs}`（默认仍是 4096 / 60 秒）。真实核对里脚本 1 用了 129 秒，**任务 08 接线时必须传更大的上限**（验收脚本用的是 16384 / 180 秒）。
