# 11：恢复这一行

**要做什么：** 因「AI 判断相近」而省掉的行旁边，有「恢复这一行」。点一下，这条成片把这一行当普通文案，按同一套规矩重新定声音；那段口播如果不再顶任何一行，就按「一段都没用上」处理。然后只给这一行合成配音，重新排时间、重新渲染。结果成为这条成片的新版本，回到待审。只影响这一条。「文案逐字写着」的行不提供恢复，因为那段口播本来就在说这句。

## 完成记录

- **恢复入口**（`lib/live-mixcut/formula/restore-line.ts`）：只接受当前版本是新规矩排出来的成片；校验这次制作输入还是当前版本、成片版本没被替换。找到这次排片里「AI 判断相近」省掉的那一行后，新建一版定声音（输入原样复制，只追加 `restoredLines`），并排一条定声音任务。之后配音、排时间、执行检查和封面沿现有链子自动往下走，不需要额外逻辑。重复点同一行返回「已恢复」，不会重复建修订；「文案逐字写着」的行、行号越界、版本过期都带原因拒绝。
- **口播不再顶行**（`lib/live-mixcut/scheduling/voice.ts`，任务 08 已留好的 `restoredLines`）：恢复的行跳过 AI 相近判断，改回普通文案；原来顶它的那段口播如果不再覆盖任何行，按「一段都没用上」处理并记下原因。
- **新版本**（`lib/live-mixcut/formula/schedule-store.ts`、`schedule-output.ts`）：定声音或配音变了就新排一次时间，产出这条成片的新版本并覆盖为当前版本；旧版本保留。恢复不会动同批其他成片。
- **配音复用**（`lib/live-mixcut/formula/narration.ts`）：配音缓存按「文字 + 音色/服务」寻址，恢复后新一版配音只有恢复的这一行是新键，其余整段命中缓存，不再调用配音服务。
- **读取语义收紧**（`lib/live-mixcut/formula/pipeline-v2.ts`、`schedule.ts`、`render-audio.ts`）：`readFormulaVoiceResult` / `readFormulaVoiceNarrationResult` 改成「最新一版有结果才算有」，不再回退到旧修订；排时间和渲染按阶段自己的 `voiceStageId` / `narrationStageId` 读结果。这样恢复期间续接扫描不会拿旧配音建新阶段（改动前会先建出一版只看旧行的配音，导致排时间缺行失败）。
- **接口**：`POST /api/live-mixcut/batches/[id]/formula/outputs/[planId]/restore-line?projectId=…`，正文 `{ lineIndex, expectedOutputVersionId }`；沿用公式接口的就绪检查、无缓存头和错误映射，提交后拉起批量调度。
- **界面**（`components/live-mixcut/review/BatchReviewInspectorDock.tsx`、`lib/live-mixcut/formula/selection-summary.ts`）：「AI 判断意思相近」的省行标记带 `lineIndex` / `restorable`，属性栏里该条后面出现「恢复这一行」按钮；「文案逐字写着这句」的标记不可恢复，不显示按钮。点击后按钮进入忙碌态，成功提示「正在补配音并重新排时间」，并先在本页隐藏该标记，等工作台 3 秒轮询刷新出新版本和标记。
