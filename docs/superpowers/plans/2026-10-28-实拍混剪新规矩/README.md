## 怎么接任务

- 挑「要先做完」的任务都已完成的那一个。现在能开工的是 01、02；02 做完后，03、04、07、12 可以同时做。
- 动手前读确认单里对应的那一节。任务 16 之前，`docs/reference/实拍混剪.md` 写的还是旧规矩；和确认单冲突时，以确认单为准。
- 规矩上拿不准的，停下来问用户，不要自己定。
- 在真实素材上要花钱的（分析画面、AI 判断、配音），先告诉用户用哪个模型、大概调用多少次，用户同意了再跑。
- 做完一个任务：勾上验收项，把「状态」改成 `done`，在文件末尾补一段「完成记录」，写做了什么、跑了哪些测试、结果、遗留问题。
- 只提交到 main，不推送。推送等用户开口。

## 所有任务都要守的

- 实拍混剪只从 `media-core` 取共享能力，不从批量生产和成片剪辑导入；开关关着时不建表、不跑后台。
- 数据库只追加迁移（模块自己的迁移流）。去掉的功能只删入口和代码，旧数据表不删。
- 10-26 的 6 个旧批次不迁移、不重排，要一直能打开看。
- 真实脚本和素材不进仓库：自动测试用编造的数据；核对真实数据的脚本只读数据库。原型 `outputs/2026-10-28-实拍混剪排片原型/` 只在本机。
- 不碰画布的改动（创作画布外部适配器、视频元数据和它们的测试）、`brand/`、10-19 双视角评审文档。
- 改哪个文件，先跑同名测试；动到跨步骤的数据交接，再跑 `npm run check:main-path`。
- 代码里的名字容易看错：任务叫 project（`projectId` 就是任务 ID），批次叫 production，后台作业叫 task。
