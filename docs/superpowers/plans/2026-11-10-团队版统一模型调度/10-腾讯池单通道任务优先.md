# 10：腾讯池单通道任务优先

**状态：** `ready-for-human`

**Blocked by:** [04：Image 2 拥堵分流](04-Image2拥堵分流.md)  
**规格覆盖：** A16  
**阅读入口：** [索引与共同约定](README.md)、[功能方案](../../specs/2026-11-10-团队版统一模型调度-功能方案.md)；开始前核对阻塞任务的实际成果与交接记录。

**What to build:** 多个成员和模型争用腾讯共享池时，在现有公平约束内优先只剩该通道的任务；溢出图片不突破名额、个人限制或抢占运行任务。

## 范围与边界

- 在 04 的容量选路上加入腾讯池内的单通道任务优先规则，保留已有成员公平和个人上限。
- 覆盖同池原有模型、仅腾讯支持的规格、七牛明确失败后只剩腾讯的任务，以及仍能等待七牛的溢出图片。
- 优先级作用于未来准入，已提交任务继续执行。

## 验收标准

- [x] 明确并记录“同等调度条件”的可执行定义：先遵守成员公平、暂停、预算和个人上限，再在可比较任务中优先没有其他可用通道者。
- [x] 只支持腾讯的模型或规格、以及七牛已明确失败而只剩腾讯机会的任务，能在与普通溢出图片竞争时获得预期优先机会。
- [x] 候选数量基于任务冻结要求、未用通道及当前可用条件判断，不能把无权限或无预算任务加入合格需求占用公平份额。
- [x] 多个成员持续提交时仍有公平进展；普通溢出任务不因规则实现错误长期饥饿，并给出可复现的调度证据。
- [x] 同一真实池的多个别名、模型和入口共享容量，动态下调容量不抢占现有调用，后续准入不超售。
- [x] 某个池受阻不无理由阻塞同成员在其他独立空闲池的合格任务；任务选择与名额领取保持原子和幂等。
- [x] 员工能看到真实等待状态，管理员能理解等待原因、池占用与优先条件，而非误以为额外开出了新名额。
- [x] 单成员借用空闲容量、成员数大于池容量以及手动固定上限等已有调度行为保持有效。

## 验证与演示

1. 用模拟池和持续到达任务构造同成员／跨成员、单池／多池、别名共池及七牛失败后转腾讯的对照序列。

2. 检查实际启动顺序、每成员进展、最大占用和取消／容量变化后的后续准入，不仅断言排序函数输出。

验证使用隔离数据和模拟供应商。涉及真实付费调用或生产变更时，以用户另行明确授权为准；没有外部证据的结论在交接中明确标为未验证。

**实现事实**

- 新增 `lib/media-core/unified-media/admission-priority.ts`：按冻结的逻辑任务、通道状态、真实供应商可用性及通道健康动态计算候选通道数。当前腾讯尝试若仍有未提交且可用的七牛通道，归为 `overflow`；仅腾讯规格、七牛明确失败/停用/缺行/健康避让等归为 `single_channel`；非统一旧任务保持普通单通道优先级。
- 准入外层仍按成员持久轮转；同一成员内先应用权限、暂停、预算、未知费用、个人/公平与池容量门禁，再在合格候选里按 `single_channel > overflow` 选择。权限/预算门禁失败仍保持原 FIFO 排障语义，不会用另一个可执行任务把真实阻塞藏起来。
- 普通溢出任务等待满 30 秒后与单通道任务同权，并按 `readySeq` 优先，防止持续到达的单通道任务造成长期饥饿。成员公平仍优先于腾讯偏好：轮到的成员先获得一次准入，再轮到其他成员。
- execution schema v11 追加 `admissionPriority/admissionCandidateCount/admissionTraceJson` 与索引，记录生效优先级、原始候选数、可用通道 key、求得时间和是否老化。未达到优先条件的旧任务保持默认普通值，不改历史权益/次数。
- 管理员任务详情显示“单通道任务优先 / 可溢出任务（候选 N 条通道）/ 普通调度”及老化标记；员工只看到原有等待状态，不下发内部调度轨迹。普通池容量、别名共池、动态降容不抢占与原子领取均复用现有 admission/reservation，不新增名额。
- 本次没有改队列提交顺序或供应商协议；偏好仅影响未来准入。`execution-admission` 原有零预算成员不稀释公平份额、独立池不互相阻塞、多池原子性测试继续通过。
