# 13：管理员待核对任务闭环

**状态：** `ready-for-human`
**执行进度：** 已完成
**Blocked by:** [03：Image 2 失败自动兜底](03-Image2失败自动兜底.md)  
**规格覆盖：** A20  
**阅读入口：** [索引与共同约定](README.md)、[功能方案](../../specs/2026-11-10-团队版统一模型调度-功能方案.md)；开始前核对阻塞任务的实际成果与交接记录。

**What to build:** 管理员从统一列表查看未知任务，凭证据补远端 ID、确认未创建或终态；恢复查询、备用资格、费用及占用同步更新，操作有权限、审计和幂等约束。

## 范围与边界

- 为管理员提供统一的待核对任务列表和基于证据的处置闭环，覆盖共享任务尝试来源。
- 依据 03 发布的任务来源、尝试和结果交付合同实现通用能力；后续接入入口通过同一关联被识别。
- 不会给员工增加强制重发按钮，也不把等待时间当作远端失败证据。

## 验收标准

- [ ] 管理员可从列表找到未知任务，查看成员、项目／画布、统一模型、实际通道、尝试、已知远端 ID、原因、最近检查及费用／名额占用。
- [ ] 普通员工及越权请求不能查看其他成员的核对明细或执行管理操作；日志和返回值不包含密钥或完整签名参数。
- [ ] 补入有依据的远端 ID 后，关联原通道和原尝试继续查询，不创建第二份原任务，也不允许将另一个成员／通道的任务误挂入。
- [ ] 确认未创建时记录依据并修正原尝试；只有未取消、仍有剩余通道且再次满足权限、预算和准入条件的任务才能继续备用。
- [ ] 确认成功时补齐原结果及费用核对；确认失败时按剩余机会处理；都不覆盖历史真实身份或重置通道次数。
- [ ] 已取消任务核对后只收尾，不启动备用和下游；下载失败仍走原结果补抓。
- [ ] 无法确认时保持待核对，清楚展示仍存在的占用，不提供以超时为由强制释放并重发的捷径。
- [ ] 每次变更记录真实管理员、证据摘要、前后状态和时间；重复提交、两个管理员同时处理、自动查询同时回报都保持幂等及可解释冲突。
- [ ] 名额与费用分别按证据处理，不因已确认生成终态就擅自把未知费用归零；结果登记、释放及结算不重复。
- [ ] 各来源通过统一合同可关联到正确结果交付入口；列表没有依靠任务名称或文件名猜归属的逻辑。

## 交接要求

- 说明实际可用的核对证据和上游未知限制，不把模拟记录核对写成已完成真实供应商账单对账。
- 在下方 Comments 记录实际完成范围、验证证据、改动说明、剩余限制及后续任务需要的合同；满足全部验收项后，将执行进度改为“已完成”。

**实现事实**

- 新增 `execution_media_tasks.reconcileVersion` 与 `execution_media_reconcile_actions` 审计表（execution schema v10）。每次动作在同一写事务内先校验版本、递增 `reconcileVersion` 并写入 `in_progress` 审计行；完成后再写前后状态与结果，重复请求按 `(mediaTaskId, idempotencyKey)` 返回原结果，不同请求复用一个幂等键返回冲突。
- `GET /api/team/reconcile` 只允许管理员，返回统一任务、成员、项目／画布、统一模型、真实通道、操作、尝试、远端 ID、等待原因、最近检查、预留／实际费用、held 名额和取消意图；`legacyItems` 单列无法关联统一任务的旧 unknown operation 与 journal orphan，不按名称推测归属。响应和日志不包含 baseUrl、API Key、providerSnapshot 或签名参数。
- `POST /api/team/reconcile` 支持：补远端 ID、确认未创建、确认成功、确认失败、仍无法确认。目标必须同时匹配统一任务、实际通道、原操作和原尝试；远端 ID 已属于另一条尝试时拒绝。
- 补远端 ID 只通过 `ExecutionFacade.reconcile({kind:'remote_id'})` 关联原传输，随后把业务任务放回 `needs_check` 走原通道续查；不新建 operation、不重置通道次数。已取消任务只保留核对身份，业务任务保持 canceled，不重新进入生成队列。
- 确认未创建与确认失败先调用 `ExecutionFacade.reconcile` 修正原尝试/费用，再复用 03 的 `handleUnifiedImageExplicitFailure`；只有未取消、仍有兼容通道且后续重新通过权限／预算／池准入的任务才进入备用。两通道都耗尽时保留原身份并失败，不产生第三次提交。
- 确认成功写原尝试的 succeeded 终态与可选核账费用；管理员可补原结果地址（也可从原回执读取，地址只存业务行用于补下载，不回传/写审计），有地址时业务任务进入 `download_failed` 只补下载，否则 `needs_check` 沿原远端身份续查。未提供实际费用时保持 `unknown/costState` 和原预留，不显示为确定零元；已取消任务确认成功只收尾，不重新调度。
- `仍无法确认` 只追加 `still_unknown` 证据，保留原占用；已取消任务仍是 canceled。审计记录真实管理员、证据摘要（脱敏后最多 1000 字）、动作、前后状态、结果与失败码。
- 新增管理员「待核对」页面与导航入口，页面展示未知状态、真实通道、尝试/费用/占用和审计摘要；没有强制失败、超时释放或重发按钮。
