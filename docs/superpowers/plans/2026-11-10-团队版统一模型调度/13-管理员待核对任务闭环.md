# 13：管理员待核对任务闭环

**状态：** `ready-for-agent`  
**执行进度：** 未开始  
**Blocked by:** [03：Image 2 失败自动兜底](03-Image2失败自动兜底.md)  
**规格覆盖：** A20  
**阅读入口：** [索引与共同约定](README.md)、[功能方案](../../specs/2026-11-10-团队版统一模型调度-功能方案.md)；开始前核对阻塞任务的实际成果与交接记录。

**What to build:** 管理员从统一列表查看未知任务，凭证据补远端 ID、确认未创建或终态；恢复查询、备用资格、费用及占用同步更新，操作有权限、审计和幂等约束。

## 范围与边界

- 为管理员提供统一的待核对任务列表和基于证据的处置闭环，覆盖共享任务尝试来源。
- 依据 03 发布的任务来源、尝试和结果交付合同实现通用能力；后续接入入口通过同一关联被识别。
- 不会给员工增加强制重发按钮，也不把等待时间当作远端失败证据。

## 验收标准

- [ ] 管理员可从列表找到未知任务，查看成员、项目／画布、统一模型、实际通道、尝试、已知远端 ID、原因、最近检查及费用／名额占用。
- [ ] 普通员工及越权请求不能查看其他成员的核对明细或执行管理操作；日志和返回值不包含密钥或完整签名参数。
- [ ] 补入有依据的远端 ID 后，关联原通道和原尝试继续查询，不创建第二份原任务，也不允许将另一个成员／通道的任务误挂入。
- [ ] 确认未创建时记录依据并修正原尝试；只有未取消、仍有剩余通道且再次满足权限、预算和准入条件的任务才能继续备用。
- [ ] 确认成功时补齐原结果及费用核对；确认失败时按剩余机会处理；都不覆盖历史真实身份或重置通道次数。
- [ ] 已取消任务核对后只收尾，不启动备用和下游；下载失败仍走原结果补抓。
- [ ] 无法确认时保持待核对，清楚展示仍存在的占用，不提供以超时为由强制释放并重发的捷径。
- [ ] 每次变更记录真实管理员、证据摘要、前后状态和时间；重复提交、两个管理员同时处理、自动查询同时回报都保持幂等及可解释冲突。
- [ ] 名额与费用分别按证据处理，不因已确认生成终态就擅自把未知费用归零；结果登记、释放及结算不重复。
- [ ] 各来源通过统一合同可关联到正确结果交付入口；列表没有依靠任务名称或文件名猜归属的逻辑。

## 验证与演示

1. 使用已成功但丢 ID、明确未创建、明确失败及无法核实四种模拟记录，完成管理员从列表到状态／费用／占用更新的操作。

2. 加入员工越权、错误远端关联、重复操作、并发管理员和已取消任务样本，检查审计及付费调用次数。

验证使用隔离数据和模拟供应商。涉及真实付费调用或生产变更时，以用户另行明确授权为准；没有外部证据的结论在交接中明确标为未验证。

## 交接要求

- 发布核对动作的证据要求、权限、冲突行为及来源交付扩展合同，供新入口与 12、15 验证。
- 说明实际可用的核对证据和上游未知限制，不把模拟记录核对写成已完成真实供应商账单对账。
- 在下方 Comments 记录实际完成范围、验证证据、改动说明、剩余限制及后续任务需要的合同；满足全部验收项后，将执行进度改为“已完成”。
- 发现超出本任务的新需求时单独记录，保持本任务边界；阻塞任务未完成时先报告缺失成果，不另造一套替代合同。
