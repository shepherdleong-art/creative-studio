**What to build:** 画布视频节点复用已验证的视频合同与画布任务桥接，支持立即分流和有限兜底，保持该节点原本开放的模式及完整视频要求。

## 范围与边界

- 在 07 的画布桥接上接入可灵 3.0，采用 06 的视频能力合同。
- 维持每种画布节点原本开放的生成模式，不借统一模型之名添加未经验证的新模式。
- 复用共享调度、受理证据和费用规则；画布视频不成为第三套队列策略。

## 验收标准

- [x] 画布视频节点只显示一个可灵 3.0，能从配置、规划、提交贯通到视频预览和产物使用。
- [x] 保持该节点模式的完整输入与输出合同，包括时长、首尾帧、比例、清晰度及智能分镜；支持组合由 06 的可信通道能力确定。
- [x] 七牛满且腾讯兼容可准入时立即分流；明确失败才允许另一通道，通道各一次、任务最多两次。
- [x] 节点只能走一家时可正常执行；两家均不支持时规划或提交前明确拒绝，不静默改变节点模式。
- [x] 画布与供应商池的准入、员工授权及每次预算检查均生效，多个节点同时执行不超售。
- [x] 重启、受理未知、轮询超时及补下载沿原尝试恢复，取消后禁止新提交；成功结果只登记并推进一次。
- [x] 实际通道、尝试、价格快照及画布来源可供管理员核对和员工任务合计读取，敏感连接配置不下发。
- [x] 旧任务的能力键和供应商快照继续有效；与 07 的图片节点组合运行时身份、依赖和产物归属准确。

**实现事实**

- 统一能力键为 `unified-kling-3`，显示“可灵 3.0”，仅开放当前代码真实可执行的 `image-to-video`（首帧必填、尾帧可选）。参数冻结 3–15 秒、比例、1K/4K 清晰度和智能分镜；真实通道只接精确 `qiniuyun/kling-3.0` 与 `kling-3.0`。
- server 模式只把统一能力放进员工可选列表，精确七牛/腾讯可灵能力留在注册表供旧图和在途任务恢复；local 模式保持原精确通道列表。统一锚点供应商行不会伪装成可用画布能力。
- 计划器与执行器使用同一份完整合同：统一模型、规则版本、节点/epoch/变体、输入顺序、首帧/尾帧、提示词、时长、比例、清晰度、智能分镜。执行前还会核对首帧实际比例与冻结比例，避免七牛按源图比例静默改变输出。
- 共享 `execution_media_tasks/channels` 以 `module=canvas`、`sourceType=canvas_node` 建立父任务；画布不写旧 `jobs/video_jobs/projects/shot_sets`。每个真实通道尝试仍使用独立 execution operation/attempt/permit、真实供应商快照和价格，父任务保持统一身份。
- 七牛优先；仅真实 `pool_capacity` 时立即把七牛标 `overflowed` 并选腾讯，不套图片 30 秒阈值。两家都满时持久 waiting，`claimCanvasTasks` 在 `nextEligibleAt` 前不领取。腾讯溢出明确失败后可回尚未提交的七牛并复用 pending operation，总真实 POST 不超过两次。
- 明确未创建/远端明确失败才换道；未知、轮询查询失败、下载失败沿原尝试收尾。受理后重启只续查/补下载，不重提；取消意图在选路、prepare、markSubmitting 和真实 POST 前均有守卫。
- 画布公司适配器补充腾讯可灵智能分镜：只有用户明确开启才发送 `multi_shot=true + shot_type=intelligence`，显式关闭不注入；七牛继续显式发送布尔值。首尾帧原协议保持不变。
- 视频尺寸吸附新增“优先冻结档位”参数；画布和普通项目都传入冻结清晰度，4K 请求不会再按旧偏好静默落成 1K。
- 腾讯可灵尾帧的原生 `OutputConfig` 只有 1080P 级证据；`4K + 尾帧`在规划和提交前拒绝，不允许先宣称 4K、实际静默落回 1080P。
- `unified-canvas-kling.test.ts` 包含 07 图片节点 → 08 视频节点的完整画布链路，验证上游产物解析、下游执行一次和产物归属。
