**What to build:** 先完成兼容性预整理：普通图片、视频、画布一致区分未受理、已受理和结果未知；员工看到准确状态，后台只续查或补下载，不因错误分类重复生成。

## 范围与边界

- 这是后续自动兜底前的兼容性预整理，以现有生成请求的状态反馈和恢复行为为交付对象。
- 覆盖团队普通图片、视频和画布的提交、轮询、下载结果；本任务不启用跨通道兜底。
- 保留旧任务的供应商、远端身份、费用快照和原次数合同；纠正不确定性判断不能变成给旧任务追加生成机会。

## 验收标准

- [ ] 同一证据在三个入口一致归为明确未创建、已受理、远端终态或结果未知；判断保留来源和阶段，不能只靠错误文本猜测。
- [ ] 请求可能已发送但响应丢失、网络断开、5xx 或限流且没有未创建证据时，员工看到“结果确认中”，后台不重新提交生成。
- [ ] 有远端 ID 的查询超时保留原身份并续查；进程重启后仍查询同一个任务，不重置付费提交次数。
- [ ] 明确远端失败与本地查询失败分别表达；没有充分证据时不将任务写成可以再次付费的失败终态。
- [ ] 已生成但下载失败时可补抓原结果，恢复后只登记一份产物，不重新调用模型。
- [ ] 结果未知时名额和未核清费用保持符合原执行合同的占用，不因本地异常、界面刷新或重启提前释放。
- [ ] 所有入口返回可安全展示的中文状态及可追溯的诊断身份，不向员工返回密钥、签名 URL 或完整上游响应。
- [ ] 新增证据分类与兼容包装可供后续任务复用；现有明确成功、明确失败路径及个人版既有规则通过回归。

## 验证与演示

1. 使用模拟供应商分别制造受理后断连、明确拒绝、查询超时和成功后下载失败，从页面／接口一直验证到远端调用次数与持久记录。

2. 在提交后、轮询中和补下载阶段模拟重启；核对远端 ID、名额、费用及产物登记。

验证使用隔离数据和模拟供应商。涉及真实付费调用或生产变更时，以用户另行明确授权为准；没有外部证据的结论在交接中明确标为未验证。

## 交接要求

- 发布可复用的受理证据合同：各类证据的来源、状态变化、允许动作、占用释放条件及旧入口兼容方式。
- 列出仍无法从上游响应可靠识别的情况；这些情况继续按未知处理，不作为已支持自动重发的证据。
- 在下方 Comments 记录实际完成范围、验证证据、改动说明、剩余限制及后续任务需要的合同；满足全部验收项后，将执行进度改为“已完成”。
- 发现超出本任务的新需求时单独记录，保持本任务边界；阻塞任务未完成时先报告缺失成果，不另造一套替代合同。
