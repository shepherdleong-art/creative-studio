## 范围与边界

- 覆盖已经接入的项目图片、项目视频、画布与团队局部返工，完成用户取消后的统一收尾体验。

- 取消不承诺远端立即停下或免费，行为以可核对的受理与终态证据为准。

## 验收标准

- [x] 尚未提交的任务取消后不再领取新通道名额或发起生成；重复取消幂等。
- [x] 取消发生于备用通道排队时，剩余机会不会被自动执行，重启后取消意图仍有效。
- [x] 取消与付费提交并发时，能确认没有提交或识别为已受理／待核对，保留对应记录；不会因竞争再开下一条通道。
- [x] 已提交任务继续沿原通道查询、必要时补下载；晚到的成功成品保存到正确任务记录并可查看或手动使用。
- [x] 迟到结果只保留一次，费用和真实通道记录完整；结果失败或费用未知也准确显示，未知不被当作已确认零费用。
- [x] 取消后的结果不会自动推进画布下游、新建后续生成、覆盖人工采用的返工片段或触发其他生产步骤。
- [x] 页面区分已停止后续生成与仍在收尾，清楚表达已有远端任务可能继续；不伪造已远端取消或即时退款。
- [x] 未知状态不因取消而提前释放名额和预算；终态及费用核对按既有执行合同分别完成，不混淆本地取消与远端结算。
- [x] 管理员核对一个已取消任务时只能补齐结果与结算，不能重新启动备用或下游；由自动查询与人工核对竞争完成时也只收尾一次。
- [x] 旧任务的合同和个人版本行为保持各自边界，取消一条任务不停止其他成员、镜头或同批条目。

**实现合同**

- 业务取消入口统一为 `applyUnifiedImageJobCancel` / `applyUnifiedKlingJobCancel`（普通项目）和 `requestCanvasTaskCancel`（画布）。未受理立即 `canceled`；已受理保留 `running`/`needs_check` 收尾并写 `cancelRequestedAt`，不宣称远端停止或退款。团队返工图片取消走 `/api/jobs/:id` 的 `action:'cancel'`，不再经过桌面 Agent 身份门禁；视频沿用 `/api/video-jobs/:id`。
- 项目图片晚到成功：保存 `image_assets` 与 job `outputImageId`，job 保持 `canceled`、`providerStatus='succeeded'`，不更新 `shots.latestGeneratedImageId`、不自动写 `shot_result_candidates`。项目视频晚到成功：保存本地文件/文件名，job 保持 `canceled` 并保留预览/下载。画布晚到成功：登记一个 `creative_canvas_assets` 与 task `outputAssetId`，task 保持 `cancelled`，不发布节点当前结果、不提升下游。
- `execution_media_tasks` 晚到结果使用 `lateResult:true` 的 resultJson，真实 channel 仍记为 `succeeded`，attempt/费用/远端身份完整；员工界面显示“已停止 · 结果已收尾 / 已保留”，任务抽屉可预览下载。取消续查和补下载只做只读远端查询/下载，不新增生成。
- 画布 `resolveCanvasTaskInputs` 把带取消意图的上游视为不可自动推进，即使晚到产物已登记也只把下游置 `blocked`。返工迟到图片/视频只留在任务记录；`select_image`、`register_video` 可由人明确采用/登记，并允许 `canceled + providerStatus=succeeded` 的晚到结果，但绝不自动覆盖当前分镜图或已采用视频。
- 取消与提交竞态复用 03/04/11 的 `beforeSend`、revision、channel guard；未知结果继续保留占用，重复取消返回幂等结果。管理员核对取消任务只收尾；若补齐可下载结果则仅转 `needs_check + download_failed` 以补抓原产物，不启动备用或下游。
- 旧同步/个人版任务保持原合同；本次没有为旧 `jobs/video_jobs` 增加跨代理重试。取消只影响目标任务，不停止其他成员、镜头或同批条目。
