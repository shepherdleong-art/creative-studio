## 验收标准

- [x] 员工单条、逐行和批量视频配置中只选一个可灵 3.0，设置与提交接口理解同一份统一模型能力。
- [x] 默认优先七牛；七牛仅因容量满而阻塞且腾讯可执行时立即使用腾讯，不套用图片 30 秒等待。
- [x] 清晰度／档位、比例、时长、首尾帧、智能分镜及入口明确选择的其他要求冻结；每个候选均满足完整合同，不静默丢参数或降配。
- [x] 只一家支持的模式或规格仍可执行；没有候选支持时在付费提交前说明原因，批量任务按每行真实要求检查。
- [x] 两条通道沿各自已验证的协议与素材交付方式提交；尾帧等精确能力 allowlist 和传输门禁保持有效。
- [x] 首条明确失败后允许另一条兼容通道一次；未知结果续查、下载失败补抓、备用名额满等待，不第三次生成。
- [x] 可灵统一模型授权与旧通道授权映射完成；每次尝试重新执行预算、暂停、成员与真实池准入检查。
- [x] 成功视频只关联到正确项目和分镜，预览与原片下载保持原语义；多次尝试仍是一条制作任务，真实费用可追溯。
- [x] 批量各行独立计次和展示状态；重复点击、并发执行或重启不重置机会，取消意图阻止后续提交。
- [x] 旧视频任务按原快照续查和原规则重试，其他视频模型及个人版保持原行为；历史智能分镜问题作为待核实事实而非当前线上结论。

**实现事实**

- 统一身份为 `unified-kling-3` 锚点，显示「可灵 3.0」；真实通道只接精确公司别名 `qiniuyun/kling-3.0`（七牛，优先）与 `kling-3.0`（腾讯）。直连 `kling-v3`、`kling-3.0` 之外的其他相似名称不会并入。server 模型列表只返回统一锚点与其他视频模型，隐藏两个真实通道；local 保持原列表。
- 普通项目只开放 `image-to-video`（首帧＋可选尾帧）。创建时冻结源图、尾帧、提示词、3–15 整数时长、比例、清晰度、智能分镜和参考素材为空的要求；首尾帧仍走既有精确 allowlist 和 COS/本机交付门禁。参考模式、超出范围时长、无可用兼容通道都在创建前拒绝，批量按每行独立检查。
- 新 `video_jobs` 写入 `unifiedModel/unifiedRuleVersion/unifiedTaskId/unifiedRequestJson/cancelRequestedAt`，业务行的 `providerId/model` 保持统一锚点；每次真实提交仍由独立 `execution_operations/attempts` 记录真实供应商、模型、permit、远端 ID、价格快照和费用。逻辑父任务复用 `execution_media_tasks/channels`，module=`video`。
- 首次选路七牛优先；七牛仅因真实 `pool_capacity` 阻塞时立即把七牛标 `overflowed`（零 POST、不消耗机会）并选腾讯，不继承图片 30 秒阈值。七牛因停用/缺失/系统健康避让而不可用时直接选腾讯。两家都无名额时持久 `waiting`/`nextEligibleAt`，deferred 领取受该时间约束。
- 明确未创建或远端明确失败后，可换另一条未提交的真实通道一次；未知、轮询查询失败、下载失败不调用换道。总真实 POST 最多两次，每通道最多一次；腾讯溢出先执行后明确失败也可回到尚未提交的七牛，复用其 pending operation。取消意图在选路、markSubmitting 和真实 POST 前检查；付费 POST 前还有 task/currentChannel/executionRevision/provider 可用性复核。
- 授权：`actorModelAllowed` 通过精确通道映射接受统一模型 key 或任一旧通道模型授权，不按前缀扩权。预算、账号暂停、成员/公平名额和真实池准入仍由 execution 每次尝试重裁。
- 费用：真实通道单独价格快照；最终成功只登记一份视频产物，员工任务投影显示统一模型「可灵 3.0」，管理员任务/用量/核对投影保留真实通道尝试。重试新建付费生成时清空 `unifiedTaskId`，未知/补下载续查保留原父任务；旧 `unifiedModel` 为空的任务完全走旧路径。
