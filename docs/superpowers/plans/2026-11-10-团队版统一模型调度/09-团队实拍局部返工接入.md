# 09：团队实拍局部返工接入

**状态：** `ready-for-agent`  
**执行进度：** 未开始  
**Blocked by:** [06：项目可灵 3.0 统一生成](06-项目可灵3统一生成.md)  
**规格覆盖：** A06、A13、A21、A22  
**阅读入口：** [索引与共同约定](README.md)、[功能方案](../../specs/2026-11-10-团队版统一模型调度-功能方案.md)；开始前核对阻塞任务的实际成果与交接记录。

**What to build:** 团队服务端范围内新建的图片、视频局部返工采用统一调度；原返工命令、候选归属、取消意图及幂等请求保持，旧任务和个人本地规则保留。

## 范围与边界

- 适配团队服务端范围内新创建的实拍局部返工图片与视频生成。
- 改变新返工的一次付费限制为每通道一次、最多两次；旧返工、个人本地版和同请求续跑保持各自原合同。
- 不迁移整套本地 Agent 实拍流程，不放开既有禁用的导入、生产同步或任意本机文件接口。

## 验收标准

- [ ] 从团队授权的局部返工入口新建图片或视频任务时，员工选择统一模型，并能查看结果候选及其状态。
- [ ] 只调整本次已确认的团队生成边界；管理员／员工归属验证和原入口访问约束保持有效，不能伪造本地 Agent 身份执行团队任务。
- [ ] 原返工命令、产品素材、镜头归属、输出要求、明确关闭的智能分镜等保持冻结，不因换通道改读后续编辑的内容。
- [ ] 新返工采用共享容量选路和有限兜底，首条明确失败才允许第二条兼容通道；未知结果只核对，已取消任务不再提交。
- [ ] 同一 requestId 重复点击或继续执行指向同一任务，重启后仍保留已用通道与费用，不重新得到两次机会。
- [ ] 新结果登记为正确镜头的候选，保留历史候选及人工采用决定，不自动覆盖已采用片段或其他镜头。
- [ ] 旧返工任务继续一次付费及原恢复合同；个人本地返工的原约束不因复用代码而被放宽。
- [ ] 团队费用、任务来源和执行身份进入共享追溯，未知核对与取消守卫可复用；单镜头领取不能停止其他 worker 正在执行的工作。

## 验证与演示

1. 用隔离的已绑定实拍工程创建团队局部图片和视频返工，演示终态失败兜底、候选登记、重复 requestId 和重启恢复。

2. 加入旧返工、个人本地模式、跨镜头并发和越权请求，验证次数、归属、采用历史和访问边界。

验证使用隔离数据和模拟供应商。涉及真实付费调用或生产变更时，以用户另行明确授权为准；没有外部证据的结论在交接中明确标为未验证。

## 交接要求

- 明确新旧返工规则的分界及相关访问上下文，记录如何证明没有把本地 Agent 流程迁移进团队服务。
- 提供候选登记、人工采用及取消后迟到结果的交接样例，供 12 和 15 验收。
- 在下方 Comments 记录实际完成范围、验证证据、改动说明、剩余限制及后续任务需要的合同；满足全部验收项后，将执行进度改为“已完成”。
- 发现超出本任务的新需求时单独记录，保持本任务边界；阻塞任务未完成时先报告缺失成果，不另造一套替代合同。
