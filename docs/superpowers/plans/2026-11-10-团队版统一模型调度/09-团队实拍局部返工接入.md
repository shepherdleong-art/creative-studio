**What to build:** 团队服务端范围内新建的图片、视频局部返工采用统一调度；原返工命令、候选归属、取消意图及幂等请求保持，旧任务和个人本地规则保留。

## 范围与边界

- 适配团队服务端范围内新创建的实拍局部返工图片与视频生成。
- 改变新返工的一次付费限制为每通道一次、最多两次；旧返工、个人本地版和同请求续跑保持各自原合同。
- 不迁移整套本地 Agent 实拍流程，不放开既有禁用的导入、生产同步或任意本机文件接口。

## 验收标准

- [x] 从团队授权的局部返工入口新建图片或视频任务时，员工选择统一模型，并能查看结果候选及其状态。
- [x] 只调整本次已确认的团队生成边界；管理员／员工归属验证和原入口访问约束保持有效，不能伪造本地 Agent 身份执行团队任务。
- [x] 原返工命令、产品素材、镜头归属、输出要求、明确关闭的智能分镜等保持冻结，不因换通道改读后续编辑的内容。
- [x] 新返工采用共享容量选路和有限兜底，首条明确失败才允许第二条兼容通道；未知结果只核对，已取消任务不再提交。
- [x] 同一 requestId 重复点击或继续执行指向同一任务，重启后仍保留已用通道与费用，不重新得到两次机会。
- [x] 新结果登记为正确镜头的候选，保留历史候选及人工采用决定，不自动覆盖已采用片段或其他镜头。
- [x] 旧返工任务继续一次付费及原恢复合同；个人本地返工的原约束不因复用代码而被放宽。
- [x] 团队费用、任务来源和执行身份进入共享追溯，未知核对与取消守卫可复用；单镜头领取不能停止其他 worker 正在执行的工作。

2. 加入旧返工、个人本地模式、跨镜头并发和越权请求，验证次数、归属、采用历史和访问边界。

验证使用隔离数据和模拟供应商。涉及真实付费调用或生产变更时，以用户另行明确授权为准；没有外部证据的结论在交接中明确标为未验证。

**实现事实**

- 团队模式不再调用桌面专用的 `checkLocalRequest`/Agent token 门禁，改由 `withTeamRoute` 的 `final_group` 资源授权、CSRF 与成员身份保护；桌面 Agent 身份仍只在本地模式有效，不能被重放到服务端。旧本地返工继续走原 desktop gate。
- 服务端新返工只允许统一模型锚点：图片选择 Image 2，视频选择可灵 3.0；直接指定真实七牛/腾讯或其旧图片/视频供应商会在创建前被拒绝。前端在团队模式自动只列统一锚点，本地仍列原供应商。
- 图片返工冻结输入图、参考图顺序、提示词、完整清晰度/比例组合、质量与规则版本；视频返工冻结当前分镜首帧、提示词、时长、图生视频模式与显式关闭的智能分镜。新任务写入 `unifiedModel/unifiedRuleVersion/unifiedRequestJson`，真实尝试身份由共享 execution 台账保存。
- `applyFilmRework` 仅为新 job/video_job 登记项目 scope 与 task principal，团队 worker 可在受理主体下执行；来源在 `execution_media_tasks` 记录为 `team_film_rework`，包含 binding/clip/requestId，供任务、费用和核对页面追溯。
- 统一图片返工成功后只向原镜头 `shot_result_candidates` 追加候选；不更新 `shots.latestGeneratedImageId`。视频候选仍由原有“登记到第五步候选”动作显式采用，自动结果不会覆盖人工选择或其他镜头。
- `requestId` 幂等仍由 `final_edit_film_reworks` 主键和原请求内容校验；相同请求继续/重启只返回同一 job，不重新获得通道机会。服务端队列改为项目级统一 worker，允许联合执行多个统一返工 job；`reassembled-shot-guard` 对 unified 任务跳过旧的一次提交失败守卫，旧桌面返工仍保持原合同。
- 未知提交、受理后查询、下载失败、通道健康、30 秒拥堵、双向有限兜底和每通道一次上限均复用 `02–06` 的共享合同；本地 Agent/个人版和其它模型路径未放宽。
