## 1. 交付结果

完成后，系统必须同时具备以下能力：

1. 新建项目时只填写生产身份字段，不再手填项目名称、产品名称和品类。
2. 项目名称由服务端按固定规则生成；同一名称同时作为正式导出基础名和输出文件夹名。
3. 产品型号不依赖知识库。任何合法型号均可创建项目、生产和导出。
4. 设置页可分别导入、查看和启用“产品策略知识库”与“脚本模板库”的不可变版本。
5. 生成脚本时自动按型号匹配产品策略；未匹配时提示但不阻断，完整回落现有详情页流程。
6. 脚本规划器自动推荐核心框架、文案钩子和画面钩子，并在结果中展示推荐依据。
7. 匹配知识库时，内部脚本标题与封面主副标题按统一名称和搜索词埋词；脚本事实仍受现有详情页证据门禁约束。
8. 画面钩子只输出玩法说明、画面公式和制作建议；本任务不自动生成对应开头画面。
9. 旧项目、旧脚本、旧导出目录与历史任务继续可读、可用，不做破坏性批量改名。

## 2. 已锁定的产品口径

本节是实现与 Review 的产品事实源。执行代理不得自行改写含义。

### 2.1 项目生产身份

新项目的生产身份字段为：

| 字段 | 规则 |
| --- | --- |
| 项目日期 | 服务端在创建项目时生成，格式 `YYYYMMDD`，按 `Asia/Shanghai` 计算并永久冻结 |
| 店铺 | 必选；仅允许 `B店`、`D店`、`K店`、`京东` |
| 型号 | 必填自由文本；整个输入值就是型号，不从连字符或尾字母自动拆分 |
| 子型号 | 选填自由文本；只有用户明确填写时才参与名称 |
| 生产类型 | 必选；仅允许 `新品种草`、`AI种草` |
| 剪辑师 | 必填自由文本；可显示本机历史输入建议，但不能做封闭人员名单 |

`新品种草` 与 `AI种草` 目前只区分业务场景和命名，不改变脚本内容、供应商、队列或成片工作流。

历史下单表的口径归一如下；该映射只用于理解和旧数据手动补全，不要求导入 218 MB 的下单表：

| 历史值 | 规范值 |
| --- | --- |
| 天猫-B店 | B店 |
| 天猫-D店 | D店 |
| 天猫-K店、天猫-k店、K店、天猫-婴童 | K店 |
| 京东-自营、京东-POP、京东-自营+POP | 京东 |

### 2.2 型号是不可推断的原子值

- `XQ9A` 是完整型号，子型号为空。
- 用户把 `PC672-A` 填进“型号”时，系统必须原样视作完整型号；不得自动变成型号 `PC672`、子型号 `A`。
- 只有用户分别填写型号 `XQ9A` 和子型号 `A` 时，名称构造器才输出 `XQ9A-A`。
- 文件名可能包含字段内部的连字符，因此任何读取端都不得反向解析项目名或文件名来恢复项目字段；SQLite 字段才是权威来源。

### 2.3 自动项目名与导出名称

唯一构造公式：

```text
{YYYYMMDD}-{店铺}-{型号}[-{子型号}]-{生产类型}-{剪辑师}
```

示例：

```text
20260815-B店-XQ9A-AI种草-紫菜卷
20260815-B店-XQ9A-A-新品种草-紫菜卷
```

规则：

- 子型号为空时整段省略，不产生连续连字符。
- 不再添加 `成片-` 前缀。
- 新项目的 `projects.name` 直接写入自动生成名称，前端仅显示只读预览，不提供名称输入框。
- 正式输出文件夹名与项目自动名称使用同一个基础名。
- 单个正式视频使用 `<基础名>.mp4`，对应封面使用 `<基础名>-封面.jpg`。
- 一次明确包含多条成片的导出，按业务顺序使用 `<基础名>-01.mp4`、`-02.mp4`；封面跟随同一序号。
- 重复导出或路径已经占用时，从下一个可用两位序号继续，绝不覆盖既有文件。
- 另一个项目产生相同基础名时，其项目名称与目录名追加 `-02`、`-03`，并在创建响应中返回最终实际名称。
- ZIP 文件也必须以同一基础名开头；允许追加用途后缀，例如 `-成片组.zip`、`-全部产物.zip`、`-创作包.zip`。

字段先做 NFKC、首尾空白与连续空白归一。Windows 禁用字符、控制字符、`.`/`..`、路径分隔符以及清洗后为空的值必须在 API 层返回可理解的 400 错误，不能静默生成一个与用户输入不同且不可识别的身份。中文、英文字母、数字、内部连字符和合法内部空格可以保留；路径安全仍必须经过最终守卫。

### 2.4 修改与冻结

- 第一次正式导出前，店铺、型号、子型号、生产类型和剪辑师可以编辑；每次保存后服务端重新生成项目名称。
- 第一次正式导出时，基础名、目录名和字段快照一起冻结。
- 第一次正式导出后，普通编辑不能静默改变导出身份。UI 必须告知已有正式产物，并要求用户显式确认“启用新的导出名称”。
- 显式启用新名称后，新导出身份成为当前身份；已有目录和产物保持原路径，历史任务继续引用旧快照。
- 所有渲染、批量生产与 ZIP 任务在排队时冻结所用导出身份，排队期间修改项目不能改变任务的目标名称。

实现可以增加版本化导出身份表，也可以采用等价的不可变快照结构；但必须同时满足“当前身份可切换、历史身份可追溯、旧文件不移动、运行中任务不漂移”四项验收条件。仅清空 `projects.exportDirName` 而不保存旧身份不合格。

### 2.5 历史项目

- 新规则只对新建项目强制生效。
- 旧项目不批量回填、不自动重命名、不移动磁盘文件。
- 旧项目进入正式导出但缺少新身份字段时，沿用现有“补齐项目信息”入口，要求补齐店铺、型号、生产类型和剪辑师；日期仍取原项目 `createdAt`。
- 补齐并确认后创建第一版新导出身份。已经存在的旧格式正式产物继续保留。
- `productName`、`productCategory` 等旧数据库列为兼容历史数据保留，但从新建页和新的项目信息编辑表单中移除，不做破坏性删列。

### 2.6 产品策略知识库

产品策略知识只在脚本生成时使用，不参与项目创建校验、项目命名、文件命名和生产资格判断。

匹配规则：

1. 对型号键执行 NFKC、首尾/连续空白归一和 ASCII 大小写归一。
2. 子型号非空时，先尝试用户显式字段组成的 `型号-子型号`；未命中再查完整“型号”字段。
3. 不做模糊匹配，不按连字符拆型号，不建立人工别名。
4. 未命中时记录 `unmatched` 状态并在脚本区提示，然后完整执行现有详情页提取、证据核验和脚本生成流程。

同一型号的多行知识按以下规则在导入时合并：

- 范围/主题类字段保留来源范围，按来源行顺序合并。
- 品类主卖点、差异化卖点和搜索词拆项、归一、去重，但保留首次出现顺序。
- 统一名称完全相同时保留一个。
- 同型号出现不同非空统一名称时，该条目标记为冲突，不得自动激活供生成使用；导入报告必须列出型号和来源行。
- 每个合并条目保留原始行号与原始字段，便于追溯。

策略字段的使用边界：

| 策略字段 | 用途 |
| --- | --- |
| 统一名称 | 匹配成功后用于内部脚本标题与封面标题 |
| 搜索词 | 标题埋词候选 |
| 品类心智 | 框架、钩子和表达方向推荐信号 |
| 品类主卖点、产品差异化卖点 | 对现有可用详情页卖点进行排序与取舍 |
| 其他列 | V1 原样保存作追溯，不直接控制生成 |

标题埋词约束：

- 内部脚本 `title` 必须包含统一名称，并自然包含至少 1 个、最多 2 个该知识条目的搜索词。
- `coverTitleParts.primary + coverTitleParts.secondary` 作为一组共同满足同样约束；不要求主标题和副标题分别重复统一名称与搜索词。
- 优先将统一名称放在封面主标题，将搜索词或由搜索词自然改写的短语放在副标题。
- 不增加独立“发布标题”字段。
- 未匹配知识库时不启用埋词门禁，完全沿用现有标题生成和兜底逻辑。

事实边界：

- 产品策略只负责称呼、关键词和策划优先级，不自动成为可写入正文的产品事实。
- 数字、材质、认证、结构、功能、功效等正文主张仍只能来自当前详情页卖点库中通过现有证据门禁且未被用户禁用的卖点。
- 策略卖点与详情页证据卖点无法对应时，不得把策略原文塞入正文；保留提示并按现有证据继续生成。
- 不得放宽 `direction-briefs.ts`、`generator.ts` 和 `validation.ts` 的 fail-closed 证据约束。

### 2.7 脚本模板库

当前模板源包含：

- 10 种脚本核心框架；
- 6 类、共 30 个开头钩子文案公式；
- 7 类、共 21 个开头画面条目；
- 18 张嵌入式参考图片。

模板中的秒数只用于解释结构节奏，不是执行时长契约。运行时继续以现有 `targetDurationSec` 和字数/时长校验为准，规划器只参考段落顺序与相对节奏，不照搬表中秒数。

系统自动推荐，不在生成前增加必填配置：

1. 根据详情页证据卖点类型、品类心智、主卖点和本轮多方案去重选择核心框架。
2. 从该框架的首选/次选钩子中选择文案钩子，再选择具体公式。
3. 根据品类、框架、钩子标签和条目有效状态选择画面钩子。
4. 同批多条方案在供给充足时应使用不同的框架或钩子组合。
5. 每条结果顶部展示推荐的框架、文案钩子、画面钩子和推荐理由。
6. 用户可点击“换一个框架/钩子”生成新修订；该动作必须排除当前组合并进入任务快照，不能只改前端显示。

画面钩子的交付范围：

- 脚本结果和导出文本包含玩法名称、画面公式、文字说明与制作建议。
- 模板管理页或脚本详情可查看关联参考缩略图。
- 脚本文档不嵌入参考图片。
- 本任务不调用可灵、即梦、Runway、Luma、MJ、SD 等工具自动生成画面；Excel 中的“AI 实现路径”只是建议字段。

模板源目前存在的已知数据问题必须在导入报告中显式处理，不能让字符串错别字直接成为关联键：

- “多卖点合辑型”与“多卖点合集型”归一为同一个稳定 ID。
- 开头画面第 7 行缺少玩法名称：保存原始行并标记为 `draft_invalid`，不进入自动推荐。
- 开头画面第 7、11 行的“搭配钩子”疑似误填为适用品类：保留原值、产生警告，无法映射到标准钩子类型的词不参与评分。
- J 列存在无标题的“即梦OK”“需要前期制图”等内容：按当前源表约定导入为“制作备注”，同时在报告中提示无标题列映射。
- “场景式”“场景代入”“前后对比”“卖点式”等非六大文案钩子词作为自由标签保存，不建立错误外键。
- 单元格中的示例文案只供模型理解公式，不要求逐字复用。
- 小红书参考链接连同原值保存，但生成不依赖联网抓取，查询参数失效不能阻断模板使用。

### 2.8 版本与可复现性

- 产品策略库和脚本模板库分别维护不可变修订；设置页可激活历史修订。
- 导入相同内容指纹必须幂等，不重复创建修订。
- 新脚本任务在创建时冻结：策略修订 ID、匹配状态、合并条目快照、模板修订 ID、推荐组合、供应商与模型、目标时长、创作要求和详情页卖点库修订。
- 已排队任务以快照执行，设置页切换当前版本不能改变它。
- 已生成脚本修订保存上述来源身份。查看历史脚本时不得用当前知识库重新解释历史结果。
- `requestKey` 的 canonical identity 必须包含新增快照字段；同 key 不同知识/模板版本返回冲突，不能误复用旧任务。

### 5.1 核心项目迁移

建议为 `projects` 增加：

```text
storeCode                 TEXT NOT NULL DEFAULT ''
```

```text
project_export_identities
  id                 TEXT PRIMARY KEY
  projectId          TEXT NOT NULL

  baseName           TEXT NOT NULL
  exportDirName      TEXT NOT NULL
```

## 6. 导入与管理设计

### 6.1 解析器

新增仅服务端使用的 XLSX 解析模块，例如：

```text
lib/script-studio/catalog-import/
  workbook.ts
  strategy.ts
  templates.ts
  normalize.ts
  storage.ts
  types.ts
```

仓库目前没有 XLSX 读取库。实现时增加一个维护活跃、许可证兼容、支持读取单元格、合并单元格和嵌入图片锚点的生产依赖；推荐评估 `exceljs`，并固定实际验证过的版本。依赖只能由 Node route/服务端模块导入。完成后必须跑生产构建和 standalone 边界验证，证明桌面包不会在运行时缺包。

上传边界：

- 只接受 `.xlsx`，同时验证 ZIP/OOXML 内容而非只信扩展名。
- 单文件上限建议 32 MiB；当前策略表约 22 KiB、模板表约 7 MiB，均有充足余量。
- AI 自动化下单表约 218 MiB，不属于导入范围。
- 原始上传写入受管 storage 临时路径，完整解析和落库成功后原子发布到版本目录；失败清理临时文件。
- 计算 SHA-256；同目录不能使用用户文件名直接拼路径。
- 导入数据库事务失败时不得切换 current revision，也不得留下可见的半版本。

### 6.2 产品策略映射

按表头语义匹配，不按 E/F/G/J/K 固定列号，也不依赖黄色填充色。当前重点字段映射为：型号、品类心智、品类主卖点、产品差异化卖点、搜索词、统一名称。

导入报告至少包括：

- 总行数、有效行数、合并后型号数；
- 空型号、空统一名称、统一名称冲突；
- 重复型号及其来源行；
- 每个字段无法识别的表头；
- 新修订是否可激活。

### 6.3 脚本模板映射

必须识别三个工作表：

- `脚本核心框架`
- `开头钩子文案`
- `开头钩子画面（待优化）`

合并单元格采用“所属分组向下继承”，空白分隔行不生成记录。嵌入图片按 drawing anchor 关联到源行；同一行允许多图。图片只保存副本和元数据，不依赖原工作簿继续存在。

修订可以带警告激活，但 `draft_invalid` 条目不得进入推荐池。设置页必须显示有效/草稿/冲突数量及具体行号。

### 6.4 设置页与 API

在 `app/settings/page.tsx` 增加“脚本知识与模板”区块，建议拆成独立组件，避免继续膨胀设置页。

建议 API：

```text
GET  /api/script-studio/catalogs
POST /api/script-studio/catalogs/strategy/import
POST /api/script-studio/catalogs/template/import
PUT  /api/script-studio/catalogs/{catalogId}/current
GET  /api/script-studio/catalogs/{catalogId}/revisions/{revisionId}
GET  /api/script-studio/template-assets/{assetId}
```

每个 route 先通过 Script Studio readiness gate。返回稳定错误码；解析错误、字段错误和系统错误分开呈现。版本只新增和切换，不提供物理删除入口。

- [ ] 匹配时内部标题和封面标题组合满足统一名称+搜索词约束。
- [ ] 自动推荐框架、文案钩子和画面钩子，并显示依据。
- [ ] 模板秒数未替代现有 targetDurationSec 契约。
- [ ] 画面钩子只输出说明、公式和建议，没有自动生成媒体。
- [ ] 脚本任务和脚本修订都能追溯使用的策略/模板版本。
- [ ] 运行中任务不受 catalog 切换、项目编辑或供应商设置变化影响。
- [ ] 相关 Node 测试、lint、生产 build 和 standalone 边界检查通过。

## 10. Review 重点

Reviewer 优先寻找以下失败模式：

1. 只改了 UI，API 仍允许空字段、非法枚举或自定义项目名。
2. 新项目名称正确，但批量导出、ZIP 或后台 worker 仍用旧公式。
3. 文件夹冻结了，视频基础名却在任务执行时按最新项目字段重算。
4. 为方便匹配而拆解 `PC672-A`，破坏“型号是原子值”的约定。
5. 用模糊匹配把相近型号串错，或在未命中时阻断生产。
6. 直接把策略表卖点作为事实送进模型，绕过详情页证据门禁。
7. catalog 切换后，排队中的任务读取了新版本。
8. 只把推荐显示在 UI，没有写入任务和脚本修订快照。
9. 依赖 Excel 原文件绝对路径，移动文件后知识库失效。
10. 把模板秒数变成固定分段，破坏现有 15/20/30/45/60 秒生成契约。
11. 把 Excel 中的工具路径或提示词当成自动执行指令。
12. 新 XLSX 依赖在开发环境可用，但 standalone/桌面包缺失。

## 11. 完成定义

只有同时满足以下条件，执行任务才算完成：

1. 第 7 节所有 Phase 完成标准均满足。
2. 第 8 节测试完成且无通过删断言、跳测试或放宽证据门禁换绿。
3. 第 9 节逐项验收通过并留下测试输出或手动截图/路径证据。
4. 第 10 节十二种失败模式均被 Reviewer 主动检查。
5. 原始 Excel、旧项目文件、既有正式产物及无关工作树修改均未受损。
