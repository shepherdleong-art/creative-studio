# 05 团队用量布局与二级页签

**状态：** `ready-for-human`

**依赖：** 04；本票输出共用分页组件供 06 使用。  
**规格：** [功能方案](../../specs/2026-11-11-工作台版本标记与团队列表易用性-功能方案.md)第 5、7、8 节。

## 目标

用户先看消耗总览，再进入短列表。查看通道详情不会压缩表格，翻页不会改变整个账期的统计。

## 修改范围

- `components/team/TeamUsagePanel.tsx`：摘要与明细请求分开、布局顺序、页签、详情对话框、分页状态。
- `components/ui/Pagination.tsx`（新增）：受控 page/pageSize/total/totalPages/loading/onChange，供团队用量与任务页共用；复用既有外观部件和令牌。
- 可抽取用量子组件及局部 CSS；避免所有 JSX 继续堆在一行，也避免无关重构。
- `components/ui/Dialog.tsx`、`components/ui/Appearance.tsx` 以复用为主，不重写共用行为。
- `scripts/team-usage-ui-contract.test.mjs`、团队用量浏览器测试与 UI 验收 fixtures/screens。

本票不再变更 04 的统计/权限/分页后端合同；确有接口缺口先在 04 Comments 记录并同步修正，不在前端补全量统计。

## 实现步骤

1. 使用 04 的 summary 和 section 查询，摘要与明细分别维护 loading/error。完成条件：翻页只加载指定列表，不下载全部列表、不清空图表。
2. 调整区块顺序，建立“制作任务 / 通道调用 / 其他记录”页签；其他记录有固定两种类型选择。完成条件：只显示活动列表，员工不可见管理专用页签/类型。
3. 制作任务与调用记录详情改用独立 wide Dialog，长文本只在对话框中换行或滚动。完成条件：开关详情前后主表列宽不变。
4. 实现公共分页组件和页面状态联动。完成条件：25/50、页码折叠、跳页、筛选归一、失败重试及过期响应处理全部可操作。

## 验收标准

- [ ] 图表始终在所有明细表之前；额度、筛选、图表、成员统计、明细的顺序符合规格。
- [ ] 默认“制作任务”每页 25 项；通道调用、非统一模型和待映射记录均使用服务端分页，不能只给第一张表分页。
- [ ] 切页签/类型回第 1 页并保留业务筛选；改变账期/模型/成员/结果/pageSize 回第 1 页；刷新保留有效页。
- [ ] 统计标题和总数读 summary/pagination，不用当前页数组求和；翻页后图表、金额、成员合计不跳变。
- [ ] 分页控件在列表上下均可用：上一页/下一页、有限页码、省略号、跳页、25/50 选择；空结果和末页禁用状态正确。
- [ ] 连续切换筛选/页码并让旧请求晚返回，页面仍显示最后一次选择的数据；单次失败保留错误和重试入口，不渲染假“0 条”。
- [ ] 打开包含长远端 ID、长项目名、长错误的详情，主表各列不挤压；通道和提交/终态为中文，并清楚标注备用未提交。
- [ ] 对话框内容独立滚动、Esc 关闭、焦点归还，技术字段可展开；不存在嵌套大表把主页面撑宽的问题。
- [ ] 员工只见自己的允许内容；浏览器网络响应也没有管理员专用通道字段，页面不会请求被禁止的 section。
- [ ] CSV 沿用完整范围导出，翻到末页再导出仍含完整筛选记录。
- [ ] 1536/1280/1024 三档、浅深主题与两内核均无整页横向溢出和被裁控件；图表自身局部滚动若必要须有可见提示。
