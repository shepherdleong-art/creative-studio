# 03 全员任务服务端分页

**状态：** `ready-for-human`

**依赖：** 无；本票输出公共分页参数/类型，供 04、05、06 使用。  
**规格：** [功能方案](../../specs/2026-11-11-工作台版本标记与团队列表易用性-功能方案.md)第 2、5、6、8 节。

## 目标

接口直接查询完整历史并按制作任务分页；旧记录可搜索、可按 ID 打开；侧栏和总览不因分页而缩成一页。

## 实现步骤

1. 枚举 `listTeamTasks` 及 `queryUnifiedTaskUsage` 的调用者。区分列表、单项详情、总数、总览近期数据；记录到 Comments。完成条件：没有调用者把默认第一页误当完整结果。
2. 建立公共分页解析和任务匹配范围。关键词覆盖当前 `SEARCH_FIELDS`，含中文派生任务/步骤名；有效状态与 UI 一致。完成条件：计数、搜索、分页共用授权与筛选逻辑。
3. 先选完整任务组 ID，再取该页所有关联执行记录和费用投影。完成条件：500 条之外可读取；同一统一任务不跨页，别页尝试不会导致费用缺失。
4. 让现有详情接口按 operationId 直接查询，沿用权限和脱敏。修正侧栏/总览/员工首页调用者。完成条件：详情不受 page/q/status 限制，统计不依赖 items.length。

## API 交付合同

`GET /api/team/tasks?q=关键词&actorUserId=…&status=…&page=2&pageSize=25`

响应继续包含 `items`、`localAgentIncluded`，增加 `pagination` 和 `totalRecords`，语义见规格。`items` 保持执行记录字段，允许当前页完整组的记录数大于 pageSize；`pagination.total` 数制作任务组。旧接口调用者统一更新，不能用保留隐含 500 上限来兼容。

内部分页、计数与 ID 查询可以拆函数，但权限和基础投影复用。只为当前页或明确的 ID 集合加载通道/执行详情；全范围计数用聚合，不渲染全量对象后切片。
