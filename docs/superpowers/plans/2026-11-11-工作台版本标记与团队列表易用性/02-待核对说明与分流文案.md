# 02 待核对说明与分流文案

**状态：** `ready-for-human`

**依赖：** 无。  
**规格：** [功能方案](../../specs/2026-11-11-工作台版本标记与团队列表易用性-功能方案.md)第 4、8 节。

## 目标

待核对页先告诉管理员发生了什么、是否有待处理项，技术字段和人工动作逐层展开；分流设置说明实际适用范围及计时阶段。

## 修改范围

- `components/team/TeamReconcilePanel.tsx`：默认卡片、空态、全部记录说明、详情/人工表单折叠。
- `components/team/TeamPoolsPanel.tsx`：标题、字段名、校验/成功文案及 aria-label。
- `components/team/TeamPoolsPanel.module.css`：仅在实际样式需要时修改。
- `scripts/team-reconcile-ui-contract.test.mjs`、`scripts/team-pools-panel.playwright.test.mjs`：跟随新文案与交互更新真正的契约。
- `scripts/team-server/ui-acceptance-screens.mjs`、`scripts/team-server/ui-acceptance-fixtures.mjs`：补待核对屏和证据 fixtures；如已有同等 fixture 则复用。
- 可新增纯展示映射模块和针对映射的测试；不把派生说明写回业务状态。

只读参考 `lib/team-service/unified-reconcile.ts`、`lib/media-core/unified-media/settings.ts`、`execution.ts`、`video-execution.ts`。本票不修改核对写入、队列、超时、预算、占用或默认阈值。

## 实现步骤

1. 用已有原因与状态做简明摘要，成功/费用/候选通道分开表达；无后台查询证据时只说“结果暂未确认”，不承诺自动恢复。完成条件：卡片无需阅读任务 ID 即可理解。
2. 将原技术字段放进“核对详情”，表单放进“人工核对”。保持目标尝试选择、草稿、版本与幂等字段、证据要求及合法动作完整。完成条件：原来可完成的核对操作仍能完成，刷新不误提交。
3. 按规格更名分流设置及相关提示，保留配置读取/保存合同。完成条件：已存 10 秒仍显示 10，保存仍写同一字段；可灵与其他模型规则完全不变。

## 验收标准

- [ ] 默认只看待核对；切“全部记录”看到成功项时提示它是历史记录，待核对数为 0 不要求逐项核对。
- [ ] 无待核对项与无历史记录使用不同空态；成功但费用未知仍保留费用核查提示。
- [ ] fixture 覆盖：提交未知、远端身份缺失、下载失败、费用未知、取消后仍待确认、成功且已核账；文案来自实际证据，不一概归类为“失败”或“系统处理中”。
- [ ] 七牛成功、腾讯候选且 0 尝试：腾讯显示“备用通道，未提交”，不显示为额外付费调用。
- [ ] 默认不展开长 ID、原始技术错误或人工表单；展开后信息完整、长文本可读，旧 legacy 未知记录仍可访问。
- [ ] “补远端 ID、确认未创建、确认成功、确认失败、仍无法确认”等原有合法操作仍可达；证据必填、并发版本冲突、幂等保护保持有效。
- [ ] 未知结果不会因展示变更触发重发、推定未创建或释放占用；查询/展开没有付费生成副作用。
- [ ] 页面显示“模型通道分流 / Image 2 排队等待时间”，说明提交前排队、腾讯可用条件及仅影响 Image 2。
- [ ] 0、10、30、3600 合法；负数、小数、超范围无效；既有值保留。请求 payload 字段和默认值无变更。
- [ ] 浅深主题、小窗口、折叠键盘操作及核对表单展开尺寸通过。
