# 04 团队用量服务端分页与汇总

**状态：** `ready-for-human`

**依赖：** 03 的公共分页合同及按 ID 查询能力；与 03 串行修改共享查询文件。  
**规格：** [功能方案](../../specs/2026-11-11-工作台版本标记与团队列表易用性-功能方案.md)第 2、5、7、8 节。

## 目标

制作任务和调用明细按完整历史分页；金额、排行、趋势、成员统计与导出覆盖整个筛选范围。页外父任务不会被误判为未映射。

## 修改范围

- `lib/team-service/usage.ts`：摘要、调用分类查询、计数及导出范围。
- `lib/team-service/unified-usage.ts`：去除统一任务 500 条截断，分页选 ID、定向详情与全范围统计。
- `lib/team-service/usage-request.ts`：section/page/pageSize 参数与完整筛选读取；复用 03 分页解析。
- `app/api/team/usage/route.ts`：按 section 返回摘要或指定列表。
- `app/api/team/usage/export/route.ts`：核对并保持与页面一致的权限/scope/筛选，忽略分页。
- 必要时新增小型查询/共享类型模块；让前端 type import 不引入数据库运行时。
- 相关用量测试；`lib/team-service/unified-usage-contract.ts` 是金额语义依据，原则上只读，不借本票重新定义账本。

需要索引时走原有追加迁移和升级 gate；不得改已发布迁移、账本历史值、定价快照或生成规则。

## 实现步骤

1. 整理任务日期、尝试日期、账期/模型/结果/成员筛选及员工字段边界。完成条件：写入 Comments 的查询口径表能说明每个 section 和摘要如何使用同一筛选，跨账期差异有解释。
2. 将全范围摘要与分页明细拆开。`section=summary` 为默认；其余 section、返回类型、权限见规格第 7 节。完成条件：摘要不附带全量 items/tasks，翻页不会重算成一页的汇总。
3. 以真实关联判定 channels/legacy/unmapped，先授权、分类和筛选，再计数和选页。完成条件：页外及跨账期的有效父任务不变成未映射，孤儿记录仍可诊断。
4. 复用按 ID 任务投影服务，清查全部查询调用者及 CSV。完成条件：没有摘要/模型选项/详情继续受 500 截断，导出不使用当前页数组。

## 关键边界

- 统一任务自动换通道仍只计 1 个制作任务；真实尝试单独计数。摘要 `counts` 必须从完整范围得到。
- 员工 `tasks` 不得携带 channels，统一模型名称保持统一；channels/unmapped section 对员工返回 403，不能只在 UI 隐藏。
- 父任务存在于别页或创建于筛选日期之前，都不是身份缺失；判断关联时不要用本页 ID Set 或受账期裁剪的 ID Set。
- 查询仅返回授权数据。员工对他人的 actorUserId 请求保持拒绝；scope=self/team 的裁决在摘要、明细和导出一致。
- 沿用人民币分的整数金额及现有费用分类；不能把未定价或尚未核账标成已结算 0 元。
- 原路由默认完整 response 将切换为 summary；清查所有消费者和测试，不保留另一个隐式“返回全部明细”的默认分支。
