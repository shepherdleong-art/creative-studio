# 06 全员任务分页交互

**状态：** `ready-for-human`

**依赖：** 03 接口和详情能力、05 共用分页组件。  
**规格：** [功能方案](../../specs/2026-11-11-工作台版本标记与团队列表易用性-功能方案.md)第 5、6、8 节。

## 目标

全员任务与我的任务每次只展示一页制作任务，搜索覆盖完整历史，按发起人分组和详情/重试仍能稳定工作。

## 修改范围

- `components/team/TeamTasksPanel.tsx`：分页/搜索请求、当前页展示分组、独立详情加载和刷新。
- `components/team/console.module.css`：必要的分页与长文本布局，保持外观令牌。
- 复用 `components/ui/Pagination.tsx`，不要再实现另一套分页规则。
- `scripts/team-task-display.test.ts`、`scripts/team-console-page.playwright.test.mjs` 及对应任务页浏览器测试；按实际现有覆盖选择最相关文件。
- `scripts/team-server/ui-acceptance-fixtures.mjs`、`scripts/team-server/ui-acceptance-screens.mjs`：大数据、旧链接、详情和末页验收。

03 已负责后端、侧栏及聚合；本票检查集成结果，发现合同缺陷回到对应票修正。`lib/team-console-overview.ts` 的 taskId URL 工具继续复用。

## 实现步骤

1. 页面使用服务端分页返回值和 totalRecords，搜索迁移到 `q`。完成条件：没有 `items.filter(matchesTaskQuery)` 承担最终历史搜索；输入保持焦点，约 300ms 防抖/Enter 立即提交。
2. 仅对服务端选中的当前页任务做分组展示，接入上下分页控件。完成条件：平铺/发起人分组看到同一批制作任务，没有二次 slice 或每个成员独立分页。
3. 从既有 detail 接口读取选中 operationId。完成条件：URL 指向当前页外的任务也能打开，翻页/关闭/重试不会破坏列表状态。
4. 覆盖请求竞态、越界页和错误重试。完成条件：旧请求无法覆盖新搜索，页码与服务端实际 page 一致。

## 验收标准

- [ ] 503 个制作任务、505 条执行记录：默认显示 25 个制作任务，文案显示完整总数；末页 3 个，不再出现“只返回最近 500 条”。
- [ ] 分组模式的成员标题标注“本页 N 项”；切平铺/分组不改变总页数、页码和本页任务集合。
- [ ] 一个统一任务包含 3 条执行记录时显示一个制作任务，详情及计数完整，不因分页重复或丢失。
- [ ] 搜索仅存在于 500 条之外的关键词能命中；姓名/工号/中文步骤/模型/任务编号保留原能力，输入过程中不丢焦点。
- [ ] 改搜索/成员/状态/pageSize 回第 1 页；手动刷新保留页，数据减少导致越界时收敛到有效页。
- [ ] 模拟旧页请求晚于新页/新搜索返回，界面保持最新条件；列表错误和详情错误独立，不伪装无记录。
- [ ] `/team/tasks?taskId=<旧operationId>` 可直接打开当前页外合法任务；员工访问他人任务显示 404 对应说明，无详情泄漏。
- [ ] 翻页保持已打开详情；关闭详情保留列表页与筛选。详情加载中/失败/已不存在均有明确反馈。
- [ ] 允许重试的失败任务仍走原重试接口；成功提交重试后刷新详情和当前页，显示回队状态，无额外模型提交动作。
- [ ] 侧栏角标不显示 25/50；总览跳转、用量/错误链接仍能打开对应任务。
- [ ] 管理员成员选项来自完整允许的成员数据，不随当前页只剩一位；员工不调用无权的成员管理接口。
- [ ] 小窗口、长项目名、空结果、末页、详情展开、浅深主题、键盘和分页焦点验收通过。
