## 实施步骤

1. 用管理员已受理跨 scope 任务后降权/员工受理后升权复现实际边界；同时检查停用、资源软删除和新阶段准入。
2. 定义最小持久任务授权：冻结任务所属 scope、依赖资源/版本及允许的回收操作。选择兼容现有 task principals 的实现，不能只冻结 admin 角色获得全局访问。
3. 区分原受理结果回收与新付费步骤：后者持续检查当前账号、权限与预算；前者不依赖 cookie 或后来角色。
4. 明确历史记录缺少依赖证据时的迁移/恢复策略，无法证明则隔离待核查，不推断为全库授权。

## 完成标准

- [ ] 降权或停用后可收取原受理结果，不能新建付费阶段或读取未冻结的他人资源。
- [ ] 升权不扩大已有任务权限；任务 ID、module、scope 不匹配均拒绝。
- [ ] 软删除依赖仍可供原任务使用，UI/新任务访问仍受删除规则约束。
- [ ] 数据库升级保留旧数据；证据不足的旧任务不会自动重提或扩大访问。
