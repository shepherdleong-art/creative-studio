1. 盘点四类模块的 schema、恢复、start、drain 及懒启动触发点，标出可能重复 worker 和模块共享 singleton。
2. 为批量与详情页脚本接入 ExecutionModuleLifecycle，使用已有 scheduler/恢复机制；统一 owner、fence、readiness 和停机信号。
3. 声明部署配置的模块开关字段、校验和环境映射，并给 06 交付固定合同。server 关闭时准确降级，local 默认维持既有约定。
4. 改正把未启动批量当整体正确结果的测试：仍证明早期 instrumentation 不抢跑，同时证明受控 runtime 阶段确实启动。
5. 覆盖维护态/恢复态，禁止通过启动恢复把 maybe_sent/unknown 自动重提。

## 完成标准

- [ ] 预存排队、运行中、已有回执、受理不明的任务后重启；无人访问页面/API 时，四模块恢复符合各自语义。
- [ ] schema 或 owner 获取失败时无 worker/付费；重复启动或页面访问不会双调度。
- [ ] 开关关闭无 worker、能力状态准确；首版全启配置四模块可执行；local 开关行为无回归。
- [ ] 停止时同一任务 AbortSignal 传入媒体子过程，已中断工作可恢复，旧 fence 不能继续写入/提交。
