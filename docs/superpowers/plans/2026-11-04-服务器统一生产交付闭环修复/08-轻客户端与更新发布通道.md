## 实施步骤

1. 核对 build-team-client、launcher、remote host、capabilities 和更新助手之间合同，先构建隔离测试包证明所有启动依赖都在。
2. 实现同源更新托管，选择受控 Caddy 静态路径或 app 路由并记录选择；仅暴露已发布 manifest/ZIP，私钥和部署配置不可读取。
3. 生成 server 更新配置/能力广告，处理未配置、旧客户端不兼容和失败重试；将包/manifest 原子发布顺序固定。
4. 用两个版本验证稳定 launcher、签名/哈希、状态快照、健康确认及回退；目录和 state 不随版本覆盖。
5. 提供正式构建所需输入清单和命令，正式材料不足时仅标注测试产物，通过 11/12 获取交付证据。

## 完成标准

- [ ] 解压测试包双击 start-client.cmd 可连接隔离 HTTPS origin；不启动本地生产后台，退出不关服务器。
- [ ] 同源托管可下载完整包，错 origin、越界路径、坏签名/哈希被拒绝，公钥与 manifest 对应。
- [ ] 上传/下载进行中升级保存状态，断网/新版启动失败回退不覆盖已交付文件或丢传输记录。
- [ ] 未配置更新入口明确提示；已配置时 capabilities 和客户端确实能发现并执行。
- [ ] 无正式材料时不能记录正式交付完成；测试密钥不进入正式包，任何包都不含私钥。
