## 实施步骤

1. 提供明确的计划任务注册/预览/状态入口，固定部署 ID、账号、绝对运行时与脚本路径；参数包含时间/时区、备份根和启用状态。
2. 限定重复注册只管理本部署的已验证任务，默认不修改其他任务。与 06/11 对齐首次启用流程，拒绝在源码加载时偷偷注册。
3. 接入已有一致性备份/日志/pin 设施；作业防重入，记录最近成功/失败及恢复证据，支持无人登录。
4. 在新临时恢复根实际恢复一次并校验配置、媒体和 DB；恢复后保持维护禁新付费直到对账。

## 完成标准

- [ ] dry-run 无系统写入，Apply 重复执行不产生重复任务、不覆盖同名陌生任务。
- [ ] 运行账号无交互 PATH 仍能启动；重叠执行不重复备份或破坏屏障。
- [ ] 失败不淘汰有效 daily；14 成功版本轮换不碰 manual/pre-upgrade，缺空间错误可定位。
- [ ] 恢复出的数据库/媒体/配置一致，未知付费记录不能因回退重提。
- [ ] 需要真实服务账号/计划任务的验证留给 12；本地报告清楚区分模拟与真实执行。
