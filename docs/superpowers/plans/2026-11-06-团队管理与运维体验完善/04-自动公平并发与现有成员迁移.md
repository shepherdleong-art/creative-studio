# 04：自动公平并发与现有成员迁移

**状态：** `wontfix`

**What to build：** 管理员可选择自动公平共享；系统按实际任务需求分配容量，单人可借用空闲名额，多人竞争获得公平运行机会。完成全部入口接入后，新老成员默认继承自动规则。

**Blocked by：** [03 团队并发默认规则与个人覆盖](03-团队并发默认规则与个人覆盖.md)。

**Parent：** [01 父规格任务](01-团队管理与运维体验完善.md)  
**需求依据：** [功能方案](../../specs/2026-11-06-团队管理与运维体验完善-功能方案.md)，自动与手动并发；A03 的自动迁移部分、A04、A05、A06。

## 实施边界

基于 03 的策略继承及覆盖，修改共享准入并接入真实生产调用链。各入口适配与必要的小范围预整理在启用自动模式之前完成，不发布“界面自动、实际仍抢占”的中间行为。

覆盖集中生产中的图片、视频、脚本、画布和使用共享池的配音／对齐；本地实拍重组和本机 Agent 不计入。实施定位见父任务“团队并发策略与迁移”。

## 验收条件

- [x] 自动模式以各共享池中有合格排队工作或真实运行占额的成员为依据，不以登录人数、页面在线或随机数分配。
- [x] 单人有充分可并行工作时可借用空闲容量；新成员加入后在名额释放时获得公平机会，不抢占或取消旧请求。
- [x] 以容量 10 验证单人借用、两人竞争及 20 人竞争；人数大于容量时仍有界轮转，不因整数均分为零停滞或长期饥饿。
- [x] 个人固定覆盖仍作为上限，不保留席位；无权限、费用不足、暂停或停用者不因自动分配获得新的调用资格。
- [x] 不同池的独立任务不被另一拥堵池的队首工作无理由挡住；多池请求原子取得所需名额，不重复占用或绕过共享容量。
- [x] 指定执行记录的准入路径与普通轮转路径遵守同一公平规则；实际图片／视频、脚本、画布及媒体入口均有模拟调用证据，不只测抽象算法。
- [x] 检查局部 worker 与任务内并发上限，解除无业务依据的瓶颈，同时保留串行依赖和真实资源约束；池容量上调有可观察的正确效果。
- [x] 降额、切换手动、竞争人数变化以及重启均不取消已受理任务；未知受理继续占额，等待并发不提前预留费用。
- [x] 自动能力完整后一次性迁移现有旧固定值为继承并留存原值审计；新成员默认继承；不改费用、权限、停用或明确暂停状态。
- [x] 迁移重跑／升级不重置已迁移成员后来明确设置的个人例外；03 以来新增的明确覆盖按来源识别，不与历史遗留值混淆。
- [x] 前端可切换自动／手动、查看继承来源与等待原因；自动状态不是永久保证的个人名额，真实上游容量不由人数推算。
- [x] 公平准入、争用、重启恢复与实际模块集成测试通过，并同步旧 ADR 的默认并发策略；涉及跨模块交接时执行主流程检查。
