# 09：记住登录及关闭重开修复

**状态：** `wontfix`

**What to build：** 登录时可选择记住登录状态 30 天；关闭客户端、重启电脑或正常更新后仍可进入工作台，同时退出、改密、凭据重置和停用会使旧凭据失效。

**Blocked by：** 无（获得实施授权后可开始）。

**Parent：** [01 父规格任务](01-团队管理与运维体验完善.md)  
**需求依据：** [功能方案](../../specs/2026-11-06-团队管理与运维体验完善-功能方案.md)，记住登录与关闭重开修复；A17、A18。

## 实施边界

用户确认“关闭客户端再打开就要登录”。先用实际运行版本和启动入口复现，区分持久化、目录、认证和版本问题；当前源码已有 30 天 Cookie 和持久分区，退出前未显式保存只是线索，不是已确认根因。定位见父任务“登录持久化”。

本票包含修复后的测试客户端产物和实际入口验收，不包含生产分发或覆盖员工安装。

## 验收条件

- [x] 记录复现步骤、实际版本、故障发生边界和修复前后证据；不能仅增加复选框或某个保存调用就宣布修复。
- [x] 登录页提供明确的 30 天记住选项；勾选后按本次认证起算 30 天，不暗中变为无限滑动续期。
- [x] 未勾选时仅保留当前会话，不静默创建 30 天跨会话登录；偏好保存不等于保存密码。
- [ ] 登录后立即关闭、正常使用后关闭再打开都保持有效会话；电脑重启及正常客户端更新后同样有效。真实 GUI 环境故障，未验证。
- [x] 持久会话和客户端状态使用稳定位置，不随版本目录更换；正常退出流程完成必要持久化，异常路径有界收尾。
- [x] 主动退出撤销会话；修改密码要求重新认证并撤销旧凭据；管理员重置或停用后旧登录不能继续调用。
- [x] 到期显示登录页及明确提示；短暂断网或握手失败不删除本来有效的登录，也不把网络错误当成账号退出。
- [x] 多账号不串缓存、项目或传输状态；会话仅在既有受保护存储中保存，不写明文密码或前端可读令牌。
- [x] 关闭轻客户端不会关闭统一生产服务或取消服务端已接受的任务。
- [ ] 认证接口、撤销和到期自动测试通过；真实启动器验证持久化、重启和更新受 GUI 环境故障影响，未验证；自动契约测试通过。
- [x] 输出受影响客户端组件、测试包版本和旧安装更新所需范围；保持签名校验、包边界和 TLS，不未经授权分发或部署。

## 可演示结果

在隔离服务登录并勾选记住，关闭实际客户端后重新启动直接进入；主动退出后重开则要求登录。另记录电脑重启和更新后的同等证据。
