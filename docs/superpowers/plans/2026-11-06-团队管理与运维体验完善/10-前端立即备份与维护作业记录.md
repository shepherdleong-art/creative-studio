# 10：前端立即备份与维护作业记录

**状态：** `ready-for-agent`

**What to build：** 管理员在备份与维护页点击立即备份，查看真实进度、校验结果及备份列表；操作由独立受控执行器完成，页面断开或重连不丢作业和发起人记录。

**Blocked by：** 无（获得实施授权后可开始）。

**Parent：** [01 父规格任务](01-团队管理与运维体验完善.md)  
**需求依据：** [功能方案](../../specs/2026-11-06-团队管理与运维体验完善-功能方案.md)，前端维护公共合同与备份；A11、A13 的公共权限／作业部分。

## 实施边界

以一次真正可恢复的备份贯通管理员界面、业务接口、应用外维护执行器和持久记录。复用现有备份屏障、校验、引用 pin 和轮换，不单独交付空的作业框架。

维护作业与审计必须位于不会随业务库还原而倒退的位置，以便 12、13、14 复用。具体代码定位见父任务“维护与清理”。

## 验收条件

- [ ] 管理员点击立即备份即可执行并看到待执行、运行、成功或失败及可验证进度；无法测量时显示阶段，不伪造百分比。
- [ ] 备份列表显示类型、时间、大小、校验状态和是否可用于还原；仅经完整性校验的备份显示成功。
- [ ] 操作记录真实网页登录管理员、动作、目标、时间与结果，不沿用脚本中“首个 active admin”冒充发起人。
- [ ] 固定受控动作通过应用外执行器完成，作业身份和结果持久；关闭页面、重新登录或应用重启后仍可查询同一操作。
- [ ] 重复点击和重试不会重复执行同一作业；互斥维护动作有统一锁定／排队或拒绝规则，进程重启后不凭丢失的内存锁并行执行。
- [ ] 服务端验证管理员、可信来源及受管目标；不允许任意命令／路径，不将既有回环控制凭据暴露浏览器或解除对外封闭。
- [ ] 使用一致性备份及媒体引用保护，空间不足、校验失败和执行器失败有明确结果；失败产物不作为可还原备份。
- [ ] 保留既有定时备份频率和用途保留规则；手动、升级前和还原前备份不混同过期缓存。
- [ ] 业务库恢复不应覆盖维护作业和审计位置；持久记录损坏或执行状态不明时显示待核查，不盲目再次启动。
- [ ] 自动化用隔离数据根验证正常、失败、幂等、互斥、权限和重启；测试服务器实际从前端生成备份并核验内容，不以脚本直接调用替代前端链路。

## 可演示结果

管理员点备份后关闭页面，再打开维护页看到同一作业完成；备份列表有可校验记录。用员工身份调用相同操作被拒绝。

## Comments

- 2026-11-06：本地实现（不改变票状态）。管理员“备份与维护”页通过固定 `POST /api/team/maintenance/jobs` 提交手动备份，`GET jobs`、`GET jobs/[id]`、`GET jobs/[id]/audit` 与 `GET backups` 用于重连、真实发起人审计和备份列表。会话、管理员与 Origin/CSRF 继续走 `withTeamRoute`；浏览器不可指定命令、配置路径、备份目录或回环控制凭据。
- 复用既有 `createTeamBackup`：SQLite Online Backup、生命周期屏障、媒体引用 pin、配置与执行 journal 固定副本、逐文件 hash、DB 完整性/外键校验和发布前/后验证。`TEAM_BACKUP_TYPES` 追加 `pre-restore`；daily 保留 14 个成功副本和既有计划任务不变，manual/pre-upgrade/pre-restore 不参与 daily 轮换。列表再次验证后才返回 `restorable: true`，失败 staging 不列为可还原。
- 作业与审计位于 `<backupRoot>/maintenance-control/{jobs.db,audit.jsonl}`，不写入、不随业务库恢复倒退；`global.lock.db` 同时约束网页 worker 和既有 CLI daily/pre-upgrade。作业身份为 UUID，幂等键唯一约束于 deployment+action+target+key；真实 AuthPrincipal 快照保存发起人。租约过期转 `needs_review`，审计损坏标记 `audit_corrupt`，不自动重跑。进度为真实阶段或 `progress: null`。
- 外部执行器入口为 `scripts/team-server/maintenance.mjs worker --config <受管 maintenance-deployment.json>`，只从持久作业取固定目标与发起人。SCM 定义、app.env 受管根、安装配置副本及停服顺序已接入；没有安装或停止任何服务。12/13/14 可复用 `MaintenanceJobStore`、`control.ts` 提交/查询、`listTeamBackups` 与 `runMaintenanceWorker`，动作类型预留 `release.execute`/`restore.execute`/`cleanup.execute`，目标分别绑定 candidateId、受管 backupId、previewId；各业务执行器仍需本票之外实现。
- 隔离验证：真实 Chromium 登录/改密、管理员点击“立即备份”、独立 worker 完成、关闭并重开页面同 UUID、备份库实读、篡改执行证据后不可还原；路由员工 403、Origin 拒绝、任意路径/命令 400、幂等/冲突、空间不足、跨进程互斥、租约过期与损坏审计均有定向测试。`tsc`、定向 ESLint、daily 轮换/引用 pin、恢复、发布白名单、PS 5.1 dry-run/BOM、计划任务和路由覆盖回归通过。
- 未实机：Windows SCM 实际安装/启动/故障重启、受管配置 ACL/gMSA、HTTPS 证书与无人登录/RDP 断开、连续 14 日计划任务、大容量媒体与真实磁盘耗尽。测试使用临时数据根、fixture release 和独立子进程，没有对生产运行备份或停止服务，没有真实 AI/付费调用。
