# 10：前端立即备份与维护作业记录

**状态：** `ready-for-agent`

**What to build：** 管理员在备份与维护页点击立即备份，查看真实进度、校验结果及备份列表；操作由独立受控执行器完成，页面断开或重连不丢作业和发起人记录。

**Blocked by：** 无（获得实施授权后可开始）。

**Parent：** [01 父规格任务](01-团队管理与运维体验完善.md)  
**需求依据：** [功能方案](../../specs/2026-11-06-团队管理与运维体验完善-功能方案.md)，前端维护公共合同与备份；A11、A13 的公共权限／作业部分。

## 实施边界

以一次真正可恢复的备份贯通管理员界面、业务接口、应用外维护执行器和持久记录。复用现有备份屏障、校验、引用 pin 和轮换，不单独交付空的作业框架。

维护作业与审计必须位于不会随业务库还原而倒退的位置，以便 12、13、14 复用。具体代码定位见父任务“维护与清理”。

## 验收条件

- [ ] 管理员点击立即备份即可执行并看到待执行、运行、成功或失败及可验证进度；无法测量时显示阶段，不伪造百分比。
- [ ] 备份列表显示类型、时间、大小、校验状态和是否可用于还原；仅经完整性校验的备份显示成功。
- [ ] 操作记录真实网页登录管理员、动作、目标、时间与结果，不沿用脚本中“首个 active admin”冒充发起人。
- [ ] 固定受控动作通过应用外执行器完成，作业身份和结果持久；关闭页面、重新登录或应用重启后仍可查询同一操作。
- [ ] 重复点击和重试不会重复执行同一作业；互斥维护动作有统一锁定／排队或拒绝规则，进程重启后不凭丢失的内存锁并行执行。
- [ ] 服务端验证管理员、可信来源及受管目标；不允许任意命令／路径，不将既有回环控制凭据暴露浏览器或解除对外封闭。
- [ ] 使用一致性备份及媒体引用保护，空间不足、校验失败和执行器失败有明确结果；失败产物不作为可还原备份。
- [ ] 保留既有定时备份频率和用途保留规则；手动、升级前和还原前备份不混同过期缓存。
- [ ] 业务库恢复不应覆盖维护作业和审计位置；持久记录损坏或执行状态不明时显示待核查，不盲目再次启动。
- [ ] 自动化用隔离数据根验证正常、失败、幂等、互斥、权限和重启；测试服务器实际从前端生成备份并核验内容，不以脚本直接调用替代前端链路。

## 可演示结果

管理员点备份后关闭页面，再打开维护页看到同一作业完成；备份列表有可校验记录。用员工身份调用相同操作被拒绝。
