# 07：服务端错误自动记录与错误中心改造

**状态：** `ready-for-agent`

**What to build：** 服务器生成、接口、存储和媒体处理出错时自动生成可追溯的错误编号，管理员和员工在错误中心看到中文原因、关联工作和诊断信息，不再手工填写技术错误码。

**Blocked by：** 无（获得实施授权后可开始）。

**Parent：** [01 父规格任务](01-团队管理与运维体验完善.md)  
**需求依据：** [功能方案](../../specs/2026-11-06-团队管理与运维体验完善-功能方案.md)，错误中心与自动上报；A09 的服务端及展示部分。

## 实施边界

复用既有诊断记录、执行失败回调和权限模型，补齐服务端捕获链路与页面。代码定位见父任务“自动诊断”。与 08 共享诊断模块的修改需协调，但两票都可基于既有接口独立验证，不人为串行。

## 验收条件

- [ ] 生成提交、轮询、结果下载、业务 API 异常、存储及媒体执行失败均有真实捕获入口，自动写入关联诊断，不能只有一个人工上报接口。
- [ ] 可信上下文关联成员、项目／画布、任务、执行尝试、阶段、可用模型与版本；未知信息明确缺失，不推断或伪造归属。
- [ ] 错误中心默认展示自动错误、中文原因和行动提示；编号查询、关联任务跳转、复制与诊断下载保持可用，技术码放详情。
- [ ] 手工技术码及任务 ID 表单退出正常使用流程；若保留补充说明入口，不要求用户懂技术码，也不替代自动记录。
- [ ] 同一事件稳定去重；正常取消、等待和预期参数校验不作为系统故障刷屏；自动恢复与最终失败可以区分。
- [ ] 记录及下载诊断不包含密钥、Cookie、请求头、完整鉴权串、签名 URL、素材原文或完整请求体；模型信息仅作安全投影。
- [ ] 员工只能查询本人记录；管理员按授权查询团队，诊断下载和关联任务访问均独立验证权限。
- [ ] 诊断记录失败不掩盖原始业务响应、不递归制造错误，也不让正常业务因诊断链路不可用被无界阻塞。
- [ ] 使用真实隔离业务接口和 worker 的故障注入验证记录与展示，不仅直接调用诊断写入函数；保留已有错误记录兼容。

## 可演示结果

在测试服务触发模拟供应商失败及受控存储失败，员工无需填表即可获得错误编号，管理员能由错误中心定位任务和阶段并下载脱敏诊断。
