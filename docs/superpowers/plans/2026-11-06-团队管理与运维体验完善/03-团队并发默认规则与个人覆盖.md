# 03：团队并发默认规则与个人覆盖

**状态：** `wontfix`

**What to build：** 管理员在前端一次设置团队手动并发默认值，成员可继承或使用个人固定上限；保存后实际任务准入按新规则执行，并能看见规则来源和等待原因。

**Blocked by：** 无（获得实施授权后可开始）。

**Parent：** [01 父规格任务](01-团队管理与运维体验完善.md)  
**需求依据：** [功能方案](../../specs/2026-11-06-团队管理与运维体验完善-功能方案.md)，自动与手动并发；A03、A06 的手动策略部分。

## 实施边界

本票先交付可独立使用的手动模式、团队继承与个人覆盖，不提前显示可用的自动模式。04 完成后才启用最终的默认自动策略和旧成员自动迁移。新增结构先兼容现有执行调用，再接入设置、准入和展示；不另开纯 schema 或纯 UI 票。

涉及实施入口见父任务“团队并发策略与迁移”。保留原权限、费用与旧策略兼容；旧值来源和新管理界面明确设置的覆盖应可区分，供 04 一次性迁移使用。

## 验收条件

- [x] 管理员可以保存团队手动默认上限；成员可选择继承、固定覆盖及恢复继承，新成员无需逐个填写已配置的默认值。
- [x] 页面显示当前占用、生效上限和规则来源；服务器在每次新准入时应用相同策略，不只改变显示数字。
- [x] 个人固定值是最大并发约束，不预占共享池名额；任何策略均不突破真实上游共享容量。
- [x] 旧成员保留兼容行为，直到 04 执行明确的自动迁移；本票不通过启动或读取页面批量改写旧策略。
- [x] 模型权限、月度额度、账号停用、个人暂停和团队维护独立生效；并发为零与显式暂停分别表达。
- [x] 调低上限或修改继承关系只影响后续提交；已受理／受理不明请求继续占额并正常收取结果，不取消或重复发送。
- [x] 新策略和来源持久化，重启后仍有效；冲突保存能被识别，不能静默覆盖另一管理员刚保存的设置。
- [x] 非管理员不能写策略；非法值有明确提示；如需迁移采用所属模块追加迁移和共享升级保护。
- [x] 通过现有执行准入测试和页面／接口验收演示继承、覆盖、恢复继承、降额等待、重启和越权拒绝；不发起付费调用。

## 可演示结果

管理员把团队默认设为测试值，为一个成员设置较小上限；两人提交模拟任务，页面规则来源与实际运行数量一致，再恢复个人继承并观察后续准入。
