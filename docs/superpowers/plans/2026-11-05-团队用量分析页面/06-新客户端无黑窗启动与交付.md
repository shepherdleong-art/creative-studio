# 06 新客户端无黑窗启动与交付

**状态：** `ready-for-agent`
**Blocked by：** None (can start immediately)

**What to build:** 以后领取新 Windows 客户端的成员双击带应用图标的默认入口，全程不见 CMD 黑窗，正常进入可操作的客户端；校验或启动失败时收到中文弹窗和日志位置。交付可验收的新包入口及装配能力，不改旧电脑。

**依据：** [新 Spec 确认单](../../specs/2026-11-05-客户端无黑窗启动与成员用量分析-确认单.md)。遵守轻客户端与服务器统一生产边界 ADR；动工前读打包与桌面运行参考。

**实现入口：** `scripts/team-client/` 中新增 C# WinExe 启动器源码，复用稳定 launcher 和诊断 CMD；在 `scripts/build-team-client.mjs` 接入 Windows 编译与装配，并同步打包白名单、相关守护测试和包内说明。

- [ ] 新 Windows 包有带应用图标的 `Creative Studio.exe`，作为说明及快捷方式的默认目标；采用 C#/.NET Framework 编译为 WinExe，编译缺失或失败时构建明确失败，不交付缺入口的新包。
- [ ] 默认入口直接隐藏启动包内运行时及稳定 launcher，不通过 CMD；正常从资源管理器双击全程无可见控制台，包括瞬间闪现，用户 GUI 正常显示和可操作。
- [ ] 签名、当前版本指针和健康提交状态仍由既有 launcher 校验；不能绕过校验直接启动版本内 GUI。仅后台启动过程隐藏，用户 GUI 保持 `windowsHide:false`。
- [ ] 保留 detached、独立日志及 unref 行为；启动器退出后 GUI 继续运行。进程创建成功不冒充后续应用健康通过，沿用既有健康机制。
- [ ] 运行时缺失、验签失败和进程创建失败产生中文弹窗，包含可操作的错误原因及日志位置；若日志目录不可写，弹窗如实说明而非宣称日志已落盘。
- [ ] 保留并清晰标注 CMD 诊断入口，日志可排障；不让日常用户仍依赖 CMD 或外部开发环境，不更改服务器地址、代理/直连配置、在线更新协议和窗口退出行为。
- [ ] 更新白名单和包边界验证，禁止把源码、运行数据和密钥打入新包；说明写清日常/诊断入口。只通过未来新包提供，不制作旧包补丁、不替换旧客户端或快捷方式，不声称版本内更新能覆盖包根入口。
- [ ] 使用临时包与测试签名完成真实入口验收：中文/空格路径、GUI 可见、启动器先退出、日志、重复启动的既有行为、缺运行时、签名异常和启动失败；不能用绕开新入口的 Electron 启动或隐藏 CMD 测试代替。
- [ ] 运行客户端 launcher、包边界及更新 wiring 定向测试，核对编译生成的 Windows GUI 子系统与新包装配，保存验收记录；不停止用户正在运行的客户端，不调用服务器关闭端点或真实付费供应商。
- [ ] 保留构建脚本已有无关修改。现工作区直连配置输出与既有守护断言的差异独立核实，不为本票顺手改连接模式；若阻断整包验收，记录具体阻断，不能跳过检查后宣称新包已验收。
