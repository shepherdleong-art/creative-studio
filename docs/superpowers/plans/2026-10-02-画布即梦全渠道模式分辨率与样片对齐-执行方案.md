## 1. 产品目标与交付范围

把即梦的视频创作能力放入自由节点画布：素材可连接和复用，创意可分支，结果可继续编辑或延长；增加“先试样片、人工选片、再生成正式视频”的完整流程。

本期交付：

1. 方舟直连与公司 API 的即梦统一六种创作方式的产品语言：文生视频、全能参考、首尾帧、智能多帧、智能编辑、视频延长；每代模型和每个渠道按自身合同执行。
2. 视频节点显式提供“分辨率”选择；按精确模型和渠道过滤选项，并与媒体数量、时长、纯音频参考、自动时长、自适应比例及输出参数一起贯通。

4. 对应的持久化、请求映射、过期处理、恢复、用量记录和验收证据。

本期覆盖当前已注册的直连 2.0 标准版、直连 2.5、公司 2.0 Fast、公司 2.5，并接入公司 2.0 标准版（`doubao-seedance-2-0-260128`）：两边 `config.yaml` 都有这条路由，主项目计价表有单价，09-29 账单有消耗；缺的是供应商登记和字段验证，见 §3.5。其余公司型号不凭名称创建供应商配置，也不假定公司提供全部型号。2.0 Mini 作为能力边界记录，不因官方支持而擅自新增模型入口。

## 3. 能力合同

### 3.1 Seedance 2.5 六种创作方式

下表的输入规则约束当前节点，不限制整张画布的素材数量或分支数量。数量之外还须执行 §3.2 的媒体限制。

| 界面模式 | API 映射 | 输入与参数 |
| --- | --- | --- |
| 文生视频 | 文本 content | 无媒体输入；比例可选／自动，时长 4–30 秒／自动 |
| 全能参考 | reference_* + omni=reference | 图 0–30、视频 0–10、音频 0–10，合计至少一份；支持纯音频；比例和时长可选／自动 |
| 首尾帧 | first_frame／last_frame | 首帧必需，尾帧可选；参考顺序决定首尾；ratio=adaptive，时长可选／自动 |
| 智能多帧 | 多图 reference_image + omni=reference | 保留独立入口，2–30 图；素材顺序和意图可编辑；时间控制靠分段提示词，见下方说明 |
| 智能编辑 | reference_* + omni=edit | 至少一段视频；每段视频 4–30 秒；ratio=adaptive、duration=-1；允许辅助图和音频 |
| 视频延长 | reference_* + omni=extend | 至少一段视频；每段视频 2–30 秒；ratio=adaptive，输出时长 4–30 秒／自动；支持串联后续延长节点 |

智能多帧（复核已定）：S5 里没有「关键帧／多帧」这个 API 概念，也没有时间戳字段。官方的时间控制写在提示词里，例如「[0-10秒]：…」这样分段描述（S5「30 秒视频连贯直出」示例）。因此按「多张 `reference_image` 按图序参考 + 分段提示词」实现。界面可提供按图序插入分段提示词模板的辅助，并说明时间点由模型按提示词理解、不保证精确命中；不虚构时间戳字段。即梦网页的智能多帧若有无法等价的交互，记录差异，交用户评估。

视频延长：单次 API 输出仍受 30 秒限制。2.0 的输出内容 S4 已写明（第 35 页，页脚 32/49）：
- 向前或向后延长 1 段视频，输出一般只含原视频的尾部画面；提示词可以要求包含原视频，例如「…最后接视频1」。
- 传入 2–3 段视频补全中间过渡时，输出包含原内容和新内容。

2.5 是否相同，按 P6 的样本授权流程用一条真实样本核实。本期支持用户主动串联多轮延长，不自动拼接原视频，也不自动无限续写。超过输入上限的长结果须明确提示边界，不静默截取。输出通常只是续写片段，而本期又不做拼接，所以界面采用「视频延长」（§9.1）。

编辑／延长：保留意图提示与参数约束校验。关键词检测只提供本地意图提示或既有前置校验，不能宣称消除模型的异步 TaskTypeMismatch；核对同义词与官方例句（S5 页脚 3/79），避免过窄词表阻碍正常表达。保留服务端错误解释。

`omni_reference_task_type` 除 `reference`／`edit`／`extend` 外还有 `auto`。S5 页脚 2–3/79 对不区分子任务的推荐是 `auto` + adaptive + -1。现在全能参考固定发 `reference`（`jimeng.ts:297`），用户在全能参考里写了编辑类提示词，会异步报 TaskTypeMismatch。本期全能参考保持 `reference`，通过提示引导用户选择编辑或延长模式（§9.1）。

### 3.2 Seedance 2.5 媒体边界与参数

依据 S1，本期落实以下规则：

- 视频：通常单段 2–30 秒，编辑单段 4–30 秒；最多 10 段，视频合计 ≤30 秒。
- 音频：单段 2–30 秒，最多 10 段，音频合计 ≤30 秒。只在 2.0 保留必须搭配视觉素材的限制。
- 图像最多 30 张；首尾帧和智能多帧按各自模式收窄。图／视频尺寸、文件大小、编码、帧率等补齐交付前预检；无法探测的关键元信息先探测，探测失败不得按 0 秒放行。2.5 的逐项规格 S5 页脚 78–79/79 已给出，P1 只需核对 2.0（S4）差异：
  - 图片：jpeg／png／webp／bmp／tiff／gif／heic／heif；宽高比 0.4–2.5；边长 300–6000 px；单张小于 30 MB。
  - 视频：mp4／mov，H.264 或 H.265，音轨 AAC／MP3（mov 另可 PCM）；宽高比 0.4–2.5；边长 300–6000 px；总像素 407696–8295044；24–60 fps；单个不超过 200 MB。
  - 音频：wav／mp3，单个不超过 15 MB。
- 请求体不超过 64 MB（S5 页脚 78–79/79）。图片交付失败时，现有代码会回退成内嵌 base64（`external.ts:359-361`、`:510`），30 张图很容易超限。提交前计算请求体大小：超限时要求图片走 COS，否则在 POST 前失败，不把超限请求发出去。
- 分类总时长和单段时长均校验，以未取整值累计，不能对每段取整后低估总量。容差只用来吸收探测误差：沿用现有 0.25 秒（`external.ts:57`；作用于单段下限和分类总量，单段上限不加），不扩大也不取消；要调整须先有真实上游样本证明。边界测试按现有行为固定。
- 视频、音频沿用本地 COS 交付；图片沿用已支持交付方式。公网可达不通过开放本机服务实现。官方还支持的资产 ID 等其他交付形式不作为本期必需入口。

| 参数 | 直接正式生成 | 样片生成 | 基于样片生成正式视频 |
| --- | --- | --- | --- |
| 清晰度 | 480p／720p／1080p | 固定 480p | 固定 1080p |
| 比例 | 依模式可选或锁定 | 依模式可选或锁定 | 从样片继承，不重复发送 |
| 时长 | 自动或 4–30，编辑固定自动 | 同左 | 从样片继承，不重复发送 |
| 音频生成 | 可设置，沿用旧节点默认 | 可设置 | 从样片继承，不重复发送 |
| 输出格式 | MP4／MOV | MP4／MOV | 可重新指定 |
| 水印／返回尾帧 | 可设置 | 可设置 | 可重新指定，不能假定自动沿用样片值 |

新增参数默认值要显式固定并兼容已有节点，不能因官方默认值变化让旧图静默变样。“自动时长”在 UI 显示中文，在 API 映射 -1；不得把 -1 钳成 4，也不得据此计为负时长。自由比例补 adaptive 和官方支持的 21:9 等完整选项。

统一参数过滤：界面按模式／生成阶段展示；切换时清理不适用的已知参数；planner 对旧图残留兜底。未知字段继续报错。正式转化使用独立请求白名单，避免继承参数被通用默认值逻辑重新塞回请求。

MOV／1080p 以及 2.0 4K 的下载、真实 MIME、扩展名、探测、播放器和导出要贯通。现在两个画布适配器的下载都把视频 MIME 写死为 `video/mp4`（`external.ts:677`、`company.ts:480`），要改成按实际格式。原始产物完整保留。

浏览器预览复用主项目 `lib/video-browser-preview.ts`，不在画布里另写一套：
- 它把非「H.264 + yuv420p」的视频转成旁边的 `<原名>.preview.mp4`，音轨转 AAC。这覆盖 2.5 的 1080p HEVC 10bit、2.0 的 4K，以及 MOV（H.264 yuv444p + PCM，S5 页脚 76/79）。
- 它只依赖 `lib/ffmpeg.ts`，不违反「画布不从 `final-edit/` 导入」的红线。
- 预览副本不登记为任务产物，不进导出清单；下载与后续正式输入仍指向原件。

返回尾帧作为关联附属素材保存，不破坏现有“一任务一主输出”的约束。

### 3.3 Seedance 2.0 模式对齐

S4 明确支持参考、编辑和延长；提供的编辑示例采用 reference_image／reference_video、ratio=16:9、duration=5，未发送 2.5 的 omni 字段。因此统一入口后仍分别构造请求。

| 统一入口 | 2.0 执行规则 | 相比 2.5 的差异 |
| --- | --- | --- |
| 文生视频 | 文本生成，4–15 秒，按型号选择分辨率 | 不允许 30 秒或样片 |
| 全能参考 | 合并旧“视频生视频／参考生成”；图≤9、视频≤3、音频≤3，至少一份媒体 | 纯视频可用；纯音频不可用，须搭配图或视频；视频和音频分别总时长≤15 秒 |
| 首尾帧 | 首帧必需、尾帧可选；直连使用明确的 first_frame／last_frame 角色 | 公司渠道须单独证明严格角色映射，不能以双图数组等同严格首尾帧 |
| 智能多帧 | 2–9 张图的顺序参考与提示词引导；独立入口 | 与 2.5 相同，时间控制靠分段提示词（§3.1）；不捏造原生时间戳控制 |
| 智能编辑 | 至少一段视频，通过 reference_* 和编辑意图提示词执行 | 不发送 omni_reference_task_type；不强制套用 2.5 的 adaptive／-1 锁定与 4 秒输入下限 |
| 视频延长 | 至少一段视频，通过参考与延长意图执行；可串联延长节点 | 单次输出仍最多 15 秒；2.0 的单视频延长和多片段串联输出语义依 S4 分别说明 |

2.0 视频／音频单段和分类总时长按其官方合同保持 2–15 秒／各≤15 秒，完整元信息预检与 2.5 共享机制而非共享数值。

2.0 的自动时长和自适应比例（复核已定）：S5 第 10–11 页（页脚 7–8/79）的对照表写明，2.0、2.0 Fast、2.0 Mini 均支持「4~15 秒；-1」，比例含 adaptive。S4 的简表只列 4–15 秒，以较新的 S5 为准。因此：
- 2.0 在适用模式开放「自动」时长和比例。
- 现有 `normalizeJimengDuration` 会把 2.0 的 -1 钳成 4（`jimeng.ts:25-27`），须改为透传。
- 不套用 2.5 的编辑锁定规则。

2.0 不开放 draft／draft_task 或 MOV。编辑／延长的请求和效果单独新增证据；原有“已验证”不能自动覆盖新增模式。2.0 与 2.5 的模型切换仍保留节点、连线与用户文本，非法参数给出解释和可见修正，不静默删除素材。

### 3.4 分辨率选择：必须可见、必须真正生效

视频生成节点在“模式”下面显式显示“分辨率”，与比例、时长并列，不隐藏在高级设置。视频使用 480p／720p／1080p／4K 文案，避免与图片模型的 1K／2K／4K 档位混用；4K API 值按官方使用 `4k`。

| 模型／生成阶段 | 官方允许的选项 | 渠道处理 |
| --- | --- | --- |
| Seedance 2.0 标准版 | 480p、720p、1080p、4K | 直连完整接入；公司路由已存在（§3.5），按字段探测结果映射 |
| Seedance 2.0 Fast／Mini | 480p、720p | 公司当前 Fast 按此目标核验；不开放 1080p／4K；Mini 仅在真实注册时展示 |
| Seedance 2.5 直接生成 | 480p、720p、1080p | 直连完整接入；公司从旧固定 size 映射（主项目 `company-gateway-size.ts` 的 1080p 像素表）扩展为经验证的显式档位 |
| Seedance 2.5 样片 | 固定 480p | 显示锁定状态及原因，仍保留可见分辨率行 |
| Seedance 2.5 基于样片转正式 | 固定 1080p | 显示锁定状态及原因 |

分辨率规则：

1. 作为能力表、节点参数和任务快照的一等字段；文生、首帧、首尾帧、全能参考、多帧、编辑、延长逐条贯通，清除适用分支中的 1080p 硬编码。
2. 旧节点缺字段时保持已确认的旧有效输出档位并显式展示：
   - 直连三条提交路径都固定发 1080p（`jimeng.ts:213/244/284`）；
   - 公司 2.5 按 1080p 像素表送 size；
   - 公司 2.0 Fast 不送 size。

   新节点默认值按 §9.1：支持且渠道已验证 1080p 的型号默认 1080p，Fast／Mini 默认 720p；受渠道能力约束时明确显示实际有效档位。公司“省略字段走默认”的旧请求须先查明有效值，不把未知默认冒充 720p 已指定。
3. 模型／阶段切换导致选项失效时提示将采用的合法档位；保留用户先前的直接生成偏好，离开样片模式时合理恢复，而非把所有直接生成永久改为 480p。实际任务只冻结当前有效值。
4. API 拒绝不支持的档位；无论直连或公司，不能接收 480p 却固定发送 1080p。公司若仅支持部分档位，显示实际可用选项及渠道原因。
5. 请求值与产物探测的宽高、编码和位深分别记录。方形／竖版等按官方对应像素表验证，不能仅凭文件名或“一条边等于 1080”判断档位。
6. 2.0 4K 有独立且更低的上游额度（S4 页脚 4–5/49：4K 每分钟 15 次、并发 1）；执行前核对当前限流并映射到已有供应商并发机制，排队和恢复沿用画布调度，不另建内存队列。
7. 公司档位和时长的事实源是主项目 `company-gateway-size.ts` 与 `video-duration.ts`。字段探测证明新档位或 30 秒可用后，先改这两个共享模块（旧工作台同时受益），画布能力表引用它们，不另写数值。

### 3.5 公司 API：对齐直连功能，独立传输合同

公司 API 是本期正式实施范围，完成标准是：**相同精确模型在直连可用的本期创作功能，公司也可用；菜单、输入、分辨率、输出设置和样片流程的差异仅来自模型本身与已明确的上游限制。** 当前本地代码使用 `/v1/videos`、`prompt`、`images`、`seconds` 和 `size`；方舟直连使用 `/contents/generations/tasks` 与 content roles。底层模型同名不能证明上述接口字段自动等价。

现状（修订时）：`company.ts` 全文不读 `generationMode`，输入规则只按素材类型匹配（`company.ts:142-146`），请求体只有 `model/prompt/images/seconds/size`。已知网关会把单图当参考图处理（`docs/reference/公司网关与COS中转.md`）。所以公司对齐要重写 Seedance 分支，不是加几个参数。

字段探测（P1，需公司内网及单独确认的受控请求清单）：先确定网关对字段的处理，再设计 P2B；不承诺零成本。
- **方法**：参考 `scripts/company-gateway-field-probe.mjs` 的非法值探测思路，但它原有的可灵证据不能外推到 Seedance。字段专属的「不认识」或「值非法」报错只作为识别线索；通用 400、其他字段先报错、静默丢弃均不能判定支持或不支持。只有确认建任务前被拒绝的请求才记录为未创建任务。同步后还可参考主项目的 `scripts/company-seedance-1080p-probe.ts`。
- **脚本**：原脚本写死探测可灵 3.0（读 `defaultModel = 'kling-3.0'` 的供应商）。复制一份改成 Seedance 型号，不改原脚本的行为。
- **边界与停止条件**：执行前提供精确型号、候选字段、请求总数上限、素材和费用上限（无法估价则明确写出未知），取得本轮请求授权。假地址和非法值不能保证不建任务或不计费。请求串行执行、禁用自动重试；出现任务 ID、成功接收、响应含糊或超时等可能已提交情况，立即停止余下探测，保留脱敏证据，不自动再发。字段识别后仍须本地映射测试和获授权的真实样本证明功能生效。
- **候选字段**至少包括：`content` 与 role、视频／音频参考、`resolution` 与 `size`、`ratio=adaptive`、`seconds=-1` 与 30、`omni_reference_task_type`、`draft`、`draft_task`、`output_format`、`return_last_frame`、`watermark`。
- **记录**：脚本只读本机配置、不打印密钥；结果按「字段／请求摘要／响应摘要／结论」记入执行记录。
- **没有内网时**：P2A 照常推进，P2B 等探测结果；不能拿本地网关替身代替字段证据。

共享模式名称、媒体约束、分辨率矩阵和界面；公司适配器处理 COS、请求字段、网关任务身份、查询和下载。实施中按“模型能力 × 渠道已验证能力”控制开放，持续补齐差额直至目标覆盖；这个临时门禁不改变全功能对齐的交付范围。直连实现作为模型规则基线，公司按实际协议转换。

| 必须核验的公司合同 | 通过条件 |
| --- | --- |
| 媒体类型与数量 | 官方支持的图片／视频／音频完整进入网关；多图顺序与提示词引用一致，无静默丢弃 |
| 首尾帧与参考图 | 找到明确角色映射或等价网关字段；历史“2.5 双图为参考重构”须新证据才能提升为严格首尾帧 |
| 分辨率／比例／时长 | 验证 resolution 或 size 的真实映射、adaptive、-1、2.5 的 30 秒；不沿用可灵尺寸表，不把 Fast 设成 1080p |
| 编辑／延长 | 2.0 参考提示词合同、2.5 omni 子任务字段或等价协议均有网关依据；参数限制按代际执行 |
| 样片／转正式 | 网关支持 draft、480p、draft_task 或等价字段；保留可复用来源身份和官方创建时间；区分网关任务 ID 与方舟原始 ID |
| 其他输出 | 音频、水印、MOV、尾帧以及真实 usage 的支持按精确模型／字段记录 |
| 查询与下载 | 沿用提交时原始网关 ID；支持结果 URL 归一与带鉴权 content 下载，重启不重复生成 |

COS 是交付步骤：所有公司输入媒体先通过受控交付层拿到 COS 预签名地址；缺配置、上传失败或不满足媒体合同在生成 POST 前失败，界面给出原因。本机 app／LiteLLM 继续只监听回环，密钥和签名串不进日志。纯文本和基于已存在样片身份的正式提交无需虚构素材上传，也不因不需要 COS 的请求强行要求 COS 配置。

本机 LiteLLM 只做转发，补不出远端网关没有的字段。网关已认、只是字段名不同的，在公司适配器里转换。真实上游网关缺字段时，形成精确的网关支持需求和受影响功能清单，保留已可用能力并标明未开放原因。不能偷偷改走外部直连、切换账号或改变计费渠道。公司模式和分辨率全部对齐仍是目标。用户已接受分阶段交付：已验证能力适配并通过对应验收后，可报告 P2B 本地适配完成；网关缺口单列受阻跟进，受影响的 P3／P6 和 A 项不得标为通过，整体不宣称全功能对齐。仅整理缺口清单，不自动向网关方发送消息。

公司每项能力须记录“目标／当前字段／预期转换／本地请求证据／真实结果／待补网关项”。已知差异至少覆盖公司 2.5 的严格首尾帧、30 秒、三档分辨率、全模态参考、纯音频、编辑／延长、样片两阶段；公司 2.0 Fast 则对齐同型号的六模式和 480p／720p，不能拿直连 2.0 标准版的 4K 上限套用 Fast。

公司 2.0 标准版（`doubao-seedance-2-0-260128`）：
- **已有**：两边 `config.yaml` 都有路由；主项目计价表有单价（¥2.52／5 秒），09-29 账单有 ¥35.29 消耗；主项目 `video-duration.ts` 和尾帧 allowlist 已把它当公司 Seedance。
- **缺**：主项目启动补种里没有这个供应商；仓库里没有它的字段和产物验证记录。
- **任务**：
  - 按主项目补种约定加 canonical 行，只补缺、不覆盖用户配置。ID 用计价表已有的 `company-seedance-2-0`，否则计价匹配不上。
  - 画布能力表先登记为 `candidate`（界面不开放），字段探测和 P6 真实样本通过后再提升。
  - 档位按 2.0 标准版（含 4K）核验，不套用 Fast 的 720p 上限。

### 3.6 旧图兼容

## 4. 样片在画布中的交互

### 4.1 两个选择维度

- 创作方式：§3.1 六种模式。
- 生成方式：“直接生成正式视频”／“先生成样片”。这是独立参数维度。
- 从样片派生的“正式生成”仍复用视频生成节点体系，但使用专门的任务意图和锁定来源；UI 明确显示“基于样片生成正式视频”。

```mermaid
flowchart LR
  A[自由连接图片 视频 音频 提示词] --> B[视频生成节点：先生成样片]
  B --> C[样片素材 A]
  B --> D[样片素材 B]
  C --> E[用户选定 A 并创建正式生成节点]
  E --> F[用户点击生成正式视频]
  F --> G[1080p 正式素材]
  G --> H[继续参考 编辑 延长 或导出]
  C --> I[作为普通参考进行新创作]
```

### 4.2 操作规则

1. 同节点可按现有多变体规则生成样片；结果分别物化为素材节点，保留播放、下载和比较能力，生成节点内不增加第二套产物列表。
2. 样片素材显示样片标识、原始创作方式、生成时间及可转正式的截止时间。截止时间来源于官方任务 created_at + 7 天，按用户本地时间显示。
3. 选择“生成正式视频”先创建一个绑定该样片的节点，展示继承内容和可调整输出设置；用户点击节点生成按钮才提交付费任务。创建节点、连线、复制、刷新均不提交。
4. 样片完成后不自动转正式。分支执行不得跨过人工选片步骤；普通“运行分支”遇到待确认的正式生成节点要明确展示跳过／待确认原因。单独点击该节点生成才建立本次正式任务，不留下可被后续分支重复消费的永久授权标记。
5. “基于样片生成正式视频”固定选定的样片 taskId／assetId；上游改提示词、替换素材、重跑或完成其他变体均不改变它。
6. 若想改内容，提供“以原参数创建新样片分支”；基于已选样片的正式节点只开放官方允许重新设置的项。
7. 样片仍可作为普通视频参考连接任意兼容节点。普通参考路径提交媒体；转正式路径提交 draft_task 身份，两条路径清晰区分。
8. 样片过期后本地素材仍可播放、下载、导出和作为普通参考；转正式入口提示过期，并提供创建新样片分支的操作，不自动重新生成。
9. 普通上传视频、导出的样片重新导入、只有本地文件但缺少有效来源身份的素材，不开放官方转正式能力。已有画布复制流程须保留或明确失效来源绑定，不能误绑定到同名节点。
10. 编辑器浅色／深色、中文输入、缩放平移、节点宽度和现有快捷键行为保持兼容。全部新增颜色走设计令牌。

P1 先提供可点击原型，覆盖上述正常与过期流程；原型不调用真实服务。原型完成后继续按已批准方案推进；只有出现未获认可的产品取舍时才提交待决问题。

### 5.1 持久化信息

| 信息 | 保存与使用规则 |
| --- | --- |
| 任务生成阶段 | 区分 direct／draft／final-from-draft；缺字段的旧任务按 direct 解释 |
| 样片来源 | 绑定源画布、源本地任务、源资产及其远端任务身份；服务端从可信记录解析，客户端只选择本地来源 |

| 官方时间 | 保存远端 created_at 与推导的 expiresAt；缺失则补查询，不能用本地完成时间延长有效期 |

| 来源关系 | 正式 task／asset 可回溯样片 task／asset；样片的普通引用与转正式关系可区分 |

API 不能信任客户端自填的 providerTaskId、到期时间或“这是样片”标记。需校验来源归属、任务类型、成功状态、主资产与任务的对应关系、模型和供应商可用性。同一 providerId 不能证明用户没有换过账号；路由或凭据配置变化后重新查询来源任务确认可访问性，失败时要求修复配置，不能换渠道重发。

### 5.2 请求与状态机

- Draft：在各适用模式的现有请求上显式添加 draft=true、resolution=480p，其他输入按创作方式校验。逐模式确认支持矩阵；发现上游不支持的组合应关闭该组合并记录证据，不能悄悄改成普通 480p 任务。
- Final：新增独立的类型化提交合同，content 只含 draft_task；同一模型、1080p、draft 省略或 false，只附加允许重新指定且已通过校验的输出设置。不会重新上传原素材或把样片当 reference_video。
- 上述为共享语义及方舟线上的合同；公司通过独立请求映射达到相同结果。网关 ID 与上游样片 ID 分字段保存，转换身份由实际协议决定；来源任务不得跨渠道或跨账号复用，除非有已验证的明确支持。
- 提交前检查有效期；排队期间可能过期，实际 POST 前再查一次。已有远端正式任务的轮询／补下载不因源样片后来过期而停止。
- 复用 requestKey 幂等、submitting／maybe_sent、远端 ID、租约、fence、slotHeld、nodeEpoch 和恢复机制。重复点击同一提交意图不得创建重复任务；同样片以后主动再次生成使用新的明确提交意图。
- 基于样片的正式任务同样是独立任务；成功后物化新的正式素材，不覆盖样片。提交结果不明进入 uncertain，不自动重发。
- 普通溯源连线继续只表示出处；样片转正式的显式来源关系须被 planner 识别并纳入指纹，不能靠放开全部溯源边遍历实现，否则旧素材的消费者会被错误卷入分支。

### 5.3 用量与导出

样片和正式生成按不同本地 taskId 分别记录。基于样片的正式任务计量输入视频时长使用原样片请求的输入视频信息，不把样片自身时长重复算作参考视频时长（S3）。

计价口径以同步后的主项目 `lib/usage-pricing.ts`（版本 `core-usage-pricing-2026-09-30`）为准：
- **公司**：视频仍按秒计，单价是每 5 秒的账单均价（2.5 为 ¥9.45／5 秒，2.0 标准版 ¥2.52／5 秒）；图片按张；GPT 按次。
- **直连方舟**：没有计价，显示「未计价」。
- **时长回退**：画布 `usage.ts` 按节点参数里的 `durationSec` 记秒数，缺失或不大于 0 时回退为 1（`usage.ts:111-113`）。自动时长和编辑任务必须改用产物探测出的实际时长。
- **公司样片**：账单均价对应的是常规正式任务，公司样片（480p）没有对应单价，记为「未计价」，不套用正式任务的均价。
- **边界**：画布只适配主项目的计价接口，不在画布分支改计价规则。

保留实际 token 用量；缺少价格依据时显示“未计价”。自动时长不得回退为虚假的 1 秒成本。提交计数、估算费用、成功任务的实际计费分开表达；失败、补查询、补下载和重复记账不虚增费用，账本失败不触发再提交。

导出 manifest 区分样片、正式产物、普通视频以及来源关系，包含必要的非敏感元信息；下载本地文件不依赖已过期的远端 URL。导出不赋予外部文件继续使用源任务的权限或有效期。
