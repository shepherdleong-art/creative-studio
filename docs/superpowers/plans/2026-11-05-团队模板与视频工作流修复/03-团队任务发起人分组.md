# 03 团队任务发起人分组

**状态：** `ready-for-agent`

**依赖：** 无。

## 目标与代码入口

实现 [规格 §5](../../specs/2026-11-05-团队模板与视频工作流修复-功能方案.md)。入口：`components/team/TeamTasksPanel.tsx`、`app/api/team/tasks/route.ts`、`lib/team-service/tasks.ts`；成员选项来源检查既有团队成员/用户 API 及权限。

现有后端 actorUserId 已在 LIMIT 500 前过滤，优先复用；现有前端文本搜索仅过滤已载入记录，不能作为服务端成员筛选替代品。

## 实施要求

1. 默认按 actorUserId 分组，显示姓名、工号、当前结果任务数、折叠按钮；组按最近任务时间排序，组内沿用原排序。
2. 增加成员选择和分组/平铺切换；成员＋状态组合交给服务端，同名成员、历史停用成员均可区分。
3. 保留搜索、复制排查信息、错误链接；刷新保留当前筛选、视图、折叠状态。明确 500 条截断和组计数口径。

## 验收

- [ ] 默认分组，可折叠，可切回原平铺；两种视图的筛选结果一致。
- [ ] 两位同名成员形成不同组，按 ID 筛选准确。
- [ ] 创建超过 500 条其他人的较新任务后，仍可从成员选项找到并查出低频成员任务。
- [ ] 状态过滤含取消语义不回归；搜索空态、加载失败、刷新和复制详情正常。
- [ ] 员工篡改 actorUserId 查询他人被拒，管理员可按成员查询。
- [ ] 组计数明确是当前结果，不能误称全历史任务数；深浅主题和窄屏正常。

## 测试与完成证据

复用 `scripts/legacy-media-execution.test.ts` 的任务身份/状态列表覆盖，必要时新增独立任务查询测试；`scripts/team-diagnostics.test.ts` 可辅助核对诊断信息回归。UI 浏览器测试覆盖默认视图、切换、折叠与刷新；不要只用源码字符串断言。提供含同名成员与 500 条截断场景的结果记录。
