# 04 视频图片预处理

**状态：** `ready-for-agent`

**依赖：** 无；完成后 05 接手共享视频创建文件。

## 目标与必读

实现 [规格 §7](../../specs/2026-11-05-团队模板与视频工作流修复-功能方案.md)。先读 `docs/reference/公司网关与COS中转.md`、`docs/reference/供应商与队列.md`。

## 代码入口与关键接缝

- `lib/video-job-create.ts`：创建阶段已经对原图做上游大小校验；此处不改，大图根本进不了队列。
- `lib/video-source-reference.ts`、`lib/video-reference-contract.ts`：原图元数据与模型限制。
- `lib/video-queue.ts` 的 `prepareReferenceSubmitRequest`：再次校验后才交付。
- `lib/video-providers/reference-media.ts`、`lib/cos-media.ts`：COS 派生副本与压缩；当前 helper 可能返回仍超限的结果或失败回退原图。
- `lib/company-gateway-tail-frame.ts`、`lib/video-providers/openai-video.ts`：首尾帧交付。团队文件注册、任务取消与派生物清理按调用链复核。
- `lib/creative-canvas/adapters/media-delivery.ts` 也复用 reference-media；改共享函数须读取 `docs/reference/创作画布.md` 并补画布兼容回归，本票不扩展画布产品功能。

## 实施要求

1. 将本机原图保护和上游交付预算分离；复用受限的图片预处理能力，在创建/执行采用一致合同。决定何时物化/缓存派生物，并记录原因；保持源图身份与原始字节。
2. 对可安全解码的大图先生成合法副本，再以实际 MIME/大小/尺寸验证；有界迭代并校验最终输出，不伪造原图 byteSize。
3. 单图参考及首尾帧分别使用正确预算；未达标、损坏、取消、上传失败均在生成 POST 前停止。严格路径不得回退发送不合格原图。
4. 保持其他模型的既有默认处理行为；文件基于 dataRoot，派生物登记/归属正确，日志只含安全指标。

## 验收

- [ ] H3 与 Wan 各一张 11 MiB 以上但在本机保护范围内的真实编码图片，能创建任务且最终提交合规副本。
- [ ] 首尾帧两张均超上游预算时分别处理，角色与顺序正确，原图哈希不变。
- [ ] 小型合规图片无不必要的有损重编码；输出 MIME 与字节/扩展名一致。
- [ ] PNG 透明通道、WebP 转受支持格式（若该入口允许）、损坏图、超像素限制、无法压到预算均有确定行为。
- [ ] 同时覆盖创建预检与执行交付；不能只测压缩 helper。
- [ ] 压缩失败、COS 失败、取消时 mock 生成 POST 次数为零；关闭可选压缩不能放行超限图。
- [ ] 并发/重试不串项目、不修改原图，临时文件可清理，历史任务冻结素材不被替换。

## 测试与完成证据

优先扩展 `scripts/video-reference-job-create.test.ts`、`scripts/video-queue-reference.test.ts`、`scripts/cos-media.test.ts`、`scripts/openai-video-adapter.test.ts`。以真实 sharp 编码的大图验证输出，假 COS 捕获实际上传字节并再次解码、测量大小；不能用短字符串冒充 11 MiB 图片或只断言参数被传入。

测试数据根在临时目录，外网供应商全 mock。向 05 交接统一预处理接口、预算、错误类型和已运行测试；更新 reference 文档中的处理顺序说明。
