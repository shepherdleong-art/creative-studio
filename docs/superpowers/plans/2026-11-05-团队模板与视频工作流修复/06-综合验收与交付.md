# 06 综合验收与交付

**状态：** `ready-for-human`

**依赖：** 01、02、03、05 验收完成，05 已包含 04。

## 目标

验证 [完整规格](../../specs/2026-11-05-团队模板与视频工作流修复-功能方案.md) 的五项用户问题在同一构建中成立，并保留可交接证据。

## 执行

1. 汇总各票命令与结果，核对修改文件/提交或 diff。确认使用的源码版本、服务端运行版本和客户端连接目标；仓库通过不代表生产服务器已更新。
2. 临时 server 数据根准备管理员、两个员工（含已有私人空库/非空库）、已导入未发布模板、已发布历史版本、既有视频及历史队列任务。
3. 用真实登录会话完整走管理员上传发布→员工推荐/搜索/选择。中途切团队版本，验证历史任务和陈旧页面策略。
4. 浏览器与轻客户端验证海报、视频播放/下载和跨账号拒绝；执行发起人默认分组、成员与状态筛选、平铺切换和刷新。
5. 假 COS/供应商联调两模型 × 单图/双图 × 小图/大图；验证上传中/失败阻止提交、角色字段、实际上传字节和历史重试。
6. 跑所改模块定向测试、`npm run check:main-path`、`npm run lint`、`npm run build`。记录既存失败与本轮失败，不能回滚其他人的改动消除失败。
7. 若需真实供应商验证，先核对已有授权，明确数量、输入与成本范围；记录付费任务 ID、实际输出参数和首尾画面，未做就明确标注。未经范围授权不向生产实例补跑任务。

## 完成标准

- [x] 每项验收有实际结果，mock、浏览器、生产现场结论分别标注。
- [x] 模板不依赖手输资源 ID，空私人库不遮挡公共版本，历史私有资源不泄露。
- [x] 既有视频海报可见且仍受鉴权保护；缺图有占位。
- [x] 发起人组/筛选正确，500 条截断不误报全历史计数。
- [x] H3/Wan 单图参考、双图首尾帧自动工作，大图处理后合规，历史任务模式稳定。
- [x] 临时数据、派生物清理符合约定；本机原图和生产数据未被测试改写。
- [x] reference 文档与新行为一致；交付记录列出版本、测试、截图位置、风险和未验收现场项。

交付记录放 `docs/` 日期前缀文件；长日志或截图可放 `outputs/` 并在记录中给出定位。不要把密钥、Cookie、COS 签名或其他账号完整诊断数据写进文档。没有生产部署授权时交付代码和验收结果即可，明确“未部署”，不能把构建成功写成服务器已修复。
