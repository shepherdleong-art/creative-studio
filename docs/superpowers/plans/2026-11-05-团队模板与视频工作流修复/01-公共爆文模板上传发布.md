# 01 公共爆文模板上传发布

**状态：** `ready-for-agent`

**依赖：** 无。

## 目标与必读

实现 [规格 §3](../../specs/2026-11-05-团队模板与视频工作流修复-功能方案.md)：管理员直接上传预览并发布；员工统一读取团队当前版本，不要求用户提供内部 ID。

先读 `docs/reference/详情页智能脚本生成.md`、`docs/adr/0001-轻客户端与服务器统一生产边界.md`。

## 实施要求

1. 设计明确团队当前库/修订的持久化身份与升级方案，不能把“管理员当前个人库”当作长期团队身份。读请求不创建员工空库。
2. 在公共资源页完成上传→预览→发布→当前版本展示，并提供此前导入版本的可视化选择发布。去掉该流程对原“库/修订/条目 ID”手工发布表单的依赖。
3. 原子发布所选修订及条目、切换当前指针；复用内容指纹去重，处理旧版本重导与并发冲突。失败时旧团队版本仍完整可用。
4. 推荐、搜索、详情、生成均选择同一团队版本；保留旧任务快照及已发布旧版读取。私人历史不连带发布；local 行为保持兼容。
5. 更新员工空状态文案与权限，复核团队路由注册和 CSRF。若增加迁移，追加到正确模块并通过共享 gate。

## 验收

- [ ] 管理员只靠文件和界面按钮即可发布，新员工能搜索/选择模板，无需资源 ID。
- [ ] 已有个人空库、个人非空库的员工，与无个人库员工读取相同团队版本。
- [ ] 所选库、修订、条目权限一致；员工 POST/切版本/修改条目均被拒绝。
- [ ] 预览取消、无有效条目、解析/发布失败不改变旧版本；同内容重复发布不产生重复版本。
- [ ] 从非当前历史内容重导可明确激活；并发发布冲突可见。
- [ ] 已导入目标版本可经名称/版本列表发布；多个历史库不自动挑错；私人未发布历史保持不可见。
- [ ] 切换版本后旧任务/断连重试仍使用原快照；陈旧页面选择提交不会被静默替换。
- [ ] local 设置页导入及模板改写行为通过回归。
