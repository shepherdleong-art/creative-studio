## 二、规矩

### 做法

- 按卡号顺序做，一张卡一个提交：`git commit -m "feat(live-mixcut): 卡N 一句话说明"`。不 push，不开新分支，不改 git 历史。
- 每张卡做完先跑「验收」里的命令，全过了才提交。
- 机械改动一律跑 `scripts/live-mixcut-port/` 里的脚本，不要手工逐个文件改。脚本报错就停下报告，不要改脚本去绕过。

### 不许做

- 不改 `lib/batch-production`、`components/batch-production`、`app/api/batch-production` 里的任何文件。唯一的例外是卡 4，把它们恢复成 main。
- `lib/live-mixcut` 不 import `lib/batch-production` 或 `lib/final-edit`，`components/live-mixcut` 不 import `components/batch-production`。
  - 共享能力用 `lib/media-core`、`lib/ffmpeg.ts`、`lib/data-root.ts` 这类共享层。
  - 从批量复制来的界面里，本来就引用了 `components/final-edit`、`components/mixcut` 和 `lib/final-edit/types`，这些保持原样（界面层共享是允许的）。
- 不新增防护逻辑（冻结、版本冲突检查、能力隔离之类）。Codex 已有的原样保留，不删也不加。
- 不改函数名、组件名、类型名，`BatchXxx` 保持原样，方便以后和批量对照同步。
- 不碰 `data/workbench.db`，也不碰 `storage/` 里已有的文件。测试和试跑一律用临时数据根（`CREATIVE_STUDIO_DATA_ROOT` 指到 `mktemp -d` 建的目录）。
- 不调用火山、豆包、GPT 这些外部服务。只有卡 1 的冒烟和卡 12、13 可以调，而且要等用户给了 Key。
- 不改 `package.json`，不加依赖。
- 不写长文档。只在卡 14 写文档，执行记录的写法见第六节。

### 什么时候停下来报告

- 要改清单外的文件，或者卡里写的原文在代码里找不到；
- 批量回归和基线对不上；
- 同一个测试修了两次还不过；
- 外部服务返回的格式和字段跟卡里写的不一样。

报告写四样：卡号、做到哪一步、现象（原样贴报错）、你打算怎么做。

### 约定

- **命名**：
  - 表名、索引、触发器、错误码里的 `batch_` 一律换成 `live_mixcut_`；
  - 接口 `/api/batch-production` 换成 `/api/live-mixcut`，import 路径 `lib/batch-production/` 换成 `lib/live-mixcut/`；
  - 存储目录统一放在 `storage/live-mixcut/` 下，导出目录是 `storage/live-mixcut/exports/<任务导出目录>/成片/`。

  这些脚本都已经替换好了，你新写的代码也照这个来。
- **projectId 的含义**：复制来的代码里到处是 `projectId` 参数和列。在实拍混剪里，它的值是任务 id，指向 `live_mixcut_projects` 表，跟工作台的 `projects` 表没有关系。一个任务只有一个批次，批次有自己的 `batchId`。界面上叫"任务"，代码里叫 project。
- **用量记账**：实拍混剪调配音时传 `projectId: null`，调模型时干脆不传 `projectId`。
- **开关**：只有设了 `CREATIVE_STUDIO_LIVE_MIXCUT_ENABLE=1`，才会建表、起后台任务、开放接口、在导航里显示。

适配器按火山官方文档写（<https://docs.volcengine.com/docs/6561/1631584>）：

- 请求：`POST https://openspeech.bytedance.com/api/v3/auc/bigmodel/recognize/flash`，请求头 `X-Api-Key`、`X-Api-Resource-Id: volc.bigasr.auc_turbo`、`X-Api-Request-Id`、`X-Api-Sequence: -1`。请求体 `{ user: { uid }, audio: { data: base64 }, request: { model_name: 'bigmodel' } }`。
- 判断结果：响应头 `X-Api-Status-Code` 为 `20000000` 算成功；`55000031`（服务繁忙）重试，其余错误码直接报错。
- 返回内容：`result.text` 是台词；`result.utterances[].words[]` 里有 `text`、`start_time`、`end_time`，单位按毫秒处理。

**真实冒烟**：等用户给了 Key 和一条 VO 素材再做，会把这条素材的声音发给火山。
