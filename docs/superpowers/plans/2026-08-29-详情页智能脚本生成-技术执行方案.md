## 2. 上线阻塞项的技术闭环

对应 PRD §14.4 的 6 个问题。**这一节没定死之前不要开始写业务代码。**

### 2.1 高风险证据核验（PRD §14.4.1）

**要求**：数字、材质、认证、功效、绝对化声明必须通过额外证据核验；**禁止同一模型输出自证**。

> **决策：定向二次视觉核验（closed-question re-probe）**

对每条命中高风险类别的候选卖点，发起一次**独立调用**：

1. **输入不同**：只发目标切片 + 前后各一片（而非整页全部切片）
2. **问题形式不同**：封闭问题 —— 「这张图中是否出现了『{候选关键事实}』？若出现，逐字返回包含它的原文行；若未出现，返回 `null`。」
3. **判定在服务端**：**不采信模型返回的 yes/no**，只采信它返回的原文摘录，然后由服务端做字符串匹配：
   - 候选卖点里的**数字**必须逐字出现在摘录中
   - 材质/认证词必须逐字出现
   - 匹配用规范化后的字符串（去空白、全角转半角、统一单位写法）
4. 匹配失败 → 该卖点标记 `evidenceGate: 'failed'`，**排除出可用池，但不阻断其余脚本生成**（PRD §5.3.3）

**为什么这不算自证**：输入、问题形式、判定主体三者都不同，且最终结论由服务端字符串匹配得出，不由模型下结论。

**必须诚实标注的局限**：仍是同一模型家族，不是真正独立的证据源。因此：

- 代码注释与 UI 文案都不得出现「逐字核真」「事实已验证」这类表述，只能说「已通过二次证据检查」
- 试运行阶段按 PRD §10.7 **100% 人工复核**自动采用的卖点
- 数字/材质/认证/功效/绝对化声明的**错误自动采用必须为 0**

**被拒选项**：
- 引入本地 OCR（tesseract.js / paddleocr）—— 新增重依赖，中文 OCR 质量存疑，且与「本地优先、免安装包体积」约束冲突。**Not now**，但接口留出适配位（见 §6.3）。
- 只靠模型自报 `confidence` —— PRD §4.11 明确禁止。

### 2.2 核心脚本迁移（PRD §14.4.2）

> **决策：新建核心表，`script_drafts` 保留只读兼容，不做数据迁移**

- 新流程写入新表 `project_scripts` / `project_script_revisions`
- `script_drafts` 的历史行**不批量改写、不静默转换**（PRD §9.7 末条）
- 下游读取路径改造成「新表 ∪ 旧表」的联合视图（见 §7）
- 批量侧 `batch_scripts` 的同步源从「只认 `script_drafts`」扩展为「两个来源都认」，**不改它的表结构**

**被拒选项**：扩展 `script_drafts` 加列 —— 无法表达稳定身份与父子关系，且会把新旧语义混在一张表里。

### 2.3 下游闸门收敛（PRD §14.4.3）

见 §7 完整方案。核心语义：

> 空 `shotSetId` = **项目级脚本**，在同一 `projectId` 下可被列出。  
> 非空 `shotSetId` = 历史脚本，保持原有**更窄**可见范围，不扩大。  
> 实际使用时才创建绑定目标 `shotSetId` 的快照。

### 2.4 持久化任务恢复（PRD §14.4.4）

> **决策：照抄 `lib/batch-production/scheduler.ts` 的租约模式**

批量侧已有一套经过实战的「原子领取 + 有限租约 + 控制态感知的过期/启动恢复 + 失败重试」实现（`docs/reference/批量生产模块.md` Phase C）。不要重新发明。

- 任务表带 `leaseUntil` / `attemptCount` / `requestKey`
- 进程启动时把超租约的 `running` 恢复为 `queued`
- `requestKey` 保证幂等（双击提交、网络重放只创建一个供应商任务）
- 接入 `lib/shutdown.ts` 的停机编排，所有外部调用传 `AbortSignal`

### 2.5 资源保护值校准（PRD §14.4.5）

`60M` 源像素与 `150MB` 解码缓冲**只是初始值**，必须可配置：

- 放 `lib/script-studio/limits.ts`，从环境变量读取并带默认值
- 每次触发上限都写日志（含实际值与阈值），供试运行后校准
- **不得**把这两个数字写死在业务逻辑里

### 2.6 用量身份兼容（PRD §14.4.6）

**开工第一天就要做的实测**（10 分钟）：

```
1. 在设置页配置一个公司供应商（非种子行）
2. 跑一次现有的脚本生成
3. 查 usage ledger 是否有记录
4. 若无记录，打印该供应商行的 type / model 字段
```

若 `type` 为空导致 `snapshotProvider` 返回 `null`（`lib/usage-ledger.ts:262`），修复方向：

- 在 `lib/providers/seed.ts` 的补种逻辑里为公司供应商行补齐 `type`
- 或在 `usage-llm.ts:78` 的 `createProviderSnapshot` 里给 `providerType` 一个基于 `apiStyle` 的兜底
- **两者都做**：补种修存量，兜底防新增

**验收**：视觉提取与文本生成两个阶段的每次调用都能在 usage ledger 里查到，`providerId` 不为空。

## 3. 数据层

### 3.1 迁移流的选择

> **决策：新建独立模块 `lib/script-studio/`，自带 `{version, sql}` 迁移流**

**理由**：`AGENTS.md` 明确写着「不许把批量复杂迁移塞回**会吞掉错误**的旧 core runner」。`lib/db.ts:331-333` 的 core runner 是：

```ts
for (const sql of CORE_DB_MIGRATIONS) {
  try { db.exec(sql); } catch { /* Column already exists */ }
}
```

本模块要建 8 张表、带外键与索引，任何一条静默失败都会造成难以排查的运行时错误。

**照抄 `lib/batch-production/schema.ts` 的形状**：

```ts
export interface ScriptStudioMigration { version: number; sql: string }
export const SCRIPT_STUDIO_MIGRATIONS: ReadonlyArray<ScriptStudioMigration> = [ ... ];
```

并照抄 `lib/batch-production/readiness.ts` 走 `lib/schema-upgrade/gate.ts` 的共享 gate（备份 / 跨进程锁 / 审计）。

**红线**：迁移只能追加，不许修改已发布条目。

**注**：本模块首版只有 `CREATE TABLE IF NOT EXISTS`，无破坏性操作，理论上备份的必要性低于批量侧。但仍走同一 gate，理由是保持模式一致、后续追加迁移时不需要临时补 gate。

### 3.3 不变量

写进代码注释，并由测试保证：

1. `project_script_revisions` **只 INSERT，永不 UPDATE 内容字段**
2. 切换历史版本 = 只改 `project_scripts.currentRevisionId`，**不复制内容、不新增版本行**
3. 人工编辑 = **新增**一条 `origin='manual_edit'` 的版本，不覆盖
4. `script_studio_selling_points` 随修订不可变；用户编辑卖点 → **新建修订**，旧修订保持可读
5. **不存在项目级唯一「采用脚本」约束**（PRD §10.4）——测试要显式断言这一点
6. 下游已创建的快照不随上游 `currentRevisionId` 变化

## 5. 编排层

### 5.1 阶段定义

首次生成（PRD §5.3.1）：

| seq | stage | 说明 |
|---|---|---|
| 1 | `input_check` | 整理输入与资源预检 |
| 2 | `read_pages` | 读取详情页图片、切片 |
| 3 | `extract` | 提取、归并、筛选卖点 |
| 4 | `evidence_gate` | 结构门禁 + 高风险二次核验 |
| 5 | `save_library` | 保存卖点库修订 |
| 6 | `plan` | 规划方向、选择模板 |
| 7 | `generate` | 生成 N 条脚本 |
| 8 | `validate` | 时长/结构/事实/重复度检查 |

复用生成跳过 2、3、4，`read_pages` 换成 `load_library`。

### 5.2 幂等

- `requestKey` = `hash(projectId + sourceSetId|libraryRevisionId + targetDuration + count + creativeBrief)`
- `script_studio_tasks` 上有 `UNIQUE(projectId, requestKey)`
- 重复提交返回既有任务，**不创建第二个**、不重复计费

### 5.3 恢复

- 进程启动时（`instrumentation.ts` 挂钩，参照批量侧做法）把 `status='running' AND leaseUntil < now` 的任务恢复为 `queued`
- 已完成的阶段不重跑（阶段表是断点）
- **重试不得重新读取未变化的详情页**（PRD §5.3.5）：`extract` 阶段成功后其产物落库，重试从 `evidence_gate` 起

### 5.4 部分成功

- `generate` 阶段逐条生成，每条独立记成功/失败
- 至少一条成功 → `status='partial'`，前端进结果页并显示缺口
- 「重试缺失条目」创建子任务，`parentTaskId` 指向原任务，结果卡标「补跑」（PRD §5.3.6）

### 5.5 停机

所有外部调用与 ffmpeg/sharp 调用接 `AbortSignal`，向 `lib/shutdown.ts` 注册。被打断的 `running` 任务退回 `queued` 走租约恢复。

### 6.3 二次核验适配器

`adapters/reprobe.ts` 的接口设计成可替换，为将来接真正独立的证据源留位：

```ts
export interface EvidenceReprobe {
  readonly kind: 'vision_closed_question' | 'ocr';
  verify(input: {
    claim: string;              // 待核验的关键事实
```

## 7. 下游闸门收敛

这是 PRD 点名的**上线阻塞**。

### 7.1 目标语义

```
空 shotSetId  → 项目级脚本，同一 projectId 下可见
非空 shotSetId → 历史脚本，保持原有更窄可见范围（不扩大）
实际使用时     → 创建绑定目标 shotSetId 的脚本快照
```

### 7.2 改造步骤

**第一步：消除内联重复判断**

把 §1.3 表里的 4、5、6 三处内联判断改为调用统一函数。新增（放 `lib/media-core/`，两个模块都要用）：

```ts
// lib/media-core/script-visibility.ts
export interface ScriptVisibilityInput {
  shotSetId: string | null | undefined;
  requestedShotSetId?: string | null;
  validShotSetIds: ReadonlySet<string>;
}
export function isScriptVisibleInContext(input: ScriptVisibilityInput): boolean;
```

规则：

- `shotSetId` 为空 → **可见**（项目级）
- `shotSetId` 非空且不在 `validShotSetIds` → 不可见（组已删）
- `shotSetId` 非空且 `requestedShotSetId` 非空且不相等 → 不可见（保持原隔离）
- 其余 → 可见

**第二步：`isUsableMixcutScriptDraft` 去掉 `shotSetId` 非空要求**

`lib/media-core/script-draft-usable.ts:7` 的 `value.shotSetId.length > 0` 删除。该函数只负责「内容结构是否可用」，**可见性交给 `isScriptVisibleInContext`**。职责分离后两处都变清楚。

> ⚠️ 改这个函数会同时影响 `mixcut-context.ts` 和 `script-catalog.ts`，必须两处都补上可见性调用，否则会**放宽**历史脚本的隔离范围。这是本次改造最容易出事的一步。

**第三步：六处读取路径统一**

| 位置 | 改法 |
|---|---|
| `lib/final-edit/mixcut-context.ts:219-221` | 结构检查 + `isScriptVisibleInContext` |
| `lib/batch-production/script-catalog.ts:80-85` | 同上 |
| `app/api/projects/[id]/final-edit/bootstrap/route.ts:22` | 删内联，改调共享函数 |
| `lib/final-edit/workspace.ts:434,437` | 删内联，改调共享函数；`script_shot_set_mismatch` 只在**历史带组脚本**上抛 |
