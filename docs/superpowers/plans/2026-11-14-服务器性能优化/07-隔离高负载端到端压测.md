## 功能与失败

1. 192 个常规分析全部完成，模拟提交共 192 次；8 个真实代理完成，远程请求峰值 4，没有超过配置 4。通用任务在分析请求等待时已被领取；媒体位满时延期，后续资源释放后完成。
2. 暂停的 2 个技术分析在观察窗内没有领取，继续后完成；正式停止后释放迟到模拟回包，任务取消、分析指针未发布（停止收敛 304.2ms）。
3. 强制结束后同根重启，16 个未发送技术分析恢复完成；同一已发分析却再次提交，总请求 2 次，旧 operation unknown、新 operation maybe_sent，见 **08 P1**。本轮未发重试 API，未清除 unknown/费用/预留。
4. 0、1 号员工明确导航到 `/team/tasks` 后，15 秒内均未显示 25 行；成功任务页打开样本为 0，不填可见时延 p50/p95。后台同类 API 仍可响应，不能用接口时延替代页面就绪时间。两次失败均保留 trace、HAR 与等待画面，见 **09**。
5. `full-03` 冷进入在 12 秒目标正文帧看门狗内未出帧；10.5 秒内出现 400 次/100 个计划的 arrangement 请求，完整统计见 `cold-open-analysis.json`。这不是解码器根因的确认。
6. SQLite integrity_check 为 ok，4,000 条完整历史行的前后 SHA-256 一致；权限隔离检查通过。tasks/workspace 单飞的逐页面观测在原始结果中，未将未覆盖的详情请求记为单飞。

浏览器使用路由网络守卫，HTTP 缓存被禁用；任务页是文档冷导航，不能据此认定普通侧栏 SPA 导航也同样超时。媒体为 384×512 预览与 160×160 分析合成视频，未覆盖大码率 1080p/4K、真实供应商、TTS/正式成片渲染/ZIP 全链路，也不构成生产服务器容量 SLA。
