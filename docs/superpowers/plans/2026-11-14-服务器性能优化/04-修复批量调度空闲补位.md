## 验收

## Comments

### 变更

- `lib/batch-production/runner.ts`：调度从“整轮 `Promise.all` + `sleep(intervalMs)`”改为每个执行位独立持续循环。空闲位可被新的进程内唤醒信号 `wakeBatchScheduler()` 立即唤醒；没有唤醒时按 `idlePollMs`（默认 `min(调度间隔, 500ms)`）做有界定时检查，不再等其他 lane 的长任务整轮结束才补位。
- 延期（`llm_execution_deferred` / `media_resource_deferred`）与租约丢失改为按原因短时退避：本地媒体/名额默认 100ms，统一准入至少 250ms，租约丢失至少 100ms。退避期内通过 `claimNextTask` 新增的可选 `excludeTaskIds` 跳过该任务，让同 lane 的其他合格任务先推进；退避到期或入队唤醒后再重试，不做忙循环。
- `lib/batch-production/bootstrap.ts`：`ensureBatchSchedulerStarted` 在已有运行实例时调用唤醒，既有写 API 的入队路径自动生效；`export-orchestrator.ts` / `output-editing.ts` 的默认唤醒也随之一并生效，调用方无需改动。
- 保留进程内单例、原子领取、analysis/general lane 互斥、并发上限、租约/心跳/过期恢复、暂停/取消/停止/停机排空与重启恢复语义；未提高任何并发数。`runPendingOnce` 与 `startBatchScheduler` 的既有默认测试语义保持不变，新增参数（`idlePollMs`、`deferBackoffMs`）均为可选。

### 残留风险

- 退避表是进程内短时状态：重启后不会继承旧进程的退避，首轮会按正常顺序重新尝试一次，符合既有重启恢复语义。
- 未走 `ensureBatchSchedulerStarted` 的旁路直接写库没有唤醒，最多等待一次空闲轮询（默认 500ms）；现有写 API 都经过该接缝。
- 准入退避下限按保守值 250ms；真实准入恢复更慢时会多几次无副作用的延期检查（延期不产生付费提交）。
- 本轮只做本机隔离探针与既有回归，未在真实多用户服务上压测。

### 代码审查修复（B 组）

- 退避表淘汰方向修正：超过 64 条时淘汰 `retryAt` **最大**（最远到期）的条目，保留最早到期的。旧实现淘汰最早到期的条目，等于把本应继续退避的任务立刻放回候选，高并发下会放大 claim+defer 写事务。
- 退避下限按资源类型分离：媒体类延期至少 1000ms（原 100ms），准入类至少 500ms（原 250ms），租约丢失仍为 100ms；仍可被入队/资源释放的 `wakeBatchScheduler()` 立即打断，因此不是固定等待。额度饱和时单槽 claim+defer 频率从约 10 次/秒降到准入 ≤2 次/秒、媒体 ≤1 次/秒。
- 空闲轮询默认值从 500ms 改为调度间隔 `intervalMs`（默认 2000ms）；显式传 `idlePollMs` 的调用方语义不变。有延期任务时等待改为 `min(idlePollMs, 距最早退避到期)`，`idlePollMs` 始终是两次领取检查的上界，未到期任务继续由 `excludeTaskIds` 跳过，不做忙循环。
- 只读 GET 不再唤醒执行位：`ensureBatchSchedulerStarted(db?, { wake?: boolean })` 默认 `wake: true` 保持写路径行为；`batches/[id]/workspace` 与 `batches/[id]/tasks` 两个只读 GET 传 `{ wake: false }`，只保证调度器已启动。全仓调用点已逐一核对，入队/控制/重试/分析/代理/语义评分/重分配等写路径继续唤醒。
- 测试：`scripts/batch-runner.test.ts` 中“准入延期必须按原因退避”的下限断言从 200ms 提高到 400ms（实际下限 500ms，留抖动余量）；场景 5 的租约参数从 20ms/80ms 放大到 1000ms/1500ms——原值在共享/高负载机器上会让租约在 executor 启动前过期，执行器对已 abort 的 signal 追加监听不会收到事件，形成既有假挂起（基线同样可复现），放大后保留“心跳晚于租约到期”的意图。**未修改执行器/租约恢复逻辑。**
- 回归：`batch-runner`、`batch-scheduler`、`media-resource-gate`、`execution-admission`、`execution-admission-contention`、`team-acceptance-fairness` 通过；`npx tsc --noEmit --incremental false`、改动文件 ESLint、`npm run check:main-path` 通过。
- 残留风险：退避表仍是进程内状态，重启后首轮按正常顺序重试一次；未走 `ensureBatchSchedulerStarted` 的旁路直接写库最多等待一次空闲轮询（现在默认 2s，写 API 均经过该接缝）；只读 GET 关闭唤醒后，若某写路径漏接唤醒，补位延迟上限为 2s 而非 500ms。
