### 代码审查修复（B 组）

- `cover-contract.ts` 的预加载改为**按键命中才生效**：`outputVersions` / `assetFingerprints` / `poolColors` / `analysisColors` / `frozenTitleRows` 用 `has(key)` 判断，命中即使用（包括值为 `null` 的“确认无行”），缺 key 一律回落原来的逐条查询，不再因预加载不完整而抛错或默认关闭快照。`analysisColorsUnavailable` 只在批次预加载遇到旧库缺 `analysis.colorJson` 列时生效。
- `CoverContractOutputVersion` 增加已解析的 `arrangement` 对象；`resolveCoverContract` / `resolveFullRenderContract` 优先复用它（仍保留 `frozenArrangementJson` 参数与逐条查询回落），`FormalArtifactPreload` 也改传已解析 arrangement（`arrangements`），每卡不再重复 3–4 次 `JSON.parse`。`resolveFullRenderContract` 内联的“查缓存→resolve→compute→写缓存”改为调用 `resolveCoverContractHash(db, id, undefined, preload)`，哈希结果不变。
- `batch-workspace.ts` 的分析色彩预加载失败按作用域处理：只有 `no such column: colorJson` 才标记 `analysisColorsUnavailable`；`SQLITE_BUSY`/锁竞争/变量数等异常保持 `analysisColors=undefined`，回到逐卡查询与逐卡失败语义。预加载映射为所有缺池色素材写入 `null`（确认无分析行），避免缺 key 误触发逐卡查询。
- 冻结封面标题所需列（`s.coverTitleJson`、`s.sourceScriptId`）并入主 plans 查询，用已解析的 `parsedPlans` 构建 `frozenTitleRows`，删除第二条三表 JOIN。
- 成功整片尝试只查当前输出版本（`targetId IN (当前 version ids)`），历史版本的 `resultJson` 不再搬进内存；`FormalArtifactPreload` 按 `targetId` 分组为 `succeededRenderAttemptsByTarget`（保持 `finishedAt DESC, id DESC` 行序），`isFormalArtifactOutdated` 只查本卡数组，不再每卡扫描整批。匹配视频+封面双指纹的第一条、损坏 JSON 保守判过期语义不变。
- 同源分组增加按映射插入顺序的 `Map<assetId, ordinal>`（`prepareSourceConflictPreload`）：每卡只遍历自己的 clip assetId，按 ordinal 排序后分组，组顺序与组内 assetIds 顺序与旧逐卡查询一致。
- 池色预加载为所有引用素材补齐 `null` 键（本次修复中发现：只做“缺 key 回落查询”会让池外封面每卡多两次 SQL，100 卡从 16 涨到 216；补齐后回到 16）。
- 按协调者查漏补修：`coverTaskRows` / `fullRenderTaskRows` 同样加 `t.targetId IN (当前版本 ids)`（复用 `currentVersionIds`），封面任务的 `succeededAttemptId` 子查询也只对可见卡的当前版本执行；行序与选卡语义不变。两个 `currentVersionIds` 声明合并为一处。
- 测试结果：`batch-workspace`（1/25/100 卡均 15 条 SQL、池外封面 1/100 卡均 16 条；100 卡中位 18.6ms，仅看门狗阈值 2000ms）、`batch-cover-contract`、`batch-export`、`batch-export-preflight`、`batch-export-concurrency`、`batch-export-identity-freeze`、`batch-output-export-freshness`、`batch-output-clip-edit`、`batch-review-{repeat-render,subtitle-edit,video-trim,video-usage}` 全部通过；`npx tsc --noEmit --incremental false`、改动文件 ESLint、`npm run check:main-path` 通过。工作区 SQL 条数断言与“不随卡片增长”断言保持严格，只放宽耗时阈值。
- 残留风险：预加载把引用素材的指纹/色彩/同源键一次性放入内存，随引用素材数增长；核心 schema 的 `batch_asset_analysis` 仍无 `colorJson` 列，池外封面在没有该列的库上保持 fail-closed（与审查前一致）；完整渲染契约哈希的 CPU 开销仍按卡发生，未引入新缓存层。
