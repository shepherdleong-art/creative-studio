# 06 优化批量工作区聚合刷新

**状态：** `ready-for-agent`  
**依赖：** 03、04、05  
**规格：** [服务器性能优化](../../specs/2026-11-14-服务器性能优化-功能方案.md)

## 修改入口

- `lib/batch-production/batch-workspace.ts`、`cover-contract.ts`、`formal-artifact-freshness.ts`、相关任务查询。
- `components/batch-production/BatchPreparationPanel.tsx` 的 tasks/workspace 刷新与调用者。
- 先读批量模块参考，以及 2026-09-25 批量统一审片确认版 PRD/执行文档；保持冻结 v14 交互。

## 验收

以批次批量取数、复用同请求契约；100 卡工作区工程目标 ≤100 条 SQL、p50下降至少60%。同类轮询最多一个在途，旧批次响应被忽略；活跃可见页面约3秒时效及编辑后即时刷新不退化。带历史产物时，封面契约、审核失效、同源提醒、正式产物新鲜度和导出资格保持一致。参照规格实施决定 7、9。

## 测试

扩展 `scripts/batch-workspace.test.ts`，回归审片、导出、封面契约及 `batch-preview-seek.playwright.test.mjs`、`mixcut-preview-initial-frame.playwright.test.mjs`。最终运行 README 统一检查，并做“批量运行中查看/拖动预览及打开任务列表”的组合验证；证据区分模拟供应商与真实媒体处理。

## Comments

**变更**

- `lib/batch-production/batch-workspace.ts`：`getBatchWorkspace` 改为按批次集中取数——计划/版本/冻结默认值、素材池时长+色彩+指纹、非池素材指纹、冻结封面标题、正式产物、封面任务、整片任务、成功尝试、口播任务、同源原图键各一次查询，再在内存里按原有规则选每卡事实。100 卡 SQL 从 1507 固定到 14（带历史产物/任务的测试夹具为 16），不随卡片数增长。
- `cover-contract.ts`：`resolveCoverContract` / `resolveFullRenderContract` / 两个 hash 函数增加**可选** `CoverContractPreload`；不传时逐条查询路径与哈希完全不变。同次请求内复用封面契约哈希，完整渲染契约不再重复解析封面。
- `formal-artifact-freshness.ts`：`isFormalArtifactOutdated` 增加可选预加载（成功尝试按 `finishedAt DESC, id DESC`、当前完整契约哈希、当前 arrangement）；默认路径不变，证据不足仍保守判过期。导出编排继续走默认路径。
- `cover-title.ts`：抽出 `parseFrozenCoverTitleRow`，逐条查询与批次预加载共用同一份冻结配置解析。
- `source-conflicts.ts`：`batchSourceReview` 可接收批次级预计算的 `resolveModule4AssetGroupKeys` 并按卡过滤；权威 key、组内 assetIds 与警告文案保持不变。
- 前端 `components/batch-production/BatchPreparationPanel.tsx` + 新增 `components/batch-production/workspace-refresh.ts`：tasks/workspace 各一个单飞协调器，同类请求最多一个在途，后到请求合并为尾随刷新；每个请求记录 batchId/generation，响应回来核对当前活动批次，切批次旧响应丢弃；页面隐藏暂停 3 秒轮询，恢复可见立即刷新一次；编辑/重试/发布后的即时刷新调用点全部保留。
- 未改权限/可见性、冻结输入、审核规则、渲染参数、数据库迁移、工作区返回形状或 UI 外观。

**残留风险**

- 数字来自本机合成数据 + 临时 SQLite，不代表生产端到端 SLA；工作区仍有每卡两次契约哈希的 CPU 开销（封面已复用，完整渲染哈希不可省），100 卡约 7 ms 量级。
- 预加载把批次引用的素材指纹、池色彩与同源键一次性放入内存，占用随引用素材数增长（不随卡片数增加查询次数）。
- 前端单飞只覆盖 tasks/workspace 两类请求；`loadBatchDetail` 等其它请求未纳入。
- 面板级“批量运行中拖动预览/打开任务列表”的真实浏览器验收未通过既有测试定位器验证，建议在具备完整构建依赖的机器上按文件头补跑。
- `batch-output-generation-ui-contract.test.mjs`、`batch-export-downloads-route.test.ts` 在集成分支基线即失败；本次未修改相关文件，也未借它们声称通过。
