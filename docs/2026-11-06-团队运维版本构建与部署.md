1. standalone 的 distribution 重导出路径越界、forbidden-paths 依赖 cwd：构建前修复并有打包回归，包含于源码提交 `390622d`。
2. PowerShell `Get-TeamBootstrapNode` 错误地返回参数和路径数组，调用时不是可执行路径：修复为返回单个路径并加真实 PowerShell 回归；已同步至可变 `deployment/service/common.ps1`。不可变 release 包不改写，因此此主机脚本补丁不包含在上述构建提交内。
3. 老版 `8a5dc544` 的 script-studio v13 只创建 `idx_ssvl_team`，本次代码的 v13 却创建 `script_studio_team_publications`。线上已有 v13 记录，启动跳过建表而 fail closed。独立副本复现后，通过共享升级锁、已验证备份、审计和事务执行缺失的 CREATE TABLE；保留迁移记录及既有索引，并将**原来已经公开**的 `__team__` 爆文库指针迁到新表，私人目录不发布。副本启动完整到 ready 后才在生产执行同样修复。
4. 旧 WinSW 收到应用 HTTP 停机后 wrapper 未退出，SCM 仍显示 Running；其日志记录 SCM access denied。按确切服务路径核对后，先停 Caddy，再停 App，再按相反顺序启动。
5. 维护恢复 helper 先启动维护实例、后清数据库标志，而 runtime 只在启动读取该标志，导致 ready 不刷新；本次在清标志后执行受控重启，并用真实 runTeamRelease 续跑原操作至 completed。
