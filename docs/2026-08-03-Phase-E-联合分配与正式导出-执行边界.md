# Phase E 执行边界：联合分配与正式导出

> 日期：2026-08-03
> 分支：`mixcut01`
> 基线：`66ea5f1 feat: complete batch mixcut phase D media preparation`

## 1. 完成定义

Phase E 把已冻结的批次输入变成可检查、可恢复、不覆盖历史的批量成片：

1. 一次读取全部脚本快照、份数、素材池、分析版本、LUT 快照和人工决定，执行真正的全批联合分配。
2. 每张 `Output Plan` 卡片只产生自己的候选 `Output Version`；失败重试不增加卡片，单条重分配不改动其他计划。
3. 正式 renderer 只读指纹一致的原片和批次冻结 LUT，复用 Phase D `ColorPipeline`，不读代理。
4. 渲染进入 Phase C 的同一套持久调度器，使用真实 FFmpeg `out_time`、`AbortSignal`、有限租约和暂停／停止语义。
5. 渲染候选先在受控中间目录生成并验证；只有正式发布成功才追加 `Artifact` 并更新当前成片指向。
6. 工作区从 SQLite 聚合批次阶段和卡片状态，提供筛选、历史、重试、单条重分配和选中导出，不从最后一条任务行猜测状态。

## 2. 联合分配合同

`BatchAllocator` 是纯计算深 Module，不读 SQLite、文件、代理或网络。

- `allocateBatch(frozenInput)` 一次看到全部计划，不是对单条 matcher 循环 N 次。
- `reallocateOutput(frozenInput, currentAllocation, targetPlanId, reason)` 把其他计划视为固定占用。
- 硬约束顺序：项目／版本谱系 → 合法区间 → 排除 → 用户锁定／手工替换 → 时长与时间线合法性。
- 质量顺序：语义与开场正确 → 新素材区间 → 新素材／顺序 → 使用次数平衡 → 封面／音乐差异。
- 素材不足时先换区间，再允许局部重叠、重复开场或语义降级，并逐项记录原因。
- 锁定与排除／离线／内容变化冲突时，只阻塞受影响计划，不自动解锁。
- 相同冻结输入、`ruleVersion` 和 `seed` 必须得到相同摘要。

分配结果只保存素材身份、原片区间、时间线区间、冻结色彩身份、封面与诊断；不保存任意文件绝对路径或代理路径。

## 3. 口播与字幕边界

Phase E 不调用真实 AI／TTS／公司媒体网关，但不得把口播和字幕从正式导出模型中删除。

- arrangement 必须保留 narration 与 subtitle seam，支持消费已指纹核验的本地音频和已对齐句段。
- 没有真实音频时可生成标记为 `silent_placeholder` 的本地视觉候选，用于分配、渲染和 UI 验证；不得把它标记为“口播已完成”。
- 正式发布动作必须知道 narration 是否 `productionReady`；若产品策略要求口播，静音候选只能显示“需处理”，不能被无警告地选入正式导出。
- 测试用本地合成音频与确定性 timing Adapter 证明正式 seam；真实供应商验收保留到 Phase F 或后续单独授权。

## 4. 渲染与发布合同

- 输出预设：3:4 `1080×1440`、9:16 `1080×1920`、16:9 `1920×1080`，24fps，H.264 `yuv420p`，AAC 48kHz。
- 每个 clip 重新解析项目素材来源并校验完整 SHA-256；LUT 重新校验冻结指纹并经 `buildColorFilterFragments` 生成 filter。
- FFmpeg 输出先写任务专属临时文件，完成后用 ffprobe 检查宽高、fps、时长和容器，再原子发布。
- Abort、租约丢失、暂停、停止、失败、验证不通过都只清理本任务的临时文件，不删除历史正式产物。
- 每个批次拥有独立目录；文件名包含 `projects.productCode`、上海日期、脚本稳定身份、计划序号、成片版本和导出序号，视频与封面使用同一主文件名。
- 每次成功发布追加 video／cover artifact，永不覆盖旧路径；只有完成实体验证和数据库登记后才切换 `currentArtifactId`。
- 设计中必须把渲染中间候选与正式发布区分开，不将零字节预留文件暴露为成片。

## 5. 工作区与 API

工作区固定读取五阶段事实：准备素材 → 分析素材 → 准备文案 → 联合分配 → 批量导出。

卡片状态是聚合结果，不直接等于某条任务状态：

- `completed`：有已验证当前正式视频产物，且无必须显示的提醒。
- `needs_attention`：有差异提醒／锁定冲突／新版失败但旧产物仍可用／口播未达正式条件。
- `processing`／`waiting`／`paused`：由当前版本的持久任务和批次期望状态推导。
- `retryable_failed`：没有可用正式产物，当前必需任务失败且可重试。
- `stopped`：没有可用产物且用户已停止未完成链路。

所有 route 继续经 readiness gate，使用 `projectId + batchId + version/plan`所有权验证、`Cache-Control: no-store` 和统一 400／404／409／503 语义。浏览器不接受或返回任意绝对路径。

## 6. 验收门禁

1. 纯逻辑：精确 N 张卡、确定性、差异事实、素材不足降级、锁定／排除冲突、单条重分配只增加目标版本。
2. 数据库：v16 真实结构升级、迁移幂等、回滚、外键／索引、旧项目数据不变，重试不增加计划。
3. 调度：仍只有一套 batch scheduler；渲染原子领取、租约、恢复、暂停／停止／重试不发布迟到结果。
4. 本机真实媒体：三种比例逐一通过 ffprobe 宽高、fps、时长、音轨、帧面和指纹验证；原片／LUT hash 前后不变。
5. 发布：重复导出不覆盖，失败不更新当前成片，视频／封面配对，路径越界／符号链接全部拒绝。
6. API／UI：刷新恢复真实卡片状态，旧成片不被新版失败隐藏，选中导出跳过无效项并说明原因，浏览器 Playwright 覆盖卡片／重分配／重试／导出。
7. 回归：单条精准混剪、模块 1–4、Phase A–D 专项测试、TypeScript、lint、build 和全部非 Playwright 测试通过。

## 7. 明确不做

- 不调用真实 AI、TTS、腾讯云、媒体网关或公司 LiteLLM。
- 不实施 Phase F 供应商旁路或 Phase G Electron／安装包。
- 不引入第二套队列、`mixcut_sessions` 或平行正式产物表。
- 不使用代理作为正式渲染源，不修改／删除原片、用户原始 LUT 或历史正式产物。
- 不修改已发布 migration v1–v15，不混入本地 Sol + Luna 配置和 Phase 0.3 用户文档。
- 不 push；只在 Phase E 所有门禁通过并完成独立 review 后由 Sol 本地提交。
