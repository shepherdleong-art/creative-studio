# 实拍重组审片启动 Windows 验收

状态：Windows 源码与新免安装 QA 的审片启动闭环通过；整个功能仍按完整接管计划推进。本阶段只用隔离合成工程，供应商请求为 0。

## 实现与保护

- 审片服务端 JPEG 按绑定 ID 和已发布版本读取不可变受管副本。首次导入识别精确 `import:<绑定ID>`，后续版本要求成功渲染任务，不回退到另一版封面。
- `connect <数据根>` 显式注册当前用户的独立协议；协议名包含数据根真实路径摘要。固定应用、Node、数据根与 Electron 用户目录，URI 只带成片、版本和审片身份。`disconnect` 校验归属后删除，桌面未运行也可使用。
- URI 严格验证、同名不同归属拒绝覆盖、实例/数据身份复核；无响应或超时不当作服务已停止。只有状态缺失或明确拒绝连接才进入冷启动。
- 复用 Windows PS 启动脚本，免安装带 `-Portable`，保留 manifest、运行时与 sidecar 流程。同数据根的请求串行，桌面实际 `loadURL` 完成后写原子回执；缺回执、失败或旧实例回执均不报告成功。
- sidecar 日志和运行状态改用 `CREATIVE_STUDIO_DATA_ROOT`；自定义数据根无记录时不按端口兜底停止其他实例。停机只允许受控应用脚本目录。

## 真机测试发现与修复

测试入口 `scripts/reassembled-review.desktop.test.mjs`，夹具为 `reassembled-P1-中文 空格-ubAViY`；真实图片/视频供应商禁用，后台制作调度关闭。测试按配置身份停止自身服务并解除自身协议，保留每次运行证据目录。

1. 第一轮 `desktop-source.log` 在 connect 回读校验失败。最小复现：ASCII 临时路径通过，中文空格路径失败；临时注册表探针显示 UTF-8 解码不匹配且含替换字符，GB18030 解码匹配。说明写入正确，错误在读取 `reg.exe` 的系统编码输出。改用 .NET Registry 读取 Unicode 原值，显式 UTF-8 输出，参数通过环境传递；不硬编码当前机器的代码页。中文回归通过，失败遗留的隔离协议已按数据身份清理。
2. 第二轮 `desktop-source-retry.log` 注册成功，但 JPEG HTTP 返回 404。真实首次交付记录使用 `import:<id>`，原 helper 错把首次交付限定成 jobId 为空。把单测改为真实导入结构后稳定复现，再修正精确导入标识分支；单测通过，等待新构建后重跑原实际 HTTP 场景。

上述失败均不计作闭环通过。当时仍待实际 HTTP 解码、热编辑器、OS 协议冷启动、重复打开及免安装对应验收；最终结果见下节。浏览器自身的外部协议确认与 Windows OS 协议分发是不同证据。

3. 初次冷启动没有处理器成功状态；补充不含 URI/token 的本地错误记录后确认启动子进程退出 0、日志为空。最小 PowerShell 命令同样在 `detached=true` 时退出 0 且不执行，非 detached 正常输出，见 `powershell-spawn-probe.mjs`。取消 detached 后可以实际启动。
4. 重复验收暴露 GUI 程序调用提前返回、代理提前清理，以及助手结束导致关联 PowerShell 无法执行 finally 的生命周期问题。最终协议注册到隐藏的固定参数 `reassembled-launch.ps1`；Node 保持启动子进程引用，启动脚本以 `Start-Process -PassThru` 和 `WaitForExit` 等待 Electron 后清理代理。加入代理健康与退出状态清理强制断言。先前仅导航成功的 `9Jv9Oh` 结果不作为完整生命周期结论，收尾超时记录保留。
