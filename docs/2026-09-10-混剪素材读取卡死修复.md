# 混剪素材读取卡死

现场为项目「20260910-D店-PS515-AI种草-PUIKIN」。桌面服务健康检查和供应商 API 正常，混剪历史列表约 0.3 秒返回，但 `/final-edit/context` 超过 65 秒仍未返回。

## 已确认原因

项目 `node_modules/ffmpeg-static/ffmpeg.exe` 及 `.next/standalone/node_modules/ffmpeg-static/ffmpeg.exe` 均被截断：文件实际 38,460,200 字节，而 PE 节表要求末端至少达到 82,797,568 字节。启动时报 `spawn EFTYPE`。目前没有证据确认截断发生于哪次下载或复制。

`probeVideoMedia` 的 ffprobe 失败后回退 FFmpeg，回退函数的 Promise executor 中 `spawn` 同步抛错，生成 rejected Promise；调用处只挂成功回调，没有错误收尾，外层元数据 Promise 永远 pending。上下文等待整批视频探测，前端因此一直显示加载中。

## 修复

- 本机损坏文件备份至 `outputs/ffmpeg-repair-20260910/ffmpeg.truncated.exe`。使用已通过 `-version` 验证的 `C:/Program Files/ffmpeg/bin/ffmpeg.exe` 修复源码依赖和 standalone 内的两个副本。这是本机运行环境修复，二进制不进 Git；系统版本为 2025-01-15 Gyan full build。
- `lib/ffmpeg.ts` 为 FFmpeg 元数据回退补齐 rejected Promise 收尾，按既有「失败返回零值与 errorMessage，不 reject」契约结束请求。
- `scripts/probe-video-media-failure.test.ts` 复现 ffprobe 同步抛错、异步 error、非零退出之后 FFmpeg 同步启动失败三条路径，检查请求及时结束且没有游离 rejection。修复前报 `metadata request stuck after throw`，修复后通过。

## 验证与生效

修复二进制后，当前桌面服务无需重启即可重新探测；同一上下文请求约 10.4 秒成功，返回 2 个分镜组与 9 个视频，均有正常时长。浏览器仍等待旧请求时需刷新。源码异常保护在下次桌面构建后生效。

真实视频旋转元数据测试 `probe-video-media.test.ts`、二进制解析与时长探测测试 `ffmpeg-resolve.test.ts` 通过。未修改用户数据库与视频素材。
