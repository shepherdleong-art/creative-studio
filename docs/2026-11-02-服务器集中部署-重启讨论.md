## 本轮目标

负责人希望把工作台生产集中到服务器，解决个人电脑分散运行造成的多人并发、排错和版本更新问题，并询问是否需要服务端与客户端应用。

当前 Next.js 工程已有页面与 API 后端，Electron 已提供桌面运行壳。需要改造的是公共服务的身份、数据归属、调度、文件传输与生命周期；“客户端＋服务端”不意味着从零重写两套业务应用。浏览器也能承担界面入口，是否保留桌面壳取决于本机文件交付需求。

## 已找回的历史基线

以 [2026-09-20 方案](2026-09-20-轻客户端与服务器统一生产方案梳理.md) 为讨论基线；[2026-09-16 方案](2026-09-16-部门多人使用与客户端部署方案梳理.md) 已被后者更新。

- 员工使用仅连接中央服务的轻客户端；服务器负责 AI 调用、轮询、结果下载、素材存档和渲染。AI 模型仍由供应商提供。
- 员工使用工号和独立工作台密码，只能访问自己的项目、素材、任务和用量；两位管理员可查看全部。供应商凭据由服务端保管。
- 原目标最高 20 人同时使用。七牛 image2 与视频共享工作台上限 70，每人最多 10，跨项目和模块计数、公平排队；其他供应商及上传、下载、渲染分别控制资源。
- 常规项目、批量生产、详情页智能脚本是原首版必须覆盖的模块。
- 最终成片自动下载到员工选定目录；原设备重连补下载，新设备按需下载；员工自行交付共享盘。
- 公共后台无人值守运行，客户端退出不停止已接受任务；集中诊断、维护时段更新、备份及恢复验证属于上线内容。

以上为旧文中的需求决定，不是当前功能已实现的证明。旧记录中的地址、部署版本、备份及供应商额度是当时的信息；本轮没有连接服务器直接核验，不能当作最新环境与容量结论。服务器形态、显卡、内存和接入条件由负责人补充确认如下。

### 本轮补充的服务器现状

2026-11-02 负责人确认：使用一台高性能电脑作为服务器，配备 3060 显卡与 64GB 内存，已经安装 Windows Server，运行在内网，可以通过远程桌面连接并使用。这些是负责人提供的当前事实，尚未由工具测量。

据此以这台既有主机作为首版部署目标；服务器主机、操作系统安装和管理员远程接入已具备。远程桌面继续作为管理员维护通道，员工日常通过各自电脑的轻客户端连接公共工作台服务。

CPU 型号、磁盘类型与可用空间、网卡／带宽、Windows Server 具体版本、GPU 显存与驱动、当前工作台版本及数据根仍待核验。远程桌面可用不能证明员工能访问工作台业务入口，也不能证明后台在无人登录时可运行、服务账号能使用 GPU 或已满足 20 人容量目标；这些保留为后续工程验证，不要求重新选择部署形态。

## 本轮已确认决定

负责人已明确接受两轮 Q1～Q6：

1. 保留轻客户端及指定目录自动下载、原设备重连补下载等体验。
2. 创作画布纳入服务器首版，与常规项目、批量生产、详情页智能脚本共同覆盖身份、权限、调度和用量。
3. 实拍重组 Agent 流程暂保留本地，后续再接入服务器。
4. 本地与服务器分别分配并发预算，核实前先错峰；独立额度或共用池的实际限流方式与数值在实施前核实。
5. 服务器从新项目开始，旧项目和素材保留原处，首版不做历史工程批量迁移或双向同步。
6. 客户端采用提示后由员工一键更新；保存本机传输状态再重启，服务器已接受的任务继续运行。

已记录为 [ADR-0001](adr/0001-轻客户端与服务器统一生产边界.md)，相关术语写入根目录 `CONTEXT.md`。旧方案的工号身份、个人隔离、管理员管理、维护更新与备份规则继续作为基线。

这里需要明确旧方案的一处增量：9 月方案要求正式生产统一走服务器，本轮明确保留本地实拍重组这一分期例外。它不意味着轻客户端具有离线生产回退能力，也不意味着本地 Agent 的工程或用量已经与服务器同步。

### 直接承接的画布交付规则

旧基线已规定“最终成片导出成功自动下载，其他产物按需下载”。当前画布只有图片／视频生成，没有最终剪辑成片节点，因此画布生成结果留在服务器，单素材按需下载；用户主动打包时，ZIP 完成后接续下载，沿用当前交互。模型的“生成正式版”不等于工作台混剪成片，不据此触发自动下载。本轮无需重复确认这一规则；若以后希望每次画布生成都自动下载，或新增最终交付物标记，再作为新需求讨论。

### Q4 已确认：本地实拍与服务器的上游额度

已确认：两条路径使用经核实的独立上游额度，或为同一额度池分配可执行的静态预算；核实前以及无法隔离或限制时，先错峰运行共用该池的生产。具体数值按平台核验和全部使用者盘点后确定。本地不接入中央调度期间，中央服务不能限制它的实际提交量；仅换 Key 也不能证明平台按 Key 隔离额度。这里的预算指在途任务并发名额，不是金额预算；错峰针对共用供应商池的付费生成，不把无上游调用的本地渲染算入该池。

具体冲突例：本地实拍默认 50 与旧方案服务器 70 若同时占用同一个池，潜在合计是 120；旧文记录的供应商上限为 100。这里是条件推演，不是已核验两者当前共用额度，也不是对平台现有上限的断言。本地的 50 按工程控制，多工程／多进程不能被视为合计仍只有 50；静态预算必须覆盖所有共用该池的提交者并有实际限流措施，不能只在文档里分配数字。

### Q5 已确认：历史项目与首版启用

已确认：服务器首版从新项目开始；旧项目、素材和本地实拍工程保留原处，首版不建设可编辑历史工程的批量迁移或双向同步。需要复用旧素材时可按新上传规则导入副本。新服务采用独立数据根，不复制整个旧库来初始化，避免带入历史项目、用户私有资源和凭据。此决定不授权删除、移动、重置或停用任何现有数据与服务。

### Q6 已确认：轻客户端外壳更新

已确认：页面与主要业务随服务端版本集中提供；外壳有更新时提示员工，保存本机传输状态后可一键更新并重启。兼容的旧客户端允许暂缓更新，不兼容时提示必须升级才能继续工作；升级客户端不停止服务器已接受的生产任务。正在上传、下载的文件需保留可恢复状态，不能强制重启后丢失进度。发布介质、可信校验、失败恢复和兼容版本范围由工程设计落实。

两轮产品决定均已确认。当前没有未决的用户偏好分支；服务器事实、供应商额度和工程参数尚未核验，若核验结果要求改变上述体验，再重开受影响的产品分支。用户随后指定现有 Windows Server 为目标并要求细化技术方案与实施计划，现已形成技术合同、17 项依赖任务、部署手册与验收矩阵；代码改造和现场验证仍未执行。
