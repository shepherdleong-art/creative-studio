## 发现与修复

1. **Windows 渲染记录无法直接登记**：固定渲染历史 spec / inputs 使用反斜杠，P1 清单要求 `/`，产生核验不一致。导入仍先验证原始 spec、render-manifest、模板和输入哈希，再规范化受管副本的镜头、音频、封面及 classic 参考文件路径。原文件不改写；越界、绝对路径、变化哈希及非规范导入清单继续拒绝。
2. **中断重试路径增长导致图片写入失败**：原实现把第二个 UUID 追加到 job ID 目录。真实免安装中断恢复时，封面路径达到 262 字符，sharp/libvips 报 `unable to open for write`，同一目录普通文件可写、短路径图片可写。改为使用与原 job ID 等长的全新同级目录，保留失败产物，不覆盖旧目录。最小复现见 `retry-path-probe.json`；完整桌面中断测试为回归入口。
3. **测试的平台假设**：Windows 不具有 POSIX 权限位语义，身份/令牌检查保留，仅 POSIX mode 断言按平台区分；目录链接攻击测试在 Windows 使用 junction。NTFS ACL 隔离不因此被宣称已验收。
4. **测试证据与失败诊断**：桌面脚本支持独立证据目录、包根和真实中断选项；核对一帧入点与镜头顺序实际进入新 spec，实际工具路径必须来自目标程序。任务失败立即报告，恢复超时不能算通过，退出检查状态文件清理。

## 复跑

PowerShell 设置环境变量后分别执行：

```powershell
$env:FILM_IMPORT_SPEC = '<当前模板的成功合成spec.json>'
$env:FILM_INTEGRATION_PARENT = '<已存在的隔离证据目录>'
$env:FILM_INTEGRATION_RENDER = '1'
node scripts/reassembled-film.integration.test.ts

$env:FILM_DESKTOP_FIXTURE = '<上一步生成的fixture.json>'
$env:FILM_DESKTOP_EVIDENCE = '<本轮新证据目录>'
node scripts/reassembled-film.desktop.test.mjs

# 免安装用新夹具，避免上一次编辑状态影响测试预期。
Remove-Item Env:FILM_INTEGRATION_RENDER -ErrorAction SilentlyContinue
node scripts/reassembled-film.integration.test.ts
$env:FILM_DESKTOP_FIXTURE = '<新输出的fixture.json>'
$env:FILM_DESKTOP_EVIDENCE = '<免安装本轮新证据目录>'
$env:FILM_DESKTOP_APP_ROOT = '<免安装QA包根>'
$env:FILM_DESKTOP_RESTART = '1'
node scripts/reassembled-film.desktop.test.mjs

# 桌面正常退出后运行。
node scripts/reassembled-film-delivery.windows.test.ts
```

固定渲染模板哈希已变化的旧样本不能直接登记：先用当前版本生成合格合成片，不篡改旧清单。完整模板矩阵的 P0 结果仍见先前文档。
