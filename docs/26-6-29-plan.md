# 执行计划：把 Windows 启动器做成真正的 EXE（含正确图标 + 品牌启动页）

> 状态：**代码改动已完成，待阶段一自验**。四项文件改动已落实，等待 `npm run build` + 编译 EXE + 双击验证。

## Context（为什么做这件事）

将 Creative Studio 装在 `H:\Creative Studio` 后遇到两层问题：

1. **已修复的根因**：standalone 构建漏掉了 `next/dist/compiled/next-server/app-route-turbo.runtime.prod.js` 等 13 个 runtime 文件，导致所有 API 路由 500、配置供应商失败。已通过 `next.config.ts` 的 `outputFileTracingIncludes` 永久修复，重建后实测 `/api/providers` 返回 200。
2. **当前要解决的体验问题**：
   - 开始菜单里没有正经的应用快捷方式，只有两个 PowerShell 图标——因为 `.iss` 的 `[Icons]` 把 `Filename` 指向了 `powershell.exe`。
   - 旧版残留的 `start-windows.cmd`（去调一个不存在的 `start-windows.ps1`，报退出码 -196608），且 cmd 控制台是 GBK 编码、日志是 UTF-8，出现乱码。
   - 真实诉求：**双击即启动、像真正的桌面应用、最好是一个 .exe**。

**已确认的事实：**
- `csc.exe` 存在于 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`；Win10/11 自带 .NET Framework 4.8 运行时，目标机器零额外依赖。
- `app\favicon.ico`（25.9KB）可直接嵌入 EXE 作为图标。
- `installer\windows\launcher.html` 是现成的"启动等待页"，会轮询服务并自动跳转，但提示文案引用了旧脚本（`launcher.vbs`/`start-windows.cmd`/`BATCH_WORKBENCH_PORT`），需更新。
- `installer\windows\start-installed.ps1` 是当前能正常工作的启动逻辑（隐藏启动 node、写日志、写 PID、轮询端口、打开浏览器）——作为新 EXE 的行为蓝本。

**已确认的选择：**
- 启动器形态：**真正的 EXE**（一个 `CreativeStudio.exe` 同时满足"文件夹双击 / 正确图标 / 真 exe"；停止与清数据沿用 PS1 脚本）。
- 浏览器落地页：**品牌启动页 `launcher.html`**（并更新其过时文案）。

**预期结果：** 重建安装包后，开始菜单/桌面是带应用图标的正经快捷方式；双击即弹出品牌启动页并在服务就绪后自动进入工作台；全程无 PowerShell 黑窗、无乱码；配置供应商不再 500。

## 逐文件改动

### 1. 新增 `installer\windows\launcher.cs`（C# 启动器源码）

WinExe（`/target:winexe` → 无黑窗）。行为镜像 `start-installed.ps1`，但落地页改为 `launcher.html`：

- **应用根目录** = EXE 所在目录（EXE 安装在 `{app}\CreativeStudio.exe`）。
- **路径**：`runtime\node.exe`、`server.js`、`storage\logs\server.{out,err}.log`、`storage\run\server.pid`、`launcher.html`。
- **端口**：`CREATIVE_STUDIO_PORT` 环境变量，默认 `3000`。
- **流程**：
  1. 用 `TcpClient` 短超时连 `127.0.0.1:port`，若已监听 → 服务已在跑，直接开 `launcher.html` 后退出。
  2. 校验 `node.exe`/`server.js` 存在，缺失则用 user32 `MessageBox`（P/Invoke，免引用 WinForms）弹友好错误。
  3. 创建 `storage\logs`、`storage\run`。
  4. **隐藏启动 node 并保证父进程退出后存活 + 日志落盘**：以 `cmd.exe /c ""<node>" server.js >> "<out.log>" 2>> "<err.log>""` 方式启动，`UseShellExecute=false`、`CreateNoWindow=true`、`WorkingDirectory=root`，并通过 `ProcessStartInfo.Environment` 设 `PORT`/`HOSTNAME=127.0.0.1`/`NODE_ENV=production`。（cmd 包一层负责文件重定向，使 node 在启动器退出后继续运行且日志不丢；node 的命令行包含 root，`stop-installed.ps1` 的端口匹配逻辑仍能正常停止它。）
  5. 写 PID 文件（best-effort）。
  6. **打开品牌启动页**：构造 `file:///.../launcher.html?port=<port>`（用 `new Uri(path).AbsoluteUri` 再拼 `?port=`），`Process.Start` 以 `UseShellExecute=true` 交给默认浏览器；`launcher.html` 自行轮询 `/favicon.ico` 并在就绪后自动跳转工作台。
  7. 退出。
- 整体 try/catch，异常用 `MessageBox` 呈现，避免静默失败。

> 行为蓝本：`installer\windows\start-installed.ps1`（端口检测、隐藏启动、日志/PID、环境变量与此一致；唯一差异是落地页用 `launcher.html` 而非裸 URL）。

### 2. 修改 `scripts\build-win-installer.ps1`（编译并放入 payload）

在 payload 组装完成、剪除禁止目录之后、调用 ISCC 之前（现约 152–154 行之间）插入编译步骤：

- 解析 `csc.exe`：优先 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`，回退 `Framework\v4.0.30319\csc.exe`，找不到则 `throw`。
- 编译：
  ```
  & $csc /nologo /target:winexe /optimize+ `
    /win32icon:"<Root>\app\favicon.ico" `
    /out:"<AppDir>\CreativeStudio.exe" `
    "<Root>\installer\windows\launcher.cs"
  ```
- 校验 `$AppDir\CreativeStudio.exe` 存在，否则 `throw`。
- `launcher.html` 已由现有步骤（约 150 行）拷入 payload；`[Files]` 的 `{app}\*` 通配会自动把新 EXE 打进安装包，无需改 `[Files]`。

### 3. 修改 `installer\windows\CreativeStudio.iss`（快捷方式指向 EXE）

- `[Icons]` 主快捷方式（开始菜单第 97 行、桌面第 101 行）：`Filename` 从 `powershell.exe`+`Parameters` 改为 `{app}\CreativeStudio.exe`（去掉 Parameters），图标自动用 EXE 内嵌图标。

- `[Run]`（107 行，安装后启动）：改为运行 `{app}\CreativeStudio.exe`（保留 `nowait postinstall skipifsilent`）。
- `[UninstallRun]`（停止）保持调用 `stop-installed.ps1` 不变。

## 风险与注意

- **SmartScreen**：新编译的未签名 EXE 首次运行可能弹"Windows 已保护你的电脑"，需点"更多信息 → 仍要运行"。代码签名超出本次范围，需在交付说明里告知用户。
- **杀软**：个别杀软可能对新生成的未签名 exe 误报，通常放行即可。
- **`file://` 带查询串**：需用 `Uri.AbsoluteUri` 生成 `file:///...launcher.html?port=3000` 交给 ShellExecute，确保 `launcher.html` 能读到 `?port`。构建后按"验证 2"实测确认。
- **lingering cmd.exe**：cmd 重定向包装层会作为 node 父进程常驻（无窗口、占用极小），属预期、无害。
