## 二、当前交互结构

### 1. 三栏编辑工作区

- 左栏：素材池。显示当前批次上下文内的素材，区分已用/未用，支持选择、替换、插入、追加和预览。
- 中栏：视频预览 + 时间轴。顶部在成片预览和素材预览之间切换；下方展示视频、字幕、口播轨道。
- 右栏：批量字幕样式、成片背景音乐、视频封面设置。右栏有独立滚动容器，不会把中栏滚出视口。
- 中栏和右栏均有明确的自动化定位标识：`batch-output-middle-scroll-area`、`batch-output-settings-scroll-area`、`batch-output-preview-pane`、`batch-output-timeline-pane`。

### 2. 时间轴编辑能力

当前时间轴保留单条剪辑的核心操作模型：

- 选择模式和分割模式；
- 视频片段左右边界拖拽裁剪；
- 视频片段等长平移取材窗口（slip）、替换、删除、插入、追加和分割；
- 字幕片段拖动、裁剪、双击编辑、删除和分割；
- 当前播放头、轨道标签和口播锁定状态；
- 右键菜单操作；
- 保持片头与口播的时间对齐约束。

素材选择、替换和追加都限定在当前批次、当前成片计划的冻结素材池中，不通过文件名或时间戳推断素材归属。

已知边界：批量时间轴不支持单条剪辑的片段重排序。

### 3. 封面精调

封面入口改为“打开视频封面设置”，点击后打开独立 drawer，交互目标与单条剪辑封面设置一致：

- 左侧选择来源视频片段并预览；
- 中央显示画幅、安全区和标题叠加效果；
- 支持封面截帧时间、输出画幅、画面缩放、水平位置、垂直位置；
- 主标题和副标题支持文字内容、字体、字号、缩放、X/Y 位置、文字框宽度、颜色、对齐、斜体、描边及阴影等；
- 预览标题使用共享的 SVG 构造逻辑，渲染端使用同一套 framing 和样式数据模型；
- 缩放范围和位移范围由共享 geometry 统一约束，默认位置从中心开始。

最新一轮专门修复了封面缩放为 `1.15` 等大于 1 的值时的右侧黑边问题：预览媒体显式使用 `maxWidth: none`，不再被全局图片/视频最大宽度规则截断。

### 4. 字幕样式与 BGM

- 批量字幕样式改为完整的 `BatchTextStyleEditor`，包括字体、字号、缩放、位置、文字框宽度、颜色、对齐、斜体、描边和阴影。
- 支持恢复批量默认样式和将当前样式应用到批次成片。
- BGM 仍按成片单独覆盖，支持音乐选择、试听、音量增益、淡入、淡出、恢复默认和应用参数。
- 字幕和 BGM 的编辑都只作用于当前批次/当前输出计划，不跨项目或跨计划写入。

## 三、前端与后端契约变化

### 1. 编辑提交与渲染生命周期

前端编辑请求支持两种阶段：

1. 编辑期间发送具体 edit command，并带 `deferRender: true`；后端更新 arrangement 并重新加载视图，但不为每个小改动排队渲染。
2. 退出编辑轮次、离开页面或组件卸载时发送 `commit_render`；后端只为这一轮最终状态排队一次渲染。

这样可以同时满足“改完马上能在前端播放查看”和“人工修改后的最终版本需要重新生成并可导出”两个要求。导出和重试流程仍检查 `editRevision`、`renderStale`、`coverTimeUs` 等新鲜度条件，不允许把旧渲染结果误当成当前编辑版本。审核接口本身不拦截这些新鲜度条件，只返回 `pendingRender` 供前端提示；硬性阻断只在导出闸门。

### 2. Arrangement 命令

`output-arrangement.ts` 现在提供类型化的片段、字幕、BGM 和封面视图及编辑命令，主要包括：

- `trim_variable`、`delete`、`insert`、`split`；
- `set_cover`；
- `set_music_track`、`set_music_params`；
- 字幕移动、裁剪、编辑、删除、分割；
- `restore_automatic_subtitles`。

所有命令完成后都会重新构建当前输出视图，前端不依赖本地猜测状态作为最终真值。

### 3. 渲染支持

批量 renderer 已支持：

- 封面 framing 和标题 override；
- 字幕样式 override/overlay；
- 每个输出独立的 BGM 参数；
- 24fps 与时间轴对齐；
- 封面时间与渲染版本的新鲜度校验。

封面配置和标题样式的归一化放在共享领域模块中，避免批量预览、单条编辑和 ffmpeg 渲染出现不同的几何含义。

## 七、请 Opus 重点 review 的问题

### A. 产品交互与布局

- 在窄窗口和常见笔记本高度下，左侧素材池、中间预览/时间轴、右侧设置是否仍然可用；是否有内容被固定高度、`overflow` 或 footer 遮挡。
- 中栏和右栏是否真正独立滚动；右栏滚到底部时，中间预览和时间轴是否保持可见。
- 素材预览是否始终复用中间窗口，切换素材后标题、时长、播放进度和时间轴状态是否正确更新。
- 是否保留了单条剪辑中用户已经习惯的控件语义、按钮状态、禁用状态和操作顺序。

### B. 封面几何与渲染一致性

- 缩放 `1`、`1.15`、较大缩放值和水平/垂直位移组合时，画面是否以中心为基准，是否仍有右侧或其他方向的异常黑边。
- 预览和最终 ffmpeg 渲染是否使用同一套 framing geometry，3:4 等非横屏画幅是否保持比例而不拉伸。
- 主标题、副标题的内容和完整样式字段是否都能从 UI 进入 arrangement、保存、重新打开并参与最终渲染。
- 旧数据缺失部分标题样式或 framing 字段时，归一化和默认值是否安全；异常数值是否正确 clamp。
- 封面截帧时间改变后，`coverTimeUs`、预览画面、渲染结果和导出新鲜度是否一致。

### C. 编辑提交、并发与新鲜度

- 连续快速拖动裁剪边界、移动片段、分割后立即离开页面时，`deferRender` 和 `commit_render` 是否会丢编辑或重复排队。
- 组件卸载、路由切换、关闭 drawer、请求失败和重复 commit 时，是否会留下错误的 `renderStale`/running 状态或旧 render candidate。
- 编辑后预览使用的是最新 arrangement，而导出、审核、重试是否会正确拒绝过期渲染。
- 分割等不需要立即重渲染的命令是否仍能保持正确的 arrangement 和版本号；最终退出编辑时是否只提交一次渲染。
- 当前批次、当前 plan、冻结素材池和未使用素材之间是否有跨上下文写入风险。

### D. 字幕、BGM 和可访问性

- 字幕样式每个字段是否能保存、恢复默认、应用到批次，并正确反映在实时预览和最终渲染中。
- 字幕 cue 的拖动、裁剪、编辑、删除、分割与自动字幕恢复是否互相影响；口播锁定后是否仍保持音画对齐。
- BGM 选择、试听、增益、淡入淡出和应用参数是否只作用于当前输出，且不会覆盖其他输出的独立设置。
- drawer、全屏按钮、右键菜单、素材预览按钮和 range/input 控件是否具备可理解的文字/ARIA 标签、焦点顺序和键盘操作。

### E. 回归与范围控制

- 是否引入了批量编辑器以外的布局或共享渲染回归，尤其是单条剪辑封面、字幕和 final-edit 共用模块。
- 评审时请将已有的 lint/build warning 与本轮新回归分开判断，不要把已有 warning 直接当成这组改动造成的问题。
- 检查是否有未纳入本轮需求的“不可用能力”重新出现在批量编辑器中，特别是口播变速和强制立即渲染入口。

## 八、已知验证边界

- 浏览器自动化 harness 当前没有暴露 `requestFullscreen`，因此已验证全屏按钮、stage 比例 CSS 和 fullscreen 代码路径，但没有在 harness 中真正进入系统级 fullscreen；这一点需要 Opus 或人工在真实浏览器里复核。
- harness 无法可靠地通过现有键盘/点击接口修改 range 的 value，因此没有用自动化操作完整复现 `1.15` 滑块拖动；但已通过 live DOM 检查确认放大媒体的 `maxWidth` 为 `none`，并结合根因定位完成修复。
- 本轮没有发起新的供应商请求、外部网络 egress 或持久化生产任务；验证使用本地代码、现有本地数据和测试/浏览器检查。
