### 阶段一关键决策（子代理偏离计划处，均合理，已确认）

1. **matrixJson 保留句段维度**：`{scores: {"segment-1": {"assetId:sceneIndex": number}, ...}, hooks: {...}}`。扁平存储会让每句打分相同、语义优先失效（正是要修的问题）。
2. **显式 segments 不传 id**：分配器仍按 `${planId}:segment:<i+1>` 生成，与改动前句段身份逐字节一致（既有冻结版本锁定段/封面引用不受影响）；`segment-N` 仅作矩阵内部键。
3. 供应商注册表走动态 import（Node 裸跑测试无法解析 script-providers 的无扩展名导入），`resolveBatchSemanticProvider`/`queueBatchSemanticScoreTasks` 为 async。
4. 失败后「重新生成」不换供应商也能恢复：同 requestKey 的 failed 任务原地回 queued（仿 `asset-preparation.ts:226-241`），我亲手补的实现 + 测试。

### defaultsJson 封面字段约定（UI 阶段必须遵守）

```
coverTitleMode: 'none' | 'preset' | 'custom'    缺省 'none'
coverTitlePresetId: string | null
coverTitleStyles: { primary: TextStyle, secondary: TextStyle } | null   -- 已按当前画幅解析的拷贝
coverTitleFraming: { scale, offsetX, offsetY } | null
```

- **存解析后的样式而非只存 id**（预设日后被改/删不影响冻结版本）；canonical 比对自动把样式纳入输入身份 → 改样式=新版本，无需改 `matchesCurrentInput`。
- UI 必须**稳定写入完整形状**（不选也要写 mode:'none'、其余 null），避免 canonical 抖动。
- 选预设时只取**当前画幅**那套 `{primary, secondary, framing}`（比例映射用 `BATCH_PRESET_TO_COVER_PRESET_ID`）。
