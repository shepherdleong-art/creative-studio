# 老通道取消未收尾导致任务中心永久显示「供应商已受理」

## 现象

团队版项目 `20261111-K店-XQ21A-A-AI种草-ALAN` 分镜组 2 的一条可灵 2.5 视频任务：

- 项目页显示「已取消 · Canceled by user」；
- 全员任务列表一直显示「视频生成 / 生成请求 / 供应商已受理」，从 18:10:34 起不再变化；
- 「待核对」页看不到这条任务。

## 根因

老通道（非统一模型，如可灵 2.5 直连供应商行）的单条取消走
`app/api/video-jobs/[id]/route.ts`，旧实现只写业务行：

```sql
UPDATE video_jobs SET status='canceled', errorMessage='Canceled by user', finishedAt=datetime('now')
WHERE id=? AND status IN ('pending','running','needs_check')
```

既没有写 `cancelRequestedAt`，也没有结算 `execution_operations`。连锁后果：

1. 轮询循环下一轮 `isVideoJobStillRunning` 返回 false，直接 return，不再查询远端；
2. 续跑领取条件要求 `status='canceled' AND cancelRequestedAt IS NOT NULL`，永远领不到；
3. 「补抓结果」的准入条件同样要求取消意图，同样拒绝；
4. 任务中心的状态取执行记录 `o.status`，它停在 `accepted` 就永远显示「供应商已受理」；
5. 全仓没有清理陈旧 `accepted` 执行记录的扫描，没有任何告警能发现它。

统一模型（Image 2 / 可灵 3.0）的取消由 `lib/media-core/unified-media/cancel-intent.ts`
负责，本来就写取消意图并保留已受理任务的收尾——**老通道漏了同一套契约**。

## 修复

新增 `lib/legacy-media-cancel.ts`，把老通道对齐到统一模型的取消契约：

| 场景 | 行为 |
| --- | --- |
| 已受理（有 `providerTaskId` 或已有结果） | 只写 `cancelRequestedAt`，保持 `running`/`needs_check`，队列继续只读查询收尾 |
| 未受理 | 立即 `canceled` + 写取消意图，并结算执行记录为 `stage_canceled` |
| 已终态 / 已记录意图 | 幂等返回，不重复写 |

配套改动：

- `lib/video-queue.ts`：续跑领取与「补抓」准入覆盖 `canceled` 且仍有远端身份的活任务；
  取消后远端失败不再把「已取消」改写成「失败」；worker 领取后、真实 POST 前的取消守卫补齐老通道；
  晚到结果的 `lateCanceled` 口径保持各自既有契约（统一模型记 canceled、老通道记 succeeded），
  两者都会让执行记录收敛到终态。
- `lib/legacy-media-lifecycle.ts`：启动时先跑一次历史孤儿修复（补写取消意图并清空 `finishedAt`），
  再按放宽后的条件恢复项目队列。
- `lib/team-service/tasks.ts`：`effectiveStatus` 增加「业务行已取消且有取消意图 → canceled」，
  修掉「执行记录仍 accepted 时任务中心显示供应商已受理」的显示口径。

## 审查补充

本轮补齐了提交在途与整组停止的收尾处理。取消判断同时读取当前执行版本的持久回执，覆盖请求已发出、远端 ID 尚未返回的窗口。付费发送前再次检查取消意图，阻止在准入日志写入期间取消的任务继续提交。

团队版整组停止会取消未提交任务，并继续查询已受理任务及补下载，直到结果收敛。程序停机仍通过 drain 中断 worker，恢复测试改为直接调用停机入口。

新增 `scripts/legacy-video-cancel-races.test.ts`，验证提交前取消、POST 在途取消后成功与失败，以及整组停止后自动收尾、收尾期间新建任务继续执行。五种场景通过，均断言无重复提交和占用正确释放。任务中心投影兼容缺少取消字段的历史结构。
