# 原声无人声状态与选片流程诊断

## 本轮证据

- 最新本机制作请求为 `0e2d68cc-6fbb-474b-87cf-a399eb4e66b8`（2026-10-26）。只读核对时，成功记录覆盖 57 个有转写结果的独立素材、16 个无音轨素材；该批失败声音任务涉及 148 个独立素材，错误均包含 `20000003`。数量是此次读取时的记录快照，不代表全部成片最终状态。
- 示例失败素材为 S14 尺寸展示、P1/P2 人物落座。文件名仅用于定位，不能据此确认视频确实没有人声。
- 火山官方[错误码文档](https://docs.volcengine.com/docs/DoubaoVoice/error-code-query?lang=en)将 `20000003` 定义为静音音频/未检测到人声，极速版也列出此状态。原适配器只接受 `20000000`，导致明确无人声被报成「请检查语音服务配置」。

## 已修复的范围

- 适配器仅在 HTTP 成功且 `X-Api-Status-Code=20000003` 时返回明确无人声证据，保留 `provider/statusCode`；普通成功空文本、缺时间、HTTP 失败均不走此分支。
- `source-speech` 仍先提取 16 kHz 单声道 PCM WAV，再交给语音识别。响应后重新核验原片，将明确无人声保存为已有 `no_speech` 领域状态，并附服务身份；不伪装成人工确认，不因此赋予成片发布资格。
- 声音阶段进度区分「人工确认没有人声」与「识别服务未检测到人声」。后续按当前原声/混合/配音设置编排，无人声不再直接阻塞声音识别阶段；需要配音而没有配置服务仍会受阻。
- 未修改真实制作记录、批量重试或重新上传用户素材，也未重启桌面。旧失败任务在新源码构建生效后可按原任务重试，不能把历史失败文本直接改写成成功记录。

## 选片现状与建议方向（未实施）

当前实拍公式模式是「脚本编号 → 对应可用文件 → 核对原声 → 声音编排 → 时间轴」。选片会核验文件、候选规则和可用区间，缺片替换使用文字依据；第一步 AI 素材说明基于文件名与资料，不是视频画面理解。不能把此状态称为已经完成视觉内容分析。

建议补充独立的素材预分析阶段：用户选好模型并显式启动后，并行进行画面内容/动作区间分析与音轨提取/语音转写，按素材指纹和分析配置缓存结果，展示可核对的内容索引，再进入批次生产。

已有脚本编号仍约束选片，视觉分析用于核对内容和选择区间；缺编号时需要原镜头的内容定义，系统才能提出有依据的替代候选。分析现有视频不能凭空知道缺失编号原本代表什么。复用批量生产的共享 `media-core` 能力，不从 `batch-production` 或 `final-edit` 反向导入。
