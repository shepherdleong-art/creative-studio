# 新电脑部署指南：Creative Studio Windows 桌面版（交给 Agent 执行）

日期：2026-08-13　适用：从共享盘拷贝免安装包到一台新的 Windows 10/11 电脑，跑通 `start-windows.cmd`

> 本文档的使用方式：把本文件交给本机上的 AI Agent（如 workbuddy），让它按下文顺序执行并在每一步自检。
> 人只需要能把共享盘上的文件夹拷到本地。

免安装包位置（共享盘，只读使用，不要在里面直接运行）：

```
U:\内容摄制部\AI工作台-0.3.0\创意工作台-0.4.0-免安装版
```

## 0. 给 Agent 的总说明

- 目标：让 `start-windows.cmd` 在这台机器上双击可用，桌面壳正常打开，设置页「公司供应商运行环境」显示就绪。
- 全程不要修改项目代码；只允许安装软件、建环境变量、运行项目自带脚本。
- `config.yaml` 和 `.env.local` 含有真实 API Key：不要打印、不要外传、不要提交到任何仓库。
- 每一步都有验证命令，验证不通过就停在该步排查，不要跳过继续。
- 安装完软件后，**当前终端的 PATH 不会刷新**：后续命令要开新终端，或用完整路径调用。

## 1. 拷贝免安装包到本地磁盘

把整个文件夹从共享盘拷到**本地磁盘**（如 `D:\创意工作台`，路径不要太深），拷完约 2.5 GB，网络慢时要等一阵。

**不要直接在 U: 盘上双击运行**：SQLite 数据库（WAL 模式）跑在网络盘上有损坏风险，node_modules 走网络盘也极慢。

包里已经包含以下关键内容，拷完确认都在（下称 `<项目目录>`）：

| 文件/目录 | 作用 | 缺失后果 |
| --- | --- | --- |
| `start-windows.cmd` | 启动入口 | 无法启动 |
| `node_modules/`（含 Electron 二进制） | 全部 Node 依赖 | 启动脚本会自动 `npm ci` 重装（要联网） |
| `.next/standalone/` | 生产构建产物 | 启动脚本会自动重新构建（几分钟） |
| `config.yaml` | 公司网关模型配置（含上游 Key） | 公司供应商不可用，其余功能正常 |
| `.env.local` | 腾讯云 COS 密钥（参考图公网交付） | 公司供应商参考图传输失败 |
| `data/` | 项目数据库 | 自动重建空库 |

两个注意点：

- `data/` 里带着原机器的项目数据（`workbench.db`）。如果同事想要干净的工作台，把 `data/` 里的文件删掉即可（库会自动重建）；想参考已有项目就保留。
- `.venv-litellm/` 是从原机器拷来的，**必然失效**（venv 写死了创建机路径）。不用手动删，启动脚本检测到会自动重建——前提是第 2.2 步的 Python 3.12 装好了。

## 2. 必装软件（只有这两样）

### 2.1 Node 运行时（免安装包已内置，通常不用装）

包内自带便携 Node：`node-runtime\node.exe`（v22.22.3，ABI 127），启动脚本优先使用它。
**不能用其他大版本**：包内 `node_modules` 的预编译原生模块（better-sqlite3）按 Node 22 编译，
Node 24 会加载失败（winget 官方源已下架 22.x，`OpenJS.NodeJS.LTS` 现在指向 24，不要装）。

仅当 `node-runtime\node.exe` 缺失时才需要手动装 Node.js 22.x：
https://nodejs.org/dist/v22.22.3/node-v22.22.3-x64.msi

验证（开新终端）：

```powershell
node-runtime\node.exe --version    # 预期 v22.22.3
```

### 2.2 Python 3.12（公司供应商需要，强烈建议装）

LiteLLM 1.89.2 要求 Python `>=3.10, <3.14`，**Python 3.14 装不上**，必须是 3.12：

```powershell
winget install --id Python.Python.3.12 -e --accept-source-agreements --accept-package-agreements
```

验证（开新终端）：

```powershell
py -3.12 --version    # 预期 Python 3.12.x
```

要点：启动脚本靠 `py -3.12` 找到解释器。官方安装器默认带 py launcher；如果 `py` 命令不存在，说明安装时去掉了 launcher，重装并勾选「py launcher」。

不装 Python 也能启动工作台，但公司供应商（生图/生视频走公司网关的模型）不可用。

## 3. 首次启动

双击 `<项目目录>\start-windows.cmd`（或 Agent 执行它）。免安装包里依赖和构建产物都齐了，脚本会自动跳过 `npm ci`、Electron 安装和构建，实际只多做一件事：

- 检测 `.venv-litellm` 失效（从别的机器拷来的一定失效），用 `py -3.12` 自动重建并安装 `requirements-litellm.txt`（首次约 1–3 分钟，要联网）；
- 然后拉起 LiteLLM 代理（127.0.0.1:4000），启动 Electron 桌面壳。

之后每次启动只要几十秒。

如果哪天 `node_modules` 或 `.next/standalone` 被删了，脚本会自动重装/重建，只是首次会慢（见第 5 节网络问题的处理）。

## 4. 验收清单（全部通过才算完成）

1. 桌面壳窗口正常打开，能看到项目列表页。
2. 设置页「公司供应商运行环境」显示就绪（代理可用）。
3. 命令行验证代理：

   ```powershell
   Invoke-RestMethod http://127.0.0.1:4000/health/liveliness
   ```

4. 在项目里实际提交一个生图任务，能返回结果（这一步同时验证 `config.yaml` 的上游 Key 没过期）。

完成后 Agent 汇报：Node 版本、Python 版本、代理健康检查结果、测试任务结果。

## 5. 常见问题（按报错对号入座）

**`npm ci` 卡在 `ffmpeg-static` / 报 `ETIMEDOUT`**
postinstall 要直连 GitHub 下载，不读 npm 代理配置。有代理就先设环境变量再重跑：

```powershell
$env:HTTP_PROXY='http://127.0.0.1:7897'; $env:HTTPS_PROXY='http://127.0.0.1:7897'
npm ci
```

（端口换成同事本机实际的代理端口。）

**Electron 二进制装不上（`fetch failed`）**
`@electron/get` 不认代理环境变量，改用国内镜像：

```powershell
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
node node_modules\electron\install.js
```

**提示「端口 4000 已被占用」**
有旧的 LiteLLM 在跑。执行 `scripts\stop-stack.ps1`；若无效，找到占用 4000 的进程停掉再启动。

**启动后「LiteLLM 环境已失效」且没有自动重建**
说明第 2.2 步的 Python 3.12 没装好或没有 py launcher。装好后**重开** `start-windows.cmd`，它会自动重建，无需手动删 venv。

**生图报 401 `Invalid token`**
不是环境问题，是 `config.yaml` 里的公司网关上游 Key 过期/被吊销。去公司网关（new-api）控制台重新生成令牌，替换 `config.yaml` 里的 `api_key`，执行 `scripts\stop-stack.ps1` 后重启。

**双击 cmd 窗口中文乱码**
不要用文本编辑器重存 `start-windows.cmd` 和 `scripts\*.ps1`。前者必须 CRLF 行尾，后者必须 UTF-8 **带 BOM**，重存会破坏。

## 6. 日常使用与停止

- 启动：双击 `start-windows.cmd`；代码更新后用 `start-windows.cmd -Rebuild`。
- 停止：应用菜单「退出」（代理随之关闭），或直接关启动窗口。网页版停止用 `stop-windows.cmd`。
- 桌面版与网页版（`scripts\start-windows.ps1`，3000 端口）共用同一个数据库 `data\workbench.db`，**不要同时运行**。
- 服务只监听 127.0.0.1，任何情况下不要把端口暴露到公网。
