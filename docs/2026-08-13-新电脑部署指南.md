# 新电脑部署指南：Creative Studio Windows 桌面版（交给 Agent 执行）

日期：2026-08-13（2026-08-14 按内置 Python 运行时方案更新）　适用：从共享盘拷贝免安装包到一台新的 Windows 10/11 电脑，跑通 `start-windows.cmd`

> 本文档的使用方式：把本文件交给本机上的 AI Agent（如 workbuddy），让它按下文顺序执行并在每一步自检。
> 人只需要能把共享盘上的文件夹拷到本地。

免安装包位置（共享盘，只读使用，不要在里面直接运行）：

```
U:\内容摄制部\AI工作台-0.3.0\创意工作台-0.4.0-免安装版
```

---

## 0. 给 Agent 的总说明

- 目标：让 `start-windows.cmd` 在这台机器上双击可用，桌面壳正常打开，设置页「公司供应商运行环境」显示就绪。
- 全程不要修改项目代码；只允许复制文件、运行项目自带脚本。
- **本方案不需要安装任何软件**：不要装 Node、不要装 Python、不要创建 venv、不要执行 pip/winget。运行环境全部内置在包里。
- `config.yaml` 和 `.env.local` 含有真实 API Key：不要打印、不要外传、不要提交到任何仓库。
- 每一步都有验证命令，验证不通过就停在该步排查，不要跳过继续。

## 1. 拷贝免安装包到本地磁盘

把整个文件夹从共享盘拷到**本地磁盘**（如 `D:\创意工作台`，路径不要太深），网络慢时要等一阵。

**不要直接在 U: 盘上双击运行**：SQLite 数据库（WAL 模式）跑在网络盘上有损坏风险，node_modules 走网络盘也极慢。

包里已经包含以下关键内容，拷完确认都在（下称 `<项目目录>`）：

| 文件/目录 | 作用 | 缺失后果 |
| --- | --- | --- |
| `start-windows.cmd` | 启动入口（固定走免安装模式） | 无法启动 |
| `portable-manifest.json` | 免安装包完整性清单 | 启动时报「免安装包不完整，请重新复制」 |
| `node-runtime/`（含 `node.exe`） | 内置 Node 22 运行时 | 同上 |
| `python-runtime/`（含 `python.exe`、`runtime-manifest.json`） | 内置 Python + LiteLLM（公司供应商组件） | 公司供应商不可用 |
| `node_modules/`（含 Electron 二进制） | 全部 Node 依赖 | 同上 |
| `.next/standalone/` | 生产构建产物 | 同上 |
| `dist-desktop/` | 桌面壳编译产物 | 同上 |
| `scripts/` | 启动/停止/自检脚本 | 同上 |
| `config.yaml` | 公司网关模型配置（含上游 Key） | 公司供应商不可用，其余功能正常 |
| `.env.local` | 腾讯云 COS 密钥（参考图公网交付） | 公司供应商参考图传输失败 |
| `环境自检.cmd` | 只读自检工具（双击运行，把输出发回排查） | 无法自助排查 |

两个注意点：

- 包里**不带** `data/`、`storage/`（本机首次启动会自动创建空库）；也不带 `.venv-litellm/`——如果你在包里看到 `.venv-litellm/`，说明复制来源不对，请重新从共享盘完整复制。
- 缺任何关键文件都**不要**尝试在本机修复（免安装模式也不允许联网修复），直接重新完整复制整个包。

## 2. 必装软件

**无。** Node 运行时（`node-runtime\node.exe`，v22.22.3）和 Python + LiteLLM 运行时（`python-runtime\`）都已内置在包里，终端用户不需要安装 Node.js 或 Python，也不需要联网。

验证（可选，开终端在 `<项目目录>` 执行）：

```powershell
node-runtime\node.exe --version      # 预期 v22.22.3
python-runtime\python.exe --version  # 预期 Python 3.12.10
```

## 3. 首次启动

1. 双击 `<项目目录>\环境自检.cmd`（可选但推荐）：关键文件齐全、Python/LiteLLM 版本探测通过则继续。
2. 双击 `<项目目录>\start-windows.cmd`。

依赖、构建产物和两套运行时都已内置，启动脚本只做完整性校验，然后拉起 LiteLLM 代理（127.0.0.1:4000）并打开桌面窗口。**不再有首次 1–3 分钟的环境重建，也不需要联网**；首次启动只是比后续略慢（LiteLLM 加载模型清单），之后每次启动几十秒。

## 4. 验收清单（全部通过才算完成）

1. 桌面壳窗口正常打开，能看到项目列表页。
2. 设置页「公司供应商运行环境」显示就绪（代理可用）。
3. 命令行验证代理：

   ```powershell
   Invoke-RestMethod http://127.0.0.1:4000/health/liveliness
   ```

4. 在项目里实际提交一个生图任务，能返回结果（这一步同时验证 `config.yaml` 的上游 Key 没过期）。

完成后 Agent 汇报：Node 版本（应为 v22.22.3）、Python 版本（应为 3.12.10）、LiteLLM 版本（应为 1.89.2）、代理健康检查结果、测试任务结果。

## 5. 常见问题（按报错对号入座）

**提示「免安装包不完整，请重新复制」**
`portable-manifest.json` 缺失/无效或关键文件缺失/损坏。不要尝试在本机修复，从共享盘重新完整复制整个包（保留本地 `data\` 和 `storage\`）。

**提示「端口 4000 已被占用」**
有旧的 LiteLLM 在跑。执行 `scripts\stop-stack.ps1`；若无效，找到占用 4000 的进程停掉再启动。

**生图报 401 `Invalid token`**
不是环境问题，是 `config.yaml` 里的公司网关上游 Key 过期/被吊销。去公司网关（new-api）控制台重新生成令牌，替换 `config.yaml` 里的 `api_key`，执行 `scripts\stop-stack.ps1` 后重启。

**双击 cmd 窗口中文乱码**
不要用文本编辑器重存 `start-windows.cmd`（必须 CRLF 行尾）和 `scripts\*.ps1`（必须 UTF-8 **带 BOM**），重存会破坏。

**其他启动异常**
双击 `环境自检.cmd`，把窗口输出原样发回给 PK；不要自行安装 Python/Node 或修改脚本。

## 6. 日常使用与停止

- 启动：双击 `start-windows.cmd`。
- 停止：应用菜单「退出」（代理随之关闭），或直接关启动窗口。
- 免安装模式**不支持** `-Rebuild`（会明确拒绝）：功能更新由发布者重新生成免安装包，按第 7 节增量覆盖。
- 服务只监听 127.0.0.1，任何情况下不要把端口暴露到公网。

## 7. 包更新后，已有安装该增量拷什么

总原则：只拷「代码和运行时」，**绝不从共享盘覆盖本地的 `data\` 和 `storage\`**（本机项目数据库与全部产物）。

| 共享盘里变了什么 | 本地操作 |
| --- | --- |
| `.next\standalone\` | 功能/修复更新（最常见），整目录覆盖（约 1.1 GB），覆盖后重启工作台 |
| `scripts\*.ps1` / `start-windows.cmd` / `环境自检.cmd` / `使用说明.txt` | 启动逻辑或说明更新，覆盖同名文件 |
| `node-runtime\` | 内置 Node 变化，覆盖（约 87 MB） |
| `python-runtime\` | 内置 Python/LiteLLM 变化，整目录覆盖（数百 MB） |
| `node_modules\` | 依赖变化（少见），整目录覆盖（约 1.3 GB） |
| `portable-manifest.json` | 上述任何一项更新时随包一起覆盖（完整性清单） |
| `config.yaml` / `.env.local` | 网关配置或密钥轮换，收到通知才覆盖 |
| `data\` / `storage\` | 永远不拷，本机的项目数据库和全部产物 |

判断依据：共享盘 `使用说明.txt` 末尾的「更新记录」，或对比同名文件修改时间。不确定就全量重拷（排除 `data\`、`storage\`）。更新后跑 `环境自检.cmd` + 第 4 节验收。
