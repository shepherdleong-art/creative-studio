# 片段右端修剪锁死修复

批量统一审片中，自动分配及插入片段可能保留非整帧时间边界。例如一个 3 秒片段从 13.433667 秒开始，且紧贴前一个片段。旧前端预检与后端 `trim_variable` 在修剪右端时同时把左端取整到 13.416667 秒，误入前片段约 17 毫秒。前端因此返回原区间；绕过前端时保存接口也报「不能覆盖相邻片段」。左端向内缩短时会避开此边界，因此表现不对称。

## 修复

共享 `lib/media-core/video-trim-range.ts` 的源区间与时间轴换算，拖动预览和后端保存使用同一规则。未编辑的源端点与对应时间轴端点保持原值，只对修改的端点取整到 24fps 帧网格；等长源窗口平移保留时间轴位置。

保留 0.5 秒最短长度、素材时长与相邻片段约束；修剪不会移动其他片段、字幕或音轨。属于 PRD T-04 的边缘修剪修复，不改变延长不得覆盖相邻片段的产品规则，不迁移或批量改写已有成片。

## 验证

- `node scripts/batch-review-video-trim.test.ts`：最小复现固定在 13.433667 秒接缝；修复前右端向内缩短断言失败。覆盖两侧修剪、非整帧源入点与未编辑端点不动。
- `node scripts/batch-output-clip-edit.test.ts`：覆盖实际 SQLite 保存和刷新结果，0.75/1/1.25/2 倍速下两侧修剪均与预览一致，相邻片段不动；已有片段编辑合同全部通过。
- 对本机最近 30 条成片进行只读计算核验：192 个符合最短长度与已知素材时长条件的片段，旧代码有 68 个右端无法向内缩短；新代码为 0 个，左端意外移动为 0 个。没有写入生产成片数据。
- TypeScript 与定向 ESLint 检查通过。
- `npm run build` 及 standalone 资源同步通过；更新前确认生成任务空闲，优雅关闭返回 `pendingTasks=0`。
