# 批量自定义脚本导入

原有手动脚本 API、粘贴弹窗与生产快照链路已经存在，但「脚本与口播」被批次和素材选择前置条件禁用，准备页没有入口，弹窗也不能选择本地文件。

准备页新增「导入自己的脚本」入口；准备素材和脚本页可在未创建批次时进入，确认输入和生产仍需满足原有条件。弹窗保留直接输入和批量粘贴，增加 TXT/Markdown 多文件上传、可编辑预览及统一目标时长。每个文件对应一份脚本，空行不拆分。项目级保存复用现有 API，不新增迁移，不改冻结快照或生产任务协议。导入后用户勾选脚本、设置份数/音色，再确认输入与开始生产。

验证：

- `node scripts/batch-manual-script-files.test.ts`：UTF-8/BOM、UTF-16、GB18030、段落保留、多文件、空文件/二进制/格式/大小/数量/总字符限制通过。
- `node scripts/batch-manual-script.test.ts`：手动脚本 CRUD、目录同步隔离、快照、按份数生成计划和开始生产/冻结通过。
- `node scripts/batch-manual-script-route.test.ts`：既有 API 契约通过。
- `npx tsc --noEmit` 通过；全仓 lint 为 0 错误、70 条存量警告，修改文件定向 lint 通过；`git diff --check` 通过。
- 隔离 Next 开发服务仅监听 `127.0.0.1:3149`，数据根为 `outputs/batch-script-upload/data-root`。真实浏览器验证无批次入口、空文件整批失败、多文件预览编辑、API 保存、刷新恢复、勾选与份数通过。验收脚本和截图在 `outputs/batch-script-upload/`。
- `npm run build` 因现有 `.next/standalone` 被占用而报 `EBUSY`，未完成生产构建，也未更新当前运行的生产版。浏览器验收未调用真实付费 TTS 或渲染完整 MP4，生产衔接由领域回归验证。

保留工作区原有的批次归档与实拍重组脚本修改。
