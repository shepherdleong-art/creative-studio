# PR #16 导出与布局清理修复

审查基线：`d37155e29607afb7137f1038f64c2ad59bd9845c`。本轮使用独立 worktree，未修改原开发工作区或真实用户数据。

## 批量导出补齐布局

新分配的 v2 包装没有解析结果，派生成片的解析结果为 stale；原导出只检查 ready，求解又依赖包装检查器挂载，导致未逐条打开包装面板的成片被跳过。

导出现在按冻结文案、输出画幅及正式口播时长主动求解缺失或失效的布局，保留冻结资源完整性门禁。成功后，在数据库事务内重查原始 arrangement、当前候选、批次版本、冻结态和停止态，再保存派生缓存并生成当前渲染契约的任务。审核、编辑修订和撤销记录不随派生计算变化；求解或预检失败不保存半套配置。

`scripts/batch-export-layout.test.ts` 通过真实分配器和导出入口复现原失败，再验证新建／派生输出、输入哈希失效、幂等复用、资源篡改，以及计算期间撤销审核、编辑、切换候选／批次、停止和解冻。几何求解使用替身，资源冻结与门禁、SQLite、素材指纹及任务登记使用真实实现。

## 布局子进程清理

原子进程把模板、字体和贴纸拷到系统临时目录；取消或超时强杀时不会运行子进程 finally，父进程也不知道这个目录。

工作副本和 Chromium userDataDir 现归入 dataRoot 下的单次请求目录。父进程等待子进程 close 后才清理，避免强杀与文件拷贝竞争；请求写入或进程启动失败也经统一 finally 清理。

`scripts/packaging-auto-layout-lifecycle.test.ts` 运行真实布局子进程，以浏览器替身停在完成模板／字体拷贝后。取消回归先红后绿；同时覆盖模拟 120 秒超时、正常成功、浏览器失败、启动失败和预先取消，并验证清理完成时子进程已退出。

## 验证边界

本轮不调用付费供应商。真实模板几何与媒体导出由现有 Chromium／HyperFrames／FFmpeg 回归另行验证；几何替身只用于快速并发与生命周期测试。本地证据目录为 `outputs/pr16-fixes-validation/`。
