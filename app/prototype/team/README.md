# 双端交互原型（可丢弃）

问题：员工创作与服务器管理应该怎样分工，哪种页面信息层级更顺手？

这是两个新角色入口，现有本地首页没有账号、团队任务或服务运维宿主，因此使用独立 App Router 路由 `/prototype/team`。沿用当前工作台的设计令牌、中文术语、图标和制作模块。

```powershell
npm run prototype:team
```

- 员工端：http://127.0.0.1:3317/prototype/team?role=client&variant=A
- 管理端：http://127.0.0.1:3317/prototype/team?role=server&variant=A
- `variant=A`：侧栏工作台，员工先看项目，管理员先看运行总览。
- `variant=B`：横向导航、任务列表与筛选，强调连续处理任务。
- `variant=C`：窄导航和分阶段看板，强调流转与需要介入的事项。

底部工具条切换角色、布局和正常／断网／维护情境；左右方向键也能切换布局，编辑输入框时不会截获。工具条中的“查看状态”展示当前内存状态，“重置”重新加载示例数据。

可体验：新建项目、选择示例素材、模拟上传校验、提交任务、详情抽屉、画布节点、任务筛选、下载与新旧设备交付、客户端更新及失败回退、维护接单、成员停用、并发预算、公共资源发布和备份记录。

## 成员用量与限制（2026-11-02 增补）

用户已选择“费用额度＋并发上限”。管理端的“成员与账号”和“团队用量”共用示例账本，显示今日费用、本月已计／月度额度、在途预留、个人云端并发和使用状态；可搜索姓名／工号及筛选需要关注的成员。

点击“用量与限额”查看四类模块明细，修改月度金额、个人并发（1–10）、不限额或暂停新的付费生成。保存后可点击“模拟该成员调用 ¥10”：余额足够且有名额时预留费用并开始；并发满时排队、不预留；余额不足时阻止调用。任务抽屉中“演示完成并结算”将预留转为已计并释放并发。降低额度不打断在途任务，受理不明的任务继续保留预留和名额。

在同一标签页切到员工端，“我的用量”展示本人额度；达到上限或暂停生成时显示提示，仍可编辑、查看和下载。所有月度数字、结算费用和分配金额均为示例；新账号默认 ¥0／并发 2 是待评审的界面建议，并非用户确认的实际分配。原型没有跨月结算、真实定价或持久化扣费，不能作为服务器限额已生效的证据。

## 运行边界

启动脚本只复制原型、图标与现有颜色令牌到 `outputs/prototype-team-ui/`，再单独启动 Next。不会加载原工作台的 layout、instrumentation、API、环境配置、数据库或 worker。服务只监听回环端口。可用 `PROTOTYPE_TEAM_PORT` 改端口。

所有人物、任务、版本、并发额度和占用数字均为示例；文件选择只读取文件名，没有上传内容。下载、更新、账号和备份只修改内存，不操作真实系统。单标签页切换角色可查看模拟状态联动；两个标签页各有独立状态。刷新重置数据。原型并不验证真实认证、隔离、排队公平性或故障恢复。

正式生产构建和普通开发入口无法打开此路由：需非 production 且显式原型环境开关。启动脚本生成的副本在启动时刷新；编辑原文件后重新执行命令可同步副本。
