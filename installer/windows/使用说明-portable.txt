创意工作台 0.6.0（Windows 免安装版）使用说明
=============================================

这个文件夹已经带齐 Node、Electron、Python、LiteLLM、公司 API 配置、COS 配置和豆包语音密钥。
支持 Windows 10/11 x64（Intel / AMD），不需要安装 Node.js、Python、LiteLLM，也不用手填域名或密钥。


一、第一次使用（没有旧项目）
----------------------------

1. 从公司共享盘复制整个「创意工作台-0.6.0-免安装版」到本地磁盘。
   不要直接在共享盘运行；SQLite 数据库必须放本机。
2. 双击 环境自检.cmd，确认关键文件没有缺失。
3. 双击 start-windows.cmd。
4. 用完从应用菜单点「退出」。若退出异常或下次提示端口占用，双击 stop-windows.cmd。


二、从 0.5.x 或其他旧版迁移项目（重要）
---------------------------------------

不要手工把 data 和 storage 两个文件夹复制到新目录。旧库保存过绝对路径，直接复制会导致
项目能打开但缩略图、图片或视频找不到。

正确步骤：

1. 把共享盘里的「创意工作台-0.6.0-免安装版」完整复制到一个全新的本地目录。
2. 新目录先不要运行 start-windows.cmd。
3. 双击新目录里的 迁移旧版数据.cmd。
4. 在弹窗中选择旧版免安装版的根目录（里面应有 data、storage、start-windows.cmd）。
5. 脚本会停止能确认属于新旧目录的残留进程，然后：
   - 用 SQLite Online Backup 复制 workbench.db，不直接生拷 WAL/SHM；
   - 复制业务素材，但不复制旧 storage\logs 和 storage\run，并清空新库里的旧 job_logs；
   - 修复 image_assets 的 path/originalPath/processedPath 和 video_jobs.localVideoPath；
   - 做数据库 quick_check，并在新目录生成「迁移报告-*.json」。
6. 看到“迁移验收通过”后，再双击 start-windows.cmd。
7. 抽查旧项目的首页缩略图、场景图、分镜图和视频播放。旧目录先保留几天，确认无误再删除。

迁移脚本不会修改旧版目录。若新版目录已经生成了 data 或 storage 内容，脚本会拒绝覆盖；
请重新复制一份从未启动过的 0.6.0 主包再迁移。


三、公司 API 已经怎么配置
------------------------

前端公司供应商统一连接本机 LiteLLM：

  http://127.0.0.1:4000

这才是正确地址，不是 128 开头的地址。本机服务只监听 127.0.0.1，不对局域网或公网开放。
真正的上游地址和 Key 在包根 config.yaml；COS 与豆包 TTS 配置在 .env.local。

全新数据目录会自动预置并启用：

- 图片：image2-medium
- 图片：qiniuyun/gpt-image-2-medium
- 视频：kling-3.0
- 视频：doubao-seedance-2-0-fast-260128
- 脚本：GPT-5-6-Luna-Standard
- 语音：豆包 seed-tts-2.0

详情页智能脚本调度器在本免安装版中默认开启。不要在设置页把公司供应商改成公网地址。


四、启动、停止与端口占用
----------------------

- 启动：双击 start-windows.cmd。
- 正常停止：应用菜单点「退出」。
- 异常停止：双击 stop-windows.cmd。

stop-windows.cmd 会先尝试优雅停机，再对“可执行路径或命令行能确认属于当前免安装目录”的
进程执行 taskkill /T /F，连同子进程一起清理。3000/4000 若被无法确认归属的其他程序占用，
脚本只显示 PID 并跳过，不会误杀。


五、完整性与安全
--------------

- portable-manifest.json 记录 0.6.0、构建时间、源码 commit，以及关键文件的大小和 SHA-256。
  start-windows.cmd 会在启动前核对；提示“免安装包不完整”时请重新完整复制。
- config.yaml 和 .env.local 含公司密钥，只能放在有权限的公司共享盘和同事本机，不得外传。
- 主发布包不带 data、storage、旧日志、旧项目或数据库，也不带开发测试脚本。
- 不要编辑 scripts 下的 .ps1；它们必须保持 UTF-8 BOM + CRLF。
- 不要删除 node-runtime、python-runtime、node_modules、.next 或 dist-desktop。


六、环境自检与常见问题
--------------------

双击 环境自检.cmd 可查看脱敏状态。需要回报问题时，把完整输出发给维护者。

- 端口 4000/3000 占用：先双击 stop-windows.cmd，再启动。
- 401 / Invalid token：公司上游 Key 可能已过期，联系维护者更新共享盘主包。
- “受控媒体传输尚未就绪”或 CREATIVE_STUDIO_COS：重新复制 .env.local 或完整主包。
- better-sqlite3 / sharp / 原生模块错误：包不完整或被杀毒软件隔离，重新复制完整主包。
- 旧项目缩略图消失：不要继续手工拷 data/storage，换干净 0.6.0 包运行 迁移旧版数据.cmd。
- 迁移报“新版目录已有 data 或 storage”：该目录已启动过，换一份干净的新包。


七、维护者/AI Agent 验收清单
-------------------------

1. 确认目录名为「创意工作台-0.6.0-免安装版」，且主包从未启动、没有 data/storage。
2. 将主包完整复制为一份独立的 QA 副本。以下第 3～8 步只在 QA 副本执行，绝不启动主包。
3. 在 QA 副本双击 环境自检.cmd：Node v22.22.3、Python 3.12.10、LiteLLM 1.89.2，关键文件齐全。
4. 在 QA 副本双击 start-windows.cmd，确认桌面窗口打开。
5. 检查 http://127.0.0.1:4000/health/liveliness 正常。
6. 设置页确认上述公司供应商已启用、Base URL 为 http://127.0.0.1:4000。
7. 只提交 1 个最小真实任务：用 qiniuyun/gpt-image-2-medium 生成一张低风险测试图。
   其他模型只核对预置、启用状态与路由，不提交计费任务；需要实测必须再次取得授权。
8. 双击 stop-windows.cmd，确认工作台和 LiteLLM 都退出，3000/4000 不再被该 QA 目录进程占用。
9. 迁移另用一份从主包复制、从未启动的迁移 QA 副本；对旧版数据副本运行 迁移旧版数据.cmd，
   确认缩略图、素材和视频可用，storage 日志和数据库 job_logs 均未迁移。
10. 记录结果后只删除两份 QA 副本；主包保持未启动状态，再复制到受限共享盘。


八、0.6.0 更新记录（2026-09-04）
------------------------------

- 新增 迁移旧版数据.cmd，修复跨版本/改目录后旧绝对媒体路径导致的缩略图与视频失效。

再使用 迁移旧版数据.cmd 搬项目。后续同一版本的小修也优先整包复制，避免 manifest 与文件混版。
