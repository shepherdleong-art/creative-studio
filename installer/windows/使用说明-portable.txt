创意工作台（免安装版）使用说明
================================

本说明分两部分：
- 第一部分给人看：怎么用。
- 第二部分给 AI Agent（如 workbuddy）看：把本文件整个发给你的 Agent，让它从第二部分开始逐条执行并自检。

2026-08-14 起，免安装包已内置全部运行环境：Node 运行时（node-runtime\）和
Python + 公司供应商组件（python-runtime\）。电脑上不需要安装任何软件，
不需要联网，不再有首次启动的环境重建。


================================
第一部分：给人看的快速说明
================================

一、电脑上要装的东西

无。运行环境全部内置在包里，不要自行安装 Node.js 或 Python。

二、每天怎么用

1. 把整个「创意工作台-0.5.0-免安装版」文件夹复制到自己电脑的本地磁盘
   （不要直接在共享盘上双击运行，网络盘有数据库损坏风险且很慢）
2. 双击文件夹里的 start-windows.cmd
3. 用完在应用菜单里点「退出」即可（公司网关代理会随之一并关闭）

三、注意事项

- 不要双击 start-windows.cmd 之外还再开一个，会提示端口占用
- 文件夹里的 config.yaml、.env.local 含公司密钥，请勿外传
- data\ 和 storage\ 是你本机的项目数据库和全部产物，首次启动自动创建；
  更新包时永远不要从共享盘覆盖这两个文件夹
- node-runtime\ 和 python-runtime\ 是内置运行环境，不要删
- 包里如果出现 .venv-litellm\ 文件夹，说明复制来源不对，请重新从共享盘完整复制
- 遇到异常：双击 环境自检.cmd（只读、密钥脱敏），把窗口输出原样发回；不要自行安装 Python/Node 或修改脚本


================================
第二部分：给 AI Agent 的执行指令
================================

【总规则】
- 目标：让 start-windows.cmd 在本机双击可用，桌面窗口正常打开，公司供应商就绪。
- 不许修改项目代码；只允许复制文件、运行项目自带脚本。
- 不许安装任何软件：不装 Node、不装 Python、不创建 venv、不执行 pip/winget。
  免安装模式本身也禁止联网修复；缺文件的唯一处理是重新完整复制包。
- config.yaml 和 .env.local 含真实 API Key：不要打印、不要外传、不要提交到任何仓库。
- 每一步都有验证命令，验证不通过就停在该步排查并报告，不要跳过继续。

【第 1 步】确认包内 Node 运行时
验证：<项目目录>\node-runtime\node.exe 存在，且运行
  node-runtime\node.exe --version
预期输出 v22.22.3。
如果该文件缺失：从共享盘包里重新拷贝整个 node-runtime 文件夹；
不要安装其他版本 Node（包内预编译原生模块按 Node 22 编译）。

【第 2 步】确认包内 Python 运行时（公司供应商需要）
验证：<项目目录>\python-runtime\python.exe 存在，且运行
  python-runtime\python.exe --version
预期输出 Python 3.12.10。
如果缺失或版本不符：重新完整复制包；不要安装系统 Python，启动脚本不会使用它。

【第 3 步】核对文件夹内容
确认以下都在（<项目目录> 指复制过来的文件夹）：
  start-windows.cmd              启动入口（免安装模式）
  portable-manifest.json         免安装包完整性清单
  node-runtime\node.exe          内置 Node 运行时
  python-runtime\python.exe      内置 Python + LiteLLM
  python-runtime\runtime-manifest.json
  node_modules\                  Node 依赖（含 Electron 二进制）
  .next\standalone\server.js     生产构建产物
  dist-desktop\main.js           桌面壳编译产物
  scripts\                       启动/停止/自检脚本
  config.yaml                    公司网关配置
  .env.local                     腾讯云 COS 密钥
最省事的核对方式：双击 环境自检.cmd，关键文件齐全即为通过。
缺任何一项都不要尝试本机修复，重新完整复制整个包。

【第 4 步】首次启动
双击（或运行）<项目目录>\start-windows.cmd。
启动脚本先校验 portable-manifest.json 与 python-runtime 完整性，
然后拉起 LiteLLM 代理（127.0.0.1:4000）并打开桌面窗口。
不需要联网，也没有环境重建步骤；首次启动只是略慢（代理加载模型清单），之后几十秒。

【第 5 步】验收（全部通过才算完成）
1. 桌面窗口正常打开，能看到项目列表页。
2. 命令行执行：Invoke-RestMethod http://127.0.0.1:4000/health/liveliness   有正常返回。
3. 设置页「公司供应商运行环境」显示就绪（代理可用）。
4. 实际提交一个生图任务，能返回结果（同时验证 config.yaml 的上游 Key 没过期）。
完成后汇报：Node 版本（应为 v22.22.3）、Python 版本（应为 3.12.10）、
LiteLLM 版本（应为 1.89.2）、代理健康检查结果、测试任务结果。

【第 6 步】常见问题（按报错对号入座）
- 提示「免安装包不完整，请重新复制」：
  portable-manifest.json 缺失/无效或关键文件缺失/损坏（拷贝不完整最常见）。
  保留本地 data\ 和 storage\，其余从共享盘重新完整复制。
- 提示「端口 4000 已被占用」：
  运行 scripts\stop-stack.ps1；无效则找到占用 4000 的进程停掉再启动。
- 生图报 401 Invalid token：
  不是环境问题，是 config.yaml 里的公司网关 Key 过期/被吊销，找PK换新 Key。
- 提示 better-sqlite3 无法加载 / 原生模块错配：
  说明启动时没用包内 node-runtime\node.exe。确认该文件存在；缺失则重新复制包。
- 双击 cmd 窗口中文乱码：
  不要用文本编辑器重存 start-windows.cmd（必须 CRLF 行尾）和 scripts\ 下的 .ps1
  （必须 UTF-8 带 BOM），重存会损坏；损坏后从共享盘重新复制同名文件。
- 其他异常：双击 环境自检.cmd，把输出原样发回，不要自行安装软件或改脚本。

【第 7 步】日常停止
应用菜单选「退出」，公司网关代理会随之一并关闭；直接关启动窗口也会触发优雅退出。

【第 8 步】共享盘的包更新后，本地该拷什么（增量更新指南）
总原则：只拷「代码和运行时」，绝不从共享盘覆盖本地的 data\ 和 storage\
（那是本机的项目数据库和全部产物，覆盖了数据就没了）。

对照表（共享盘里什么变了 → 本地拷什么）：
  .next\standalone\   功能/修复更新（最常见）。整个文件夹覆盖，约 1.1 GB，覆盖后重启工作台
  scripts\ 里的 .ps1   启动逻辑更新。覆盖同名文件
  start-windows.cmd   启动入口更新。覆盖
  环境自检.cmd / 使用说明.txt   自检工具或说明更新。覆盖
  portable-manifest.json   上述任何一项更新时随包一起覆盖（完整性清单）
  node-runtime\       内置 Node 运行时变化。覆盖（约 87 MB）
  python-runtime\     内置 Python/LiteLLM 变化。整个文件夹覆盖（数百 MB）
  node_modules\       依赖变化（少见）。整个文件夹覆盖，约 1.3 GB
  config.yaml         公司网关模型或 Key 变更，收到通知才覆盖
  .env.local          COS 密钥轮换，收到通知才覆盖
  data\、storage\     永远不拷！这是本机自己的数据

怎么知道包更新了：看本文末尾「更新记录」，或对比共享盘和本地同名文件的修改时间。
不确定哪变了：全量重拷整个包，但先把本地的 data\ 和 storage\ 排除在外。
更新后验证：双击 环境自检.cmd 确认关键文件齐全，再启动跑一遍第 5 步验收。

【自助排查】
文件夹里的 环境自检.cmd 可双击运行（只读、密钥脱敏），把输出原样发回即可定位大多数问题。
